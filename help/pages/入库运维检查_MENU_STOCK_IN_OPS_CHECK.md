# 入库运维检查

## 页面功能

给系统管理员、平台管理员和财务总监核对到货通知到采购入库、再到库存明细和进项发票是否对得上。只出检查结果，**不会改任何单据**。

一次检查会看：

- 到货通知已经显示已入库，却找不到已入库的采购入库单
- 已经有已入库的采购入库单，到货通知状态还停在已质检等
- 同一张到货通知被入了多次
- 已入库明细没有库存明细，或库存明细还挂着已删的入库
- 入库明细金额和数量×单价对不上
- 到货通知 / 入库单 / 采购订单的供应商不是同一家
- 入库单删了，进项发票核销还在

只查采购入库。报关入库、退货、报废、调拨不参加检查。质检做完但还没入库，属于待入库，不会当成错误。

## 操作说明

<div class="help-op-block">

**检查**

对全部到货通知、采购入库、库存明细和进项核销跑一遍。完成后标题下方会出现错误、警告、合计三张卡片，明细在更下面的表格。

</div>

<div class="help-op-block">

**筛选**

结果太多时，用卡片下方的条件栏只看一类问题。可按级别、检查类型、单据类型筛选，也可输入单号（匹配本行单号或关联单号，从左边开始匹配）。点「搜索」或回车生效；下拉选完即生效。筛选时第三张卡片会改成「显示」当前条数 / 全部条数。「重置」只清筛选，不会清掉这次检查结果，也不会改任何单据。

</div>

## 结果怎么看

| 列 | 含义 |
|---|---|
| 级别 | 错误必须处理；警告建议核对 |
| 单号 | 点进去打开对应单据 |
| 关联单号 | 同一条问题的另一张单 |
| 错误原因 | 哪里不对 |
| 运维操作建议 | 按这一行的单据逐步写明：打开哪个页面、哪张单号、点哪个按钮。多步会换行编号。未做进项核销的行不会让你去反核销 |

本页不提供一键修复。同一张到货通知入了多次时，一般留下入库单号最小的那张，删掉其余后再到 Debug 模拟数据里点「刷新到货通知状态」。改完后再点一次「检查」确认是否消失。
