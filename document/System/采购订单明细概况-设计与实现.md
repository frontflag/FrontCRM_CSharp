# 采购订单明细概况 — 功能要求与实现说明

本文描述 **FrontCRM（CRM.Core / CRM.API / CRM.Web）** 中「采购订单明细概况」页签的业务口径、功能要求、数据计算与代码索引。与 [业务逻辑与数据关系文档](业务逻辑与数据关系文档.md)、[采购订单主状态](采购订单主状态.md)、[销售订单明细概况-设计与实现](销售订单明细概况-设计与实现.md)、[财务 Phase 1 操作手册](../EBS/财务/财务Phase1操作手册.md)、[业务详情页面规范](../PRD/规范/UI规范/业务详情页面规范.md) §7.4 交叉引用。

---

## 1. 业务定位

采购订单详情页底部 **「采购订单明细详情」** 面板，在选中某条采购明细后，用 **概况** 页签以 **4 行 × 7 列** 矩阵快速展示该行从付款到进项发票的执行进度，无需逐个切换下游 Tab。

| 概念 | 说明 |
|------|------|
| **适用对象** | 单条 `purchase_order_item`（采购订单明细行） |
| **展示形态** | 矩阵表：行 = 总数 / 已执行 / 待处理；列 = 基准信息 + 4 个执行环节 |
| **与其他 Tab 关系** | 概况为 **汇总快照**；各下游 Tab（付款、到货通知、入库、进项发票等）仍为 **明细列表**，二者互补 |
| **默认 Tab** | 单击或双击订单明细行打开面板时，默认激活 **概况** |

## 2. 功能要求

### 2.1 入口与交互

| 入口 | 路径 / 操作 | 说明 |
|------|-------------|------|
| 采购订单详情 | `/purchase-orders/:id` → 主 Tab「订单明细」→ 单击/双击某行 | 展开底部「采购订单明细详情」面板，默认 **概况** |
| 页签顺序 | 概况为 **第一个** Tab，其后为采购申请、付款、到货通知… | 与 `PurchaseOrderDetail.vue` 面板 Tab 顺序一致 |

**交互规则：**

- 面板标题展示 `采购订单明细详情` + 明细编号（`purchaseOrderItemCode`）；
- 概况无分页；数据随 `detail-tab-aggregates` 一次性返回；
- 无 `lineOverview` 时显示空状态「暂无概况数据」；
- 敏感字段脱敏开启时（`maskPurchaseSensitiveFields`），整个明细详情面板不展示（含概况）。

### 2.2 矩阵结构

```
              │ 明细总额 │ 明细数量 │ 付款 │ 到货通知 │ 入库 │ 进项发票 │
──────────────┼─────────┼─────────┼──────┼─────────┼──────┼─────────┤
总数          │ 金额+币别│  qty     │ 金额 │  qty    │ qty  │ 金额+币别│
已执行        │   —     │   —     │ 金额 │  qty    │ qty  │ 金额     │
待处理        │   —     │   —     │ 金额 │  qty    │ qty  │ 金额     │
```

**行规则：**

| 行 | 说明 |
|----|------|
| **总数** | 该列的业务目标量：数量为采购行 `qty`；金额为行全额 `qty × cost`（含币别） |
| **已执行** | 该环节已完成量 |
| **待处理** | 剩余待完成量（一般 = 总数 − 已执行） |

**列规则：**

| 列 | 单位 | 总数 | 已执行 | 待处理 | 列标题着色 |
|----|------|------|--------|--------|------------|
| 采购订单明细总额 | 金额 + 币别 | `qty × cost` | `—` | `—` | 不着色 |
| 采购订单明细数量 | 数量 | `qty` | `—` | `—` | 不着色 |
| 付款 | 金额 + 币别 | `PaymentAmount` | `PaymentAmountFinish` | `PaymentAmountNot` | 着色 |
| 到货通知 | 数量 | `qty` | `QtyStockInNotifyExpectSum` | `max(0, qty − ExpectSum)` | 着色 |
| 入库 | 数量 | `qty` | `QtyReceiveTotal` | `max(0, qty − 已入库)` | 着色 |
| 进项发票 | 金额 + 币别 | `PurchaseInvoiceAmount` | `PurchaseInvoiceDone` | `PurchaseInvoiceToBe` | 着色 |

**金额列 Phase 1**：单行单币别（`purchase_order_item.currency`）；多币别按币别分行展示留待后续版本。

### 2.3 列标题状态配色（仅标题文字）

对 **付款、到货通知、入库、进项发票** 4 列，根据 **已执行 vs 总数** 为列标题 **文字** 着色；**格子底色** 与第一列行标题一致，不加粗。

| 条件 | 标题文字色 | 语义 |
|------|------------|------|
| 已执行 = 0 | 灰（`info`） | 未开始 |
| 0 < 已执行 < 总数 | 黄（`warning`） | 进行中 |
| 已执行 = 总数 | 绿（`success`） | 已完成 |
| 已执行 > 总数 | 红（`danger`） | 异常（如超通知、超入库） |

基准列（采购明细总额、采购明细数量）不参与着色。

### 2.4 金额与权限

- 金额列受 `purchase.amount.read` 控制；无权限时金额单元格显示 `—`；
- 后端 `mask511` 时金额相关字段归零后返回，前端同样脱敏。

### 2.5 权限

| 操作 | RBAC |
|------|------|
| 查看概况及下游 Tab 聚合 | `purchase-order.read` |
| 金额列可见 | 另需 `purchase.amount.read` |

接口路径与既有采购订单明细详情 Tab 相同，不新增独立权限点。

## 3. 数据口径

各指标与 `PurchaseOrderItemExtendSyncService.RecalculateAsync` 及 [PurchaseOrderItemExtend 统计字段文档](../EBS/采购/PurchaseOrderItemExtend统计字段文档.md) 保持一致。

### 3.1 基准列

```text
lineAmount.total = Round(qty × cost, 2)
lineQty.total    = qty
currency           = purchase_order_item.currency
```

### 3.2 付款（金额）

| 字段 | 口径 |
|------|------|
| `PaymentAmount` | 行全额 `qty × cost` |
| `PaymentAmountFinish` | 有效付款单明细 `verification_done` 合计（排除已取消、审核失败付款单） |
| `PaymentAmountNot` | `max(0, PaymentAmount − PaymentAmountFinish)` |

**注意**：概况展示 **已核销付款**，不用 `PaymentAmountRequested`（请款额，含待审请款）。

### 3.3 到货通知（数量）

对称销售订单概况「出库申请」口径（方案 A）：

| 字段 | 口径 |
|------|------|
| **已执行** | `QtyStockInNotifyExpectSum` = 本行各到货通知 `expect_qty` 合计 |
| **待处理** | `max(0, qty − ExpectSum)` |

> 不使用 extend 字段 `QtyStockInNotifyNot`（剩余可下达货通知数，含在途/已收逻辑）作为矩阵待处理，以免与「总数 − 已执行」语义不一致。

到货通知汇总与 SyncService 一致：本行全部有效到货通知（软删记录由仓储层排除）。

### 3.4 入库（数量）

| 字段 | 口径 |
|------|------|
| `QtyReceiveTotal` | `stock_in_item_extend.purchase_order_item_id = 本行`，父单 `stock_in.status = 2（已入库）` 且 `stock_in_type = 采购入库`，累计 `stock_in_item.quantity` |
| 待处理 | `max(0, qty − QtyReceiveTotal)` |

### 3.5 进项发票（金额）

| 字段 | 口径 |
|------|------|
| `PurchaseInvoiceAmount` | 行全额 |
| `PurchaseInvoiceDone` | 关联本行的进项发票明细 `bill_amount` 合计（SyncService 按入库单 + 质检/采购来源解析，排除红冲、作废入库单） |
| `PurchaseInvoiceToBe` | `max(0, PurchaseInvoiceAmount − PurchaseInvoiceDone)` |

## 4. API 与 DTO

### 4.1 接口

仅在 **单条明细 scope** 的 aggregates 接口中返回 `lineOverview`；订单级 aggregates 不返回。

```
GET /api/v1/purchase-orders/{orderId}/purchase-order-items/{purchaseOrderItemId}/detail-tab-aggregates
```

响应在既有 Tab 列表字段之外增加：

```json
{
  "lineOverview": {
    "lineAmount": { "total": 230000, "currency": 1 },
    "lineQty": { "total": 1000 },
    "payment": { "total": 230000, "done": 0, "pending": 230000, "currency": 1 },
    "arrivalNotice": { "total": 1000, "done": 500, "pending": 500 },
    "stockIn": { "total": 1000, "done": 0, "pending": 1000 },
    "purchaseInvoice": { "total": 230000, "done": 0, "pending": 230000, "currency": 1 }
  },
  "payments": [ ... ],
  "arrivalNotices": [ ... ]
}
```

TypeScript 类型见 `CRM.Web/src/api/purchaseOrder.ts`：`PurchaseOrderLineOverview`、`PurchaseOrderLineOverviewQtyMetric`、`PurchaseOrderLineOverviewAmountMetric`。

### 4.2 后端构建

| 位置 | 说明 |
|------|------|
| `PurchaseOrdersController.BuildPurchaseOrderDetailTabAggregatesPayloadAsync` | `purchaseOrderItemIdScope != null` 时调用 `BuildPurchaseOrderLineOverviewAsync` |
| `PurchaseOrdersController.BuildPurchaseOrderLineOverviewAsync` | 读取 `purchase_order_item`、`purchase_order_item_extend` |

## 5. 前端实现

### 5.1 页面与组件

| 文件 | 职责 |
|------|------|
| `CRM.Web/src/views/RFQ/PurchaseOrderDetail.vue` | 概况 Tab 模板、矩阵渲染、列标题着色、单元格格式化 |
| `CRM.Web/src/api/purchaseOrder.ts` | `getPurchaseOrderItemDetailTabAggregates`、`PurchaseOrderLineOverview` 类型 |

### 5.2 关键逻辑

| 函数 / 状态 | 说明 |
|-------------|------|
| `selectPurchaseOrderItemRow` | 打开面板，`activeTab = 'overview'`，拉取 aggregates |
| `poLineOverviewColumns` | 绑定 `lineOverview`；`colorize` 控制是否参与标题着色 |
| `poLineOverviewRows` | 总数 / 已执行 / 待处理三行 |
| `poOverviewHeaderTone` / `poOverviewColHeadClass` | 列标题文字色：gray / yellow / green / red |
| `formatPoOverviewCell` | 基准列 done/pending 显示 `—`；金额受 `canViewPurchaseAmount` 控制 |

### 5.3 样式（`.so-line-overview`）

与销售订单明细概况共用同一套样式类名：

- 表头行、第一列共用 `--crm-detail-section-header-bg`；
- 列标题状态色仅改 **文字颜色**，字重 400；
- 数据格使用 `--crm-table-text`、`--crm-card-bg`，适配浅色/深色主题。

## 7. 测试与回归要点

1. 单击/双击明细行后面板默认打开 **概况**，矩阵 6 列 3 行与下游 Tab 汇总一致；
2. 到货通知已执行 = `ExpectQty` 合计，待处理 = `qty − ExpectSum`；
3. 到货/入库超量时列标题红色；
4. 入库仅统计 **已完成采购入库**；
5. 付款/进项发票：部分完成黄色标题，全额绿色；与列表 `paymentProgressStatus` / `invoiceProgressStatus` / `purchaseProgressStatus` 同源（口径见 [采购订单主状态](采购订单主状态.md) §4）；
6. 无 `purchase.amount.read` 时金额格为 `—`；
7. 订单级 `detail-tab-aggregates` 响应不含 `lineOverview`；
8. 切换主题后表头/数据文字对比度可读。
