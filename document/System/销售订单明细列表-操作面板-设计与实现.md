# 销售订单明细列表 · 右侧「操作」面板 — 功能要求与实现说明

本文描述 **FrontCRM（CRM.Core / CRM.API / CRM.Web）** 中 **销售订单明细列表页**（`SalesOrderItemList`）右侧工作区辅助栏 **「操作」** 页签的设计要求与实现方法。与 [销售订单明细列表-设计与实现](销售订单明细列表-设计与实现.md)（列表列、筛选、**采购员列**）、[销售订单明细列表-流程页签-设计与实现](销售订单明细列表-流程页签-设计与实现.md)（右侧 **「流程」** 全链路时间轴，列表 + 详情）、[销售订单明细概况-设计与实现](销售订单明细概况-设计与实现.md)（详情页底部概况矩阵）、[系统设计规范](系统设计规范.md)、`help/pages/销售订单明细_MENU_SALES_ORDER_ITEMS.md` 交叉引用。

---

## 1. 业务定位

| 概念 | 说明 |
|------|------|
| **适用页面** | 销售订单明细列表 `/sales-order-items`（`SalesOrderItemList`）、销售订单详情 `/sales-orders/:id`（`SalesOrderDetail`） |
| **展示位置** | `AppLayout` 右侧辅助栏（`aux-right`），与 **「帮助」** 页签并列；展开右栏默认 **操作** 见 [扩展面板.工作台规范 §2](../../PRD/规范/UI规范/扩展面板.工作台规范.md)；**视觉 token** 见 [扩展窗口页签-操作规范](../../PRD/规范/UI规范/扩展窗口页签-操作规范.md) |
| **页签 ID** | `r-ops`（文案 i18n：`layout.auxTabs.ops` → 中文「操作」） |
| **目标** | 在右侧「操作」页签就绪时，单击列表行查看该行摘要、备货库存、**使用备货**（若有），并发起 **申请采购** / **申请出库**（交互门控见 §2.4）；详情页单击订单明细行时同步展示同一操作面板 |
| **测试对照** | [销售订单明细列表-操作面板-测试对照说明](../QA/销售/销售订单明细列表-操作面板-测试对照说明.md) |
| **与详情页概况区别** | 详情页底部为 4×10 全链路矩阵；右侧操作面板为 **4～5 张卡片**（订单明细 / 备货库存 / **使用备货**（条件）/ 采购申请 / 出库通知），侧重日常操作 |

**在销售订单明细列表或销售订单详情路由下** 注册三页签（操作 + 流程 + 帮助），默认选中 **操作**；操作/流程共用 `SalesOrderItemOpsPanel` / `SalesOrderItemFlowPanel` + `salesOrderItemOpsPanel` store。离开上述路由时恢复仅「帮助」，并 `clear()` 操作面板 store。

## 2. 布局与交互要求

### 2.1 整体结构

```
┌─ 右侧辅助栏 ─────────────────────────┐
│ [操作] [帮助]              [全屏][✕] │
├──────────────────────────────────────┤
│  （无选中行）请在「操作」页签下单击行… │
│  或                                  │
│  ┌ 订单明细 ─────────────────────┐   │
│  ├ 备货库存（条件显示）──────────┤   │
│  ├ 使用备货（条件显示）──────────┤   │
│  ├ 采购申请 ──────────── 已完成 ✓│   │
│  └ 出库通知 ─────────────────────┘   │
└──────────────────────────────────────┘
```

- 四个区块 **直接作为页签内容子级** 纵向排列，无额外浮动外层壳；宽度 `100%` 自适应父面板，禁止横向滚动。
- 嵌入模式（`embedded`）使用 `div.so-item-ops-root--embedded`，样式 token 对齐 `--crm-aux-*`。
- 各卡片 **无标题图标**，仅保留文字标题。

### 2.2 列表交互（摘要）

| 操作 | 行为 |
|------|------|
| **单击行** | 见 **§2.4 决策表**（按右栏展开状态 + 当前页签门控） |
| **双击行** | 跳转销售订单详情 `SalesOrderDetail`（与改造前一致，优先级高于单击） |
| **选中行高亮** | 表格 `row-class-name`：`so-item-row--active`（来自 store 选中行） |
| **敏感字段脱敏** | `maskSaleSensitiveFields === true` 时：**仍加载**面板；敏感字段 `—`；按钮按角色权限 |

### 2.3 右栏展开 / 收起与接口（摘要）

**混合数据源 + 按需请求**（见 §4）。列表 `loadList` 刷新时 **清空**操作面板 store；离开列表路由 `clear()`。细则见 §2.4。

### 2.4 操作页签交互决策表（定稿 · 全站列表共用）

以下为使用右侧 **「操作」** 页签（`r-ops`）的**列表页**强制门控（不强制展开右栏、不强制切到「操作」）。

**适用列表：** 销售订单明细、采购订单明细、报关单列表、到货通知列表、质检列表、**出库单列表**。实现：`CRM.Web/src/composables/useListRightOpsPanelInteraction.ts`。

| # | 右栏状态 | 当前右栏页签 | 用户动作 | 结果 |
|---|----------|--------------|----------|------|
| A | **收起** | （不可见） | 单击列表行 | **忽略**：不展开右栏、不选中行、**不请求**操作面板 API |
| B | **展开** | **非「操作」**（如「帮助」） | 单击列表行 | `setRowOnly`：记住选中并高亮；**不切页签**、**不请求** |
| C | **展开** | **「操作」** | 单击列表行 | `selectRow`：选中 + 请求面板数据（销售/采购为 aggregates；报关为详情） |
| D | **展开** | 由非「操作」→ **点「操作」页签** | 切换页签 | 若 store **已有选中行** → 加载面板数据；无选中行则空态 |
| E | 由收起→**展开** | 且当前页有 **「操作」** 页签 | 展开右栏 | 默认激活 **`r-ops`**（[扩展面板.工作台规范 §2](../../PRD/规范/UI规范/扩展面板.工作台规范.md)）；若 store **已有选中行** → 加载面板数据 |
| F | 任意 | 任意 | 列表刷新 / 离开路由 | `clear()` 操作面板 |

**原则：**

1. **不打扰**：收起右栏或用户正在看「帮助」时，单击行不得抢焦点打开/切换到操作面板。  
2. **按需请求**：仅在「操作」页签对用户可见且需要展示数据时调用操作面板接口。  
3. **延迟加载**：在「帮助」等页签下可先选中行，切回「操作」时再加载（场景 D）。

**详情页（销售/采购订单详情）补充：** 单击订单明细行仍打开**底部明细面板**并请求其聚合；**不得** `setRightActiveTab('r-ops')` 强制切右侧页签。底部加载完成后可 `syncRowAndAggregates` 写入操作面板 store，便于用户稍后切到「操作」时已有数据。

### 2.5 子面板布局规范（定稿 · 全站「操作」页签共用）

**视觉 token（卡片层、字号、进度条、主按钮色）：** [扩展窗口页签-操作规范](../../PRD/规范/UI规范/扩展窗口页签-操作规范.md)。本节保留卡片 **类型与结构** 摘要；新页勿再复制一份 SCSS 数值。

**适用列表 / 面板：** 销售订单明细、采购订单明细、报关单列表、到货通知列表、质检列表、**出库单列表**，及后续复用 `so-item-ops-panel.scss` 的右栏 **「操作」** 页签嵌入面板（`embedded`）。

**共享样式：** `CRM.Web/src/assets/styles/so-item-ops-panel.scss`（各 `*OpsPanel.vue` 通过 `@import` 引用，禁止在单页重复写一套 token）。

#### 2.5.1 状态面板

用于工作流 / 进度 **状态标签** 独立卡片（如 `.ops-card--status-only`）。

| 项 | 规范 |
|----|------|
| 结构 | `.ops-status-tags` → `.ops-status-tags__row` → `el-tag` |
| 列数 | **默认 3 列**：`grid-template-columns: repeat(3, minmax(0, 1fr))` |
| 单标签 | 仍用 3 列网格；**仅 1 个状态时只占第一列**，不得拉满整行 |
| 多标签 | 每行最多 3 个；超出按业务顺序 **换行** 到下一 `.ops-status-tags__row` |
| 标签样式 | `effect="dark"`、`size="small"`；格内 `width: 100%` 居中 |

**示例：** 销售订单明细两行 × 三列（备货 / 采购 / 出库；发货 / 收款 / 发票）；到货通知单行仅「未到货」等 1 个标签时占左列 1/3 宽。

#### 2.5.2 信息面板（只读 Key:Value）

用于采购 / 质检 / 入库 / 使用备货等 **字段摘要** 卡片（非概况 hero、非指标+进度条操作卡）。

| 项 | 规范 |
|----|------|
| 结构 | `.ops-stock-region-row` → 最多 2 个 `.ops-stock-region-cell` |
| 单元格 | `ops-kv__label` + `ops-kv__sep`（`：`）+ `ops-kv__value`（**同行** Key:Value，左对齐） |
| 列数 | **默认双列**：每行 2 个字段 |
| 单列行 | 仅 1 个字段时，一行内只放 **1 个** `ops-stock-region-cell`（占左半列，右侧留空） |
| 链接值 | 单号类字段用 `router-link` + **`link-text`** 跳转，见 **§2.5.4**（默认正文色，悬停才变蓝+下划线）；强调数量等可用 `ops-kv__value--accent` |

**参考实现：** 销售订单明细「使用备货」卡片；到货通知「采购 / 质检 / 入库」卡片字段分行见各页 §3。

#### 2.5.4 单号跳转（信息面板内）

只读信息面板中，**可跳转的业务单号**在字段值处直接点击跳转；**不得**为同一目标再配独立「查看 xxx」主按钮（`.ops-action-btn`）。

| 项 | 规范 |
|----|------|
| 实现 | `router-link` + **`link-text`**，置于对应 Key:Value 的 `ops-kv__value` 内 |
| 视觉 | 与 [列表跳单号链接样式规范 PRD](../../PRD/规范/UI规范/列表跳单号链接样式规范PRD.md) 一致：**默认** `color: inherit`、无下划线；**`:hover`** 主题蓝 + 下划线 + `pointer` |
| 跳转目标 | 与各列表操作列 / 详情页 **同源**（权限与 query 参数一致） |
| 脱敏 | 511 等脱敏场景 **不渲染链接**，仅 `—` 或纯文本 |
| 无记录 | 无目标单据时不显示链接（空态文案，非按钮） |

**已定稿示例（到货通知操作面板）：**

| 字段 | 路由 |
|------|------|
| 采购明细单号 | `PurchaseOrderDetail` + `purchaseOrderItemId` query |
| 质检单号 | `QcCreate` + `noticeId` + `qcId` query |
| 入库单号 | `StockInDetail` + `id` param |

**参考实现（销售）：** 「使用备货」卡片采购单号链 `PurchaseOrderDetail`。

#### 2.5.5 操作 + 进度卡片 · 完成态生成单号（全站共用）

视觉与交互以 [扩展窗口页签-操作规范 §7.6](../PRD/规范/UI规范/扩展窗口页签-操作规范.md) 为准；**参考实现**为采购「申请付款」卡片。

| 项 | 规范 |
|----|------|
| 何时 | 卡片「已完成」时 **必须** 展示已生成且未取消的对象单号（可点击跳转）；未完成但已有单据时允许同样展示 |
| 布局 | 指标下方浅色横线 +「标签：单号」；单号不加粗；完成态不渲染进度条与主按钮 |
| 脱敏 | 不渲染链接 |
| 无单 | 不渲染该行 |

**销售订单明细操作页签映射：**

| 卡片 | 单号 | 跳转 |
|------|------|------|
| 采购申请 | `purchaseRequisitions.billCode` | `PurchaseRequisitionDetail` |
| 出库通知 | `stockOutRequests.requestCode` | `StockOutNotifyDetail` |

采购订单明细：申请付款 → 付款单号；到货通知 → 到货通知单号。

#### 2.5.3 不适用本节的卡片类型（页面自定）

| 类型 | 布局 | 说明 |
|------|------|------|
| **概况** | `.ops-overview-line` 纵向 Value | 无 Key 标签；首行 hero 琥珀单号（§3.1 等） |
| **操作 + 进度** | `.ops-metrics` 双列 + 生成单号行 + `.ops-progress` | 采购申请 / 出库通知 / 到货 / 请款等；含主按钮；**已完成须展示生成对象单号**（见 **§2.5.5** / [操作规范 §7.6](../PRD/规范/UI规范/扩展窗口页签-操作规范.md)） |
| **表单 / 下拉** | 业务组件 | 如报关单「设置海关状态」卡片 |

各列表操作面板文档在 §3 仅描述 **字段顺序与口径**；布局默认遵循本节，除非 §3 或 §2.5.3 明确例外。

## 3. 四张卡片 — 功能与 UI 要求

### 3.1 订单明细

**标题：**「订单明细」（非「概况」）

**展示规则：** 去掉 Key 标签，仅左对齐 Value 文本行：

| 顺序 | 内容 | 样式 |
|------|------|------|
| 1 | `sellOrderItemCode` | 琥珀色 `$color-amber`，18px 加粗 |
| 2 | 客户中文名 | 13px，常规 |
| 3 | 客户英文名 | **无内容整行隐藏**（`customerEnglishName` 空或脱敏） |
| 4 | PN | 常规 |
| 5 | 品牌 | 常规 |
| 6 | 销售单价 + 币别 | `formatUnitPriceWithCurrencyCodeSuffix(price, currency)`，如 `1.234567 USD` |
| 7 | 数量 | `{qty} pcs`，**不加粗、不用强调色** |

**数据来源：** 列表行 `row`（含列表 API 下发的 `customerEnglishName`，后端 `HydrateSellOrderLineListCustomerEnglishAsync` 填充）。

### 3.2 备货库存

**布局：** 大陆/海外为 §2.5.2 双列 Key:Value；「总计库存」为整行 `.ops-kv`（例外见 §2.5.3）。

**显示条件：** `总计库存 > 0`，否则 **整张卡片不渲染**。

| 字段 | 标签 | 数据 |
|------|------|------|
| 大陆仓 | `stockDomestic` | `regionType ≠ 海外` 的备货池可用量合计 |
| 海外仓 | `stockOverseas` | `regionType = 海外(20)` 合计 |
| 总计库存 | `stockTotal` | 大陆 + 海外 |

**备货池判定：** `stockType === 2` 或 `isStockingPoolMatch === true`；数量字段 `qtyRepertoryAvailable`。

**实现：** `summarizeStockingByRegion(aggregates.stockItems)`（`utils/sellOrderItemOpsPanel.ts`）。

### 3.3 使用备货

**布局：** §2.5.2 双列 Key:Value（每 PO 一行组：采购单号+采购员；生成日期+使用数量）。

**显示条件（方案 A）：** 仅当存在备货使用记录时显示整张卡片（`aggregates.stockingUsage.items.length > 0`），否则 **不渲染**。

**位置：** 夹在 **「备货库存」** 与 **「采购申请」** 之间；与「备货库存」**并存**（地域汇总卡片保留）。

**分组口径：** 按 **采购主单** `purchaseOrderId` 汇总；同一 PO 下多条备货补充拣货合并为一行。

**使用数量口径（A1）：** `SUM(PickedQty)`，其中 `pickingtaskitem.IsStockingSupplement = true` 且 `PickedQty > 0`（**含已拣未出库**）。

| 字段 | 标签 | 数据 |
|------|------|------|
| 采购单号 | `stockingUsagePoCode` | `purchaseOrderCode`；可链 `PurchaseOrderDetail` |
| 生成日期 | `stockingUsagePoDate` | `PurchaseOrder.CreateTime`（日期部分） |
| 采购员 | `stockingUsagePurchaser` | `PurchaseOrder.PurchaseUserName` |
| 使用数量 | `stockingUsageQty` | 该 PO 下汇总 `usedQty`；强调色 |

**数据链路：**

```text
sellOrderItemId
  → packing_item（SellOrderItemId 或 StockOutNotifyId）
  → pickingtaskitem（IsStockingSupplement=true, PickedQty>0, PackingItemId）
  → stock_item → purchase_order_item → purchase_order
  → GROUP BY purchaseOrderId
```

**业务参考：** [销售订单使用采购备货-业务逻辑](采购备货/销售订单使用采购备货-业务逻辑.md)（备货池快照 vs 本卡片「实际使用记录」为不同口径）。

### 3.4 采购申请

| 元素 | 要求 |
|------|------|
| 指标 | 已申请数量 / 可申请数量（两列） |
| 进度条 | 高度 **10px**；已申请/订单量；红色渐变；**不显示**「xx% 完成度」文案 |
| 状态文案 | **不显示**「当前可申请」；仅在禁用时显示 `purchaseDisabledHint` |
| 禁用提示 | 与列表操作列一致（`applyPurchaseDisabledHint.ts`）：摘要 + 明细列表 + `nextStep` |
| 按钮 | 权限 `purchase-requisition.write` 或 `sales-order.write`；文案「申请采购」 |
| 按钮样式 | 可用：深蓝 `#0f4c81`；不可用：灰底 `#e5e7eb` |
| **已完成** | 见 §3.6；须展示采购申请单号（可跳转），见 §2.5.5 |

**进度：** `purchaseAppliedQty / orderQty`；已申请优先 `lineOverview.purchaseRequisition.done`，否则由 `purchaseRemainingQty` 反推。

### 3.5 出库通知

| 元素 | 要求 |
|------|------|
| 指标 | 已通知数量 / 可通知数量 |
| 进度条 | 10px 高；蓝色渐变；无完成度百分比文案 |
| 状态文案 | 不显示「当前可申请」；禁用时 `stockOutDisabledHint`（含采购门槛 PO 明细） |
| 按钮 | 权限 `sales-order.write`；文案「申请出库」 |
| 按钮样式 | 同采购申请（可用深蓝 / 不可用灰色） |
| **已完成** | 见 §3.6；须展示出库通知单号（可跳转），见 §2.5.5 |

**进度：** `stockOutNotifiedQty / orderQty`；已通知/可通知优先 `lineOverview.stockOutNotify.done/pending`。

**按钮禁用口径：** `salesOrderLineApplyStockOutButtonDisabled`（与列表一致）。

### 3.6 「已完成」态（采购申请 / 出库通知）

标题栏 **右侧** 显示绿色对钩（`CircleCheck`）+ 文案「已完成」；**隐藏**操作按钮、禁用提示与进度条。指标下方按 §2.5.5 / [操作规范 §7.6](../PRD/规范/UI规范/扩展窗口页签-操作规范.md) 展示生成对象单号（可点击跳转）。

| 卡片 | 判定条件（满足其一且主表允许操作） | 生成单号 |
|------|-----------------------------------|----------|
| 采购申请 | `purchaseProgressStatus === 2`；或 `可申请数量 ≤ 0` 且 `已申请数量 ≥ 订单量` | `aggregates.purchaseRequisitions`（跳过 status=3 已取消）→ `PurchaseRequisitionDetail` |
| 出库通知 | `stockOutNotifyProgressStatus === 2`；或 `可通知数量 ≤ 0` 且 `已通知数量 ≥ 订单量` | `aggregates.stockOutRequests`（跳过 status=-1 已取消）→ `StockOutNotifyDetail` |

主表须 `salesOrderMainAllowsPurchaseAndStockOut(orderStatus)`（审核通过 / 进行中 / 完成）。

## 4. 数据来源

### 4.1 总览

| 数据块 | 主要来源 | 补充来源 |
|--------|----------|----------|
| 订单明细卡片 | 列表行 `row` | — |
| 备货库存 | 聚合接口 `aggregates.stockItems` | — |
| 使用备货 | 聚合接口 `aggregates.stockingUsage` | — |
| 采购申请数量 | 列表行 `purchaseRemainingQty`、`purchaseProgressStatus` | `lineOverview.purchaseRequisition`；单号用 `purchaseRequisitions` |
| 出库通知数量 | 列表行 `stockOutNotifyProgressStatus` 等 | `lineOverview.stockOutNotify`；单号用 `stockOutRequests` |
| 按钮禁用 / 提示 | 列表行（与操作列共用 utils） | — |

### 4.2 聚合接口

```
GET /api/v1/sales-orders/{orderId}/sell-order-items/{sellOrderItemId}/detail-tab-aggregates
```

- 与销售订单 **详情页** 单条明细 aggregates **同一 DTO**（`SalesOrderDetailTabAggregates`）。
- 列表操作面板主要使用：`stockItems`、`stockingUsage`（使用备货）、`lineOverview`（采购申请/出库通知 done、pending）、`purchaseRequisitions` / `stockOutRequests`（完成态单号）。
- **非**列表行数据的本地纯转换；库存与 lineOverview 依赖该接口。

### 4.3 列表接口补充字段

列表 `getItemLines` 行 DTO（`SellOrderItemLineDto`）需包含操作判断字段，例如：

- `customerEnglishName`（客户 `EnglishOfficialName`）
- `purchaseRemainingQty`、`purchaseProgressStatus`
- `stockOutNotifyProgressStatus`、`stockOutApplyPurchaseGateOk` 等

后端：`SalesOrderService.HydrateSellOrderLineListCustomerEnglishAsync`；控制器按客户可见性脱敏。

## 9. 测试与回归要点

交互门控（§2.4 A～F）以 QA 文档为准：[销售订单明细列表-操作面板-测试对照说明](../QA/销售/销售订单明细列表-操作面板-测试对照说明.md)。

其余功能回归：

1. 进入列表后右栏有 **操作 + 帮助**；其他页面仅 **帮助**。
2. 右栏已展开且为「操作」时切换行：每次请求新 `sellOrderItemId` 的 aggregates。
3. 总计库存为 0：不显示备货库存卡片。
4. 无备货补充拣货记录：不显示「使用备货」卡片；有记录时按 PO 分行，采购单号可跳转详情。
5. 客户英文名为空：订单明细卡片无英文行。
6. 采购/出库全部完成：标题「已完成」+ 绿勾，无按钮、无进度条；指标下展示可点击的采购申请单号 / 出库通知单号（对齐申请付款卡片）。
7. 采购/出库未完成：按钮可用为深蓝，不可用为灰色；禁用提示与列表操作列一致；已有单据时仍可展示单号。
8. 申请采购/出库成功后 `loadList` + 面板数据刷新。
9. 脱敏开启：仍可加载面板；敏感字段为 `—`；无权限按钮按角色隐藏/禁用。
10. 窄右栏宽度：无横向滚动条，文本可换行。
11. 双击仍进详情。
12. **布局（§2.5）：** 状态标签区为 3 列网格；仅 1 个标签时不拉满整行。「使用备货」等为双列 Key:Value。
