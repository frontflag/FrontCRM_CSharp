# 销售订单明细列表 · 右侧「操作」面板 — 功能要求与实现说明

本文描述 **FrontCRM（CRM.Core / CRM.API / CRM.Web）** 中 **销售订单明细列表页**（`SalesOrderItemList`）右侧工作区辅助栏 **「操作」** 页签的设计要求与实现方法。与 [销售订单明细列表-设计与实现](销售订单明细列表-设计与实现.md)（列表列、筛选、**采购员列**）、[销售订单明细概况-设计与实现](销售订单明细概况-设计与实现.md)（详情页底部概况矩阵）、[系统设计规范](系统设计规范.md)、`help/pages/销售订单明细_MENU_SALES_ORDER_ITEMS.md` 交叉引用。

---

## 1. 业务定位

| 概念 | 说明 |
|------|------|
| **适用页面** | 销售订单明细列表 `/sales-order-items`（`SalesOrderItemList`）、销售订单详情 `/sales-orders/:id`（`SalesOrderDetail`） |
| **展示位置** | `AppLayout` 右侧辅助栏（`aux-right`），与 **「帮助」** 页签并列 |
| **页签 ID** | `r-ops`（文案 i18n：`layout.auxTabs.ops` → 中文「操作」） |
| **目标** | 单击列表行后，在不离开列表的前提下查看该行摘要、备货库存、**使用备货**（若有），并发起 **申请采购** / **申请出库**；详情页单击订单明细行时同步展示同一操作面板 |
| **与详情页概况区别** | 详情页底部为 4×10 全链路矩阵；右侧操作面板为 **4～5 张卡片**（订单明细 / 备货库存 / **使用备货**（条件）/ 采购申请 / 出库通知），侧重日常操作 |

**在销售订单明细列表或销售订单详情路由下** 注册双页签（操作 + 帮助），默认选中 **操作**；两页共用 `SalesOrderItemOpsPanel` + `salesOrderItemOpsPanel` store。离开上述路由时恢复仅「帮助」，并 `clear()` 操作面板 store。

## 2. 布局与交互要求

### 2.1 整体结构

```
┌─ 右侧辅助栏 ─────────────────────────┐
│ [操作] [帮助]              [全屏][✕] │
├──────────────────────────────────────┤
│  （无选中行）单击列表行查看…          │
│  或                                  │
│  ┌ 订单明细 ─────────────────────┐   │
│  ├ 备货库存（条件显示）──────────┤   │
│  ├ 使用备货（条件显示）──────────┤   │
│  ├ 采购申请 ──────────── 已完成 ✓│   │
│  └ 出库通知 ─────────────────────┘   │
└──────────────────────────────────────┘
```

- 四个区块 **直接作为页签内容子级** 纵向排列，无额外浮动外层壳；宽度 `100%` 自适应父面板，禁止横向滚动。
- 嵌入模式（`embedded`）使用 `div.so-item-ops-root--embedded`，样式 token 对齐 `--crm-aux-*`。
- 各卡片 **无标题图标**，仅保留文字标题。

### 2.2 列表交互

| 操作 | 行为 |
|------|------|
| **单击行** | 选中行；切换右栏至「操作」；若右栏已展开则拉取聚合数据；若右栏收起则 **仅记录行**，展开后再拉取 |
| **双击行** | 跳转销售订单详情 `SalesOrderDetail`（与改造前一致，优先级高于单击） |
| **选中行高亮** | 表格 `row-class-name`：`so-item-row--active` |
| **敏感字段脱敏** | `maskSaleSensitiveFields === true` 时：不响应单击、清空 store |

### 2.3 右栏展开 / 收起与接口

**混合数据源 + 按需请求**（见 §4）：

| 场景 | 行为 |
|------|------|
| 右栏 **已展开**，单击行 | `selectRow` → 更新行 + 请求 `detail-tab-aggregates` |
| 右栏 **收起**，单击行 | `setRowOnly` → **不请求**；`toggleRightPanel(true)` 展开 |
| 右栏由收起变为展开 | `watch(rightPanelVisible)` → 若已有选中行则 `loadAggregates` |
| 列表 `loadList` 刷新 | 右栏展开：同步行并重新请求；收起：仅 `setRowOnly` 更新行对象 |
| 离开列表路由 | `salesOrderItemOpsStore.clear()` |

## 3. 四张卡片 — 功能与 UI 要求

### 3.1 订单明细

**标题：**「订单明细」（非「概况」）

**展示规则：** 去掉 Key 标签，仅左对齐 Value 文本行：

| 顺序 | 内容 | 样式 |
|------|------|------|
| 1 | `sellOrderItemCode` | 琥珀色 `$color-amber`，18px 加粗 |
| 2 | 客户中文名 | 13px，常规 |
| 3 | 客户英文名 | **无内容整行隐藏**（`customerEnglishName` 空或脱敏） |
| 4 | PN | 常规 |
| 5 | 品牌 | 常规 |
| 6 | 销售单价 + 币别 | `formatUnitPriceWithCurrencyCodeSuffix(price, currency)`，如 `1.234567 USD` |
| 7 | 数量 | `{qty} pcs`，**不加粗、不用强调色** |

**数据来源：** 列表行 `row`（含列表 API 下发的 `customerEnglishName`，后端 `HydrateSellOrderLineListCustomerEnglishAsync` 填充）。

### 3.2 备货库存

**显示条件：** `总计库存 > 0`，否则 **整张卡片不渲染**。

| 字段 | 标签 | 数据 |
|------|------|------|
| 大陆仓 | `stockDomestic` | `regionType ≠ 海外` 的备货池可用量合计 |
| 海外仓 | `stockOverseas` | `regionType = 海外(20)` 合计 |
| 总计库存 | `stockTotal` | 大陆 + 海外 |

**备货池判定：** `stockType === 2` 或 `isStockingPoolMatch === true`；数量字段 `qtyRepertoryAvailable`。

**实现：** `summarizeStockingByRegion(aggregates.stockItems)`（`utils/sellOrderItemOpsPanel.ts`）。

### 3.3 使用备货

**显示条件（方案 A）：** 仅当存在备货使用记录时显示整张卡片（`aggregates.stockingUsage.items.length > 0`），否则 **不渲染**。

**位置：** 夹在 **「备货库存」** 与 **「采购申请」** 之间；与「备货库存」**并存**（地域汇总卡片保留）。

**分组口径：** 按 **采购主单** `purchaseOrderId` 汇总；同一 PO 下多条备货补充拣货合并为一行。

**使用数量口径（A1）：** `SUM(PickedQty)`，其中 `pickingtaskitem.IsStockingSupplement = true` 且 `PickedQty > 0`（**含已拣未出库**）。

| 字段 | 标签 | 数据 |
|------|------|------|
| 采购单号 | `stockingUsagePoCode` | `purchaseOrderCode`；可链 `PurchaseOrderDetail` |
| 生成日期 | `stockingUsagePoDate` | `PurchaseOrder.CreateTime`（日期部分） |
| 采购员 | `stockingUsagePurchaser` | `PurchaseOrder.PurchaseUserName` |
| 使用数量 | `stockingUsageQty` | 该 PO 下汇总 `usedQty`；强调色 |

**数据链路：**

```text
sellOrderItemId
  → packing_item（SellOrderItemId 或 StockOutNotifyId）
  → pickingtaskitem（IsStockingSupplement=true, PickedQty>0, PackingItemId）
  → stock_item → purchase_order_item → purchase_order
  → GROUP BY purchaseOrderId
```

**业务参考：** [销售订单使用采购备货-业务逻辑](采购备货/销售订单使用采购备货-业务逻辑.md)（备货池快照 vs 本卡片「实际使用记录」为不同口径）。

### 3.4 采购申请

| 元素 | 要求 |
|------|------|
| 指标 | 已申请数量 / 可申请数量（两列） |
| 进度条 | 高度 **10px**；已申请/订单量；红色渐变；**不显示**「xx% 完成度」文案 |
| 状态文案 | **不显示**「当前可申请」；仅在禁用时显示 `purchaseDisabledHint` |
| 禁用提示 | 与列表操作列一致（`applyPurchaseDisabledHint.ts`）：摘要 + 明细列表 + `nextStep` |
| 按钮 | 权限 `purchase-requisition.write` 或 `sales-order.write`；文案「申请采购」 |
| 按钮样式 | 可用：深蓝 `#0f4c81`；不可用：灰底 `#e5e7eb` |
| **已完成** | 见 §3.5 |

**进度：** `purchaseAppliedQty / orderQty`；已申请优先 `lineOverview.purchaseRequisition.done`，否则由 `purchaseRemainingQty` 反推。

### 3.5 出库通知

| 元素 | 要求 |
|------|------|
| 指标 | 已通知数量 / 可通知数量 |
| 进度条 | 10px 高；蓝色渐变；无完成度百分比文案 |
| 状态文案 | 不显示「当前可申请」；禁用时 `stockOutDisabledHint`（含采购门槛 PO 明细） |
| 按钮 | 权限 `sales-order.write`；文案「申请出库」 |
| 按钮样式 | 同采购申请（可用深蓝 / 不可用灰色） |
| **已完成** | 见 §3.5 |

**进度：** `stockOutNotifiedQty / orderQty`；已通知/可通知优先 `lineOverview.stockOutNotify.done/pending`。

**按钮禁用口径：** `salesOrderLineApplyStockOutButtonDisabled`（与列表一致）。

### 3.6 「已完成」态（采购申请 / 出库通知）

标题栏 **右侧** 显示绿色对钩（`CircleCheck`）+ 文案「已完成」；**隐藏**操作按钮及禁用提示。

| 卡片 | 判定条件（满足其一且主表允许操作） |
|------|-----------------------------------|
| 采购申请 | `purchaseProgressStatus === 2`；或 `可申请数量 ≤ 0` 且 `已申请数量 ≥ 订单量` |
| 出库通知 | `stockOutNotifyProgressStatus === 2`；或 `可通知数量 ≤ 0` 且 `已通知数量 ≥ 订单量` |

主表须 `salesOrderMainAllowsPurchaseAndStockOut(orderStatus)`（审核通过 / 进行中 / 完成）。

## 4. 数据来源

### 4.1 总览

| 数据块 | 主要来源 | 补充来源 |
|--------|----------|----------|
| 订单明细卡片 | 列表行 `row` | — |
| 备货库存 | 聚合接口 `aggregates.stockItems` | — |
| 使用备货 | 聚合接口 `aggregates.stockingUsage` | — |
| 采购申请数量 | 列表行 `purchaseRemainingQty`、`purchaseProgressStatus` | `lineOverview.purchaseRequisition` |
| 出库通知数量 | 列表行 `stockOutNotifyProgressStatus` 等 | `lineOverview.stockOutNotify` |
| 按钮禁用 / 提示 | 列表行（与操作列共用 utils） | — |

### 4.2 聚合接口

```
GET /api/v1/sales-orders/{orderId}/sell-order-items/{sellOrderItemId}/detail-tab-aggregates
```

- 与销售订单 **详情页** 单条明细 aggregates **同一 DTO**（`SalesOrderDetailTabAggregates`）。
- 列表操作面板主要使用：`stockItems`、`stockingUsage`（使用备货）、`lineOverview`（采购申请/出库通知 done、pending）。
- **非**列表行数据的本地纯转换；库存与 lineOverview 依赖该接口。

### 4.3 列表接口补充字段

列表 `getItemLines` 行 DTO（`SellOrderItemLineDto`）需包含操作判断字段，例如：

- `customerEnglishName`（客户 `EnglishOfficialName`）
- `purchaseRemainingQty`、`purchaseProgressStatus`
- `stockOutNotifyProgressStatus`、`stockOutApplyPurchaseGateOk` 等

后端：`SalesOrderService.HydrateSellOrderLineListCustomerEnglishAsync`；控制器按客户可见性脱敏。

## 5. 权限

| 能力 | RBAC |
|------|------|
| 查看操作面板 | `sales-order.read`（随列表） |
| 客户名 / 英文名 | `customer.info.read` 或 `sales-order.read`；脱敏时面板不可用 |
| 申请采购按钮 | `purchase-requisition.write` **或** `sales-order.write` |
| 申请出库按钮 | `sales-order.write`（`useSaleOrderWriteGate`） |

按钮点击通过 store **注册回调** 回列表页执行：`applyPurchaseOne` → 采购申请弹窗；`applyStockOutOne` → `ApplyStockOutDialog`。

## 6. 前端实现架构

### 6.1 文件职责

| 文件 | 职责 |
|------|------|
| `CRM.Web/src/layouts/AppLayout.vue` | 路由 `SalesOrderItemList` 时注册 `r-ops` + `r4`；渲染 `SalesOrderItemOpsPanel`（`embedded`）；离开路由 `clear()` |
| `CRM.Web/src/components/RFQ/SalesOrderItemOpsPanel.vue` | 4～5 卡片 UI、计算属性、样式 |
| `CRM.Web/src/stores/salesOrderItemOpsPanel.ts` | 选中行、`aggregates`、加载态；`setRowOnly` / `loadAggregates` / `selectRow` |
| `CRM.Web/src/views/RFQ/SalesOrderItemList.vue` | 行点击、右栏联动、`refreshOpsPanelIfOpen`、handler 注册 |
| `CRM.Web/src/composables/useWorkspaceLayout.ts` | `rightPanelVisible`、`setRightActiveTab`、`toggleRightPanel`；`inject(WorkspaceLayoutKey)` |
| `CRM.Web/src/utils/sellOrderItemOpsPanel.ts` | 备货分区汇总、进度百分比 |
| `CRM.Web/src/utils/applyPurchaseDisabledHint.ts` | 采购禁用提示（与列表一致） |
| `CRM.Web/src/utils/applyStockOutDisabledHint.ts` | 出库禁用提示（与列表一致） |
| `CRM.Web/src/locales/zh-CN.ts` / `en-US.ts` | `salesOrderItemList.opsPanel.*`、`layout.auxTabs.ops` |

### 6.2 Store API

```typescript
// stores/salesOrderItemOpsPanel.ts
setRowOnly(row)        // 仅记录列表行，不请求 API
loadAggregates(text)   // 按当前 row 请求 detail-tab-aggregates（同 key 已加载则跳过）
selectRow(row, text)   // setRowOnly + loadAggregates
refreshFromListRows(rows, text, fetchAggregates)
clear()
registerHandlers({ applyPurchase, applyStockOut })
```

`aggregatesRowKey` 用于避免重复请求；`loadSeq` 防止竞态覆盖。

### 6.3 列表页关键逻辑

```typescript
// SalesOrderItemList.vue — onRowClick
if (isRightPanelVisible()) {
  await store.selectRow(row, ...)
} else {
  store.setRowOnly(row)
  workspaceLayout.toggleRightPanel(true)  // 展开后 watch 触发 loadAggregates
}

// watch rightPanelVisible: false → true 且 route 为列表 → loadAggregates
```

### 6.4 组件 Props / 事件

`SalesOrderItemOpsPanel` 由 `AppLayout` 注入：

- `row`、`aggregates`、`loading`、`loadError`（来自 store）
- `maskSensitive`、`canPurchaseReq`、`canWriteSo`
- `embedded`（固定 `true`）
- 事件：`apply-purchase` / `apply-stock-out` → store `runApplyPurchase` / `runApplyStockOut`

## 9. 测试与回归要点

1. 进入列表后右栏有 **操作 + 帮助**；其他页面仅 **帮助**。
2. 单击行：展开右栏、操作页签、高亮行；双击仍进详情。
3. **右栏收起**时单击：Network **无** `detail-tab-aggregates`；展开后出现请求。
4. 右栏已展开时切换行：每次请求新 `sellOrderItemId` 的 aggregates。
5. 总计库存为 0：不显示备货库存卡片。
6. 无备货补充拣货记录：不显示「使用备货」卡片；有记录时按 PO 分行，采购单号可跳转详情。
7. 客户英文名为空：订单明细卡片无英文行。
8. 采购/出库全部完成：标题「已完成」+ 绿勾，无按钮，无禁用长文案。
9. 采购/出库未完成：按钮可用为深蓝，不可用为灰色；禁用提示与列表操作列一致。
10. 申请采购/出库成功后 `loadList` + 面板数据刷新。
11. 脱敏开启：单击无效，store 清空。
12. 窄右栏宽度：无横向滚动条，文本可换行。
