## 1. 背景与目标

复用历史 `assign_method = 4`（原「指定采购员」，现文案 **指定采购**）：创建/编辑需求时整单指定同一位报价员。为避免新建页默认就要选人，该选项**默认不出现**，须在采购参数勾选 **允许指定采购** 后才进入「分配方式」下拉。

---

## 2. 产品规则

### 2.1 门控（允许指定采购）

| 项 | 口径 |
|----|------|
| 入口 | 参数管理 → 采购参数 → **默认分配方式** |
| 控件 | 勾选 **允许指定采购**（与「默认分配方式」下拉同一页、同一保存） |
| 参数 | `System.RFQ.AllowDesignatedPurchaser`，Boolean，**默认 false**（未配置视为关闭） |
| 开启后 | 新建/编辑需求「分配方式」下拉**最后一项**出现「指定采购」 |
| 关闭后 | 新建页不下发该项；已是指定采购的编辑页**仍显示当前项**（避免下拉空白），但不能把其它方式改成指定采购 |
| 默认分配方式下拉 | 仍只允许 2 / 3 / 5，**永不包含**指定采购 |

详情「分配采购员」（整单再分配会把主单写成 4）**不受本开关限制**。入口：采购部/采购运营部总监，或 SuperAdmin / Admin / Manager（`HasBizDataBypass`）。不得只认 SuperAdmin 或仅采购运营身份。

### 2.2 创建 / 编辑表单

选中「指定采购」后，分配方式右侧出现必填 **分配采购**（红星 + 中文「请选择分配采购」）。

| 项 | 口径 |
|----|------|
| 名单 | 采购参数「报价员池」已勾选且在职；`GET /api/v1/rfqs/quoter-pool-options`（`rfq.create` 或 `rfq.write`，不要求采购参数权限） |
| 人数 | **忽略**「报价人数」N；每条明细只写槽位 1，槽位 2 为空 |
| 编辑加明细 | 主单已是 4 时沿用该人，不必再选 |
| 编辑改成 4 | 须开关已开；与新建同一套必填下拉；**不重分已有明细** |
| 复制 / 草稿 | 带出该人；已不在池则清空并提示重选 |

### 2.3 后端硬拒绝

| 场景 | 结果 |
|------|------|
| 创建 `assign_method=4` 且开关关闭 | `ArgumentException`：「未开启指定采购」 |
| 编辑从非 4 改为 4 且开关关闭 | 同上 |
| 编辑保持 4（含加明细沿用原人） | 允许，即使开关已关 |
| 指定采购但未选人 | 「请选择分配采购」 |
| 所选人不在报价员池（创建，或改成新人） | 文案含报价员池 |
| 编辑沿用原人且该人已不在池 | 允许（`AllowDesignatedPurchaserOutsidePool`） |

## 3. 实现

### 3.1 参数与采购参数页

| 组件 | 路径 |
|------|------|
| 参数码 | `SysParamCodes.RfqAllowDesignatedPurchaser` |
| 读写 | `IPurchaseQuoterPoolService.Get/SetAllowDesignatedPurchaserAsync` |
| 规则 | `RfqDesignatedPurchaserRules`（未开启文案） |
| 页面 | `CRM.Web/src/views/System/PurchaseDefaultAssignMethodSettings.vue` |
| 可选补齐脚本 | `scripts/ensure_rfq_allow_designated_purchaser_postgresql.sql` |

未配置时 GET 为 false；采购参数页首次保存自动建行。无新权限码（沿用 `system.params.purchase.default-assign-method.read/write`）。

### 3.2 API

| 用途 | 方法 | 路径 | 权限 |
|------|------|------|------|
| 采购参数读写（`assignMethod` + `allowDesignatedPurchaser`） | GET/PUT | `/api/v1/purchase-params/default-assign-method` | `system.params.purchase.default-assign-method.read` / `.write` |
| 新建/编辑页读默认方式与开关 | GET | `/api/v1/rfqs/default-assign-method` | `rfq.create` 或 `rfq.write` |
| 分配采购名单 | GET | `/api/v1/rfqs/quoter-pool-options` | `rfq.create` 或 `rfq.write` |

DTO：`PurchaseParamsDefaultAssignMethodDto` / `SetPurchaseParamsDefaultAssignMethodRequest`。

### 3.3 策略与需求服务

```
RFQService.CreateAsync / UpdateAsync
    → 创建选 4、或从非 4 改为 4：EnsureDesignatedPurchaserEnabledAsync
    → RfqPurchaserAssignmentOrchestrator
        → assign_method=4 → DesignatedPurchaserAssignStrategy
            → 校验报价员池（或允许沿用出池原人）
            → 全部明细槽位 1 = 所选人，槽位 2 = null
```

| 组件 | 路径 |
|------|------|
| 策略 | `CRM.Core/Services/RfqAssignment/DesignatedPurchaserAssignStrategy.cs` |
| 创建/编辑入参 | `CreateRFQRequest.AssignedPurchaserUserId` / `UpdateRFQRequest.AssignedPurchaserUserId` |
| 门控 | `RFQService.EnsureDesignatedPurchaserEnabledAsync` |

DI：策略已在 `ServiceExtensions` 注册。部署 API 后须重启。

### 3.4 前端

| 位置 | 文件 |
|------|------|
| 下拉全集（4 在最后） | `CRM.Web/src/constants/rfqFormEnums.ts` → `ASSIGN_METHOD_OPTIONS` |
| 默认参数页选项（不含 4） | 同文件 `DEFAULT_ASSIGN_METHOD_OPTIONS` |
| 创建/编辑 | `RFQCreate.vue`：`assignMethodOptions` = 开关开 **或** 当前已是 4 时才含指定采购 |
| 采购参数 API | `CRM.Web/src/api/purchaseParams.ts` |
| 需求页读开关 | `CRM.Web/src/api/rfq.ts` → `getDefaultAssignMethod()` |

### 3.5 测试

| 测试类 | 覆盖 |
|--------|------|
| `DesignatedPurchaserAssignStrategyTests` | 只写槽位 1、不在池拒绝、沿用原人可出池 |
| `RfqDesignatedPurchaserRulesTests` | 开关关闭抛「未开启指定采购」 |
| `RFQServiceTests` | 创建指定采购写全行；未选人；开关关闭创建/改方式拒绝；已是 4 时关闭开关仍可保存 |
| `RfqDefaultAssignMethodRulesTests` | 默认分配方式合法值不含 4 |
