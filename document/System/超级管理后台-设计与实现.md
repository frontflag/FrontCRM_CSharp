# 超级管理后台 — 设计方案（待确认）

**状态：** 草案 / 待产品确认（确认前不开工实现）  
**关联现状：** FrontCRM 各客户站内已有运维（系统错误、用户反馈）、系统管理、参数管理；尚无跨站控制面  
**粒度定稿：** **多租户 / 多客户站**（非仅 dev/uat/prod）

---

## 0. 已定稿决策

| # | 议题 | 定稿 |
|---|------|------|
| 1 | 多「生产系统」粒度 | **多租户 / 多客户站**（每站独立部署、独立业务库、独立业务登录） |
| 2 | 配置冲突策略 | **本地可 override**（超级后台下发为基线；站点本地修改优先生效，且不被下次全量覆盖冲掉） |
| 3 | 运维汇聚方式 | **定时同步**（拉取增量） |
| 4 | 是否从超级后台点进某站详情 | **否**（不调生产站详情 API；总控只看已汇聚副本） |
| 5 | 第一期（MVP）范围 | **站点注册 + 公告下发 + 报错/反馈汇聚只读**；角色 / 字典 / 品牌同步 → **第二期** |
| 6 | 部署形态（前期共识） | **独立数据库、独立域名与界面、独立登录账号** |

---

## 1. 目标与非目标

### 1.1 目标

为一个超级管理后台，统一治理 **多个 FrontCRM 客户站**：

| 能力域 | 远期 | MVP |
|--------|------|-----|
| 统一参数（角色权限模板、字典、安全设置等） | 第二期+ | 不做 |
| 统一业务参数（如品牌） | 第二期 | 不做 |
| 统一运维（系统报错、用户建议、上线功能发布公告） | 报错/反馈汇聚 + 公告下发 | ✅ |

### 1.2 非目标（MVP）

- 不取代各客户站内的业务操作与本站运维菜单（站内「系统错误 / 用户反馈」**保留**）
- 不做中央权限真相源、不做运行时直读超级库
- 超级后台 **不** SSO 进客户站、**不**代理打开站内详情页
- 不做跨站改单、远程登录业务用户

---

## 2. 总体架构

```text
┌─────────────────────────────────────┐
│  超级管理后台（独立域名 / 独立库 / 独立账号） │
│  · 站点注册与凭证                         │
│  · 公告编辑与下发任务                      │
│  · 报错 / 反馈汇聚只读列表与详情（本地副本）   │
└───────────────┬─────────────────────┘
                │ 定时拉取（增量）
                │ 公告下发（推送，见 §5）
     ┌──────────┼──────────┐
     ▼          ▼          ▼
  客户站 A    客户站 B    客户站 C
  (业务库)    (业务库)    (业务库)
```

| 层次 | 职责 |
|------|------|
| 超级库 | 站点元数据、同步水位、汇聚副本、公告主数据与下发状态、超管账号 |
| 客户站库 | 继续承担业务 + 本站 `sys_error_log` / `user_feedback` + 本站已接收公告 |

**模式归纳：** 运维 = **汇聚（C）**；公告 = **下发**；参数类（二期）= **基线下发 + 本地 override（A）**。

## 3. MVP 功能说明

### 3.1 站点注册

超级后台维护「客户站」清单，建议字段：

| 字段 | 说明 |
|------|------|
| `SiteCode` | 稳定编码（如 `semicore` / `idesemi`） |
| `DisplayName` | 展示名 |
| `BaseApiUrl` | 该站 FrontCRM API 根地址（供定时拉取 / 公告推送） |
| `SyncCredential` | 站间服务凭证（见 §6，不落业务用户密码） |
| `Enabled` | 是否参与同步/下发 |
| `LastSyncAt` / `LastSyncStatus` | 运维可见 |

### 3.2 公告下发

| 项 | 方案 |
|----|------|
| 编辑 | 在超级后台撰写标题、正文、生效时间、是否强制置顶等 |
| 下发 | 超级后台 **推送** 到各目标站「接收公告」API（可多选站点） |
| 站内展示 | 各站沿用/对接现有版本公告或通知能力（实现阶段对齐现有 Release Notes / 通知） |
| 失败 | 按下发任务记录成功/失败；支持对失败站重试 |

> 公告与「字典/品牌」不同：公告以总控为权威源，站点侧以接收副本展示，**不做本地改文案 override**（仅可本站已读/关闭类状态）。

### 3.3 报错 / 反馈汇聚（只读）

| 项 | 方案 |
|----|------|
| 方向 | 超级后台定时 **拉取** 各站增量 |
| 存储 | 超级库保存 **足够运维阅读的完整副本**（因不允许再进站详情） |
| 列表维度 | 必须带 `SiteCode` / 站点名；错误编号展示为站内原号（如 `E-12`），列表可显示 `站点 + E-12` |
| 操作 | MVP **只读**（不在总控标记已处理；处理仍在各站完成，或二期再做「总控标记并回写」） |
| 同步内容（报错） | 发生时间、模块、摘要、详情/堆栈、路径、用户、是否已处理、原 Id 等 |
| 同步内容（反馈） | 类型、标题/摘要、状态、提交人、时间、原 Id；附件以 **元数据 + 可访问策略** 另定（见 §7 拟默认） |

**默认同步间隔（待确认）：** 5 分钟；支持手动「立即同步」。

---

## 4. 第二期（确认后另开设计，此处仅边界）

- 权限/角色 **模板**、数据字典、安全设置、品牌等：超级后台维护基线 → 下发到站  
- **本地可 override：** 站点字段级或记录级标记「本地覆盖」后，后续基线同步 **跳过** 这些项  
- 仍不建议做成运行时直读超级库  

---

## 5. 同步与下发协议（MVP 要点）

### 5.1 拉取（报错 / 反馈）

- 各客户站提供 **只读增量 API**（需服务凭证），参数示例：`since`（水位时间或 Id）、`page`  
- 超级后台按站记录水位；失败告警（任务状态），下次继续  
- 幂等键：`(SiteCode, SourceTable, SourceId)`  

### 5.2 推送（公告）

- 超级后台调用各站「upsert 公告」API  
- 站内以 `CentralAnnouncementId`（或等价）去重  

### 5.3 明确不做（MVP）

- 超级后台 **不** 调用站内「按 Id 取详情」供人点击钻取（与定稿一致）  
- 因此首次同步即须拉齐详情字段，而非只拉列表摘要  

---

## 6. 安全

| 项 | 方案 |
|----|------|
| 超管登录 | 独立账号体系；与各站业务用户隔离 |
| 站间调用 | 每站颁发 **Site Sync API Key**（或 mTLS，实现期二选一；MVP 倾向 API Key + IP 允许列表） |
| 传输 | HTTPS |
| 最小权限 | 站侧仅开放：增量读报错/反馈、接收公告；**无**业务写接口暴露给总控 |

## 7. 拟默认项（请一并确认或改口）

下列未在你方四条答复中覆盖，方案中按默认写入；确认方案时请勾选或修改：

| # | 项 | 拟默认 |
|---|----|--------|
| D1 | 同步间隔 | **5 分钟** + 手动立即同步 |
| D2 | 总控是否「标记已处理」 | MVP **否**（只读）；处理在各站 |
| D3 | 反馈附件 | MVP 同步 **附件元数据**（文件名/类型）；二进制文件 **不同步** 到超级库（总控详情显示「请到对应客户站查看附件」） |
| D4 | 各站原有运维菜单 | **保留**（本站值班仍可用） |
| D5 | 公告站内载体 | 优先对接现有「版本更新 / 通知」能力，避免再造第三套公告 UI（实现期评估） |
| D6 | 站点编码 | 与现有登录租户品牌 Id 对齐（如有），便于运维识别 |

若 D3 改为「附件也要进总控」，则需对象存储或文件中转，MVP 成本明显上升。

## 8. 工程形态（确认后实施）

建议独立解决方案/仓库边界（名称可再定）：

| 组件 | 说明 |
|------|------|
| `SuperAdmin.Api` | 超管 API + 定时同步 Job |
| `SuperAdmin.Web` | 独立前端 |
| `SuperAdmin` DB | PostgreSQL 独立库 |
| FrontCRM 各站 | 增加「同步读出 + 公告接收」薄 API，及服务凭证配置 |

本仓库 FrontCRM 侧改动以 **站间契约** 为主，避免把超管 UI 塞进现有 `CRM.Web`。

---

## 9. 验收口径（MVP）

1. 超管可注册 ≥2 个客户站并配置凭证  
2. 某站产生系统错误 / 用户反馈后，在同步间隔内出现在超管列表，且 **详情不依赖再调该站**  
3. 超管发布公告并选择站点后，目标站用户可见  
4. 超管账号无法登录客户站业务系统；业务账号无法登录超管  
5. 超管界面无「打开站点详情」类跳转（符合定稿）
