# 销售订单明细概况 — 功能要求与实现说明

本文描述 **FrontCRM（CRM.Core / CRM.API / CRM.Web）** 中「销售订单明细概况」页签的业务口径、功能要求、数据计算与代码索引。与 [业务逻辑与数据关系文档](业务逻辑与数据关系文档.md)、[采购订单明细概况-设计与实现](采购订单明细概况-设计与实现.md)、[收款核销-设计与实现](财务/收款核销-设计与实现.md)、[财务 Phase 1 操作手册](../EBS/财务/财务Phase1操作手册.md)、[业务详情页面规范](../PRD/规范/UI规范/业务详情页面规范.md) §7.4 交叉引用。

## 1. 业务定位

销售订单详情页底部 **「销售订单明细详情」** 面板，在选中某条销售明细后，用 **概况** 页签以 **4 行 × 10 列** 矩阵快速展示该行从采购到收款的执行进度，无需逐个切换下游 Tab。

| 概念 | 说明 |
|------|------|
| **适用对象** | 单条 `sell_order_item`（销售订单明细行） |
| **展示形态** | 矩阵表：行 = 总数 / 已执行 / 待处理；列 = 基准信息 + 7 个执行环节 + 2 个金额环节 |
| **与其他 Tab 关系** | 概况为 **汇总快照**；各下游 Tab（采购申请、入库、收款核销等）仍为 **明细列表**，二者互补 |
| **与绩效分工** | 概况管 **执行进度**；**绩效**面板在明细详情面板正下方独立展示 **三层利润**，见 [销售订单明细绩效-设计与实现](销售/销售订单明细绩效-设计与实现.md) |
| **默认 Tab** | 单击或双击订单明细行打开面板时，默认激活 **概况** |

## 2. 功能要求

### 2.1 入口与交互

| 入口 | 路径 / 操作 | 说明 |
|------|-------------|------|
| 销售订单详情 | `/sales-orders/:id` → 主 Tab「订单明细」→ 单击/双击某行 | 展开底部「销售订单明细详情」面板，默认 **概况** |
| 页签顺序 | 概况为 **第一个** Tab，其后为需求明细、报价、采购申请… | 与 i18n `salesOrderDetailView.tabs.overview` 一致 |

**交互规则：**

- 面板标题展示 `销售订单明细详情` + 明细编号（`sellOrderItemCode`）；
- 概况无分页；数据随 `detail-tab-aggregates` 一次性返回；
- 无 `lineOverview` 时显示空状态文案（`overview.empty`）；
- 敏感字段脱敏开启时（`maskSaleSensitiveFields`），整个明细详情面板不展示（含概况）。

### 2.2 矩阵结构

```
              │ 销售明细总额 │ 销售明细数量 │ 采购申请 │ 采购订单明细 │ 入库 │ 出库申请 │ 出库 │ 收款核销 │ 销项发票 │
──────────────┼─────────────┼─────────────┼─────────┼─────────────┼──────┼─────────┼──────┼─────────┼──────┤
总数          │  …          │  …          │  qty    │  qty        │ qty  │ qty     │ qty  │ 金额+币别│ 金额+币别│
已执行        │  —          │  —          │  …      │  …          │ …    │ …       │ …    │ …       │ …    │
待处理        │  —          │  —          │  …      │  …          │ …    │ …       │ …    │ …       │ …    │
```

**行规则：**

| 行 | 说明 |
|----|------|
| **总数** | 该列的业务目标量：数量为销售行 `qty`；金额为行全额 `qty × price`（含币别） |
| **已执行** | 该环节已完成量 |
| **待处理** | 剩余待完成量（一般 = 总数 − 已执行；采购申请超量时见 §3.2） |

**列规则：**

| 列 | 单位 | 总数 | 已执行 | 待处理 | 列标题着色 |
|----|------|------|--------|--------|------------|
| 销售订单明细总额 | 金额 + 币别 | `qty × price` | `—` | `—` | 不着色 |
| 销售订单明细数量 | 数量 | `qty` | `—` | `—` | 不着色 |
| 采购申请 | 数量 | `qty` | 有效 PR 数量合计 | `max(0, qty − PR合计)` | 着色 |
| 采购订单明细 | 数量 | `qty` | `QtyAlreadyPurchased` | `QtyNotPurchase` | 着色 |
| 入库 | 数量 | `qty` | 已完成采购入库数量 | `qty − 已入库` | 着色 |
| 出库申请 | 数量 | `qty` | `QtyStockOutNotify` | `QtyStockOutNotifyNot` | 着色 |
| 出库 | 数量 | `qty` | `QtyStockOutActual` | `qty − 已出库` | 着色 |
| 收款核销 | 金额 + 币别 | `ReceiptAmount` | `ReceiptAmountFinish` | `ReceiptAmountNot` | 着色 |
| 销项发票 | 金额 + 币别 | `InvoiceAmount` | `InvoiceAmountFinish` | `InvoiceAmountNot` | 着色 |

### 2.3 列标题状态配色（仅标题文字）

对 **参与进度统计的 7 列**（采购申请～销项发票），根据 **已执行 vs 总数** 为列标题 **文字** 着色；**格子底色** 与第一列行标题一致，不加粗。

| 条件 | 标题文字色 | 语义 |
|------|------------|------|
| 已执行 = 0 | 灰（`info`） | 未开始 |
| 0 < 已执行 < 总数 | 黄（`warning`） | 进行中 |
| 已执行 = 总数 | 绿（`success`） | 已完成 |
| 已执行 > 总数 | 红（`danger`） | 异常（如 PR 超申请） |

基准列（销售明细总额、销售明细数量）不参与着色。

### 2.4 金额与权限

- 金额列受 `sales.amount.read` 控制；无权限时金额单元格显示 `—`（与订单明细列表一致）；
- 后端 `mask521` 时金额相关字段归零后返回，前端同样脱敏。

### 2.5 权限

| 操作 | RBAC |
|------|------|
| 查看概况及下游 Tab 聚合 | `sales-order.read` |
| 金额列可见 | 另需 `sales.amount.read` |

接口路径与既有销售订单明细详情 Tab 相同，不新增独立权限点。

## 3. 数据口径

各指标与 `SellOrderItemExtendSyncService.RecalculateAsync` 及业务文档保持一致，避免概况与列表/主表进度字段不一致。

### 3.1 基准列

```text
lineAmount.total = Round(qty × price, 2)
lineQty.total    = qty
currency           = sell_order_item.currency
```

### 3.2 采购申请（数量）

- **已执行**：关联本销售明细的采购申请中，`status ≠ 3（已取消）` 的 `qty` 合计；
- **待处理**：`max(0, qty − 已执行)`；
- **超申请**：若 PR 合计 > 销售行 qty，待处理为 0，已执行为实际合计，列标题显示 **红色**。

> 采购申请进度 **不读** `SellOrderItemExtend`，在 aggregates 构建时由当次查询的 `purchaseRequisitions` 行现场汇总。

### 3.3 采购订单明细（数量）

来自 `sell_order_item_extend`（由 SyncService 维护）：

| 字段 | 口径 |
|------|------|
| `QtyAlreadyPurchased` | 关联本销售明细的 `purchase_order_item.qty` 合计 |
| `QtyNotPurchase` | `max(0, qty − QtyAlreadyPurchased)` |

### 3.4 入库（数量）

与 SyncService 入库进度一致：

1. `stock_in_item_extend.sell_order_item_id = 本明细`；
2. 父单 `stock_in.status = 2（已入库）` 且 `stock_in_type = 采购入库`；
3. **已执行** = 满足条件的 `stock_in_item.quantity` 合计；
4. **待处理** = `max(0, qty − 已执行)`。

### 3.5 出库申请（数量）

| 字段 | 口径 |
|------|------|
| `QtyStockOutNotify` | 有效出库通知数量合计（`StockOutRequestStatusCode.IsActiveForQuantitySum`） |
| `QtyStockOutNotifyNot` | `max(0, qty − QtyStockOutNotify)` |

### 3.6 出库（数量）

| 字段 | 口径 |
|------|------|
| `QtyStockOutActual` | 销售出库单头 `sell_order_item_id` 匹配，状态为已出库(2)或已完成(4)，累计 `total_quantity` |
| 待处理 | `max(0, qty − QtyStockOutActual)` |

### 3.7 收款核销（金额）

| 字段 | 口径 |
|------|------|
| `ReceiptAmount` | 行全额 `qty × price` |
| `ReceiptAmountFinish` | 本销售明细关联应收 `finance_receivable.verified_done` 合计 |
| `ReceiptAmountNot` | `max(0, ReceiptAmount − ReceiptAmountFinish)` |

**注意**：单条应收全部核销 ≠ 销售明细收款完成；须累计达到行全额。详见 [收款核销-设计与实现](财务/收款核销-设计与实现.md) §3.6。

### 3.8 销项发票（金额）

| 字段 | 口径 |
|------|------|
| `InvoiceAmount` | 行全额 |
| `InvoiceAmountFinish` | 扩展表已开票累计（SyncService 维护） |
| `InvoiceAmountNot` | `max(0, InvoiceAmount − InvoiceAmountFinish)` |

## 4. API 与 DTO

### 4.1 接口

仅在 **单条明细 scope** 的 aggregates 接口中返回 `lineOverview`；订单级 aggregates（多明细）不返回。

```
GET /api/sales-orders/{orderId}/sell-order-items/{sellOrderItemId}/detail-tab-aggregates
```

响应在既有 Tab 列表字段之外增加：

```json
{
  "lineOverview": {
    "lineAmount": { "total": 2300000, "currency": 840 },
    "lineQty": { "total": 1000 },
    "purchaseRequisition": { "total": 1000, "done": 1000, "pending": 0 },
    "purchaseOrder": { "total": 1000, "done": 0, "pending": 1000 },
    "stockIn": { "total": 1000, "done": 0, "pending": 1000 },
    "stockOutNotify": { "total": 1000, "done": 0, "pending": 1000 },
    "stockOut": { "total": 1000, "done": 0, "pending": 1000 },
    "receiptWriteOff": { "total": 2300000, "done": 0, "pending": 2300000, "currency": 840 },
    "invoice": { "total": 2300000, "done": 0, "pending": 2300000, "currency": 840 }
  },
  "rfqItems": [ ... ],
  "purchaseRequisitions": [ ... ],
  "packings": [ ... ]
}
```

`packings`：经装箱明细 `sell_order_item_id` 或关联出库通知反查的装箱单主单列表，字段与 `/inventory/packing` 列表（`PackingListItemDto`）一致；页签位于 **出库通知** 之后、**出库** 之前。

`stockIns`：经入库明细扩展 `sell_order_item_id` 反查的入库单列表，字段与 `/inventory/stock-in` 列表（`StockInListItemDto`）一致。

`stockOutRequests`：按 `sales_order_item_id` 关联的出库通知列表，字段与出库通知列表页（`StockOutRequestListItemDto`）一致。

`stockOuts`：按 `sell_order_item_id` 关联的销售出库单列表，字段与 `/inventory/stock-out` 列表（`StockOutListItemDto`）一致。

TypeScript 类型见 `CRM.Web/src/api/salesOrder.ts`：`SellOrderLineOverview`、`SellOrderLineOverviewQtyMetric`、`SellOrderLineOverviewAmountMetric`。

### 4.2 后端构建

| 位置 | 说明 |
|------|------|
| `SalesOrdersController.BuildSalesOrderDetailTabAggregatesPayloadAsync` | `sellOrderItemIdScope != null` 时调用 `BuildSellOrderLineOverviewAsync` |
| `SalesOrdersController.BuildSellOrderLineOverviewAsync` | 读取 `sell_order_item`、`sell_order_item_extend`，汇总 PR 与入库 |
| `SalesOrdersController.BuildSellOrderTabStockInsAsync` | 按销售明细反查入库单，复用 `IStockInService.GetStockInListItemsByIdsAsync` |
| `SalesOrdersController.BuildSellOrderTabPackingsAsync` | 按销售明细反查装箱单，复用 `IPackingService.GetPackingListItemsByIdsAsync` |
| `SalesOrdersController.BuildSellOrderTabStockOutRequestsAsync` | 按销售明细反查出库通知，复用 `IStockOutService.GetStockOutRequestListItemsByIdsAsync` |
| `SalesOrdersController.BuildSellOrderTabStockOutsAsync` | 按销售明细反查出库单，复用 `IStockOutService.GetStockOutListItemsByIdsAsync` |

## 7. 测试与回归要点

1. 双击明细行后面板默认打开 **概况**，矩阵 9 列 3 行数据与下游 Tab 汇总一致；
2. PR 已取消（status=3）不计入采购申请已执行；
3. PR 超申请时：待处理=0、已执行=实际合计、列标题红色；
4. 入库仅统计 **已完成采购入库**；
5. 收款核销：部分核销显示黄色标题，全额绿色；与 `ReceiptProgressStatus` 不冲突；
6. 无 `sales.amount.read` 时金额格为 `—`；
7. 订单级 `detail-tab-aggregates` 响应不含 `lineOverview`；
8. 切换主题后表头/数据文字对比度可读。
