## 1. 目标与非目标

### 1.1 目标

1. **租户公司邮箱（管理员）**  
   - 「公司邮箱」页签：分区标题 **「SMTP/IMAP 服务器」** — **平台后缀** + SMTP（主机/端口/TLS）+ IMAP（主机/端口/SSL）+ **最早同步邮件日期** + **启用 SMTP 发信**（全站总开关）。  
   - **不**再配置系统发件账号：去掉 `user` / `password` / `fromAddress` / `fromName`（代码不再读写；旧 JSON 数据可留库不管）。  
   - **不**展示「系统通知账号」入口（系统通知发信另议，之后再做）。  
   - 展示全站 **验证成功** 的用户邮箱列表（含 **邮箱密码** 列：默认掩码，眼睛可看明文）。  
   - 页签访问与保存：**仅 SuperAdmin（`SYS_ADMIN`）**。

2. **个人邮箱（员工）**  
   - 在 **`/profile/mailbox`** 维护多条邮箱（平台 / 其他）、密码、显示名称；逐条「验证邮箱」。  
   - 平台邮箱：验 **IMAP 收信 + SMTP 真发测试信**；可设 **默认发信邮箱**（单选）。  
   - 其他邮箱：**只收不发**（仅验 IMAP；自填 IMAP 主机/端口/SSL；不可设默认；不参与业务发信）。  
   - 展示验证成功 / 失败状态；密码默认掩码，眼睛图标可看明文。  
   - **深链：** 业务页可跳转 `/profile/mailbox?from=<站内路径>`；页顶「返回来源页面」回到业务页（`from` 仅接受以 `/` 开头的站内路径）。兼容旧链接 `/profile?tab=mailbox` → 重定向到正式地址。

3. **Profile 信息架构**  
   - `/profile` 改为与 `/company-info` 相同的 **左侧菜单面板**，将现有区块拆为多个菜单项，并新增「我的邮箱」（路由 `/profile/mailbox`，同一 `ProfileView`）。

4. **业务发信（二期）**  
   - 通用发信：`IEmailSender` 按 `senderUserId` 使用该用户 **默认 + 已验证平台邮箱**；SMTP 主机参数取公司配置。  
   - 本版本业务接入：**PO 报表发信**（发信人 = **当前登录用户**，不按单据业务员）。  
   - 其它业务模块暂无发信入口则不必额外接入；日后挂同一套即可。  
   - 系统通知（无登录员工上下文）：**另议**，本版不做。

### 1.2 非目标（本阶段不做）

| 项 | 说明 |
|----|------|
| 系统通知账号 / 无用户上下文发信 | 另议；公司页不出现入口 |
| POP 收信（UI/校验） | 收信协议 **仅 IMAP**；库内 `pop_*` 列保留作兼容回退 |
| 「其他邮箱」发信 / 个人 SMTP 主机 | 其他邮箱只收不发；平台发信固定用租户 SMTP 主机 |
| AI 抽取 / 附件落盘 | 见 [我的邮件](./我的邮件-设计与实现.md)；本期邮箱设置本身不含 |
| OAuth / 授权码专用流程 | 账号密码（或邮箱授权码当密码填） |
| 清理旧 JSON 中系统账号字段 | 代码不读写即可；**不强制**本次 DDL/迁移删除字段值 |

## 2. 产品定稿规则

### 2.1 邮箱类型

| 类型 | 编码建议 | 地址规则 | 验证 |
|------|----------|----------|------|
| 平台邮箱 | `platform` | **强制** `{本地部分}@{租户后缀}`；本地部分员工可改 | IMAP 登录成功 **且** 用该条账号密码连租户 SMTP **真发一封**到自己；可设默认发信 |
| 其他邮箱 | `personal` | 完整地址自由填写；**自填** IMAP 主机/端口/SSL | 仅 IMAP；**只收不发**；不可设默认 |

- 每人可有 **多条** 平台邮箱 + **多条** 其他邮箱。  
- 每条均有 **显示名称**（`displayName`，默认可空；发信时为空则 From **仅地址**）。  
- 平台 / 其他均 **不要** 个人侧 SMTP 主机字段（平台用租户 SMTP）。

### 2.2 平台邮箱预填（规则 C）

进入「我的邮箱」或首次拉取列表时，若用户 **尚无任何平台邮箱**：

1. 读取租户后缀（见 §3.1）；未配置后缀则暂不自动建草稿（或建草稿但提示管理员先配后缀——实现取：无后缀则不自动插入，UI 提示）。  
2. 本地部分：  
   - `User.Email` 非空 → 取其 `@` 前一段（trim）；若无 `@` 则整段邮箱当本地部分。  
   - `User.Email` 为空 → 本地部分字面量 **`xxx`**。  
3. 地址 = `{本地部分}@{规范化后缀}`。  
4. 状态 = **未验证**；密码为空；**显示名称默认为空**。

### 2.3 租户后缀

- 配置位置：公司信息 → **公司邮箱**（文案仍叫「公司邮箱」，不改为「邮箱设置」）。  
- 示例：`@xxx.com` 或 `xxx.com`（入库规范化：保证以 `@` 开头的域名后缀，小写）。  
- **变更后缀时：**  
  - 所有 **未验证** 的平台邮箱：地址自动改写为「原本地部分 + 新后缀」。  
  - 所有 **已验证成功** 的平台邮箱：地址同样改写后缀，且 **`verifyStatus` 置为未验证**（需重验）；清空成功时间；可写提示文案「后缀已变更，请重新验证」。

### 2.4 验证行为

| 项 | 规则 |
|----|------|
| 平台 IMAP | 连租户 IMAP 主机；账号=该条完整邮箱地址（或与密码配套的登录名，默认用完整地址）；密码=该条密码；打开 `INBOX` |
| 平台 SMTP | 连 **租户 SMTP 主机/端口/SSL**；认证账号密码=**该条平台邮箱**；`From`/`To`=该条地址；主题与正文固定为 **「CRM平台邮箱验证」**（可中英相同固定串） |
| 其他 IMAP | 连该条自填 IMAP；账号默认完整地址 |
| 失败后再验 | **清除**旧失败信息后重试，写入新结果 |
| 成功后改密码 / IMAP 主机 / 端口 / SSL / 平台本地部分或后缀导致地址变 | 状态立刻变回 **未验证**（并清 `verifiedAt`）；须重验后才可参与「我的邮件」同步 |
| 业务发信 | 见 §2.8、§2.9（登录用户默认平台邮箱） |

### 2.5 管理员已验证列表

- 仅包含 `verifyStatus = 成功` 的邮箱。  
- **推荐按邮箱行展示**（便于「邮箱密码」列一一对应），字段至少包括：  
  **账号**（用户登录名/显示名）、**邮箱地址**、**类型**（平台/其他）、**显示名称**、**邮箱密码**、验证时间（可选）。  
- 若 UI 需「按用户分组」，组内仍按每条邮箱一行，密码不合并。  
- **邮箱密码**展示规则见 §2.7（默认 `******`，点眼睛看明文）。仅 SuperAdmin 可请求解密明文。

### 2.6 权限

| 能力 | 权限 |
|------|------|
| 公司信息 · 基础/银行/Logo/印章/仓库/报表等 | 现有 `system.params.company.read` / `write` |
| 公司信息 · **公司邮箱**页签（读配置、改 SMTP/IMAP/后缀/最早同步日、看已验证列表） | **仅 SuperAdmin（`SYS_ADMIN`）** |
| 个人「我的邮箱」CRUD + 验证 | 登录用户操作 **本人** 数据（无需公司信息权限） |

前端：非 SuperAdmin 不展示或禁用「公司邮箱」页签；直链 API 仍须后端拒绝。  
后端：公司邮箱相关读写 **不得** 仅依赖 `system.params.company.write`（有公司写权限的非 SA 也不可改邮箱配置）。

### 2.7 密码存储与界面揭示（补加）

| 项 | 规则 |
|----|------|
| 存储算法 | **对称加密（可解密）** 写入数据库；**禁止**仅用单向哈希（验证/展示明文需要解密） |
| 密钥 | 使用服务端配置的对称密钥（如 `appsettings` / 环境变量中的专用 Key，或封装 `IMailboxPasswordCipher`）；密钥不入库、不进前端 |
| 库内字段 | 只存密文（如 `password_cipher`）；可选存算法版本号便于轮换 |
| 列表/表单默认 UI | 密码输入或展示位显示 **`******`**（或等价掩码），**不**在首屏直接铺明文 |
| 眼睛图标 | 点击切换：掩码 ↔ **明码**；再次点击收回掩码 |
| `/profile/mailbox` · 我的邮箱 | 本人编辑/查看自己的邮箱密码：默认 `******`，点眼睛显示明码；业务引导可带 `?from=` |
| `/company-info` · 公司邮箱 · 已验证列表 | 增加 **「邮箱密码」** 列：默认 `******`，点眼睛显示该条明码（仅 SA） |
| 租户侧系统发件密码 | **二期起废弃**；公司配置不再读写 `user`/`password` |

**API 与明文回传：**

- 普通列表 GET：**默认不返回明文**，仅 `passwordSet`（或固定掩码占位），避免日志/代理误记。  
- **揭示明文**（点眼睛时）：调用受控接口解密后返回，例如  
  - 本人：`GET /api/v1/me/mailboxes/{id}/password`  
  - SA：`GET /api/v1/company-profile/verified-user-mailboxes/{id}/password`  
- 亦可在点眼睛时用一次性 query（如 `?revealPassword=1`）拉单行；须鉴权 + 审计日志（谁在何时查看了哪条邮箱密码）。  
- 验证发信/IMAP/业务发信时仅在服务端解密，密码不写响应体。

### 2.8 默认发信邮箱

| 项 | 规则 |
|----|------|
| 谁可设为默认 | **仅** `platform` **且** `verifyStatus = 成功`；未验证不可勾选 |
| 交互 | **单选**（同一用户同时至多一条 `isDefaultSend`）；仅已验证平台行显示可点单选 |
| 自动默认 | 用户 **尚无默认** 时，某条平台邮箱 **验证成功** → **自动**设为默认（含「第一条验证成功」与「默认被清空后再次验证成功」） |
| 默认失效 | 默认邮箱被 **删除**，或因改密/改地址/后缀变更等变为 **未验证/失败** → **清空默认**，**不**自动切到其它已验证邮箱；用户须再验证成功（触发自动默认）或手动单选 |
| 其他邮箱 | 不可设默认 |

### 2.9 业务发信（二期）

| 项 | 规则 |
|----|------|
| SMTP 主机 | 公司「SMTP/IMAP 服务器」：`smtpHost` / `smtpPort` / `useSsl` |
| 认证与 From | 登录用户的 **默认发信邮箱**：账号=地址、密码=该条密文解密；`From` = `displayName`（可空）+ 地址；显示名为空则 **仅地址** |
| 发信人 | **当前登录用户**（如 PO），不按单据业务员 |
| `enabled` | **全站 SMTP 总开关**：关闭则业务发信禁止（不仅系统通知） |
| 失败策略 | **明确失败**，不静默回退任何公司系统账号 |
| 统一提示（无默认/未验证等） | 「请先在个人设置 → 我的邮箱中完成平台邮箱验证。」 |
| 错误码（须区分） | 见 §4.4；前端按码映射文案；SMTP 拒信可附带服务端简短 `message` |
| 前置检查 | 发信按钮：**灰显 + tooltip**（未就绪不可点）；旁附「去配置我的邮箱」→ `/profile/mailbox?from=<当前页>`；数据来自 `send-ready` |
| 本版接入 | 通用 `IEmailSender(senderUserId)` + **PO**；系统通知另议 |

## 3. 数据设计

### 3.1 租户邮箱配置（sysparam）

参数键仍为：`Company.Profile.SmtpEmail`（JSON）。

**二期有效字段（读写）：**

| 字段 | 说明 |
|------|------|
| `enabled` | 启用 SMTP 发信（全站总开关） |
| `smtpHost`, `smtpPort`, `useSsl` | SMTP 服务器 |
| `platformEmailSuffix` | 租户平台后缀，如 `@xxx.com` |
| `imapHost`, `imapPort`, `imapUseSsl` | 租户 IMAP；供平台邮箱验证收信与「我的邮件」同步 |
| `mailSyncEarliestDate` | 最早同步邮件日期（全租户一份）；语义见[我的邮件](./我的邮件-设计与实现.md) |
| `popHost`, `popPort`, `popUseSsl` | **兼容旧数据**；加载时若无 IMAP 可从 POP 回填；UI 以 IMAP 为准 |

**废弃字段（代码不再读写，旧值可留库）：** `user`、`password`、`fromAddress`、`fromName`（及派生的 `passwordSet` 展示）。

**说明：** 平台验证发信与业务发信：SMTP **主机/端口/SSL** 取本配置；**认证账号密码**取员工对应邮箱。

### 3.2 个人邮箱表（新表）

建议表名：`user_mailbox`（PostgreSQL）。

| 列 | 类型 | 说明 |
|----|------|------|
| `id` | uuid/varchar(36) PK | |
| `user_id` | varchar(36) NOT NULL | FK → `user` |
| `kind` | smallint / varchar | `platform` / `personal` |
| `address` | varchar(256) NOT NULL | 完整邮箱 |
| `local_part` | varchar(128) NULL | 平台邮箱本地部分；personal 可空 |
| `display_name` | varchar(200) NULL | 显示名称 |
| `password_cipher` | text NULL | **对称加密**密文（可解密）；禁止明文落库 |
| `password_set` | bool | 是否已存密码（可由 cipher 是否非空推导） |
| `crypto_version` | smallint NULL | 可选，密钥/算法版本，便于轮换 |
| `imap_host` | varchar(256) NULL | **仅 personal**；platform 用租户 IMAP |
| `imap_port` | int NULL | personal；默认 993 |
| `imap_use_ssl` | bool | personal；默认 true |
| `pop_host` / `pop_port` / `pop_use_ssl` | | **兼容保留**；校验/UI 优先 IMAP，缺省时可回退 POP 值 |
| `verify_status` | smallint | `0` 未验证 / `1` 成功 / `2` 失败 |
| `verify_message` | varchar(1000) NULL | 失败原因或成功简述 |
| `verified_at` | timestamptz NULL | |
| `is_default_send` | bool | **默认发信**；同一 `user_id` 未删除行中至多一条为 true；仅平台+已验证允许为 true |
| `is_deleted` | bool | 软删 |
| `create_time` / `modify_time` | | |
| `create_by_user_id` / `modify_by_user_id` | | 可选 |

索引：`(user_id)`；`(verify_status)` 供管理员列表；唯一约束建议：`user_id + lower(address)` 在未删除行上唯一。

**不**把邮箱密码写入 `user.Email`；`user.Email` 仍仅作联系邮箱 / 预填本地部分来源。

### 3.3 验证状态枚举

```text
None = 0   // 未验证（含草稿、改密后回退）
Ok   = 1   // 成功
Fail = 2   // 失败
```

## 4. API 设计（草案）

### 4.1 公司邮箱（SuperAdmin）

可挂在现有 `CompanyProfileController` 下拆分，或独立 `CompanyMailboxController`：

| 方法 | 路径建议 | 说明 |
|------|----------|------|
| GET | `/api/v1/company-profile/mailbox-settings` | SMTP（脱敏）+ IMAP + 最早同步日 + 后缀；**仅 SA** |
| PUT | 同上 | 保存；**仅 SA**；后缀变更触发 §2.3 级联 |
| GET | `/api/v1/company-profile/verified-user-mailboxes` | 已验证成功列表（按邮箱行；**不含**密码明文）；**仅 SA** |
| GET | `/api/v1/company-profile/verified-user-mailboxes/{id}/password` | 解密返回该条明文密码；**仅 SA**；写审计日志 |

现有 `GET/PUT /api/v1/company-profile`：

- 对非 SA：**Strip** `SmtpEmail`（及扩展的 IMAP/后缀），避免无权限读取。  
- 对 SA：可继续打包返回，或改为前端公司邮箱页只打专用接口（推荐专用接口，权限边界清晰）。  
- `PUT` 公司档案时：非 SA **忽略** body 中的邮箱配置；SA 可用专用 PUT 或一并保存（实现选定一种，避免双写冲突）。

### 4.2 个人邮箱（本人）

| 方法 | 路径建议 | 说明 |
|------|----------|------|
| GET | `/api/v1/me/mailboxes` | 列表（**无**密码明文，仅 `passwordSet`）；含 `isDefaultSend`；若无平台邮箱则按 §2.2 惰性预填一条草稿后返回 |
| GET | `/api/v1/me/mailboxes/send-ready` | 发信前置检查：`ready` + `blockReason`（错误码，见 §4.4）；供按钮灰显/tooltip |
| POST | `/api/v1/me/mailboxes` | 新增；密码明文仅出现在请求体，入库前对称加密 |
| PUT | `/api/v1/me/mailboxes/{id}` | 更新；密码空=保留原密文；有新密码则重加密；敏感字段变更 → 未验证并清默认（若本条曾是默认） |
| PUT | `/api/v1/me/mailboxes/{id}/default-send` | 设为默认发信（单选）；仅平台+已验证；其它同行 `is_default_send=false` |
| DELETE | `/api/v1/me/mailboxes/{id}` | 软删；若为默认则清空默认 |
| GET | `/api/v1/me/mailboxes/{id}/password` | 本人解密查看明文（供眼睛图标）；限流 |
| POST | `/api/v1/me/mailboxes/{id}/verify` | 执行验证；成功且当前无默认 → 自动设本条为默认 |

校验要点：

- `platform`：`address` 必须等于 `{localPart}@{suffix}`（suffix 取当前租户配置）。  
- `personal`：`imapHost`（或兼容 `popHost`）必填；`address` 须为合法邮箱格式。  
- 验证前必须 `password_set`。  
- 设默认：必须平台 + 验证成功。

### 4.3 验证服务（后端）

`IMailboxVerifyService`（MailKit）：

1. **IMAP**：`ImapClient` 连接 → 认证 → 打开 `Inbox` → 断开。  
2. **平台 SMTP 测试信**：`SmtpClient` 连租户主机 → 用邮箱账号密码认证 → 发一封纯文本（主题/正文「CRM平台邮箱验证」）到自身 → 断开。  
3. 异常映射为简短中文 `verify_message`（认证失败 / 连接超时 / 证书等），不回传服务器原始堆栈给前端。

### 4.4 业务发信错误码与 Sender

`IEmailSender`（二期）签名须带 `senderUserId`（或等价上下文）；实现步骤：

1. 读租户 SMTP：未 `enabled` → `SmtpDisabled`；无 `smtpHost` → `SmtpHostMissing`。  
2. 查该用户 `is_default_send` 且未删的平台邮箱：无 → `NoDefaultMailbox`。  
3. 默认条非「平台 + 成功」或无密码 → `DefaultNotVerified`（文案可用统一提示）。  
4. 连接 SMTP、用该条凭据认证并发送；服务商拒信 → `SmtpRejected`（附简短 message）。

| 错误码 | 含义 | 前端提示（建议） |
|--------|------|------------------|
| `SmtpDisabled` | 未启用 SMTP 发信 | 管理员未启用 SMTP 发信 |
| `SmtpHostMissing` | 未配 SMTP 主机 | 管理员未配置 SMTP 服务器 |
| `NoDefaultMailbox` | 无默认发信邮箱 | 请先在「我的邮箱」完成平台邮箱验证。 |
| `DefaultNotVerified` | 默认邮箱不可用（未验证/无密码等） | 同上 |
| `SmtpRejected` | SMTP 认证或发送被拒 | 邮件服务器拒绝发送：{message} |

PO 等调用点：传入当前登录用户 Id；前端发信前调 `send-ready`，未 `ready` 则按钮灰显 + tooltip（按 `blockReason` 映射），并提供跳转 `/profile/mailbox?from=...`。业务页统一用 `profileMailboxLocation(route.fullPath)`。

## 6. 安全

| 项 | 要求 |
|----|------|
| 密码存储 | **对称加密（可解密）**；库内仅密文；密钥仅服务端 |
| 明文回传 | 仅「揭示密码」专用接口；列表 GET 默认不带明文 |

| 传输 | HTTPS；日志禁止打印密码明文与完整 Authorization |
| 验证/揭示限流 | 按 userId + IP 限制频率，防爆破与批量拖库 |
| 越权 | mailbox 密码接口仅本人；公司侧揭示仅 SA |
| 测试信 | 仅发往该条地址自身，禁止自定义收件人（防滥用） |

## 9. 验收要点（摘要）

### 一期

- 非 SA 看不到公司邮箱页签，专用 API 返回 403。  
- 新用户打开我的邮箱：自动一条未验证平台草稿。  
- 平台验证：IMAP + 测试信双成功；其他邮箱只测 IMAP。  
- 密码对称加密；眼睛揭示明文。

### 二期

- 公司页仅后缀 + SMTP/IMAP 服务器 + 最早同步日 + 启用开关；无账号/密码/From/系统通知入口。  
- 仅已验证平台可单选默认；首验/无默认再验成功 → 自动默认；默认失效 → 清空不自动切。  
- PO：用登录用户默认邮箱发；未就绪按钮灰显 + tooltip；服务端按错误码失败，不回退公司账号。  
- 显示名为空时 From 仅地址；其他邮箱不能发信、不能设默认。
