# 系统通知 — 设计与实现

> **状态：** 已上线（点对点发送 + 铃铛抽屉 + 角标/摇动 + 全部已读）  
> **产品名：** 消息通知管理（侧栏）；用户侧称「系统消息」  
> **PRD：** [消息通知管理PRD](../../PRD/业务功能/系统/消息通知管理PRD.md)  
> **关联页面：**  
> - 管理：`/ops/user-notices`（运维管理 · 消息通知管理，仅 SuperAdmin）  
> - 用户：顶栏铃铛抽屉 ·「系统消息」Tab  
> **QA：** [系统通知-测试对照说明](../../QA/系统/系统通知-测试对照说明.md)  
> **帮助：** [控制台](../../../help/pages/控制台_MENU_DASHBOARD.md)、[消息通知管理](../../../help/pages/消息通知管理_MENU_OPS_USER_NOTICES.md)  
> **权限：** 管理端 `meta.sysAdminOnly`（与系统公告同类，无独立权限码）；用户侧任意已登录账号可读自己的通知  
> **DDL：** `scripts/ensure_sys_user_notice_postgresql.sql`；迁移 `20260924120000_AddSysUserNotice`

与 [系统公告](./系统公告-设计与实现.md) **分开**：公告是全员强制弹窗 + Markdown；本功能是点对点、不挡登录、纯文本。

## 1. 目标与非目标

### 1.1 目标

1. SuperAdmin 在运维「消息通知管理」给指定启用员工发送一条通知（发送即落库）。  
2. 接收人在顶栏铃铛抽屉「系统消息」查看；**点开卡片即记已读**。  
3. 铃铛角标 = 未读系统通知 + 未读系统公告；超过 20 显示 `20+`。  
4. 仅当存在 **未读且重要** 的系统通知时铃铛摇动；仅有未读公告不摇。  
5. 打开抽屉时：有未读系统通知默认「系统消息」，否则「系统公告」。  
6. 各 Tab 底部「设置全部已读」（通知 / 公告各自接口）。  
7. 模拟登录不摇、不记已读、角标按 0。

### 1.2 非目标（本期不做）

| 项 | 说明 |
|----|------|
| 改已发 / 撤回 / 删除 | 发送后不可改、不可删 |
| 群发 / 全员 / 按部门 | 一次一人 |
| 附件 / Markdown | 纯文本，标题 100、正文 4000 |
| 强制弹窗挡登录 | 不做 |
| 草稿 | 无草稿状态 |
| 独立权限码 | 仅 SuperAdmin |
| 站外触达 | 不做 |

## 2. 产品定稿规则

### 2.1 字段

| 字段 | 规则 |
|------|------|
| 接收人 | 必选；仅 `IsActive && Status == 1`（启用） |
| 重要 | 可选；界面文案「重要 / 普通」；库列 `is_urgent` |
| 标题 | 必填，去空白后最长 **100** |
| 正文 | 必填，去空白后最长 **4000**，纯文本 |

内容摘要（列表）：去空白后正文前 **80** 字，超出加 `…`。接收人展示：`账号 / 姓名`，无姓名则仅账号。

### 2.2 生命周期

```
发送（一次一人）→ 落库（read_at 空）→ 接收人点开或全部已读 → read_at = UTC now
```

- 无草稿、无撤回、无删除接口。  
- 管理端查看详情 **不** 写 `read_at`。

### 2.3 已读与模拟登录

| 项 | 规则 |
|----|------|
| 未读 | `read_at IS NULL` |
| 单条已读 | `POST /me/user-notices/{id}/read`，幂等 |
| 全部已读 | `POST /me/user-notices/read-all`，只更新当前用户未读行 |
| 管理端 GET | 只读，不改已读 |
| 模拟登录 | JWT 含 `impersonator`：摘要返回 0；写已读接口 200 但不落库 |

### 2.4 铃铛与抽屉

| 项 | 规则 |
|----|------|
| 交互 | 点顶栏铃铛 → 右侧抽屉（与系统公告共用 `SystemMessageDrawer`） |
| Tab | 系统消息 \| 系统公告 |
| 默认 Tab | `noticeUnreadCount > 0` → `messages`，否则 `announcements` |
| 顶栏角标 | `noticeUnread + announcementUnread`；`>20` → `20+` |
| 摇动 | `hasUnreadUrgent && !isImpersonating` |
| 轮询 | 主壳约 **60s** 拉两边 `unread-summary` |
| 系统消息卡片 | 整卡可点；第 1 行图标+标题、日期右对齐；第 2 行摘要 |
| 列表时间 | 今日/昨日 + `HH:mm`，其它 `YY-MM-DD HH:mm`（`formatDisplayRelativeNoticeTime`） |
| 详情时间 | `YYYY-MM-DD HH:mm` |
| 已读样式 | 文字与重要图标变灰；悬停底色 `#fff6d4` |
| 全部已读 | 系统消息 → `me/user-notices/read-all`；系统公告 → `me/announcements/read-all` |

### 2.5 管理端「消息通知管理」

| 项 | 规则 |
|----|------|
| 路由 | `ops/user-notices`，`meta.sysAdminOnly` |
| 菜单 | 运维管理组，用户反馈之后；仅 `isSysAdmin` 可见 |
| 埋点页 | `TelemetryCatalog`：`UserNoticeList` = 消息通知管理 |
| 列 | 重要、已读、接收人、标题、内容摘要、发送时间 |
| 列布局 | `column-layout-key="ops-user-notice-list-v2"`；重要列宽 96 |
| 已读行 | `row-class` 文字灰色；已读 tag 仍为 success 绿 |
| 重要列 | 仅重要显示红色纸飞机（`NoticeUrgentIcon`，Material send） |
| 能力 | 筛选、发送、点行看正文；无编辑/删除 |

## 3. 数据模型

表 `sys_user_notice`：**一对一行**，不预插全员。

| 列 | 类型 | 说明 |
|----|------|------|
| `id` | varchar(36) PK | GUID |
| `recipient_user_id` | varchar(36) | 接收人 |
| `is_urgent` | bool 默认 false | 重要 |
| `title` | varchar(100) | 标题 |
| `body` | varchar(4000) | 正文 |
| `sender_user_id` | varchar(36) | 发送人 |
| `create_time` | timestamptz | 发送时间 UTC |
| `read_at` | timestamptz NULL | 空=未读 |

索引：

- `ix_sys_user_notice_recipient_create` `(recipient_user_id, create_time DESC)`  
- `ix_sys_user_notice_create_time` `(create_time DESC)`  
- `ix_sys_user_notice_unread` `(recipient_user_id) WHERE read_at IS NULL`

实体：`CRM.Core/Models/System/SysUserNotice.cs`。常量：`SysUserNoticeLimits.TitleMaxLength=100`，`BodyMaxLength=4000`。

## 4. API

### 4.1 管理（仅 SuperAdmin，否则 403）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/v1/ops/user-notices/recipients` | 启用员工下拉 |
| GET | `/api/v1/ops/user-notices` | 分页列表。query：`isUrgent`、`isRead`、`recipientUserId`、`keyword`、`sendFrom`、`sendTo`、`page`、`pageSize`（最大 100） |
| GET | `/api/v1/ops/user-notices/{id}` | 全文；**不**改 `read_at` |
| POST | `/api/v1/ops/user-notices` | 发送。body：`recipientUserId`、`isUrgent`、`title`、`body` |

关键字：`ILike` 匹配标题或正文（`%` `_` `\` 转义）。发送日：`sendFrom` 含当日 00:00 UTC，`sendTo` 不含次日 00:00。排序：`create_time DESC`。

### 4.2 用户（已登录；写已读见模拟登录）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/v1/me/user-notices/unread-summary` | `{ unreadCount, hasUnreadUrgent }`；模拟登录返回 0 |
| GET | `/api/v1/me/user-notices` | 本人列表（含 `bodyPreview`），最新在前 |
| GET | `/api/v1/me/user-notices/{id}` | 本人全文；非接收人 404 |
| POST | `/api/v1/me/user-notices/{id}/read` | 幂等写 `read_at` |
| POST | `/api/v1/me/user-notices/read-all` | 本人全部未读 |

公告侧配套：`POST /api/v1/me/announcements/read-all`（抽屉「系统公告」全部已读）。

## 6. 后端实现

1. EF：`ApplicationDbContext.SysUserNotices` + 迁移 `20260924120000_AddSysUserNotice`（SQL 幂等 `CREATE TABLE IF NOT EXISTS`）。  
2. 服务：`SysUserNoticeService` / `ISysUserNoticeService`；DI 注册于 `ServiceCollectionExtensions`。  
3. 控制器：`OpsUserNoticesController`（`GetUserPermissionSummaryAsync` → `IsSysAdmin`）、`MeUserNoticesController`。  
4. 发送校验：接收人启用、标题/正文非空且长度上限。  
5. 全部已读：`ExecuteUpdateAsync` 批量写 `read_at`。  
6. 手工库：`scripts/ensure_sys_user_notice_postgresql.sql`（可重复执行）。

## 7. 流程示意

```mermaid
flowchart TD
  admin[SuperAdmin 消息通知管理] --> send[选人 + 标题正文 发送]
  send --> row[sys_user_notice 落库]
  row --> recip[接收人铃铛]
  recip --> badge[角标 = 通知未读 + 公告未读]
  recip --> shake{未读且重要?}
  shake -->|是| anim[铃铛摇动]
  shake -->|否| still[不摇]
  recip --> open[点铃铛开抽屉]
  open --> tab{有未读通知?}
  tab -->|是| msg[默认系统消息]
  tab -->|否| ann[默认系统公告]
  msg --> click[点卡片]
  click --> read[写 read_at]
  msg --> all[设置全部已读]
  all --> read
  impersonate[模拟登录] --> skip[不摇不记已读角标0]
```
