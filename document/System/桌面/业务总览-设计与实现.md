# 业务总览 — 设计与实现

> **状态：** 已上线  
> **入口：** `/dashboard` 控制台（欢迎区 / 个人提成下方；无独立菜单）  
> **帮助：** [控制台](../../../help/pages/控制台_MENU_DASHBOARD.md)  
> **前端：** `CRM.Web/src/components/Dashboard/DashboardOverviewPanel.vue`

控制台中间条 KPI + 两条趋势。主部门身份（`identityType`）决定指标集；**不是**多套页面。

| 身份 | `identityType` |
| --- | --- |
| 销售（及未单独配置的其它身份，如商务） | 1（及非 2/3/5/6） |
| 采购 / 采购运营 | 2 / 3 |
| 财务 | 5 |
| 物流 | 6 |

---

## 1. 指标

| 身份 | KPI | 左趋势 | 右趋势 |
| --- | --- | --- | --- |
| 销售 | 需求条目、销售订单条目、转化率、在库美金、应收美金 | 需求趋势（近 30 天按日） | **成单趋势**：已审核销售订单折算美金 |
| 采购 | 报价条目、采购订单条目、转化率、**在库明细条数**、**应付明细条数** | 报价趋势（近 30 天按日） | **采购趋势**：采购订单明细条目数（近 30 天按日） |
| 物流 | **库存**明细条数（历史至今）、**入库/出库/报关明细**条数（近 30 天） | **入库趋势**：入库明细条数按日 | **出库趋势**：出库明细条数按日 |
| 财务 | **付款**记录、**核销进项发票**、**收款**记录、**核销收款**、**核销销项发票**（均为近 30 天） | **付款趋势**：付款记录条数按日 | **收款趋势**：收款记录条数按日 |

销售/采购的范围文案来自分析接口 `scopeLabel`。物流/财务主标题仍写「近 30 天」；仅库存格子下标「历史至今」。风险预警仍为美金门槛，不改为这些条数。

---

## 2. 采购「在库」= 库存明细条目数

采购桌面 **不** 再用物流分析 `onHandAmountUsd`。

| 项 | 口径 |
| --- | --- |
| 数字 | `GET /api/v1/inventory-center/stock-items` 默认筛选的 `total`（与列表标题「共 N 条」一致） |
| 筛选 | 不带出库状态、是否有库存、采购员等额外条件；仅账号数据范围 + 默认排除手工移库源行 |
| 含已出清 | 是（列表默认如此；不是仅 `qty_repertory > 0` 的层数，也不是 PCS） |
| 脱敏 | 条数不跟采购/销售金额权限；0 显示 `0` |
| 提示 | 格子下「库存明细条数（历史至今）」 |

打开库存明细时若再筛采购员/有库存，标题条数可与桌面不同。

销售桌面「在库」仍为物流分析折算美金（采购成本；只跟 `maskAmounts`）。

---

## 2.1 采购「应付」= 应付明细条数

采购桌面 **不** 再用采购分析待办 `payableAmount` 美金。

| 项 | 口径 |
| --- | --- |
| 数字 | `GET /api/v1/purchase-orders/items/analytics/dashboard` 的 `snapshot.payableLineCount` |
| 含义 | 采购订单明细上 `payment_amount_not > 0` 的行数（与明细看板「应付款明细数」一致） |
| 筛选 | 默认列表筛选（无日期、采购员等额外条件）；仅账号采购数据范围 |
| 脱敏 | 条数不跟金额权限；0 显示 `0` |
| 提示 | 格子下「应付明细条数（历史至今）」 |

销售桌面「应收」仍为销售分析待办折算美金。

---

## 2.2 采购「采购趋势」= 采购订单明细条目数

采购桌面右侧趋势标题为 **采购趋势**（销售仍为成单趋势），**不** 再用 `purchaseAmountApproved` 美金。

| 项 | 口径 |
| --- | --- |
| 数字 | 采购分析 `GET .../trends?groupBy=day` 的 `purchaseOrderItemCount` |
| 含义 | 近 30 天、按采购订单创建日分日；未删除且未取消的采购订单明细行数 |
| 与 KPI | 与上方「采购订单」条目同一套数据，只是拆成每日 |
| 提示 | 悬停为「明细条目」，不是折算美金 |

销售桌面成单趋势仍为已审核销售订单折算美金。

---

## 3. 物流桌面

| KPI | 口径 | 时间 |
| --- | --- | --- |
| 库存 | 与采购在库相同：库存明细列表默认 `total` | **历史至今** |
| 入库 | `stock_in_item` 行数；单头筛选与入库单列表一致（不含移库）；按 **入库日** | 近 30 天 |
| 出库 | 出库明细列表默认筛选的行数；按 **出库日** | 近 30 天 |
| 报关 | `customs_declaration_item` 行数，按报关单 **报关日**；数据范围与报关单列表一致（物流按创建人范围，财务/管理员全量） | 近 30 天 |

趋势：近 30 天每日入库明细条数、出库明细条数。取数 `GET /api/v1/dashboard/ops/logistics`。

---

## 4. 财务桌面

| KPI | 口径 | 时间 |
| --- | --- | --- |
| 付款 | 付款记录列表看板 `snapshot.headerCount`；按 **付款日** | 近 30 天 |
| 核销进项发票 | 有效 `finance_purchase_invoice_write_off` 行（反核销软删后不计）；按流水 **创建日** | 近 30 天 |
| 收款 | 收款记录列表看板 `snapshot.headerCount`；按 **收款日** | 近 30 天 |
| 核销收款 | 有效 `finance_receivable_write_off` 行；与收款核销流水同一数据范围；按流水 **创建日** | 近 30 天 |
| 核销销项发票 | 有效 `finance_sell_invoice_write_off` 行；按流水 **创建日** | 近 30 天 |

核销格子计的是 **已完成匹配流水**，不是待核销桌面待办。无对应列表权限时该格为「—」。

付款/收款趋势分别复用付款、收款列表看板 `trends?groupBy=day` 的 `headerCount`。三个核销计数：`GET /api/v1/dashboard/ops/finance-write-offs`。

## 5. 实现索引

| 层 | 路径 |
| --- | --- |
| 面板 | `DashboardOverviewPanel.vue`：按 `identityType` 分流 `loadPurchase` / `loadSales` / `loadLogistics` / `loadFinance` |
| 库存列表 | `inventoryCenterApi.searchStockItems`（采购在库、物流库存） |
| 应付明细 | `purchaseOrderItemListAnalyticsApi.getDashboard` → `payableLineCount` |
| 物流美金 | `GET /api/v1/analytics/logistics/dashboard`（销售桌面在库） |
| 物流明细 | `GET /api/v1/dashboard/ops/logistics`；查询 `DashboardOpsOverviewQuery` |
| 付款/收款 | `financePaymentListAnalyticsApi` / `financeReceiptListAnalyticsApi` |
| 财务核销 | `GET /api/v1/dashboard/ops/finance-write-offs` |
