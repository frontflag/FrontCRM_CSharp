## 1. 目标与非目标

### 1.1 目标

1. 客户详情「新闻动态」：左抓取记录、右 Markdown 正文+目录；顶栏「立即抓取」；**SYS_ADMIN** 可删除当前选中的一条成功简报。  
2. 内容走 AI 场景 `customer.news.monitor`（联网），提示词为 11 维企业情报监测。  
3. 首次窗口近 **3 个月**（结束日=上海今天）；再次仅收录上次成功简报结束日之后的新信息。  
4. **同日允许多份**；左侧每条成功记录单独列出（日期 + 时间 + 覆盖区间）。  
5. 失败记录不出现在左侧。

### 1.2 非目标（本期不做）

| 项 | 说明 |
|----|------|
| 全客户每日定时作业 | 费用高；只按需抓取 |
| 写回客户主数据 / 调查报告 | 只读存档 |
| 股票代码、实控人、母子公司主数据 | 档案无股票代码填「未知」，模型须按公司全称检索是否上市，禁止把未知当成未上市；实控人/关联公司仍填「未维护」 |
| 覆盖当天旧简报 | 一天多份，不覆盖 |

## 2. 产品定稿

| 项 | 口径 |
|----|------|
| 首次窗口 | 近 3 个月，结束日=上海今天 |
| 再次窗口 | 上次成功 `period_end` 的次日～今天；同日再抓可退化为当天 |
| 谁可看 | 能进该客户详情且 **非** 521 脱敏 |
| 521 | **整页隐藏**：不显示「新闻动态」页签；接口 403 |
| 立即抓取 | 客户业务员本人，或组织上级（部门经理/总监且数据范围覆盖该业务员），或 SYS_ADMIN / SYS_MANAGER，或有 `biz.ai.customer_intel.lookup` |
| 删除简报 | **仅 SYS_ADMIN**（不含 SYS_MANAGER）；硬删当前选中的成功记录；抓取进行中不可删 |
| 同日 | 允许多份 |
| 与调查 | 右栏调查仍是 13 章档案；本页是按次监测 Markdown |

时区：`Asia/Shanghai`（`CommissionShanghai`）。

## 3. 实现

| 层 | 说明 |
|----|------|
| 场景 | `customer.news.monitor`，`enable_web_search=true`，缓存 TTL=0，`output_format=text` |
| 场景权限码 | 复用 `biz.ai.customer_intel.lookup`（AI 配置试跑）；业务抓取另做门控，走 `InvokeSystemAsync` 记真实用户配额 |
| 落库 | `customer_news_briefing`，按次一行，无日期唯一约束 |
| 读 | `GET /api/v1/customers/{id}/news` 成功列表 + `canFetch` + `canDelete`；`GET .../news/{briefingId}` 全文；`GET .../news/latest-run` 最近一次（含失败） |
| 删除 | `DELETE .../news/{briefingId}`，仅成功行；非 SYS_ADMIN 403；抓取中 409 |
| 手跑 | `POST .../news/run` **立即返回** `pending`，模型在后台跑。抓取期间按钮禁用（文案「抓取中」），用轻量 `GET .../news/latest-run`（含 `isRunning`）判断结束，**不**长等 POST，避免 Nginx 120s 504。完成后刷新列表并重新可点。 |
| UI | `CustomerNewsMonitorPanel`；正文复用 `IndustryNewsBriefingView`（关闭行业新闻 ★ 规范化）；删除在顶栏「立即抓取」左侧 |
| 模版 | `/system/ai-config` 模板 `customer.news.monitor` |

占位符：`company_name`、`nick_name`、`stock_code`、`industry`、`hq_location`、`related_companies`、`actual_controller`、`window_months`、`start_date`、`end_date`、`monitor_mode`、`change_tracking_rule`。

Markdown 二级标题：核心摘要、事实详情、风险雷达、变化追踪、待核实区。首次省略变化追踪。
