# 客户列表 — 左栏检索 — 设计与实现

**状态：** 第一、二、三阶段已上线（preset + quickFilter + 主栏 chip）  
**页面：** `/customers`（`CustomerList`，左栏「检索」页签 + 主栏筛选区）  
**交互参考：** [销售订单明细列表-左栏检索-设计与实现](../销售/销售订单明细列表-左栏检索-设计与实现.md)

## 1. 业务定位

左栏「检索」用于 **主栏不便直接表达的业务视角条件**（时间桶、关注、待办、需求、成单、在途业务），与主栏 keyword / 类型 / 行业 / 业务员 / 结算币别 **共用 URL query**。

| 概念 | 说明 |
|------|------|
| **preset 单选** | 左栏全部选项全局仅一项激活；再点同一项或主栏 preset chip ✕ → **`router.replace` 清空全部 query（含 keyword）** |
| **keyword 叠加** | 选中 preset 时保留：`searchTerm`、`customerType`、`industry`、`salesUserId`、`currency`（可与 preset 同时生效） |
| **主栏隐藏** | 有 preset 时隐藏与之冲突的主栏控件：**状态**、**级别**、**创建日期区间**（preset 已展开对应 query） |
| **筛选页签模式** | 结算币别页签/下拉与 preset 可并存（对齐销售订单明细：preset 时进度页签隐藏、币别可保留） |
| **数据权限** | 与列表一致；mask521 隐藏客户名称等敏感列 |

左栏 **不提供** 底部「重置」按钮；取消条件仅通过 **再点同一 preset** 或 **主栏 chip ✕**（与销售订单明细一致）。

## 2. preset 列表（定稿，分阶段交付）

### 2.1 时间（客户创建时间）

锚点：**`customerinfo.CreateTime`**（与现有 `createdFrom` / `createdTo` 一致）。  
日期格式：**本地日历 `YYYY-MM-DD`**；区间 **含起止日**（与 `CustomerListQuery` 后端 `[from, to+1day)` 一致）。

| preset ID | 左栏文案 | 日期区间（本地） |
|-----------|----------|------------------|
| `created_today` | 今日创建的客户 | 今日～今日 |
| `created_last_7_days` | 近7日创建的客户 | 今日往前 **6** 天～今日（共 7 个自然日） |
| `created_last_30_days` | 近30日创建的客户 | 今日往前 **29** 天～今日（共 30 个自然日） |

时间类 **不写** `quickFilter`；由前端展开 `createdFrom` / `createdTo` 写入 URL（展示用保留 `preset`）。

> **与现状差异：** 当前实现使用 `daysAgo(7)` / `daysAgo(30)`，区间比定稿 **多 1 天**；refactor 时改为与 [销售订单明细](../销售/销售订单明细列表-左栏检索-设计与实现.md) 相同口径。

### 2.2 关注

| preset ID | 左栏文案 | 展开 query / API |
|-----------|----------|-------------------|
| `favorite` | 收藏的客户 | `favoriteOnly=1`（列表请求带当前用户收藏 ID 集合） |
| `vip` | VIP客户 | `customerLevel=VIP`（后端 `Level=5`） |

### 2.3 待办

| preset ID | 左栏文案 | 展开 query / API |
|-----------|----------|-------------------|
| `pending_submit` | 待提交客户 | `status=1`（新建，未提交审核） |
| `pending_audit` | 待审核客户 | `status=2`（待审核） |

### 2.4 需求（第二阶段，需后端 `quickFilter`）

锚点：**需求主单/明细创建时间**（具体表与字段在实现阶段与 RFQ 列表对齐，默认 **`RFQ` / 需求明细 `CreateTime`**）。

| preset ID | 左栏文案 | 判定口径（定稿） |
|-----------|----------|------------------|
| `has_demand` | 有需求的客户 | 存在至少一条有效需求记录 |
| `demand_last_7_days` | 近7日发需求的客户 | 存在 **任意一条** 需求落在近 7 个自然日内 |
| `demand_last_30_days` | 近30日发需求的客户 | 同上，近 30 日 |
| `demand_stale_6m` | 半年前发需求的客户 | 存在历史需求，且 **最近一条** 需求创建时间 **早于** 6 个月前（近 6 个月无新需求） |
| `demand_stale_1y` | 1年前发需求的客户 | 同上，锚点为 12 个月 |

「近 N 日」= **窗口内至少有一条**（选项 A，非「最近一条落在窗口内」）。

### 2.5 成单（第二阶段，需后端 `quickFilter`）

锚点：**销售订单 `SellOrder.CreateTime`**（成单日期以订单创建为准）。

| preset ID | 左栏文案 | 判定口径（定稿） |
|-----------|----------|------------------|
| `has_deal` | 已成单的客户 | 存在有效销售订单（建议：`status >= 10` 且非取消/审核失败，与 `CustomersController.IsCommercialSellOrder` 一致） |
| `deal_last_7_days` | 近7日成单的客户 | 存在订单 `CreateTime` 落在近 7 个自然日内 |
| `deal_last_30_days` | 近30日成单的客户 | 同上，近 30 日 |
| `deal_stale_6m` | 半年前成单的客户 | 存在历史成单，且 **最近一条** 订单创建时间 **早于** 6 个月前 |
| `deal_stale_1y` | 1年前成单的客户 | 同上，12 个月 |

### 2.6 业务（第三阶段，需后端 `quickFilter`）

| preset ID | 左栏文案 | 判定口径（与客户首页 KPI 一致） |
|-----------|----------|--------------------------------|
| `pending_shipment` | 有在库的客户 | 存在 **客单**（`StockType=1`）在库明细：`QtyRepertory > 0`、未软删，且能挂到该客户（行上 `CustomerId`，或经 `SellOrderItemId`→销售订单客户）；不含备货/样品 |
| `has_receivable` | 应收款的客户 | 存在未结应收台账：`finance_receivable.VerifiedToBe > 0`（未软删） |

> **码名说明：** URL / `quickFilter` 仍用历史码 `pending_shipment` / `has_receivable`，语义已改为「客单在库 / 应收台账」，勿再按订单头 `StockOutStatus` / `FinanceReceiptStatus` 理解。

**关联：** [客户首页 KPI-设计与实现](./客户首页KPI-设计与实现.md)

## 3. 交互与 UI（对齐销售订单明细）

### 3.1 左栏 `CustomerSearchPanel`

| 项 | 规则 |
|----|------|
| 布局 | 标题「客户检索」+ 分组（时间 / 关注 / 待办 / …）+ 纵向全宽按钮 |
| 样式 | 与 `SalesOrderItemSearchPanel.vue` 一致：`__head` / `__group` / `__list` / `__item`，hover / `is-active` 色值相同 |
| 点击未激活项 | `router.replace`：保留 keyword 区 query → 写入 `preset` + 展开字段 |
| 点击已激活项 | `router.replace({ query: {} })`，**清空全部 query** |
| 单选 | 任意时刻最多一个 preset；选新项替换旧 preset |

### 3.2 主栏 `CustomerList`

| 项 | 规则 |
|----|------|
| preset chip | 有 `preset` 时在筛选区顶部展示文案 + ✕；✕ 行为同「再点同一 preset」 |
| 隐藏控件 | 有 preset 时隐藏：**状态下拉**、**级别下拉**、**创建日期区间** |
| 保留控件 | 关键词、类型、行业、业务员、结算币别（及结算币别页签模式） |
| 主栏「重置」 | 清空全部 query（含 preset、keyword） |
| 路由 | 左栏与 chip 使用 **`router.replace`**（避免堆叠历史） |

### 3.3 与筛选页签模式

- 有 preset 时：**不**隐藏结算币别页签条/下拉（与 SO 明细保留币别一致）。
- preset 与 `crm.customer-list.tab-mode` 独立；清空 query 不清 localStorage 页签偏好。

## 4. URL query 约定

| 键 | 说明 |
|----|------|
| `preset` | 当前左栏 preset ID（展示与单选判断） |
| `quickFilter` | 第二、三阶段业务类 preset 对应后端码（时间/关注/待办类不写） |
| `createdFrom` / `createdTo` | 时间类 preset 展开，或主栏手动日期（有 preset 时主栏日期隐藏） |
| `status` / `customerLevel` / `favoriteOnly` | 待办/关注类 preset 展开 |
| keyword 区 | `searchTerm`、`customerType`、`industry`、`salesUserId`、`currency` |

**驱动链：** 左栏点击 / 主栏查询 / chip ✕ / 重置 → `router.replace` → `watch(route.query)` → 同步表单 → 列表请求。

## 7. 现状与目标差异（第一阶段 refactor 清单）

| 项 | 当前实现 | 目标（本文档） |
|----|----------|----------------|
| URL 模型 | 多字段直接写 query，无 `preset` | 增加 `preset` + 展开字段 |
| 取消 preset | 仅清左栏字段，保留 keyword | **清空全部 query** |
| 路由 | `router.push` | `router.replace` |
| 逻辑位置 | 写在 `CustomerSearchPanel.vue` | 抽到 `customerListPreset.ts` |
| 近7日/30日 | `daysAgo(7)` / `daysAgo(30)` | 往前 6 / 29 天 |
| 主栏 | 无 chip；状态/级别/日期可与左栏叠加 | chip + 有 preset 时隐藏冲突控件 |
| 左栏分组 | 仅时间/关注/待办 | 二、三阶段扩展需求/成单/业务 |
| i18n | 脚本内 `t()` 初始化 chip 文案 | 模板内 `t(presetI18nKey(id))` |
