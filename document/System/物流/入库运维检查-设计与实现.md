# 入库运维检查 — 设计与实现

> **状态：** MVP（2026-08-17）  
> **适用页面：** `/inventory/stock-in/ops-check`（入库管理 → 入库运维检查）  
> **测试对照：** [入库运维检查-测试对照说明](../../QA/物流/入库运维检查-测试对照说明.md)  
> **帮助：** `help/pages/入库运维检查_MENU_STOCK_IN_OPS_CHECK.md`  
> **关联：** [出库运维检查](./出库运维检查-设计与实现.md)、[进项发票反核销](../财务/进项发票反核销-设计与实现.md)

---

## 1. 目的

只读全量核对：到货通知、采购入库单/明细、库存明细、进项核销流水。查出链条中断、状态不一致、重复入库、金额偏差、供应商不一致、核销悬挂。不自动改数。

## 2. 权限与入口

| 项 | 规则 |
|---|---|
| 菜单 | 入库管理最后一项（批次核销之后）；仅 `IsSysAdmin` 或 `IsSysManager` |
| 路由 | `StockInOpsCheck`，须注册在 `inventory/stock-in/:id` **之前**；`meta.adminOrManagerOnly` |
| API | `POST /api/v1/stock-in/ops-check`，`ManagementAccountPolicy.CanForceDelete` |
| 范围 | 全量；结果最多 2000 条 |

无新权限码、无新迁移。物流系统管理员、普通入库菜单用户不可见。

## 3. 扫描范围

仅 **采购入库**（`StockInType` 规范化后为 10；排除移库 3、报关 20、退货 30、报废 40）。已过账 = `stock_in.Status = 2`（界面「标记已入库」）。

到货通知 ↔ 已过账入库：复用 `ArrivalNoticeStatusCalculator.IsPostedStockInLinkedToNotice`（`SourceId` / `SourceCode` / `QcId` / `qc.StockInId`；历史 `SourceId` 可能存通知单号）。已过账单还须 `StockInTypeCode.MatchesNoticeStockInType`。

**不报：** 质检完成但尚未过账入库（那是待入库正常态）。不扫库存汇总桶 vs `stock_item`。不扫进项核销金额对账（只扫悬挂流水）。

## 4. 检查项

| 类别 | 条件 | 级别 | 运维操作建议 |
|---|---|---|---|
| 链条 | 到货通知状态 100 且无已过账采购入库 | 错误 | 若有未过账单：对该入库单号「标记已入库」；再打开「Debug 模拟数据」点「刷新到货通知状态」。无未过账单则只刷新 Debug |
| 状态 | 已有已过账采购入库，通知不是 100 | 错误 | 「Debug 模拟数据」→「刷新到货通知状态」。不写到货列表刷新（该列表无此按钮） |
| 重复 | 同一通知 ≥ 2 张已过账采购入库 | 错误 | **保留入库单号最小的一张**，其余逐步「强制删除」（输入该入库单号确认）；最后 Debug 刷新通知。仅当**被删的那张**有进项核销时，先对该进项发票单号「反核销」 |
| 链条 | 已过账入库明细没有 `stock_item` | 错误 | 该入库若有核销则先进项发票「反核销」；对该入库「强制删除」；质检「生成入库」重入 |
| 链条 | `stock_item` 指向缺失/已删入库明细或已删入库单 | 错误 | 库存明细对该库存明细编号「强制删除」 |
| 重复 | 同一 `stock_in_item_id` ≥ 2 条 `stock_item` | 错误 | 保留库存明细编号最小的一条，其余「强制删除」 |
| 金额 | 已过账入库明细 `Amount` ≠ `Quantity × Price`，容差 0.01（`StockOutOpsCheckAmounts`） | 错误 | 打开该入库详情核对本行；有核销则先进项「反核销」；「强制删除」后质检重入 |
| 供应商 | 通知 / 入库 / 采购订单 `VendorId` 不一致 | 错误 | 打开该采购订单号与入库单详情核对供应商（无「刷新供应商」按钮） |
| 链条 | 进项核销流水存在、入库单缺失或已删 | 错误 | 打开该**进项发票单号**点「反核销」并输入该单号。不出现「到列表里找」 |
| 状态 | 质检已挂已过账入库，但 `QCInfo.StockInStatus` 仍为未入库（1） | 警告 | 打开「质检」该质检单号核对；重新进入质检列表会同步。无单独写按钮 |

建议由服务端按**本行单据**生成：一步一行、①②③ 编号；每步含页面 + 单号 + 按钮。未核销行不得出现反核销步骤。前端建议列 `white-space: pre-line` 保留换行。

到货通知状态刷新只在 Debug 页，不在到货列表。

## 5. 结果过滤（前端切片）

检查仍是全量扫描，过滤不传 API、不缩小扫描范围。下拉即时生效；单号回车或点「搜索」。重置只清过滤，不清已跑出的报告。

| 条件 | 字段 | 规则 |
|---|---|---|
| 单号 | `DocCode` 或 `RelatedDocCode` | 去空格、忽略大小写、**右模糊**（`StartsWith`） |
| 级别 | `Severity` | `error` / `warning`；清空 = 全部 |
| 检查类型 | `Category` | `chain` 链条 / `status` 状态 / `duplicate` 重复 / `amount` 金额 / `vendor` 供应商 |
| 单据类型 | `DocType`（主单） | `arrivalNotice` 到货通知 / `stockIn` 入库单 / `stockInItem` 入库明细 / `stockItem` 库存明细 / `qc` 质检 / `purchaseInvoice` 进项发票 / `purchaseOrder` 采购订单 / `debug` Debug |

标题与筛选之间为数据面板：「错误」（红）、「警告」（橙）、「合计」（青，全量条数）。有过滤时第三张改为「显示 x / y」。无匹配时文案为「当前过滤无匹配」，与「未发现异常」区分。过滤只作用于已返回的最多 2000 条。
