## 1. 口径

按箱出库（来源申请为装箱单号，如 `PAK…`）一头可对应多条销售行：

- 头表 `stock_out.SellOrderItemId` **故意为空**
- 销售行写在 `stock_out_item_extend.sell_order_item_id` / `sell_order_item_code`
- 装箱写在出库明细 `stock_out_item.packing_id`；来源申请已是装箱单号

因此详情 **基本信息不再展示**：

| 原字段 | 原因 |
|---|---|
| 销售订单明细编号 | 头表 1 对 1，与按箱出库粒度不符 |
| 装箱单号 | 与「来源申请」重复，且详情接口未填列表用的 `packingCodes` |

这两项只出现在 **出库明细表**。底部「销售订单明细」按本单出库行扩展表上的销售行加载（去重），不再依赖头表那一个 ID。

通知单线出库（头表仍有销售行）同样走明细列与底部区块，不在头上单独占格。

---

## 2. 实现

| 位置 | 行为 |
|------|------|
| `StockOutDetail.vue` 基本信息 | 去掉销售订单明细编号、装箱单号 |
| 出库明细列 `sellOrderItemCode` / `packingCode` | 编号优先扩展表，否则头表；装箱仍按行 `packing_id` |
| 底部销售订单明细 | `loadItems` 之后按行上 `sellOrderItemId` 拉销售明细 |
| `GetDetailViewAsync` | 头表无销售行时，用扩展表第一条销售行解析业务员 |
| 出库明细列表筛选 | 销售订单明细编号同时匹配扩展表冗余编号 |
