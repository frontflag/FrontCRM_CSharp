本文描述 **FrontCRM（CRM.Web / CRM.API / CRM.Core）** 中 **到货通知列表页**（`ArrivalNoticeList` / `/logistics/arrival-notices`）右侧工作区辅助栏 **「操作」** 页签的设计要求与实现方法。

---

## 1. 业务定位

| 概念 | 说明 |
|------|------|
| **适用页面** | 到货通知列表（路由名 `ArrivalNoticeList`） |
| **展示位置** | `AppLayout` 右侧辅助栏（`aux-right`） |
| **页签 ID** | `r-ops`（文案 `layout.auxTabs.ops` → 中文「操作」） |
| **目标** | 单击列表行查看本行到货概况、**到货信息**、采购/质检/入库摘要，并发起 **确认到货** / **编辑到货信息**；质检/入库等通过 **单号链接** 跳转（§2.5.4） |
| **与列表操作列关系** | 行内「确认到货 / 编辑到货信息 / 质检 / 明细 / 删除」**保留**；右栏为增强入口 |

**在本列表路由下** 注册双页签（操作 + 帮助），默认选中 **操作**；离开路由时 `arrivalNoticeOpsPanelStore.clear()`。

## 2. 布局与交互

### 2.1 卡片结构

```
┌─ 右侧 [操作] [帮助] ─────────────────┐
│ 到货概况（单号 hero + 供应商/PN/…）   │
│ 状态标签（工作流 status）             │
│ 到货信息（方式 / 公司 / 单号 + 编辑） │
│ 确认到货（按钮 / 已完成 ✓）           │
│ 采购（只读 KV）                       │
│ 质检（有记录展示；单号可点）          │
│ 入库（有记录展示 / 空态提示）         │
└──────────────────────────────────────┘
```

### 2.2 列表交互（§2.4 门控）

适用列表含：**销售订单明细、采购订单明细、报关单列表、到货通知列表、质检列表**。  
实现：`useListRightOpsPanelInteraction.ts`。布局见 [销售操作面板 §2.5](../销售订单明细列表-操作面板-设计与实现.md)。

| 场景 | 行为 |
|------|------|
| 右栏收起 + 单击行 | 忽略（不展开、不请求） |
| 展开 + 非「操作」页签 + 单击 | 仅 `setRowOnly` 高亮 |
| 展开 + 「操作」+ 单击 | `selectRow` → 请求 aggregates |
| 采购 511 脱敏 | **仍加载**面板（与列表同源）；敏感字段显示 `—`；按钮按角色权限 |

列表 **搜索/重置/筛选** 触发 `loadData` 时 `resetListRightPanelOnReload`；分页刷新选中行时 `refreshFromListRows` 同步面板。

### 2.4 子面板布局

遵循 [销售操作面板 §2.5](../销售订单明细列表-操作面板-设计与实现.md)：

| 卡片 | 布局 |
|------|------|
| 到货概况 | §2.5.3 概况纵向 Value |
| **状态** | §2.5.1 **3 列**状态标签；仅 1 个状态时占第一列 |
| 到货信息 | §2.5.2 双列 Key:Value + 编辑按钮（见 [编辑到货信息](./到货通知-编辑到货信息-设计与实现.md)） |
| 确认到货 | §2.5.3 操作按钮卡 |
| 采购 / 质检 / 入库 | §2.5.2 **双列 Key:Value**（字段分行见 §3） |

### 2.5 操作按钮

| 按钮 | 显示条件 | 行为 |
|------|----------|------|
| **确认到货** | `status=10` 且 `canWriteLogisticsData` | `PATCH /arrival-notices/{id}/status?status=20` |
| **编辑到货信息** | `ArrivalNoticeArrivalInfoAccessRules.CanEdit` | 打开「编辑到货信息」对话框 |

质检 / 入库详情：**不设**独立主按钮；点击质检单号 / 入库单号跳转（[§2.5.4](../销售订单明细列表-操作面板-设计与实现.md)）。

## 3. 各卡片字段

### 3.1 到货概况（列表行 + 无额外请求）

| 顺序 | 字段 |
|------|------|
| 1 | 到货通知单号（琥珀 hero） |
| 2 | 供应商中/英文名 |
| 3 | PN、品牌 |
| 4 | 预计到货日 |
| 5 | 本批预计数量 `expectQty` |
| 6 | 到货类型标签（采购/报关/退货/报废） |

### 3.2 采购面板（aggregates.purchase）

**布局：** [§2.5.2](../销售订单明细列表-操作面板-设计与实现.md) 双列 Key:Value。

| 行 | 左列 | 右列 |
|----|------|------|
| 1 | 采购明细单号 | 采购员 |
| 2 | 采购日期 | 采购明细数量 |

| 标签 | 口径 |
|------|------|
| 采购明细单号 | `purchaseorderitem.purchase_order_item_code`，可链 `PurchaseOrderDetail?purchaseOrderItemId=` |
| 采购员 | 通知冗余 `purchaseUserName`；**报关入库**时取原始采购主单 `purchaseUserName` |
| 采购日期 | **采购订单主单 `createTime`** |
| 采购明细数量 | **采购行 `qty`** |

**报关入库（`StockInType=20`）**：到货通知本身无 `PurchaseOrderItemId`；服务沿 `customs_declaration_item.source_stock_item_id` → `stock_item`（必要时经 `stock_in_item_extend`）解析 **原始采购明细** 与主单，填充本面板（与报关单业务记录「原始采购」口径一致）。

### 3.3 质检面板（aggregates.qc）

**布局：** [§2.5.2](../销售订单明细列表-操作面板-设计与实现.md) 双列 Key:Value。

| 行 | 左列 | 右列 |
|----|------|------|
| 1 | 质检单号 | 质检人 |
| 2 | 质检日期 | — |
| 3 | 合格数量 | 不合格数量 |

有记录：上述字段；**质检单号**可链 `QcCreate?noticeId=&qcId=`（§2.5.4，无「查看质检」按钮）。  
无记录：「尚未生成质检记录」。

### 3.4 入库面板（aggregates.stockIn）

**布局：** [§2.5.2](../销售订单明细列表-操作面板-设计与实现.md) 双列 Key:Value。

| 行 | 左列 | 右列 |
|----|------|------|
| 1 | 入库单号 | 操作人 |
| 2 | 入库日期 | — |
| 3 | 入库状态 | 入库类型 |
| 4 | 仓库 | 入库数量 |

有记录：上述字段（入库单号链 `StockInDetail`）。  
无记录：「尚未生成入库记录」。

入库单匹配：`QC.StockInId`，或 `stock_in.source_id = noticeId`，或 `stock_in.qc_id = qc.Id`（与扩展表状态回写一致）。

## 4. API

`GET /api/v1/logistics/arrival-notices/{id}/ops-aggregates`

响应（`ApiResponse<ArrivalNoticeOpsAggregates>`）：

- `purchase`：`PurchaseOrderItemCode`、`PurchaseUserName`、`PurchaseOrderCreateTime`、`Qty` 等  
- `qc`：单号、创建时间、创建人、合格/不合格数量  
- `stockIn`：单号、日期、操作人、状态、类型、仓库名、数量  

采购 511 脱敏时清空采购明细单号与采购员。

## 6. 权限

| 能力 | 权限 / 条件 |
|------|-------------|
| 进入列表 | `purchase-order.read`（路由既有） |
| 确认到货 | `canWriteLogisticsData`（部门物流非只读） |
| 采购单链接 | 非 511 脱敏 |
| 查看质检 / 入库链接 | 点击面板内 **质检单号 / 入库单号**（§2.5.4）；沿用各详情页权限 |
