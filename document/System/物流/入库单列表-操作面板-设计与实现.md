本文描述 **FrontCRM** 中 **入库单列表页**（`StockInList` / `/inventory/stock-in`）右侧工作区辅助栏 **「操作」** 页签的设计要求与实现方法。

## 1. 业务定位

| 概念 | 说明 |
|------|------|
| **适用页面** | 入库单列表（路由名 `StockInList`）；**不含** 新建 `StockInCreate`、详情 `StockInDetail` |
| **展示位置** | `AppLayout` 右侧辅助栏（`aux-right`） |
| **页签 ID** | `r-ops`（文案 `layout.auxTabs.ops` → 中文「操作」） |
| **目标** | 单击列表行查看入库概况、状态、备注、采购/到货摘要，并发起 **修改备注** |
| **与列表操作列关系** | 行内「修改备注 / 标记已入库 / 删除 / 强制删除」**保留**；本版右栏 **不纳入** 标记已入库与删除 |
| **流程页签** | 由 [入库单列表-流程页签-设计与实现](./入库单列表-流程页签-设计与实现.md) 描述；列表模式注册 `r-flow`，与「操作」并列，**默认仍「操作」** |
| **看板模式** | **不注册** `r-ops` / `r-flow`（右栏仅「帮助」）；清空选中、**不请求** aggregates、不选行 |

**在本列表路由下（列表模式）** 注册三页签（操作 + 流程 + 帮助），进入路由默认 **操作**（可被按路由记忆覆盖）；离开路由时 `stockInOpsPanelStore.clear()` 与 `stockInFlowPanelStore.clear()` 分别执行。

## 2. 布局与交互

### 2.1 卡片结构

```
┌─ 右侧 [操作] [帮助] ─────────────────┐
│ 入库概况（单号 hero + 供应商/PN/…）   │
│ 状态标签（工作流 status）             │
│ 备注（正文 + 编辑备注）               │
│ 采购订单（只读 KV）                   │
│ 到货通知（只读 KV）                   │
└──────────────────────────────────────┘
```

五张卡片 **直接作为页签内容子级** 纵向排列；嵌入模式 `embedded`，样式 `so-item-ops-panel.scss`。

### 2.2 列表交互（§2.4 门控）

适用列表增加 **入库单列表**。实现：`useListRightOpsPanelInteraction.ts`。

| 场景 | 行为 |
|------|------|
| 右栏收起 + 单击行 | 忽略（不展开、不请求） |
| 展开 + 非「操作」页签 + 单击 | 仅 `setRowOnly` 高亮 |
| 展开 + 「操作」+ 单击 | `selectRow` → 请求 aggregates |
| 展开 + 由非「操作」→ 点「操作」 | 若 store 已有选中行 → `loadAggregates` |
| 双击行 | 跳转入库详情（与单击互不冲突） |
| 采购 511 脱敏 | **仍加载**面板；供应商/单价/采购员/采购明细单号为 `—`；报关公司名仍显示 |
| 搜索 / 重置 | `resetListRightPanelOnReload` 清空选中 |
| 分页刷新 | `refreshFromListRows` 同步选中行 |
| 切到看板 | 摘掉「操作」页签（仅帮助）；清空选中，不请求 |
| 切回列表 | 重新注册「操作 + 帮助」，默认操作 |

### 2.3 子面板布局

| 卡片 | 布局 |
|------|------|
| 入库概况 | §2.5.3 **概况**（身份行无标签；日期/单价/数量为 §2.5.2 KV） |
| 状态 | §2.5.1 独立状态卡，单标签占 3 列第一格 |
| 备注 | 正文 + 卡底通栏主按钮（对齐到货通知「编辑到货信息」） |
| 采购 / 到货 | §2.5.2 双列 Key:Value |

### 2.4 操作按钮

| 按钮 | 显示条件 | 行为 |
|------|----------|------|
| **修改备注** | `canWriteLogisticsData` | 打开列表现有备注对话框（`stockInApi.update`） |

无物流写权限：备注卡仍展示正文，**不渲染**按钮。  
本版 **不** 把「标记已入库」放进右栏。

### 2.5 单号链接（§2.5.4）

| 字段 | 路由 |
|------|------|
| 入库单号（概况 hero） | `StockInDetail` |
| 采购明细单号 | `PurchaseOrderDetail` + `purchaseOrderItemId` query |
| 到货通知单号 | `ArrivalNoticeList` + `noticeId` query |

511 时采购明细单号不链出。

## 3. 各卡片字段

### 3.1 入库概况（列表行；单价可被 aggregates 覆盖）

| 顺序 | 内容 |
|------|------|
| 1 | 入库单号（琥珀 hero，可链详情） |
| 2 | 供应商中/英文名（`VendorNameReadonlyText`；脱敏 `—`） |
| 3 | 物料型号 `materialModelSummary` |
| 4 | 品牌 `materialBrandSummary` |
| 5 | 「入库日期」`stockInDate`（无日期 `—`） |
| 6 | **同一行双列：** 左「采购单价」+ 币别（优先 aggregates 采购行 `cost`/`currency`；否则列表 `unitPriceSummary`；脱敏 `—`）；右「入库数量」`{totalQuantity} pcs`（不加粗、不用强调色） |
| 7 | 入库类型 `StockBizTypeTag`；**报关入库**时图标 + 报关公司名称（无名不渲染 `—`） |

**不含仓库。** 概况卡无主按钮。

### 3.2 状态

与列表状态文案一致：草稿 / 待入库 / 已入库 / 已取消。

### 3.3 备注

有内容：原文折行；无内容：`—`。卡片始终渲染。保存后列表列与面板同步。

### 3.4 采购订单（aggregates.purchase）

| 行 | 左列 | 右列 |
|----|------|------|
| 1 | 采购明细单号 | 采购订单类型（客单 / 备货 / 样品） |
| 2 | 采购日期（主单创建日） | 采购员 |
| 3 | 采购明细数量 | 采购单价 + 币别 |

无记录：「暂无关联采购明细」。报关入库走原始采购溯源（与到货/质检操作面板一致）。本版 **只展示第一条** 采购明细。

### 3.5 到货通知（aggregates.arrivalNotice）

| 行 | 左列 | 右列 |
|----|------|------|
| 1 | 到货通知单号 | 到货类型 `StockBizTypeTag` |
| 2 | 实到日期（无则 `—`，不回落预计到货日） | （右空） |
| 3 | 到货数量（`receiveQty` 实收） | 质检通过（`qc.passQty`；无质检 `—`） |

无记录：「暂无关联到货通知」。

## 4. API

`GET /api/v1/stock-in/{id}/ops-aggregates`

授权与入库详情相同（不可见 403）。响应 `ApiResponse<StockInOpsAggregates>`：

- `purchase`：采购明细单号/主单/类型/采购员/日期/数量/单价/币别  
- `arrivalNotice`：通知单号、类型、实到日、实收数量、质检通过量  

到货通知主键：入库头 `SourceId`；空则经 `QcId` → 质检 `StockInNotifyId`。再复用 `GetArrivalNoticeOpsAggregatesAsync` 解析采购与质检。

采购 511 清空采购明细单号、采购员、单价与币别。

列表行另回填 `customsBrokerName`（报关入库溯源，不落库）。
