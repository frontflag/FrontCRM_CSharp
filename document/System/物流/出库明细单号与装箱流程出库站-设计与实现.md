## 1. 问题

1. **`stock_out_item` 没有业务单号。** 出库明细列表、流程卡只能写出库单号 + 型号 + 数量，无法像销售明细（`SO00238-1`）那样点名「哪一行」。
2. **装箱「流程」出库站展示不准。** 现用销售明细聚合的出库**单头**，再按装箱单号 `packingCodes` 过滤，数量取单头 `TotalQuantity`。一张多行装箱单、或同一销售行被重复执行出库时，一条装箱明细会看到多张整箱数量的出库单，对不上本行数量。

本设计两件事一起做：先有正式的出库明细单号，再按装箱行对齐真实出库明细。

---

## 2. 已确认口径

| # | 项 | 决定 |
|---|-----|------|
| 1 | 编号形态 | `{出库单号}-{行序号}`，与销售/采购/入库/装箱明细同构。例：`STO00221-1` |
| 2 | 工具函数 | `OrderLineItemCodes.StockOut(stockOutCode, seq)` |
| 3 | 存哪 | `stock_out_item.stock_out_item_code`（实体 `StockOutItem.StockOutItemCode`），**不**放扩展表 |
| 4 | 不用装箱/拣货行号 | 出库明细号挂在出库单下；装箱行拆库存或重复出库时，复用 `PAK…` 会撞号或说不清归属 |
| 5 | 出库站对齐 | `packing_item` → `pickingtaskitem.packing_item_id` → `stock_out_item.picking_task_item_id` → `stock_out` |
| 6 | 数量 | 出库站卡片用该出库明细 `ActualQty`（空则 `Quantity`），**不用**单头 `TotalQuantity` |
| 7 | 一对多 | 一行装箱可对应 N 条出库明细（拆拣货行，或重复执行出库）。全展示，不合并、不隐藏 |
| 8 | 对不上 | 无拣货行或对不上出库明细 → 出库站「未开始」，**不再**回退为「该销售行全部出库单」 |
| 9 | 本版不做 | 新造与出库单号无关的流水号；列级 `NOT NULL`（写入已强制有号，历史空号仍可空） |
| 10 | 其它站数量 | 装箱流程销售行 / 出库通知 / 拣货按本装箱行数量；出库站仍用该出库明细数量 |
| 11 | 重复出库 | 装箱单已有未取消的有效出库明细时，批量/执行出库拒绝再出 |

## 3. 出库明细单号

### 3.1 规则

- 同一张出库单内按**创建顺序**从 `1` 起编：`{StockOutCode}-1`、`-2`…。
- 出库单号全局唯一，故明细单号也全局唯一（与 `SO00238-1` 相同）。
- 调拨虚拟出库同样赋号（通常一行：`{虚拟出库单号}-1`）。
- 软删行也回填/保留编号，避免恢复后撞号。
- 列长 `varchar(64)`：头表 `StockOutCode` 最长 32，加 `-{seq}` 足够。

### 3.2 写入点

| 路径 | 行为 |
|------|------|
| `StockOutService.ExecuteStockOutAsync`（装箱批量 / 执行出库页） | 创建每条 `StockOutItem` 时赋号 |
| `InternalTransferPostingKernel` 虚拟出库行 | 同步赋号 |
| 其它 `new StockOutItem` | 必须走同一赋号函数，禁止漏写 |

历史数据：按 `StockOutId` 分组，组内按 `CreateTime`、`ItemId` 排序回填。回填后对非空值建**全局唯一**索引。

### 3.3 展示与检索

| 位置 | 行为 |
|------|------|
| 出库明细列表 | 增加「出库明细单号」列；筛选支持单号/子串（可与出库单号同一输入或独立框，实施时与列表习惯对齐）；另支持单头 **出库类型**（销售含历史 1，见 [翻页查询规范](../翻页查询规范.md)）；列表在「出货方式」前展示出库类型标签。主表套用 [业务列表规范](../../PRD/规范/UI规范/业务列表规范.md)（列设置、行高、分页底栏） |
| 出库单详情明细表 | 露出明细单号 |
| 装箱流程出库站 | 单号=出库单号（可点）；出库明细=出库明细单号；数量=本行数量 |
| 导出 CSV | 出库明细导出含该列（与列表脱敏规则一致） |

主键、外键、核销、利润快照仍用 `ItemId`，编号只作展示与检索。

## 4. 装箱流程出库站

三处共用 `PackingItemFlowPanel` / `buildPackingItemFlowStations`，出库站口径必须一致：

- 装箱明细列表：单击行（无 chip）
- 装箱单列表：单击箱 + 顶部明细单号
- 装箱单详情：单击装箱行

### 4.1 对账链路

```
packing_item.Id
  → pickingtaskitem.packing_item_id
  → stock_out_item.picking_task_item_id
  → stock_out
```

不再用 `aggregates.stockOuts` + `packingCodes` 匹配单头。

### 4.2 出库站卡片

| 字段 | 取值 |
|------|------|
| 单号 | `stock_out.StockOutCode`，链到出库单详情 |
| 出库明细 | `stock_out_item.StockOutItemCode` |
| 数量 | 该行实出数量 |
| 状态 / 日期 / 客户 | 出库单头（521 脱敏同现网） |

一装箱行拆成多条拣货行 → 多张卡。重复执行出库 → 多张卡（例如 `STO00221-1`、`STO00222-1`，数量均为本行数量）。

### 4.3 数据

绑定装箱行时，按 `packingItemId` 查该行出库明细（服务端 JOIN 拣货行），写入 store extras，适配器只渲染 extras，不回退销售行全量出库单。

建议接口（实施时可并入现有 packing/stock-out 控制器）：

`GET /api/v1/packing/items/{packingItemId}/flow-stock-out-lines`

返回：`stockOutId`、`stockOutCode`、`stockOutItemId`、`stockOutItemCode`、`qty`、`status`、`createTime`、客户/创建人（按 521 掩）。

## 5. 关系（对照）

| 关系 | 口径 |
|------|------|
| 出库单 : 出库明细 | 1 : N（编号 `{单号}-{序}`） |
| 出库明细 : 拣货行 | 装箱主路径 1 : 1（`picking_task_item_id`） |
| 装箱明细 : 拣货行 | 1 : N（一行装箱拆多条库存） |
| 装箱单 : 出库单 | 主路径 1 : 1；重复执行可 1 : N（本版如实展示，不拦） |

无拣货的 FIFO 非装箱出库、调拨虚拟出库：有明细单号，但不进入装箱流程出库站。

---

## 6. 权限与脱敏

- 出库明细列表 / 装箱流程：沿用现网 read（销售或采购只读即可进物流列表者保持不变）。
- 521：客户名、金额等仍掩；**明细单号、出库单号、数量不掩**（与销售明细单号可见、客户名掩的习惯一致）。
- 脱敏不拦截流程加载。
