# 出入库类型旧枚举刷新 — 功能要求与实现说明

> **状态：** 阶段 A 已落地（`stock_in` / `stock_out` 及同源类型列盘点 `1/2/4 = 0`）  
> **实施方案：** [出入库类型旧枚举刷新实施方案](../../实现方案/出入库类型旧枚举刷新实施方案.md)  
> **不修改** `document/EBS/`

本文约定：仅将库存链路中的 **旧出入库类型 `1/2/4` 刷成现行 `10/30/40`**。采购订单、销售订单的 `status` **不在范围内**。

---

## 1. 背景

现行类型码（`StockInTypeCode` / `StockOutTypeCode`）：

| 值 | 入库 | 出库 |
|----|------|------|
| **10** | 采购入库 | 销售出库 |
| **20** | 报关入库 | 报关出库 |
| **40** | 报废入库 | 报废出库 |
| **30** | 退货入库 | 退货出库 |
| **3** | 移库虚拟入库 | 移库虚拟出库 |

历史写入曾用 `1`（采购/销售）、`2`（退货）、`4`（报废）。EF 迁移与 2026-08 运维刷新后，**`stock_in` / `stock_out`（及通知、质检、装箱）存量 `1/2/4` 已为 0**。现行落库为 `10/20/30/40`，移库仍为 `3`。创建路径不会再写 `1/2/4`（入参旧码经 `Normalize` 会变成 `10`，不会原样落库）。

界面已禁止把未知类型兜成采购/销售；筛选「采购/销售」只查 `10`。

---

## 2. 映射（仅此四条）

| 旧值 | 新值 | 说明 |
|------|------|------|
| 1 | 10 | 采购入库 / 销售出库 |
| 2 | 30 | 退货 |
| 4 | 40 | 报废 |
| **3** | **不改** | 仍是移库 |

**不映射：** `0`、空、`20`、未识别值。禁止把未知改成 `10`。

---

## 3. 范围

### 3.1 刷新列（类型字段）

| 表 | 列 | 方向 |
|----|----|------|
| `stock_in` | `"StockInType"` | 入 |
| `stockin_notify` | `"StockInType"` | 入 |
| `qcinfo` | `"StockInType"` | 入 |
| `stock_out` | `"StockOutType"` | 出 |
| `stockout_notify` | `"StockOutType"` | 出 |
| `packing` | `"StockOutType"` | 出 |

明细表（`stock_in_item`、`stock_out_item` 等）**无**独立类型列，不刷。

### 3.2 明确不做

| 对象 | 原因 |
|------|------|
| `purchaseorder.status` / `purchaseorderitem.status` | 现行 1=新建、2=待审核，不是出入库类型 |
| `sellorder.status` | 同上；勿运行 `migrate_sellorder_status_to_10_20_100.sql` |
| 扩展表 `*_progress_status` | 现行 0/1/2 = 待/部分/完成 |
| `stock_out."Type"` | 与 `StockOutType` 独立，含义不同 |
| 值 `3` | 移库 |

---

## 4. 风险与缓解

| 风险 | 缓解 |
|------|------|
| 把订单 `status` 当成类型刷 | 脚本只 `UPDATE` 上表类型列；评审清单勾选「未改 status」 |
| 把 `3` 改成 30 | `WHERE` 仅 `IN (1,2,4)` |
| 漏刷同源表 | 六张表同一事务；刷前/刷后用盘点 SQL 对账 |
| 刷完立刻删代码兼容 | 分阶段：先数据，再写入映射，确认残留为 0 后再删 `LegacyPurchase` / 前端认 `1` |
| 筛选桶变化 | `1` 变成 `10` 后会进入「采购/销售」页签，这是预期 |

残留 `2/4` 时，后端 `Normalize` 会把非业务白名单值落到采购/销售 `10`，前端却显示退货/报废。刷成 `30/40` 是在消除该不一致。

---

## 5. 分阶段

| 阶段 | 内容 | 完成标准 |
|------|------|----------|
| **A 存量** | 六表幂等 `UPDATE`；只改 `1/2/4` | **已完成**：盘点 `1/2/4 = 0`；`3` 未改 |
| **B 写入** | 主创建路径已写 `10/20/30/40` / `3`，不再生成 `1/2/4` | **已满足**（未再单独立项改 `Normalize`） |
| **C 收口**（观察后再做） | 去掉读路径对 `1` 的兼容（`IsPurchaseReceipt`、前端 `n===1`） | 盘点持续为 0 后再做；**本期不改代码** |

阶段 C **不**把 `Normalize` 的「未知→采购/销售」改回来；未知仍按产品规则保持未知。
