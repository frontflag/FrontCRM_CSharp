# 装箱单状态刷新 — 设计与实现

> **状态：** 已实现（2026-07-30）  
> **适用页面：** 装箱单详情 `/inventory/packing/:id`  
> **关联：** [装箱单详情-流程页签-设计与实现](./装箱单详情-流程页签-设计与实现.md)、强制删除出库

---

## 1. 问题

管理员强制删除出库单后，库存与出库通知会回滚，但装箱单主状态可能仍停留在 **出库完成（100）**，流程页签「装箱」站显示已完成，而「拣货 / 出库」显示未开始。

## 2. 方案（C + B）

| 路径 | 行为 |
|------|------|
| **B. 详情「刷新」** | `POST /api/v1/packing/{id}/refresh-status`，按有效出库事实对账状态后重载详情与流程 |
| **C. 强制删除出库** | `ForceDeleteWithInventoryRollbackAsync` 末尾对关联 `stock_out_item.packing_id` 装箱单跑同一套对账 |

## 3. 对账规则

有 **未删除** 且状态为已出库（`stock_out.Status` ∈ {2, 4}）的关联出库（任一即算有效）：

- 出库明细 `stock_out_item.packing_id` = 装箱单；或
- 出库头 `stock_out.SourceId` = 装箱单（按箱出库）

则 → 装箱状态 **100（出库完成）**（可上行）

否则：

- 当前为 **100 / 50** → **40（已备货）**（允许下行）
- 其它状态不变

实现：`IPackingStatusReconcileService` / `PackingStatusReconcileService`。

刷新无变化且仍有有效出库时，结果带 `blockingStockOutCodes`（阻挡回退的出库单号），详情弹窗直接展示，避免「流程出库站未开始」却对账仍判有出库时无处排查。

**强制删除出库：** 须先 `SaveChanges` 落库软删，再对账装箱。若在未提交前查库，`is_deleted` 仍为 false，会误判「仍有有效出库」导致装箱停在 100。

### 3.1 流程「出库」站与对账口径不一致（已修）

按箱出库时头表 `stock_out.SellOrderItemId` 为空，销售行写在 `stock_out_item_extend`。原先销售明细聚合只按头表销售行查看出库 → 装箱流程「出库」恒为「未开始」，但刷新对账仍能通过 `packing_id` / `SourceId` 命中有效出库。

已改为聚合同时纳入 extend 关联；装箱单号展示亦补上 `SourceId`=装箱单路径。

## 4. 权限

| 操作 | 权限 |
|------|------|
| 详情「刷新」 | `IsSysAdmin` **或** `IsSysManager`（产品 Admin） |
| 强制删除出库 | 仍仅 `IsSysAdmin`（不变）；删除成功后自动对账装箱，无需再点刷新 |

## 5. 前端

`PackingDetailPage.vue` 页头右侧「刷新」按钮（样式对齐销售订单详情）；仅 SuperAdmin / SYS_MANAGER 可见。
