## 1. 目的

只读全量核对：装箱单、装箱明细、出库单、出库明细、应收款。查出链条中断、状态不一致、金额/币别偏差、客户不一致、重复出库。不自动改数。

## 2. 权限与入口

| 项 | 规则 |
|---|---|
| 菜单 | 出库管理最后一项；仅 `IsSysAdmin` 或 `IsSysManager` |
| 路由 | `StockOutOpsCheck`，`meta.adminOrManagerOnly` |
| API | `POST /api/v1/stock-out/ops-check`，`ManagementAccountPolicy.CanForceDelete` |
| 范围 | 全量；结果最多 2000 条 |

物流系统管理员、普通出库菜单用户不可见。

## 3. 检查项

排除 `StockOutType = 3`（调拨虚拟出库）。有效出库 = 未删除且状态 ∈ {2, 4}。

| 类别 | 条件 | 级别 | 运维操作建议 |
|---|---|---|---|
| 链条 | 装箱状态 100 且无有效出库 | 错误 | 装箱单详情点「刷新」 |
| 链条 | 装箱 100 但装箱行对不上出库明细 | 错误 | 装箱单详情核对明细；出库单列表「强制删除」后按流程重出 |
| 链条 | 销售出库状态 4 无应收 | 错误 | 出库单列表「强制删除」后重出，再点「标记完成」 |
| 链条 | 应收存在、出库单缺失或已删 | 错误 | 未核销：应收款详情「作废应收」；已核销：收款单「反核销」后再作废 |
| 状态 | 有有效出库但装箱不是 100 | 错误 | 装箱单详情点「刷新」 |
| 状态 | 已有有效出库，通知不是已出库/已取消 | 警告 | 出库单列表未完成则「标记完成」 |
| 重复 | 一装箱单 ≥ 2 张有效出库 | 错误 | 出库单列表「强制删除」多余单（已核销先收款单「反核销」），装箱单详情「刷新」 |
| 重复 | 一装箱行对应 ≥ 2 张出库单 | 错误 | 同上 |
| 金额 | 应收数量 ≠ 出库明细数量合计 | 错误 | 作废应收后强制删除出库并重出「标记完成」 |
| 金额 | 应收金额 ≠ Σ(出库数量 × 销售行单价)，容差 0.01 | 错误 | 同上 |
| 金额 | 应收币别 ≠ 销售订单币别 | 错误 | 同上 |
| 客户 | 装箱 / 出库 / 应收 / 销售订单 `customer_id` 不一致 | 错误 | 销售订单详情「刷新 ▾ → 刷新客户」 |
| 客户 | 主键一致但应收名称 ≠ 客户主数据 | 警告 | 销售订单详情「刷新 ▾ → 刷新客户」 |

销售出库不查供应商（本类型不适用）。出库明细单价常为 0，金额以销售行为准。

装箱行对齐：`packing_item` → `pickingtaskitem.packing_item_id` → `stock_out_item.picking_task_item_id`，或 `packing_id` + 扩展表销售行。

## 4. 结果过滤（前端切片）

检查仍是全量扫描，过滤不传 API、不缩小扫描范围。下拉即时生效；单号回车或点「搜索」。重置只清过滤，不清已跑出的报告。

| 条件 | 字段 | 规则 |
|---|---|---|
| 单号 | `DocCode` 或 `RelatedDocCode` | 去空格、忽略大小写、**右模糊**（`StartsWith`） |
| 级别 | `Severity` | `error` / `warning`；清空 = 全部 |
| 检查类型 | `Category` | `chain` 链条 / `status` 状态 / `duplicate` 重复 / `amount` 金额 / `customer` 客户 |
| 单据类型 | `DocType`（主单） | `packing` 装箱单 / `packingItem` 装箱明细 / `stockOut` 出库单 / `receivable` 应收款 |

顶栏统计为「错误 / 警告」分项：标签灰色、数字着色（错误红、警告橙），项间竖线分隔。有过滤时另显「显示 x / y」。无匹配时文案为「当前过滤无匹配」，与「未发现异常」区分。过滤只作用于已返回的最多 2000 条。
