## 一、功能定位

为库存相关数据提供**可审计的导出**：

1. **列表导出**：入库单、出库单、库存桶、库存明细按当前筛选导出 CSV；
2. **批次导出**：批次核销列表、入库单/装箱单/采购订单/销售订单详情批次面板导出 CSV；
3. 每次导出由**服务端**写入 `log_operation`：**导出动作** + **导出条件**（前端传入的 query）；
4. **查看入口**：系统日志 → **导出日志**（操作日志不再列出导出行）；单据详情批次面板「导出记录 / 操作日志」Tab 仍展示该单条件摘要。

本能力属于 **`log_operation` 操作审计**，不是 Telemetry 行为埋点。

## 二、已确认设计口径

| # | 项 | 决定 |
|---|-----|------|
| 1 | 范围 | 入库单 / 出库单 / 库存桶 / **库存明细**列表导出；批次导出同一审计规范 |
| 2 | 条件粒度 | 只记**前端传入的 query**（不记数据范围权限折叠后的最终条件） |
| 3 | 敏感字段 | 客户名 / 供应商名等按**列表脱敏规则**写入文件与日志（口径 B） |
| 4 | 查看入口 | 系统「导出日志」+ 详情「导出记录」Tab；均展示**条件摘要** |
| 5 | 写入时机 | **导出 API 服务端**写 `log_operation`；禁止仅依赖前端二次 `log-export` |
| 6 | 空条件 | `filters` 仍写入（可为 `{}`）；摘要为「全部（无筛选）」 |
| 7 | 条件展示 | `filterSummary` 中仓库 Id、枚举/状态码等转为**业务名称**；`filters` 仍保留原始码值 |

## 三、实现现状（对照设计目标）

### 3.1 列表导出

| 页面 | 路由 / 组件 | API | ActionType |
|------|-------------|-----|------------|
| 入库单列表 | `/stock-ins` · `StockInList.vue` | `GET /api/v1/stock-in/export` | `StockInListExport` |
| 出库单列表 | `/stock-outs` · `StockOutList.vue` | `GET /api/v1/stock-out/export` | `StockOutListExport` |
| 库存桶 | `/inventory/bucket` · `InventoryBucketList.vue` | `GET /api/v1/inventory-center/overview/export` | `InventoryStockListExport` |
| 库存明细 | `/inventory/stock-items` · `InventoryStockItemList.vue` | `GET /api/v1/inventory-center/stock-items/export` | `InventoryStockItemListExport` |

- 按钮位置：页头右侧，样式类 `btn-export`（浅黄）。
- 文件名：中文业务名 + `_yyMMddHHmm.csv`（如 `入库单列表_2607212015.csv`）。
- 上限：默认 **50000** 行；截断时描述含「已截断」，`ExtraInfo.truncated=true`。
- **出库单列表 CSV：** 状态 / 出库类型 / 出货方式写**业务名称**（如「出库完成」「报关出库」「快递」），不写数字码。客户列改为中文/英文名称（不再导出原「客户」列），并含销售单价、销售单价币别、金额币别。销售单价优先出库明细扩展销售价，否则销售订单行单价（多行去重逗号拼接）；头表金额为 0 时 **金额 = Σ(出库数量 × 销售单价)**；**金额币别与销售单价币别一致**。
- **库存明细列表 CSV：** 供应商列改为中文/英文名称（不再导出原「供应商」列），并含采购单号、在库单价、在库单价币别、在库金额、在库金额币别。在库单价=在库层采购单价快照；**在库金额 = 当前在库数量 × 在库单价**；金额币别与在库单价币别一致。采购敏感角色掩码供应商名称与单价/金额。

### 3.2 批次导出

| 入口 | API | 日志挂靠 |
|------|-----|----------|
| 批次核销 · 入库/出库 | `GET .../batch-reconciliation/export/in-batches`、`.../out-batches` | `BizType=BatchReconciliation` 或按 `exportSource` 挂单据 |
| 入库单详情 · 入库批次 | 同上 + `exportSource=stockIn` | `StockIn` / `StockInBatchExport` |
| 装箱单详情 · 出库批次 | 同上 + `exportSource=packing` | `Packing` / `StockOutBatchExport` |
| PO 详情 · 入库批次 | 同上 + `exportSource=purchaseOrder` | `PurchaseOrder` |
| SO 详情 · 出库批次 | 同上 + `exportSource=salesOrder` | `SalesOrder` |

前端已去掉二次 `log-export`；统一由 `InventoryExportHttp.AppendBatchExportLogAsync` 在导出成功后写入。

### 3.3 导出日志查看

| 入口 | 说明 |
|------|------|
| 系统日志 → 导出日志 | `ExportLogList.vue`；导出行已从操作日志排除 |
| 入库/装箱/PO/SO 批次面板 | 「操作日志 / 导出记录」内页签；列含条件摘要 |

列表级导出（无单号）仍写 `log_operation`：`RecordId=list`，`RecordCode` 如 `STOCK_IN_LIST`、`INVENTORY_STOCK_ITEM_LIST`；集中查看走导出日志。

## 五、审计模型

### 5.1 存储

表 **`log_operation`**，经 `IExportOperationLogService` → `ILogOperationAppendService.AppendAsync`。不新增独立导出日志表。

### 5.2 BizType / ActionType / Record

| 场景 | BizType | ActionType | RecordId / RecordCode |
|------|---------|------------|------------------------|
| 入库单列表 | `StockIn` | `StockInListExport` | `list` / `STOCK_IN_LIST` |
| 出库单列表 | `StockOut` | `StockOutListExport` | `list` / `STOCK_OUT_LIST` |
| 库存桶列表 | `InventoryStock` | `InventoryStockListExport` | `list` / `INVENTORY_STOCK_LIST` |
| 库存明细列表 | `InventoryStockItem` | `InventoryStockItemListExport` | `list` / `INVENTORY_STOCK_ITEM_LIST` |
| 批次核销 · 入库/出库 | `BatchReconciliation` | `BatchReconciliationInExport` / `OutExport` | `list` / `BATCH_RECON_IN` \| `OUT` |
| 入库详情批次 | `StockIn` | `StockInBatchExport` | 入库单 Id / Code |
| 装箱详情批次 | `Packing` | `StockOutBatchExport` | 装箱单 Id / Code |
| PO 详情批次 | `PurchaseOrder` | `PurchaseOrderStockInBatchExport` | PO Id / Code |
| SO 详情批次 | `SalesOrder` | `SalesOrderStockOutBatchExport` | SO Id / Code |

`operationDesc` 示例：`导出入库单列表 120 条`、`导出库存明细列表 15 条（已截断）`。

### 5.3 ExtraInfo JSON

```json
{
  "schemaVersion": 1,
  "exportKind": "inventoryStockItemList",
  "exportedCount": 15,
  "affectedCount": 15,
  "maxRows": 50000,
  "truncated": false,
  "filters": { "warehouseId": "def6b268-…", "outboundStatus": 1 },
  "filtersMasked": false,
  "filterSummary": "仓库=深圳仓；出库状态=未出库"
}
```

| 字段 | 说明 |
|------|------|
| `filters` | 规范化 query（去 `page`/`pageSize`/`currentUserId`/`exportSource`）；保留原始码值 |
| `filterSummary` | 服务端生成中文摘要；键名中文标签；值做业务名称映射 |
| `filtersMasked` | 是否按 511/521 脱敏写入 |

### 5.4 `filterSummary` 业务名称映射

| 键 | 展示规则 |
|----|----------|
| `warehouseId` | 写日志时查仓库主数据 → **仓库名称**（解析失败则保留 Id） |
| `stockInType` | 采购入库 `10` / 报关入库 `20` / 退货入库 `30` / 报废入库 `40` / 调拨入库 `3`（存量旧码 `1/2/4` 已刷净） |
| `stockOutType` | 销售出库 `10` / 报关出库 `20` / 退货出库 `30` / 报废出库 `40` / 调拨出库 `3`（存量旧码 `1/2/4` 已刷净） |
| `stockType` | 客单库存 / 备货库存 / 样品库存 |
| `status`（出库单列表） | 草稿 / 待出库 / 准备出库 / 已取消 / 出库完成 |
| `outboundStatus` | 未出库 / 部分出库 / 出库完成 |
| `repertoryHasStock` | 有库存 / 无库存 |
| `shipmentMethod` | 送货 / 自提 / 快递 |

实现：`ExportOperationAudit.BuildFilterSummary` + `ExportFilterDisplayContext`；`ExportOperationLogService` 在含 `warehouseId` 时加载仓库名。

### 5.5 敏感字段（口径 B）

- 前端脱敏场景不传敏感筛选项；服务端对 CSV 与日志同步应用 511/521 掩码。
- 库存明细导出：供应商/采购价/毛利等走采购脱敏；客户/业务员/毛利等走销售脱敏。

## 六、实现方法（代码入口）

### 6.1 后端

| 职责 | 路径 |
|------|------|
| ExtraInfo / 摘要 / 标签映射 | `CRM.Core/Utilities/ExportOperationAudit.cs` |
| 写日志门面 | `CRM.Core/Services/ExportOperationLogService.cs` |
| 常量 | `CRM.Core/Constants/ExportAuditKinds.cs`、`BusinessLogTypes.cs` |
| CSV / 分页收集 / 批次审计挂靠 | `CRM.API/Utilities/InventoryExportHttp.cs` |
| 列表导出 Controllers | `StockInController`、`StockOutController`、`InventoryCenterController` |
| 批次导出 | `BatchReconciliationController` + `AppendBatchExportLogAsync` |
| 单元测试 | `tests/CRM.Core.Tests/Utilities/ExportOperationAuditTests.cs` |

流程（列表导出）：

1. 用与列表相同的 Query（无分页）+ `CollectForExportAsync` 翻页至上限；
2. 按用户权限做 511/521 掩码；
3. 拼 CSV → `CsvFile`（文件名时间戳）；
4. `NormalizeFilters` → `_exportLog.AppendAsync`（内部生成带业务名称的 `filterSummary`）。

批次导出：生成 CSV 后调用 `AppendBatchExportLogAsync`，按 `exportSource`（或筛选推断）选择 BizType/Record。

### 6.2 前端

| 职责 | 路径 |
|------|------|
| 列表导出按钮 + 确认 + 下载 | `StockInList` / `StockOutList` / `InventoryBucketList` / `InventoryStockItemList` |
| API | `stockInApi.exportList`、`stockOutApi.exportList`、`inventoryCenterApi.exportOverview` / `exportStockItems` |
| 文件名时间戳 | `CRM.Web/src/utils/exportFileName.ts` → `withExportTimestamp` |
| 批次面板导入/导出 | `StockInBatchPanel`、`StockOutBatchPanel`、PO/SO BatchPanel；样式 `batch-panel-toolbar.scss`（`btn-export`） |
| 批次核销列表导出 | `BatchReconciliationList.vue` |
| 导出日志列表 | `ExportLogList.vue`（条件摘要、条目数、系统备注） |
| BizType 文案 | `businessLogLabels.ts`（含「库存明细」） |

前端**不再**在导出成功后调用 `log-export`。

### 6.3 UI 约定

- 列表页 / 批次工具栏「导出」「导入」使用浅黄 `btn-export`；危险操作仍用红色 `--danger`。
- 导出前确认框：按当前筛选、最多 50000 条。

## 八、验收要点

| # | 场景 | 期望 |
|---|------|------|
| 1 | 入库/出库/库存桶/库存明细导出 | CSV 下载；导出日志有对应业务类型；导出条件可读 |
