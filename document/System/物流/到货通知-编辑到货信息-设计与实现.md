## 1. 业务定位

补创建后的物流信息维护：预计到货方式、快递公司、预计到货快递单号。只改这三项，不改变到货状态、数量或日期。采购到货与报关到货同一套。

| 入口 | 说明 |
|------|------|
| 列表操作列 | 「编辑到货信息」（展开按钮 / 收起菜单） |
| 右侧操作面板 | 「到货信息」卡：三字段只读 + 同名按钮 |

无权限：操作列按钮隐藏；面板仍展示三字段（空为 —），不显示按钮。列表不加「快递公司」列。

---

## 2. 字段与校验

| 字段 | 存 | 控件 | 必填 |
|------|----|------|------|
| 预计到货方式 | `stockin_notify.ShipmentMethod` | 字典 `LogisticsArrivalMethod`（出货场景，不含「物流/4」） | 否，可清空 |
| 快递公司 | `ExpressCompany` | 字典 `LogisticsExpressMethod`；仅方式=快递(3) 可填 | 否 |
| 预计到货快递单号 | `CourierTrackingNo` | 文本 | 否 |

保存规则：方式非快递时服务端清空快递公司。无效方式码拒绝。任意状态（未到货 / 待检 / 已质检 / 已入库 / 遗留新建）均可改。

---

## 3. 权限

规则：`ArrivalNoticeArrivalInfoAccessRules.CanEdit`（前端 `canEditArrivalNoticeArrivalInfo` 对齐）。

| 角色 | 可否编辑 |
|------|----------|
| 系统管理员 `SYS_ADMIN` | 是（不受物流只读限制） |
| 平台管理员 `SYS_MANAGER` | 是 |
| 业务经理 `SYS_BIZ_MANAGER` | 是 |
| 主部门物流(6) + `DEPT_DIRECTOR` / `DEPT_MANAGER` | 是；主部门物流数据只读则否 |
| 物流部员工、兼任物流、域管理员 `SYS_MGR_*` | 否 |

可见行仍受现有到货通知数据范围约束；越权或不可见行 API 返回 403 / 404。

---

## 4. API

`PATCH /api/v1/logistics/arrival-notices/{id}/arrival-info`

```json
{ "shipmentMethod": "3", "expressCompany": "SF", "courierTrackingNo": "SF123" }
```

空字符串按清空处理。成功返回更新后的到货通知。实现：`LogisticsController` → `LogisticsService.UpdateArrivalNoticeInfoAsync`；写前 `GetByIdsAsync` 校验数据范围。
