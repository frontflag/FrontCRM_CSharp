## 1. 业务定位

| 概念 | 说明 |
|------|------|
| **目标** | 以本条出库明细为当前节点，展示上下游五站 |
| **页签** | 默认 **流程** `r-flow`；并列「客户」、帮助（无「操作」） |
| **数据粒度** | 一条 `stock_out_item`（`stockOutItemId`） |
| **只读** | 无动作按钮；单号可跳转 |

视觉对齐出库通知 / 库存明细流程。当前站为 **出库**。不做收款/开票；采购、质检、入库、拣货、备货均不出现。

---

## 2. 站序与绑定

```
销售明细 → 出库通知 → 库存明细 → 装箱 → 出库 ☜
```

以 `stock_out_item` 为锚向上游收口，**不**扩到整张销售明细：

| 站 | 绑定 |
|----|------|
| 出库（当前） | 本行。单号=出库单号，并列 `stock_out_item_code`。状态后给出库类型；创建日期与创建人同一行 |
| 装箱 | `stock_out_item.PackingId`（无则空站） |
| 出库通知 | 装箱行 `packing_item.StockOutNotifyId`，否则扩展表销售行 → 出库通知 |
| 库存明细 | 优先 `StockItemId` / 扩展表；否则 `PickingTaskItemId` → 拣货层。含 qty=0 |
| 销售明细 | 扩展表或通知上的 `SellOrderItemId`。无销售行则空站，其余站仍展示 |

字段按站裁剪：销售/通知/装箱/出库走客商与出库类型；供应商、采购价、入库数量只在库存明细站。出库类型回退装箱/列表行（见 [流程页签规范 §2.3](../../PRD/规范/UI规范/流程页签规范.md)）。报关类型 20 时用装箱 `CustomsDeclarationId` 或通知溯源，避免类型为「—」。

## 3. 交互

`dataTabIds: ['r-flow']`。单击同时绑流程 store 与客户面板。查询高亮 `?highlight=` 与流程选中行共用 `so-item-row--active`。

| 条件 | 行为 |
|------|------|
| 右栏收起单击 | 忽略 |
| 展开且非「流程」单击 | 仅高亮 |
| 展开且在「流程」单击 | `GET /api/v1/stock-out/items/{stockOutItemId}/flow-aggregates` |
| 离开路由 | `stockOutItemFlowStore.clear()` |

## 4. 实现索引

| 层 | 路径 |
|----|------|
| API | `GET /api/v1/stock-out/items/{stockOutItemId}/flow-aggregates` |
| 服务 | `IStockOutItemFlowService` / `StockOutItemFlowService` |
| DTO | 复用 `StockItemFlowDocDto`（出库站 `LineDocCode` = 明细单号） |
| 脱敏 | `ApplyStockOutItemFlowAggregates` |
| 面板 | `StockOutItemFlowPanel.vue` |
| 适配 | `utils/stockOutItemFlowPanel.ts` |
| Store | `stores/stockOutItemFlowPanel.ts` |
| 列表 | `StockOutItemList.vue`；`AppLayout` 注册 `r-flow` + `r-customer` + 帮助 |

权限：有销售订单时 `CanAccessSalesOrderAsync`，对齐出库通知流程。
