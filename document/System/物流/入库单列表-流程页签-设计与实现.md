## 1. 需求摘要


| 项          | 定稿                                                   |
| ---------- | ---------------------------------------------------- |
| **目标**     | 在入库单列表右栏展示 **当前选中入库单** 上下游 **物流链路**，以地铁竖轴、自上而下推进     |
| **范围（v1）** | **仅物流 7 站**；不含采购申请、付款申请、付款、采购发票、收款、开票、销售明细独立站        |
| **数据粒度**   | 一张入库单头（`stock_in.id` / 列表行 `id`）                     |
| **多行策略**   | 同站 **多张卡片**；按业务单据主键 **去重**；同站多卡按 **创建时间升序**          |
| **默认页签**   | 进入列表默认仍为 **「操作」** `r-ops`；「流程」`r-flow` 为并列页签         |
| **移库源行**   | `stock_item.transfer_type = 10`（手工移库源行）在 **库存明细站展示** |
| **只读**     | 无动作按钮；单号在权限允许时可跳转详情                                  |
| **描述**     | 各站 `description` 字段预留，v1 **固定不展示**（空 / `—`）          |


视觉与交互族与 [库存明细列表-流程页签](./库存明细列表-流程页签-设计与实现.md) 一致：`so-item-flow-panel.scss`、`StockBizTypeTag`、`FlowYouAreHereMark`。

## 2. 业务定位


| 概念             | 说明                                             |
| -------------- | ---------------------------------------------- |
| **展示位置**       | `AppLayout` 右侧辅助栏                              |
| **页签组合（列表模式）** | **操作** `r-ops` + **流程** `r-flow` + **帮助** `r4` |
| **页签组合（看板模式）** | 仅 **帮助**（与操作面板一致：不注册操作/流程，清空选中）                |
| **当前业务站**      | **入库**；标题旁 `FlowYouAreHereMark`，站容器 `is-main`  |
| **与操作页签关系**    | 并存、独立 Store 与 API；互不替代。操作页签仍负责概况/备注/采购到货摘要     |
| **与列表操作列**     | 无变更；流程页签不承载删除、改备注等动作                           |


离开 `StockInList` 路由时：`stockInFlowPanelStore.clear()`（与 `stockInOpsPanelStore` 分别清理）。

## 3. 站点顺序（定稿，7 站）

```
采购明细 → 质检 → 入库 ☜ → 库存明细 → 出库通知 → 装箱 → 出库
```

```
┌─ 右侧 [操作] [流程] [帮助] ─────────────┐
│  ○ 采购明细                              │
│  │  ┌─ 卡1 PO00058-1 ─────────┐          │
│  ○ 质检                                 │
│  │  ┌─ 卡1 QJ0007G ───────────┐          │
│  ● 入库 ☜ 当前                         │
│  │  ┌─ 卡1 STI00075 ──────────┐          │
│  ○ 库存明细                              │
│  │  ┌─ 卡1 STK… ┐ ┌─ 卡2 … ─┐          │
│  ○ 出库通知 → 装箱 → 出库（同站可多卡）   │
└─────────────────────────────────────────┘
```

空站仍渲染站点骨架，卡片区展示「未开始」（`emptyStation` 文案，与库存明细流程一致）。

## 4. 布局与交互



### 4.1 列表门控

实现：`useListRightOpsPanelInteraction.ts`，`dataTabIds: ['r-flow']`（与操作页签 `'r-ops'` 分列加载）。


| 场景                     | 行为                                                                                   |
| ---------------------- | ------------------------------------------------------------------------------------ |
| 右栏收起 + 单击行             | 忽略（不展开、不请求）                                                                          |
| 展开 + **「操作」** + 单击     | `stockInOpsStore.selectRow` → `ops-aggregates`；**不**预拉流程                             |
| 展开 + **非流程、非操作」** + 单击 | 仅 `setRowOnly` 高亮（若仅有帮助则无请求）                                                         |
| 展开 + **「流程」** + 单击     | `stockInFlowPanelStore.selectRow` → `flow-aggregates`                                |
| 由其它页签 **切到「流程」**       | 若已有选中行 → `loadSelected`                                                              |
| 由其它页签 **切到「操作」**       | 若已有选中行 → `stockInOpsStore.loadAggregates`                                            |
| 双击行                    | 仍跳转入库详情 `StockInDetail`（与单击互不冲突）                                                     |
| 搜索 / 重置                | `resetListRightPanelOnReload` 清空 **操作与流程** 两 Store 选中                                |
| 分页刷新                   | 操作 Store 已有 `refreshFromListRows`；流程 Store **同步**列表行快照，若当前在流程页签则 **强制刷新** aggregates |
| 看板模式                   | 不注册 `r-ops` / `r-flow`；清空两 Store                                                     |
| 511 / 521 脱敏           | **仍加载** API；敏感字段前端/服务端掩码为 `—`                                                        |


进入本页默认右栏页签：**操作**（可被按路由记忆覆盖；**不**改为默认流程）。

### 4.2 卡片视觉

遵守 [流程页签规范 §2.5～§2.9](../../PRD/规范/UI规范/流程页签规范.md)：

- 创建日期：`yy-MM-dd`（`formatFlowCardDate`）
- 供应商/客户：**通栏一行**，文案 `{名称} ({编号})`；有 `vendor.read` / `customer.read` 且有机读 ID 时可新开页跳转
- 单号链接：默认正文色，悬停橙色，无下划线
- 入库/出库类型：`StockBizTypeTag`；报关类型且有关联报关单 ID 时显示海关图标

**入库站（当前站）补充：**

- 第一行：左单号（链 `StockInDetail`），右入库类型（报关入库 + 报关图标）
- 第二行：左状态，右创建日期或入库日期（与库存明细流程入库站对齐）

**移库虚拟出库：** 出库站若关联 `stock_out.stock_out_type = 3`（移库），类型文案为 **「移库」**；**不**展示误导性客户名称；出库单默认列表仍排除移库单，但 **按出库单号搜索可查到**（与库存明细流程一致）。

**描述：** 各站 `description` 后端可返回 null，前端 v1 不渲染。

## 6. 数据口径

锚点：**入库单头** `stockInId`。

### 6.1 上游


| 站    | 解析规则                                                                      |
| ---- | ------------------------------------------------------------------------- |
| 采购明细 | 入库单下所有 **未删** `stock_in_item` → 关联 `purchase_order_item_id` **去重**；每明细一行卡 |
| 质检   | 入库头 `qc_id`（可空）；无 QC 则空站。多单共用同一 QC 时仅 **一卡**                              |
| 入库   | 当前入库头 + 列表行展示字段                                                           |




### 6.2 本单库存层


| 站    | 解析规则                                                                                                            |
| ---- | --------------------------------------------------------------------------------------------------------------- |
| 库存明细 | `stock_item.stock_in_id = stockInId`；**含** `transfer_type = 10` 移库源行；**含** 软删层（`IgnoreQueryFilters`），便于运维对照强制删除 |




### 6.3 下游（按本单下所有库存层聚合）

对每张 `stock_item` 复用与 `StockItemFlowService.FillDownstreamThisLayerAsync` **相同绑定规则**，再在入库单维度 **按单据 Id 合并**：


| 站    | 绑定键                                                                                   | 去重与数量                                     |
| ---- | ------------------------------------------------------------------------------------- | ----------------------------------------- |
| 出库通知 | `packing_item.stock_out_notify_id`（经本层 packing / picking 反查）                          | 按 `stockout_notify.id` 去重；数量为本入库单相关层贡献量之和 |
| 装箱   | `packing_item` / 拣货反查                                                                 | 按 `packing.id` 去重                         |
| 出库   | `stock_out_item_extend.stock_item_id` **及** 直挂 `stock_out_item.stock_item_id`（移库虚拟出库） | 按 `stock_out.id` 去重；数量为本层出库量合计            |


**禁止：** 用销售明细 `detail-tab-aggregates` 铺整单下游；仅展示与本入库单 posted 层有 **直接库存绑定** 的单据。

### 6.4 读权限

- 入库单：与 `GET /api/v1/stock-in/{id}` / `ops-aggregates` 相同（不可见 → 403，流程 API 同步）
- 下游销售相关：沿用销售数据范围；521 脱敏客户/业务员/销售价
- 下游采购相关：511 脱敏供应商/采购员/采购价

## 7. API



### 7.1 流程聚合

```
GET /api/v1/stock-in/{id}/flow-aggregates
```

响应：`ApiResponse<StockInFlowAggregatesDto>`

建议 DTO 结构（卡片字段复用 `StockItemFlowDocDto`）：

```csharp
public sealed class StockInFlowAggregatesDto
{
    public string StockInId { get; set; } = string.Empty;
    /// <summary>当前站：入库单头（单卡）。</summary>
    public StockItemFlowDocDto StockIn { get; set; } = new();
    public List<StockItemFlowDocDto> PurchaseOrderItems { get; set; } = new();
    public List<StockItemFlowDocDto> Qcs { get; set; } = new();
    public List<StockItemFlowDocDto> StockItems { get; set; } = new();
    public List<StockItemFlowDocDto> StockOutNotifies { get; set; } = new();
    public List<StockItemFlowDocDto> Packings { get; set; } = new();
    public List<StockItemFlowDocDto> StockOuts { get; set; } = new();
}
```

Controller 在返回前调用：

- `PurchaseSensitiveFieldMask511.ApplyStockInFlowAggregates`
- `SaleSensitiveFieldMask521.ApplyStockInFlowAggregates`

（新增与 `ApplyStockItemFlowAggregates` 同构的掩码方法。）

### 7.2 与现有 API 关系


| API                                                         | 用途                                     |
| ----------------------------------------------------------- | -------------------------------------- |
| `GET .../ops-aggregates`                                    | **操作**页签；本需求 **不替换**                   |
| `GET .../inventory-center/stock-items/{id}/flow-aggregates` | 库存 **单层** 流程；入库单流程为 **多头层聚合**，不直接复用该端点 |

## 8. 后端实现要点


| 项   | 说明                                                                                       |
| --- | ---------------------------------------------------------------------------------------- |
| 接口  | `IStockInFlowService`                                                                    |
| 实现  | `StockInFlowService`（`CRM.Core/Services/`）                                               |
| 注册  | `ServiceExtensions` Scoped                                                               |
| 控制器 | `StockInController` 增加 `flow-aggregates`                                                 |

| 性能  | v1 **不做分页折叠**；明细行/库存层较多时全量返回（约定：单入库单通常 < 50 层；极端情况前端仍渲染，后续可加「展开更多」）                      |




### 8.1 实现步骤（建议顺序）

1. 定义 `StockInFlowAggregatesDto`、`IStockInFlowService`
2. 实现 `GetFlowAggregatesAsync(stockInId, currentUserId)`：权限校验 → 上游采购/QC/入库 → 本单库存层 → 逐层下游合并
3. 抽取 `StockItemFlowService` 下游填充为可复用方法
4. 掩码扩展 + Controller 端点
5. 单元测试：多采购行去重、移库源行出现、移库虚拟出库类型、软删层、511/521 字段（可测掩码器）
