本文描述 **FrontCRM（CRM.Web / CRM.API / CRM.Core）** 中 **质检列表页**（`QcList` / `/logistics/qc`）右侧工作区辅助栏 **「操作」** 页签的设计要求与实现方法。



---



## 1. 业务定位



| 概念 | 说明 |

|------|------|

| **适用页面** | 质检列表（路由名 `QcList`）；**不含** `QcCreate` 详情页 |

| **展示位置** | `AppLayout` 右侧辅助栏（`aux-right`） |

| **页签 ID** | `r-ops`（文案 `layout.auxTabs.ops` → 中文「操作」） |

| **目标** | 单击列表行查看质检摘要及采购/到货/入库上下游，并发起 **生成入库** |

| **与列表操作列关系** | 行内「查看 / 生成入库 / 删除」**保留**；右栏为增强入口 |



**在本列表路由下** 注册双页签（操作 + 帮助），默认选中 **操作**；离开路由时 `qcOpsPanelStore.clear()`。



**PRD 规范摘要：** 产品/UI 评审以 [扩展面板.工作台规范 §6](../../PRD/规范/UI规范/扩展面板.工作台规范.md) 为准；本文补充 API、字段口径与代码索引。

## 2. 布局与交互



### 2.1 卡片结构



```

┌─ 右侧 [操作] [帮助] ─────────────────┐

│ 质检摘要（单号 hero + 状态 + 数量 + 可入库/图片）│

│ 质检入库（生成入库按钮 / 已完成标记） │

│ 采购订单（只读 KV）                   │

│ 到货通知（只读 KV）                   │

│ 入库（有记录 KV / 空态提示）          │

└──────────────────────────────────────┘

```



- 五张卡片 **直接作为页签内容子级** 纵向排列；嵌入模式 `embedded`，样式 `so-item-ops-panel.scss`（与销售/到货操作面板共用）。



### 2.2 列表交互（§2.4 门控）



适用列表含：**销售订单明细、采购订单明细、报关单列表、到货通知列表、质检列表**。  

实现：`useListRightOpsPanelInteraction.ts`。



| 场景 | 行为 |

|------|------|

| 右栏收起 + 单击行 | 忽略 |

| 展开 + 非「操作」页签 + 单击 | 仅 `setRowOnly` 高亮 |

| 展开 + 「操作」+ 单击 | `selectRow` → 请求 aggregates + 质检图片数 |

| 展开 + 由非「操作」→ 点「操作」 | 若 store 已有选中行 → `loadAggregates` |

| 双击行 | 跳转 `QcCreate?qcId=`（与单击互不冲突） |

| 采购 511 脱敏 | 不响应单击、`clear()` store |

| 搜索/重置/筛选（`resetPage`） | `resetListRightPanelOnReload` 清空选中 |

| 分页刷新 | `refreshFromListRows` 同步选中行 |



### 2.3 子面板布局



遵循 [销售操作面板 §2.5](../销售订单明细列表-操作面板-设计与实现.md)：



| 卡片 | 布局 |

|------|------|

| 质检摘要 | §2.5.3 **概况**（hero 单号 + 标签 + §2.5.2 双列 KV） |

| 质检入库 | §2.5.3 **操作 + hint**（主按钮 / 已完成 ✓） |

| 采购 / 到货 / 入库 | §2.5.2 **双列 Key:Value** |



### 2.4 质检入库 · 操作按钮



与销售订单明细操作面板（§2.5.3）一致：**已完成**、**置灰 + hint**、**只读仅 hint** 三种态。



| 状态 | 判定 | UI |

|------|------|-----|

| **已完成** | `stockInId` 或 `aggregates.stockIn` 存在 | 标题旁「已完成 ✓」；无按钮 |

| **可执行** | `canWriteLogisticsData` + 未完成 + 未驳回 + `passQty > 0` | 主色「生成入库」 |

| **置灰** | 有写权限 + 未完成 + 业务阻断（未通过 / 无合格量） | `ops-action-btn--disabled` + summary + nextStep |

| **只读** | 无 `canWriteLogisticsData` + 未完成 | **仅 hint**，不渲染按钮（与销售明细一致） |



提示文案与按钮禁用逻辑：`utils/qcCreateStockInDisabledHint.ts`（`qcCreateStockInCompleted` / `qcCreateStockInButtonDisabled` / `buildQcCreateStockInDisabledHintContent`）。



**生成入库流程（与列表操作列同源）：**



1. 用户确认（`ElMessageBox`）

2. 按到货通知拉明细、过滤 `passedQty > 0` 行

3. 按通知区域选仓（多仓时弹窗）

4. `stockInApi.create` → `logisticsApi.bindQcStockIn` → `stockInApi.updateStatus(2)` 完成过账

5. 刷新列表；操作面板 `refreshFromListRows` 同步



Handler 注册：`QcList.vue` `onMounted` → `qcOpsStore.registerHandlers({ createStockIn })`；面板按钮 `@create-stock-in` → `qcOpsStore.runCreateStockIn()`。



### 2.5 单号链接（§2.5.4）



| 字段 | 路由 |

|------|------|

| 质检单号（摘要 hero） | `QcCreate` + `qcId` query |

| 采购明细单号 | `PurchaseOrderDetail` + `purchaseOrderItemId` query |

| 到货通知单号 | `ArrivalNoticeList` + `noticeId` query |

| 入库单号 | `StockInDetail` + `id` param |



脱敏（511）时采购明细单号、采购员不链出；值为 `—`。

## 3. 各卡片字段



### 3.1 质检摘要（列表行 + 图片数）



**布局：** hero 质检单号 + 状态标签；下方两行双列 KV（§2.5.2）。



| 行 | 左列 | 右列 |

|----|------|------|

| — | 质检单号（琥珀 hero，链 §2.5） | 状态 `el-tag`（`qcList.qcStatus.*`） |

| 1 | 通过数量 `passQty` | 拒收数量 `rejectQty` |

| 2 | 可入库数量（= `passQty`） | 质检图片（图片附件张数，「{n} 张」） |



- 通过/拒收/可入库数量来自**列表行**，选中即展示。

- 质检图片：`documentApi.getDocuments('QC', qcId)` 并行加载；计数口径 `utils/qcImageDocument.ts`（仅图片 MIME/扩展名），与质检详情 `QcCreate`、采购明细「质检图片」页签一致。



### 3.2 质检入库面板



卡片标题：**质检入库**（`qcList.opsPanel.createStockInTitle`）。



按 §2.4 展示「生成入库」按钮、置灰 hint 或「已完成 ✓」；**不**在此卡重复摘要中的数量/图片字段。



### 3.3 采购订单面板（aggregates.purchase）



双列 Key:Value，口径与 [到货通知操作面板 §3.2](./到货通知列表-操作面板-设计与实现.md) 一致。



| 行 | 左列 | 右列 |

|----|------|------|

| 1 | 采购明细单号 | 采购员 |

| 2 | 采购日期 | 采购明细数量 |



无记录：「暂无关联采购明细」。



### 3.4 到货通知面板（aggregates.arrivalNotice）



| 行 | 左列 | 右列 |

|----|------|------|

| 1 | 到货通知单号（链 `ArrivalNoticeList?noticeId=`） | 到货类型（`StockBizTypeTag`） |

| 2 | 到货日期 | 到货数量 |



**到货日期：** `actualArrivalDate` 优先；无实到日则 `expectedArrivalDate`；标签统一「到货日期」，不区分预计/实到。



无记录：「暂无关联到货通知」。



### 3.5 入库面板（aggregates.stockIn）



有记录：入库单号、入库日期、操作人、入库状态、入库类型、仓库、入库数量（入库单号链 `StockInDetail`）。  

无记录：「尚未生成入库记录」。

## 4. API 与数据加载



### 4.1 操作聚合



`GET /api/v1/logistics/qcs/{id}/ops-aggregates`



响应（`ApiResponse<QcOpsAggregates>`）：



- `purchase`：与到货通知 aggregates 同结构  

- `arrivalNotice`：通知单号、类型、实到/预计到日、预计数量  

- `stockIn`：与到货通知 aggregates 同结构  



实现：`GetQcOpsAggregatesAsync` 以质检单关联的 `StockInNotifyId` 复用 `GetArrivalNoticeOpsAggregatesAsync` 的采购/入库解析，并补充到货通知字段。



采购 511 脱敏时清空采购明细单号与采购员。



### 4.2 质检图片数（并行）



`GET /api/v1/documents?bizType=QC&bizId={qcId}`



- 与 aggregates **并行**请求（`qcOpsPanel.loadAggregates`）。

- 前端 `countQcImageDocuments` 过滤后写入 `qcImageCount`，经 `AppLayout` 传入 `QcOpsPanel`。

## 6. 权限



| 能力 | 权限 / 条件 |

|------|-------------|

| 进入列表 | `purchase-order.read`（路由既有） |

| 生成入库 | `canWriteLogisticsData` + 行级 `canCreateStockIn`（`status !== -1` 且无 `stockInId`） |

| 采购单链接 | 非 511 脱敏 |

| 到货/入库链接 | 各目标页既有权限 |
