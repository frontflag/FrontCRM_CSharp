## 1. 业务定位

与需求 / 销售同一套右栏「客户」摘要。按单据主键解析客户，不信任行上 `customerId`。

| 页面 | 绑定 | 页签顺序 | 默认 |
|------|------|----------|------|
| 出库通知列表（两路由同一页） | 单击行 | 客户 → 帮助；报关筛选时 **报关 → 客户 → 帮助** | 帮助（报关筛选时仍为报关） |
| 出库通知详情 | 进页按单头 | 客户 → 帮助 | 帮助 |
| 装箱单列表 | 单击行 | 流程 → 客户 → 帮助 | 流程 |
| 装箱单详情 | 进页按单头（不跟明细行） | 流程 → 客户 → 帮助 | 流程 |
| 装箱单明细 | 单击行 → 所属装箱单的客户 | 流程 → 客户 → 帮助 | 流程 |
| 出库单列表 | 单击行 | 操作 → 客户 → 帮助 | 操作 |
| 出库单详情 | 进页按单头 | 客户 → 帮助 | 帮助 |
| 出库明细 | 单击行 | 客户 → 帮助 | 帮助 |

列表单击 **不** 自动切到「客户」。报关出库通知单击仍会自动展开并切到「报关」（原行为）。

## 2. 权限

完整面板裁剪与需求模块相同。

进入履约页：`sales-order.read` **或** `purchase-order.read`（系统管理员 / bypass 视为具备）。

数据范围与各列表一致：

- 出库通知：物流范围「全部」则放行；否则须能访问关联销售订单。
- 装箱单 / 出库单：物流范围「全部」或销售范围「全部」则放行；销售范围 4（521）拒绝；否则按业务员本人 / 客户范围 / 关联销售订单判定。

## 3. 接口

`GET /api/v1/customer-workspace?source=&id=`

| source | id | 客户来源 |
|--------|----|----------|
| `stockOutRequest`（别名 `stock-out-notify` 等） | 出库通知主键 | `StockOutRequest.CustomerId` |
| `packing` | 装箱单主键 | `Packing.CustomerId` |
| `packingItem`（别名 `packing-item` 等） | 装箱明细主键 | 明细 → 装箱单头 `CustomerId` |
| `stockOut` | 出库单主键 | `StockOut.CustomerId` |
| `stockOutItem` | 出库明细主键 | 明细 → 出库单头 `CustomerId` |
