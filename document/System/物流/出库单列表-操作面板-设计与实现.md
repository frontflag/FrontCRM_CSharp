本文描述 **FrontCRM（CRM.Web / CRM.API / CRM.Core）** 中 **出库单列表页**（`StockOutList` / `/inventory/stock-out`）右侧工作区辅助栏 **「操作」** 页签的设计要求与实现方法。

---

## 1. 业务定位

| 概念 | 说明 |
|------|------|
| **适用页面** | 出库单列表（路由名 `StockOutList`）；**不含** 出库明细列表 `StockOutItemList`、出库详情 `StockOutDetail` |
| **展示位置** | `AppLayout` 右侧辅助栏（`aux-right`） |
| **页签 ID** | `r-ops`（文案 `layout.auxTabs.ops` → 中文「操作」） |
| **目标** | 单击列表行查看本单摘要、出货方式、出库明细 / 销售行 / 应收摘要，并发起 **编辑出货信息**、**标记完成** |
| **与列表操作列关系** | 行内「详情 / 编辑 / 标记完成 / 删除 / 强制删除」**保留**；右栏为增强入口，不替代行内按钮 |
| **流程页签** | **不注册** `r-flow`（装箱流程出库站见装箱列表/详情） |

**在本列表路由下** 注册双页签（操作 + 帮助），进入路由默认 **操作**（可被按路由记忆覆盖，见工作台规范 §2.0）；离开路由时 `stockOutOpsPanelStore.clear()`。

## 2. 布局与交互

### 2.1 卡片结构

```
┌─ 右侧 [操作] [帮助] ─────────────────┐
│ 出库摘要（单号 hero + 状态/类型 + 客户/业务员无标题 + 合计数量）│
│ 出货方式（日期 / 方式 / 快递公司 / 单号；标题栏右侧「编辑」）│
│ 标记完成（按钮 / 已完成 ✓）                       │
│ 出库明细（1:N KV 组，截断）                       │
│ 销售订单明细（仅销售出库；1:N KV 组，截断）       │
│ 应收款（仅销售出库；1:N KV 组，截断）             │
└──────────────────────────────────────┘
```

六张卡片 **直接作为页签内容子级** 纵向排列；嵌入模式 `embedded`，样式 `so-item-ops-panel.scss`。

### 2.2 列表交互（§2.4 门控）

适用列表增加 **出库单列表**。实现：`useListRightOpsPanelInteraction.ts`。

| 场景 | 行为 |
|------|------|
| 右栏收起 + 单击行 | 忽略（不展开、不请求） |
| 展开 + 非「操作」页签 + 单击 | 仅 `setRowOnly` 高亮 |
| 展开 + 「操作」+ 单击 | `selectRow` → 请求 aggregates |
| 展开 + 由非「操作」→ 点「操作」 | 若 store 已有选中行 → `loadAggregates` |
| 双击行 | 跳转出库详情（与单击互不冲突） |
| 销售 521 脱敏 | **仍加载**面板；客户/业务员/金额为 `—`；按钮按角色权限 |
| 搜索 / 重置 / 页签模式点页签 | `resetListRightPanelOnReload` 清空选中 |
| 分页刷新 | `refreshFromListRows` 同步选中行 |

### 2.3 子面板布局

遵循 [销售操作面板 §2.5](../销售订单明细列表-操作面板-设计与实现.md)：

| 卡片 | 布局 |
|------|------|
| 出库摘要 | §2.5.3 **概况**（hero 单号 + 状态/类型 + 客户/业务员无标题 + 合计数量左对齐） |
| 出货方式 | §2.5.2 双列 Key:Value；标题栏右侧 **label/link「编辑」**（非卡底通栏主按钮） |
| 标记完成 | §2.5.3 **操作 + hint**（主按钮 / 已完成 ✓） |
| 出库明细 / 销售订单明细 / 应收款 | §2.5.2 双列 Key:Value；**每条记录一组**，组间分割线（同销售「使用备货」） |

**1:N 截断：** 每张 1:N 卡最多展示 **8** 组；超出时卡底文案「还有 n 条，打开详情」，「打开详情」为 `link-text` 进本出库详情。无记录走各卡空态，不展示截断行。

### 2.4 操作按钮

| 按钮 | 显示条件 | 行为 |
|------|----------|------|
| **编辑**（出货方式卡 **标题栏右侧**，`el-button` `link` `primary`，与列表操作列同款） | `canWriteLogisticsData` | 打开列表现有「编辑出库信息」对话框（补快递公司，见 §3.2 / §5） |
| **标记完成** | `canWriteLogisticsData` 且状态 **不是**「出库完成」 | 打开列表现有「标记完成」对话框（客户/地址/装箱/日期/快递单号/备注） |

已完成：标记完成卡标题旁「已完成 ✓」，**无**按钮。  
无物流写权限且未完成：不渲染标记完成按钮（对齐质检只读档）。出货方式卡仍展示四字段，无「编辑」。

危险操作（删除 / 强制删除）**不进**右栏。

## 3. 各卡片字段

### 3.1 出库摘要（列表行，无额外请求）

**布局：** 概况纵向 Value；状态与类型放在摘要内，**不**单独开 §2.5.1 状态卡（仅一个工作流状态）。

| 顺序 | 内容 |
|------|------|
| 1 | 出库单号（琥珀 hero，`link-text` 进 `StockOutDetail`） |
| 2 | 出库状态 `el-tag`（与列表文案一致）+ 出库类型 `StockBizTypeTag`（报关类型旁海关图标保留） |
| 3 | 客户名称（无标题；`CustomerNameReadonlyText` `中文 / 英文`；脱敏 `—`） |
| 4 | 业务员名称（无标题；脱敏 `—`；头表无业务员时回退销售行） |
| 5 | 合计出库数量 `totalQuantity`（**有**标题「合计数量」，标签+数值左对齐，数值 `ops-kv__value--accent`） |
| 6 | **仅报关出库**且有报关单：报关单号 `link-text` 进 `CustomsDeclarationDetail`（与类型旁图标并存，图标不替代本行） |

报关/退货/报废：无报关单号行（非报关）或无销售下游卡（见 §3.4 / §3.5）。

### 3.2 出货方式

**布局：** §2.5.2 双列 Key:Value。

| 行 | 左列 | 右列 |
|----|------|------|
| 1 | 出库日期 | 出货方式（字典 `LogisticsArrivalMethod` 展示名） |
| 2 | 快递公司（字典 `LogisticsExpressMethod` 展示名） | 快递单号 |

空值为 `—`。快递公司口径见 **§5**。

「编辑」打开与操作列同源对话框，字段：出库日期（必填）、出货方式、快递公司、快递单号。

- 快递公司仅当出货方式 = 快递（ItemCode `3`）可填；非快递保存时服务端清空快递公司（对齐到货通知）。
- 详情页「可编辑」区块同步补快递公司，走同一 `UpdateHeader`。
- 已出库完成仍允许编辑物流字段（与现网操作列一致）。

### 3.3 出库明细（aggregates.items）

各类出库均渲染本卡。无行：「暂无出库明细」。

每组：

| 行 | 左列 | 右列 |
|----|------|------|
| 1 | 出库明细单号（纯文本；无独立明细详情） | 装箱单号（有 `packingId` 时 `link-text` 进 `PackingDetail`） |
| 2 | 货代单号 | 物料型号 `purchasePn` |
| 3 | 品牌 `purchaseBrand` | 出库数量（强调色） |
| 4 | 出库金额 + 币别 | （右空） |

**出库金额：** `salesPrice × outQuantity`，币别 `salesCurrency`；无效或无单价则整格 `—`。展示遵循金额与币别范式（数字 + 空格 + 三位字母上色）。无 `sales.amount.read` 或 521 脱敏时金额整格 `—`。

### 3.4 销售订单明细（aggregates.sellOrderItems）

**仅销售出库**（类型 10 或历史 1）渲染；报关/退货/报废 **整卡不渲染**。

口径与详情底部一致：扩展表销售行去重，不依赖头表单一 `SellOrderItemId`。无行：「暂无关联销售订单明细」。

每组：

| 行 | 左列 | 右列 |
|----|------|------|
| 1 | 销售订单明细号（`link-text` 进 `SalesOrderDetail` + `salesOrderItemId` query；脱敏不链） | 业务员 |
| 2 | 物料型号 | 品牌 |
| 3 | 数量 | （右空） |

### 3.5 应收款（aggregates.receivables）

**仅销售出库**渲染。粒度：一张应收对应一条销售行（与详情应收面板相同）。不做核销/作废。

| 空态 | 文案 |
|------|------|
| 状态 ≠ 出库完成 | 「尚未标记完成，暂无应收」 |
| 已完成仍无行 | 「暂无应收款」 |

每组：

| 行 | 左列 | 右列 |
|----|------|------|
| 1 | 应收单号（有收款读权限才链 `/finance/receivables/{id}`，否则纯文本） | （右空，单号单独一行） |
| 2 | 出库数量 | 应收金额 + 币别 |
| 3 | 收款核销状态（`el-tag`） | （右空，状态单独一行） |
| 4 | 收款已核销 + 币别 | 收款待核销 + 币别 |
| 5 | 发票核销状态（`el-tag`） | （右空） |
| 6 | 发票已核销 + 币别 | 发票待核销 + 币别 |

金额字段无销售金额读权限或脱敏时为 `—`。金额 + 币别与出库明细相同：数字 + 空格 + 三位字母 **系统色**（`dock-tier-ccy`）。状态标签与财务应收列表文案一致（未核销 / 部分 / 完成）。

## 4. API

`GET /api/v1/stock-out/{id}/ops-aggregates`

授权与出库详情相同（出库不存在 404）。响应 `ApiResponse<StockOutOpsAggregates>`：

- `items`：本单有效出库明细（字段见 §3.3）
- `sellOrderItems`：去重销售行摘要（非销售出库空数组）
- `receivables`：与 `GET {id}/receivables` 同结构（非销售空数组）

销售 521 脱敏时服务端清空明细/销售行上的客户与业务员，以及金额类字段（与列表同源掩码）。

列表行单击 **不** 为摘要/出货方式再请求本接口以外的详情；出货方式四字段以列表行为准，编辑保存后 `refreshFromListRows` 同步。

## 5. 快递公司落库

现状：`stock_out` **无** `ExpressCompany` 列；列表 DTO 仅当 `SourceId` 能命中出库通知时回填通知上的快递公司。按箱出库 `SourceId` 为装箱单主键，列表列经常为空。

本功能：

1. 头表新增 `stock_out."ExpressCompany"`（`varchar(64)`，字典 `LogisticsExpressMethod` ItemCode）。
2. `UpdateHeader` 写入出货方式、快递公司、快递单号；非快递则清空公司。
3. 列表/详情展示优先级：头表有值 → 出库通知 → 关联装箱 `packing_extend_ship.express_company`。
4. 已有出库单不强制回填；用户编辑保存后头表生效。

无需新权限码。须执行迁移后重启 API。

## 7. 权限

| 能力 | 权限 / 条件 |
|------|-------------|
| 进入列表 | 出库单菜单既有读权限 |
| 编辑出货信息 / 标记完成 | `canWriteLogisticsData`（部门物流非只读） |
| 客户 / 业务员 | 非销售 521 脱敏 |
| 出库金额 / 应收金额 | `sales.amount.read` 且非 521 脱敏 |
| 点进应收详情 | 收款读权限（无权限只显示单号文本） |
| 报关单 / 装箱 / 销售行链接 | 各目标页既有权限；无单号或脱敏不渲染链接 |
