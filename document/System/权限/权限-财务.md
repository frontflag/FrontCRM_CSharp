# 权限：财务模块

本文与 **`sys_permission` 种子**、**`RbacService` 权限汇总**、**`DataPermissionService` 财务过滤**及前端 **`AppLayout` / 路由** 当前实现一致。与 [RBAC 权限节点清单](../../实现方案/RBAC权限节点清单.md)、[RBAC 权限系统 PRD](../../PRD/RBAC权限系统PRD.md) §5.3、[数据权限-业务员客户与采购员供应商](./数据权限-业务员客户与采购员供应商.md) 交叉引用。

## 一、功能权限码（`finance-*`）

财务业务在 `sys_permission` 中登记 **8 个** 权限码，命名规则：`[资源].[操作]`（`read` / `write`）。

| PermissionCode | 中文名（种子） | Resource | 典型能力 |
|----------------|----------------|----------|----------|
| `finance-receipt.read` | 收款-查看 | finance-receipt | 收款单列表/详情；侧栏「收款管理」 |
| `finance-receipt.write` | 收款-维护 | finance-receipt | 新建/编辑/提交/核销等；待办审批 `FINANCE_RECEIPT` |
| `finance-payment.read` | 付款-查看 | finance-payment | 付款单列表/详情；侧栏「付款管理」 |
| `finance-payment.write` | 付款-维护 | finance-payment | 请款/付款/完成等；待办审批 `FINANCE_PAYMENT` |
| `finance-sell-invoice.read` | 销项发票-查看 | finance-sell-invoice | 销项发票列表/详情 |
| `finance-sell-invoice.write` | 销项发票-维护 | finance-sell-invoice | 销项发票写操作 |
| `finance-purchase-invoice.read` | 进项发票-查看 | finance-purchase-invoice | 进项发票列表/详情 |
| `finance-purchase-invoice.write` | 进项发票-维护 | finance-purchase-invoice | 进项发票写操作 |

**说明**

- 上述 8 码**不包含**销售订单、客户、采购订单等资源权限；不能单靠 `finance-*` 打开「销售订单」模块（见 §六）。
- PRD 附录中的 `payment.view`、`invoice.manage` 为**旧命名示例**；实现以 `finance-*` 为准。

**种子与补绑脚本**

| 说明 | 路径 |
|------|------|
| 主权限种子 | `seed_initial_rbac_admin.sql` |
| 财务菜单/角色补绑 | `scripts/ensure_finance_operator_menu_permissions.sql` |
| 生产迁移中的同批权限 | `prod-migration.sql`（`p0000000-…0013`～`001a`） |

## 二、财务参数（归入系统管理）

| PermissionCode | 中文名 | 用途 |
|----------------|--------|------|
| `rbac.manage` | 用户/角色/权限管理 | **财务参数**菜单（汇率设置、付款银行）、汇率修改、付款银行维护 |

| 接口/页面 | 权限要求 |
|-----------|----------|
| `GET /api/v1/finance/exchange-rates/current` | 仅需登录 `[Authorize]`（报价等业务可读当前汇率，避免 403 退回默认汇率） |

| 路由 `/system/finance-params/*` | `rbac.manage`（`CRM.Web/src/router/routes.ts`） |

## 三、前端菜单与路由

侧栏「财务」分组（`AppLayout.vue`）按 **read** 权限显隐；列表内保存/提交等按钮另需对应 **write**。

| 菜单/路由 | 所需权限 |
|-----------|----------|
| 付款管理 `/finance/payments` | `finance-payment.read` |
| 进项发票 `/finance/purchase-invoices` | `finance-purchase-invoice.read` |
| 收款管理 `/finance/receipts` | `finance-receipt.read` |
| 销项发票 `/finance/sell-invoices` | `finance-sell-invoice.read` |
| 财务参数 `/system/finance-params/*` | `rbac.manage` |

付款侧栏组：`finance-payment.read` **或** `finance-purchase-invoice.read` 之一即可展开分组；收款侧栏组同理（收款 **或** 销项）。

## 四、API 与审批

### 4.1 控制器基类权限

| 控制器 | 类级 read | 写操作 |
|--------|-----------|--------|
| `FinanceReceiptsController` | `finance-receipt.read` | `finance-receipt.write` |
| `FinancePaymentsController` | 部分列表 `RequireAny`（见下） | 多数 `finance-payment.write` |
| `FinanceSellInvoicesController` | `finance-sell-invoice.read` | `finance-sell-invoice.write` |
| `FinancePurchaseInvoicesController` | `finance-purchase-invoice.read` | `finance-purchase-invoice.write` |

### 4.2 `RequireAny`（采购侧在 PO 上请款）

部分付款接口允许 **`finance-payment.read` / `finance-payment.write`** 与 **`purchase-order.read` / `purchase-order.write`** 二选一（如 `FinancePaymentsController` 部分 GET/POST），便于采购员在采购订单场景发起请款，而不单独授予全套 `finance-*`。

### 4.3 待办审批（`ApprovalsController`）

| 业务类型 | 审批操作依赖 | 列表/查看依赖 |
|----------|--------------|---------------|
| `FINANCE_RECEIPT` | `finance-receipt.write` | `finance-receipt.read` |
| `FINANCE_PAYMENT` | `finance-payment.write` | `finance-payment.read` |

## 五、角色绑定（常见）

| 角色 RoleCode | 财务相关权限 |
|---------------|--------------|
| `finance_operator` | 8 个 `finance-*`（read + write） |
| `DEPT_DIRECTOR` / `DEPT_MANAGER` | 同上 8 码（`ensure_finance_operator_menu_permissions.sql` 补绑） |
| `DEPT_EMPLOYEE` | 种子通常仅 4 个 `finance-*.read`；财务部员工需额外挂 `finance_operator` 才有 write（否则付款保存/完成 API 403） |
| `biz_all` | 含全套 `finance-*`（若使用该业务角色） |
| `SYS_ADMIN` | 全部功能 + 数据 |

**财务部 + 仅 `DEPT_EMPLOYEE` 的补挂逻辑**：`ensure_finance_operator_menu_permissions.sql` 对主部门 `IdentityType=5` 或部门名含「财务」且仅有 `DEPT_EMPLOYEE` 的用户自动补挂 `finance_operator`（已有总监/经理/管理员角色则跳过）。

## 六、主部门身份与权限码剥离（`RbacService` + 前端）

JWT / `permission-summary` 中的 `permissionCodes` 在汇总时会按**主部门 `IdentityType`** 剥离或补全（`CRM.Core/Services/RbacService.cs`；前端 `auth.ts` → `isIdentityBlockedForPermission` 与菜单一致）。

| 主部门 IdentityType | 剥离的财务相关码 | 补全的财务相关码 |
|---------------------|------------------|------------------|
| **5 财务** | （不剥离 `finance-*`） | 补全 8 个 `finance-*` 的 read/write（种子常仅有 read） |
| **1 销售** | `finance-payment.*`、`finance-purchase-invoice.*` | — |
| **2/3 采购/采购助理**（含 `belongsToPurchaseDept`） | `finance-receipt.*`、`finance-sell-invoice.*` | — |
| **4 客服** | 另剥离 `finance-purchase-invoice.read` 等 | — |

**财务身份不剥离** `sales-order.*`：与采购部对称，采购侧会剥离销售订单与收款/销项财务码，销售侧会剥离付款/进项财务码。

## 七、数据权限（部门维度）

> 部门维度完整说明（销售/采购/物流/财务四组 Scope+Access、隐藏客户/供应商、迁移脚本等）见 **[权限-部门](./权限-部门.md)**。本节侧重财务部与 **销售/采购** 字段的组合；财务独立范围 **`FinanceDataScope` / `FinanceDataAccess`** 见 [权限-部门](./权限-部门.md) 第六节。

财务部的配置由主部门 **`sys_department`** 上两组字段共同决定：

| 字段 | 含义 |
|------|------|
| **`SaleDataScope` / `PurchaseDataScope`** | **可见范围**：`0=全部，1=自己，2=本部门，3=本部门及下级，4=禁止`（`DataPermissionService` 行级过滤） |
| **`SaleDataAccess` / `PurchaseDataAccess`** | **访问方式**：`0=读写`，`1=只读`（`RbacService` 汇总时剥离写权限码，与范围正交） |

与 `finance-*` 功能码独立。部门编辑页：`/system/departments/:id/edit`（`DepartmentEdit.vue`）。

### 7.1 推荐部门配置（财务部查全量销售订单但不可改删）

```json
{
  "IdentityType": 5,
  "SaleDataScope": 0,
  "SaleDataAccess": 1,
  "PurchaseDataScope": 0,
  "PurchaseDataAccess": 0,
  "DepartmentName": "财务部"
}
```

效果：

- **可见**：全部销售订单、采购订单等（范围 `0` + 角色含 `sales-order.read` 等）。
- **可写**：财务单据（`finance-*` write 仍由财务身份补全）；**不可**新建/编辑/删除销售订单（`SaleDataAccess=1` 时剥离 `sales-order.write`、`customer.write`、`rfq.write`、`rfq.create`、`purchase-requisition.write`）。
- 用户需**重新登录**或刷新 `permission-summary` 后生效。

仅 PRD 旧示例（读写未区分）时：

```json
{ "IdentityType": 5, "SaleDataScope": 0, "PurchaseDataScope": 0 }
```

等价于 `SaleDataAccess=0`、`PurchaseDataAccess=0`（默认读写）。

### 7.2 财务单据过滤例外（`DataPermissionService`）

| 对象 | 规则 |
|------|------|
| **收款单** `FilterFinanceReceiptsAsync` | `IdentityType == 5`（财务）时**不按** `FinanceReceipt.SalesUserId` / 客户业务员缩小 |
| **付款单** `FilterFinancePaymentsAsync` | 财务时**不按** `Vendor.PurchaseUserId` 缩小 |
| **进项发票** `FilterFinancePurchaseInvoicesAsync` | 同上（经供应商采购员链路时财务例外） |

详见 [数据权限-业务员客户与采购员供应商](./数据权限-业务员客户与采购员供应商.md) §二、§三、§四。

### 7.3 销售订单列表（非 `finance-*` 能力）

销售订单 API 要求 **`sales-order.read`**（`SalesOrdersController`），写操作要求 **`sales-order.write`**（`SaleDataAccess=1` 时由 `RbacService` 从汇总中移除 write，API 与菜单写按钮均不可用）。

| 场景 | 能否看销售订单 | 能否改/删销售订单 |
|------|----------------|-------------------|
| 账号**仅有** `finance_operator` / 8 个 `finance-*` | **否** | **否** |
| 财务部 + `DEPT_EMPLOYEE` + `SaleDataScope=0` + `SaleDataAccess=0` | **是** | **是**（若有 write 角色绑定） |
| 财务部 + `SaleDataScope=0` + **`SaleDataAccess=1`（只读）** | **是** | **否** |
| `DEPT_DIRECTOR` / `DEPT_MANAGER` + `SaleDataAccess=1` | **是** | **否**（总监/经理也会被部门只读剥离 write） |
| `SaleDataScope=4` | **否** | **否** |

列表金额另需 **`sales.amount.read`**；财务部不触发 §5.2.1 采购向销售域列级脱敏（`SaleDataScope != 4` 且非采购身份）。前端可用 `authStore.isSaleDataReadOnly()` 辅助隐藏写操作（以后端 `permission-summary` 为准）。

## 八、与其他模块的关系（速查）

| 关联 | 说明 |
|------|------|
| 销售订单 | 功能码 `sales-order.*`；数据范围 `SaleDataScope` + `FilterSalesOrdersAsync` |
| 采购订单 | 功能码 `purchase-order.*`；部分付款接口 `RequireAny` |
| 客户/供应商主数据 | 财务身份不屏蔽 `customer.*` / `vendor.*`（与采购/销售主部门剥离策略不同） |
| 强制删除 | 财务类单据需 `finance-*-invoice.write` / `finance-payment.write` / `finance-receipt.write`（见 [强制删除 API 契约](../../实现方案/强制删除_API契约与错误码.md)） |
| 敏感字段 | 销售金额：`sales.amount.read`；客户敏感：`customer.info.read` |
