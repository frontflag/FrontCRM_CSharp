# 权限：部门维度（`sys_department`）

本文归档 **主部门**（`sys_user_department.IsPrimary`）在 `sys_department` 上的数据范围、访问方式、模块隐藏等配置，及其与 **功能权限码（`sys_permission`）**、**行级数据过滤**、**前端菜单/路由** 的关系。

与 [RBAC 权限系统 PRD](../../PRD/RBAC权限系统PRD.md) §5、[管理角色分级与权限体系 PRD](../../PRD/管理角色分级与权限体系PRD.md)（管理角色、`system.*` 门禁、与 `DataScope` 正交）、[数据权限-业务员客户与采购员供应商](./数据权限-业务员客户与采购员供应商.md)、[权限-财务](./权限-财务.md) 交叉引用。

---

## 一、配置入口与数据表

| 说明 | 路径 / 表 |
|------|-----------|
| 部门列表 | `/system/departments`（`DepartmentList.vue`） |
| 新增/编辑 | `/system/departments/create`、`/system/departments/:id/edit`（`DepartmentEdit.vue`） |
| 部门详情 | `/system/departments/:id`（`DepartmentDetail.vue`） |
| 管理 API | `PUT/POST /api/v1/rbac/admin/departments`（`RbacController.UpsertDepartmentRequest`） |
| 物理表 | `public.sys_department`（实体 `RbacDepartment`） |

**生效对象**：员工登录后 `GET /api/v1/auth/permission-summary` 读取 **主部门** 字段；兼任部门不改变上述范围（兼任仅影响 `belongsToPurchaseDept` 等少量判定）。

**系统管理员 / 平台管理员**：`SYS_ADMIN`、`SYS_MANAGER`（及一期 `SYS_BIZ_MANAGER`）置 `HasBizDataBypass`，不受部门范围/只读/隐藏限制（菜单、路由、业务 API 均 bypass）。系统菜单仍须 `hasManagementAccess` + 对应 `system.*`（见 [管理角色分级 PRD §三 / §五](../../PRD/管理角色分级与权限体系PRD.md#三管理角色分级)）。

**L3 域管理员与部门配置正交：** `SYS_MGR_*` **不** 因管理身份获得业务全量；系统管理须 `hasManagementAccess` + 对应 `system.*` 权限码。`DEPT_*` 组织角色 **永不** 在种子中附带 `system.*`。

修改部门配置后，用户需 **重新登录**（或刷新 `permission-summary`）后前端与汇总权限才一致。

## 二、字段总览

每组配置由 **「数据范围 Scope」** 与 **「访问方式 Access」** 两个维度组成（范围与读写 **正交**）。另有与范围无关的 **布尔开关**。

| 分组 | 范围字段 | 访问字段 | 额外开关 | 控制侧重 |
|------|----------|----------|----------|----------|
| 销售 | `SaleDataScope` | `SaleDataAccess` | `HideCustomerManagement` | 销售侧业务数据 + 客户管理菜单 |
| 采购 | `PurchaseDataScope` | `PurchaseDataAccess` | `HideVendorManagement` | 采购侧业务数据 + 供应商管理菜单 |
| 物流 | `LogisticsDataScope` | `LogisticsDataAccess` | — | 入库/出库/库存/报关 |
| 财务 | `FinanceDataScope` | `FinanceDataAccess` | — | 付款管理/收款管理 |
| 组织 | — | — | `IdentityType`、`Status` | 身份剥离策略、部门启用（见 §八） |

**范围 Scope 枚举（0–4，四组通用）**

| 值 | 编辑页文案 | 行级数据含义（`DataPermissionService`） |
|----|------------|----------------------------------------|
| 0 | 全部 | 不按创建人/部门缩小（在具备功能权限前提下可见全量） |
| 1 | 自己 | 仅本人创建或归属本人的数据（按各实体 `CreateByUserId` / 业务员 / 采购员字段） |
| 2 | 本部门 | 主部门及同级员工集合内 |
| 3 | 本部门及下级 | 主部门路径下子部门员工集合内 |
| 4 | 禁止 | 列表过滤为空；部分菜单整组隐藏（见 §五） |

**访问 Access 枚举（0–1，四组通用）**

| 值 | 编辑页文案 | 汇总时行为 |
|----|------------|------------|
| 0 | 读写 | 不因部门剥离写权限码（仍受角色绑定约束） |
| 1 | 只读 | `RbacService` 剥离对应写权限码；API 写接口另有过滤（§六） |

范围为 **4 禁止** 时，编辑页 **禁用** 访问方式下拉，保存时强制 `*DataAccess = 0`。

**新建部门默认值**（`DepartmentEdit.vue`）：`SaleDataScope=2`、`PurchaseDataScope=2`；物流/财务范围默认 `0`；各 `*Access=0`；隐藏开关默认 `false`。

## 三、销售数据范围（`SaleDataScope` / `SaleDataAccess`）

### 3.1 影响的数据域（行级）

`DataPermissionService` 中主要包含（非穷举）：

- 客户 `CustomerInfo`
- 销售订单 `SellOrder`
- 需求 `RFQ`（销售侧归属）
- 收款单、销项发票等（在 **未** 启用财务独立范围 `FinanceDataScope 1–3` 时，仍可能按销售范围过滤）

详见 [数据权限-业务员客户与采购员供应商](./数据权限-业务员客户与采购员供应商.md)。

### 3.2 只读时剥离的功能码（`SaleDataAccess = 1`）

| 剥离 PermissionCode |
|---------------------|
| `sales-order.write` |
| `customer.write` |
| `rfq.write` |
| `rfq.create` |
| `purchase-requisition.write` |

**保留** `*.read`（若角色已绑定）：可见范围仍由 `SaleDataScope` 决定。

### 3.3 前端

- `authStore.isSaleDataReadOnly()` → `useDepartmentDataReadOnly().canWriteSaleData`
- `useSaleOrderWriteGate()`：写 SO 需 `sales-order.write` 且非只读
- 销售/客户相关列表与详情页：写按钮 `v-if="canWriteSaleData"` 等

### 3.4 典型场景：财务部只看全量订单、不可改

```json
{
  "IdentityType": 5,
  "SaleDataScope": 0,
  "SaleDataAccess": 1,
  "PurchaseDataScope": 0,
  "PurchaseDataAccess": 0
}
```

说明见 [权限-财务](./权限-财务.md) §7.1。

## 四、采购数据范围（`PurchaseDataScope` / `PurchaseDataAccess`）

### 4.1 影响的数据域（行级）

- 供应商 `Vendor`
- 采购订单 `PurchaseOrder`
- 采购申请 `PurchaseRequisition`
- 付款单、进项发票等（财务范围未接管时按采购链路过滤）

### 4.2 只读时剥离的功能码（`PurchaseDataAccess = 1`）

| 剥离 PermissionCode |
|---------------------|
| `purchase-order.write` |
| `vendor.write` |
| `purchase-requisition.write` |

### 4.3 前端

- `authStore.isPurchaseDataReadOnly()`、`usePurchaseOrderWriteGate()`
- 采购订单/供应商/PR 列表与详情写操作门控

## 五、物流数据范围（`LogisticsDataScope` / `LogisticsDataAccess`）

### 5.1 控制的菜单（`AppLayout.vue`）

`LogisticsDataScope = 4` 时 **`showLogisticsMenus = false`**，隐藏整组：

- 入库管理（`stock-in.*` 相关路由）
- 出库管理
- 库存管理
- 报关

仍须具备对应 `stock-in.read`、`inventory.read` 等功能权限；部门禁止与功能码 **叠加**。

### 5.2 行级过滤

`ApplyLogisticsCreatorUserScopeAsync`：Scope 为 1/2/3 时按创建人/部门用户集合过滤；`0` 不缩小；`4` 等价无数据。

适用：入库单、出库单、库存、报关等物流实体列表查询。

### 5.3 只读（`LogisticsDataAccess = 1`）

- **不在** `RbacService` 中批量剥离 `stock-in.write` 等码（与销/采不同）。
- API：`LogisticsDataAccessHttp.CanWriteAsync` → 写接口返回 403。
- 前端：`isLogisticsDataReadOnly()`、`canWriteLogisticsData` 隐藏写按钮。

### 5.4 API 辅助类

`CRM.API/Utilities/LogisticsDataAccessHttp.cs`（入库/出库/库存/报关控制器调用）。

---

## 六、财务数据范围（`FinanceDataScope` / `FinanceDataAccess`）

### 6.1 控制的菜单

`FinanceDataScope = 4` 时 **`showFinanceMenus = false`**，隐藏：

- **付款管理**：付款记录、进项发票
- **收款管理**：收款记录、销项发票

功能码仍须 `finance-payment.read` 等；详见 [权限-财务](./权限-财务.md)。

### 6.2 行级过滤

- `FinanceDataScope` 为 **1–3**：`ApplyFinanceCreatorUserScopeAsync` / `ApplyFinanceDepartmentScopeIfNeededAsync` 按单据 `CreateByUserId` 与部门用户集合过滤付款/收款/进销项发票列表。
- `FinanceDataScope = 0`：不按财务部门范围缩小（非财务身份仍可能受 **销售/采购** 范围交叉过滤，见 `DataPermissionService` 内 legacy 逻辑）。
- `FinanceDataScope = 4`：财务列表无行（与菜单隐藏一致）。

财务身份（`IdentityType = 5`）对收款/付款等另有 **不按业务员/采购员缩小** 的例外，见 [权限-财务](./权限-财务.md) §7.2。

### 6.3 只读时剥离的功能码（`FinanceDataAccess = 1`）

| 剥离 PermissionCode |
|---------------------|
| `finance-payment.write` |
| `finance-receipt.write` |
| `finance-sell-invoice.write` |
| `finance-purchase-invoice.write` |

### 6.4 前端与 API

- `useFinanceWriteGate()`：付款/收款/发票写按钮
- `FinanceDataAccessHttp.CanWriteAsync`：`FinancePaymentsController`、`FinanceReceiptsController`、进/销项发票写接口

## 七、隐藏客户管理 / 隐藏供应商管理

与 **Scope 0–4 无关** 的独立开关（部门编辑页复选框）。

| 字段 | 勾选效果 |
|------|----------|
| `HideCustomerManagement` | 剥离 `customer.read`、`customer.write`；隐藏侧栏「客户管理」；拦截客户模块路由。**例外：** 主部门 `IdentityType=5`（财务）仍保留 `customer.read`，供收款/销项发票下拉选用 |
| `HideVendorManagement` | 剥离 `vendor.read`、`vendor.write`；隐藏侧栏「供应商管理」；拦截供应商模块路由。**例外：** 主部门 `IdentityType=5`（财务）仍保留 `vendor.read`，供付款/进项发票下拉选用 |

### 7.1 路由拦截（`router/index.ts` + `departmentModuleGate.ts`）

| 模块 | 拦截路径示例 |
|------|----------------|
| 客户 | `/custome`、`/customerlist`、`/customers/**`（含详情、编辑、联系人、质保书、回收站等） |
| 供应商 | `/vendor`、`/vendorlist`、`/vendors/**` |

命中后跳转 `/dashboard`（非 SYS_ADMIN）。

### 7.2 与「销售/采购 Scope = 4」的区别

| 配置 | 客户/供应商菜单 | 典型差异 |
|------|-----------------|----------|
| `SaleDataScope = 4` | 可能仍显示（若有 `customer.read`） | 仅缩小销售相关 **业务单据** 可见行 |
| `HideCustomerManagement = true` | **强制隐藏** | 无论 Scope，剥离客户功能码并封路由 |

## 八、业务身份 `IdentityType`（同页配置）

存储于 `sys_department.IdentityType`，参与 `RbacService.GetUserPermissionSummaryAsync` 的 **功能码剥离/补全**（与部门范围独立）。

| 库值 | 编辑页展示 | 含义 |
|------|------------|------|
| 0 | 0 无 | 无预设身份；可按部门名兜底财务/采购判定 |
| 1 | 1 销售 | 剥离付款/进项财务码 |
| 2 | 2 采购 | 剥离销售订单、收款/销项财务码等 |
| 3 | 4 采购运营 | 同采购侧策略 |
| 4 | 3 商务 | 额外剥离供应商、PO、草稿只读、进项发票等；**合并**客户/需求/销售订单读写（含 `rfq.create`、`sales-order.write`，支持新建需求、销售订单与申请出库通知） |
| 5 | 6 财务 | 补全 8 个 `finance-*` 读写码（种子常仅 read） |
| 6 | 5 物流 | 参与客户/供应商菜单身份屏蔽 |

前端 `authStore.isIdentityBlockedForPermission` 与上述策略对齐。

**与待审批自审：** 身份 1 的部门总监可审本人客户/销售订单；身份 2/3 的部门总监可审本人供应商/采购订单。不新增权限码，判定走组织角色 + 本字段。见 [审批桌面-设计与实现](../审批/审批桌面-设计与实现.md) §4.1。

**侧栏身份屏蔽（与 Hide* 叠加）**

- 客户管理：采购(2/3)、物流(6) 默认不显示；`HideCustomerManagement` 再隐藏。
- 供应商管理：销售(1)、物流(6) 默认不显示；`HideVendorManagement` 再隐藏。

## 九、`permission-summary` 下发字段

登录与 `GET /api/v1/auth/permission-summary` 返回（camelCase），供 `auth.ts` 使用：

| 字段 | 类型 | 说明 |
|------|------|------|
| `saleDataScope` / `saleDataAccess` | number | 销售范围与读写 |
| `hideCustomerManagement` | boolean | 隐藏客户管理 |
| `purchaseDataScope` / `purchaseDataAccess` | number | 采购范围与读写 |
| `hideVendorManagement` | boolean | 隐藏供应商管理 |
| `logisticsDataScope` / `logisticsDataAccess` | number | 物流 |
| `financeDataScope` / `financeDataAccess` | number | 财务 |
| `identityType` | number | 主部门身份 |
| `belongsToPurchaseDept` | boolean | 是否采购侧部门（兼任+名称兜底） |
| `permissionCodes` | string[] | 已应用 §3–§7 剥离后的有效功能码 |

**登录依赖**：`AuthService.LoginAsync` 在签发 JWT 前调用 `GetUserPermissionSummaryAsync`，会查询 `sys_department` **全部上述列**。生产库缺列会导致登录 500（`42703 column xxx does not exist`）。

## 十、配置矩阵速查

| 需求 | 建议配置 |
|------|----------|
| 仅能看自己的销售订单 | `SaleDataScope = 1`，`SaleDataAccess = 0` |
| 看全部 SO 但不能改 | `SaleDataScope = 0`，`SaleDataAccess = 1` |
| 完全不做销售数据 | `SaleDataScope = 4` |
| 不看客户菜单但能看 SO | 角色保留 `sales-order.read`，`HideCustomerManagement = true` |
| 物流岗只看本部门入库 | `LogisticsDataScope = 2` 或 `3` |
| 禁止物流模块 | `LogisticsDataScope = 4` |
| 财务只看付款不能改 | `FinanceDataScope = 0`，`FinanceDataAccess = 1` |
| 禁止财务菜单 | `FinanceDataScope = 4` |
