## 3. 概况浮窗

### 3.1 客户（`CustomerSelect`）

字段顺序：客户编码、中文全称、英文全称、简称、统一社会信用代码、邓白氏、客户类型、行业｜创建日期、业务员。

- 详情：`customerApi.getCustomerById`
- 字典：`useCustomerDictStore`（类型/行业）
- 销售脱敏（`maskSaleSensitiveFields`）：隐藏编码、名称类、信用代码、邓白氏、业务员；保留类型、行业、创建日期（与全站身份编码规则一致，见脱敏专篇）

### 3.2 供应商（`VendorSelect`）

字段顺序：供应商编码、中文全称、英文全称、简称、统一社会信用代码、邓白氏、等级、身份、行业｜创建日期、采购员。

- 详情：`vendorApi.getVendorById`
- 字典：`useVendorDictStore`（等级/身份/行业）
- 采购脱敏（`maskPurchaseSensitiveFields`）：隐藏编码、名称类、信用代码、邓白氏、采购员；保留等级、身份、行业、创建日期

### 3.3 交互与定位

| 项 | 约定 |
|----|------|
| 展开按钮 | `@mousedown.stop.prevent` + `@click.stop.prevent`，避免点按钮变成选中 |
| 浮层 | `Teleport` → `body`；贴当前实例 `popper-class` 右侧；不够则翻到左侧 |
| 保持下拉 | 面板 `@mousedown.stop.prevent` |
| 唯一实例 | `popper-class` 带随机 instanceId，避免多下拉串位 |

## 4. 编码回填修复

**问题：** `selectedCode` 默认 `''`，`ensureSelectedVisible` 用 `!= null` 判断会把搜索结果里已有编码**覆盖成空**，选中行右侧出现 `—`，而概况卡走详情接口仍有正确编码。

**方案：**

1. 仅当 `selectedCode?.trim()` 非空时覆盖选项编码；
2. 组件内 `lastSelectedMeta` 记住最近选中项的编码/名称；
3. 概况加载成功后，若选项缺编码则用详情编码回写。

客户、供应商下拉同一逻辑。
