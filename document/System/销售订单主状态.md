# 销售订单主状态（`sellorder.status`）

C# 枚举：`CRM.Core.Models.Sales.SellOrderMainStatus`（`: short`，与数据库 `smallint` 一致）。

| 数值 | 枚举成员 | 含义 |
|------|----------|------|
| 1 | `New` | 新建 |
| 2 | `PendingAudit` | 待审核 |
| 10 | `Approved` | 审核通过 |
| 20 | `InProgress` | 进行中 |
| 100 | `Completed` | 完成 |
| -1 | `AuditFailed` | 审核失败 |
| -2 | `Cancelled` | 取消 |

前端列表/明细「状态」列、看板 `orderStatus` 均读主表 `sellorder.status`（**非**明细扩展进度字段）。

---

## 1. 人工流转（`SalesOrderService.UpdateStatusAsync`）

| 当前状态 | 允许目标 | 说明 |
|----------|----------|------|
| `New(1)` | `PendingAudit(2)` | 提交审核 |
| `PendingAudit(2)` | `Approved(10)` / `AuditFailed(-1)` | 审核通过 / 驳回（驳回可带 `AuditRemark`） |
| 任意（无额外校验） | `InProgress(20)` / `Completed(100)` / `Cancelled(-2)` 等 | 调试或业务接口直接写入时无阶段门禁（以调用方为准） |

待办审批（`ApprovalsController` / `SALES_ORDER`）：`PendingStatus = **2**`（`PendingAudit`），通过为 **10**，驳回为 **-1**。

**申请出库（主单）**：`RequestStockOutAsync` 将主状态更新为 **InProgress（20）**（与自动同步并存，属显式入口之一）。

---

## 2. 自动同步（与明细扩展执行链对齐）

实现：`SellOrderMainStatusSyncService` / `SellOrderMainStatusCompute`（`CRM.Core/Services/SellOrderMainStatusSyncService.cs`）。

**不参与自动重算的主状态**（保持原值）：`New`、`PendingAudit`、`AuditFailed`、`Cancelled`。

**有效明细**：`sellorderitem.status != 1`（`1` = 已取消，不参与判断）。

### 2.1 `Approved(10) → InProgress(20)`

当主状态为 **审核通过**，且至少一条有效明细的扩展表出现「执行链已开始」：

满足以下**任一**即视为已开始（扩展字段来自 `sellorderitemextend`，由 `SellOrderItemExtendSyncService.RecalculateAsync` 维护）：

| 条件 | 字段 |
|------|------|
| 采购已开始 | `purchase_progress_status > 0`（0=待 1=部分 2=完成） |
| 入库已开始 | `stock_in_progress_status > 0` |
| 出库已开始 | `stock_out_progress_status > 0` |
| 收款已开始 | `receipt_progress_status > 0` |
| 开票已开始 | `invoice_progress_status > 0` |
| 已下达出库通知 | `qty_stock_out_notify > 0` |

### 2.2 `InProgress(20) → Completed(100)`

当主状态为 **进行中**，且**全部有效明细**的收款进度均为 **完成**：

- 扩展表 `receipt_progress_status >= 2`（2 = 完成）
- 单条明细收款完成口径：`receipt_amount_finish`（该行所有应收 `verified_done` 之和）≥ 销售行全额 `qty × price`（即 `receipt_amount`），由 `SellOrderItemExtendSyncService` 在重算时写入

**说明**：主状态「完成」以**收款完成**为准，**不**以出库完成为准。

### 2.3 `Completed(100) → InProgress(20)`（回退）

当主状态为 **完成**，但任一条有效明细 `receipt_progress_status < 2`（例如收款反核销）时，回退为 **进行中**。

### 2.4 同步触发时机

| 场景 | 入口 |
|------|------|
| 业务事件重算明细扩展后 | `SellOrderItemExtendSyncService.RecalculateAsync` 末尾调用 `TrySyncOrderMainStatusAsync`（采购、入库、出库、收款核销等链路） |
| 详情页「刷新状态」 | `SalesOrderService.RefreshDownstreamAsync(Status)`：逐行 `RecalculateAsync(StatusOnly)` 后同步主状态；不改单价/客户/型号 |
| Debug 批量修复 | `POST /api/v1/debug/refresh-sellorder-main-status`：遍历未软删订单，逐单 `RefreshDownstreamAsync(Status)`；跳过 `Cancelled` / `AuditFailed`；不再覆盖销售价 |

列表 `/sales-order-items` 的「状态」列与上述主表字段同源；历史订单若扩展已更新而主状态滞后，可在业务事件触发重算后自动修正，或通过 Debug / 详情「刷新状态」批量对齐。详见 [销售订单分面刷新](./销售/销售订单分面刷新-设计与实现.md)。

---

## 3. 与出库业务校验的关系

- **申请出库 / 执行出库** 等门禁：主单须 `Status >= Approved(10)` 且 **非** `Completed(100)`（见 [业务规则总览](./业务规则总览.md) §8）。
- **主状态变为完成**：仅由 §2.2 收款规则驱动，与出库单是否全部完成无直接绑定。
