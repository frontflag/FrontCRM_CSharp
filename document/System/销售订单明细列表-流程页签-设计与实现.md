## 1. 业务定位

| 概念 | 说明 |
|------|------|
| **目标** | 以时间节点推进方式展示 **单条销售明细** 从建立到收款/开票的完整业务链路（地铁路线图式纵向轴） |
| **展示位置** | `AppLayout` 右侧辅助栏第三页签 **「流程」**，与「操作」「帮助」并列 |
| **页签 ID** | `r-flow`（文案 i18n：`layout.auxTabs.flow` → 中文「流程」） |
| **数据粒度** | 一条销售订单明细行（`sellOrderItemId`） |
| **只读** | 无申请采购/出库等动作按钮；单号可跳转详情，样式见 [流程页签规范 §2.6](../PRD/规范/UI规范/流程页签规范.md) |

**与「操作」页签区别：**

| | 操作 `r-ops` | 流程 `r-flow` |
|--|--------------|---------------|
| 侧重 | 日常动作、进度条、申请采购/出库 | 全链路只读时间轴 |
| 备货 | 备货库存汇总 + 使用备货卡片 | 仅 **使用备货** 作为一站（在出库通知之后） |
| 范围 | 列表 + 详情右侧均可挂 | 列表 + 详情（与操作共用选中明细行 / aggregates） |

## 2. 布局与交互

### 2.1 整体结构

```
┌─ 右侧辅助栏 ─────────────────────────────┐
│ [操作] [流程] [帮助]           [全屏][✕] │
├──────────────────────────────────────────┤
│  ● 销售订单明细                          │
│  │  ┌ 小卡：单号/状态/日期/… ─────────┐ │
│  │  └────────────────────────────────┘ │
│  ● 采购申请                              │
│  │  ┌ 小卡 1 ────────────────────────┐ │
│  │  ├ 小卡 2（同站多卡，创建升序）────┤ │
│  │  └────────────────────────────────┘ │
│  ○ 采购明细（未开始：空心站）            │
│  │                                       │
│  …                                       │
│  ● 发票                                  │
└──────────────────────────────────────────┘
```

- 竖轴 **从上往下**；禁止依赖横向滚动。
- **同站多卡：** 竖轴按节点类型固定一站；站内多张单据小卡按 **创建时间升序（早→晚）** 叠放。
- 未发生节点：**仍画空心站**，站内无小卡，文案「未开始」。

### 2.2 站点视觉态

| 站态 | 圆点 | 判定（定稿） |
|------|------|----------------|
| **未开始** | 空心 | 该站无任何单据/记录 |
| **进行中** | 实心（主题色/进行中色） | 有单据，且 **未全部终态** |
| **已完成** | 实心（完成色，如绿） | 有单据，且 **全部终态** |

- 小卡自身另用状态文案/标签展示单张单据状态。
- 终态枚举见 **§4.3**；实现时优先复用各模块既有状态文案函数，避免新造文案表。

### 2.3 交互门控（对齐操作面板 §2.4，并扩展至「流程」）

适用：销售订单明细列表。实现可扩展 `useListRightOpsPanelInteraction`（或等价），将「需要加载面板数据」的页签从仅 `r-ops` 扩展为 **`r-ops` ∪ `r-flow`**。

| # | 右栏状态 | 当前页签 | 用户动作 | 结果 |
|---|----------|----------|----------|------|
| A | 收起 | — | 单击行 | 忽略：不展开、不选中、**不请求** |
| B | 展开 | **非**「操作」且 **非**「流程」（如帮助） | 单击行 | `setRowOnly`：高亮；不切页签；**不请求** |
| C | 展开 | **操作** 或 **流程** | 单击行 | `selectRow`：选中 + 请求 aggregates（可与操作共用 store） |
| D | 展开 | 切到「操作」或「流程」 | 切换页签 | 若已有选中行 → 加载/复用 aggregates |
| E | 收起→展开 | 默认仍优先 **操作**（工作台规范） | 展开 | 若随后切到「流程」且已有选中行 → 展示流程 |
| F | 任意 | 任意 | 列表刷新 / 离开路由 | `clear()` |

**原则：**

1. 「流程」与「操作」共用同一选中行与同一 aggregates 缓存，避免双请求。
2. 脱敏（`maskSaleSensitiveFields`）时：仍可加载（与操作一致）；敏感字段 `—`。
3. 双击行仍进销售订单详情，优先级高于单击。

### 2.4 小卡字段布局

- 站标题：节点中文名（如「采购申请」）。
- 小卡内：**双列 Key:Value**（对齐操作面板 §2.5.2）；单字段可占左列。
- 单号：`router-link` + `link-text`（[列表跳单号链接样式规范](../PRD/规范/UI规范/列表跳单号链接样式规范PRD.md)）；脱敏或无权限时纯文本。
- **描述：** MVP 预留一行 Key「描述」，Value 固定空/`—`（各节点后续单独定义聚合文案）。

## 3. 节点清单与顺序（定稿）

```
1. 销售订单明细
2. 采购申请
3. 采购明细
4. 质检
5. 入库
6. 出库通知
7. 使用备货
8. 装箱
9. 出库
10. 收款核销
11. 发票
```

说明：

- 已去掉重复「出库」；**出库**仅保留装箱之后一处。
- **使用备货**在出库通知之后；内容为 `aggregates.stockingUsage`（按采购主单汇总的备货补充拣货），**不是**备货库存池快照。**无使用记录时整站不渲染**（例外于「空站仍画空心」通则）。
- 不展示独立「备货库存」站（备货库存仍留在「操作」页签）。

## 4. 数据与字段映射

### 4.1 数据源

| 来源 | 用途 |
|------|------|
| 列表行 `row` | 销售订单明细站：单号、状态、客户、业务员、单价、数量、创建相关时间 |
| `GET /api/v1/sales-orders/{orderId}/sell-order-items/{sellOrderItemId}/detail-tab-aggregates` | 下游各站单据列表 + `stockingUsage` |

**MVP 不新增专用流程 API**；前端将 aggregates + row 适配为 `FlowStation[]`。

人员字段若 DTO 缺失：**显示「—」**，本期不强制补全 aggregates。

### 4.2 公共展示字段（按站裁剪）

每站小卡候选字段：

| Key | 说明 |
|-----|------|
| 单号 | 可跳转；样式见 [流程页签规范 §2.6](../PRD/规范/UI规范/流程页签规范.md) |
| 状态 | 单据状态文案 |
| 创建日期 | `yy-MM-dd`（两位年、无时分），见 [流程页签规范 §2.7](../PRD/规范/UI规范/流程页签规范.md) |
| 客户名称 | **仅部分站显示**（§4.4）。销售明细站通栏 `{名称} ({编号})`，无独立编号行 |
| 角色人名 | Key 为 **角色名**（业务员/采购员/…），非统一「业务员」 |
| 单价 · 币别 或 金额 · 币别 | §4.5 |
| 数量 | 有业务数量的站；收款/发票不显示数量 |
| 描述 | MVP 空 |

### 4.3 各站映射表

| # | 站名 | aggregates / row | 单号 | 人员 Key → 字段 | 数量/金额 | 客户 |
|---|------|------------------|------|-----------------|-----------|------|
| 1 | 销售订单明细 | `row` | `sellOrderItemCode`（可附销售单号） | **业务员** → `salesUserName` | `qty`；单价·币别=销售价 | **通栏** `{名称} ({编号})`，无独立编号行 |
| 2 | 采购申请 | `purchaseRequisitions` | `billCode` | **采购员** → 当前 DTO **无** → `—` | `qty`；单价若无则隐藏单价行 | **不显示** |
| 3 | 采购明细 | `purchaseOrderItems` | `purchaseOrderItemCode`（主单号可辅显） | **采购员** → `purchaseUserName` | `qty`；单价·币别=`cost`+`currency` | **不显示** |
| 4 | 质检 | `qcs` | `qcCode` | **创建人** → `createUserName` | 可用 `passQty`/`rejectQty` 或合计口径（实现时与质检列表一致） | **不显示** |
| 5 | 入库 | `stockIns` | `stockInCode` | **创建人** → `createUserName` | `totalQuantity`；不显示单价 | **不显示** |
| 6 | 出库通知 | `stockOutRequests` | `requestCode` | **申请人** → `requestUserName`（优先）；缺则 `—`（`salesUserName` 可作辅信息不强绑） | `outQuantity`；不显示单价 | **显示** |
| 7 | 使用备货 | `stockingUsage.items` | **采购单号** `purchaseOrderCode` | **采购员** → `purchaseUserName` | `usedQty`；不显示单价 | **不显示** |
| 8 | 装箱 | `packings` | `code` | **创建人** → `createUserName`；可辅显 **业务员** `salesUserName`（若需验证销售传递，MVP 主显创建人，业务员有则第二人员行可选——**MVP 仅主显创建人**） | `itemRows` 或关联行数量口径（与装箱列表一致） | **显示**（`customerName`；编号若 DTO 无则仅名称） |
| 9 | 出库 | `stockOuts` | `stockOutCode` | **创建人** → `createUserName`（有 `salesUserName` 时另可验证，MVP 主显创建人） | `totalQuantity`；不显示单价 | **显示** |
| 10 | 收款核销 | `receiptWriteOffs` | `financeReceiptCode` 优先，否则应收/核销相关单号 | **操作人** → `operatorUserName` | **金额·币别**=`amount`+`currency`；**不显示数量** | **显示** |
| 11 | 发票 | `sellInvoices` | `invoiceCode` / `invoiceNo` | **创建人** → 当前 aggregates **无** → `—` | **金额·币别**=`invoiceTotal`+`currency`；**不显示数量** | **显示**（`customerName`；编号无则仅名称） |

**使用备货** 创建日期：用 `purchaseOrderCreateTime`（与操作面板「生成日期」一致）。  
跳转：采购单号 → `PurchaseOrderDetail`（同操作面板）。

### 4.4 客户 Key:Value 显示范围（定稿）

| 站 | 客户名称 / 客户编号 |
|----|---------------------|
| **销售明细** | **通栏「客户名称」**，文案 `{客户名称} ({客户编号})`（例 `Acme (C001)`）；**无**独立「客户编号」行；脱敏为 `—`。有 `customer.read`（且非身份屏蔽、未隐藏客户管理）且卡上有 `customerId` 时，名称可点：悬停手型 + 橙色（同流程单号 §2.6），**新开页**进客户详情；否则纯文本 |
| 出库通知、装箱、出库、收款核销、发票 | **显示**名称 + 编号两格（与既有一致）；名称跳转门控与销售明细站相同 |
| 采购申请、采购明细、质检、入库、使用备货 | **不显示**（采购侧也不显示供应商） |

### 4.5 单价 / 金额（定稿）

| 站 | 规则 |
|----|------|
| 销售明细 | 销售单价 · 币别 |
| 采购申请 / 采购明细 | 采购单价 · 币别（有则显；申请无单价则隐藏该行） |
| 质检 / 入库 / 出库通知 / 使用备货 / 装箱 / 出库 | 不显示单价 |
| 收款核销 / 发票 | **金额 · 币别**（替代数量） |

### 4.6 站终态判定（实现指引）

站级「已完成」= 该站 **全部小卡** 对应单据处于终态。示意（实现时对齐现有枚举与列表状态文案）：

| 站 | 终态示意（需与代码常量对齐） |
|----|------------------------------|
| 销售明细 | 行/单取消或关闭类终态按销售侧既有定义；进行中订单为进行中 |
| 采购申请 | PR 完成/关闭等终态 |
| 采购明细 | PO 行/头完成类状态 |
| 质检 | 质检完成 |
| 入库 | 入库过账/完成 |
| 出库通知 | 通知完成/已出库类终态 |
| 使用备货 | 有记录即视为该站「有单据」；全部卡可视为完成（使用记录无独立流程态）或统一「已完成」 |
| 装箱 | 装箱完成/已发运类 |
| 出库 | 出库过账/完成 |
| 收款核销 | 核销已生效（无草稿态则有记录即完成） |
| 发票 | 发票开具完成类状态 |

若与 `sell_order_item_extend.*ProgressStatus`（0/1/2）可对齐，站态可优先参考进度字段作校验，但 **小卡仍以具体单据状态为准**。

### 5.1 类型草案（前端）

```ts
type FlowStationStatus = 'empty' | 'active' | 'done'

interface FlowCard {
  id: string
  docNo: string
  docRoute?: { name: string; params?: object; query?: object }
  statusText: string
  isFinal: boolean
  createdAt?: string | null
  customerName?: string | null
  customerCode?: string | null
  personRoleKey: string   // i18n key，如 purchaser / operator
  personName?: string | null
  unitPriceText?: string | null  // 含币别，或金额·币别
  qtyText?: string | null
  description?: string | null    // MVP null
}

interface FlowStation {
  key: string
  titleKey: string
  stationStatus: FlowStationStatus
  cards: FlowCard[]  // 创建时间升序
}
```
