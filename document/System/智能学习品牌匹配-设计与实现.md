## 一、功能定位

业务员在 **Excel 导入 RFQ** 或 **手工建单** 时，客户表格中的品牌写法往往与系统标准品牌不一致（如「TI(德州仪器)」「ST/意法」）。系统需要在不增加重复劳动的前提下，将 **导入原文** 稳定映射到 `biz_brand` 标准品牌。

**智能学习品牌匹配** 包含两层能力：

| 能力 | 说明 |
|------|------|
| **自动匹配** | 按固定优先级：学习映射 → 规则拆词匹配 →（可选）AI 标准名映射 → 待选手选 |
| **学习记忆** | 用户在某次导入中 **手动选定** 标准品牌后，将「导入原文 → brandId」写入全公司共享学习表；下次相同（归一化后）原文自动命中 |

**设计目标：**

1. **越用越准** — 组织内共用学习结果，减少重复选手选。
2. **可解释** — 每条明细可区分来源：`learned` / `rule` / `ai` / 手选。
3. **不误绑** — 规则层与 AI 层均要求 **唯一命中**；歧义一律 `pending`。
4. **学习可覆盖** — 同一 `source_key` 后写覆盖 `brand_id`（以最新人工确认为准）。

**不在本期范围：**

- 学习映射管理后台（查看/删除/批量导入学习表）
- 按用户/部门隔离学习（当前为 **全公司共享**）
- 非 RFQ 业务节点自动学习（架构可复用，首期仅 RFQ 路径写入）

## 二、业务场景

### 2.1 RFQ Excel 导入（读 + 写）

```
ImportRFQDialog Step 2
  → buildBrandMatchCache（学习 + 规则）
  → 可选：AI 品牌映射（仅 pending）
  → 进入 RFQCreate

RFQCreate
  → 用户为 pending 行选手品牌（BizBrandSelect）
  → onItemBrandChange：若有 _importBrandText → rememberLearnedMapping
```

### 2.2 文本 AI 建 RFQ（仅读，不写学习）

`entity.parse.rfq` 预填后，`RFQCreate` 对非 Excel 来源调用 `resolveBrandIdsForItems`（同样走学习 + 规则链），但 **无 `_importBrandText` 时不触发学习写入**。

### 2.3 匹配关键词选取

| 字段 | 优先级 |
|------|--------|
| 供应品牌 `brand` | 优先 |
| 客户品牌 `customer_brand` | `brand` 为空时兜底 |

实现：`resolveBrandMatchKeyword(supplyBrand, customerBrand)`。

## 三、匹配链架构

```
导入原文 (source_text)
    │
    ▼
normalizeBrandSourceKey ──► source_key（查重键）
    │
    ├─① POST /biz-brands/learned-mappings/resolve
    │      命中 → mappingSource = learned, brandId 已填
    │
    ├─② expandBrandMatchCandidates（拆词）
    │      对每个候选 → GET /biz-brands/options?keyword=
    │      pickBizBrandMatch（唯一命中）
    │      命中 → mappingSource = rule
    │
    ├─③（Excel 导入可选）entity.parse.rfq_excel_brand_map
    │      LLM 输出 standard_brand → 再执行 ② 解析 brandId
    │      命中 → mappingSource = ai
    │
    └─ 仍未唯一命中 → status = pending，保留 _importBrandText
              │
              ▼ 用户手选标准品牌
         POST /biz-brands/learned-mappings/remember
              → 写入学习表，下次走 ①
```

**优先级原则：** ① 学习表一旦命中即返回，不再走规则拆词；② 规则层不覆盖已学习结果；③ AI **仅处理 pending**，不覆盖 `learned` / `rule` 已匹配行。

## 四、学习机制

### 4.1 写入（Remember）

| 项 | 内容 |
|----|------|
| 触发 | `RFQCreate.onItemBrandChange`，且行上存在 `_importBrandText`（Excel 导入保留的原文） |
| API | `POST /api/v1/biz-brands/learned-mappings/remember` |
| 请求体 | `{ sourceText, brandId }` |
| 校验 | `sourceText` 非空；`brandId` 对应未删除的 `biz_brand` |
| 用户反馈 | Toast：「已记住该品牌映射…」（`rfqExcelImport.brandLearned`） |
| 成功后 | 清除行上 `_importBrandText`，避免重复写入 |

**注意：** 仅当用户 **主动改选品牌** 且带有导入上下文时学习；规则/AI 自动匹配 **不会** 自动写入学习表（避免错误映射固化）。

### 4.2 读取（Resolve）

| 项 | 内容 |
|----|------|
| 触发 | `buildBrandMatchCache` 批量解析前 |
| API | `POST /api/v1/biz-brands/learned-mappings/resolve` |
| 请求体 | `{ sourceTexts: string[] }`（去重后的导入原文列表） |
| 响应 | `[{ sourceText, sourceKey, brandId, standardBrand }]` |
| 失败策略 | 前端 catch 后降级为仅规则匹配（学习查询可选） |

### 4.3 归一化键 `source_key`

前后端算法一致，保证同一「写法」命中同一条学习记录：

| 步骤 | 规则 |
|------|------|
| 1 | `trim` |
| 2 | 全角括号 `（）` → `()` |
| 3 | 全角字母数字等 → 半角（`ToHalfWidth`） |
| 4 | 连续空白合并为单个空格 |
| 5 | **转小写**（英文大小写不敏感） |

| 原文 | source_key |
|------|------------|
| `TI(德州仪器)` | `ti(德州仪器)` |
| `ＴＩ（德州仪器）` | `ti(德州仪器)` |
| `  ST  ` | `st` |

前端：`normalizeBrandSourceKey`（`bizBrandMatch.ts`）  
后端：`BizBrandSourceKeyHelper.Normalize`

### 4.4 存储策略

| 策略 | 说明 |
|------|------|
| 唯一键 | `source_key` UNIQUE |
| 冲突 | 已存在则 **更新** `brand_id`、`source_text`、`hit_count++`、`last_used_by_user_id` |
| 软删品牌 | resolve 时跳过 `biz_brand.is_deleted = true` 的映射 |
| 作用域 | **全公司共享**，非 per-user |

## 五、规则层（非学习）

规则层在学习未命中时执行，与「学习」解耦，便于单独演进同义词与拆词逻辑。

### 5.1 候选拆词 `expandBrandMatchCandidates`

对原文生成多个检索关键词，依次尝试：

- 原文与括号半角化版本
- 括号外前缀（如 `TI(德州仪器)` → `TI`）
- 括号内（如 `德州仪器`）
- 按 `/` 分段
- 按 `,;|、` 等分隔符分段

### 5.2 唯一匹配 `pickBizBrandMatch`

在 `GET /biz-brands/options` 返回的候选中，按顺序尝试 **精确**（忽略大小写）匹配：

1. `standardBrand`
2. `brandEName`
3. `brandCName`
4. `alias` 中 **完整 token**（非子串模糊）

任一阶段出现 **多条** 命中 → 返回 `null`（歧义待选）。  
仅当 `options.length === 1` 时允许兜底唯一（无字段级精确匹配时）。

### 5.3 AI 层（补漏，非学习）

场景 `entity.parse.rfq_excel_brand_map` 将 pending 原文映射为 **标准品牌名称**（字符串），再经规则层解析为 `brandId`。详见 [RFQ Excel导入-设计与实现](./RFQ Excel导入-设计与实现.md) §4.2。

## 六、数据模型

### 6.1 表 `biz_brand_learned_mapping`

| 列 | 类型 | 说明 |
|----|------|------|
| `id` | BIGSERIAL | 主键 |
| `source_text` | VARCHAR(500) | 导入原文（展示、写入 remember 时的文本） |
| `source_key` | VARCHAR(500) UNIQUE | 归一化查重键 |
| `brand_id` | BIGINT FK | → `biz_brand.id` |
| `hit_count` | INT | 学习/复用次数 |
| `last_used_by_user_id` | VARCHAR(36) | 最近一次 remember 用户 |
| `create_by_user_id` | VARCHAR(36) | 首次创建用户 |
| `create_time` / `update_time` | TIMESTAMPTZ | |
| `is_active` | BOOLEAN | 默认 true |

脚本：`scripts/ensure_biz_brand_learned_mapping_postgresql.sql`  
EF：`CRM.Infrastructure/Migrations/20260815120000_BizBrandLearnedMapping.cs`

### 6.2 前端行级上下文字段

| 字段 | 说明 |
|------|------|
| `_importBrandText` | Excel 导入保留的原始品牌文本；学习写入依据；匹配成功后清除 |
| `_brandMatchStatus` | `matched` / `pending` / `empty`（导入对话框统计用） |
| `_brandMappingSource` | `learned` / `rule` / `ai` |
| `brandId` | 标准品牌 ID；保存 RFQ 必填 |

## 七、API 与权限

基路径：`/api/v1/biz-brands`（`BizBrandsController`，`[Authorize]`）

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `learned-mappings/remember` | 写入/更新学习映射 |
| POST | `learned-mappings/resolve` | 批量解析学习映射 |
| GET | `options` | 规则层品牌搜索（已有） |

**权限：** 学习读写 **无独立权限码**，登录且可访问品牌 API 即可（与品牌主数据同一控制器鉴权）。  
Excel 导入入口另需 `biz.ai.entity.parse.rfq`（AI 补漏按钮，与文本 AI 建 RFQ 共用）。

## 八、前端实现

**核心模块：** `CRM.Web/src/utils/bizBrandMatch.ts`

| 导出 | 用途 |
|------|------|
| `normalizeBrandSourceKey` | 与后端一致的查重键 |
| `expandBrandMatchCandidates` | 规则层拆词 |
| `pickBizBrandMatch` | 候选唯一匹配 |
| `buildBrandMatchCache` | 批量：resolve 学习 + 规则匹配 |
| `matchBrandKeyword` | 单词匹配 |
| `rememberLearnedBrandMapping` | 调用 remember API |
| `resolveBrandIdsForItems` | RFQ 明细批量补 brandId（文本 AI 预填等） |
| `resolveBrandMatchKeyword` | 供应品牌 / 客户品牌取词 |

**调用方：**

| 组件 | 行为 |
|------|------|
| `ImportRFQDialog.vue` | `resolveBrandMatches` → 统计「规则/学习」「AI」「待选择」 |
| `RFQCreate.vue` | `onItemBrandChange` → 学习写入；`itemNeedsBrandAttention` 提示 |
| `RfqItemPanelFields.vue` | 待选品牌行内提示文案 |

**API 封装：** `CRM.Web/src/api/bizBrand.ts` — `rememberLearnedMapping`、`resolveLearnedMappings`。

## 十一、扩展与约束

| 主题 | 说明 |
|------|------|
| 复用 | 新业务只需调用 `buildBrandMatchCache` + `rememberLearnedBrandMapping`，并约定 `_importBrandText` 语义 |
| 学习质量 | 依赖人工确认；错误手选会覆盖同 key 的学习结果 |
| 数据迁移 | 可从历史 RFQ 洗学习表（未实现）；当前仅在线学习 |
| 与品牌审核 | `brandId` 指向待审核品牌时仍可学习；保存 RFQ 时仍校验有效品牌 |
