# 管理角色三级（SuperAdmin / Admin / Manager）— 设计与实现

**状态：** 一期已落地  
**关联：** [管理角色分级与权限体系PRD](../PRD/管理角色分级与权限体系PRD.md)

## 命名对照

| 产品称呼 | RoleCode | permission-summary |
|----------|----------|-------------------|
| SuperAdmin | `SYS_ADMIN` | `isSysAdmin` |
| Admin | `SYS_MANAGER` | `isSysManager` |
| Manager | `SYS_BIZ_MANAGER` | `isBizManager` |

`hasManagementAccess` = 上述三者之一；`hasBizDataBypass` 同期为 true（业务数据行级全量）。

一期**不实现**原 PRD 的 `SYS_MGR_*` DepartManager。

## 能力摘要

- Manager：业务数据全量；员工管理（仅普通员工）；不可建 Manager/Admin/SuperAdmin
- Admin：含 Manager 能力；可建 Manager；系统菜单按角色上 `system.*` 勾选；不可见 SuperAdmin
- SuperAdmin：全部；SuperAdmin 改密仅 SQL

## 实现要点

- 权限码：`CRM.Core/Constants/SystemPermissionCodes.cs`
- 种子迁移：`CRM.Infrastructure/Migrations/20260726060000_SeedManagementRolesAndSystemPermissions.cs`
- 账号边界：`CRM.API/Authorization/ManagementAccountPolicy.cs` + `RbacController`
- 前端：`canAccessSystemPermission` / `canAccessParamsModule`（`CRM.Web/src/stores/auth.ts`）
- **参数模块约定**：侧栏 `system.params.{sales|purchase|finance}.read`；页内子项 `system.params.{area}.{feature}.read|write`（未来新增子菜单按此命名即可在角色编辑中自动标为「页内子项」）
- 种子：`seed_params_page_sub_permissions.sql` / 迁移 `20260726080000_SeedParamsPageSubPermissions`

## 运维

本地/服务器执行 EF 迁移或手工跑迁移 SQL 后，Admin/Manager 角色与 `system.*` 权限才会生效。现有 `SYS_ADMIN` 仍凭 `IsSysAdmin` 全放行。
