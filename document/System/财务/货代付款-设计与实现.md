## 一、业务背景与目标

### 1.1 业务场景

客户向本公司支付一笔款项（收款单），该笔款项实质为**代收货代费用**，财务收到客户款后需**线下转付给货代公司**。本模块用于：

1. 在收款单上打标「货代付款」；
2. 收款单审核通过后，自动进入**货代付款台账**；
3. 财务线下付款后，在系统中**登记付款明细**（支持多次部分付款）；
4. 维护独立的**货代公司主数据**及收款银行账户。

### 1.2 设计原则

| 原则 | 说明 |
|------|------|
| 货代公司独立主数据 | 与客户、供应商无关联，在「货代公司管理」单独维护 |
| 台账以收款单为维度 | 一笔货代付款收款单对应一条台账；已付/待付由付款明细汇总计算 |
| 线下付款、系统记账 | 付款明细**无审核流**；财务实际转付后登记 |
| 与预收款互斥 | 同一收款单不可同时勾选「货代付款」与「预收款」 |
| 复用收款权限 | 读写权限均挂在 `finance-receipt.read` / `finance-receipt.write` |

### 1.3 业务流程

```
┌──────────────┐    ┌──────────────┐    ┌──────────────┐    ┌──────────────┐
│ 新建收款单   │───>│ 勾选货代付款 │───>│ 收款单审核   │───>│ 进入货代付款 │
│              │    │ （可选填货代）│    │ 通过(≥2)     │    │ 台账列表     │
└──────────────┘    └──────────────┘    └──────────────┘    └──────────────┘
                                                                    │
                                                                    ▼
┌──────────────┐    ┌──────────────┐    ┌──────────────┐    ┌──────────────┐
│ 台账状态完成 │<───│ 累计已付≥应收│<───│ 登记付款明细 │<───│ 线下转付货代 │
│ (30)         │    │              │    │ (可多次)     │    │              │
└──────────────┘    └──────────────┘    └──────────────┘    └──────────────┘
```

## 二、功能设计要求

### 2.1 收款单打标（入口）

**页面**：收款记录 → 新建收款单（`FinanceReceiptList.vue`）

| 字段 | 要求 |
|------|------|
| 货代付款 | 复选框；与「预收款」互斥（前端互禁 + 后端校验） |
| 货代公司 | 勾选货代付款后显示；**可选**；placeholder「请选择货代公司（可选）」 |
| 布局 | 货代公司字段单独占一行，第二列（`:offset="12"`） |
| 提示文案 | 灰色小字，距复选框约 2em；不含「与预收款互斥」「可在收款核销页使用」等说明 |

**后端规则**（`FinanceReceiptService.ValidateFreightForwarderReceiptFlags`）：

- `is_freight_forwarder_payment = true` 且 `receipt_purpose = 20`（预收）→ 抛错「货代付款与预收款不能同时勾选」
- 若填写了 `freight_forwarder_company_id`，须存在于 `freight_forwarder_company` 表

**收款单状态与台账准入**：

- 仅 `status >= 2`（已审核）且 `status != 4`（非取消）的货代付款收款单进入台账
- 状态 2=已审核，3=已收款

### 2.2 货代公司管理

**路由**：`/finance/freight-forwarder-companies`（`FreightForwarderCompanyManage`）  
**入口**：货代付款列表页「货代公司管理」按钮

| 功能 | 要求 |
|------|------|
| 列表 | 遵循业务列表页规范（`CrmDataTable`、列设置、行密度、分页、操作列） |
| 新建/编辑 | 编号 `FFC` 流水号自动生成；中文名必填 |
| 启用/停用 | `Status`：1=启用，0=停用；停用后不出现在业务下拉 |
| 收款银行 | 每家公司可维护多条；支持默认账户、停用 |
| 删除 | 软删除；若被收款单或付款明细引用则禁止删除 |

### 2.3 货代付款台账列表

**路由**：`/finance/freight-forwarder-payables`  
**菜单位置**：收款管理 → 销项发票 **下方**

| 列/筛选项 | 说明 |
|-----------|------|
| 台账状态 | 10 待付款 / 20 部分付款 / 30 付款完成（计算字段，不落库） |
| 收款单号、收款公司、货代公司 | 关键字可搜单号/客户 |
| 应收总额、已付、待付、币别、收款日期 | 金额遵循列表金额显示范式 |
| 操作 | 详情、付款（待付 > 0 时） |

**台账状态计算**（`FinanceFreightForwarderPayableStatusHelper`）：

```
已付 = SUM(付款明细.PaymentAmount)
待付 = MAX(0, 应收总额 - 已付)
状态 = 已付<=0 → 10；已付>=应收 → 30；否则 → 20
```

### 2.4 货代付款详情

**路由**：`/finance/freight-forwarder-payables/:id`（`:id` = 收款单 ID）

遵循**业务详情页规范**：

- CaptionBar：前缀「货代付款」+ 收款单号 + 台账状态 Tag
- 基本信息区：收款公司、货代公司、应收/已付/待付、收款日期
- 付款明细：`CrmDataTable` 嵌入；空态 `DetailListPanelEmpty`
- 相关业务：链接至收款单详情
- 待付 > 0 且有写权限时，标题栏显示「登记付款」

### 2.5 登记货代付款弹窗

**组件**：`FinanceFreightForwarderPaymentPayDialog.vue`

| 字段 | 必填 | 说明 |
|------|------|------|
| 货代公司 | 是 | 收款单未填时，首次付款前必选；与收款单已选须一致 |
| 货代收款银行 | 否 | 按货代公司联动；默认账户自动选中 |
| 付款银行 | 否 | 公司出款账户（`company-bank-select`） |
| 待付 | — | 只读 |
| 本次付款金额 | 是 | > 0 且 ≤ 待付余额 |
| 付款方式 | 否 | 默认银行转账；标签走 `financeEnums.paymentMode.*` |
| 付款日期 | 否 | |
| 银行水单号 | 否 | |
| 备注 | 否 | |
| 银行水单附件 | 否 | 业务类型 `FINANCE_FF_PAYMENT` |

## 三、数据模型

### 3.1 表结构总览

| 表名 | 用途 |
|------|------|
| `freight_forwarder_company` | 货代公司主数据 |
| `freight_forwarder_company_bank` | 货代收款银行账户（`is_deleted` 软删） |
| `finance_freight_forwarder_payment` | 货代付款明细 |
| `financereceipt`（扩展列） | `is_freight_forwarder_payment`、`freight_forwarder_company_id` |

### 3.2 收款单扩展字段

| 列名 | 类型 | 说明 |
|------|------|------|
| `is_freight_forwarder_payment` | boolean | 是否货代付款收款 |
| `freight_forwarder_company_id` | varchar(36) NULL | 货代公司 ID；创建时可选，首次付款前必填 |

### 3.3 货代付款明细关键字段

| 列名 | 说明 |
|------|------|
| `FinanceFfPaymentId` | 主键 GUID |
| `FinanceReceiptId` | 关联收款单 |
| `FreightForwarderCompanyId` | 货代公司（冗余，便于历史追溯） |
| `PaymentAmount` | 本次付款金额 |
| `PaymentCurrency` | 币别（默认与收款单一致） |
| `PaymentMode` | 1 银行转账 / 2 现金 / 3 支票 / 4 承兑汇票 |
| `CompanyBankId` | 我方付款银行 |
| `FfCompanyBankId` | 货代收款银行 |
| `BankSlipNo` | 银行水单号 |
| `PaymentDate` | 付款日期 |
| `PaymentUserId` | 登记人 |
| `is_deleted` | 软删除；不参与已付汇总 |

### 3.4 流水号

| ModuleCode | 前缀 | 说明 |
|------------|------|------|
| `FreightForwarderCompany` | `FFC` | 货代公司编号，5 位序号 |

### 3.5 EF 映射注意

`freight_forwarder_company`、`freight_forwarder_company_bank`、`finance_freight_forwarder_payment` 三张表使用 `create_by_user_id`（GUID），**无** `BaseEntity` 的 bigint `CreateUserId`/`ModifyUserId`，须在 `ApplicationDbContext` 中 `Ignore` 这两个属性。

### 4.3 核心业务规则（Service 层）

#### 台账列表/详情准入

```csharp
r.IsFreightForwarderPayment == true
&& r.Status >= 2   // 已审核
&& r.Status != 4   // 非取消
```

#### 登记付款（`CreatePaymentAsync`）

1. 收款单须已打标且已审核通过  
2. 货代公司：请求体或收款单上须存在；首次付款时回写收款单 `freight_forwarder_company_id`  
3. 货代公司须与收款单已选一致（若收款单已有）  
4. `PaymentAmount > 0` 且 `≤ 待付余额`  
5. 货代收款银行须属于该货代公司且未停用  

#### 更新货代公司（`UpdateReceiptFfCompanyAsync`）

- 已有付款记录时，不可修改收款单上的货代公司

#### 删除货代公司（`SoftDeleteAsync`）

- 被 `financereceipt.freight_forwarder_company_id` 或 `finance_freight_forwarder_payment.FreightForwarderCompanyId` 引用时禁止删除

### 4.4 台账状态码

| 值 | 常量 | 含义 |
|----|------|------|
| 10 | `Pending` | 待付款 |
| 20 | `Partial` | 部分付款 |
| 30 | `Completed` | 付款完成 |

## 九、与现有模块关系

```
收款单 (financereceipt)
  ├── is_freight_forwarder_payment = true
  └── 审核通过 → 货代付款台账（虚拟，按收款单聚合）
        └── finance_freight_forwarder_payment（付款明细，1:N）
              └── 附件 FINANCE_FF_PAYMENT

货代公司 (freight_forwarder_company)
  └── freight_forwarder_company_bank（收款账户，1:N）
```

**不涉及**：

- 收款核销流程变更（货代付款收款仍走正常收款审核）  
- 与采购订单 `FreightForwarderOrderNo`（货代单号）无直接关联  
- 独立付款单（`fin_financepayment`）流程
