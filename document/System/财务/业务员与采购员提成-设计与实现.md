## 1. 入池口径

### 1.1 粒度

一行提成明细 = 一条已完成销售出库行 `stock_out_item`（装箱 `packing.Status = 100` 后落库）。

「销售订单部分 / 采购订单部分」= 该出库行对应的销售明细 / 采购明细数量与 GP，**不是**整张 SO/PO。未出库、未收款完成的明细不入池。

### 1.2 条件（两边相同门槛，归属人不同）

同时满足才入池：

1. **已出库**：存在对应 `stock_out_item`（经装箱完成）。
2. **收款核销完成**：该出库行所属 **销售明细** `sellorderitemextend.receipt_progress_status = 2`（完成）。本系统核销在应收（出库单 × 销售明细），**不**做拣货行拆款。
3. **收款核销延期**：`提成计算日期 − 收款核销日期 > 收款核销延期提成天数`（上海日历日整数差，**严格大于**）。天数是全局整数，业务员与采购员共用，不跟系数版本。填 `0` 时核销当天不入池，次日（差 1 天）才入池。

采购员侧的「收款核销」仍是 **销售侧应收核销**：该 PO 物料已卖出且对应销售明细已收齐。不做进项发票/付款核销门槛。

「基础 GP」不是入池门槛字段：当期入池 GP 达不到该人等级第 1 档达标金额时，取档点数为 0（见 §2.3）。

### 1.3 出库 GP

```text
出库GP = stock_out_item_extend.profit_out_biz_usd
```

与现网出库利润快照同一字段，不另算、不手工调整。单位：**业务 USD**。

### 1.4 归属人

| 角色 | 取值（按优先级） |
| --- | --- |
| 业务员 | `sellorder.sales_user_id` → 否则 `packing.sales_id` / `stock_item.salesperson_id` |
| 采购员 | `purchaseorder.purchase_user_id` → 否则 `stock_item.purchaser_id` |

无归属人：该侧不生成行（另一侧仍可生成）。

### 1.5 入池日

**收款核销日期（入池日）** = 销售明细进度变为完成的那一笔核销：有收款单用 `finance_receipt.ReceiptDate` 的上海日历日；预收池核销无收款单，用核销落库日转上海日。`sellorderitemextend` 不另存完成日，计算时按核销流水回放。

**提成计算日期** = 预计提成用当天动态 Job 的上海日历日；正式锁定用偶数月 2 日锁定日。即时预览（若做）用「今天」上海日。

动态表是否入行看「当前是否满足 §1.2」；锁定按 **入池日** 落入哪个双月账期。延期天数未满足时视为未入池。

反核销导致进度 &lt; 2：次日动态重算时该行消失。 **已锁定行不回滚。**

## 2. 系数梯度

不建「提成方案」。系数按**版本包**维护：头表 `commission_rate_version`（类型 + 版本号 + 状态），行表 `commission_rate`（**一行 = 版本 + 用户等级**），最多 10 档。业务员、采购员版本序列独立。

**生效版仍可改档**；每日预计提成读当时生效版的当时档位。**只有正式提成锁定快照冻结**（含当时 `version_id`、点数），之后改档或切版本都不动锁定行。

维护入口见 [提成系数实施方案](../../实现方案/提成系数实施方案.md)（参数管理 → 提成参数）。增量脚本：`scripts/commission_rate_version_schema.sql`、`scripts/commission_calc_setting_schema.sql`。

全局计算参数表 `commission_calc_setting`（单行）：`receipt_writeoff_delay_days`（0～3650，默认 0）。与生效版本同一页保存。

### 2.1 表

`commission_rate_version`：`id`、`role_type`（1 业务员 / 2 采购员）、`version_no`、`remark`、`status`（1 草稿 / 2 生效 / 3 停用）。唯一 `(role_type, version_no)`；每类型最多一行 `status = 2`。

`commission_rate`：

| 列 | 说明 |
| --- | --- |
| `id` | uuid |
| `version_id` | FK → 版本头 |
| `user_level` | 1～20；唯一 `(version_id, user_level)` |
| `threshold_1`…`threshold_10` | 达标金额（USD，整数），可空 |
| `rate_points_1`…`rate_points_10` | 提成点数，`5.0` = **5%**（0.0～100.0，1 位），可空 |
| `remark` | 可选，最长 200 |

现网原 40 行迁为各类型 **V1 / 初始版本 / 生效**。新建版本从指定旧版复制 20 行，状态为草稿。列表只编辑档位、不增删等级行。

阶梯规则：不必填满 10 档；须从第 1 档起 **连续** 填（不能跳档）；同一档金额与点数成对；已填达标金额 **严格递增**。空档存 NULL。

### 2.2 取级

取 **入池日** 当时等级：`user_level_history` 回放；从未改级则用当前 `user.level`（默认 1）。见用户等级文档。

### 2.3 取档

```text
在该 (生效版本, 等级) 行的已填档中，取 threshold_i ≤ 当期入池 GP 且 i 最大的 rate_points_i
全空，或 GP < 第 1 档金额 → 0
提成 = 出库GP × (points / 100)
```

建议第 1 档达标金额填 **0**，否则低于首档的 GP 点数为 0。

「当前开放双月」= 尚未执行锁定的账期（见 §3.2）。已锁定账期不再用新点数重算。

## 3. 动态表与锁定表

### 3.1 提成动态表

| 项 | 规则 |
| --- | --- |
| 生成 | 每天 **0:00 Asia/Shanghai** 全量重算并 **覆盖** 写入 |
| 范围 | 满足 §1.2、且出库行 + 角色 **尚未进入锁定表** |
| 可变 | 等级、梯度、出库 GP、收款状态变化 → 次日反映 |
| 手工 | 不提供改金额、加减项 |

建议物理表：`commission_dynamic`（销售/采购用 `role` 区分，或分两表同构）。每日 Job **先清空未锁定结果再插入**（或按业务键 upsert），保证幂等。

明细建议列：角色、人员、等级快照、系数、出库 GP、提成、销售单/行、采购单/行、出库单/行、出库日、入池日、计算时间。

列表可按人汇总，下钻到出库行。

### 3.2 双月账期与锁定

偶数月：2 / 4 / 6 / 8 / 10 / 12。

**锁定时刻：** 该月 **2 日 0:00 Asia/Shanghai**。

**锁定窗口：** 上一完整双月（按入池日，上海日历）：

| 锁定触发 | 入池日落入 | 账期标签 |
| --- | --- | --- |
| 2月2日 0:00 | 上年 12/1 ～ 本年 1/31 | `yyyyMM` 用结束月，如 `202601` |
| 4月2日 0:00 | 2/1 ～ 3/31 | `202603` |
| 6月2日 0:00 | 4/1 ～ 5/31 | `202605` |
| … | … | … |
| 12月2日 0:00 | 10/1 ～ 11/30 | `202611` |

2 日当天及之后才入池的行进入 **下一个** 开放双月，不补进已锁账期。

### 3.3 提成锁定表

| 项 | 规则 |
| --- | --- |
| 生成 | 偶数月 2 日 Job：把动态表中入池日属于该窗口的行 **复制** 到 `commission_locked` |
| 快照 | 人员、等级、系数、出库 GP、提成、单号全部冻结 |
| 动态侧 | 这些业务键从动态表删除（或不再重算） |
| 幂等 | 同一 `role + stock_out_item_id` 已锁定则跳过，禁止重复锁定 |
| 不可改 | 无反核销回滚、无改系数重算、无财务加减 |

未到锁定日的行一直留在动态表（含历史很久仍未收款、收款后尚未跨过锁定日的行）。

### 3.4 Job

对齐现有 `BackgroundService`（如邮件同步），**不用** Hangfire。

| Job | Cron（上海） | 行为 |
| --- | --- | --- |
| `CommissionDynamicJob` | 每天 `0 0 * * *` | 重算动态表 |
| `CommissionLockJob` | `0 0 2 2,4,6,8,10,12 *` | 切锁定；当日仍先跑动态再锁定（或锁定 Job 内先重算再切） |

偶数月 2 日：先动态、后锁定，避免漏算前一日入池。支持运维手工触发（同一套幂等）。

时区：与邮件 Job 相同，用 `Asia/Shanghai`，不要用服务器本地时区硬编码。

## 7. 验收要点（实现后写 QA）

落地后再按 [测试规范总纲](../../QA/测试规范总纲.md) 出对照说明。草案级核对：

| # | 场景 | 期望 |
| --- | --- | --- |
| 1 | 已出库、销售明细收款未完成 | 两边都不入动态 |
| 2 | 收款完成后次日 0 点 | 动态出现，提成 = 出库 GP × 当时等级系数 |
| 3 | 只出库一部分销售明细且该明细已收齐 | 仅该部分出库行入池 |
| 4 | 同一出库行有业务员和采购员 | 动态各一行，系数各查各表 |
| 5 | 未配置等级系数 | 提成 = 0，行仍可展示 |
| 6 | 改系数或改等级 | 未锁定行次日变；锁定行不变 |
| 7 | 反核销 | 未锁定行次日消失；锁定行仍在 |
| 8 | 偶数月 2 日 | 上一双月入池行进锁定、动态不再包含 |
| 9 | 3 月出库、4 月 10 日才收款完成 | 入 4–5 月账期，6 月 2 日锁定，不进 4 月 2 日那批 |

金额：出库 GP 与提成按 USD、与快照两位小数对齐；足额入池（收款完成）成功，未完成拒绝入池。本期无核销超额场景（提成不按收款额拆）。
