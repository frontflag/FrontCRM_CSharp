# 收款核销 — 功能要求与实现说明

本文描述 **FrontCRM（CRM.Core / CRM.API / CRM.Web）** 中「收款核销」的业务口径、功能要求、数据模型与代码索引。与 [业务逻辑与数据关系文档](../业务逻辑与数据关系文档.md) §5.2.1、[财务 Phase 1 操作手册](../../EBS/财务/财务Phase1操作手册.md)、[收款记录帮助](../../help/pages/收款记录_MENU_FINANCE_RECEIPT.md) 交叉引用。

---

## 1. 业务定位

收款核销用于将 **已审核/已收款的客户来款**（收款单明细）或 **客户预收池余额**，与 **销售出库产生的应收款** 进行金额匹配，形成可追溯的核销流水。

| 概念 | 说明 |
|------|------|
| **应收款** | 销售出库单头完成后自动生成，一出库单对应一条 `finance_receivable` |
| **收款单明细** | 客户实际来款，审核通过后可参与核销 |
| **预收池** | 客户币别维度预收余额，可核销应收或由原收款明细余额转入 |
| **核销流水** | 每次匹配落库 `finance_receivable_write_off`，为审计与查询的唯一事实来源 |

**与旧版 EBS 差异**：本系统以 `finance_receivable` + `finance_receivable_write_off` 为核销主数据，不再使用独立的「核销单主表 + 核销明细表」模型。

## 2. 功能要求

### 2.1 页面与入口

| 入口 | 路由 | 说明 |
|------|------|------|
| 收款核销工作台 | `/finance/receipt-write-off` | 三栏：待核销客户 → 待核销收款 → 待核销应收 |
| 收款核销流水 | `/finance/receipt-write-off/ledger` | 全量核销流水列表，支持关键字检索 |
| 应收款详情 | `/finance/receivables/:id` | 展示该应收的核销记录 |
| 销售订单明细详情 | 销售订单详情 → 双击明细行 → **收款核销** 页签 | 展示该销售明细关联的全部核销流水 |

菜单路径：**收款管理 → 收款核销**。

### 2.2 收款核销工作台（三栏交互）

1. **左栏 · 待核销客户**
   - 列表展示有待核销收款或待核销应收的客户；
   - 支持关键字搜索、双击/「选中」选定客户；
   - 展示待核销总额（琥珀色强调）、待核销收款笔数、收款日期范围等。

2. **中栏 · 待核销收款**
   - 仅展示当前选中客户下、状态为 **已审核(2)** 或 **已收款(3)** 的收款单明细；
   - 可勾选一条或多条收款明细，展示可核销余额；
   - 未选客户时显示灰斜体占位提示。

3. **右栏 · 待核销应收**
   - 展示当前客户下 `verified_to_be > 0` 的应收款；
   - 「本次核销」列可录入本次分配金额（>0 时绿色加粗）；
   - 支持使用 **预收池** 分配（`advancePoolAllocations`）；
   - 提交前校验：至少一条分配金额 > 0。

4. **提交核销**
   - 一次提交可包含多条「收款明细 → 应收款」分配，以及多条「预收池 → 应收款」分配；
   - 若预收挂单销售单与应收销售单不一致，首次返回需用户确认的 SO 不匹配列表，确认后带 `confirmSoMismatch: true` 重提。

5. **收款余额转预收池**（可选操作）
   - 对仍有可核销余额的收款明细，可将余额转入客户预收池，便于后续纯预收核销。

6. **流水入口**
   - 页头按钮跳转「收款核销流水」页。

### 2.3 收款核销流水

- 数据来源：`finance_receivable_write_off` 关联 `finance_receivable`（及可选 `finance_receipt`）；
- 列：核销时间、来源、收款单号、应收款号、出库单号、销售订单号、客户、PN、品牌、核销金额、操作人、备注；
- 应用应收款 **数据权限**（与应收款列表一致）；
- 支持按关键字过滤（应收号、出库号、销售单号、客户、PN、收款单号等）。

### 2.4 销售订单明细「收款核销」页签

- 页签名称：**收款核销**（原「收款」页签已替换）；
- 内容：该 `sell_order_item_id` 下所有核销流水（与流水页字段一致，无分页，上限 2000 条）；
- 数据接口：`GET .../sell-order-items/{id}/detail-tab-aggregates` 返回字段 `receiptWriteOffs`。

### 2.5 权限

| 操作 | RBAC |
|------|------|
| 查看核销候选、流水、客户汇总 | `finance-receipt.read` |
| 执行核销、余额转预收池 | `finance-receipt.write` |
| 应收款列表/详情（核销对象） | 应收款数据权限 + 财务读权限 |

销售订单明细页签聚合接口使用 `sales-order.read`；其中核销流水仍受应收款数据范围过滤。

## 3. 核心业务规则

### 3.1 应收款生成（核销前置）

- 触发：销售出库单状态为 **已出库(2)** 或 **已完成(4)**，且类型为销售出库；
- 服务：`FinanceReceivableService.TryCreateForStockOutAsync`；
- 金额：`stock_out.total_amount`，若为 0 则 `total_quantity × sell_order_item.price`；
- 初始：`verified_done = 0`，`verified_to_be = amount`，`verification_status = 待核销`；
- 同一 `stock_out_id` 仅一条有效应收（软删除外）。

### 3.2 可核销余额口径

| 对象 | 可核销余额计算 |
|------|----------------|
| 收款明细 | `receipt_convert_amount - verified_amount - advance_pool_amount` |
| 应收款 | `verified_to_be` |
| 预收池 | 客户 + 币别维度 `finance_customer_advance` 余额 |

### 3.3 核销提交校验（`ApplyWriteOffAsync`）

1. 至少一条有效分配（收款明细或预收池）；
2. 同一批次不可跨 **多个客户**；
3. 使用收款明细时：收款单须 **已审核或已收款**；收款币别须与应收币别一致；
4. 每条分配：金额 > 0，且 ≤ 对应收款明细/应收剩余可核销额；
5. 预收池分配总额 ≤ 客户该币别预收余额；
6. SO 不匹配时须 `confirmSoMismatch`（见 §3.5）。

### 3.4 核销落库与回写

每笔成功分配：

1. 写入 `finance_receivable_write_off`（`write_off_source`：10=收款明细，20=预收池）；
2. 累加 `finance_receipt_item.verified_amount`（来源为收款明细时）；
3. 累加 `finance_receivable.verified_done`，重算 `verified_to_be` 与 `verification_status`；
4. 预收池来源时 additionally 调用 `FinanceCustomerAdvanceService.ApplyFromPoolAsync`；
5. 对涉及的 `sell_order_item_id` 调用 `SellOrderItemExtendSyncService.RecalculateAsync`。

### 3.5 预收与销售单不匹配确认

当收款明细的预收挂单 `advance_sell_order_id`（或 `sell_order_id`）与应收款的 `sell_order_id` 不一致，或预收池核销指定了不同的 `advanceSellOrderId` 时，收集 `soMismatches` 列表。用户确认后继续核销，备注可记「SO不匹配已确认」。

### 3.6 销售明细「收款状态」与单条应收核销的关系（重要）

以下两个指标 **不可混用**：

| 展示位置 | 口径 | 完成条件 |
|----------|------|----------|
| **应收款详情** | 单条 `finance_receivable` | `verified_to_be = 0` → 该出库批次应收已核销完毕 |
| **销售订单明细 · 收款状态** | 整行 `sellorderitemextend` | `receipt_amount_finish`（该行所有应收 `verified_done` 之和）相对 **销售行全额** `qty × price` |

因此：**一条应收款全部核销 ≠ 销售明细收款完成**。一条销售明细可多次出库、产生多条应收；仅当累计已核销金额达到销售行全额时，`ReceiptProgressStatus` 才为「收款完成(2)」。

实现：`SellOrderItemExtendSyncService` 中 `ReceiptAmount = lineQty × price`，`ReceiptAmountFinish = Σ receivable.verified_done`。

## 4. 数据模型

### 4.1 主表

| 表 | 说明 |
|----|------|
| `finance_receivable` | 应收款（出库批次） |
| `finance_receivable_write_off` | 核销流水（审计主表） |
| `finance_receipt` / `finance_receipt_item` | 收款单及明细 |
| `finance_customer_advance` / `finance_customer_advance_ledger` | 预收池及台账 |

### 4.2 核销流水关键字段

| 字段 | 说明 |
|------|------|
| `finance_receivable_id` | 必填，关联应收 |
| `finance_receipt_id` / `finance_receipt_item_id` | 来源为收款明细时填写 |
| `write_off_source` | 10 收款明细；20 预收池 |
| `amount` | 本次核销金额 |
| `operator_user_id` | 操作人 |
| `create_time` | 核销时间 |

### 4.3 编码

应收款流水号：模块码 `FinanceReceivable`，前缀 `ARV`（如 `ARV0000A`）。

| 方法 | 路径 | 权限 | 说明 |
|------|------|------|------|

|------|------|------|
| GET | `/api/v1/sales-orders/{id}/sell-order-items/{lineId}/detail-tab-aggregates` | 含 `receiptWriteOffs` |

## 7. 典型业务场景

### 7.1 单次出库、一次收款、一次核销

出库完成 → 生成应收 ARV → 客户来款录入收款单并审核 → 收款核销页选定客户 → 勾选收款明细与应收 → 填写本次核销金额 → 提交。应收详情显示「已核销」；若销售行仅此一批出库且金额等于行全额，则销售明细收款状态为「收款完成」。

### 7.2 分批出库、分次核销

同一销售明细多次出库 → 多条应收。可对同一收款单分多次核销到不同应收，或多次收款分别核销。销售明细收款状态按 **行全额** 与 **累计 verified_done** 计算，在全部出库应收均核销且累计达到行全额前，显示「部分收款」。

### 7.3 预收池核销

客户已有预收余额 → 在右栏对应应收填写预收分配金额 → 提交。流水 `write_off_source = 20`，无收款单号。

### 7.4 查询与追溯

- 财务：核销流水页按客户/单号检索；
- 业务：销售订单 → 明细详情 → 收款核销页签查看该 PN 行全部核销记录；
- 财务：应收款详情查看针对该出库批次的核销明细。

## 8. 测试与回归要点

1. 核销后 `finance_receivable_write_off` 行数与金额正确；
2. 收款明细 `verified_amount`、应收 `verified_done/verified_to_be` 同步；
3. 销售明细 `ReceiptProgressStatus` 在部分/全部核销场景下符合 §3.6 口径；
4. SO 不匹配时首次返回 `requiresSoMismatchConfirm`，确认后可成功；
5. 无 `finance-receipt.write` 时 POST 核销 403；
6. 销售明细页签 `receiptWriteOffs` 与流水页同源数据一致。
