## 1. 业务定位

### 1.1 目的

给财务 / 业务员一张 **按客户、按单一币别、按期间** 的客户沟通件：期初、本期出库应收、本期已核销收款、期末滚存余额。用于对账、催收、打印给客户确认。

**不是** 新的应收主数据，**不替代** `/finance/receivables` 台账与看板。

### 1.2 与现有菜单的关系

| 页面 | 粒度 | 用途 |
|------|------|------|
| 应收款 `/finance/receivables` | 一条出库应收一行 | 财务台账、核销状态、导出 |
| 客户对账单聚合列表 | 一个客户 + 一种币一行 | 找「对谁、对哪种币」出单 |
| 客户对账单详情 | 该客户该币 + 期间 | 列表规范工作页 + 预览报表 |

入口：侧栏 **收款管理 → 客户对账单**（组内最后一项）；应收款列表 **页面右上角**（与「导出」并列）也可进，样式对齐需求明细「进入报价桌面」。看板模式按钮仍在搜索栏。一期 **不** 新权限码。

### 1.3 定稿决策

| # | 议题 | 结论 |
|---|------|------|
| 1 | 应收增加用哪张单 | **出库应收** `finance_receivable`，不用销项发票 |
| 2 | 是否落库 | **否**。每次按当日数据重算；无对账单号、无草稿/已发出/已确认 |
| 3 | 多币别 | **一张单一种币**；多币客户在聚合列表多行 |
| 4 | 与应收菜单 | 应收列表下一层，不替换 |
| 5 | 入口交互 | 按钮 → 聚合列表 → 点行进详情（不是条件弹窗直接预览） |
| 6 | 未核销来款 / 预收池 | **不上单**（期末与应收待核销合计一致） |
| 7 | 入期间日期 | 增加：出库日；已收：核销 `CreateTime` |
| 8 | 明细粒度 | **一条应收一行**；单据号 = 应收单号 |
| 9 | 打印 | 中/英切换 + 打印 + 导出 PDF |
| 10 | 开票清单 / 签章 / 账龄截止 | 开票清单一期不做；页脚备注 + 签章区要；账龄截止默认可改，只展示 |
| 11 | 已结清客户+币 | **列表要出**（待核销 0）；可筛「仅待核销」 |
| 12 | 详情下部 | **对账流水**（期初 + 本期增加 + 本期已收 + 滚余额），不是再列一遍应收台账 |

## 2. 页面与路由

权限与应收列表相同：`finance-receipt.read`；数据范围 `CanAccessFinanceReceivable` / `ApplyFinanceReceivableListDataScopeAsync`（与列表可见应收一致）。一期 **不** 新权限码。

| 路由 | 路由名 | 说明 |
|------|--------|------|
| `/finance/receivable-statements` | `FinanceReceivableStatementList` | 客户+币别聚合列表 |
| `/finance/receivable-statements/:customerId/:currency` | `FinanceReceivableStatementDetail` | 详情工作页（业务列表规范）；右上角「预览报表」 |
| `/finance/receivable-statements/:customerId/:currency/preview` | `FinanceReceivableStatementPreview` | 报表预览（中/英、打印、导出 PDF） |

查询参数（详情）：

| 参数 | 默认 | 说明 |
|------|------|------|
| `from` | 上一个自然月 1 日 | 对账期间起（含），`YYYY-MM-DD` |
| `to` | 上一个自然月最后一日 | 对账期间止（含） |
| `aging` | 打开当天（本地日） | 账龄截止，只展示 |
| `lang` | `zh` | 打印件语言 `zh` / `en` |

改期间或账龄截止后更新 URL，便于刷新 / 分享（仍是即时重算，不是某版快照）。

返回：详情回聚合列表；聚合列表回 `/finance/receivables`（保留原列表筛选若可）。

## 3. 聚合列表

### 3.1 数据范围

当前用户数据权限内、`finance_receivable.is_deleted = false` 的全部应收，按 `customer_id + currency` 聚合。

- 历史上有过应收即出一行，**含已全部核销**（`verified_to_be` 合计为 0）。
- 作废 / 软删应收 **不** 入组、不入合计。
- **不** 按对账期间过滤（否则结清客户无法打开上月对账单）。

### 3.2 列（建议）

金额遵循 [金额与币别代码显示范式](../../PRD/规范/UI规范/金额与币别代码显示范式.md)（数字 + 空格 + 三位币别字母）。列表规范：列设置、列宽持久化、行高密度。

| 列 | 口径 |
|----|------|
| 客户编号 | 客户主数据 |
| 客户中文名 | `OfficialName` |
| 客户英文名 | `EnglishOfficialName` |
| 币别 | 该行聚合币 |
| 应收笔数 | 未删应收条数 |
| 应收总额 | Σ `Amount` |
| 已核销 | Σ `VerifiedDone` |
| 待核销 | Σ `VerifiedToBe`（结清为 0） |
| 最近出库日 | 组内 `StockOutDate`（空则 `CreateTime`）最大 |
| 业务员 | 客户档案业务员（无则应收上 `SalesUserId`） |

单击或双击一行进入详情（带该 `customerId`、`currency`，期间用默认上月）。行末 **操作列**（列头 `<`/`>` 展开收起，收起为 `...`）含 **详情**，与单击进详情同一路由。

### 3.3 筛选

| 条件 | 说明 |
|------|------|
| 关键词 | 客户编号 / 中文名 / 英文名 / 业务员账号（忽略大小写） |
| 仅待核销 | 勾选后只保留 Σ `VerifiedToBe` > 0 |
| 币别 | 可选；不选则全部 |

默认：关键词空、**不**勾「仅待核销」、币别不限。排序：客户中文名 → 币别。

看板模式下从应收列表点进来，不预选行。

## 4. 详情页（工作页）

工作页，不是不可改的纸面。页面 chrome 对齐 [业务列表规范](../../PRD/规范/UI规范/业务列表规范.md) 与 [列表搜索栏规范](../../PRD/规范/UI规范/列表搜索栏规范.md)：`crm-biz-list-page` 页眉、搜索栏（期间起/止 + 账龄截止 + 查询/重置）、`CrmDataTable` 流水、底栏列设置与行高密度。流水滚余额须整表阅读，**不接分页**（规范 §4.1 详情内嵌/少量固定行豁免）。打印 / PDF 用同一套计算结果套对账单版式（§6）。

### 4.1 上部：客户基础

取自客户主数据 + 默认联系人（`customercontactinfo.IsMain`；无则空）。**只读、现取**，不按期间冻结。

| 项 | 来源 |
|----|------|
| 客户名称 | `OfficialName`、`EnglishOfficialName`（工作页不展示客户编号） |
| 联系人 | 默认联系人 `CName`/`EName` |
| 业务员 | 客户 `SalesUserId`（紧挨联系人之后） |
| 电话 | 默认联系人电话，优先 `Tel` 否则 `Mobile` |
| 账期 | `Payment`，展示「账期 N 天」（空则按主数据默认展示约定，与客户页一致） |
| 信用额度 | `CreditLine`；额度币别与对账单币可能不同，按主数据展示并标明来自客户档案 |

无客户查看权限时：仅编号 + 业务员（对齐客户页签裁剪），名称可显示应收快照 `customer_name`。

### 4.2 中部：对账信息

可改：**对账期间**、**账龄截止**。改后点搜索栏「查询」重拉详情 API，KPI 与流水一起刷新。「重置」回到默认上月期间与当天账龄截止。

展示（该客户 + 该币 + 该期间）：

| 项 | 公式（见 §5） |
|----|----------------|
| 币别 | 路径上的一种币 |
| 生成日期 | 打开/重算当天（本地日）；打印件同步 |
| 账龄截止 | 条件值，一期只展示，不另出未清发票附件 |
| 期初应收余额 | `Opening` |
| 本期应收增加 | `PeriodIncrease` |
| 本期已收 | `PeriodReceived` |
| 期末应收余额 | `Opening + PeriodIncrease − PeriodReceived` |

四个金额必须等于下部流水：期初行余额、本期增加列合计、本期已收列合计、最后一行余额。

期间默认：若今天为 `2026-09-07`，则 `2026-08-01`～`2026-08-31`。起 > 止时拒绝并提示。

### 4.3 下部：对账流水

列：

| 列 | 说明 |
|----|------|
| 日期 | 业务日（§5.1） |
| 单据号 | 期初空；增加=应收单号；已收=收款单号或「预收」 |
| 摘要 | 见 §4.4 |
| 应收增加 | 出库应收金额；退货类一期没有，不出现负数增加 |
| 已收/扣减 | 核销金额 |
| 余额 | 滚存 |

行序：期初行 → 其余按日期升序，同日：先增加后已收，再按单据号。

行类型：

1. **期初**：日期=期间起；摘要「期初应收余额」；增加/已收空；余额=`Opening`。`Opening=0` 仍出这一行。
2. **应收增加**：期间内出库应收，一条应收一行。
3. **已收/扣减**：期间内有效核销流水一行（来源 10 收款明细 / 20 预收池）。

单据号、应收单号可点进 `/finance/receivables/:id`；收款单号可点进收款详情（有权限时）。无权限则纯文本。

### 4.4 摘要

| 行 | 摘要 |
|----|------|
| 期初 | 期初应收余额 |
| 增加 | `{出库单号} {型号}`（型号空则只出库单号） |
| 已收（来源 10） | 收款核销 {收款单号} |
| 已收（来源 20） | 预收核销 |

## 5. 余额与期间口径

只使用未删除应收、未删除核销（`is_deleted = false`）。反核销软删的流水不参与。

### 5.1 业务日

| 事件 | 业务日 |
|------|--------|
| 应收增加 | `stock_out_date` 的日期部分；空则应收 `CreateTime` 转系统默认时区（与应收列表出库日展示一致）后取日 |
| 已收/扣减 | 核销 `CreateTime` 同上转时区后取日（核销表无业务日期） |

期间 `[from, to]` **闭区间**。未核销来款、预收池余额、销项发票匹配、红字/折让/退货 **不** 产生行，也 **不** 改四个合计。

### 5.2 公式

对固定 `customerId + currency`：

```text
Opening        = Σ AR.Amount（业务日 < from）
               − Σ WO.Amount（业务日 < from）

PeriodIncrease = Σ AR.Amount（from ≤ 业务日 ≤ to）

PeriodReceived = Σ WO.Amount（from ≤ 业务日 ≤ to）

Ending         = Opening + PeriodIncrease − PeriodReceived
```

`WO` 只统计挂在上述未删应收上的未删核销。

滚余额：

```text
余额₀ = Opening
余额ᵢ = 余额ᵢ₋₁ + 行ᵢ.应收增加 − 行ᵢ.已收
```

恒等式：`Ending` = 最后一行余额 = 该客户该币全部未删应收的 `VerifiedToBe` 合计，**当且仅当** 期间止日 ≥ 所有事件业务日（「截至今天」）。任意历史期间的期末是「截止 to 日」的账面余额，不必等于列表当前待核销。

### 5.3 数值例

出库：7/20 应收 100；8/05 应收 50。核销：8/12 核 40；9/03 核 30。期间 8/01–8/31。

| 项 | 值 |
|----|-----|
| 期初 | 100 |
| 本期增加 | 50 |
| 本期已收 | 40 |
| 期末 | 110 |

9 月核销 30 不进 8 月。未核销来款即使 8 月已确认，也不上单。

### 5.4 与应收列表对齐（核对用）

- 聚合列表「待核销」= 该客户该币当前 Σ `VerifiedToBe`。
- 详情若 `to` ≥ 今天（本地日），期末应等于该合计。
- 详情下部增加行，应能在应收列表用客户+币+出库日筛到同一批单号与金额。

## 6. 打印与 PDF

详情右上角 **预览报表** 进入独立预览页。预览工具栏（不进打印）：**返回**、**中文 / 英文**、**打印**、**导出 PDF**。无邮件发送、无对账单号。

版式对齐讨论用样张，数据按 §4～§5：

- 标题：客户对账单 / Customer Statement
- 生成日期、币别、对账期间、账龄截止、账期、信用额度、客户与联系人
- 三数或四数摘要：期初、本期增加、期末（本期已收可放摘要或只在表尾）
- 流水表（颜色：已收绿、期末/负向红，与样张一致即可）
- 表尾：本期增加合计、本期已收合计、期末余额
- 备注（静态，中英各一套），例如：本单仅供对账、不是收款凭证；异议请在 N 个工作日内提出
- 供方确认 / 客户确认签章区

打印件 chrome 对齐客户报价单报表：`po-doc--inv-v2` 藏青抬头、A4 纸面、区块标题、表格与签章框（`FinanceReceivableStatementReportBody.vue`）。页面壳层复用 `po-report-page` + `po-order-report-print`。**不要** 复制报价邮件调试逻辑。

金额在工作页列表遵循币别字母范式；打印件可用当地习惯千分位，同一币别不必每格重复币种符号，页眉已标明币别即可。

## 7. API（建议，实现时落地）

基路径 `/api/v1/finance/receivable-statements`。权限：`finance-receipt.read`。一律现算，无写接口。

### 7.1 聚合列表

`GET /api/v1/finance/receivable-statements?keyword=&onlyOpen=&currency=&page=&pageSize=`

`onlyOpen=true` 时仅 Σ `VerifiedToBe` > 0。分页上限对齐应收列表（最大 2000）。

行字段：`customerId`、`customerCode`、`customerName`、`customerEnglishName`、`currency`、`receivableCount`、`amountTotal`、`verifiedDone`、`verifiedToBe`、`latestStockOutDate`、`salesUserId`、`salesUserName`。

### 7.2 详情

`GET /api/v1/finance/receivable-statements/{customerId}/{currency}?from=&to=&aging=`

- `from`/`to` 必填，闭区间。非法期间 400。
- 该客户该币在权限内 **零条应收**：仍 200，期初/增减为 0，流水仅期初行（便于结清或误点）。若客户不存在：404。
- 无权看到该客户下任何应收：404（不泄露客户是否有账）。

响应：

- `customer`：§4.1 快照
- `statement`：期间、生成日期、账龄截止、`opening`、`periodIncrease`、`periodReceived`、`ending`、`currency`
- `lines[]`：`lineType`（`opening` / `increase` / `receipt`）、`date`、`docNo`、`summary`、`increaseAmount`、`receivedAmount`、`balance`、`receivableId`、`stockOutId`、`receiptId`、`writeOffId`

服务建议独立 `FinanceReceivableStatementService`（或 `FinanceReceivableListQuery` 旁路查询），复用应收数据范围，不要复用收款核销左栏 `GetWriteOffCustomerSummariesAsync`（那是待核销 **来款** 客户）。

## 10. 一期明确不做

- 落库、对账单号、发出/确认状态机、邮件发送
- 未核销来款、预收池余额上单
- 销项发票作增加行；开票清单附件
- 折让、贷项通知单、退货减应收
- 新权限码（沿用 `finance-receipt.read`）
- 跨币别一张单、汇率折算合计

二期若做「税务对账单」（按发票），须与本现金对账单分开，不得改 §5 公式。
