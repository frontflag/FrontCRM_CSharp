## 1. 业务口径

管理员纠错或强制删除进项发票前，须先撤销该票对入库明细的核销匹配。

```text
已核销的进项发票
  → ① 反核销（软删本票全部有效流水，重算余额）
  → ② 强制删除（SYS_ADMIN / SYS_MANAGER + 确认发票号码）
```

| 项 | 口径 |
|---|---|
| 粒度 | **整票**：撤销该发票全部有效核销流水 |
| 流水 | **软删** `finance_purchase_invoice_write_off.is_deleted = true`（EF `HasQueryFilter` 已过滤） |
| 开票 / 认证 | **不变** |
| 已冲红 | **拒绝**反核销 |
| 付款单 | **不**反核销付款；仅按剩余流水重算发票 `PaymentDone` / `PaymentToBe` / `PaymentStatus`（相对 `VerifiedDone`） |
| 入库已删 | 反核销仍成功；跳过缺失的入库明细 extend / 头缓存 |
| 确认单号 | `confirmBillCode` 须等于 **发票单号 `InvoiceCode` 或 发票号码 `InvoiceNo`**（Ordinal） |

**反核销 ≠ 冲红 / 取消认证。** 核销桌面仍只做正向提交。

---

## 2. 前置条件

| # | 规则 |
|---|------|
| P1 | 进项发票存在 |
| P2 | `confirmBillCode` 与 `InvoiceCode` 或 `InvoiceNo` 完全一致 |
| P3 | `RedInvoiceStatus != 1` |
| P4 | 至少一笔有效核销流水，否则「当前进项发票无需反核销」 |
| P5 | 财务数据可写（非只读） |

---

## 3. API 与权限

| 项 | 值 |
|----|-----|
| 方法 | `POST /api/v1/finance/purchase-invoices/{id}/reverse-verification` |
| Body | `{ "confirmBillCode": "INVI…" }`（发票单号或发票号码） |
| 权限 | `finance-purchase-invoice.write` |
| 成功 | 200，`data` 为回滚后的进项发票 |
| 典型错误 | 400 未填确认号 / 单号不匹配 / 无需反核销；409 已冲红 |

---

## 4. 执行效果

1. 软删本票全部有效 `finance_purchase_invoice_write_off`。
2. 按剩余有效流水重算发票 `VerifiedDone` / `VerifiedToBe` / `VerificationStatus`。
3. 按入库明细剩余流水重算 `stock_in_item_extend.InvoiceMatch*`；刷新 `stock_in_extend` 头缓存（入库单已删则跳过）。
4. 波及的采购明细调用 `IPurchaseOrderItemExtendSyncService.RecalculateAsync`。
5. `FinancePurchaseInvoicePaymentSyncService.RecalculateForInvoiceAsync` 回写付款缓存。
6. `log_operation`，`ActionType=进项发票反核销`。

```text
明细 InvoiceMatchToBe = Amount - Σ(有效流水 where stock_in_item_id)
发票 VerifiedToBe     = InvoiceAmount - Σ(有效流水 where invoice_id)
付款 PaymentToBe      = max(0, VerifiedDone - PaymentDone)
```

---

## 5. 强制删除守卫（配套）

| 被删节点 | 有有效进项核销流水时 |
|---|---|
| 进项发票 | 拒绝，提示须先反核销（另仍拦已认证 / 已冲红） |
| 入库单（普通删除与强制删除） | 拒绝，文案列出 **进项发票单号**（最多 5 个） |

入库强制删除仍保留原「存在未软删库存明细」拦截。
