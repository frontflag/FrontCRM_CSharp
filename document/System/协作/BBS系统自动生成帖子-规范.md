# BBS 系统自动生成帖子 — 规范

> **状态：** 已实现（操作说明《论坛如何使用》）  
> **设计对照：** [BBS论坛-设计与实现](./BBS论坛-设计与实现.md) §5.1  
> **实施方案：** [BBS论坛-实施方案](../../实现方案/BBS论坛-实施方案.md)  
> **帮助（业务用户）：** [论坛](../../../help/pages/论坛_MENU_BBS.md)  
> **适用：** 由 API 启动幂等写入、并同步到各环境的论坛帖。页面上由人新发的帖子不走本规范。

本文件只约定这类帖子的注意事项。表结构、接口与代码路径见设计文档。

## 1. 通用注意事项

| 项 | 要求 |
|----|------|
| 同步 | 正文放在 `CRM.Infrastructure/Bbs/SystemPosts/*.md`，随 API 发布。启动时：库里没有的系统帖新建；正文与文件不一致的才更新；未变化的不写。浏览数、回复数保留。删掉文件不会删除已发布的帖。`-PublishAllBbsPosts` 才在当次启动按文件重写全部系统帖，标记用完即删 |
| 作者 | 展示为「系统」 |
| 页面锁定 | 任何人（含系统管理员）不能在页面上编辑、关闭、打开、置顶、取消置顶、删除或上传媒体。可以回复 |
| 正文格式 | 存 Markdown。详情页必须渲染成标题、段落和图片，不能把 `#`、`**`、`![](...)` 当原文显示 |
| 主段落间隔 | 每个 `#` 标题上方多空一行。 |
| 配图 | 放在 `CRM.Web/public/bbs-guide/`，访问路径 `/bbs-guide/`。全量包不包含该目录。发布时先保留服务器上的旧图，再只上传新建或内容变化的文件。`-PublishAllBbsGuide` 才全部重传。不要用各库上传文件 |
| 配图文件 | 须是浏览器能直接打开的 UTF-8 文本（SVG 内中文不能写坏） |
| 页面链接 | 正文提到本系统页面时，写成该页在菜单或标题上的名称，用户点击名称即可打开。不要把 `http://` 或 `/commission/pool` 这类网址、路径直接写给读者看。Markdown 写成 `[页面名称](站内路径)`，路径只放在链接地址里。若同一名称在不同角色登录后打开的页面不一致，只写名称，不提供点击跳转 |

新建「操作说明」由运维 Bot 完成，不改 C#。写之前先读本文件，正文按第 4 节逐条执行：

1. 在 `CRM.Infrastructure/Bbs/SystemPosts/` 新增一篇 Markdown。文件头固定为 `id`、`title`、`board: ops-guide`、`top`。`id` 以 `bbs-sys-` 开头，只用小写字母、数字和连字符。
2. 正文遵守本规范，尤其是第 4 节。配图放在 `CRM.Web/public/bbs-guide/`，用 `/bbs-guide/...` 引用。
3. 在本文件第 2 节补上这篇的正文范围。

发布仍用现有命令。默认只写入有变化的帖、只上传有变化的图。

## 2. 「操作说明」板块

当前帖：《论坛如何使用》（主键 `bbs-sys-ops-guide`），置顶。

正文只讲普通用户怎么用论坛：

- 从哪里进入
- 板块用来筛选帖子
- 发帖与匿名
- 看帖和回复，以及正文下方的赞和踩（含配图）
- 发起投票、投票规则，以及如何查看投票结果（含配图）

**正文不写管理员的板块操作（新建、排序、版主、删板块）。**

可以保留的事实说明（不是操作步骤）：「系统更新 / 操作说明」由管理员发布；匿名发帖时，版主和管理员仍能看到真实姓名。

已撤回、启动时软删、不再发布：主键 `bbs-sys-ops-manual`（标题「操作说明」）。

《如何查看提成》（主键 `bbs-sys-commission-guide`），置顶。改写任务见 [如何查看提成-改写说明](./如何查看提成-改写说明.md)。

正文给业务员和采购员：

- 业务提成和采购提成怎么算
- 业务员、采购员怎么查看和核对
- 提成池现在就能用
- 预计提成和正式提成按已对业务员和采购员开放来写
- 计划提成的用途和设置方法

## 3. 详情页（所有帖子）

赞和踩与正文隔开两行空白，不要和正文混在一起。本节适用于每一篇帖子的详情页，不限于系统自动生成的帖。

---

## 4. 正文写法（运维 Bot 写帖时逐条执行）

适用第 2 节每一篇「操作说明」。写完后用本节清单自检，未满足的不要发布。

1. 一篇只讲一件事。一节只写一个操作。节标题用页面上的任务名，例如「从哪里进入」「怎么查看」。
2. 每一节按这个顺序写：点哪里（菜单、按钮用粗体，用词与界面一致）→ 紧跟一张图 → 图下只写这一步的结果或例外。图和说明之间不插入下一步的规则。
3. 一张图只画一个页面，并给出一行能看懂的示例（金额、点数、状态用具体值）。不要把整页宽表缩进图里，列太多就拆成下一张图。图内不写「示意图」「不是截图」「不在这里写死」这类说明。
4. 开头两句写明给谁、打开后先做什么。计算规则、锁定日、梯度放在读者已经知道去哪一页之后，或单独成节。第一屏是操作路径。
5. 一段只有一个结论。成对概念（例如预计 / 正式）先用一句话写清差别，再给入口链接。同一事实只写一次，图上已有的列不要在下一段再列一遍。
6. 文末写一句：使用上有疑问，直接在下面回复。
7. 正文不写管理员的板块操作（新建、排序、版主、删板块）。范围以第 2 节该篇的条目为准，不自行加内容。
8. 提到本系统页面时写成网页名称，并做成点击跳转；正文里不出现网址或路径。同一个名称在不同角色登录后打开的页面不一致时，只写名称，不提供跳转。
