## 1. 目标与非目标

### 1.1 目标

了解本站用户如何使用系统：会话、页面、时长、操作、异常与 API 性能；并提供运维侧统计看板。

### 1.2 非目标

- 不替代登录日志 / 操作审计 / 系统错误台  
- 不采集请求体、响应体、Token、密码、表单逐字输入  
- 本期不做跨客户站汇聚  
- 不做用户级「关闭埋点」开关

## 2. 事件模型

### 2.1 统一信封

| 字段 | 说明 |
|------|------|
| `eventId` | 客户端 UUID，上报幂等 |
| `eventType` | `session` / `page` / `engagement` / `action` / `result` / `error` / `perf` |
| `eventName` | 如 `session_start`、`page_view`、`btn_click`、`api_timing` |
| `occurredAt` | 客户端时间（ISO） |
| `receivedAt` | 服务端入库时间 |
| `sessionId` | 会话 Id |
| `userId` / `userName` | 当前登录用户 |
| `pageKey` | 路由模板键（见 §2.3） |
| `routePath` | 可选，实际 path（含 Id 时用于明细，**聚合不用**） |
| `client` | browser / os / deviceType / screenW / screenH / userAgent 摘要 |
| `payload` | JSON，按类型扩展 |

### 2.2 事件类型与 payload

| eventType | eventName | payload 要点 |
|-----------|-----------|--------------|
| `session` | `session_start` / `session_end` | reason: `login` / `idle_30m` / `logout` / `tab_close` |
| `page` | `page_view` / `page_leave` | 进入/离开；PV 靠 view 计数 |
| `engagement` | `page_timing`（可在 leave 时一条汇总） | `visibleMs`、`activeMs` |
| `action` | `btn_click` / `menu_click` 等 | `actionId`、展示文案（可选） |
| `result` | `form_submit` 等 | `outcome`: `success` / `validation_fail` / `api_fail` |
| `error` | `js_error` / `api_error` | message、stack 截断；API：status、path 模板、durationMs、可选 `errorId`。**`api_error` 仅系统异常**（超时/断网、5xx），不含业务 404/400 等 |
| `perf` | `api_timing` | method、path 模板、durationMs、status（全量；看板「失败」列按系统异常口径汇总） |

### 2.3 `pageKey` 约定

- 使用路由 **name** 或 path **模板**（如 `biz.customers.detail` / `/biz/customers/:id`）  
- 聚合「高频页面」只按 `pageKey`，避免详情 Id 打散  
- 实现期维护「路由 → pageKey」映射（与 `routes.ts` 对齐）

### 2.4 Session 规则

- 登录成功生成 `sessionId`，发 `session_start`  
- **30 分钟**无埋点活动（含无 API/页面/操作上报）→ 视为结束，下次操作新开会话  
- 登出、关页（`sendBeacon`）→ `session_end`  
- 登录/登出时间仍可由登录日志提供粗粒度对照；**分析以 Session 为准**

### 2.5 页面时长（双轨）

| 指标 | 规则 |
|------|------|
| `visibleMs` | `document.visibilityState === 'visible'` 时累计（含「开着页打电话」） |
| `activeMs` | 可见且 **近 5 分钟内**有点击/滚动/键盘 |

两者都落库；看板默认可展示 visible，分析时可筛 active。

## 3. 采集范围与禁止项

### 3.1 采集

- 客户端信息、Session、页面 PV/离开、双轨时长  
- **按钮/菜单较全覆盖**（声明式 `data-track` / 封装组件 + 关键路径补点；上线验收按模块清单勾选）  
- 表单结果（成功 / 校验失败 / API 失败）  
- JS 错误；API **全量**耗时；**系统异常**失败（5xx / 超时），业务查无（404）等不记失败  
- 强制、不可关闭  

### 3.2 禁止采集

- Body、Authorization、Cookie 全文、密码  
- 大段表格数据、附件内容  
- 埋点用于聚合的键使用 path **模板**，不把业务密文当维度  

### 3.3 API 排除名单（代码常量）

前端 axios 拦截器维护常量数组，例如：

- 埋点上报接口自身（防自激）  
- 已知轮询/心跳类（实现时对照：登录扫码轮询、微信绑定轮询、RFQ 列表自动刷新等）  

匹配前缀或模板则 **不写** `api_timing` / 一般也不写轮询类 `api_error`（5xx 是否记可在实现清单中默认「排除名单内一律不记」以降噪）。

## 4. 上报方式

| 项 | 定稿 / 拟默认 |
|----|----------------|
| 缓冲 | 前端内存队列 |
| 触发 | **每 30s** 或 **满 20 条** |
| 关页 | `sendBeacon` / `fetch keepalive` 冲刷 |
| 失败重试 | 短退避；可选 `sessionStorage` 小容量暂存 |
| 后端 | 批量入库；校验登录态；按 `eventId` 幂等 |
| 字段 | 瘦事件，单条限制大小（实现期定上限，如 8KB） |
| 并发 | 明细先提交；日汇总按键排序 upsert + 事务内重试（防 `40P01` 死锁）；汇总最终失败不拖垮上报（记日志，明细已入库） |

## 5. 存储与清理

| 对象 | 说明 |
|------|------|
| `telemetry_event`（名可定） | 明细事件，**保留 90 天** |
| `telemetry_daily_*` 汇总表 | 按天聚合 PV、action、API 耗时；保留更长（拟默认 400 天） |
| 清理 | 定时 Job：删/归档超过 90 天的明细 |

与 `log_login` / `log_operation` / `sys_error_log` **分表**，不混写。

---

## 6. 与系统错误的关系

| | `sys_error_log` | 埋点 `api_error` / `api_timing` |
|--|-----------------|----------------------------------|
| 来源 | 服务端未处理异常、关键 DbUpdate 失败等 | 前端所见请求结果与耗时 |
| 用户提示 | Toast + `E-{id}` | 不直接替代错误台 |
| 关联 | 若响应含 `errorId`，埋点 **可选附带** | 便于对照，非外键强绑 |

## 7. 统计看板（埋点分析）

菜单：**运维管理 → 埋点分析**（侧栏整组**仅系统管理员**可见。权限码 `biz.telemetry.analytics` 仍控制直链/API）。

| 看板 | 指标 |
|------|------|
| 高频打开页面 | `page_view` 按 `pageKey` |
| 高频操作 | `action` 按 `actionId` + `pageKey` |
| API 耗时 | 按 path 模板：平均、最长；建议附 P95、次数 |

可附：日活、人均会话数、会话时长（visible）分布——一期有余力则做，否则二期。

数据源优先读 **日汇总表**；支持选日期范围。

## 10. 验收口径（一期）

1. 登录后产生 session；30 分钟无操作后再操作得到新 `sessionId`  
2. 打开/离开业务页有 PV；详情页聚合不按具体 Id 打散  
3. 页面离开时有 `visibleMs` / `activeMs`  
4. 各模块主要按钮与菜单可在分析中按 `actionId` 统计（覆盖度按验收清单）  
5. API 全量出现在耗时统计；排除名单内接口不出现  
6. 校验失败 / API 失败有 result 或 error 事件  
7. 系统管理员：运维管理 → 埋点分析 三块看板可用；非管理员侧栏无「运维管理」；无 `biz.telemetry.analytics` 时直链/API 拒绝  
8. 明细超过 90 天可被清理；采集不可由用户关闭
