**状态：** 已上线  
**页面：** 列表 `/stocking-purchase-items`；只读详情 `/stocking-purchase-items/:id`

## 1. 功能需求

### 1.1 目的

汇总公司全部 **备货采购** 订单明细，供采购部职员、采购助理、采购运营查阅备货情况（物料型号、采购数量、采购单价、备货可用库存）。本页是查阅入口，**不替代**「采购订单 / 采购订单明细」上的跟单作业。

### 1.2 数据

- 仅采购订单头 **订单类型 = 备货采购**（`Type = 2`）的明细行。
- 客单采购、样品采购不出现。
- **本页看全部备货行**，不按采购员 / 助理数据范围收缩（与「采购订单明细」不同）。

### 1.3 入口与权限

| 项 | 要求 |
|------|------|
| 菜单 | 采购管理 → **备货采购清单**，排在「采购订单明细」之后 |
| 谁能进 | 具备采购订单查看权限，且为采购侧：采购部职员、采购助理、采购运营（含对应扩展角色）；系统管理员可进 |
| 谁不能进 | 销售、物流等非采购侧人员，即使有采购订单查看权限；采购数据范围为「禁止」不可进 |
| 权限码 | **不新增**独立权限码，复用采购订单查看权限 + 采购侧身份门控 |

### 1.4 列表

- UI 对齐「采购订单明细」列表（筛选、列设置、列宽记忆、导出），但本页独立列宽记忆，互不影响。
- **首期只要列表 + 导出**；不要看板、不要左栏快捷筛选、不要行勾选。
- 无「订单类型」下拉（已锁定备货）。
- 搜索栏勾选 **有可用库存**（默认不勾）：勾选后只显示可用库存数量 **> 0** 的行；分页与导出使用同一条件。
- 操作列仅 **详情**；无通知到货、申请付款。

### 1.5 列名与口径（与采购订单明细对照）

| 本页列名 | 同源字段 | 采购订单明细页列名 | 含义 |
|----------|----------|--------------------|------|
| 采购数量 | 明细 `Qty` | 数量 | 该备货采购明细行订了多少 |
| 采购单价 | 明细 `Cost` | 单价 | 该行采购单价 |
| 可用库存数量 | 见 §3 | （本页新增） | 该型号+品牌当前备货池还能用多少，**不是**本行已入库数 |

无采购金额查看权限时，采购单价 / 行金额脱敏；无供应商信息权限时供应商名按现有采购脱敏。可用库存数量 **不要求** 库存读权限。

### 1.6 详情

从本页进入的采购订单详情 **只读**：不打印、不编辑、不删除、不到货、不付款、不录入货代单号。右侧仅帮助。跟单作业请到「采购订单 / 采购订单明细」。

### 1.7 明确不做（本版）

看板、左栏快捷检索、行勾选、写操作、独立权限码、数据库迁移。

## 2. 权限与数据范围（实现）

门控：`StockingPurchaseListAccess.CanEnter`（后端）、`canAccessStockingPurchaseList`（前端菜单 / 路由）。前后口径一致。

**可进（须同时满足）：**

1. 采购数据范围不是「禁止」（`PurchaseDataScope = 4`）；系统管理员 / 业务数据 bypass 不受此限。
2. 系统管理员或业务数据 bypass；**或** 持有 `purchase-order.read`，且满足下列之一：
   - 隶属采购侧部门（`BelongsToPurchaseDept`）
   - 主部门身份为采购 / 采购运营（`IdentityType` 2 / 3）
   - 角色含 `purchase_buyer` / `purchase_operator` / `purchase_ops_operator`

**列表查询：** 标志 `StockingPurchaseSharedList = true` 时 **跳过** `ApplyPurchaseOrderDataScopeAsync`，再锁定 `Type = 2`。

**详情 GET：** `AllowPurchaseOrderGetAsync` = 原 `CanAccessPurchaseOrderAsync` **或**（订单 `Type = 2` 且可进清单）。**仅放宽读**（GetById、tab 聚合、变更日志、已删明细）。写接口仍走原采购员范围，本页不提供写入口。

直链本页而无权：路由守卫回控制台。

## 3. 可用库存数量

本行 **PN + 品牌**（去首尾空白、不区分大小写）下：

```text
可用库存数量 = Σ QtyRepertoryAvailable
  条件：StockType = 2（备货）
        且非手工移库源行
  合计截断为非负
PN 或品牌为空 / 无匹配 → 0
```

多行同一 PN+品牌显示 **同一池余量**，不是「本行还没入完的数」。

勾选「有可用库存」时，服务端按 **同一口径** 过滤后再分页（`HasAvailableStock`），避免只滤当前页导致总条数不准。导出走同一查询。

实现：`CRM.Infrastructure/PurchaseOrders/StockingAvailableQtyLookup.cs`。

## 4. 页面与交互

### 4.1 列表 `/stocking-purchase-items`

| 项 | 说明 |
|------|------|
| 组件 | `StockingPurchaseItemList.vue` 包装 `PurchaseOrderItemList.vue`（`meta.stockingPurchaseList`），避免与采购订单明细共用组件实例 |
| 筛选 | 订单生成日期、采购订单/明细号、货代单号、供应商、采购员、物料型号、交易币别、付款/采购/入库/开票进度；另有 **有可用库存** |
| 列宽 | `stocking-purchase-list-main-v2`（与 `purchase-order-item-list-main` 独立） |
| 页签模式 | 可开币别/进度（不含订单类型）；独立 localStorage 键 `crm.stocking-po-item-list.tab-mode` |
| 勾选「有可用库存」 | 立即查询；写入路由 `hasAvailableStock=1`，刷新保持 |

### 4.2 详情 `/stocking-purchase-items/:id`

`StockingPurchaseOrderDetail.vue` 包装 `PurchaseOrderDetail.vue`（`meta.stockingPurchaseReadOnly`）。点详情带 `purchaseOrderItemId` 以选中该行。`canWritePo = false`，隐藏打印与业务按钮。

从本页打开他人备货单可查阅；若改用地址栏打开普通采购订单详情且无该单数据范围，写操作仍失败（原页权限不变）。

| 方法 | 路径 | 说明 |
|------|------|------|

## 7. 与「采购订单明细」的已知差异

| 项 | 备货采购清单 | 采购订单明细 |
|------|----------------|----------------|
| 行范围 | 仅备货（Type=2） | 客单 / 备货 / 样品 |
| 数据范围 | 采购侧全员看全部备货行 | 按采购员 / 助理收缩 |
| 列名 | 采购数量、采购单价、可用库存数量 | 数量、单价（无库存列） |
| 有可用库存 | 有 | 无 |
| 看板 / 左栏检索 / 行勾选 / 到货付款 | 无 | 有 |

两页结果不一致属设计，不是缺陷。
