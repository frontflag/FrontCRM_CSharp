# 采购订单下游采购价刷新 — 设计与实现

**状态：** MVP  
**页面：** 采购订单详情 `/purchase-orders/:id` → 主按钮「刷新」（非下拉「刷新供应商」）  
**测试对照：** [采购订单下游采购价刷新-测试对照说明](../../QA/采购/采购订单下游采购价刷新-测试对照说明.md)  
**帮助：** [采购订单](../../../help/pages/采购订单_MENU_PURCHASE_ORDERS.md)

---

## 1. 目标

采购员建单录错采购价、入库或出库后才发现时，在采购订单详情点 **「刷新」**，以**当前采购明细行**的单价为准，覆盖下游所有采购价/金额快照。

- **准绳：** 行 `Cost` / `Currency` / `ConvertPrice`（改价保存时已重算折算美金；刷新不再取当日汇率）。
- **无状态门控：** 已入库、已请款、已核销、已进项匹配一律覆盖。数据安全由点击刷新的人负责。
- **顺序：** 先写下游快照 → 再跑现有明细扩展 `RecalculateAsync`（进度、目标额、利润）。

与「刷新供应商」分离：供应商同步仍有完结门控；本能力只改采购价快照。

## 2. 权限

| 项 | 说明 |
|----|------|
| API | `purchase-order.write`（沿用 `POST …/refresh-item-extends`） |
| 数据范围 | `CanAccessPurchaseOrderAsync` |

无新权限码、无新迁移。

## 3. API

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/v1/purchase-orders/{id}/refresh-item-extends` | 覆盖下游采购价快照 + 重算明细扩展；请求体空 |

结果在原 `PurchaseOrderItemExtendRefreshResult` 上增加：到货通知/入库明细/入库单头/入库扩展/库存/出库扩展更新计数、单价变化行、进项匹配超额警告、已付超额警告。

## 4. 下游覆盖清单

| 节点 | 字段 | 新值 |
|------|------|------|
| 到货通知 `stockin_notify` | `Cost`，重算 `ExpectTotal` / `ReceiveTotal` | **全部批次**都改单价；数量不自动放大/缩小 |
| 入库明细 `stockinitem` | `Price` / `Currency` / `Amount = Qty × Cost` | 经 `stock_in_item_extend.purchase_order_item_id` |
| 入库扩展 | 保留 `InvoiceMatchDone`；`ToBe = Amount − Done`；状态重标 | 允许负余额 + 警告 |
| 入库单头 `stock_in.TotalAmount` | `Σ(行金额)` | 一单多行：本单行用新价，其它行用各自入库价 |
| 库存 `stockitem` | `PurchasePrice` / `PurchaseCurrency` / `PurchasePriceUsd` / `PurchaseAmount`，并 `SyncDenormalizedComputedFields()` | 按 `PurchaseOrderItemId` |
| 出库明细扩展 `stock_out_item_extend` | `PurchasePrice` / `PurchaseCurrency` / `PurchasePriceUsd`，按本行出库数量重算 `ProfitOutBizUsd` | **用采购行新价写，不从旧库存层抄**；不改销售价、`OriginalPurchasePrice` |
| 采购行扩展 | 现有 `RecalculateAsync` | 快照写完后再跑（会连带销售行扩展利润） |

进项匹配余额：

```text
InvoiceMatchDone 保留
InvoiceMatchToBe = Amount − InvoiceMatchDone
状态按新总额与已完成额重标（FinanceVerificationStatusCode.Resolve）
```

已付警告（不改请款/付款流水）：

```text
Σ VerificationDone（排除付款单取消 / 审核失败）> 采购行 Qty × Cost
不拦截；结果里列出警告
```

允许 `InvoiceMatchDone > Amount` 或已付大于新行总额（不拦截）；结果里列出警告。

到货通知数量：现有 Recalculate 仅在「恰好 1 条通知」时收缩超量预计数量；刷新与 Recalculate 两条路径都对**全部通知**同步 `Cost`。

### 4.1 明确不改

- 请款 / 付款 / 核销流水金额
- 进项发票票面
- 报关申报单价
- 销售价
- `OriginalPurchasePrice`（P0）

## 5. 操作日志

`log_operation`：`BizType=PurchaseOrder`，`ActionType=刷新采购价`。记录操作人、单价变化行（旧→新）、到货/入库/库存/出库条数；超额警告写入 `ExtraInfo`。

## 7. 前端

- 确认文案说明会覆盖下游采购价（含已入库/已请款/已核销/已进项匹配），不改请款付款流水与进项票面。
- 结果弹窗展示下游计数、单价变化行、进项匹配 / 已付超额警告。
- 仅扩展无变更但快照有更新时，**不**显示「无更新数据」。
