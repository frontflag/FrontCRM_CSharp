## 1. 业务定位

| 概念 | 说明 |
|------|------|
| **目标** | 以时间节点推进方式展示 **单条采购明细** 从建立到付款/进项发票的完整业务链路（地铁路线图式纵向轴） |
| **展示位置** | `AppLayout` 右侧辅助栏 **「流程」**，与「操作」「帮助」并列 |
| **页签 ID** | `r-flow`（文案 i18n：`layout.auxTabs.flow` → 中文「流程」） |
| **数据粒度** | 一条采购订单明细行（`purchaseOrderItemId`） |
| **只读** | 无到货/请款动作按钮；单号可跳转详情（与操作面板链接规范一致） |

**与「操作」页签区别：**

| | 操作 `r-ops` | 流程 `r-flow` |
|--|--------------|---------------|
| 侧重 | 日常动作、进度条、通知到货/申请付款 | 全链路只读时间轴 |
| 范围 | 列表 + 详情右侧均可挂 | 列表 + 详情（与操作共用选中明细行 / aggregates） |

## 2. 布局与交互

### 2.1 整体结构

与销售明细流程页签一致：竖轴从上往下；同站多卡按创建时间升序；未发生节点仍画空心站「未开始」。

### 2.2 站点视觉态

| 站态 | 圆点 | 判定 |
|------|------|------|
| **未开始** | 空心 | 该站无任何单据 |
| **进行中** | 实心（进行中色） | 有单据，且未全部终态 |
| **已完成** | 实心（完成色） | 有单据，且全部终态 |

### 2.3 交互门控

对齐 [销售流程页签 §2.3](../销售订单明细列表-流程页签-设计与实现.md) / 操作面板 §2.4：`dataTabIds: ['r-ops','r-flow']`。

「流程」与「操作」共用 `purchaseOrderItemOpsPanel` 选中行与 aggregates，避免双请求。脱敏（`maskPurchaseSensitiveFields`）时仍可加载；敏感字段 `—`。双击行仍进采购订单详情。

### 2.4 小卡字段

双列 Key:Value。公共字段：单号、状态、创建日期、供应商名称、供应商编号、角色人名、单价·币别或金额·币别（有则显）、数量（有则显）、描述（MVP 空/`—`）。

**入库站**例外：第一行 **单号** 通栏；第二行左 **入库类型**、右 **状态**。入库类型文案与入库单列表一致：`10` 采购入库，`20` 报关入库，`30` 退货，`40` 报废，`3` 移库，未识别为「未知」（不兜成采购入库）。存量旧码 `1/2/4` 已刷净；展示代码仍认历史 `1`。

## 3. 节点清单与顺序（定稿）

```
1. 采购申请
2. 采购订单明细
3. 申请付款
4. 付款
5. 到货通知
6. 质检
7. 入库
8. 进项发票
```

说明：

- **不以「当前明细」打头**：按业务发生序，采购申请在前。
- **付款链在物流前**：反映可预付；空站仍画空心。
- 无关联销售明细时，「采购申请」为空站。

## 4. 数据与字段映射

### 4.1 数据源

| 来源 | 用途 |
|------|------|
| 列表行 `row` | 采购订单明细站；供应商回退 |
| `GET /api/v1/purchase-orders/{orderId}/purchase-order-items/{purchaseOrderItemId}/detail-tab-aggregates` | 各站单据列表（含 `qcs`） |

**MVP 不新增专用流程 API**；前端将 aggregates + row 适配为 `FlowStation[]`。

### 4.2 「申请付款」与「付款」分站

请款/付款落在同一实体 `FinancePayment`（`aggregates.payments`）。

| 站 | 规则 |
|----|------|
| 申请付款 | `payments` 排除已取消（`status === -2`） |
| 付款 | 仅已付款终态（`status === 100`） |

已付款单据可同时出现在两站。单号跳转 `FinancePaymentDetail`。

### 4.3 各站映射表

| # | 站名 | 数据源 | 单号 | 人员 Key | 数量/金额 | 供应商 |
|---|------|--------|------|----------|-----------|--------|
| 1 | 采购申请 | `purchaseRequisitions` | `billCode` | 采购员（常无 → —） | `qty`；无单价则隐藏 | 回退行 |
| 2 | 采购订单明细 | `row` | `purchaseOrderItemCode` | 采购员 → `purchaseUserName` | 单价·币别；`qty` | 行上名称/编号 |
| 3 | 申请付款 | `payments`（见 §4.2） | `financePaymentCode` | 申请人（`createUserName`，缺 → —） | **金额·币别**（应付/请款）；不显数量 | DTO 或回退行 |
| 4 | 付款 | `payments` status=100 | 同上 | 同上 | **已付金额·币别** | 同上 |
| 5 | 到货通知 | `arrivalNotices` | `noticeCode` | 采购员 | `expectQty`；不显单价 | DTO 优先 |
| 6 | 质检 | `qcs` | `qcCode` | 创建人 | pass/reject | 回退行 |
| 7 | 入库 | `stockIns` | `stockInCode` | 创建人 | `totalQuantity`；不显单价；第二行左 **入库类型**、右 **状态** | 回退行 |
| 8 | 进项发票 | `purchaseInvoices` | `invoiceNo` | 创建人（常无 → —） | **金额·币别**；不显数量 | DTO 或回退行 |

供应商：**各站均显示**名称+编号；缺编号时回退当前采购明细行 `vendorCode`。

### 4.4 站终态示意

| 站 | 终态示意 |
|----|----------|
| 采购申请 | PR 完成/关闭（status 2/3） |
| 采购订单明细 | 行状态完成/取消/审核失败（100/-1/-2） |
| 申请付款 | 付款完成或审核失败（100/-1） |
| 付款 | 均为已付款（100）→ 有卡即完成 |
| 到货通知 | 已入库（100） |
| 质检 | 通过/未通过（100/-1） |
| 入库 | 完成/取消（2/3） |
| 进项发票 | 已认证（confirmStatus=1）或红冲类终态 |
