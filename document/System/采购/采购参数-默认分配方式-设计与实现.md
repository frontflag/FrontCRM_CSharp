## 1. 入口

| 项 | 说明 |
|----|------|
| 主菜单 | 参数管理 → **采购参数** → 左栏 **默认分配方式**（位于「报价员池」下方） |
| 布局 | 与其它采购参数页相同：左栏分类 + 右栏表单 + 保存 / 刷新 |
| 权限 | 读 `system.params.purchase.default-assign-method.read`；写 `.write`。无新权限码 |

---

## 2. 字段

| 字段 | 说明 |
|------|------|
| 分配方式 | 下拉仅 **采报优先（5） / 条目轮询（2） / 品牌轮询（3）**。出厂默认 5。**不含**指定采购，避免新建页一进来就必填采购员 |
| 允许指定采购 | 勾选。默认未勾选。勾选并保存后，新建/编辑需求的「分配方式」下拉才出现「指定采购」 |

同一「保存」写入两个系统参数。刷新后勾选状态须保持。

### 2.1 关闭勾选后的口径

- 已保存需求的 `assign_method` **不改写**。
- 已是指定采购的单据，编辑页仍显示该项，可保存、可加明细沿用原人。
- 不能把其它分配方式改成指定采购（前端不下发选项；后端拒绝「未开启指定采购」）。
- 详情「分配采购员」不受本勾选限制。

---

## 3. 存储与 API

| 参数 | 说明 | 默认 |
|------|------|------|
| `System.RFQ.DefaultAssignMethod` | 新建需求「分配方式」默认选中项（2/3/5） | `5` |
| `System.RFQ.AllowDesignatedPurchaser` | 是否开放指定采购 | `false` |

| 用途 | 方法 | 路径 |
|------|------|------|
| 本页读写 | GET/PUT | `/api/v1/purchase-params/default-assign-method`（DTO 含 `assignMethod`、`allowDesignatedPurchaser`） |
| 需求页只读 | GET | `/api/v1/rfqs/default-assign-method`（`rfq.create` 或 `rfq.write`，不要求采购参数权限） |

未配置时 GET 回退上述默认值。首次在本页保存会自动创建 `sysparam` 行。可选脚本：

- `scripts/ensure_rfq_default_assign_method_postgresql.sql`
- `scripts/ensure_rfq_allow_designated_purchaser_postgresql.sql`

合法默认项校验：`RfqDefaultAssignMethodRules`（**不含** 4）。开关文案：`RfqDesignatedPurchaserRules.NotEnabledMessage`。
