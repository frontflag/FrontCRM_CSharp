## 1. 目标

三租户打印采购订单报表时，**配色**与同租户 Packing / Invoice / 销售订单报表一致。

版式按全局参数 `System.Report.StyleVersion` 在 **V1 / V2** 间切换：

| 版本 | 版式 |
|------|------|
| **V1**（默认） | 现网三套皮肤，完全不动 |
| **V2** | 对齐 refined PDF：藏青顶栏底、白字「采购订单」、强调色「PURCHASE ORDER」、右侧斜纹底纹、顶栏下青色渐变横线、浅灰分区条+强调竖线、条款浅底卡片、双方签章虚线框；**强调色仍按租户** |

本期只接**采购订单打印**。销售订单、装箱、发票不读该参数。

非目标：列表页皮肤；新造合同编号 / 运费金额 / Incoterms 主数据字段。

## 2. 架构

| 层 | 说明 |
|----|------|
| 租户来源 | `VITE_TENANT_ID` → `LOGIN_TENANT_ID` |
| 样式版本 | `GET /api/v1/report-params/effective-style-version`（任意登录可读；非法/空 → V1） |
| 皮肤选择 | `resolvePurchaseOrderReportSkin(tenant, version)`（租户映射与 Packing 相同） |
| 数据 | `docBind`（卖方=供应商、买方=我方、印章在买方/需方侧） |
| V1 版式 | 三套皮肤 + 共用 `PurchaseOrderReportBody` |
| V2 版式 | 三套皮肤 + 共用 `PurchaseOrderReportV2Body`（图1分区，字段不丢） |

```
PurchaseOrderReportPage
  → GET effective-style-version（无参数管理权限也可）
  → resolvePurchaseOrderReportSkin(LOGIN_TENANT_ID, V1|V2)
  → V1: PurchaseOrderReportSkin{Semicore|Idesemi|Ecoinf}
  → V2: PurchaseOrderReportV2Skin{Semicore|Idesemi|Ecoinf}
```

切换全局参数后需**刷新报表页**才变（工具栏不做即时切换）。打印 / PDF / 邮件仍截 `.po-doc`。

## 4. 皮肤差异摘要

租户映射（V1 / V2 相同）：

| 租户 | 皮肤 | 主题要点 |
|------|------|----------|
| semicore | Idesemi | V1 深色顶栏 `#0D1F35`；V2 白底顶栏 + 藏青订单编号条 `#0A1628`、强调青 `#00AEEF` |
| idesemi | Ecoinf | V1 左大标题、青竖条 `#6DC5F6`；V2 同 PDF 结构，强调 `#6DC5F6` |
| ecoinf | Semicore | V1 绿表 `#A8D070`；V2 同 PDF 结构，强调绿 `#A8D070` |

与 SO 差异：三栏文案为「卖方 / 买方 / 交付」（V2 为「需方 / 供方」）；印章在 **Buyer / 需方** 侧；确认语为 24 小时合同确认。

明细表只打印实际行；**不补空白行、不显示「以下空白」**。无明细时显示「暂无明细」。

Logo / 抬头 / 印章仍走公司信息，与样式版本无关。金额脱敏、抬头切换、含印章开关行为不变。

## 5. V1 → V2 字段对照（不丢）

V1 已打印数据在 V2 必须仍出现。图1多出来的格子用已有数据填；没有独立字段的显示 `—`，不新造业务字段。

| 现网 V1 | 图1 V2 落点 |
|---------|-------------|
| Logo + 我方公司名 | 顶栏左 Logo；需方公司名 |
| 采购订单 + 单号/日期 | 顶栏右「采购订单 / PURCHASE ORDER」+ PO NO；元数据「订单日期」 |
| 卖方=供应商 名称/地址/电话 | 供方（右）；联系人/电话/邮箱拆开展示（有则填） |
| 买方=我方 名称/地址 | 需方（左）；补公司资料联系人/电话/邮箱（有则填） |
| 收货人（仓联系人+电话）+ extraLines 收货地址 | 交付「交货地址 / Ship To」 |
| 最晚交期 | 交付「交货日期」 |
| 运输方式（固定文案「送货/物流/快递」） | 交付「贸易条款 / Incoterms」 |
| extraLines「运费承担：供方承担」 | 交付「文件要求」旁保留；汇总「运费」金额无独立字段则 `—`（不编造 0.00） |
| extraLines「付款方式」= 订单备注 `comment` | 元数据「付款条款 / PAYMENT」 |
| 合同编号 | 无独立字段 → `—` |
| 序号、品牌、规格(PN)、产品名称(comment)、单位、币种、数量、含税单价、税率、行金额 | V2 明细按 PDF 八列：序号 / MPN / 厂牌 / 批号 / 规格及描述 / 数量 / 单价 / 金额；PN→MPN，产品名称→描述；单位并入描述口径外仍固定 PCS 不单列；币种在元数据，税率在汇总税费 |
| 总计数量 + 含税合计 | 表下总计行 |
| 不含税 / 增值税 / 价税合计 / 税率标签 / 货币 | 汇总：小计←不含税、税费←增值税、总额←价税合计；货币在元数据/汇总带 |
| 服务条款 + 「24小时确认」 | 条款区 2 列网格 + 文首法律效力句；24 小时句保留 |
| 卖方签章 / 买方签章+印章+日期 | 供方右、需方左 |

金额无 `purchase.amount.read` 时数量/单价/金额为 `—`。

## 6. 读取全局参数

管理端 `GET/PUT /api/v1/report-params/style-version` 仍要 `system.params.report.global.read` / `.write`。

打印账号通常无参数管理权限，因此打印页走：

`GET /api/v1/report-params/effective-style-version` — `[Authorize]`（登录即可），返回规范化 `V1`/`V2`。

## 7. 验证要点

- 未配置或非法值：打印为 V1。
- 参数改为 V2 后刷新打印页：图1版式；三租户配色仍可区分。
- 无参数管理权限的采购员：仍能打开打印并读到生效版本。
- 同租户 PO 与 Packing 页眉色系一致；打印/PDF/邮件三皮肤可用。
- V2 字段不丢；合同编号、运费金额为 `—`。
- 金额脱敏仍为 `—`。
