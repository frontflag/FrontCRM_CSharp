# 采购订单换供应商 — 设计与实现

## 1. 目标

允许**系统管理员**与**采购侧总监**（`DEPT_DIRECTOR` + 主部门 `IdentityType` 2/3）在编辑采购订单时更换整单供应商，并保证：

- 主表 `purchaseorder.vendor_id / vendor_name / vendor_code` 与全部未删明细 `purchaseorderitem.vendor_id` 一致；
- 名称来自供应商主数据，禁止只改名称不改 ID；
- 未完结下游自动同步；已完结下游阻断整单更换。

## 2. 权限

| 方式 | 说明 |
|------|------|
| RBAC | `purchase-order.change-vendor`（见 `scripts/ensure_purchase_order_change_vendor_permission_postgresql.sql`） |
| 角色 | 系统管理员；或 `RfqItemQuoteAccessRules.IsPurchaseDepartmentDirector` 同等判定 |
| 数据范围 | 须通过 `CanAccessPurchaseOrderAsync`，不可跨范围改单 |

后端：`PurchaseOrderVendorChangeAccessRules`；前端：`canChangePurchaseOrderVendor()`。

## 3. API

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/v1/purchase-orders/{id}/change-vendor/preview?newVendorId=` | 预检：同步计数 / 阻断原因 |
| PUT | `/api/v1/purchase-orders/{id}` body 含 `vendorId` | 执行更换（与编辑保存同一入口） |

## 4. 下游分界

| 下游 | 同步 | 阻断 |
|------|------|------|
| 到货通知 `stockin_notify` | `status < 100` | `status = 100` 已入库 |
| 入库单 `stock_in` | 未过账（`status ≠ 2`） | 已过账 |
| 付款单 `financepayment` | `status < 100` 且非取消 | `status = 100` 已付款 |
| 进项发票 `financepurchaseinvoice` | 未认证且未冲红 | 已认证 / 已冲红 |
| 在库 `stock_item` | 不改历史快照 | 有过账入库即阻断 |

质检展示名随到货通知冗余字段更新（`qcinfo` 无落库供应商名）。

## 5. 业务规则

- 换供应商后**主状态不回退**（保持已确认等）。
- 新供应商不得为黑名单 / 禁用 / 已删 / `PENDING` / 手工占位 ID。
- 原 `vendor_contact_id` 不属于新供应商时**清空**。
- 明细保存时 `vendor_id` **一律取主表**（整单一供）。
- 与「刷新供应商名称」（仅 sysadmin、只刷 `vendor_name`）并存。
