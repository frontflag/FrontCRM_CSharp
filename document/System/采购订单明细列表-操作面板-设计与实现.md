# 采购订单明细列表 · 右侧「操作」面板 — 功能要求与实现说明

本文描述 **FrontCRM（CRM.Core / CRM.API / CRM.Web）** 中 **采购订单明细列表页**（`PurchaseOrderItemList`）右侧工作区辅助栏 **「操作」** 页签（面板标题 i18n：**「采购订单明细」**）的设计要求与实现方法。与 [采购订单明细概况-设计与实现](采购订单明细概况-设计与实现.md)（详情页底部概况矩阵）、[销售订单明细列表-操作面板-设计与实现](销售订单明细列表-操作面板-设计与实现.md)（同模式参考）、[系统设计规范](系统设计规范.md)、`help/pages/采购订单明细_MENU_PURCHASE_ORDER_ITEMS.md` 交叉引用。

---

## 1. 业务定位

| 概念 | 说明 |
|------|------|
| **适用页面** | 采购订单明细列表 `/purchase-order-items`（`PurchaseOrderItemList`）、采购订单详情 `/purchase-orders/:id`（`PurchaseOrderDetail`） |
| **展示位置** | `AppLayout` 右侧辅助栏（`aux-right`），与 **「帮助」** 页签并列 |
| **页签 ID** | `r-ops`（文案 i18n：`layout.auxTabs.ops` → 中文「操作」） |
| **面板标题** | `purchaseOrderItemList.opsPanel.title` → 中文「采购订单明细」 |
| **目标** | 在右侧「操作」页签就绪时查看该行摘要，并发起 **到货通知** / **申请付款**（列表门控同销售明细 §2.4）；详情页单击订单明细行时同步展示同一操作面板 |
| **交互规范** | 与 [销售订单明细列表-操作面板 §2.4](销售订单明细列表-操作面板-设计与实现.md) 一致；实现 `useListRightOpsPanelInteraction` |
| **测试对照** | [采购订单明细列表-操作面板-测试对照说明](../QA/采购/采购订单明细列表-操作面板-测试对照说明.md) |
| **与详情页区别** | 详情页底部 `poItemLinePanel` 保留 7 Tab 全链路（概况 / 采购申请 / 付款 / 到货 / 入库 / 库存 / 进项发票）；右侧操作面板为 **3 张卡片** 承载日常操作 |

**在采购订单明细列表或采购订单详情路由下** 注册双页签（操作 + 帮助），默认选中 **操作**；两页共用 `PurchaseOrderItemOpsPanel` + `purchaseOrderItemOpsPanel` store。离开上述路由时恢复仅「帮助」，并 `clear()` 操作面板 store。

## 2. 布局与交互要求

### 2.1 整体结构

```
┌─ 右侧辅助栏 ─────────────────────────┐
│ [操作] [帮助]              [全屏][✕] │
├──────────────────────────────────────┤
│  （无选中行）单击列表行查看概况与操作… │
│  或                                  │
│  ┌ 订单明细 ─────────────────────┐   │
│  ├ 到货通知 ──────────── 已完成 ✓│   │
│  └ 申请付款 ─────────────────────┘   │
└──────────────────────────────────────┘
```

- 三个区块 **直接作为页签内容子级** 纵向排列，无额外浮动外层壳；宽度 `100%` 自适应父面板，禁止横向滚动。
- 嵌入模式（`embedded`）使用 `div.so-item-ops-root--embedded`，样式 token 对齐 `--crm-aux-*`。
- 各卡片 **无标题图标**，仅保留文字标题。
- 组件复用 [销售操作面板 §2.5](../销售订单明细列表-操作面板-设计与实现.md) SCSS（`.ops-card`、`.ops-metrics`、`.ops-progress`、`so-item-ops-panel.scss` 等）；到货进度条为绿色渐变，请款进度条为橙色渐变。

### 2.2 列表交互

| 操作 | 行为 |
|------|------|
| **单击行** | 见 [销售操作面板 §2.4](销售订单明细列表-操作面板-设计与实现.md)（A～F）；采购实现于 `PurchaseOrderItemList` + `useListRightOpsPanelInteraction` |
| **双击行** | 跳转采购订单详情 `PurchaseOrderDetail`，query 带 `purchaseOrderItemId`（优先级高于单击） |
| **选中行高亮** | 表格 `row-class-name`：`so-item-row--active` |
| **敏感字段脱敏** | `maskPurchaseSensitiveFields === true` 时：不响应单击、清空 store |

### 2.3 右栏展开 / 收起与接口

**混合数据源 + 按需请求**（见 §4）。门控与加载时机同销售 §2.4（`selectRow` / `setRowOnly` / `loadAggregates`）。列表刷新 `resetListRightPanelOnReload` 清空 store；离开路由 `clear()`。

**详情页：** 单击明细行打开底部 `poItemLinePanel` 并请求聚合；**不**强制 `setRightActiveTab('r-ops')`；加载完成后可 `syncRowAndAggregates` 写入操作面板 store。

### 2.4 列表页移除的遗留 UI

改造前 `PurchaseOrderItemList.vue` 底部存在 `poItemLinePanel`（7 Tab 明细面板），**从未在列表页打开**（`visible` 恒为 `false`），属于死代码。改造后：

- **删除** 列表页 `poItemLinePanel` 模板、`lineTabAggregates` 状态及相关 helpers；
- **保留** 列表页「通知到货」「申请付款」弹窗及 `openArrivalDialog` / `openPaymentDialog`；
- **保留** `PurchaseOrderDetail.vue` 底部 `poItemLinePanel` 不变。

## 3. 三张卡片 — 功能与 UI 要求

### 3.1 订单明细

**标题：**「订单明细」（`overviewTitle`，非「概况」）

**展示规则：** 去掉 Key 标签，仅左对齐 Value 文本行：

| 顺序 | 内容 | 字段 | 样式 |
|------|------|------|------|
| 1 | 采购明细编号 | `purchaseOrderItemCode` | 琥珀色 `$color-amber`，18px 加粗 |
| 2 | 供应商中文名 | `vendorName` | 13px，常规；脱敏显示 `—` |
| 3 | 供应商英文名 | `vendorEnglishName` | **无内容整行隐藏** |
| 4 | 物料型号 | `pn` | 常规 |
| 5 | 品牌 | `brand` | 常规 |
| 6 | 采购单价 + 币别 | `cost`, `currency` | `formatUnitPriceWithCurrencyCodeSuffix`，如 `19.50 USD` |
| 7 | 数量 | `qty` | `{qty} pcs`，不加粗、不用强调色 |

**数据来源：** 列表行 `row`（含列表 API 下发的 `vendorEnglishName`，后端 `MapPurchaseOrderItemListLines` 按供应商可见性填充）。

### 3.2 到货通知

| 元素 | 要求 |
|------|------|
| 指标 | **已通知数量** / **可通知数量**（两列大数字） |
| 进度条 | 高度 **10px**；已通知 / 订单量；绿色渐变（`ops-progress__bar--arrival`）；**不显示**百分比文案 |
| 状态文案 | 不显示「当前可申请」；仅在禁用时显示 `arrivalDisabledHint` |
| 禁用提示 | 摘要 + `nextStep`（`applyArrivalDisabledHint.ts`） |
| 按钮 | 权限 `purchase-order.read`；文案「通知到货」 |
| 按钮样式 | 可用：深蓝 `#0f4c81`；不可用：灰底 `#e5e7eb` |
| **已完成** | 见 §3.4 |

**数量口径：**

| 指标 | 列表行字段 | 聚合补充（优先） |
|------|------------|------------------|
| 订单量 | `qty` | `lineOverview.arrivalNotice.total` |
| 已通知 | `qtyStockInNotifyExpectSum` | `lineOverview.arrivalNotice.done` |
| 可通知 | `qtyStockInNotifyNot`（缺省则 `qty − 已通知`） | `lineOverview.arrivalNotice.pending` |

**门槛：** `itemStatus === 30`（`PO_STATUS_VENDOR_CONFIRMED`，供应商已确认）。

**按钮点击：** store `runApplyArrival` → 列表页 `openArrivalDialog` → `buildPurchaseArrivalNoticeLineRow`。

### 3.3 申请付款

| 元素 | 要求 |
|------|------|
| 指标 | **已申请金额** / **可申请金额**（两列）；金额与币别 **折行两行显示**（上：金额，下：ISO 币别 + `dock-tier-ccy` 配色） |
| 进度条 | 10px 高；已申请金额 / 明细总额；橙色渐变；无百分比文案 |
| 状态文案 | 禁用时 `paymentDisabledHint` |
| 按钮 | 权限 `finance-payment.write` **或** `purchase-order.write`；文案「申请付款」 |
| 按钮样式 | 同到货通知 |
| **已完成** | 见 §3.4 |

**金额展示格式：**

```
39,000.00        ← formatTotalAmountNumber（第一行，20px 加粗）
USD              ← listAmountCurrencyIso + dock-tier-ccy--*（第二行，12px）
```

**请款口径（重要）：** 本卡片度量的是 **请款申请** 进度，**不得** 使用详情页概况矩阵 `lineOverview.payment`（该列为 **已付** `PaymentAmountFinish` / **待付** `PaymentAmountNot`）。

| 指标 | 计算 |
|------|------|
| 明细总额 `lineTotal` | 行 `lineTotal`，缺省 `qty × cost` |
| 已申请金额 | `paymentRequestedAmount`（扩展表 `PaymentAmountRequested`） |
| 可申请金额 | `max(0, lineTotal − paymentRequestedAmount)` |

**业务门槛（`canApplyPayment`）：** 后端列表 API 计算：

```csharp
canInitiatePaymentFromPo
  && FinancePaymentStatus < 2
  && (ItemStatus == 30 || OrderStatus == 30)
```

**按钮点击：** store `runApplyPayment` → 列表页 `openPaymentDialog`（与操作列共用弹窗）。

### 3.4 「已完成」态（到货通知 / 申请付款）

标题栏 **右侧** 显示绿色对钩（`CircleCheck`）+ 文案「已完成」；**隐藏**操作按钮及禁用提示。

| 卡片 | 判定条件 |
|------|----------|
| 到货通知 | `可通知数量 ≤ 0` **且** `已通知数量 ≥ 订单量` |
| 申请付款 | `可申请金额 ≤ 0` **且** `已申请金额 ≥ 明细总额` |

### 3.5 禁用提示分支

**到货通知**（`applyArrivalDisabledHint.ts`）：

| 条件 | summary i18n key |
|------|------------------|
| `itemStatus ≠ 30` | `arrivalNeedConfirmed` |
| `可通知 ≤ 0` | `arrivalNoRemaining` |

**申请付款**（`applyPaymentDisabledHint.ts`）：

| 条件 | summary i18n key |
|------|------------------|
| `!canApplyPayment` 且未确认 | `paymentNeedConfirmed` |
| `!canApplyPayment` 其他 | `paymentNotEligible` |
| `canApplyPayment` 但可申请 ≤ 0 | `paymentNoRemaining` |

展示与禁用判断 **共用** `getPaymentMetrics(row)` / `getArrivalMetrics(row[, aggregates])`，避免展示数字与按钮状态不一致。

## 4. 数据来源

### 4.1 总览

| 数据块 | 主要来源 | 补充来源 |
|--------|----------|----------|
| 订单明细卡片 | 列表行 `row` | — |
| 到货通知数量 | 列表行 `qtyStockInNotify*` | 聚合 `lineOverview.arrivalNotice`（展示优先） |
| 申请付款金额 | 列表行 `lineTotal`、`paymentRequestedAmount` | **不用** `lineOverview.payment` |
| 按钮禁用 / 提示 | 列表行（与 utils 共用） | 到货展示可参考 aggregates |

### 4.2 聚合接口

```
GET /api/v1/purchase-orders/{purchaseOrderId}/items/{purchaseOrderItemId}/detail-tab-aggregates
```

- 与采购订单 **详情页** 单条明细 aggregates **同一 DTO**（`PurchaseOrderDetailTabAggregates`）。
- 列表操作面板当前主要使用：`lineOverview.arrivalNotice`（到货数量展示）。
- **申请付款卡片不读取** `lineOverview.payment`（概况付款列语义不同，见 §3.3）。
- 接口在右栏展开且选中行变化时按需请求；收起时仅缓存列表行。

### 4.3 列表接口关键字段

`PurchaseOrdersController.MapPurchaseOrderItemListLines` 下行对象需包含：

| 字段 | 用途 |
|------|------|
| `purchaseOrderItemId`, `purchaseOrderId`, `purchaseOrderItemCode` | 选中、跳转、聚合 scope |
| `vendorName`, `vendorEnglishName` | 订单明细卡片 |
| `pn`, `brand`, `qty`, `cost`, `currency`, `lineTotal` | 摘要 / 请款计算 |
| `itemStatus` | 到货门槛（30=已确认） |
| `qtyStockInNotifyExpectSum`, `qtyStockInNotifyNot` | 到货指标 |
| `paymentRequestedAmount` | 已请款金额（需 `purchase.amount.read`） |
| `canApplyPayment` | 申请付款业务门槛 |

### 6.2 Store API

```typescript
// stores/purchaseOrderItemOpsPanel.ts
setRowOnly(row)        // 仅记录列表行，不请求 API
loadAggregates(text)   // GET detail-tab-aggregates（同 key 已加载则跳过）
selectRow(row, text)   // setRowOnly + loadAggregates
refreshFromListRows(rows, text, fetchAggregates)
clear()
registerHandlers({ applyArrival, applyPayment })
runApplyArrival() / runApplyPayment()
```

`aggregatesRowKey` 避免重复请求；`loadSeq` 防止竞态覆盖。

## 10. 测试与回归要点

1. 进入采购订单明细列表后右栏有 **操作 + 帮助**；其他页面仅 **帮助**。
2. 单击行：展开右栏、操作页签、高亮行；双击仍进详情并带 `purchaseOrderItemId`。
3. **右栏收起**时单击：Network **无** `detail-tab-aggregates`；展开后出现请求。
4. 供应商英文名为空：订单明细卡片无英文行。
5. 到货全部通知完成：标题「已完成」+ 绿勾，无按钮。
6. 请款已全部申请：同上；**已申请金额** 显示请款累计，非已付金额。
7. 未满足条件：灰按钮 + `nextStep`；与列表操作列行为一致。
8. 申请付款金额区：金额与币别 **两行** 显示，币别颜色与列表金额列一致。
9. 请款已满但已付为 0：面板应显示已申请满额，**不应**误显示已申请 0 却提示已满（回归 §8.1 口径）。
10. 通知到货 / 申请付款弹窗提交后 `loadList` 刷新，面板 `refreshOpsPanelIfOpen` 同步。
11. 脱敏开启：单击无效，store 清空。
12. 从销售订单明细列表切到采购列表（或反向）：对方 store 已清空，仅显示对应面板。
13. 窄右栏：无横向滚动，长供应商名可换行。
