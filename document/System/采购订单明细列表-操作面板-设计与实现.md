# 采购订单明细列表 · 右侧「操作」面板 — 功能要求与实现说明

本文描述 **FrontCRM（CRM.Core / CRM.API / CRM.Web）** 中 **采购订单明细列表页**（`PurchaseOrderItemList`）右侧工作区辅助栏 **「操作」** 页签（面板标题 i18n：**「采购订单明细」**）的设计要求与实现方法。与 [采购订单明细概况-设计与实现](采购订单明细概况-设计与实现.md)（详情页底部概况矩阵）、[采购订单明细列表-流程页签-设计与实现](采购/采购订单明细列表-流程页签-设计与实现.md)（右侧 **「流程」** 全链路时间轴，列表 + 详情）、[销售订单明细列表-操作面板-设计与实现](销售订单明细列表-操作面板-设计与实现.md)（同模式参考）、[系统设计规范](系统设计规范.md)、`help/pages/采购订单明细_MENU_PURCHASE_ORDER_ITEMS.md` 交叉引用。

## 1. 业务定位

| 概念 | 说明 |
|------|------|
| **适用页面** | 采购订单明细列表 `/purchase-order-items`（`PurchaseOrderItemList`）、采购订单详情 `/purchase-orders/:id`（`PurchaseOrderDetail`） |
| **展示位置** | `AppLayout` 右侧辅助栏（`aux-right`），与 **「帮助」** 页签并列 |
| **页签 ID** | `r-ops`（文案 i18n：`layout.auxTabs.ops` → 中文「操作」） |
| **面板标题** | `purchaseOrderItemList.opsPanel.title` → 中文「采购订单明细」 |
| **目标** | 在右侧「操作」页签就绪时查看该行所属 **采购订单** 与明细摘要，并发起 **到货通知** / **申请付款**（列表门控同销售明细 §2.4）；详情页单击订单明细行时同步展示同一操作面板 |
| **交互规范** | 与 [销售订单明细列表-操作面板 §2.4](销售订单明细列表-操作面板-设计与实现.md) 一致；实现 `useListRightOpsPanelInteraction` |
| **测试对照** | [采购订单明细列表-操作面板-测试对照说明](../QA/采购/采购订单明细列表-操作面板-测试对照说明.md) |
| **与详情页区别** | 详情页底部 `poItemLinePanel` 保留 7 Tab 全链路（概况 / 采购申请 / 付款 / 到货 / 入库 / 库存 / 进项发票）；右侧操作面板为 **采购订单 + 订单明细 + 状态标签 + 申请付款 / 到货通知** 卡片承载日常操作 |

**在采购订单明细列表与采购订单详情路由下** 均注册三页签（操作 + 流程 + 帮助）。默认选中 **操作**；操作/流程共用 `PurchaseOrderItemOpsPanel` / `PurchaseOrderItemFlowPanel` + `purchaseOrderItemOpsPanel` store。离开上述路由时恢复仅「帮助」，并 `clear()` 操作面板 store。

## 2. 布局与交互要求

### 2.1 整体结构

```
┌─ 右侧辅助栏 ─────────────────────────┐
│ [操作] [流程] [帮助]        [全屏][✕] │
├──────────────────────────────────────┤
│  （无选中行）单击列表行查看概况与操作… │
│  或                                  │
│  ┌ 采购订单 ─────────────────────┐   │
│  │ 编号 50%  │  状态 50%         │   │
│  │ 供应商名称（加粗整行）         │   │
│  ├ 订单明细（hero 编号→PN…）─────┤   │
│  ├ （状态标签）                    │   │
│  ├ 申请付款 ─────────────────────┤   │
│  └ 到货通知 ──────────── 已完成 ✓│   │
└──────────────────────────────────────┘
```

- 各卡片 **直接作为页签内容子级** 纵向排列，无额外浮动外层壳；宽度 `100%` 自适应父面板，禁止横向滚动。
- 嵌入模式（`embedded`）使用 `div.so-item-ops-root--embedded`，样式 token 对齐 `--crm-aux-*`。
- 各卡片 **无标题图标**，仅保留文字标题。
- 组件复用 [销售操作面板 §2.5](../销售订单明细列表-操作面板-设计与实现.md) SCSS（`.ops-card`、`.ops-metrics`、`.ops-progress`、`so-item-ops-panel.scss` 等）；到货进度条为绿色渐变，请款进度条为橙色渐变。

### 2.2 列表交互

| 操作 | 行为 |
|------|------|
| **单击行** | 见 [销售操作面板 §2.4](销售订单明细列表-操作面板-设计与实现.md)（A～F）；采购实现于 `PurchaseOrderItemList` + `useListRightOpsPanelInteraction` |
| **双击行** | 跳转采购订单详情 `PurchaseOrderDetail`，query 带 `purchaseOrderItemId`（优先级高于单击） |
| **选中行高亮** | 表格 `row-class-name`：`so-item-row--active` |
| **敏感字段脱敏** | `maskPurchaseSensitiveFields === true` 时：**仍加载**面板；敏感字段 `—`；按钮按角色权限 |

### 2.3 右栏展开 / 收起与接口

**混合数据源 + 按需请求**（见 §4）。门控与加载时机同销售 §2.4（`selectRow` / `setRowOnly` / `loadAggregates`）。列表刷新 `resetListRightPanelOnReload` 清空 store；离开路由 `clear()`。

**详情页：** 单击明细行打开底部 `poItemLinePanel` 并请求聚合；**不**强制 `setRightActiveTab('r-ops')`；加载完成后可 `syncRowAndAggregates` 写入操作面板 store。

### 2.4 列表页移除的遗留 UI

改造前 `PurchaseOrderItemList.vue` 底部存在 `poItemLinePanel`（7 Tab 明细面板），**从未在列表页打开**（`visible` 恒为 `false`），属于死代码。改造后：

- **删除** 列表页 `poItemLinePanel` 模板、`lineTabAggregates` 状态及相关 helpers；
- **保留** 列表页「通知到货」「申请付款」弹窗及 `openArrivalDialog` / `openPaymentDialog`；
- **保留** `PurchaseOrderDetail.vue` 底部 `poItemLinePanel` 不变。

## 3. 卡片 — 功能与 UI 要求

### 3.0 采购订单

**标题：**「采购订单」（`purchaseOrderTitle`）

**位置：** 操作页签内容区 **最上方**（在「订单明细」之前）。

**展示规则：** 与订单明细中的普通字段同一套 `.ops-overview-line`（**13px / 500**，**不是**明细编号的琥珀色 Hero）。**采购订单编号与状态同一行，各占行宽 50%**；编号可点进详情，**无下划线**（含悬停）。**供应商名称在最下一行**（整行、**加粗**）。

| 行 | 内容 | 字段 | 样式 |
|----|------|------|------|
| 1 左 50% | 采购订单编号 | `purchaseOrderCode` | 普通字段；有 `purchaseOrderId` 时用 `.ops-po-code-link` 点进采购订单详情，无下划线 |
| 1 右 50% | 状态 | `orderStatus` | 采购主单状态文案（`purchaseOrderMainStatusLabel`）。**审核通过(10)**、**待确认(20)** 在状态后追加斜体浅灰「（等待供应商确认）」（`.ops-po-status-hint`，`$text-muted` + `font-style: italic`，文案 `purchaseOrderStatusAwaitingVendorHint`）；其余状态只显示主单状态文案 |
| 2 整行 | 供应商名称 | `vendorName` / `vendorEnglishName` | `VendorNameReadonlyText`（中英合并；英文空则只显示中文；脱敏为 `—`）；**加粗**（`font-weight: 700`） |

**数据来源：** 列表行 `row`（列表 API / 详情 `poDetailLineToListShape` 均含 `purchaseOrderCode`、`orderStatus`、`purchaseOrderId`、供应商名）。

### 3.1 订单明细

**标题：**「订单明细」（`overviewTitle`，非「概况」）

**展示规则：** 去掉 Key 标签，仅左对齐 Value 文本行：

| 顺序 | 内容 | 字段 | 样式 |
|------|------|------|------|
| 1 | 采购明细编号 | `purchaseOrderItemCode` | 琥珀色 `$color-amber`，18px 加粗 |
| 2 | 物料型号 | `pn` | 常规 |
| 3 | 品牌 | `brand` | 常规 |
| 4 | 采购单价 + 币别 | `cost`, `currency` | `formatUnitPriceWithCurrencyCodeSuffix`，如 `19.50 USD` |
| 5 | 数量 | `qty` | `{qty} pcs`，不加粗、不用强调色 |

**数据来源：** 列表行 `row`。供应商名称已移至 §3.0「采购订单」卡片。

### 3.2 到货通知

| 元素 | 要求 |
|------|------|
| 指标 | **已通知数量** / **可通知数量**（两列大数字） |
| 进度条 | 高度 **10px**；已通知 / 订单量；绿色渐变（`ops-progress__bar--arrival`）；**不显示**百分比文案 |
| 状态文案 | 不显示「当前可申请」；仅在禁用时显示 `arrivalDisabledHint` |
| 禁用提示 | 摘要 + `nextStep`（`applyArrivalDisabledHint.ts`） |
| 按钮 | 权限 `purchase-order.read`；文案「通知到货」 |
| 按钮样式 | 可用：深蓝 `#0f4c81`；不可用：灰底 `#e5e7eb` |
| **生成单号** | 「到货通知单号」；`aggregates.arrivalNotices`；点进到货通知列表（`noticeId`）；样式同申请付款，见 [操作规范 §7.6](../PRD/规范/UI规范/扩展窗口页签-操作规范.md) |
| **已完成** | 见 §3.4 |

**数量口径：**

| 指标 | 列表行字段 | 聚合补充（优先） |
|------|------------|------------------|
| 订单量 | `qty` | `lineOverview.arrivalNotice.total` |
| 已通知 | `qtyStockInNotifyExpectSum` | `lineOverview.arrivalNotice.done` |
| 可通知 | `qtyStockInNotifyNot`（缺省则 `qty − 已通知`） | `lineOverview.arrivalNotice.pending` |

**门槛：** `itemStatus === 30`（`PO_STATUS_VENDOR_CONFIRMED`，供应商已确认）。

**按钮点击：** store `runApplyArrival` → 列表页 `openArrivalDialog` → `buildPurchaseArrivalNoticeLineRow`。

### 3.3 申请付款

| 元素 | 要求 |
|------|------|
| 指标 | **已申请金额** / **可申请金额**（两列）；金额与币别 **折行两行显示**（上：金额，下：ISO 币别 + `dock-tier-ccy` 配色） |
| 进度条 | 10px 高；已申请金额 / 明细总额；橙色渐变；无百分比文案 |
| 状态文案 | 禁用时 `paymentDisabledHint` |
| 按钮 | 权限 `finance-payment.write` **或** `purchase-order.write`；文案「申请付款」 |
| 按钮样式 | 同到货通知 |
| **生成单号** | 「付款单号」；`aggregates.payments`（未删除、未取消）；点进付款单详情；**参考实现**（其它操作+进度卡片对齐本卡） |
| **已完成** | 见 §3.4 |

**金额展示格式：**

```
39,000.00        ← formatTotalAmountNumber（第一行，20px 加粗）
USD              ← listAmountCurrencyIso + dock-tier-ccy--*（第二行，12px）
```

**请款口径（重要）：** 本卡片度量的是 **请款申请** 进度，**不得** 使用详情页概况矩阵 `lineOverview.payment`（该列为 **已付** `PaymentAmountFinish` / **待付** `PaymentAmountNot`）。

| 指标 | 计算 |
|------|------|
| 明细总额 `lineTotal` | 行 `lineTotal`，缺省 `qty × cost` |
| 已申请金额 | `paymentRequestedAmount`（扩展表 `PaymentAmountRequested`） |
| 可申请金额 | `max(0, lineTotal − paymentRequestedAmount)` |

**业务门槛（`canApplyPayment`）：** 后端列表 API 与详情 `GetById` 计算（已确认及之后仍可分批请款）：

```csharp
canInitiatePaymentFromPo
  && PaymentProgressStatus < 2   // 扩展表：已核销合计 < 行采购总额（未到付款完成）
  && (ItemStatus >= 30 || OrderStatus >= 30)
```

`PaymentProgressStatus` / `FinancePaymentStatus` 均按 **已核销合计 vs 行采购总额**（`qty × cost`）计算，**不是** vs 已请款。列表 `canApplyPayment` **优先用扩展表进度**，避免历史行 `finance_payment_status` 仍为旧口径时误拦。第一笔请款付清后，只要已付仍小于行总额，状态为部分付款，允许再请剩余款。

列表 JSON 另下发 `orderStatus`、`financePaymentStatus`，供前端禁用提示按本行直接原因分支（见 §3.5）。**在途请款**（未取消/未审核失败的付款单占用已申请金额）**不是** `canApplyPayment` 的阻断条件；请款已满时由前端 `可申请金额 ≤ 0` 灰按钮。禁用文案不得写「可能已有在途请款」。

**按钮点击：** store `runApplyPayment` → 列表页 `openPaymentDialog`（与操作列共用弹窗）。

### 3.4 「已完成」态（到货通知 / 申请付款）

标题栏 **右侧** 显示绿色对钩（`CircleCheck`）+ 文案「已完成」；**隐藏**操作按钮、禁用提示与进度条。指标下方展示生成对象单号（可点击跳转），布局对齐 [操作规范 §7.6](../PRD/规范/UI规范/扩展窗口页签-操作规范.md)。

| 卡片 | 判定条件 | 生成单号 |
|------|----------|----------|
| 到货通知 | `可通知数量 ≤ 0` **且** `已通知数量 ≥ 订单量` | `aggregates.arrivalNotices` → 到货通知列表 |
| 申请付款 | `可申请金额 ≤ 0` **且** `已申请金额 ≥ 明细总额` | `aggregates.payments`（未删除、未取消）→ 付款单详情 |

### 3.5 禁用提示分支

**到货通知**（`applyArrivalDisabledHint.ts`）：

| 条件 | summary i18n key |
|------|------------------|
| `itemStatus ≠ 30` | `arrivalNeedConfirmed` |
| `可通知 ≤ 0` | `arrivalNoRemaining` |

**申请付款**（`applyPaymentDisabledHint.ts`）：互斥，只展示**当前成立的一条直接原因**，禁止「可能…」兜底。操作面板传入 `canInitiatePayment`（`finance-payment.write` 或 `purchase-order.write`）。判定顺序：

| 顺序 | 条件 | summary i18n key |
|------|------|------------------|
| 1 | 无申请付款权限 | `paymentNoPermission` |
| 2 | 明细或主单已取消 / 审核失败（`-1` / `-2`） | `paymentCancelled` |
| 3 | 未达供应商确认（主单与明细均 `< 30`） | `paymentNeedConfirmed` |
| 4 | `FinancePaymentStatus >= 2`（已核销合计 ≥ 行采购总额）**且** 存在未删除付款单 | `paymentFinanceDone`；只列出未删除付款单号 |
| 4′ | `FinancePaymentStatus >= 2` 但仅有已删除付款单 / 无活单 | **不阻断**申请付款（视为过期状态）；**不展示**已删除付款单号 |
| 4a | `FinancePaymentStatus` 为未付款/部分付款，可申请 **> 0**（含第一笔已付清、行总额未付完） | **不阻断**；按钮可点（分批请款） |
| 5 | 可申请金额 ≤ 0 | `paymentNoRemaining` |

`nextStep` 与上表同一原因对应的 `paymentNext*`。货款已付清且存在未删除付款单时用 `paymentNextFinanceDoneWithDocs`。已删除 `paymentNotEligible` / `paymentNextNotEligible`。

聚合 `payments` 可含软删除单据（`isDeleted`）。操作面板只列出未删除付款单。删除付款单后须重算采购明细 `FinancePaymentStatus`（`DeleteCoreAsync` → `SyncPurchaseFinanceStatusAsync` / 扩展 `RecalculateAsync`）。历史行可在采购订单详情「刷新扩展」按新公式回写。

## 4. 数据来源

### 4.1 总览

| 数据块 | 主要来源 | 补充来源 |
|--------|----------|----------|
| 采购订单卡片 | 列表行 `purchaseOrderCode`、`orderStatus`、`purchaseOrderId`、`vendorName`、`vendorEnglishName` | — |
| 订单明细卡片 | 列表行 `row` | — |
| 到货通知数量 | 列表行 `qtyStockInNotify*` | 聚合 `lineOverview.arrivalNotice`（展示优先）；单号用 `arrivalNotices` |
| 申请付款金额 | 列表行 `lineTotal`、`paymentRequestedAmount` | **不用** `lineOverview.payment` |
| 按钮禁用 / 提示 | 列表行（与 utils 共用） | 货款已付清时用 `aggregates.payments` 展示付款单号；到货单号用 `arrivalNotices` |

### 4.2 聚合接口

```
GET /api/v1/purchase-orders/{purchaseOrderId}/items/{purchaseOrderItemId}/detail-tab-aggregates
```

- 与采购订单 **详情页** 单条明细 aggregates **同一 DTO**（`PurchaseOrderDetailTabAggregates`）。
- 列表操作面板当前主要使用：`lineOverview.arrivalNotice`（到货数量展示）；`arrivalNotices`（到货通知单号）；`payments`（付款单号）。
- **申请付款卡片不读取** `lineOverview.payment`（概况付款列语义不同，见 §3.3）。
- 接口在右栏展开且选中行变化时按需请求；收起时仅缓存列表行。

### 4.3 列表接口关键字段

`PurchaseOrdersController.MapPurchaseOrderItemListLines` 下行对象需包含：

| 字段 | 用途 |
|------|------|
| `purchaseOrderCode`, `purchaseOrderId`, `orderStatus` | 顶部「采购订单」卡片 |
| `purchaseOrderItemId`, `purchaseOrderItemCode` | 选中、跳转、聚合 scope |
| `vendorName`, `vendorEnglishName` | 顶部「采购订单」卡片最末行 |
| `pn`, `brand`, `qty`, `cost`, `currency`, `lineTotal` | 摘要 / 请款计算 |
| `itemStatus` | 到货门槛（≥30=已确认及之后） |
| `orderStatus` | 主单状态；申请付款确认门槛与取消判定 |
| `financePaymentStatus` | 明细财务付款状态（0 未付 / 1 部分 / 2 付款完成）；与扩展 `paymentProgressStatus` 同一口径：已核销 vs 行总额；`>= 2` 不可再请款 |
| `qtyStockInNotifyExpectSum`, `qtyStockInNotifyNot` | 到货指标 |
| `paymentRequestedAmount` | 已请款金额（需 `purchase.amount.read`） |
| `canApplyPayment` | 申请付款业务门槛（权限 + 未付款完成 + 已确认） |

## 5. 权限

| 能力 | RBAC / 条件 |
|------|-------------|
| 查看列表与操作面板 | `purchase-order.read`（随列表） |
| 供应商名 / 英文名 | `vendor.info.read` 等；`maskPurchaseSensitiveFields` 时面板不可用 |

| 通知到货按钮 | `purchase-order.read`（`canPurchaseOrderItemOpsArrival`） |
| 申请付款按钮 | `finance-payment.write` **或** `purchase-order.write`（`canPurchaseOrderItemOpsPayment`）；`isSysAdmin` 或角色 `SYS_ADMIN` 视为有权限 |

## 10. 测试与回归要点

1. 进入采购订单明细列表后右栏有 **操作 + 流程 + 帮助**；离开本页后恢复仅 **帮助**。
2. 单击行：展开右栏、操作页签、高亮行；最上方卡片标题「采购订单」，编号与状态**同一行且各占 50%**；**供应商名称在该卡片最下一行且加粗**（不在订单明细卡片）；编号为 13px 常规字（非琥珀色加粗、**无下划线**）；状态为采购主单状态，**审核通过 / 待确认** 须带斜体浅灰「（等待供应商确认）」，已确认及之后只显示状态本身；有单号时可点进采购订单详情；双击仍进详情并带 `purchaseOrderItemId`。
3. **右栏收起**时单击：Network **无** `detail-tab-aggregates`；展开后出现请求。
4. 供应商英文名为空：「采购订单」卡片供应商行只显示中文名（无单独英文行）。
5. 到货全部通知完成：标题「已完成」+ 绿勾，无按钮、无进度条；指标下展示可点击的 **到货通知单号**。
6. 请款已全部申请：同上；展示可点击的 **付款单号**；**已申请金额** 显示请款累计，非已付金额。
7. 未满足条件：灰按钮 + **本行直接原因** + 对应 `nextStep`（无权限 / 取消 / 未确认 / 货款已付清 / 请款已满）；**不得**出现「可能已有在途请款」类兜底。第一笔已付清但行总额未付完（可申请 > 0）时按钮应可点。仅当已核销合计 ≥ 行总额时才提示货款已付清并列出 **付款单号**；付款记录不要用采购订单号去筛「付款单号」。
8. 申请付款金额区：金额与币别 **两行** 显示，币别颜色与列表金额列一致。
9. 请款已满但已付为 0：面板应显示已申请满额，**不应**误显示已申请 0 却提示已满（回归 §8.1 口径）。
10. 通知到货 / 申请付款弹窗提交后 `loadList` 刷新，面板 `refreshOpsPanelIfOpen` 同步。
11. 脱敏开启：仍可加载面板；敏感字段为 `—`；无权限按钮按角色隐藏/禁用。
12. 从销售订单明细列表切到采购列表（或反向）：对方 store 已清空，仅显示对应面板。
13. 窄右栏：无横向滚动，长供应商名可换行。
