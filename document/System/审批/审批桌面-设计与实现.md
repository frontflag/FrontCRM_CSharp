# 审批桌面（审核桌面）设计与实现

**状态：** MVP  
**路由：** `/approval-desktop`（标题：审核桌面）  
**关联：** 待审批页 `/pending-approvals`（并存入口）

---

## 1. 产品目标

将待审队列、上一条/下一条导航、审批表单、右侧参考信息合并为单页，支持连续审批作业。

- 与「待审批」列表+弹窗模式**并存**；不做「Approve All」批量通过。
- 入口：待审批页右上角「审核桌面」按钮。
- 顶栏统计始终为**全局待审**分项计数（不随左栏类型过滤变化）。
- 通过/拒绝后刷新队列并**自动选中下一条**（若无下一条则选中列表末条或清空）。

---

## 2. 页面结构

待审队列与调查/行参考均使用 **AppLayout 左右扩展面板页签**（与列表页同一工作台模式），**不是**审核桌面主区内的独立左右栏。

```text
┌─ 左扩展 ─┬──────────────────────────┬─ 右扩展 ──────────┐
│ 待审队列  │ 顶：上一条 | 统计 | 下一条 │ 客户/供应商调查   │
│ +类型过滤 │ 中：审批表单（嵌入）     │ SO/PO 行卡片 / 帮助│
└──────────┴──────────────────────────┴────────────────────┘
```

| 区域 | 行为 |
|------|------|
| 左扩展「待审核」 | 仅路由 `ApprovalDesktop`；`/pending-approvals` 不注册待审队列（左栏恢复默认检索/收藏/历史占位）；条目首行「类型标签 + 单据编号」同行 |
| 顶栏 + 中栏 | 全局待审统计；上/下一条；`ApprovalAuditWorkspace`（`embedded=true`） |
| 右扩展 | 随当前审核类型动态页签（调查 / 销售或采购行）+「帮助」；与列表页右栏同级 |

---

## 3. 右侧页签规则

| 审核类型 | 页签 |
|----------|------|
| CUSTOMER | 客户调查 |
| VENDOR | 供应商调查 |
| SALES_ORDER | 客户调查 + 销售订单（概况/明细） |
| PURCHASE_ORDER | 供应商调查 + 采购订单（概况/明细） |
| FINANCE_PAYMENT | 供应商调查 |
| FINANCE_RECEIPT | 客户调查 |

调查面板复用 `CustomerIntelPanel` / `VendorIntelPanel`（Pinia `bindContext`）。

### 销售/采购订单页签（概况 + 明细）

| 页签 | 面板 | 字段 |
|------|------|------|
| 销售订单 | 订单概况 | 销售订单编号、客户名称、创建日期、销售员账号 |
| 销售订单 | 订单明细 | 订单明细编号、物料型号、品牌、销售单价+币别、数量、报价利润（`quote.profitUsd`） |
| 采购订单 | 订单概况 | 采购订单编号、供应商名称、创建日期、销售员账号（无则采购员） |
| 采购订单 | 订单明细 | 订单明细编号、物料型号、品牌、采购单价+币别、数量、采购利润（`purchaseProfitExpected`；无关联则 —） |

## 4. 前端实现要点

| 文件 | 职责 |
|------|------|
| `views/Approvals/ApprovalDesktop.vue` | 顶栏导航 + 中栏审批表单；绑定调查 store / partyContext |
| `components/Approvals/ApprovalDesktopQueuePanel.vue` | 左扩展「待审」页签内容 |
| `stores/approvalDesktopQueue.ts` | 待审队列、选中态、partyContext（左右扩展与主区共享） |
| `layouts/AppLayout.vue` | 注册左「待审」、右调查/行卡片/帮助页签并挂载面板 |
| `components/Approvals/ApprovalAuditWorkspace.vue` | 原审核弹窗内容；`embedded` 嵌入桌面 |
| `components/Approvals/ApprovalOrderLineCards.vue` | SO/PO 订单概况 + 明细面板与利润加载 |
| `views/Approvals/PendingApprovals.vue` | 入口按钮；弹窗仍用 Workspace |

权限：与待审批相同（登录即可进入桌面；决定权限仍由 `canDecide` / 后端 decide 校验）。敏感字段掩码沿用销售/采购掩码 composable。

---

## 5. API（复用）

- `GET /api/v1/approvals/items?state=pending`
- `GET /api/v1/approvals/summary`（可按 `bizType` 分项）
- `POST /api/v1/approvals/pending/decide`
- `GET /api/v1/sales-orders/{id}/sell-order-items/{itemId}/line-profit`
