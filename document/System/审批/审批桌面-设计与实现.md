# 审批桌面（审核桌面）设计与实现

**状态：** MVP  
**路由：** `/approval-desktop`（标题：审核桌面）  
**关联：** 待审批页 `/pending-approvals`（并存入口）  
**测试对照：** [审批桌面-测试对照说明](../../QA/审批/审批桌面-测试对照说明.md)  
**帮助：** [待审批](../../../help/pages/待审批_MENU_PENDING_APPROVALS.md)

---

## 1. 产品目标

将待审队列、上一条/下一条导航、审批表单、右侧参考信息合并为单页，支持连续审批作业。

- 与「待审批」列表并存：列表「审核 / 仅查看」以及 **待处理分段双击行** 跳转本桌面并定位该条；不做「Approve All」批量通过。已通过 / 已拒绝分段双击仍打开业务详情。
- 入口：待审批页右上角「进入审批桌面」按钮。
- 顶栏统计始终为**全局待审**分项计数（不随左栏类型过滤变化）。
- 通过/拒绝后刷新队列并**自动选中下一条**（若无下一条则选中列表末条或清空）。

---

## 2. 页面结构

待审队列与调查/行参考均使用 **AppLayout 左右扩展面板页签**（与列表页同一工作台模式），**不是**审核桌面主区内的独立左右栏。

```text
┌─ 左扩展 ─┬──────────────────────────┬─ 右扩展 ──────────┐
│ 待审队列  │ 顶：上一条 | 统计 | 下一条 │ 客户/供应商调查   │
│ +类型过滤 │ 中：审批表单（嵌入）     │ SO/PO 行卡片 / 帮助│
└──────────┴──────────────────────────┴────────────────────┘
```

| 区域 | 行为 |
|------|------|
| 左扩展「待审核」 | 仅路由 `ApprovalDesktop`；`/pending-approvals` 不注册待审队列（左栏恢复默认检索/收藏/历史占位）；条目首行「类型标签 + 单据编号」同行 |
| 顶栏 + 中栏 | 全局待审统计；上/下一条；`ApprovalAuditWorkspace`（`embedded=true`）。「业务相关信息」金额为 **数字 + 币别 ISO**（如 `27.00 RMB`），不用 `¥`/`$` 前缀。销售订单中栏为 **客户信息** + **订单概况/订单明细** |
| 右扩展 | 随当前审核类型动态页签（调查 / 销售或采购行）+「帮助」；进入桌面时右栏**展开**。销售订单/客户默认页签为 **客户调查**（「销售订单」页签仍可手点） |

## 3. 右侧页签规则

| 审核类型 | 页签 |
|----------|------|
| CUSTOMER | 客户调查 |
| VENDOR | 供应商调查 |
| SALES_ORDER | 客户调查 + 销售订单（概况/明细） |
| PURCHASE_ORDER | 供应商调查 + 采购订单（概况/明细） |
| FINANCE_PAYMENT | 供应商调查 |

收款单 **不再进入** 待审队列（已取消审核，在收款记录页确认）。历史 `approval_record` 中的 `FINANCE_RECEIPT` 仅作快照；右栏「客户调查」映射可保留给历史记录。

调查面板复用 `CustomerIntelPanel` / `VendorIntelPanel`（Pinia `bindContext`）。

**无调查记录时自动调查：**

- **提交审核（后端）**：客户 / 供应商 / 销售订单 / 采购订单 / **付款** 提交待审后，若对应右栏会展示客户或供应商调查且尚无可用最新报告，则后台异步调用调查接口（不阻塞提交响应）。实现：`IApprovalPartyIntelWarmupService`。**收款单不再提交待审。**
- **打开审批桌面（前端）**：绑定客户/供应商上下文后调用 `ensureLookup`（无报告则 `investigate`）。

### 3.1 销售订单审核展示（本轮已落地）

中栏自上而下：

| 区块 | 说明 |
|------|------|
| 业务相关信息 | 业务类型、业务单号、提交日期、状态、往来方、金额。金额为 **数字 + 币别 ISO**（如 `27.00 RMB`），**不加粗**，不用 `¥`/`$` 前缀；销售掩码为 — |
| 客户信息 | 浅黄底 `#fff8e1`。客户名称、客户类型、结算币别、账期类型、账期天数、信用额度 |
| 订单概况 | 淡青底。销售订单编号、订单类型（客单采购 / 备货采购 / 样品采购）、客户名称、**订单金额**（数字加粗 + 币别）、创建日期、销售员。中栏两列 |
| 订单明细 | 淡青底。标题后条数 `（ n条 ）`（不加粗）；标题行右侧折叠/展开，默认展开，刷新后恢复展开（不写本地记忆）。中栏两列 |
| 订单文件 / 意见 / 历史 | 与其它审核类型相同 |

**订单明细字段顺序（销售）：** 订单明细编号 → 客户订单号（空则 —）→ 物料型号 → 品牌 → 生产日期（`dateCode` 字典文案）→ 交期（仅日期）→ 销售单价+币别 → 数量 → 报价利润（USD）→ 报价利润率。

**报价利润 / 报价利润率：** 数据来自 `GET .../sell-order-items/{itemId}/line-profit` 的 `quote` 层。无报价成本或销售掩码时显示 —。数值后有问号，点击展示公式（与界面文案一致）：

```text
报价利润(USD) = (销售单价 − 报价) × 销售数量
报价利润率     = 销售单价 ÷ 报价     （倍数，界面保留 2 位小数）
```

其中「销售单价 / 报价」取折算美金单价（`convertPrice` / `quoteConvertCost`）。

**右栏：** 进入桌面时右扩展展开；销售订单默认页签 **客户调查**。仍保留「销售订单」页签，内容与中栏订单概况/明细为同一组件（右栏单列）。切换待审条时回到默认「客户调查」。

实现：`ApprovalAuditWorkspace.vue`（客户信息 + 嵌入行卡片）、`ApprovalOrderLineCards.vue`（`mode=sales`，中栏 `columns=2`）、`AppLayout.vue`（默认 `r-customer-intel`）。

### 3.2 采购订单（概况 + 明细）

采购订单概况/明细目前主要在 **右扩展「采购订单」页签**；中栏仍为供应商信息 + 订单金额/交期/采购员等旧布局（**尚未**按 3.1 销售订单中栏结构对齐）。

| 面板 | 字段 |
|------|------|
| 订单概况 | 采购订单编号、供应商名称、创建日期、销售员（无则采购员） |
| 订单明细 | 订单明细编号、物料型号、品牌、交期（行 `deliveryDate` 仅日期）、采购单价+币别、数量、采购利润（`purchaseProfitExpected`；无关联则 —）。标题条数与折叠与销售共用组件 |

## 4. 前端实现要点

| 文件 | 职责 |
|------|------|
| `views/Approvals/ApprovalDesktop.vue` | 顶栏导航 + 中栏审批表单；绑定调查 store / partyContext |
| `components/Approvals/ApprovalDesktopQueuePanel.vue` | 左扩展「待审」页签内容 |
| `stores/approvalDesktopQueue.ts` | 待审队列、选中态、partyContext（左右扩展与主区共享） |
| `layouts/AppLayout.vue` | 注册左「待审」、右调查/行卡片/帮助页签并挂载面板 |
| `components/Approvals/ApprovalAuditWorkspace.vue` | 原审核弹窗内容；`embedded` 嵌入桌面 |
| `components/Approvals/ApprovalOrderLineCards.vue` | SO/PO 订单概况 + 明细面板与利润加载 |
| `views/Approvals/PendingApprovals.vue` | 「进入审批桌面」入口；行内「审核 / 仅查看」与待处理分段双击行均带 `bizType`/`businessId` 跳转桌面 |

权限：与待审批相同（登录即可进入桌面；决定权限仍由 `canDecide` / 后端 decide 校验）。敏感字段掩码沿用销售/采购掩码 composable。

## 5. API（复用）

- `GET /api/v1/approvals/items?state=pending`
- `GET /api/v1/approvals/summary?pendingOnly=true`：COUNT 聚合，返回 `pendingCount` + `byBizType`（有审批权时用业务列表 `TotalCount`，避免拼 5000 条）
- 审核桌面：左栏只等 `items`；统计先用队列回填，再后台一次 `summary?pendingOnly=true` 校正（不再并行 7 次 summary）
- `POST /api/v1/approvals/pending/decide`
- `GET /api/v1/sales-orders/{id}/sell-order-items/{itemId}/line-profit`
