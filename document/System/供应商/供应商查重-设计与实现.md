## 1. 产品需求

### 1.1 目标

避免不同采购员重复创建**同一家**供应商。系统在保存前 / 审批时对照已有档案，**只提醒、不强制拦截**：用户确认后仍可保存；审批人仍可通过对/拒绝。

### 1.2 入口与时机

| 场景 | 何时查 | 结果如何用 |
|------|--------|------------|
| 新建供应商 | 点「转正式」且中文全称校验通过之后 | 有命中则弹窗；取消不创建，确认仍创建 |
| 编辑供应商 | 点「保存」 | 同上；确认仍保存 |
| 保存草稿 | **不查** | — |
| 审批桌面 · 供应商审核 | 选中待审供应商、详情加载完成后自动查 | 中栏展示，**不**拦截通过/拒绝 |
| 销售订单 / 采购订单审核 | **不查、无面板** | — |

新建/编辑：**仅当**中文全称、英文全称、统一社会信用代码、邓白氏相对**本会话上次已确认的查重**有变化时才再请求。指纹按当前输入四字段 `trim` 后拼接，存在页面内存，刷新后失效。

查重接口失败时：新建/编辑 **中止保存** 并提示错误；审批面板显示错误文案，**仍可**通过/拒绝。

### 1.3 比对规则

四字段**分别**精确比对，**任一命中即提醒**。不跨字段（例如把本单中文全称填成别人的英文全称，不算命中）。

| 字段 | 存储 | 预处理 |
|------|------|--------|
| 中文全称 | `vendorinfo.OfficialName` | 去首尾空格 + 去掉中间所有空白（含全角） |
| 英文全称 | `vendorinfo.EnglishOfficialName` | 同上，再 **不区分大小写** |
| 统一社会信用代码 | `vendorinfo.CreditCode`（表单原「税号」标签改名，不另加列） | 同上，再大写 |
| 邓白氏编码 | `vendorinfo.DUNS`（新增 `varchar(20)`，与 `customerinfo.DUNS` 对齐） | 去空白后再去掉 `-`，再大写 |

其它约定：

| 项 | 约定 |
|------|------|
| 空值 | **空不参与比对**（双方都没英文名，不因英文名为空判重复） |
| 四字段全空 | 不查库，返回空列表 |
| 范围 | **含软删、黑名单** |
| 排除自身 | 编辑 / 审批传入 `excludeVendorId` |
| 数据权限 | **专用查重 API，不走采购列表数据范围**；「仅本人」仍能看到他人已建的同一家 |
| 简称 / 别名 | **不参与** |
| 模糊 / 同义 / 拼音 | **不做** |
| Excel 导入 / AI 建档 / 名片识别 | **本期不接** |

命中最多展示 **10** 条（`CreateTime` 新的优先）；超出时 `truncated=true`，界面提示仅列出前 10 条。软删标「已删除」，黑名单标「黑名单」。无详情权限或已删除时名称灰显、不跳转；有权限则新开供应商详情。

### 1.4 展示口径

命中卡片（新建弹窗与审批面板共用）每条为：

```text
已存在供应商，采购员：{名}，创建日期：{日期}
中文全称：…
英文全称：…
统一社会信用代码：…
邓白氏编码：…
```

采购员优先档案上的采购员姓名，缺则按 `PurchaseUserId` 解析用户实名/账号。

新建/编辑弹窗另有确认句与「确认创建 / 确认保存」。审批面板无确认按钮：无命中显示「未发现重复供应商」；加载中显示「正在查重…」。

审批桌面布局：查重面板在 **供应商专属信息** 之下。专属信息仍为浅黄底；查重面板底色/边框与销售订单审核 **订单概况** 相同（浅青 `rgba(0, 212, 255, 0.03)`）。

### 1.5 非目标

- 不替代供应商列表模糊搜（`findSimilarVendors`），二者口径不同，验收勿混用。
- 不在保存接口内再次强制查重（前端提醒 + 专用 API；后端保存不因重复而拒绝）。
- 不做客户查重（本功能仅供应商）。

## 2. 字段与存储

- **统一社会信用代码**：沿用 `vendorinfo.CreditCode`。
- **邓白氏编码**：`vendorinfo.DUNS` `varchar(20)`。创建/更新时 `Trim`，空则 `null`。详情、编辑、字段变更日志均已接。

迁移：`20260911120000_VendorDuns`。**API 启动不自动迁移。** 见 §5。

## 3. 实现方法

### 3.1 归一化与比对

`CRM.Core/Utilities/VendorDuplicateKeys.cs`：

- `NormalizeName` / `NormalizeEnglish` / `NormalizeCreditCode` / `NormalizeDuns`
- `HasAnyKey`：四项归一化后全空则不查
- `IsMatch`：输入侧与库内档案侧分别归一化后，任一非空键相等即命中
- `MaxMatches = 10`

单测：`tests/CRM.Core.Tests/Utilities/VendorDuplicateKeysTests.cs`。

### 3.2 查重数据与服务

1. `IVendorListQuery.GetDuplicateCheckRowsAsync`：`Vendors.IgnoreQueryFilters()`，**不**套列表数据范围，一次取出 Id/编码/四字段/采购员/创建时间/软删/黑名单/归属类型。
2. `VendorService.CheckDuplicatesAsync`（`VendorService.Duplicates.cs`）：
   - 请求体兼容 `officialName`/`name`、`creditCode`/`taxNumber`、`duns`
   - 无任何有效键 → 空结果
   - 内存过滤排除自身 + `IsMatch`
   - 按创建时间倒序截取 10 条
   - `CanViewDetail`：未删除且当前用户 `CanAccessVendorAsync` 为真（列表查重可见 ≠ 能点进详情）

### 3.3 API

`POST /api/v1/vendors/check-duplicates`

- 权限：类级 `vendor.read`（供应商信息读）。**无**方法级 `vendor.write`，以便审批人只读供应商信息时也能查。
- 不套采购列表数据范围；含软删。
- 请求：`excludeVendorId`、`officialName`、`englishOfficialName`、`creditCode`、`duns`（均可空）。
- 响应：`items[]`、`truncated`。

前端：`vendorApi.checkDuplicates`（`CRM.Web/src/api/vendor.ts`）。

### 3.4 新建 / 编辑

`VendorEdit.vue`：

- 「转正式 / 保存」路径调用 `confirmDuplicatesIfNeeded`；草稿保存绕过。
- 有命中则 `el-dialog` + `VendorDuplicateHits.vue`；取消关闭对话框视为放弃保存。
- 信用代码、邓白氏在简称/别名后同一行。

### 3.5 审批桌面

`ApprovalAuditWorkspace.vue`：`bizType === VENDOR` 时中栏 stacked：

1. 供应商专属信息（浅黄 `extra-panel--customer`）
2. 供应商查重（浅青 `extra-panel--order-ref`，与 `ApprovalOrderLineCards`「订单概况」同色）

详情 `getVendorById` 成功后调用 `checkDuplicates`，`excludeVendorId` = 当前待审 `businessId`，四字段取待审供应商详情。用序号丢弃过期请求，避免快速切换待审条时串结果。

命中展示复用 `VendorDuplicateHits.vue`（与新建弹窗同一组件、同一文案）。

### 3.6 实现索引

| 位置 | 说明 |
|------|------|
| `VendorDuplicateKeys` | 归一化与比对 |
| `POST /api/v1/vendors/check-duplicates` | 查重；需供应商信息读 |
| `IVendorListQuery.GetDuplicateCheckRowsAsync` | `IgnoreQueryFilters`，不套列表数据范围 |
| `VendorService.CheckDuplicatesAsync` | 排除自身；`CanViewDetail` 走现有详情权限 |
| `VendorEdit.vue` | 转正/保存前弹窗 |
| `ApprovalAuditWorkspace.vue` | 供应商审核中栏查重面板 |
| `VendorDuplicateHits.vue` | 命中列表（新建弹窗与审批共用） |
| `VendorDuplicateKeysTests` | 空值、大小写、空白、邓白氏连字符、不跨字段 |

## 4. 权限与数据范围

| 能力 | 规则 |
|------|------|
| 调用查重 | `vendor.read` |
| 新建/编辑保存 | `vendor.write`（现有供应商维护） |
| 命中是否出现 | **不受**采购列表「仅本人 / 本部门」限制 |
| 名称是否可点进详情 | `CanAccessVendorAsync`；已删除不可点 |
| 采购敏感掩码 | 查重结果仍展示名称与编码（避免漏建）；详情页邓白氏等按现有掩码 |

## 5. 上线 SQL（PostgreSQL，可重复执行）

```sql
BEGIN;

ALTER TABLE public.vendorinfo
    ADD COLUMN IF NOT EXISTS "DUNS" character varying(20);

COMMENT ON COLUMN public.vendorinfo."DUNS" IS '邓白氏码（D-U-N-S Number）';

INSERT INTO public."__EFMigrationsHistory" ("MigrationId", "ProductVersion")
SELECT '20260911120000_VendorDuns', '9.0.11'
WHERE NOT EXISTS (
  SELECT 1 FROM public."__EFMigrationsHistory" h
  WHERE h."MigrationId" = '20260911120000_VendorDuns'
);

COMMIT;
```

开发库可用 `CRM.DbMigrator --apply --force-dev`，或手工执行以上 SQL。上线后重启 API，浏览器强刷前端。
