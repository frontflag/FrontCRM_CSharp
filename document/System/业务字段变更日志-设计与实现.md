# 业务字段变更日志 — 设计与实现

**适用范围：** 客户、供应商、需求（RFQ）、报价（Quote）、销售订单（SO）、采购订单（PO）六类主数据的**字段级**变更追溯。  
**关联表：** `log_change_fldval`（字段变更）；子实体/明细**删除**另记 `log_operation`（操作日志，本文仅交叉引用）。  
**UI 规范：** [业务详情页面规范 §7.2 / §7.4](../PRD/规范/UI规范/业务详情页面规范.md)  
**维护说明：** 新增可写字段日志的业务模块时，须同步更新本文档对应章节与 `BusinessLogTypes`。

---

## 1. 设计目标

| 目标 | 说明 |
|------|------|
| **可追溯** | 谁在何时将哪个对象的哪个字段从什么值改为什么值 |
| **主从一体** | 详情页一次查询可聚合主表 + 下属子表/明细行的变更 |
| **与操作日志分工** | 字段编辑 → `log_change_fldval`；整段删除、强制删除等 → `log_operation` |
| **展示友好** | 外键 ID 写入前解析为展示名（客户名、用户名等）；枚举/状态写中文标签 |
| **同事务** | 业务 `SaveChanges` **之前**写入变更记录，与业务更新同一事务提交 |

---

## 2. 数据模型

### 2.1 表 `log_change_fldval`

DDL 见迁移 `20260328210000` 与补充脚本 `document/sql/remote_release_supplement_tables_postgresql.sql`。

| 列 | 说明 |
|----|------|
| `BizType` | 业务类型，与 `BusinessLogTypes` 常量一致 |
| `RecordId` | 发生变更的记录主键（主表 Id 或子表/明细 Id） |
| `RecordCode` | 业务编码快照（主表单号、子表编码、`{单号}-L{n}` 等） |
| `FieldName` | 字段英文名（程序用，如 `remark`、`lineAdded`） |
| `FieldLabel` | 字段中文标签（列表「字段」列展示） |
| `OldValue` / `NewValue` | 变更前后展示值；无变化不写行 |
| `ChangedAt` | 变更时间（服务端 `NOW()`） |
| `ChangedByUserId` / `ChangedByUserName` | 操作人；系统自动回写时报价状态用「系统」 |

索引：`("BizType", "RecordId")`、`("ChangedAt")`。

### 2.2 与 `log_operation` 的分工

| 场景 | 存储 | 示例 `ActionType` |
|------|------|-------------------|
| 字段值变化 | `log_change_fldval` | — |
| 新增子行（聚合展示） | `log_change_fldval`，`fieldName=lineAdded` | — |
| 删除子行/明细 | `log_operation` | `需求明细删除`、`报价明细删除`、`销售明细删除`、`采购明细删除` 等 |
| 删除报价整单 | `log_operation` | `报价单删除`（按需求明细行查看，不进更改日志；见 [需求明细已删报价](./需求/需求明细已删报价-设计与实现.md)） |
| 冻结、审核等动作 | `log_operation` | 各模块自定义文案 |

## 3. 通用实现规则（R1–R5）

适用于**主表 + 明细**类单据（需求、报价、销售/采购订单；客户/供应商为**主表 + 多类子实体**，规则同构）。

| 规则 | 说明 |
|------|------|
| **R1 写入时机** | `UpdateAsync` / `CreateAsync` 等在调用 `SaveChangesAsync` **之前**，对比保存前快照与当前实体，逐字段调用 `FieldChangeLogAppender.AppendIfChangedAsync` |
| **R2 BizType** | 主表一条 BizType；明细/子表另一条 BizType（见 §4） |
| **R3 新增明细** | `fieldName=lineAdded`，`fieldLabel` 为「新增明细」或「新增联系人」等；`NewValue` 为摘要行 |
| **R4 删除明细** | **仅** `log_operation`，**不**写 `lineDeleted` 到 `log_change_fldval` |
| **R5 系统自动改状态** | 写 `fieldName=status`；报价成单/关闭等由 `QuoteStatusSyncService` 记操作人「系统」；需求关闭/分配、销售/采购订单审核流转等用实际 `actingUserId`（`actingUserId` 为空时展示「系统」） |

### 3.1 核心工具类

| 类 | 路径 | 职责 |
|----|------|------|
| `FieldChangeLogAppender` | `CRM.Core/Utilities/FieldChangeLogAppender.cs` | 归一化空值、比较差异、`INSERT log_change_fldval` |
| `OperationLogAppender` | `CRM.Core/Utilities/`（各模块注入） | 删除等操作日志 |
| `OperationLogActorResolver` | `CRM.Core/Utilities/` | `actingUserId` → 用户展示名 |
| `BusinessLogTypes` | `CRM.Core/Constants/BusinessLogTypes.cs` | 全系统 BizType 常量 |

写入示例（简化）：

```csharp
await FieldChangeLogAppender.AppendIfChangedAsync(
    _unitOfWork,
    BusinessLogTypes.Rfq,
    rfq.Id,
    rfq.RfqCode,
    "remark", "备注",
    oldVal, newVal,
    userId, userName);
```

### 3.2 查询约定

- 按主单 Id 查询时，SQL `OR` 聚合：主表 `RecordId = 主单Id` **或** 明细/子表 `RecordId IN (SELECT … FROM 子表 WHERE 主单外键 = …)`。
- 列表按 `ChangedAt DESC`。
- 返回 DTO 含 `ObjectLabel`：`主表` 或 `RecordCode`（明细行编码）。

| 模块 | 主表 BizType | 子表/明细 BizType | 明细/子表 RecordCode 示例 |

- **主表：** 公司信息、归属销售、信用、地区等字段；状态变更记 `status`。

## 8. 报价（Quote）

### 8.1 设计范围

- **主表：** 客户、业务员、采购员、报价日期、备注等（`QuoteService.FieldChangeLog.cs`）。
- **明细：** 单条 `QuoteItem` 承载供应商报价阶梯字段（供应商、单价、币别、交期、产地等）；新增记 `lineAdded`。

## 9. 销售订单（Sales Order）

### 9.1 设计范围

- **主表：** 客户名称、业务员、销售助理、订单类型、币别、交期、交货地址、产品种类、客户联系人、开票信息、付款条款、备注、订单总额、折算总额等；`UpdateAsync` 保存前快照对比。
- **明细：** `SellOrderItem` 数量、单价、币别、交期、DC、物料型号、品牌、备注、关联报价、客户订单号/料号/品牌、产品 ID 等；`SyncSellOrderItemsOnUpdateAsync` 更新后逐行对比。
- **状态 R5：** `UpdateStatusAsync` 主状态变更记 `fieldName=status`、`fieldLabel=订单状态`，中文标签（新建/待审核/审核通过/进行中/完成/审核失败/取消）；操作人为 `actingUserId` 解析结果。
- **删除明细 R4：** `AppendSellOrderItemDeleteOperationLogsAsync` → `log_operation`，`ActionType=销售明细删除`（整单删除时为 `销售明细整单删除`）。
- **创建：** `CreateAsync` **不写**字段变更日志（首版明细与主表初始值不记 `lineAdded`）；仅后续 `UpdateAsync` 新增行记 `lineAdded`。
- **删除日志 Tab（配套）：** 详情页另有「删除日志」页签，数据来自 `GetDeletedOrderItemsAsync`（查询 `is_deleted=true` 的明细，并关联 `log_operation` 推断操作人），与 `log_change_fldval` 分工互补。

### 9.2 后端实现

| 项 | 位置 |
|----|------|
| 字段对比与写入 | `CRM.Core/Services/SalesOrderService.cs`（内联，非 partial） |
| 主表/明细写入 | `AddSalesOrderFieldChangeLogAsync`、`AddSellOrderItemFieldChangeLogAsync`（直接 `INSERT log_change_fldval`） |
| 更新接线 | `UpdateAsync` — `SaveChangesAsync` **之后**写主表/明细变更与删除操作日志 |
| 状态变更 | `UpdateStatusAsync` — 状态保存后写 `status` 行 |
| 查询 DTO | `SalesOrderFieldChangeLogDto` in `ISalesOrderService.cs` |
| 删除明细查询 | `SalesOrderDeletedItemLogDto`、`GetDeletedOrderItemsAsync` |
| API | `GET /api/v1/sales-orders/{id}/change-logs` → `SalesOrdersController` |
| 删除明细 API | `GET /api/v1/sales-orders/{id}/deleted-items` |

权限：与详情读一致，经 `IDataPermissionService.CanAccessSalesOrderAsync` 校验。

**实现差异（相对 §3）：** 销售订单未使用 `FieldChangeLogAppender`，且在业务 `SaveChangesAsync` **之后**写入变更行（与需求/报价「同事务、保存前」略有不同，但仍在同一请求内完成）。

### 9.3 前端实现

| 项 | 位置 |
|----|------|
| API | `CRM.Web/src/api/salesOrder.ts` → `getChangeLogs`、`getDeletedItems` |
| 详情 Tab | `SalesOrderDetail.vue` —「更改日志」「删除日志」；页签 `标签 (N)` |
| 表格 | 六列（时间、操作人、对象、字段、原值、新值）；`objectLabel` 直接展示 |
| 敏感字段 | `maskSaleSensitiveFields` 为 true 时隐藏更改/删除日志页签及内容 |
| 预取 | 进入详情后静默预取更改日志条数（与需求/报价一致） |
| 空态 | `DetailListPanelEmpty`（`size="low"`） |

## 10. 采购订单（Purchase Order）

### 10.1 设计范围

- **主表：** 供应商（换 ID 记 `vendorId` 展示「编码 名称」；同 ID 刷名称仍记 `vendorName`）、采购员、采购助理、币别、交期、送货地址、备注、内部备注、订单总额、折算总额、订单类型等；`UpdateAsync` 保存前快照对比。
- **明细：** `PurchaseOrderItem` 数量、单价（cost）、币别、交期、DC、物料型号、品牌、备注、内部备注、关联销售明细、行供应商、产品 ID 等。
- **状态 R5：** `UpdateStatusAsync` 记 `status` / `订单状态`（新建/待审核/审核通过/待确认/已确认/进行中/采购完成/审核失败/取消）；部分状态下会同步明细行 `status`。
- **删除明细 R4：** `LogPurchaseOrderItemsDeletedAsync` → `log_operation`，`ActionType=采购明细删除`（整单删除时为 `采购明细整单删除`）。
- **创建：** `CreateAsync` **不写**字段变更日志；后续 `UpdateAsync` 新增行记 `lineAdded`。
- **供应商名称刷新：** `RefreshVendorNameAsync` 对比主表 `vendorName` 后写变更日志。
- **更换供应商 ID：** 另写 `log_operation`（`ActionType=更换供应商`），见 [采购订单换供应商-设计与实现](./采购/采购订单换供应商-设计与实现.md) §8。
- **删除日志 Tab：** 同销售订单，`GetDeletedOrderItemsAsync` + `GET …/deleted-items`。

### 10.2 后端实现

| 项 | 位置 |

| 字段对比与写入 | `CRM.Core/Services/PurchaseOrderService.cs`（内联） |

| 更新接线 | `UpdateAsync` — `SaveChangesAsync` **之后**写主表/明细变更与删除操作日志 |
| 状态变更 | `UpdateStatusAsync` |
| 查询 DTO | `PurchaseOrderFieldChangeLogDto` in `IPurchaseOrderService.cs` |
| API | `GET /api/v1/purchase-orders/{id}/change-logs` → `PurchaseOrdersController` |
| 删除明细 API | `GET /api/v1/purchase-orders/{id}/deleted-items` |

权限：经 `IDataPermissionService.CanAccessPurchaseOrderAsync` 校验。

### 10.3 前端实现

| 项 | 位置 |
|----|------|
| API | `CRM.Web/src/api/purchaseOrder.ts` → `getChangeLogs`、`getDeletedItems` |

## 12. 扩展新模块检查清单

1. 在 `BusinessLogTypes` 增加主表/明细常量。  
2. 新增 `*Service.FieldChangeLog.cs`（partial）或内联方法：快照、`AppendIfChanged`、查询 SQL。  
3. 在 `Create/Update` 路径接线（推荐 **SaveChanges 前**，与需求/报价一致；销售/采购订单当前为 **SaveChanges 后**）；删除走 `log_operation`。  
4. 控制器增加 `GET …/change-logs`；权限与详情读权限一致。  
5. 前端 API 类型 + 详情（或编辑）Tab + i18n + `businessLogLabels`（若需）。  
6. 单元测试：至少一条主表字段变更 + 一条 `lineAdded`（若有明细）。  
7. **更新本文档**对应章节。

## 13. 已知限制

- **历史数据：** 功能上线前的编辑**不会**回填日志。  
- **API 部署：** 新增路由须重新编译并重启 `CRM.API`；未部署时前端 `change-logs` 返回 404。  
- **客户/供应商 Tab 文案**为「变更日志」；**需求/报价/销售/采购订单**为「更改日志」— 产品用语略有差异，实现等价。  
- **销售/采购订单创建：** `CreateAsync` 不记字段变更与 `lineAdded`，仅 `UpdateAsync` 及状态流转产生日志。  
- **销售/采购订单写入时机：** 字段日志在业务 `SaveChangesAsync` **之后**写入（与需求/报价保存前写入不同）；失败时业务已提交、日志可能缺失。  
- **敏感字段脱敏：** 销售/采购详情在 `maskSaleSensitiveFields` / `maskPurchaseSensitiveFields` 下不展示更改/删除日志页签。  
- **删除日志展示：** 销售/采购「删除日志」来自软删明细表 + `log_operation` 关联，非 `log_change_fldval` 查询。  
- **需求已删报价：** 挂在明细行上查看，数据来自软删报价 + `log_operation`（`报价单删除`），不进入需求「更改日志」页签。
