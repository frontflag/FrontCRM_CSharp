# 销售参数 — 设计与实现

> **状态：** 草案（分面刷新五开关；代码未落地前仍为单开关「刷新客户」）  
> **权限：** 侧栏 `system.params.sales.read`；页内「分面刷新」`system.params.sales.refresh-customer.read` / `.write`（权限码未改）  
> **关联：** [销售订单分面刷新-设计与实现](./销售订单分面刷新-设计与实现.md)、[销售订单下游客户同步-设计与实现](./销售订单下游客户同步-设计与实现.md)

---

## 2. 左栏：分面刷新

| 字段 | 说明 |
|------|------|
| 五个开关 | 刷新客户 / 物料型号 / 品牌 / 数量 / 单价 |
| 存储 | 旧布尔 `System.Sales.AllowRefreshCompletedBizNodes`（客户）与 JSON `System.Sales.RefreshCompletedFacets`（pn/brand/qty/price；customer 与旧布尔同步） |
| API | `GET/PUT /api/v1/sales-params/refresh-completed-facets`；兼容 `GET/PUT …/allow-refresh-completed-biz-nodes` |
| 权限 | `refresh-customer.read` / `.write` |

### 默认

- 刷新客户：**不允许**（沿用现网）
- 型号 / 品牌 / 数量 / 单价：**允许**（避免上线后单价行为倒退）

### 行为口径

- **不允许**：该分面遇到已完结下游 → 整面阻断  
- **允许**：列出已完结单据，详情须确认后才覆盖  
- **刷新状态**不看本页开关  
- 刷新客户允许时：出库通知 / 装箱 / 出库即使已完成也可同步客户；已核销应收与已开票销项不再阻断，但**仍不改写**其客户字段  

编辑换客户保存不套详情 `confirmCompleted`。
