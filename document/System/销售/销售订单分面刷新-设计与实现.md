## 1. 目标与准绳

详情页刷新拆成六项。准绳均为**已保存的销售订单头 / 明细行**，刷新不改这些源字段。

| 分面 | 入口 | 做什么 |
|------|------|--------|
| 刷新状态 | 主按钮 | 只按已有单据事实重算派生状态与进度 |
| 刷新客户 | 下拉 | 同 ID 刷头名称 + 下游（完结门控见销售参数「分面刷新」；须确认才覆盖已完结出库链） |
| 刷新物料型号 | 下拉 | 覆盖销售身份的型号快照（含客户料号） |
| 刷新品牌 | 下拉 | 覆盖销售身份的品牌快照（含客户品牌） |
| 刷新数量 | 下拉 | 对齐出库通知计划量（只收缩超量且未出库的单条通知），再重算总额 / 利润 / 状态 |
| 刷新单价 | 下拉 | 覆盖下游销售价快照，再重算总额 / 利润 / 状态 |

刷新型号 / 品牌**不**改库存层 `purchase_pn` / `purchase_brand`，**不**换 `StockAggregateId`，**不**改 `StockItemCode`。

数量 / 单价会**顺带**刷新状态。刷新状态**绝不**回写 PN、品牌、数量、单价。保存销售明细**不会**自动改下游型号/品牌快照，须显式点本分面。保存仍可能按 Default Recalculate 收缩超量单条出库通知（业务事件，不是详情刷新状态）。

**不是本功能：** 销售订单列表 / 明细列表的列表重查、浏览器 F5。

## 3. API

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/v1/sales-orders/{id}/refresh/preview` | 非状态分面预检：能否刷新、是否有已完结、列出单据。`facet=customer` 可转现网客户预检 |
| POST | `/api/v1/sales-orders/{id}/refresh` | body `{ "facet": "status\|customer\|pn\|brand\|qty\|price", "confirmCompleted": false }` |
| POST | `/api/v1/sales-orders/{id}/refresh-item-extends` | **兼容**：等价 `facet=price`（兼容路径对 price 传 `confirmCompleted: true`） |
| GET | `/api/v1/sales-orders/{id}/sync-downstream-customer/preview` | 现网客户预检；详情刷新客户仍可用 |
| POST | `/api/v1/sales-orders/{id}/sync-downstream-customer` | 现网客户同步；详情须带 `confirmCompleted` 才覆盖已完结出库链 |
| GET / PUT | `/api/v1/sales-params/refresh-completed-facets` | 五个分面开关 |
| GET / PUT | `/api/v1/sales-params/allow-refresh-completed-biz-nodes` | 兼容：读写「刷新客户」开关，与 JSON 的 customer 同步 |

`facet=customer` 在 Facade 内转到现网客户同步结果映射。Debug「刷新销售订单状态」改为 `facet=status`，不再顺带覆盖销售价。

有已完结且参数开时：预检通过后须 `confirmCompleted=true`，否则后端拒绝。参数关且有已完结：预检即阻断，不执行。无已完结：`confirmCompleted` 可 false。刷新状态不走预检门控。

## 4. Recalculate 副作用拆分

`SellOrderItemExtendSyncService.RecalculateAsync` 增加选项：

| 选项 | 出库通知计划量 | 数量校验 |
|------|----------------|----------|
| `Default`（保存、出库、收款等） | 单条超量且未出库则收缩 | 开（`enforceLineQtyOutboundGuards` 仍可单独关掉） |
| `StatusOnly`（刷新状态 / 刷新单价之后 / 刷新数量之后） | 关 | 关 |
| `QtyPlanOnly`（刷新数量的计划量一步） | 单条超量且未出库则收缩 | 开 |

分批出库通知仍**不得**自动扩成整单。刷新型号 / 品牌**不**跑 Recalculate。已出库（`status=100`）通知数量**永不**被本 Recalculate 收缩。

## 5. 各分面下游与调用顺序

Facade：`SalesOrderService.RefreshDownstreamAsync`。

```text
customer → MapCustomerRefreshResultAsync（现网客户同步）
price    → SalesPriceDownstreamSync.ApplyAsync → Recalculate(StatusOnly) → 主状态
pn/brand → IdentityDownstreamSync.ApplyAsync → 不 Recalculate、不换堆
qty      → SyncStockOutNotifyPlanQtyAsync → Recalculate(StatusOnly) → 主状态
status   → Recalculate(StatusOnly) → 主状态
```

不再调用 `RecalculateByPurchasePnAndBrandAsync(销售行 PN, 品牌)`。

### 5.1 刷新状态

重算：明细扩展进度（采购/入库/出库/收款/开票）、利润、出库通知占用、单头主状态。

不改：客户、PN、品牌、数量、单价、出库通知计划量、核销流水、销项票面。

### 5.2 刷新客户

见 [下游客户同步](./销售订单下游客户同步-设计与实现.md)。完结门控走销售参数「分面刷新 → 刷新客户」：关则已完结且客户不一致整面阻断；开则预检列出**将覆盖**的已完结出库通知/装箱/出库单，详情须确认后才执行（`confirmCompleted`）。已核销应收**客户主键**仍不改，名称快照可对齐主数据；已开票销项仍不同步客户字段。编辑页换客户保存仍走 `ApplyAsync`，不套详情确认标志。

### 5.3 刷新物料型号 / 品牌

先按销售行当前值覆盖下游快照（刷新型号只写型号类，刷新品牌只写品牌类）。

| 节点 | 型号 | 品牌 |
|------|------|------|
| 出库通知 | `MaterialCode` ← `sellorderitem.pn` | `MaterialName` ← `brand` |
| 装箱明细 | `Pn` ← `pn` | `Brand` ← `brand` |
| 装箱扩展 | `customer_pn` ← `CustomerPn` | `customer_brand` ← `CustomerBrand` |
| 应收 | `PN` ← `pn` | `Brand` ← `brand` |

**不写：** 采购订单、到货/入库、`stockitem.purchase_pn`/`purchase_brand`、报关 `purchase_pn`/`purchase_brand`、出库明细层、拣货、待报关表（待报关列表型号是读出库通知快照）。

装箱主表 `Pn`/`Brand` 创建时取自销售行（经出库通知）。采购分面也会按库存反查采购行写同一列。后执行者生效。

默认可覆盖已完结展示快照（参数默认允许；关则整面阻断）。覆盖前详情会列出已完结单据并要求确认。

### 5.4 刷新数量

**可改：** 出库通知在「本行恰好 1 条有效通知、尚未出库、且数量 > 销售行数量」时收缩 `Quantity`；然后 `StatusOnly` 重算扩展 / 利润 / 状态。

**禁止改：** 已出库通知数量、实出、库存、装箱、报关实绩、品牌、单价。销售数量小于已实出或小于有效通知合计则失败。

### 5.5 刷新单价

见 [下游销售价刷新](./销售订单下游销售价刷新-设计与实现.md)。写完价快照后用 `StatusOnly` 重算。已完结须预检列出、确认后才覆盖（相对现网「点了就改」的补加）。

## 8. 已完结节点（按分面）

销售参数「分面刷新」五个开关，权限仍用 `system.params.sales.refresh-customer.*`。存储：旧布尔 `System.Sales.AllowRefreshCompletedBizNodes`（客户）与 JSON `System.Sales.RefreshCompletedFacets`（pn/brand/qty/price；customer 与旧布尔同步）。

| 分面 | 默认 | 已完结判定（预检列出） |
|------|------|------------------------|
| 客户 | 关 | 现网将覆盖的：已出库通知、已出库完成装箱、已出库出库单（且客户 ID 不一致）。已核销应收、已开票销项参数关时阻断（仅客户 **ID** 不一致）；参数开时不阻断、仍不改已核销应收主键 / 已开票销项。主键已一致时应收**名称快照**可对齐 |
| 物料型号 / 品牌 | 开 | 出库通知已出库；装箱已出库完成；出库单已出库；应收已核销或已开票匹配 |
| 数量 | 开 | 出库通知已出库（本分面**不**收缩其数量；存在即门控） |
| 单价 | 开 | 装箱已出库完成；库存明细已入账且有售价快照；出库单已出库；应收已核销或已开票匹配 |
| 刷新状态 | — | 不走本门控 |

行为：参数关且有已完结 → 整面阻断。参数开且有已完结 → 必须确认后才刷新。无已完结 → 原确认框即可。

客户默认关：沿用现网 `AllowRefreshCompletedBizNodes`，改已完结单据上的客商身份风险高。型号等默认开：上线前单价分面本来就会覆盖已完结，默认拦住会行为倒退。要允许客户覆盖已完结出库链：打开本页「刷新客户」并保存；详情仍须确认列出的单据。

编辑页换客户保存走 `SalesOrderCustomerDownstreamSyncService.ApplyAsync`，不套详情 `confirmCompleted`。参数关时已完结且客户 ID 仍为旧值则阻断整单保存。
