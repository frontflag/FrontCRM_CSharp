# 销售订单下游客户同步 — 设计与实现

**状态：** MVP 第一期已上线  
**页面：** 销售订单详情 `/sales-orders/:id` → 刷新按钮下拉「刷新客户」  
**测试对照：** [销售订单编辑保存-客户名称-测试对照说明](../../QA/销售/销售订单编辑保存-客户名称-测试对照说明.md)

## 1. 目标

销售订单 **`customer_id` 已修正** 后，将**未出库完成**链路上的下游 `customer_id` 快照同步为订单当前客户；**已出库 / 已核销 / 已开票**单据阻断并提示。

与「刷新扩展」（重算 `sellorderitemextend`）分离，避免误操作。

## 2. 权限

| 项 | 说明 |
|----|------|
| API | `sales-order.write` |
| 数据范围 | `CanAccessSalesOrderAsync` |

## 3. API

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/v1/sales-orders/{id}/sync-downstream-customer/preview` | 预检：同步计数 / 阻断列表 |
| POST | `/api/v1/sales-orders/{id}/sync-downstream-customer` | 执行同步 |

## 4. MVP 第一期：同步 vs 阻断

| 下游 | 同步条件 | 阻断条件 |
|------|----------|----------|
| 出库通知 `stockout_notify` | `status < 100` 且非取消，客户 ID 不一致 | `status = 100` 已出库 |
| 装箱单 `packing` | `status < 100`，客户 ID 不一致 | `status = 100` 已出库完成 |
| 装箱明细扩展 `packing_item_extend` | 随待同步装箱单明细批量 UPDATE | — |
| 出库单 `stock_out` | `status` 非已出库/取消，客户 ID 不一致 | `status = 2` 已出库 |
| 应收 `finance_receivable` | **不同步** | 已有核销记录 |
| 销项发票 `financesellinvoice` | **不同步** | 已开票且客户不一致 |

装箱单列表/详情客户名由 `customer_id` 查主数据展示，**无单独 `customer_name` 列**。

## 5. 前端交互

- 主按钮：仍为「刷新」（`refresh-item-extends`）。
- 下拉 ▾：**刷新客户** → 预检 → 确认 → 同步 → 结果摘要。
