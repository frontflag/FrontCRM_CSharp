## 1. 目标

业务员建单录错销售价、出库后才发现时，在销售订单详情点 **「刷新单价」**，以**当前销售明细行**的单价为准，覆盖下游所有销售价/金额快照。

- **准绳：** 行 `Price` / `Currency` / `ConvertPrice`（改价保存时已重算折算美金；刷新不再取当日汇率）。
- **已完结：** 按销售参数「分面刷新 → 刷新单价」（默认允许）：关则整面拦住；开则详情须列出已核销/已开票等单据并确认后才覆盖。
- **顺序：** 先写下游快照 → 再跑明细扩展 `RecalculateAsync(StatusOnly)`（进度、目标额、利润；不收缩出库通知计划量）。

与「刷新客户」分离：客户同步仍有完结门控；本能力只改销售价快照。总入口见 [分面刷新](./销售订单分面刷新-设计与实现.md)。

## 3. API

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/v1/sales-orders/{id}/refresh` `facet=price` | 分面入口 |
| POST | `/api/v1/sales-orders/{id}/refresh-item-extends` | 兼容：等价 `facet=price`（`confirmCompleted: true`） |

结果在原 `SalesOrderItemExtendRefreshResult` 上增加：装箱/库存/出库扩展/出库单头/应收更新计数、单价变化行、应收超额警告。

## 4. 下游覆盖清单

| 节点 | 字段 | 新值 |
|------|------|------|
| 装箱明细扩展 `packing_item_extend` | `Price` / `PriceCurrency` / `PriceConvertPrice` | 行单价、币别、`ConvertPrice` |
| 库存明细 `stockitem` | `SalesPrice` / `SalesCurrency` / `SalesPriceUsd`，并 `SyncDenormalizedComputedFields()` | 按 `SellOrderItemId` |
| 出库明细扩展 `stock_out_item_extend` | `SalesPrice` / `SalesCurrency` / `SalesPriceUsd`，按本行出库数量重算 `ProfitOutBizUsd` | **用销售行新价写，不从旧库存层抄** |
| 出库单头 `stock_out.TotalAmount` | `Σ(出库数量 × 该行销售单价)` | 一单多行：本单行用新价，其它行用各自扩展上的价 |
| 应收 `finance_receivable` | `UnitPrice`、`Currency`、`Amount = OutboundQty × 新单价` | 按 `SellOrderItemId`；无状态拦截 |
| 销售行扩展 | `RecalculateAsync(StatusOnly)` | 快照写完后再跑；不收缩出库通知 |

应收余额：

```text
VerifiedDone / InvoiceMatchDone 保留
VerifiedToBe = Amount − VerifiedDone
InvoiceMatchToBe = Amount − InvoiceMatchDone
状态按新总额与已完成额重标（FinanceVerificationStatusCode.Resolve）
```

允许 `VerifiedDone > Amount` 或 `InvoiceMatchDone > Amount`（不拦截）；结果里列出警告（应收编号、已核销/已匹配、新总额、待核销/待匹配可为负）。

### 4.1 明确不改

- 收款 / 预收核销流水金额
- 销项发票票面
- 报关申报单价
- 采购价 / 入库成本

## 5. 操作日志

`log_operation`：`BizType=SalesOrder`，`ActionType=刷新销售价`。记录操作人、单价变化行（旧→新）、装箱/库存/出库/应收条数；超额警告写入 `ExtraInfo`。

## 7. 前端

- 入口：下拉 **刷新单价**；确认前先预检，有已完结则列出单据。
- 确认文案说明会覆盖下游销售价（含已出库/已核销/已开票），不改收款流水与发票票面。
- 结果弹窗展示下游计数、单价变化行、应收超额警告。
- 仅扩展无变更但快照有更新时，**不**显示「无更新数据」。
