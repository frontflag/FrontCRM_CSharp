## 1. 目标

在报关明细列表右栏画出与报关单相同的 10 站地铁轴。锚是 **当前这一行报关明细**，不是整张报关单。

右栏页签：**流程 + 帮助**。无操作、无客户页签。进入页默认 **流程**。

双击一行仍进入报关单详情。报关单列表 / 详情的流程仍按整张报关单画轴，见报关单流程文档。

---

## 2. 收口

| 站 | 本页看到的单据 |
|----|----------------|
| 销售订单明细、销售出库通知、待报关、报关出库通知 | 只挂本行对应的那一张 |
| 报关装箱、报关 | 仍是报关单头。装箱与报关单 1:1。报关站数量仍是整张报关单的申报数量合计 |
| 报关出库 | 只挂本行拣货明细 `picking_task_item_id` 对应的出库单。没有拣货明细时该站为空 |
| 报关到货、报关质检、报关入库 | 只挂本行 `customs_declaration_item` 绑定的下游 |

当前站仍是 **报关**（`FlowYouAreHereMark`）。不另开「报关明细」站。报关明细没有自己的流程状态，结关和作废在报关单头上。

同站多卡按创建时间升序。空站仍画「未开始」。不含拣货站。

---

## 3. 字段与站点章

卡片字段、客户排版、报关图标与报关单流程相同，套用 [流程页签规范 §2.5～§2.8](../../PRD/规范/UI规范/流程页签规范.md)。

- 报关当前站不出客户；报关公司只出现在这一站。
- 511 / 521 仍加载聚合，敏感字段显示 `—`。报关公司不按供应商脱敏。

站点章按 [流程页签规范 §0.4](../../PRD/规范/UI规范/流程页签规范.md)，与报关单流程共用 `customsDeclarationFlowPanel.ts`。卡片「状态」仍是单据自己的业务文案。

---

## 4. 交互门控

`dataTabIds: ['r-flow']`，与销售操作面板 §2.4 同构：

| 右栏 | 单击列表行 |
|------|------------|
| 收起 | 不请求 |
| 展开且在「帮助」 | 只高亮，不离开帮助 |
| 展开且在「流程」 | 请求本行聚合 |

列表重新查询后清空已选流程行。从报关单流程切到本页时清空报关单锚；从本页切回报关单列表或详情时清空本行锚，避免用明细 Id 去拉报关单聚合。

---

## 5. API

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/v1/customs-declaration-items/{id}/flow-aggregates` | 模块访问同报关模块。返回体与报关单 `flow-aggregates` 相同 |

实现：`CustomsDeclarationFlowService.GetFlowAggregatesForItemAsync`。先按未删除明细找到报关单，再按本行过滤上下游；装箱与报关单头不按行拆开。

上线：须重启 API 后该路径才可用。
