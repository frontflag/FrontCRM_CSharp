## 1. 问题

装箱确认时按 **装箱明细** 各生成 1 行报关明细；拣货后回写只取该装箱行的 **第一条** 拣货。同一装箱行从两张采购单拣货时，第二段的采购价（P0）与原供应商会丢失。

## 2. 规则

| 项 | 约定 |
|----|------|
| **生成时机** | 装箱确认 **不** 出报关单（仍预检报关公司、境外仓、待报关关联）。仅创建拣货任务壳时也不出单。 |
| **生成点** | 拣货明细 **保存并结案** 后，头+行一次生成。本产品保存拣货即完成任务。 |
| **粒度** | **1 拣货任务明细 = 1 报关明细**。同一装箱行拆成两笔拣货 → 两行报关明细 → 后续可对应两张到货通知。 |
| **唯一键** | `customs_declaration_item.picking_task_item_id` 未删唯一；`packing_item_id` 仅追溯、非唯一。 |
| **改拣货（未试算、未到货）** | 按新拣货行 **自动重建** 报关明细（保留报关单头与单号）。不改装箱明细。前端提示已重建。 |
| **改拣货（已试算或已到货）** | **拒绝保存**，提示先清除费用（及到货）。避免拣货与报关明细脱节。 |
| **补生成** | 须已完成拣货且装箱尚未出库完成；已有有效报关单则跳过。不自动拆历史已试算/已到货的合并行。 |

确认时仍校验报关公司与境外仓，失败则保持「新建」，避免先确认再失败。

## 3. 实现要点

- `CustomsV2FlowService.ValidateCustomsPackingReadyForDeclarationAsync`：确认预检。
- `AssertCanReplacePickingForCustomsAsync`：改拣前拦截已试算 / 已到货。
- `SyncCustomsDeclarationAfterPickingAsync`：按拣货行生成或重建；P0 / 原供应商取自该拣货在库行。
- 报关出库 `ApplyCustomsStockOutExtend` 优先按 `picking_task_item_id` 对齐；无该字段的历史行回退 `packing_item_id`。

## 4. 历史数据

迁移回填：已完成拣货的报关明细写入 **第一条** 匹配拣货行 ID。已试算或已到货的合并行 **不拆分**；新流程只作用于新生成/未锁定重建。
