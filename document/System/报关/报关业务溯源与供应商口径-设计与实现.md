# 报关业务溯源与供应商口径 — 设计与实现

**适用范围：** FrontCRM 报关 **V2 进口**全链路中，**报关入库**（`StockInType=20`）与 **报关出库**（`StockOutType=20`）相关业务记录在 **供应商字段**、**报关公司展示**、**报关单跳转** 上的定稿口径与落地规划。  
**关联文档：** [报关到货通知（手工发起）— 设计与实现](./报关到货通知-设计与实现.md)、[报关 V2 — DDL 与表结构](../../实现方案/报关V2_DDL与表结构.md)、[报关费用方案](./报关费用方案.md)、[EBS 报关业务逻辑](../../EBS/物流/报关.md)、[业务规则总览 §9](../业务规则总览.md)  
**维护说明：** 调整 `VendorId` 语义、列表报关单列、详情溯源区块或统一 Trace API 时，须同步更新本文与各关联文档交叉引用。

**定稿日期：** 2026-07-08

## 1. 背景与问题

报关 V2 将 **境外报关出库** 与 **境内收货** 拆成两段。境内侧沿用通用物流模块（到货通知 → 质检 → 入库），列表与详情均复用「供应商」列/字段。

讨论中需澄清：

1. 报关入库类型到货通知的「供应商」应显示什么？
2. 能否把 **报关公司** 写入各业务节点的 `vendorId`，并在质检、入库、装箱、拣货、出库一路传递？
3. 用户如何 **方便查看对应报关记录**，并在报关记录中查看 **报关公司名称** 及完整报关信息？

---

## 2. 定稿口径（2026-07-08）

### 2.1 两类主数据不可混用

| 概念 | 存储 | 业务含义 |
|------|------|----------|
| **供应商（Vendor）** | `vendor` 表；业务单 `vendor_id` | 物料 **原采购商 / 供货方**；关联采购、应付、请款 |
| **报关公司（Customs Broker）** | `customs_broker` 表；报关单 `customs_broker_id` | 关务 **代理服务商**；关联报关费、代理费，**不是**货权供货方 |

**结论：不在 `vendorId` 中挂报关公司 ID。**

原因摘要：

- `vendor_id` 外键指向 **`vendor` 表**，与 **`customs_broker` 主键不互通**，强行写入会导致列表 join 失败或显示「—」。
- 财务/请款、采购数据权限、库存/报表的「供应商」维度均假设 `vendorId` 为 **采购供应商**；改为报关公司会破坏应付与统计语义。
- 装箱、拣货、报关出库发生在 **境内到货之前**，供应商语义本就是 **原采购供应商**，不是报关公司。

### 2.2 报关入库 / 报关出库业务记录的 `VendorId`

| 业务记录 | `VendorId` 取值 | 说明 |
|----------|-------------------|------|
| 报关到货通知 `stockin_notify` | `customs_declaration_item.vendor_id` 快照 | 生成时由 `BuildCustomsArrivalNotifyAsync` 写入 |
| 质检 `qcinfo` | 继承到货通知（无独立采购链路） | 列表供应商来自通知 |
| 报关入库 `stock_in` | 到货通知 / 报关明细快照 | 详情页标签为 **「原供应商」** |
| 报关出库通知 / 出库单 | 报关明细或在库行快照 | 与采购供应商一致 |

**报关明细 `vendor_id` 来源：** 拣货回写时取自 **在库明细 `stock_item.vendor_id`**（原采购入库快照）：

```text
拣货 → layer.VendorId
  → customs_declaration_item.VendorId（CustomsV2FlowService 拣货回写）
  → stockin_notify.VendorId
  → stock_in.VendorId
```

若列表供应商显示「—」，根因通常是 **在库行 / 报关明细未带回原供应商**，而非「应改挂报关公司」。修复方向是 **补全原供应商快照链路**（P0），不是改 `vendorId` 语义。

### 2.3 报关公司在哪里看

| 信息 | 权威入口 | 其它节点 |
|------|----------|----------|
| 报关公司名称、编码 | **报关单详情**头信息（`CustomsBrokerId` → `customs_broker`） | 可选只读摘要，**不写入 `vendorId`** |
| 海关状态、申报日期、税费 | **报关单详情** + [报关费用方案](./报关费用方案.md) | 入库详情 `StockInCustomsContext` 可展示费用摘要 |
| 全链路上下游单据 | **报关单详情 · 业务记录面板** | 各节点提供 **跳转报关单** 即可 |

**原则：报关单是报关信息的唯一权威入口（Hub）；其它节点做溯源跳转 + 最少摘要（Spoke）。**

## 3. 交互模型：Hub + 轻链接

### 3.1 报关单（Hub）

用户在 **报关单详情** 查看：

- 报关公司（名称、编码）
- 海关状态、申报日期、汇率、税费
- **业务记录面板**（`CustomsDeclarationBusinessRecordsPanel`）：销售/采购/出库/装箱/到货/质检/入库等聚合列表

其它页面 **不重复** 维护完整费用表，避免双源不一致。

### 3.2 各业务节点（Spoke）

| 节点 | 供应商列 | 报关信息（建议） |
|------|----------|------------------|
| 报关出库通知 / 出库单 | 原供应商 | 列或 Tag：**报关单号** → 报关单详情；详情可加轻量「报关信息」条 |
| 装箱 / 拣货 | 原供应商 | 经 `packing.customs_declaration_id` 链报关单 |
| 到货通知 / 质检 | 原供应商 | **报关单号**（经 `customs_declaration_item_id`） |
| 报关入库 / 入库单 | 原供应商（详情标签「原供应商」） | 列表加报关单号；**入库详情已实现**完整 `customsContext` |

列表示例：

```text
供应商              报关单
炬芯科技(深圳)…     BG2026001   ← 点击进入报关单详情
```

**报关公司名称不必强依赖列表列**（列宽、权限、脱敏）；需要时在报关单详情查看。若关务需在列表速览，可增加 **只读** 列 `customsBrokerName`（展示用，不入 `vendorId`）。

### 3.3 详情页轻量「报关信息」条（出库侧）

报关出库通知详情 / 出库单详情建议增加：

```text
报关单：BG2026001（链接）
报关公司：深圳××报关行
[查看完整报关信息 → 报关单详情]
```

**列表侧：** 出库通知列表已实现右侧「报关单」页签（只读摘要），见 [出库通知列表-报关单页签-设计与实现](./出库通知列表-报关单页签-设计与实现.md)。

## 4. 数据链路（关联键）

### 4.1 报关出库侧 → 报关单

```text
stockout_notify (StockOutType = 报关)
  → customs_declaration_item.customs_stockout_notify_id
  → customs_declaration (+ customs_broker_id)
  → customs_broker.cname
```

### 4.2 报关入库侧 → 报关单

```text
stockin_notify (StockInType = 报关, customs_declaration_item_id)
  → customs_declaration_item
  → customs_declaration (+ customs_broker_id)
```

### 4.3 质检 / 入库单

```text
qcinfo / stock_in
  → stockin_notify_id
  → 同上（4.2）
```

### 4.4 装箱

```text
packing.customs_declaration_id
  → customs_declaration（直接）
```

### 4.5 原供应商（与报关单链路独立）

```text
stock_item.vendor_id（在库快照）
  → customs_declaration_item.vendor_id
  → stockin_notify.vendor_id / stock_in.vendor_id
  → 列表「供应商」列（join vendor 表）
```

## 5. 现行实现与缺口

### 5.1 已实现

| 能力 | 实现位置 |
|------|----------|
| 报关入库详情完整溯源 | `StockInCustomsContextQuery` → `StockInEdit.vue`（报关单链接、报关公司、费用、时间线） |
| 报关单业务记录 Hub | `CustomsDeclarationBusinessRecordsQuery` → `CustomsDeclarationBusinessRecordsPanel.vue` |
| 到货通知生成规则 | `CustomsV2FlowService.BuildCustomsArrivalNotifyAsync`（含 `VendorId` = 报关明细快照） |
| 按销售出库通知查报关单 API | `GET /api/v1/customs-declarations/by-stock-out-request/{stockOutRequestId}` |
| 入库列表报关 Tag | `StockInList.vue`（到货通知 tooltip，非报关单号列） |
| 出库列表报关 Tag | `StockOutNotifyList.vue` / `StockOutList.vue` |
| 出库通知列表 · 报关单右栏页签 | `StockOutNotifyList.vue` + `StockOutNotifyCustomsTabPanel.vue`（见 [出库通知列表-报关单页签-设计与实现](./出库通知列表-报关单页签-设计与实现.md)） |
| 出库通知详情轻量报关条 | `StockOutNotifyDetail.vue` → `StockOutCustomsSummaryPanel.vue` |

### 5.2 待补齐（按优先级）

| 阶段 | 内容 | 价值 |
|------|------|------|
| **P0** | 拣货回写 / 在库行补全 **原供应商** → `decItem.VendorId` → 到货/质检/入库 `vendorId` | 供应商列正确 |
| **P1** | 到货通知、质检、入库 **列表** 增加 **报关单号** 可点链接 | 境内物流最常查 |
| **P2** | 报关出库通知、出库单 **列表 + 详情** 轻量报关区块 / 报关单列 | 出库侧对称；**列表右栏「报关单」页签已实现**（[出库通知列表-报关单页签-设计与实现](./出库通知列表-报关单页签-设计与实现.md)）；出库单列表与详情摘要待补齐 |
| **P3** | 装箱 / 拣货详情增加报关单链接 | 关务全链路闭环 |

### 5.3 后端建议（统一 Trace 查询）

新增可复用查询（名称示例 `ICustomsTraceQuery` / `ResolveCustomsTraceAsync`）：

**输入（其一）：** `stockInNotifyId` | `qcId` | `stockInId` | `stockOutRequestId` | `packingId`

**输出（列表/详情共用 DTO）：**

| 字段 | 说明 |
|------|------|
| `declarationId` / `declarationCode` | 跳转报关单 |
| `customsBrokerId` / `customsBrokerName` | **仅展示**，不入 `vendorId` |
| `customsClearanceStatus` | 可选摘要 |
| `vendorId` / `vendorName` | 原供应商，与业务单 `vendorId` 一致 |

列表 API 批量 join，避免 N+1；出库侧可对称实现 `StockOutCustomsContextQuery`。

## 6. 权限与脱敏

| 场景 | 规则 |
|------|------|
| 跳转报关单 | 需 **报关模块读权限**（`CustomsModuleAccess`）；无权限时单号不可点或 Tooltip 提示 |
| 采购脱敏 | 供应商仍走 `PurchaseSensitiveFieldMask511`；与报关模块权限 **正交** |
| 报关公司名 | 在报关单详情展示；列表可选列不受采购供应商脱敏影响 |

## 7. 与 EBS  legacy 的差异说明

EBS 历史文档曾将报关公司（`CustomsDefId`）关联到 **客户表** 特殊客户，与 FrontCRM V2 的 **`customs_broker` 独立主数据** 不同。

FrontCRM V2 定稿：

- **报关公司** → 仅 `customs_declaration.customs_broker_id`
- **列表「供应商」** → 仅 **原采购供应商**（`vendor`）
- **勿** 将报关公司 ID 写入 `vendor_id`
