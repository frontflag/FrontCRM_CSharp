# 报关到货通知（手工发起）— 设计与实现

**适用范围：** FrontCRM 报关 **V2 进口**链路中，境内仓 **到货通知**（`stockin_notify`，`StockInType=20`）的创建规则与实现；后续 **质检 → 报关入库** 仍走通用物流模块。  
**关联文档：** [报关 V2 — DDL 与表结构](../实现方案/报关V2_DDL与表结构.md) §11、[报关业务溯源与供应商口径](./报关业务溯源与供应商口径-设计与实现.md)（**VendorId / 报关单跳转定稿**）、[报关费用方案](./报关费用方案.md)（**生成前须完成费用试算与关税税率**）、[EBS 报关业务逻辑](../EBS/物流/报关.md)（费用公式）、[到货通知 PRD](../PRD/业务功能/物流/到货通知.md)、[入库库存出库业务关系](../EBS/物流/入库库存出库业务关系文档.md)  
**维护说明：** 调整前置条件、API 或 UI 发起点时，须同步更新本文与 `报关V2_DDL` §11。

## 1. 设计背景

### 1.1 业务问题

报关 V2 将 **境外报关出库** 与 **境内收货** 拆成两段：

| 事件 | 含义 |
|------|------|
| **报关出库执行完成** | 境外仓库存扣减，货进入报关通道 |
| **报关到货通知** | 通知 **境内仓** 可以收货 / 待检 |

初版 V2 曾在 **报关出库过账完成时自动** 创建到货通知，导致境内列表过早出现「到货待检」，与关务 **尚未结关** 的事实不一致。

### 1.2 定稿原则（2026-07）

| 原则 | 说明 |
|------|------|
| **关务确认后再通知境内** | 发起点放在 **报关记录（`customs_declaration`）**，由关务人工触发 |
| **结关为硬前置** | `CustomsClearanceStatus = 已结关（100）` 后才允许生成 |
| **物流与关务分工** | 境外出库仍由物流拣货/执行；境内到货通知由关务在报关单上发起 |
| **与采购到货分离** | 报关到货 **无** 采购订单明细入口；字段从报关明细带出 |
| **幂等** | 每个 `customs_declaration_item` 最多一条有效到货通知 |

## 2. 与采购到货通知对比

| 维度 | 采购到货（`StockInType=10`） | 报关到货（`StockInType=20`） |
|------|------------------------------|------------------------------|
| **创建方式** | 采购订单明细页 **人工新建** | 报关单详情/列表 **人工「生成报关到货通知」** |
| **前置** | PO 已确认 | 已结关 + 目标境内仓 + 报关出库已执行 |
| **地域** | 按 PO 币别：RMB→大陆 / 外币→海外 | 固定 **大陆**（`RegionType=Domestic`） |
| **关联键** | `PurchaseOrderItemId` | `customs_declaration_item_id` |
| **PO 字段** | 有 | 空（`PurchaseOrderId` 等为空串） |

## 3. V2 端到端链路（发起点标注）

```text
销售申请出库（人工，可勾选境外仓+报关）
    → 自动：待报关 pendlist + 销售 SOR 待报关(5)

待报关列表（人工）→ 生成报关出库通知(StockOutType=20)

报关装箱确认（人工）→ 自动：报关单 + 报关明细

拣货 + 执行报关出库（人工）→ 境外库存扣减
    ※ 不再自动创建到货通知

报关单（人工）
    → 设置海关状态 = 已结关
    → 【人工】生成报关到货通知  ← 本文核心

到货通知列表（人工）→ 确认到货 → 质检 → 报关入库
    → 自动：pendlist 关闭、销售 SOR 5→10（待装箱）
```

## 4. 手工发起规则

### 4.1 发起点

| 入口 | 说明 |
|------|------|
| **报关单详情** | 主按钮「生成报关到货通知」（`canCreateArrivalNotifies=true` 时显示） |
| **报关单列表** | 海关状态已为「已结关」的行，操作列同按钮 |

### 4.2 前置条件（全部满足）

| # | 条件 | 常量 / 字段 |
|---|------|-------------|
| 1 | 报关单未作废 | `InternalStatus ≠ Voided` |
| 2 | 海关状态 = **已结关** | `CustomsClearanceStatus = 100`（`CustomsClearanceStatusCodes.Cleared`） |
| 3 | 已维护 **目标境内仓库** | `customs_declaration.ToWarehouseId` |
| 4 | 报关明细对应 **报关出库通知已执行出库** | `stockout_notify.Status = 100`（`StockOutRequestStatusCode.StockedOut`），经 `customs_declaration_item.customs_stockout_notify_id` |
| 5 | 该明细 **尚无** 到货通知 | `stockin_notify.customs_declaration_item_id` 唯一（未删） |
| 6 | **报关费用已试算**（定稿 2026-07-08） | 头 `exchange_rate > 0`；行 `duty_rate` 已维护；`tax_included_unit_price > 0`；采购系数已快照。详见《[报关费用方案](./报关费用方案.md)》§7 |

### 4.3 粒度与幂等

- **粒度：** 按 **报关单头** 一次操作，为本单所有 **满足条件且尚未生成** 的明细 **各创建一条** 到货通知。
- **幂等：** 已有到货通知的明细跳过；若全部已生成，API 返回 400「没有可生成的报关到货通知」。
- **部分阻塞：** 若存在「未出库」明细且无待生成行，返回阻塞原因「存在未完成报关出库的明细…」。

### 4.4 阻塞原因（只读展示）

详情接口返回 `arrivalNotifyBlockReason`、`canCreateArrivalNotifies`、`pendingArrivalNotifyCount`、`existingArrivalNotifyCodes`，供关务判断下一步操作。

常见文案：

| 场景 | `BlockReason` |
|------|----------------|
| 未结关 | 海关状态须为「已结关」后才能生成报关到货通知。 |
| 无目标仓 | 请先在报关单上维护目标境内仓库。 |
| 报关出库未完成 | 存在未完成报关出库的明细，请执行报关出库后再生成。 |
| 已全部生成 | 全部明细已生成报关到货通知。 |
| 未填报关汇率 | 请填写报关汇率并完成费用试算。 |
| 未填报关税率 | 请填写报关税率并完成费用试算。 |
| 未完成费用试算 | 请先完成报关费用试算。 |

## 5. 生成数据规则

服务方法：`CustomsV2FlowService.BuildCustomsArrivalNotifyAsync`。

| 字段 | 取值 |
|------|------|
| `NoticeCode` | `ModuleCodes.ArrivalNotice` 流水号 |
| `StockInType` | `20`（`StockInTypeCode.Customs`） |
| `Status` | `10`（到货待检，与采购到货一致） |
| `RegionType` | `Domestic`（大陆） |
| `CustomsDeclarationItemId` | 报关明细主键 |
| `SellOrderItemId` / `Pn` / `Brand` / `VendorId` | 报关明细快照（**`VendorId` = 原物料采购商**，非报关公司；详见 [报关业务溯源与供应商口径 §2](./报关业务溯源与供应商口径-设计与实现.md#22-报关入库--报关出库业务记录的-vendorid)） |
| `ExpectQty` | `DeclareQty` |
| `Cost` | `TaxIncludedUnitPrice > 0` 则取之，否则 `DeclareUnitPrice` |
| `ExpectTotal` | `ExpectQty × Cost`（四舍五入 2 位） |
| `ExpectedArrivalDate` | 生成日（UTC 转 date） |
| `PurchaseOrder*` | 空（非采购链路） |

## 6. 后续链路（自动 / 人工）

到货通知生成之后，与 [到货通知 PRD](../PRD/业务功能/物流/到货通知.md) 一致，**均为人工推进**：

```text
stockin_notify (Status=10 到货待检)
    → 确认到货 → 创建 qcinfo (StockInType=20)
    → 质检通过 → stock_in (StockInType=20)
```

**报关入库完成时自动**（`OnCustomsStockInCompletedAsync`）：

1. 境内 `stock_item.PurchasePrice` 回写为 P1（`TaxIncludedUnitPrice`）  
2. 关联 `customs_pendlist` → `Closed`  
3. 销售出库通知：`PendingCustoms(5)` → `PendingPacking(10)`，`CustomsStatus=Completed`

## 7. API 与权限

### 7.1 生成到货通知

```http
POST /api/v1/customs-declarations/{id}/create-arrival-notifies
```

| 项 | 说明 |
|----|------|
| **Controller** | `CustomsDeclarationsController.CreateArrivalNotifies` |
| **权限** | 报关模块可读 + **物流数据可写**（`LogisticsDataAccessHttp.CanWriteAsync`） |
| **成功响应** | `CreateCustomsArrivalNotifiesResultDto`：`createdCount`、`created[]`（含 `noticeCode`、行号） |
| **失败** | 400 + `InvalidOperationException` 文案 |

### 7.2 详情可读性字段

`GET /api/v1/customs-declarations/{id}` 在 `CustomsDeclarationDetailViewDto` 中附加：

- `canCreateArrivalNotifies`
- `pendingArrivalNotifyCount` / `existingArrivalNotifyCount`
- `existingArrivalNotifyCodes`
- `arrivalNotifyBlockReason`
- 明细行 `arrivalNotifyCode`（已生成时）

内部评估：`CustomsV2FlowService.GetArrivalNotifyReadinessAsync` / `EvaluateArrivalNotifyReadinessAsync`。

## 10. 与旧文档 / 旧实现差异

| 项 | 旧（EBS / 移库方案） | V2 定稿 |
|----|---------------------|---------|
| 境内入账方式 | 报关完成 + **移库一步过账** | **到货 → 质检 → 报关入库**（`stock_in` Type=20） |
| 到货通知触发 | 报关完成 **自动** 或 EBS 状态 `DoneCustoms→NewStockInNotify` | 报关单上 **人工**，且须 **已结关** |
| `POST .../complete` | 移库过账 | **410 废弃** |
| 发起点 | 分散在出库/结关事件 | **报关记录** |

阅读 EBS《报关.md》时：**第 3 章费用公式仍有效**；**步骤 7「自动生成到货通知」及 §4.1 旧状态枚举** 以本文与 V2 DDL 为准。

## 11. 关务操作 checklist

1. 确认各明细 **报关出库已执行**（境外库存已扣）。  
2. 在报关单维护 **目标境内仓库**（若装箱确认时已有默认值，可 PATCH 调整）。  
3. **设置海关状态 → 已结关**。  
4. 点击 **生成报关到货通知**；记录返回的 `STIR…` 单号。  
5. 通知仓库在 **到货通知** 模块按常规流程：确认到货 → 质检 → 入库。  
6. 报关入库完成后，销售侧出库通知自动从 **待报关** 进入 **待装箱**。
