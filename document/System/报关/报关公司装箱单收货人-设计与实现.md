# 报关公司装箱单收货人 — 设计与实现

**状态：** MVP  
**页面：** `/customs/brokers`；报关装箱单打印 `/inventory/packing/:packingId/packing-report`；报关装箱 Invoice `/inventory/packing/:packingId/invoice-report`  
**关联：** [报表规范-装箱单-V2](../../PRD/规范/业务规范/报表规范-装箱单-V2.md) §5.4、[装箱单 Packing List 打印](../物流/装箱单PackingList打印-三租户皮肤-设计与实现.md)、[报关 V2 DDL](../../实现方案/报关V2_DDL与表结构.md) §16.2  
**脚本：** `scripts/customs_broker_print_consignee_postgresql.sql`；EF `20260901080000_CustomsBrokerPrintConsignee`

---

## 1. 背景

报关装箱单发给 **报关公司**。打印页收货人曾强制使用销售订单客户名 + 客户 Ship To，与单据用途不符。

定稿：仅 `packing.StockOutType = 20` 的 **装箱单报表** 与 **装箱 Invoice**，收货人整块（名称、地址、联系人、电话、邮箱）现查 `customs_broker`。销售装箱、装箱列表「客户」列不变。

---

## 2. 主数据

`customs_broker` 新增列（均可空，便于存量迁移；**新建/编辑必填**联系人、电话、地址）：

| 列 | 类型 | 保存 | 打印 |
|---|---|---|---|
| `contact_name` | varchar(100) | 必填 | 联系人 |
| `tel` | varchar(64) | 必填 | 电话 |
| `email` | varchar(200) | 选填 | 邮箱；空则 `—` |
| `address` | varchar(500) | 必填 | 地址（按需印出的原文） |

名称仍用已有 `cname` / `ename`。报表收货人名称固定 **`cname`（中文名）**，不用英文名。不做 521 脱敏。

不建联系人子表。深圳/香港继续用服务方向拆成两条主数据。

---

## 3. 打印装载

`GET /api/v1/packing/{id}/packing-report-bundle` 与 `GET /api/v1/packing/{id}/invoice-report-bundle` 在销售客户地址面板之后调用 `OverlayCustomsBrokerConsigneeAsync`：

1. 非报关装箱 → 不覆盖  
2. 无 `customs_broker_id` 或公司已删 → **400**，提示缺少报关公司  
3. 联系人 / 电话 / 地址任一空 → **400**，提示去「报关公司」补资料  
4. 覆盖 Bill To / Ship To 四行，并写 `PackingAddresses.Email`

出库单路径 `stock-out/{id}/packing-report-bundle?packingId=` 同样覆盖。销售装箱 Invoice **不**覆盖。

前端：报关类型用送货第一行作收货人名称，**不**再用销售客户名覆盖，**不**因 521 打成 `—`。Invoice 另在地址块补邮箱行。

报关装箱 Invoice 单价取装箱行销售价 `packing_item_extend.Price`，币别取 `PriceCurrency` 按行打印（如 `6.75 RMB`）；表头不再写死 USD。

---

## 4. 装箱创建

选择报关公司后预填送货/账单公司、地址、联系人、电话（方便仓库）。报表仍以主数据为准。

所选报关公司收货人资料不齐时，**禁止生成装箱单**（与拒打同一口径）。

---

## 5. 存量

上线后已有报关公司须再编辑一次补齐联系人、电话、地址，否则无法新建报关装箱、也无法打印报关装箱单。
