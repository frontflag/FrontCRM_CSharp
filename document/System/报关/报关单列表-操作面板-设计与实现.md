# 报关单列表 · 右侧「操作」面板 — 功能要求与实现说明

本文描述 **FrontCRM（CRM.Core / CRM.API / CRM.Web）** 中 **报关单列表页**（`CustomsDeclarationList`）右侧工作区辅助栏 **「操作」** 页签的设计要求与实现方法。与 [销售订单明细列表-操作面板-设计与实现](../销售订单明细列表-操作面板-设计与实现.md)（同模式参考）、[报关到货通知-设计与实现](./报关到货通知-设计与实现.md)（生成到货通知业务规则）、[报关费用方案](./报关费用方案.md)、[报关业务溯源与供应商口径](./报关业务溯源与供应商口径-设计与实现.md) 交叉引用。

---

## 1. 业务定位

| 概念 | 说明 |
|------|------|
| **适用页面** | 报关单列表（路由名 `CustomsDeclarationList`） |
| **展示位置** | `AppLayout` 右侧辅助栏（`aux-right`），与 **「帮助」** 页签并列 |
| **页签 ID** | `r-ops`（文案 i18n：`layout.auxTabs.ops` → 中文「操作」） |
| **面板标题** | `customsPages.declarations.opsPanel.title` → 中文「报关单」 |
| **目标** | 单击列表行后，在不离开列表的前提下查看报关单摘要，并发起 **设置海关状态** / **生成报关到货通知** |
| **与详情页区别** | 详情页含费用面板、明细表、业务记录；列表操作面板为 **3 张业务卡片**（概况 / 海关状态 / 报关到货通知），侧重关务日常推进 |

**仅在本列表路由下** 注册双页签（操作 + 帮助）；离开页面时恢复仅「帮助」，并 `customsDeclarationOpsStore.clear()`。

### 1.1 在报关 V2 链路中的位置

报关 V2 进口侧境内收货发起点为 **报关单上人工生成到货通知**（非移库一步过账，**`StockTransfer` 报关移库单已废弃**）。操作面板将列表场景下的两个关键关务动作集中呈现：

```text
装箱确认 → 自动生成报关单
    → 拣货 + 执行报关出库（境外扣减）
    → 【操作面板】设置海关状态 = 已结关
    → 【操作面板】生成报关到货通知
    → 到货通知 → 质检 → 报关入库（StockInType=20）
```

## 2. 布局与交互要求

### 2.1 整体结构

```
┌─ 右侧辅助栏 ─────────────────────────┐
│ [操作] [帮助]              [全屏][✕] │
├──────────────────────────────────────┤
│  （无选中行）单击列表行查看…          │
│  或                                  │
│  ┌ 报关概况 ─────────────────────┐   │
│  ├ 状态标签（流程 + 海关）───────┤   │
│  ├ 海关状态 ─────────────────────┤   │
│  └ 报关到货通知 ──────── 已完成 ✓│   │
└──────────────────────────────────────┘
```

- 各区块 **直接作为页签内容子级** 纵向排列；宽度 `100%` 自适应父面板，禁止横向滚动。
- 嵌入模式（`embedded`）复用 [销售操作面板 §2.5](../销售订单明细列表-操作面板-设计与实现.md)：`so-item-ops-root--embedded`、`ops-card`、`so-item-ops-panel.scss` 等。
- 样式 token 对齐 `--crm-aux-*`；子面板布局（状态 3 列 / 信息双列 Key:Value）见 [销售操作面板 §2.5](../销售订单明细列表-操作面板-设计与实现.md)。

### 2.2 列表交互

| 操作 | 行为 |
|------|------|
| **单击行** | 见 [销售操作面板 §2.4](../销售订单明细列表-操作面板-设计与实现.md)（A～F）；本页 `CustomsDeclarationList` + `useListRightOpsPanelInteraction`；加载方法为 `loadDetail` |
| **双击行** | 跳转报关单详情 `CustomsDeclarationDetail`（与改造前一致） |
| **选中行高亮** | 表格 `:row-class-name="opsPanelRowClassName"` → `so-item-row--active` |
| **列表操作列** | **保留**原有「设置海关状态 / 生成到货通知 / 删除」等；右侧面板为 **增强入口**，非替代 |

### 2.3 右栏展开 / 收起与接口

**混合数据源 + 按需请求**（见 §4）。门控同销售 §2.4；「操作」就绪时 `selectRow` / `loadDetail`。列表刷新 `resetListRightPanelOnReload`；设置海关状态 / 生成到货通知成功后若仍为选中行可再 `loadDetail`。离开路由 `clear()`。

**测试对照：** [报关单列表-操作面板-测试对照说明](../../QA/报关/报关单列表-操作面板-测试对照说明.md)

## 3. 三张卡片 — 功能与 UI 要求

### 3.1 报关概况

**标题：**「报关概况」

**展示规则：** 左对齐文本行（无 Key 标签）：

| 顺序 | 内容 | 样式 |
|------|------|------|
| 1 | `declarationCode` | 琥珀色 `$color-amber`，18px 加粗 |
| 2 | 报关公司名称 | 13px，常规 |
| 3 | 申报日期 | 常规 |
| 4 | 源仓 → 目标仓 | `fromWarehouseCode → toWarehouseCode`（详情加载后） |
| 5 | 出库通知单号 | `stockOutRequestCode` |

**数据来源：** 列表行 `row` 提供基础字段；仓库路线等以详情 `detail` 为准（加载后覆盖）。

### 3.2 状态标签（无独立标题卡片）

报关流程状态 + 海关状态，各一枚 `el-tag`（`effect="dark"`），与列表列、详情页标签配色一致：

| 字段 | 取值 |
|------|------|
| `internalStatus` | 待处理(1) / 报关中(2) / 已完成(3) / 作废(-1) |
| `customsClearanceStatus` | 未维护(0) / 放行(10) / 已结关(100) |

### 3.3 海关状态

| 元素 | 要求 |
|------|------|
| 当前值 | KV 行展示当前海关状态文案 |
| 按钮 | 文案「设置海关状态」；权限见 §5 |
| 作废单 | 显示「报关单已作废，不可继续操作。」；**不显示**按钮 |
| 交互 | 点击按钮 → 列表页打开原有 `el-dialog` 设置海关状态（与操作列共用 `openClearance` / `saveClearance`） |

### 3.4 报关到货通知

| 元素 | 要求 |
|------|------|
| 指标 | **已生成条数** / **待生成条数**（`existingArrivalNotifyCount` / `pendingArrivalNotifyCount`） |
| 进度条 | 高度 10px；绿色渐变；`已生成 / 明细总数` |
| 阻塞摘要 | 按钮不可用时显示 `arrivalDisabledHint.summary`（优先后端 `arrivalNotifyBlockReason`） |
| 待办清单 | 按钮不可用时列出 **尚未满足** 的前置条件（见 §3.5） |
| 下一步 | 针对 **第一个未完成前置** 的操作指引（`nextStep`） |
| 按钮 | 文案「生成报关到货通知」；`canCreateArrivalNotifies === true` 且非作废时可点 |
| 按钮样式 | 可用：深蓝 `#0f4c81`；不可用：灰底 `#e5e7eb` |
| **已完成** | 全部明细已生成到货通知时：标题栏绿色对钩 +「已完成」；隐藏按钮与长文案 |

**按钮可用口径：** 与详情页、列表操作列一致，以详情接口 `canCreateArrivalNotifies` 为准（后端 `CustomsV2FlowService.EvaluateArrivalNotifyReadinessAsync`）。

**交互：** 确认弹窗 → `POST /api/v1/customs-declarations/{id}/create-arrival-notifies` → toast → 刷新列表与面板。

### 3.5 生成到货通知 — 前置条件与提示规则

后端权威评估见 [报关到货通知-设计与实现](./报关到货通知-设计与实现.md) §4.2。前端操作面板在按钮禁用时，通过 `buildCustomsArrivalDisabledHintContent` **结构化展示待办项**（与销售订单「申请出库」禁用提示同模式：摘要 + 明细列表 + nextStep）。

| # | 检查项 | 未完成时待办文案（i18n key 后缀） |
|---|--------|-----------------------------------|
| 1 | 报关单未作废 | `prereqVoided` |
| 2 | 海关状态 = 已结关(100) | `prereqClearance` |
| 3 | 头 `exchangeRate > 0` | `prereqExchangeRate` |
| 4 | `feesCalculatedAt` 已填 | `prereqFeesCalculated` |
| 5 | `toWarehouseId` 已维护 | `prereqToWarehouse` |
| 6 | 存在有效明细 | `prereqHasItems` |
| 7 | 明细费用字段完整（采购价、采购系数、关税率、HS、含税单价等） | `prereqLine*` |
| 8 | 报关出库已执行 | `prereqStockOutDone` |

**提示组装规则：**

1. **摘要：** 优先 `detail.arrivalNotifyBlockReason`；否则取第一条待办；再否则通用文案。
2. **明细列表：** 所有 `done === false` 的检查项（作废单仅展示作废一项）。
3. **下一步：** 按检查顺序取第一个未完成项的 `next*` 文案。
4. **已完成：** `existingArrivalNotifyCount >= 明细数` 且 `pendingArrivalNotifyCount === 0`，或后端已全部生成且不可再创建。

**说明：** 费用维护、目标仓维护等需在 **报关单详情** 完成；面板引导文案中明确「进入报关单详情」。

## 4. 数据来源

### 4.1 总览

| 数据块 | 主要来源 | 补充来源 |
|--------|----------|----------|
| 报关概况（单号、公司、日期、SOR） | 列表行 `row` | 详情 `detail` |
| 仓库路线 | 详情 `detail` | — |
| 状态标签 | 列表行 / 详情 | — |
| 到货通知指标与可否创建 | 详情 `detail` | — |
| 禁用提示 | 详情字段 + `customsDeclarationArrivalDisabledHint.ts` | `arrivalNotifyBlockReason` |

### 4.2 详情接口（面板按需请求）

```
GET /api/v1/customs-declarations/{id}
```

响应 DTO：`CustomsDeclarationDetailDto`，操作面板主要使用：

| 字段 | 用途 |
|------|------|
| `canCreateArrivalNotifies` | 生成按钮是否可用 |
| `arrivalNotifyBlockReason` | 阻塞摘要 |
| `pendingArrivalNotifyCount` / `existingArrivalNotifyCount` | 指标与进度 |
| `existingArrivalNotifyCodes` | 已生成单号展示 |
| `exchangeRate` / `feesCalculatedAt` / `toWarehouseId` | 前置检查 |
| `items[]` | 明细数、行级费用检查 |
| `internalStatus` / `customsClearanceStatus` | 状态标签 |

列表行 DTO（`CustomsDeclarationListItemDto`）字段较少，**不足以**计算到货通知前置；故面板在右栏展开后必须拉取详情。

### 4.3 写操作 API（复用列表既有实现）

| 操作 | API |
|------|-----|
| 设置海关状态 | `PATCH` 报关单海关状态（`patchCustomsClearanceStatus`） |
| 生成报关到货通知 | `POST /api/v1/customs-declarations/{id}/create-arrival-notifies` |

## 5. 权限

| 能力 | 口径 |
|------|------|
| 查看操作面板 | 随报关单列表可读权限 |
| 设置海关状态 / 生成到货通知按钮 | `useDepartmentDataReadOnly().canWriteLogisticsData`（物流数据可写） |

### 6.2 Store API

```typescript
// stores/customsDeclarationOpsPanel.ts
setRowOnly(row)           // 仅记录列表行，不请求 API
loadDetail(text)          // 按当前 row 请求 GET customs-declarations/{id}（同 key 已加载则跳过）
selectRow(row, text)      // setRowOnly + loadDetail
refreshFromListRows(rows, text, fetchDetail)
clear()
registerHandlers({ setClearance, createArrival })
runSetClearance() / runCreateArrival()
```

`detailRowKey` 避免重复请求；`loadSeq` 防止竞态覆盖。

### 6.3 列表页关键逻辑

```typescript
// CustomsDeclarationList.vue — 同销售 §2.4 / useListRightOpsPanelInteraction
// A 收起忽略；B 非操作 setRowOnly；C 操作 selectRow→loadDetail；D/E 切到操作或展开后 loadDetail
```

### 6.4 组件 Props / 事件

`CustomsDeclarationOpsPanel` 由 `AppLayout` 注入：

- `row`、`detail`、`loading`、`loadError`、`actionLoading`（来自 store）
- `canWriteLogistics`
- `embedded`（固定 `true`）
- 事件：`set-clearance` / `create-arrival` → store `runSetClearance` / `runCreateArrival`

## 9. 测试与回归要点

1. 进入报关单列表后右栏有 **操作 + 帮助**；其他页面仅 **帮助**。
2. 单击行：展开右栏、操作页签、高亮行；双击仍进详情。
3. **右栏收起**时单击：Network **无** `customs-declarations/{id}`；展开后出现请求。
4. 右栏已展开时切换行：每次请求新报关单 id 的详情。
5. 未结关：到货通知按钮灰色；待办含「待设置海关状态为已结关」；nextStep 指向设置海关状态。
6. 已结关但费用/出库未完成：待办清单多项；摘要与详情页 `arrivalNotifyBlockReason` 一致。
7. 全部明细已生成到货通知：标题「已完成」+ 绿勾，无按钮。
8. 面板「设置海关状态」与列表操作列弹窗 **同一套**；保存后列表与面板同步刷新。
9. 面板「生成报关到货通知」与列表操作列 **同一确认与 API**；成功后指标与进度更新。
10. 作废单：海关状态卡片与到货卡片均不可操作，显示作废提示。
11. 窄右栏宽度：无横向滚动条，文本可换行。
