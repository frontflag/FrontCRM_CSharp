## 1. 目标

1. **流程页签**：以当前待报关行为主节点，地铁竖轴展示上下游（上游单线、下游可多卡）。  
2. **强制删除**：管理员清理孤儿/错误待报关行；确认码为 **pendlist Guid**（仅弹窗展示，列表与主节点卡不展示 Id）。

---

## 2. 流程站点顺序（定稿）

```
上游（单线）
1. 销售订单明细
2. 出库通知（销售 Type=10）   ← 已删则站在，单号「已删除」
3. 待报关列表                 ← ★ 主节点（当前业务指示：见 UI 规范；不显示 Id）

下游（可多分支 / 同站多卡）
4. 报关出库通知（Type=20）    ← 小卡额外展示 pendlist Id（溯源）
5. 装箱
6. 拣货
7. 出库
8. 报关
9. 到货
10. 质检
11. 报关入库
```

交互门控：右栏收起不加载；展开且在 `r-flow` 时单击行加载。页签 ID：`r-flow`。

卡片视觉套用 [流程页签规范 §2.5～§2.7](../../PRD/规范/UI规范/流程页签规范.md)：KV 不折行、单号去蓝链/悬停橙、创建日期 `yy-MM-dd`。客户名称两格展示；有客户读权限且卡上有客户 ID 时可点，新开页进客户详情。

---

## 3. API

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/v1/customs-pendlists/{id}/flow-aggregates` | 流程聚合 |
| POST | `/api/v1/customs-pendlists/{id}/force-delete` | Body: `{ confirmPendlistId }`；仅 SYS_ADMIN / SYS_MANAGER |

强制删除 Guard：存在未删报关出库通知 / 装箱明细 / 报关明细 → 400。成功则 `status=Cancelled` + `is_deleted=true`。

补充：强制删除**销售**出库通知时同步取消/软删关联 pendlist（与普通删除一致）。
