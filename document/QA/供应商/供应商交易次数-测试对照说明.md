> **页面 / 路由：** 待审批 `/pending-approvals`、审批桌面 `/approval-desktop`（采购订单供应商信息）；需求明细 `/rfq-items` 底部采购报价  
> **设计文档：** [供应商交易次数-设计与实现](../../System/供应商/供应商交易次数-设计与实现.md)、[审批桌面-设计与实现](../../System/审批/审批桌面-设计与实现.md)  
> **自动化：** `tests/CRM.Core.Tests/Utilities/VendorTradeCountRulesTests.cs`、`QuoteServiceTests.GetPagedAsync_ShouldHydrateVendorTradeCount`、`CRM.Web/src/tests/quote-vendor-trade-count.test.ts`  
> **权限 / DDL：** 无新权限码、无迁移。有采购订单审批或需求明细读权限即可看到次数；全公司同一数字。

## 一、入口与权限

| 步骤 | 预期 |
|------|------|
| 有权打开采购订单待审 | 供应商信息可见「交易次数」 |
| 有权打开需求明细并点一行 | 底部采购报价在「供应商等级」后可见「交易次数」 |
| 无对应页权限 | 进不了该页；本功能无单独权限码 |
| 采购数据范围为「仅本人」 | 次数仍是该供应商全公司合计，不因本人范围变小 |
| 无付款记录读权限、有采购审批或需求明细 | 仍能看到次数（现读，不要求付款列表权） |

---

## 二、审批采购订单（必测）

准备：供应商甲有效付款单覆盖 **3** 条不同采购明细（其中一行只请过部分款、一行付款单仍为新建草稿）。

| 步骤 | 预期 |
|------|------|
| 打开甲的采购订单待审 | 交易次数为 **3** |
| 甲没有任何有效付款单 | 显示 **0** |
| 采购脱敏账号 | 供应商名为 —；**交易次数仍为数字** |

---

## 三、需求明细采购报价（必测）

| 步骤 | 预期 |
|------|------|
| 报价有供应商，甲交易次数为 3 | 「交易次数」列为 **3** |
| 同一供应商多条报价 | 各行次数相同 |
| 报价无供应商 | **—** |
| 列顺序 | 供应商名称 → 供应商等级 → **交易次数** → 报价数量 |
| 已删报价表 / 报价列表页 | **无**本列 |

---

## 四、口径 / 公式核对

```text
交易次数 = COUNT DISTINCT 采购明细ID
  有效付款单（未软删，状态 ≠ −1 审核失败、≠ −2 取消）
  归属付款单供应商
  采购明细未软删
```

| 步骤 | 预期 |
|------|------|
| 同一采购明细两张有效付款单 | 仍计 **1** |
| 仅审核失败或已取消的付款单 | 不计 |
| 删除未提交草稿后 | 次数减少（若该行再无其它有效单） |
| 货代付款 | 不计 |
| 换供应商后未完结付款已跟到乙 | 次数记在乙，不记在甲 |

本功能不适用：金额核销 / 匹配的足额成功与超额拒绝（总纲 §4.5）。不提交核销金额。

## 五、回归 / 交叉

| 步骤 | 预期 |
|------|------|
| 供应商审批、付款审批 | 供应商面板 **无**交易次数 |
| 报价桌面 / 报价列表 | **无**本列 |
| 供应商详情页 | 可不展示本字段（详情 JSON 可带 `tradeCount`，界面不要求） |

---

## 六、本功能不适用

- **本功能不适用：工作台左栏队列入列与顶栏 N/M（总纲 §4.3）。** 审批桌面只改中栏供应商信息字段。
- **本功能不适用：列表页签模式 / 左栏检索 / 操作面板单击门控（总纲 §4.4）。**
- **本功能不适用：金额提交 / 核销 / 匹配足额与超额（总纲 §4.5）。**
- **本功能不适用：数据分析看板公式。** 与供应商滚存、成单供应商数无关。
- **本功能不适用：多租户皮肤 / 打印（总纲 §4.6）。** 三租户同一数字口径。
