# 供应商查重 — 测试对照说明

> **页面 / 路由：** 供应商新建 `/vendor/create`、编辑 `/vendor/:id/edit`；审批桌面 `/approval-desktop`（供应商审核）  
> **设计文档：** [供应商查重-设计与实现](../../System/供应商/供应商查重-设计与实现.md)  
> **权限：** 供应商信息读（查重接口、详情跳转）；供应商维护（转正式 / 保存）  
> **上线前置：** 执行迁移 `20260911120000_VendorDuns` 或设计文档 §5 等价 SQL 后重启 API，浏览器强刷前端  
> **桌面骨架：** 审批队列 / 顶栏 N/M 见 [审批桌面-测试对照说明](../审批/审批桌面-测试对照说明.md)；本对照测查重口径与中栏面板

---

## 一、入口与权限

| 步骤 | 预期 |
|------|------|
| 有供应商维护权限，打开新增，点「转正式」 | 先校验中文全称必填；再请求查重；无命中则直接创建 |
| 有供应商维护权限，打开编辑，点「保存」 | 名称/信用代码/邓白氏相对上次查重未变则不再请求；有变化则再查 |
| 仅点「保存草稿」 | **不**查重、不弹窗 |
| 无供应商维护、仅读 | 不能进新建/编辑，无法从该页调查重 |
| 无供应商信息读 | 按现有规则进不了列表；`POST /api/v1/vendors/check-duplicates` 亦不可用 |
| 查重接口失败（断网 / 500） | 新建/编辑 **不保存**，有错误提示 |
| 审批桌面选中供应商待审 | **供应商专属信息** 之下出现 **供应商查重** 面板；有命中列出，无命中「未发现重复供应商」；**不**拦截通过/拒绝 |

Network：查重为 `POST /api/v1/vendors/check-duplicates`（需供应商信息读）。审批请求带 `excludeVendorId` = 当前待审供应商。

---

## 二、比对口径（精确匹配）

预处理：去首尾空格、去掉中间空白（含全角）；英文与信用代码不区分大小写；邓白氏再去掉 `-`。空字段不参与。简称不参与。

| 步骤 | 预期 |
|------|------|
| 中文全称与已有库内全称在去掉空格后相同 | **弹出提醒**（足额命中） |
| 英文全称仅大小写 / 中间空格不同 | **弹出提醒** |
| 统一社会信用代码仅大小写 / 空格不同 | **弹出提醒** |
| 邓白氏 `12-345 6789` 对已有 `123456789` | **弹出提醒** |
| 本单英文名为空，库内另一家也无英文名 | **不因英文名判重复** |
| 四字段都空（仅草稿其它项） | 点转正式仍因中文全称必填失败；接口对全空键返回空列表 |
| 中文全称不同，仅简称相同 | **不提醒** |
| 把本单中文全称填成别人的英文全称、其它三项都空/不同 | **不跨字段命中** |
| 编辑自己、四项与当前档案相同 | **不命中自己** |
| 对方已软删或在黑名单 | **仍提醒**，并分别标「已删除」「黑名单」 |
| 采购数据范围为「仅本人」，对方由其他采购员创建 | **仍能看到提醒**（查重不走列表数据范围） |
| 命中超过 10 家 | 最多 10 条，并提示仅列出前 10 条 |
| 弹窗点取消 | 不保存 |
| 弹窗点确认创建 / 确认保存 | **仍保存成功**（不拦截） |
| 确认后未改四项再点保存 | 不再弹（同一会话） |

弹窗 / 审批面板每条首行文案为「已存在供应商，采购员：{名}，创建日期：{日期}」；其下四行带字段名：中文全称、英文全称、统一社会信用代码、邓白氏编码。无详情权限或已删除时名称灰显，点击不跳转；有权限时可打开详情。

## 三、审批桌面查重面板

> 桌面左栏队列、顶栏计数见审批桌面对照。口径与第二节相同。

| 步骤 | 预期 |
|------|------|
| 队列选中供应商待审 | 中栏专属信息之下为查重面板；加载中「正在查重…」 |
| 与库内另一家四字段归一化后相同（排除自己） | 列出命中，卡片文案与新建弹窗相同（无「确认创建」按钮） |
| 无其它命中 | 「未发现重复供应商」 |
| 查重接口失败 | 面板显示错误；**仍可**通过/拒绝 |
| 对方已删除 / 黑名单 | 仍列出并打标 |
| 采购数据范围为「仅本人」 | 仍能列出他人创建的重复供应商 |
| 通过 / 拒绝 | **不**因有重复而拦截 |
| 销售/采购订单审核 | **无**该面板 |
| 面板底色 | 与销售订单审核 **订单概况** 相同（浅青）；专属信息仍为浅黄 |

## 四、表单字段

| 步骤 | 预期 |
|------|------|
| 新建/编辑基本信息区 | 「简称/别名」后为 **统一社会信用代码**、**邓白氏编码** |
| 填写邓白氏后保存，再进编辑/详情 | 值还在 |
| 详情基本信息 | 可见统一社会信用代码、邓白氏编码 |

---

## 五、数据范围与脱敏

| 步骤 | 预期 |
|------|------|
| 列表仍按现有采购数据范围 | 列表可见集合与改前一致；**查重可以出现列表里看不到的供应商** |
| 采购敏感掩码 | 详情中名称等按现有规则打码；查重结果为避免漏建重复，仍展示命中名称与编码 |
| 无详情权限 | 名称灰显，不跳转；确认后仍可保存当前草稿为正式 |

---

## 六、本功能不适用

- **本功能不适用：§4.5 核销金额足额成功 / 超额拒绝**（不是金额核销/匹配；身份查重的「相等则提醒、空不参与、超 10 条截断」见第二节）。
- **本功能不适用：审批桌面左栏队列 / 顶栏全局计数 / 上一条下一条**（见审批桌面对照；本对照只测中栏查重面板，见第三节）。
- **本功能不适用：列表页签模式持久化 / 左栏检索 / 操作面板门控**。
- **本功能不适用：多租户打印皮肤**。
- **本版不测：** Excel 导入、AI 建档/名片识别的查重（本期不接）。

## 七、上线前置

3. 前端强刷。未加列时保存邓白氏会失败。

### 已知口径差异

- 查重是四字段分别精确比对（归一化后），不是模糊搜、不是简称。
- 现有供应商列表模糊搜（`findSimilarVendors`）与本次查重无关，不要用列表搜结果当验收标准。
- 后端保存接口 **不**因重复而拒绝；拦截只发生在前端弹窗点取消，或查重 API 失败。

*部署含供应商查重的版本并跑完迁移后验收。*
