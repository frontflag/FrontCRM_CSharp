# 供应商等级 — 测试对照说明

> **页面 / 路由：** 供应商新建 `/vendor/create`、编辑 `/vendor/:id/edit`、列表 `/vendorlist`；系统管理 → 数据字典（类别「供应商等级」）；需求明细 `/rfq-items` 底部采购报价与已删报价；报价列表 `/quotes`；需求详情已删报价弹窗  
> **设计文档：** [供应商等级-设计与实现](../../System/供应商/供应商等级-设计与实现.md)、[需求明细已删报价-设计与实现](../../System/需求/需求明细已删报价-设计与实现.md)、[报价保存回写供应商等级-设计与实现](../../System/报价/报价保存回写供应商等级-设计与实现.md)  
> **权限：** 供应商信息读/维护（列表看、新建改）；字典维护另需系统字典权限；报价列随报价/需求读权限  
> **看板口径：** [采购分析-测试对照说明](../数据分析/采购分析-测试对照说明.md)、[供应商列表看板-设计与实现](../../System/供应商/供应商列表看板-设计与实现.md)  
> **上线前置：** 执行迁移 `20260909120000_VendorLevelSABC`（及 `20260910120000_VendorLevelDeleteLegacyDict`）或设计文档 §6 等价 SQL 后重启 API，浏览器强刷前端

## 一、入口与权限

| 步骤 | 预期 |
|------|------|
| 有供应商维护权限，打开新增 | 可见「等级」下拉，选项仅为 **S、A、B、C**（S 在上、C 在下） |
| 无供应商维护、仅读 | 可进列表看等级列；不能改 |
| 无供应商信息读 | 按现有规则进不了列表或名称打码；**与本改动无关的权限回归即可** |
| 有报价/需求读权限 | `/quotes`、`/rfq-items` 采购报价与已删报价可见等级列（只读）；无读权限则进不了对应页 |
| 有报价保存、无供应商维护 | 在新建/编辑报价改等级并保存后，主数据等级更新。步骤见 [报价保存回写供应商等级-测试对照说明](../报价/报价保存回写供应商等级-测试对照说明.md) |

---

## 二、下拉与默认

| 步骤 | 预期 |
|------|------|
| 新增页不改等级，保存草稿/转正式 | 等级为 **C** |
| 新增选 S 后保存 | 列表/详情显示 **S** |
| 下拉 | **无** `1-`、`1`、`1+`、`2-`、旧 13 档；等级不可清空 |
| 列表筛选等级 | 选项同样只有 S/A/B/C |
| Excel 导入等级空或无法识别 | 落入 **C**；填 `S`/`A`/`B`/`C` 或 `1`～`4` 能对应 |
| AI 解析名片/文本中的等级 | 认 S/A/B/C 与 1～4；无法识别时保存仍落 **C** |

---

## 三、存量与字典

| 步骤 | 预期 |
|------|------|
| 迁移后任意历史供应商 | 等级均为 **C**（含原 1- / 旧 A 等） |
| 系统字典 VendorLevel | 仅四条：1=S、2=A、3=B、4=C；旧码 **已删除**，状态「全部」也看不到 |
| 客户新建/编辑等级 | **不变**（仍为客户自己的 D/C/B/BPO/VIP/VPO） |

---

## 四、看板 / 分析

| 步骤 | 预期 |
|------|------|
| 供应商列表看板、采购分析「供应商」、采购订单看板 · 供应商等级饼图 | 扇区文案为 **S / A / B / C / 未设置**，不是「等级 1」 |
| 采购敏感掩码 | 金额类按现有规则打码；**等级饼图仍能加载** |

**公式（本改动不改金额口径）：** 有金额权时按成单 USD 占比；无权限时按订单数占比。扇区名来自字典名称（回退 S/A/B/C）。看板集合与列表筛选一致（见供应商列表看板设计）。

---

## 五、数据范围与脱敏

| 步骤 | 预期 |
|------|------|
| 部门/采购数据范围 | 列表与看板仍只出现当前账号可见供应商 |
| 采购敏感掩码 | 供应商名/金额按现有规则为 `—`；等级列仍显示 S/A/B/C |

## 六、报价列表 / 需求明细采购报价

| 步骤 | 预期 |
|------|------|
| `/rfq-items` 选中有报价的明细 | 底部采购报价「供应商名称」后有「供应商等级」，文案为 **S / A / B / C**（与供应商主数据当前等级一致，不是报价当时快照） |
| 报价行无 `vendor_id`（只填了名称） | 等级列为 **—** |
| 同一报价多供应商且等级不同 | 去重后顿号拼接，如 `S、A` |
| 采购敏感掩码账号 | 供应商名称为 `—`，等级列仍显示字母 |
| `/quotes` 报价列表 | 「供应商名称」后同样有「供应商等级」；无名称时等级仍可显示（有 ID 即可） |
| `/rfq-items` 已删报价 | 无记录时整块不显示；有记录时标题「已删报价 {n} 条」默认折叠，展开后供应商后有等级列；有 ID 显示 S/A/B/C，无 ID 为 — |
| 需求详情「已删报价」弹窗 | 供应商后有等级列；有 ID 显示 S/A/B/C，无 ID 为 — |
| 部门/报价数据范围 | 报价列表与需求明细仍只出现当前账号可见数据 |

## 七、本功能不适用

- **本功能不适用：§4.5 核销金额足额成功 / 超额拒绝**（等级不是核销/匹配金额）。
- **本功能不适用：审批桌面式左右栏默认页签**（供应商编辑不是审批桌面）。
- **本功能不适用：列表页签模式持久化**（本改动不改页签模式；看板/列表切换规则见供应商列表看板对照，此处不重复）。
- **本功能不适用：多租户打印皮肤**。
- **本功能不适用：列宽记忆升版**（仅插入新列，不升 `column-layout-key`）。

2. 重启 API。  
3. 前端强刷，避免旧下拉缓存。

### 已知口径差异

- 库内仍存 `1～4`，界面显示字母；与客户等级码表不同，不要用客户等级去对供应商。
- 存量一律 C，**不**按旧 `1-`～`3+` 映射到 S/A/B。
- 报价上的等级是 **现读主数据**，供应商后来改档后，历史报价列也会变。

*部署含供应商等级 S/A/B/C 的版本并跑完迁移后验收。*
