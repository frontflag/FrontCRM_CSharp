# 销售分析 — 测试对照说明

| 项 | 内容 |
|----|------|
| 菜单路径 | 数据分析 → 销售分析 |
| 路由 | `/reports/sales` |
| 页面副标题 | 按订单创建日、美元下单额（convert_total）统计 |
| 口径提示 | 排除取消/审核失败订单；成单金额为审核通过及以上 |
| API | `GET /api/v1/analytics/sales/dashboard`、`/trends`、`/breakdowns` |

---

## 一、全局筛选（影响下文各指标）

| 筛选项 | 参数 | 默认/说明 |
|--------|------|-----------|
| 视角 | `viewLevel`：公司 / 部门 / 个人 | 可见项由销售数据范围 `saleDataScope` 决定 |
| 日期区间 | `dateFrom`～`dateTo` | 默认：今天往前 5 个月～今天（**含首尾日**） |
| 趋势粒度 | `groupBy`：按日 / 按周 / 按月 | 仅影响趋势图 |
| 部门 | `departmentId` | 部门视角且有权时可选 |
| 业务员 | `salesUserId` | 个人视角且可选多人时显示 |

**通用订单过滤：**

- 销售订单主表 `status` **排除**：取消（-2）、审核失败（-1）。
- 销售订单明细：`is_deleted = false` 且 `status = 0`（有效行）。
- **日期字段**：统计概览、趋势、分解、排行均按 **`sellorder.create_time`**（订单创建日）落在区间内；**待办区不受日期区间限制**。

**数据范围：** 按当前用户销售数据权限 + 视角镜头过滤（部门镜头取业务员**主部门** `rbac_user_department.is_primary`）。

**金额脱敏：** 无销售金额读权限等场景下 `maskAmounts=true`，金额类 KPI 为 `—`，币别分解改为按**订单数**占比。

## 二、待办 KPI（不受日期区间限制）

| 字段名称 | 统计公式 | 统计说明 |
|----------|----------|----------|
| 待核销应收款 | `finance_receivable`：`!is_deleted` 且 `verified_to_be > 0`；按 `currency` 分组 `SUM(verified_to_be)`；`totalUsd` = `FromExtend`（`verified_to_be × convert_price / price`；**产品主口径为 SO 行历史折算价**，价比为 0 时才回落查询日财务汇率） | 与应收款列表看板 KPI「待核销应收款」同源（**待核销余额**）。经 `sell_order_item_id` 挂 SO 行取 `price`/`convert_price`（折算美金单价）。数据权限同列表 `ApplyFinanceReceivableListDataScopeAsync`，再叠销售分析公司/部门/个人透镜。与日期无关；勾选/取消列表「仅待核销」不改变本合计。 |
| 待出库明细数 | `COUNT(sellorderitem.id)` 且 `stock_out_progress_status IN (0,1)` | 有效明细行中，出库进度为「待出库(0)」或「部分出库(1)」的行数。统计的是**明细条数**，不是订单张数。 |
| 待开票金额 | 按订单 `currency` 分组 `SUM(invoice_amount_not)`；`totalUsd` 折算同上 | 有效明细「未开票」**原币分档** + **折算美金**。与日期无关。 |

**测试注意：** 待办应收 ≠ 趋势图「应收趋势」（趋势仍为 SO extend `receipt_amount_not`、已审核、按创建日落桶）；待办为财务应收台账待核销余额。公司视角下与 `/finance/receivables` 看板「待核销应收款」应一致（同用户权限）。

## 三、统计概览 KPI（受日期区间限制）

| 字段名称 | 统计公式 | 统计说明 |
|----------|----------|----------|
| 需求条目数 | `COUNT(rfqitem.id)` | 区间内创建的需求明细行数。数据范围按需求（RFQ）权限过滤；**跟单专属范围**用户恒为 0。 |
| 需求客户数 | `COUNT(DISTINCT rfq.customer_id)`（`customer_id` 非空） | 区间内需求涉及的去重客户数。跟单专属范围用户恒为 0。 |
| 需求→销售转化率 | `已转化需求明细数 / 需求条目数 × 100`（保留 2 位小数） | **分子**：区间内需求明细中，存在链路 `sellorderitem → quote → rfq_item`（有报价且已生成销售明细）的去重明细数。**分母**为 0 时显示空。非客户级转化率。 |
| 销售订单条目数 | `COUNT(sellorderitem.id)` | 区间内创建的销售订单有效明细行数（含未审核订单）。 |
| 销售客户数 | `COUNT(DISTINCT sellorder.customer_id)` | 区间内销售订单去重客户数（含未审核订单）。 |
| 成单金额（已审核） | `SUM(sellorder.convert_total)` 且 `status >= 审核通过(10)` | 区间内创建且**已审核通过及以上**的订单，美元折算总额 `convert_total`。**USD**。 |
| 已出库金额 | 原币：`SUM(qty_stock_out_actual × price)` 按币别；`totalUsd`：`SUM(qty_stock_out_actual × convert_price)` | 已审核有效明细；展示 **折算美金 + 原币分档**（勿跨币种混加原币）。 |
| 已收款金额 | 原币：`SUM(receipt_amount_finish)` 按币别；`totalUsd`：`FromExtend`（SO 行 `convert_price/price`；价比不可用时回落查询日财务汇率） | 已审核有效明细；展示 **折算美金 + 原币分档**（勿跨币种混加原币）。 |

## 四、趋势图（按 `groupBy` 分桶）

每个趋势点为时间段 `period` 内、按 **`sellorder.create_time` 或 `rfqitem.create_time`** 落桶的聚合值（需求类用 RFQ 明细创建日，销售类用订单创建日）。

| 图表名称 | 统计公式（每桶） | 统计说明 |
|----------|------------------|----------|
| 成单金额趋势 | `SUM(convert_total)`，`status >= 10` | 桶内已审核订单美元成单额。脱敏时为 0。 |
| 已出库金额趋势 | 桶内 `SUM(qty_stock_out_actual × convert_price)` | 折算美金合计。 |
| 已收款金额趋势 | 桶内已收款 `FromExtend` 折算美金合计 | 折算美金合计。 |
| 需求客户数趋势 | `COUNT(DISTINCT rfq.customer_id)` | 桶内去重需求客户数。 |
| 销售客户数趋势 | `COUNT(DISTINCT customer_id)` | 桶内去重销售客户数。 |
| 需求条目趋势 | `COUNT(rfqitem)` | 桶内需求明细条数。 |
| 订单条目趋势 | `COUNT(sellorderitem)` | 桶内销售明细条数。 |
| 转化率趋势 | 桶内已转化需求明细 / 桶内需求明细 × 100 | 与概览转化率同口径，按桶计算。 |
| 应收趋势 | 桶内已审核明细 `receipt_amount_not` → `FromExtend` 折算美金合计（`TotalUsd`） | 与已收款趋势同折算路径；单位「折算美元」。**与待办应收口径不同**（待办为财务台账 verified_to_be）。 |

**分桶规则：** 按日 `yyyy-MM-dd`；按周 ISO 周 `yyyy-Wnn`（周一为周首）；按月 `yyyy-MM`。

## 五、分解图

**展示约定：** 各分解图图例/行尾须同时显示 **绝对量（金额或行数/张数）+ 百分比**；不得只显示 `%`。纯比率类（如「转化率趋势」）除外。总规见 [`数据看板总要求.md` §3.7](../../IMP/数据看板/数据看板总要求.md)。

### 5.1 订单主状态（柱状图）

| 统计公式 | 统计说明 |
|----------|----------|
| 按 `sellorder.status` 分组；未脱敏：`SUM(convert_total)`；脱敏：`COUNT(订单)` | 区间内所有非取消/失败订单，按主状态汇总金额或订单数。含未审核订单。状态文案：新建、待审核、审核通过、进行中、完成等。 |

### 5.2 币别金额（成单已审核）（饼图）

| 统计公式 | 统计说明 |
|----------|----------|
| 仅 `status >= 10`；按 `currency` 分组；未脱敏：`SUM(convert_total)`；脱敏：`COUNT(订单)` | 已审核成单按原币别分布。脱敏时标题提示「按订单数占比」。 |

### 5.3 全链路环节（明细行）（饼图）

| 统计公式 | 统计说明 |
|----------|----------|
| 已审核订单有效明细，按**互斥瓶颈**分类后 `COUNT(行)` | 优先级：待采购 → 待入库 → 待出库 → 待收款 → 待开票 → 已完结。每行只归入一个环节。 |

**分类规则（明细 extend 字段）：**

1. `purchase_progress < 2` → 待采购  
2. 否则 `stock_in < 2` → 待入库  
3. 否则 `stock_out < 2` → 待出库  
4. 否则 `receipt_progress < 2` 或 `receipt_amount_not > 0` → 待收款  
5. 否则 `invoice_progress < 2` 或 `invoice_amount_not > 0` → 待开票  
6. 否则 → 已完结  

### 5.4 出库进度（明细行）（柱状图）

| 统计公式 | 统计说明 |
|----------|----------|
| 按 `stock_out_progress_status` 分组 `COUNT(行)` | 0=待出库，1=部分出库，2=出库完成。区间内所有非取消/失败订单明细（不限于已审核）。 |

**占比：** 各分解项 `ratio = 该项 value / 同组 value 之和 × 100`（2 位小数）。

**面板按钮（仅本图）：** 标题行右侧「口径」「详情」。设计与实现见 [`销售分析-出库进度详情与口径-设计与实现.md`](../../System/数据分析/销售分析-出库进度详情与口径-设计与实现.md)。

## 七、测试核对清单

1. **缩短日期区间**：概览、趋势、分解、排行应变化；**待办三项不应仅因缩区间而变小**（仅权限/视角变化才影响待办）。
2. **取消/审核失败订单**：不应进入任何销售统计（待办同样排除）。
3. **成单金额**：仅 `status >= 10`；新建/待审核订单不计入成单金额与排行。
4. **币种**：成单金额/排行为 **USD（`$`）**；待办应收/待开票、已出库/已收款 KPI 为 **折算美金 + 原币分档**；成单/出库/收款/**应收**趋势为折算美金。勿把 RMB 与 USD 原币直接相加。
5. **转化率**：按**需求明细行**是否已关联销售明细，非按客户或订单张数。
6. **跟单专属用户**：需求类指标为 0 或空；仅跟单可见范围内订单参与销售类统计。
7. **金额脱敏账号**：金额 KPI 为 `—`；币别饼图按订单数；排行金额列为 `—`。
8. **部门镜头**：仅按业务员**主部门**归属，兼职部门不计入部门排行。
9. **出库进度「口径」**：Tip 三段文案与帮助「分解 → 出库进度」一致（见 §5.4.1）。
10. **出库进度「详情」**：信息栏视角/区间正确；可拖动与缩放；明细编号可下钻列表；无客户权限时无客户列（见 §5.4.2）。
11. **分解占比展示**：订单主状态 / 币别 / 全链路 / 出库进度均同时显示数值与百分比；转化率趋势可只显示 `%`。
12. **待办「口径 / 详情」**：Tip 与帮助一致；详情新标签打开列表；整卡不再下钻（见 §2.1）。
13. **金额 KPI 样式**：待办 split 主金额约 18px；原币列顶标签 /「查看本币」Tip 左侧标签为灰色；金额尾缀币别为系统色（粉 RMB / 绿 USD 等）；概况已出库/已收款可点「查看本币」；成单有「（折算美金）」后缀；金额卡在销售客户数后换行。见总要求 §3.8 / 金额与币别范式 §5.2。
14. **口径 Tip 首行标签**：待办/应收 KPI Tip 为「指标」（帮助表第一列标题）；分解「出库进度」Tip 为「图」。见总要求 §3.9。

## 八、已知口径差异（易误判为缺陷）

| 对比项 | 说明 |
|--------|------|
| 待办应收 vs 趋势应收 | 待办=财务应收台账 Σ verified_to_be；趋势=SO extend 未收款按创建日分桶 |
| 待办应收 vs 列表看板 | 待办与列表「待核销应收款」同源（verified_to_be）；≠ 列表「出库应收款」（Amount） |
| 待办应收 vs 明细看板应收 | 不同源（台账 verified_to_be vs 明细 receipt_amount_not+出库） |
| 成单金额 vs 已出库/已收款 | 成单为订单头 convert_total（USD）；出库/收款为明细原币分档 + 折算美金 |
| 销售客户数 | `customer_id` 为空仍可能计入 distinct，需结合样本数据判断 |

**文档版本：** 与代码库 `developV3` 销售分析实现一致（`SalesAnalyticsQuery` / `SalesAnalyticsPage`）。
