## 一、采购员列展示

### 1.1 前置数据

准备销售明细行 **S**，关联：

- PO-A（创建较早）：采购员账号 `zhangsan`
- PO-B（创建较晚）：采购员账号 `lisi`
- 或同一张 PO 下两条 `purchaseorderitem`（采购员应只出现一次）

### 1.2 预期

| 场景 | 列表「采购员」列 |
|------|------------------|
| S 仅有 PO-A、PO-B 且均有效 | `zhangsan，lisi`（按 PO **创建时间** 升序；同人只出现一次） |
| S 无有效 PO（未下 PO / 仅 PR） | `—` |
| PO 主表已取消（`status = -2`） | 该 PO 采购员**不计入** |
| PO 明细已取消/审核失败（`-2`/`-1`） | 该明细关联**不计入** |

### 1.3 核对方式

1. 打开销售订单明细列表，筛选定位到 S。  
2. 对比采购订单明细列表：按 `sell_order_item_id` 查关联 PO 及主表 `PurchaseUserId`、创建时间。  
3. 用户表 `User.UserName` 应与列中账号一致（非 `RealName`）。

## 二、采购员筛选

### 2.1 文本框 `purchaseUserAccount`

| 输入 | 预期 |
|------|------|
| `zhang` | 保留任一有效 PO 采购员账号/姓名/PO 冗余名包含 `zhang` 的销售行 |
| 无匹配采购员 | `totalCount = 0` |
| 清空后查询 | 恢复全量（与其他筛选 AND） |

### 2.2 与分页

- 筛选后 `total` 与 SQL 一致；翻页不应出现「筛了却混入无关行」。  
- 不应依赖前端对当前页内存过滤。

### 2.3 看板联动

- 输入采购员筛选后切换「看板」：KPI / 趋势 / 分布 / 排行范围应与列表 `total` 同一筛选集。  
- 修改筛选后看板自动刷新（`boardFilters` 含 `purchaseUserAccount`）。
