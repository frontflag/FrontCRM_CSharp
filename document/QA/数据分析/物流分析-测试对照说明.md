# 物流分析 — 测试对照说明

| 项 | 内容 |
|----|------|
| 菜单路径 | 数据分析 → 物流分析 |
| 路由 | `/reports/logistics` |
| 页面副标题 | 在库存量截至查询日；库龄按入库日；金额 USD 采购成本 |
| API | `GET /api/v1/analytics/logistics/dashboard`、`/trends`、`/breakdowns`、`/customer-matrix` |

---

## 一、全局筛选

| 筛选项 | 参数 | 说明 |
|--------|------|------|
| 视角 | 公司 / 部门 / 个人 | 物流数据范围 + 销采归属模式（B 类用户可能无「公司」Tab） |
| 库存类型 | `all` / `customerOrder` / `purchaseStock` | 全部 / 客单库存 / 采购库存（按 `stock_type` 或 PO 类型过滤） |
| 截至日期 | `dateTo` | **在库概览、库龄、矩阵、排行** 的库龄计算截止日 |
| 趋势区间 | `dateFrom`～`dateTo` | **仅入库趋势图** |
| 趋势粒度 | `groupBy` | 按日/周/月 |
| 矩阵科目 | `matrixSubject` | 客户矩阵子列：销售员 / 供应商 / 采购员 / 品牌 |

**在库行纳入条件：**

- `stock_item.qty_repertory > 0`，未删除。
- 关联 `stock_in` 未删除。
- 排除调拨源类型 `transfer_type = ManualTransferSource`。
- 库龄：`max(0, dateTo − stock_in.stock_in_date)`（自然日）。

**金额：** `在库金额 = qty_repertory × purchase_price_usd`（USD 采购成本）。无采购金额读权限时 `maskAmounts=true`，金额显示 `—`。

## 二、待办 KPI

| 字段名称 | 统计公式 | 统计说明 |
|----------|----------|----------|
| 待入库数量(PCS) | `SUM( max(0, poi.qty − extend.qty_receive_total) )` 四舍五入为整数 | 采购订单有效明细的「订购量 − 已收货量」剩余之和。**当前 PO  backlog**，不受 `dateTo` 限制。仅统计未取消 PO、未取消明细、剩余 > 0。受库存类型（客单/备货 PO）与采购数据范围过滤。 |

**测试注意：** 不含「到货通知在途未建 PO 收货」等阶段；与在库快照是不同概念。

---

## 三、在库概览 KPI（截至 `dateTo`）

| 字段名称 | 统计公式 | 统计说明 |
|----------|----------|----------|
| 在库商品数量 | `SUM(qty_repertory)` | 符合范围的在库行现存数量合计（PCS）。 |
| 在库商品金额 | `SUM(qty_repertory × purchase_price_usd)` | USD 采购成本总值；脱敏为 `—`。 |
| 加权平均库龄 | `ROUND( Σ(库龄天×数量) / Σ(数量), 1 )` | 按数量加权的平均在库天数；总量为 0 时为空。库龄起算日为**入库日**。 |
| 客户数 | `COUNT(DISTINCT customer_id)`（非空） | 有客户锚点的在库行涉及的去重客户数；**无客户_id 的备货行不计入**。 |
| 销售员数 | `COUNT(DISTINCT salesperson_id)`（非空） | 去重销售员数。 |
| 供应商数 | `COUNT(DISTINCT vendor_id)`（非空） | 去重供应商数。 |
| 采购员数 | `COUNT(DISTINCT purchaser_id)`（非空） | 去重采购员数。 |
| 品牌数 | `COUNT(DISTINCT purchase_brand)`（非空） | 去重品牌数。 |

## 四、库龄分布（饼图）

| 桶名称 | 统计公式 | 统计说明 |
|--------|----------|----------|
| 0–30天 | `SUM(qty)`，`库龄 ≤ 30` | 按**数量**占比，非金额。 |
| 31–90天 | `SUM(qty)`，`31 ≤ 库龄 ≤ 90` | 同上。 |
| 91–180天 | `SUM(qty)`，`91 ≤ 库龄 ≤ 180` | 同上。 |
| 181–365天 | `SUM(qty)`，`181 ≤ 库龄 ≤ 365` | 同上。 |
| 365天以上 | `SUM(qty)`，`库龄 > 365` | 同上。 |

**占比：** `ratio = 桶数量 / 总在库数量 × 100`。五桶数量之和应等于「在库商品数量」。

**展示约定：** 图例须同时显示 **数量 + 百分比**（占比类补绝对量；总规见 [`数据看板总要求.md` §3.7](../../IMP/数据看板/数据看板总要求.md)）。

## 五、入库数量趋势

| 字段名称 | 统计公式 | 统计说明 |
|----------|----------|----------|
| 入库数量（每周期） | `SUM(qty_repertory)`，`stock_in_date ∈ [周期开始, 周期结束)` | 按**入库日**落入趋势区间各桶的库存行数量之和。表示该时段入库流量，**非期末在库存量**。 |

**API 字段 `pendingStockInQty`：** 一期恒为 0，页面不展示，无需测试。

## 六、客户 × 统计科目矩阵

**父行（客户锚点）：** 按 `customer_id` 分组；无客户显示「无客户 / 备货」。

| 父行字段 | 统计公式 | 统计说明 |
|----------|----------|----------|
| 在库数量 | 组内 `SUM(qty_repertory)` | 该客户锚点下 PCS 合计。 |
| 在库金额 | 组内 `SUM(qty × purchase_price_usd)` | USD；脱敏为 `—`。 |
| 加权平均库龄 | 组内按数量加权平均库龄 | 同概览公式。 |

**子行（统计科目）：** 由 `matrixSubject` 决定分组键。

| matrixSubject | 子列标题 | 分组键 | 空值显示 |
|---------------|----------|--------|----------|
| salesperson | 销售员名称 | `salesperson_id` | 未分配销售员 |
| vendor | 供应商名称 | `vendor_id` | 未分配供应商 |
| purchaser | 采购员名称 | `purchaser_id` | 未分配采购员 |
| brand | 品牌名称 | `purchase_brand` | 未填品牌 |

子行指标公式与父行相同，在「客户 + 科目」子集上计算。父行数量应等于其子行数量之和（同一锚点内）。

**排序：** 父行、子行默认按在库金额降序（脱敏时按数量）。

## 八、测试核对清单

1. **截至日期**：改变 `dateTo` 应改变在库数量、金额、库龄、矩阵、排行；**待入库 PCS 不应仅因改截至日而变**。
2. **库存类型**：客单/采购/全部 三套数据分别核对；样品库存等仅在「全部」出现。
3. **库龄**：手工抽一行：`dateTo − stock_in_date` 与桶归属一致。
4. **矩阵**：切换科目会重新请求 API；子行合计=父行。
5. **趋势 vs 快照**：趋势按入库日区间；快照按 `dateTo` 时点存量。
6. **脱敏**：金额 KPI、矩阵金额、排行金额为 `—`。
7. **下钻**：部分下钻未带 `stock_type`，列表可能比 KPI 略宽（已知差异）。
