## 一、入口与懒加载

### 1.1 前置条件

- 测试账号具备 `sales-order.read`、`sales.amount.read`
- 未开启销售敏感脱敏（非 521 遮罩场景）
- 准备销售订单 **SO-TEST**，含至少一条已出库明细 **LINE-A**

### 1.2 预期

| 步骤 | 预期 |
|------|------|
| 单击/双击订单明细行 | 底部出现「销售订单明细详情」+ 其下「绩效」面板 |
| 绩效默认状态 | 标题栏折叠，**不发起** `line-profit` 请求（Network 无该 URL） |
| 点击绩效标题展开 | 出现 loading，随后展示变量区 + 三层利润表 |
| 再次折叠绩效 | 内容隐藏；再次展开不重复请求（同一明细、无 refresh） |
| 收起明细详情面板 | 绩效面板一并消失 |
| 明细刷新扩展后（refreshKey 变化）且绩效已展开 | 重新请求 `line-profit` |

## 二、三层利润核对

以 **LINE-A** 为例，展开绩效后核对：

| 层 | 利润（USD）对照源 | 利润率 |
|----|-------------------|--------|
| 报价 | `sellorderitemextend`：`ReQuoteProfitExpected`（有报价成本）或 `QuoteProfitExpected` | 扩展表对应 rate；报价成本为 0 → UI 显示 `—` |
| 预计销售 | `SalesProfitExpected`（瀑布：有 PO→采购成本；否则整行备货→备货采购成本；否则报价成本；否则「-」） | `销售收入 ÷ 所用成本`；无来源 → `—`。列表列读落库值，与绩效不一致时对订单点「刷新」 |
| 出库 | `ProfitOutBizUsd` | 与列表页该行「出库利润」列一致；出库成本 0 且利润 ≥ 0 → `—` |

**毛利率 tooltip：** `(利润 ÷ 对应收入) × 100%`，收入在出库层为 `outboundRevenueUsd`。

## 三、出库成本：实际批次 vs 回退

### 3.1 实际批次（`useActualOutboundCost = true`）

**数据条件：** LINE-A 存在已完成销售出库单，且 `stock_out_item_extend.PurchasePriceUsd > 0`（或 `ProfitOutBizUsd ≠ 0`）。

| 核对项 | 公式 / SQL 思路 |
|--------|-----------------|
| 出库采购成本合计 | `Σ (extend.PurchasePriceUsd × 出库数量)`，数量优先 `QtyStockOut`，否则 `stock_out_item` 实出数量 |
| 绩效变量区「出库采购成本」 | 与上合计一致（2 位 USD） |
| 出库利润 | 优先 `Σ extend.ProfitOutBizUsd`；全 0 且成本 > 0 时为 `出库销售收入 − 成本` |
| API `outboundCostDetails` 行数 | = 满足条件的 extend 行数（不按出库单合并） |
| 明细表表尾合计 | = `outboundCostUsd` |

**抽样 SQL（按销售明细 ID 替换 `:lineId`）：**

```sql
SELECT so.stock_out_code, ext.purchase_order_item_code,
       ext."PurchasePriceUsd", ext."QtyStockOut",
       ROUND(ext."PurchasePriceUsd" * COALESCE(NULLIF(ext."QtyStockOut", 0), soi.quantity)::numeric, 2) AS cost_usd
FROM stock_out so
JOIN stock_out_item soi ON soi.stock_out_id = so."StockOutId"
JOIN stock_out_item_extend ext ON ext."StockOutItemId" = soi."ItemId"
WHERE so.sell_order_item_id = :lineId
  AND so.is_deleted = false AND soi.is_deleted = false AND ext.is_deleted = false
  AND so.stock_out_type = 1 AND so.status IN (2, 4);
```

### 3.2 回退 PO 折算单价（`useActualOutboundCost = false`）

**数据条件：** 有已出库数量，但无可用 extend 快照（无行、单价全 0 等）。

| 核对项 | 预期 |
|--------|------|
| info 说明 | 含「尚无出库批次成本快照」「PO 折算采购单价回退」 |
| 出库成本明细表 | **不显示** |
| 出库采购成本 | `QtyStockOutActual × (Σ PO成本 USD ÷ Σ PO数量)` |

## 四、公式变量对照与明细表

| 区域 | 核对要点 |
|------|----------|
| 采购成本区 | 有 PO 时展示 `POxxx · 折算采购单价 × 数量 = 成本`，**不**单独显示「加权均价」行 |
| 出库区 | 有批次时展示 `POxxx · 真实采购单价 × 数量`；显示「批次采购单价」 |
| 折行 | 窄屏时标签与数值分两行，数值表达式不换行中断 |
| 出库成本明细表 | 默认折叠；列：出库单（可点）、PO 明细、采购单价、数量、小计；标题显示 `共 N 张出库单 · M 行批次` |
| 出库单链接 | 跳转 `/inventory/stock-out/{id}` 且单号正确 |

## 五、异常说明

按设计文档 §2.5 构造数据，确认对应 `el-alert` 出现且文案层前缀为「报价 / 预计销售 / 出库」（非「报价层」等）。

重点回归：

- 尚未出库 + 出库利润 0 → 含出库状态标签
- 回退口径 → 出库 info 说明批次快照缺失

## 六、历史数据重算

| 方式 | 路径 | 验证 |
|------|------|------|
| 单订单 | 销售订单详情「刷新扩展」 | LINE-A `ProfitOutBizUsd` 与绩效出库利润一致 |
| Debug 批量 | Debug → 数据 →「刷新出库利润」 | 返回扫描/变更/失败条数；失败明细含数量校验错误 |
| 离线 | `scripts/refresh_sellorderitemextend_outbound_profit_postgresql.sql` | 先「预览」再 UPDATE，与 C# 口径一致 |

**失败样例：** 销售数量 < 已出库数量时，Debug 批量该行失败，extend 不更新。

## 七、权限与脱敏

| 场景 | 预期 |
|------|------|
| 无 `sales.amount.read` | 不显示绩效面板（与概况金额规则一致） |
| 521 脱敏 | 不显示绩效面板；`line-profit` 对脱敏用户返回 null |

---

## 八、回归要点

1. 绩效利润与 **销售订单明细列表** 同行出库利润列一致（刷新扩展后）。  
2. 展开绩效 **不影响** 打开明细详情时的 `detail-tab-aggregates` 体积（无内嵌 lineProfit）。  
3. API 部署后新字段 `poCostLines`、`outboundCostDetails` 出现在 `line-profit` 响应中。  
4. 单测 `SellOrderOutboundProfitCalcTests` 全部通过。

## 预计销售成本瀑布（对照）

| 场景 | 期望 costSource | 期望利润 |
|------|-----------------|----------|
| 本行有 PO 明细（含未确认/价为 0） | po | 收入 − 全部 PO 折成本；公式注「采购成本」 |
| 无 PO，备货用量或出库批次 ≥ 行 qty | stocking | 收入 − 备货加权单价×行 qty；公式注「备货采购成本」 |
| 无 PO、备货未覆盖整行、有报价折成本 | quote | 收入 − 报价成本；公式注「报价成本」 |
| 以上皆无 | 
one | 利润/利润率/毛利率均为「-」 |
| 备货只用部分行数量 | 
one（或下落报价） | 不外推备货单价 |

刷新：销售订单详情「刷新」或 Debug 批量重算扩展后，SalesProfitExpected 与绩效一致。
