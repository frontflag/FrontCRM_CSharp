# 销售订单编辑保存 — 客户名称 — 测试对照说明

> **状态：** 已上线（2026-07-19 客户 ID/名称同步修复后纳入回归）  
> **页面：** `/sales-orders/:id/edit`（编辑）、`/sales-orders`（主表列表）、`/sales-order-items`（明细列表）  
> **设计说明：** 主表列表按 `customer_id` enrich 客户主数据名称；明细列表读 `sell_order.customer_name` 快照 — 二者必须一致  
> **自动化：** `tests/CRM.Core.Tests/Services/SalesOrderCustomerEditSaveTests.cs`

---

## 一、前置

- 测试账号具备销售订单编辑与客户读权限（非 mask521）
- 准备至少两个不同客户（A、B），名称在客户档案中可区分
- 浏览器 Network 可查看 `PUT /api/v1/sales-orders/{id}` 请求体

---

## 二、黄金路径（必测）

| 步骤 | 操作 | 预期 |
|------|------|------|
| 1 | 打开一张已有销售订单 → **编辑** | 客户下拉与表单客户名与当前订单一致 |
| 2 | 将客户从 A **改为 B** → **保存** | 请求体含 **`customerId`**（B 的 ID）与 `customerName`；保存成功 |
| 3 | 打开 **销售订单主表列表**，找到该单 | 客户列显示 **B 的官方名称**（与编辑页一致） |
| 4 | 打开 **销售订单明细列表**，按订单号筛选 | 客户名称列与主表 **完全一致** |
| 5 | 再次进入编辑页 | 客户下拉选中 B，名称与两列表一致 |

**失败信号：** 主表显示 A、明细显示 B（或相反）— 说明 `customer_id` 与 `customer_name` 快照再次脱节。

---

## 三、Network 契约（必测）

| 检查项 | 预期 |
|--------|------|
| 编辑保存 `PUT` body | 更换客户时 **必须** 含 `customerId` |
| 仅改备注/明细、未换客户 | 可不传 `customerId`；若传则与库内一致 |
| 换客户后响应/详情 | `customerId` 为新客户；`customerName` 来自客户主数据（非表单过期标签） |

---

## 四、历史脏数据（抽查）

若订单曾因旧 bug 出现「主表 / 明细客户名不一致」：

| 步骤 | 预期 |
|------|------|
| 编辑页重新选择正确客户并保存 | 两列表恢复一致 |
| 详情页「刷新扩展」 | **不会** 修正装箱单、应收等下游已落库客户名；仅重算明细扩展进度 |
| 详情页「刷新 ▾ → 刷新客户」 | ① 按订单 `customer_id` 刷新头 `customer_name` 快照（明细列表随之一致）；② 同步**未出库完成**下游 `customer_id`；已出库/已核销/已开票阻断 |
| 仅名称快照过期（ID 已正确） | 「刷新客户」预检非 NoOp，同步后主表/明细客户名与主数据一致 |
| 编辑页更换客户（未保存） | tip 栏列出拟同步下游 / 阻断原因；**不落库** |
| 编辑页换客户 → 保存 →「刷新并保存」 | 一次保存头客户+未完结下游；主表/明细/下游 ID 一致 |
| 编辑页换客户 → 保存 → 取消确认 | 仍停留编辑页，客户与其它字段均未保存 |
| 编辑页换客户但下游已完结阻断 | 不可保存换客户；提示阻断单据 |
| 下游单据客户名 | 未完结下游以订单 `customer_id` 为准；装箱等展示优先读 SO 快照 |
