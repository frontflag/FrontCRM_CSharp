# 用户行为埋点 — 测试对照说明

> **设计文档：** [用户行为埋点-设计与实现](../../System/用户行为埋点-设计与实现.md)  
> **权限脚本：** `scripts/ensure_telemetry_postgresql.sql`

---

## 上线前

1. 执行 `scripts/ensure_telemetry_postgresql.sql`
2. 重启 API，管理员重新登录
3. 确认运维菜单出现「埋点分析」

---

## 采集

| 步骤 | 预期 |
|------|------|
| 登录后操作业务页 | 产生 session_start；路由切换有 page_view |
| 停留可见页面 | 离开页后有 page_timing（visibleMs / activeMs） |
| 点击菜单/按钮 | 高频操作中可见 actionId（`menu.*` / `btn.*` 或 `data-track`） |
| 调用业务 API | 埋点分析 API 耗时中有对应 path 模板 |
| 调用 `/api/v1/telemetry/` | **不**出现在 API 耗时 |
| 用户无法关闭采集 | 设置中无关闭开关 |

---

## 看板

| 步骤 | 预期 |
|------|------|
| 运维 → 埋点分析 | 三块：高频页面 / 高频操作 / API 耗时 |
| 无 `biz.telemetry.analytics` | 无菜单 |
| 日期筛选 | 按日汇总查询 |

---

## 按钮覆盖说明

一期采用 **全局点击捕获**：

- 带 `data-track` 的元素优先（稳定 Id）
- 否则对 `button` / `.el-button` / 侧栏菜单项按文案生成 `btn.{page}.{label}` / `menu.{label}`

关键运维入口已加稳定 `data-track`。业务页建议逐步补 `data-track` 以便跨语言稳定统计。
