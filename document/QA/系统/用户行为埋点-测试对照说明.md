# 用户行为埋点 — 测试对照说明

> **设计文档：** [用户行为埋点-设计与实现](../../System/用户行为埋点-设计与实现.md)  
> **权限脚本：** `scripts/ensure_telemetry_postgresql.sql`

---

## 上线前

1. 执行 `scripts/ensure_telemetry_postgresql.sql`
2. 重启 API，管理员重新登录
3. 以**系统管理员**登录，确认侧栏「运维管理」下出现「埋点分析」

---

## 采集

| 步骤 | 预期 |
|------|------|
| 登录后操作业务页 | 产生 session_start；路由切换有 page_view |
| 停留可见页面 | 离开页后有 page_timing（visibleMs / activeMs） |
| 点击菜单/按钮 | 高频操作中可见 actionId（`menu.*` / `btn.*` 或 `data-track`） |
| 调用业务 API | 埋点分析 API 耗时中有对应 path 模板；**业务 404（如品牌不存在）计入调用、不计入失败** |
| 人为制造 5xx / 断网 | 「失败」列增加；有对应 `api_error`（若未在排除名单） |
| 调用 `/api/v1/telemetry/` | **不**出现在 API 耗时 |
| 用户无法关闭采集 | 设置中无关闭开关 |

---

## 看板

| 步骤 | 预期 |
|------|------|
| 系统管理员：运维管理 → 埋点分析 | 三块：高频页面 / 高频操作 / API 耗时 |
| 非系统管理员 | 侧栏无「运维管理」整组 |
| 非系统管理员手输路径且有 `biz.telemetry.analytics` | **仍可进入**（本期只改菜单） |
| 无 `biz.telemetry.analytics` | 直链/API 拒绝 |
| 日期筛选 | 按日汇总查询 |

---

## 按钮覆盖说明

一期采用 **全局点击捕获**：

- 带 `data-track` 的元素优先（稳定 Id）
- 否则对 `button` / `.el-button` / 侧栏菜单项按文案生成 `btn.{page}.{label}` / `menu.{label}`

关键运维入口已加稳定 `data-track`。业务页建议逐步补 `data-track` 以便跨语言稳定统计。

---

## 本功能不适用（总纲强制声明）

- **本功能不适用：金额 / 核销 / 匹配的足额成功与超额拒绝**（§4.5）。
- **本功能不适用：工作台左右栏队列**（§4.3）。
- **本功能不适用：列表页签模式 / 操作面板门控**（§4.4）。
- **本功能不适用：多租户皮肤 / 打印**（§4.6）。
- **本功能不适用：销售/采购敏感掩码**（§4.2）。
