# 系统错误自动落库 — 测试对照说明

> **设计文档：** [系统错误自动落库-设计与实现](../../System/系统错误自动落库-设计与实现.md)  
> **权限脚本：** `scripts/ensure_sys_error_log_ops_postgresql.sql`  
> **状态：** MVP 可验收

---

## 一、落库范围

| 场景 | 预期 |
|------|------|
| 未处理异常导致 HTTP 500 | `sys_error_log` 新增一行；响应含 `errorId`（`E-{id}`） |
| SaveChanges 触发 `DbUpdateException` / 并发冲突 | 同样落库；业务接口即便 catch 后返回失败信封，也应带上 `errorId` |
| 业务校验拒绝、403、404 | **不**写入 `sys_error_log` |
| 同一请求 DbUpdate 已落库后又冒泡为未处理异常 | **不**重复写第二行（复用同一 `errorId`） |

---

## 二、用户侧提示

| 步骤 | 预期 |
|------|------|
| 触发 500 或关键保存失败 | Toast/提示为业务友好文案，并含「错误编号 E-…」 |
| 提示内容 | **不**展示堆栈、SQL、内部表名 |
| 与用户反馈 | **不**自动生成反馈工单；用户可自愿在 AI 助手中粘贴错误编号 |

---

## 三、运维 · 系统错误

| 步骤 | 预期 |
|------|------|
| 系统管理员：侧栏「运维管理」→「系统错误」 | 打开 `/ops/system-errors` |
| 非系统管理员 | 侧栏**无**「运维管理」整组 |
| 非系统管理员手输路径且有 `sys.errorlog.read` | **仍可进入**（本期只改菜单） |
| 无 `sys.errorlog.read` | API 拒绝 |
| 列表 | 可见错误编号、时间、模块、摘要、路径、用户、是否已处理 |
| 详情 | 可见堆栈/详情（运维可见）；可填备注并「标记已处理」（需 `sys.errorlog.resolve`） |
| 与「用户反馈」 | **独立入口**，列表互不自动关联 |

---

## 四、上线检查

| 项 | 预期 |
|----|------|
| 执行权限脚本 | `SYS_ADMIN` 具备 read/resolve |
| 重启 API 并重新登录 | 新权限生效 |
| 表 | 使用既有 `sys_error_log` |

---

## 五、本功能不适用（总纲强制声明）

- **本功能不适用：金额 / 核销 / 匹配的足额成功与超额拒绝**（§4.5）。
- **本功能不适用：工作台左右栏队列**（§4.3）。
- **本功能不适用：列表页签模式 / 操作面板门控**（§4.4）。
- **本功能不适用：多租户皮肤 / 打印**（§4.6）。
- **本功能不适用：看板统计公式**。
- **本功能不适用：销售/采购敏感掩码**（§4.2）。
