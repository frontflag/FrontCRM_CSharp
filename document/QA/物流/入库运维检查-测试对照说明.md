# 入库运维检查 — 测试对照说明

> **页面 / 路由：** 入库管理 → 入库运维检查 `/inventory/stock-in/ops-check`（`StockInOpsCheck`）  
> **设计文档：** [入库运维检查-设计与实现](../../System/物流/入库运维检查-设计与实现.md)  
> **权限 / DDL：** 无新权限码、无新迁移。菜单与 `POST /api/v1/stock-in/ops-check`：系统管理员、平台管理员、财务总监（主部门财务 + `DEPT_DIRECTOR`）。  
> **关联：** [出库运维检查-测试对照说明](./出库运维检查-测试对照说明.md)、[进项发票反核销-测试对照说明](../财务/进项发票反核销-测试对照说明.md)

## 一、入口与权限

| 步骤 | 预期 |
|------|------|
| 系统管理员或平台管理员登录 | 入库管理最后一项可见「入库运维检查」（批次核销之后）；可进页面；点「检查」返回 200 |
| 财务总监登录（财务部部门总监） | 同上：菜单可见；可进页面；点「检查」返回 200 |
| 财务部员工（非总监） | 无此菜单；直开 `/inventory/stock-in/ops-check` 回控制台；接口 403 |
| 物流操作员（有入库菜单、非上述角色） | 无此菜单；直开 `/inventory/stock-in/ops-check` 回控制台；接口 403 |
| 未登录 | 进登录页 |
| 本功能不新增 write 按钮 | 无「一键修复」 |

## 二、检查与结果

| 步骤 | 预期 |
|------|------|
| 进入后未点检查 | 提示点击「检查」开始；表空 |
| 点「检查」 | 按钮「检查中…」；完成后表出结果；标题与筛选之间数据面板：「错误」红字、「警告」橙字、「合计」青字 |
| 全量 | 不要求输入入库单号或日期；过滤不改变扫描范围（不发带条件的 API） |
| 单号可点 | 到货通知 → 到货通知列表；入库单 → 入库详情；库存明细 → 库存明细列表；进项发票 → 进项发票详情；采购订单 → 采购订单详情；Debug → Debug 模拟数据 |
| 运维操作建议 | 须含页面名 + **本行单号** + 按钮名；一步一行、①②③ 编号；换行可见。未核销行**不得**出现「反核销」。已核销须写出**进项发票单号**（不是「到列表里找」）。重复入库保留单号最小的一张，只对其余单写「强制删除」。状态滞后须写「Debug 模拟数据」点「刷新到货通知状态」，不得写到货列表刷新。不含表名、权限码 |
| 错误原因无 GUID | 供应商主键不一致须为 `到货通知 {通知单号}（{供应商编码}） / 入库 … / 采购订单 …`，**不得**出现 GUID |
| 建议换行 | 重复入库行的运维操作建议分多行显示（①②③…），不是挤在同一行 |

## 二-b、结果过滤（前端切片）

先跑出一份含多类问题的报告，再测过滤。过滤**不重新请求** `POST /api/v1/stock-in/ops-check`。

| 步骤 | 预期 |
|------|------|
| 级别 = 错误 | 只剩错误行；数据面板全量错误/警告/合计不变；第三张改为「显示 x / y」 |
| 级别 = 警告 | 只剩警告行 |
| 清空级别 | 恢复该维度全部 |
| 检查类型 = 重复 | 只剩重复类；不含金额/供应商等其它类 |
| 检查类型 = 金额 | 只剩数量×单价对账类 |
| 检查类型 = 供应商 | 只剩供应商主键不一致类 |
| 单据类型 = 到货通知 | 主单为到货通知的行；入库明细/库存明细/进项主单不出现 |
| 单据类型 = 进项发票 | 主单为进项发票的行 |
| 单号输入入库单号前缀回车或点搜索 | 单号或关联单号以该前缀开头（忽略大小写）的行留下 |
| 单号输入完整单号 | 命中该单及以其为单号/关联单号的行（右模糊，不含中间匹配） |
| 单号输入中间片段 | **不命中**（非包含匹配） |
| 组合：级别错误 + 检查类型重复 + 单号前缀 | 同时满足才显示 |
| 过滤后无行 | 文案「当前过滤无匹配。」，不是「未发现异常。」 |
| 重置 | 条件清空，表恢复本次检查全量；不重新跑检查 |
| 截断提示仍在时过滤 | 只切已返回的前 2000 条；顶栏截断提示仍在 |

### 本地样例（有则必测）

| 数据 | 预期至少含 |
|------|------|
| 到货通知状态 100、无已过账采购入库、也无未过账单 | 错误：已入库但无已过账采购入库；建议仅 ① 打开「Debug 模拟数据」，点「刷新到货通知状态」。无「反核销」 |
| 到货通知状态 100、仅有未过账采购入库 | 建议含对该入库单号「标记已入库」，再 Debug「刷新到货通知状态」 |
| 已过账采购入库存在、通知仍为 30 | 错误：建议仅 Debug「刷新到货通知状态」 |
| 同一通知 ≥ 2 张已过账采购入库、均未核销 | **保留入库单号最小的一张**；建议含对其余单号「强制删除」+ 输入对应单号，最后 Debug 刷新；**不得**出现「反核销」 |
| 其余重复入库已核销 | 建议第一步为打开具体「进项发票」单号点「反核销」并输入该进项发票单号；再对该入库「强制删除」。不得写「到进项发票列表里找」 |
| 入库已删、进项核销流水仍在 | 建议仅 ① 打开「进项发票」该发票单号，点「反核销」，输入该单号确认 |
| 质检已通过、尚无已过账入库（待入库） | **不得**出现「质检完未入库」类错误或警告 |
| 报关/退货/报废/调拨入库异常 | **不参与**本页扫描 |

## 三、口径 / 公式核对

本功能**不做核销提交**。金额是对账：

```text
期望金额 = Round(入库明细 Quantity × Price, 2, AwayFromZero)
一致：|期望 − Amount| ≤ 0.009  → 不报
不一致：差额 ≥ 0.01         → 报错误
```

| 用例 | 预期 |
|------|------|
| **足额（期望金额 = 明细金额）** | **不报金额错误**（单测 `AmountsMatch_Equal_IsTrue`，复用 `StockOutOpsCheckAmounts`） |
| 超额 0.01 | 报金额不一致（单测 `AmountsMatch_OverByOneCent_IsFalse`） |
| 少 0.01 | 同上 |
| 核销/匹配提交 | **本功能不适用：无核销、匹配、付款提交** |

供应商：到货通知 / 入库单 / 采购订单 `VendorId` 不一致 → 错误；原因写各单**单号**及供应商**编码**，不得出现 GUID。  
客户：采购入库 **本功能不适用**。  
报关/退货/报废/调拨入库不参与。
