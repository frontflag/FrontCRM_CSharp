## 一、入口与权限

| 步骤 | 预期 |
|------|------|

| 本功能不新增 write 按钮 | 无「一键修复」 |

## 二、检查与结果

| 步骤 | 预期 |
|------|------|
| 进入后未点检查 | 提示点击「检查」开始；表空 |
| 点「检查」 | 按钮「检查中…」；完成后表出结果；标题与筛选之间数据面板：「错误」红字、「警告」橙字、「合计」青字 |
| 全量 | 不要求输入装箱单号或日期；过滤不改变扫描范围（不发带条件的 API） |
| 单号可点 | 装箱单 → 装箱详情；装箱行 → 装箱明细列表；出库单 → 出库详情；应收 → 应收详情 |
| 运维操作建议 | 须含页面名 + **本行单号** + 按钮名；一步一行、①②③ 编号；换行可见。未核销行**不得**出现「反核销」。已核销须写出**收款单号**（不是「到列表里找」）。重复出库保留单号最小的一张，只对其余单写「强制删除」。出库仍有效的金额类建议**不得**含「作废应收」。不含「软删」「picking_task_item_id」等开发用语 |
| 建议换行 | `PAK0020C` 重复行的运维操作建议分多行显示（①②③④），不是挤在同一行 |

## 二-b、结果过滤（前端切片）

先跑出一份含多类问题的报告，再测过滤。过滤**不重新请求** `POST /api/v1/stock-out/ops-check`。

| 步骤 | 预期 |
|------|------|
| 级别 = 错误 | 只剩错误行；数据面板全量错误/警告/合计不变；第三张改为「显示 x / y」 |
| 级别 = 警告 | 只剩警告行 |
| 清空级别 | 恢复该维度全部 |
| 检查类型 = 重复 | 只剩重复类（如 `PAK0020C` 多张出库）；不含金额/客户等其它类 |
| 检查类型 = 金额 | 只剩数量/金额/币别对账类 |
| 单据类型 = 装箱单 | 主单为装箱单的行；装箱明细/出库/应收主单不出现 |
| 单据类型 = 应收款 | 主单为应收的行 |
| 单号输入 `PAK` 回车或点搜索 | 单号或关联单号以 `PAK` 开头（忽略大小写）的行留下；`STO` 开头且关联也不是 `PAK*` 的行消失 |
| 单号输入完整 `PAK0020C` | 命中该装箱及以其为单号/关联单号的行（右模糊，不含中间匹配） |
| 单号输入中间片段（如 `0020`） | **不命中** `PAK0020C`（非包含匹配） |
| 组合：级别错误 + 检查类型重复 + 单号 `PAK` | 同时满足才显示 |
| 过滤后无行 | 文案「当前过滤无匹配。」，不是「未发现异常。」 |
| 重置 | 条件清空，表恢复本次检查全量；不重新跑检查 |
| 截断提示仍在时过滤 | 只切已返回的前 2000 条；顶栏截断提示仍在 |

### 本地样例（有则必测）

| 数据 | 预期至少含 |
|------|------|
| `PAK001ZB` 状态 100、出库已软删 | 错误：出库完成但无有效出库；建议仅 ① 点本行该装箱单号打开「装箱单详情」，点击「刷新」。无「反核销」 |
| 出库已删、应收仍在且未核销（如 `ARV00007` / `STO0020X`） | 建议仅 ① 打开「应收款详情」`ARV00007`，点「作废应收」，输入 `ARV00007` 确认。无「反核销」。点单号进详情后右上角有「作废应收」；作废后该行从应收列表消失，再检查不再报 |
| 出库**仍有效**、未核销应收 | 应收详情**无**「作废应收」。`POST …/void` 返回失败，文案「出库单仍有效，不能作废应收」。要拆链须先反核销（若已核销）再对该出库「强制删除」（会一并软删未核销应收） |
| 强制删除未核销应收的出库 | 出库与该出库下有效未核销应收一并软删；再检查**不得**再报「出库单已删除，应收仍有效」 |
| 出库已删、应收已核销 | 建议第一步为打开具体「收款单」`FRC…` 点「反核销」并输入该收款单号；第二步对该应收「作废应收」。详情无「作废应收」按钮直至反核销。不得写「到收款单列表里找」 |
| `PAK0020C` 状态 40、四张出库完成、应收均未核销 | 错误：有有效出库但装箱不是 100（建议仅刷新装箱）。错误：重复出库（`STO00221/222/223/22M`），**保留 `STO00221`**；建议含对 `STO00222`、`STO00223`、`STO0022M` 的「强制删除」+ 输入对应单号，最后本行 `PAK0020C`「刷新」；**不得**出现「反核销」。原因含应收 `ARV0001D/E/F/G` 且未核销 |

## 三、口径 / 公式核对

本功能**不做核销提交**。金额是对账：

```text
期望金额 = Round(Σ 出库行数量 × 销售行单价, 2, AwayFromZero)
期望数量 = Σ 出库行数量（扩展 QtyStockOut > 0 用扩展，否则 ActualQty/Quantity）
一致：|期望 − 应收| ≤ 0.009  → 不报
不一致：差额 ≥ 0.01         → 报错误
```

| 用例 | 预期 |
|------|------|
| **足额（期望金额 = 应收金额）** | **不报金额错误**（单测 `AmountsMatch_Equal_IsTrue`） |
| 超额 0.01 | 报金额不一致（单测 `AmountsMatch_OverByOneCent_IsFalse`） |
| 少 0.01 | 同上 |
| 核销/匹配提交 | **本功能不适用：无核销、匹配、付款提交** |

币别：应收 `Currency` ≠ 销售订单 `Currency` → 错误。  
客户：装箱 / 出库 / 应收 / 销售订单 `customer_id` 不一致 → 错误。  
供应商：销售出库 **本功能不适用**。  
调拨虚拟出库（类型 3）不参与。  
金额/数量/币别不一致且出库仍有效：运维建议为反核销（仅已核销）→ 强制删除出库 → 重出 → 标记完成，**不得**出现「作废应收」。
