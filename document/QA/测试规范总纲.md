# 测试规范总纲

本文是 FrontCRM **测试文档与验收** 的总纲，汇总自 `document/QA/` 下既有「测试对照说明」的通用写法与要求。

## 0. 强制遵守（人工与 AI）

**以后生成或更新各功能的测试用例 / 测试对照说明时：**

1. **必须先完整阅读本文**（`document/QA/测试规范总纲.md`），不得跳过。
2. **生成的文档必须落实本文全部适用要求**（结构、交叉引用、§4 通用维度、§4.5 金额边界、§6 自检等）。
3. 某条款对本功能确实不适用时，须在对照说明中**显式注明「本功能不适用：…」**，不得省略后假装已覆盖。
4. 未通过 §6 自检清单，不得视为该测试文档已完成。

Cursor 规则：`.cursor/rules/qa-test-spec.mdc`（alwaysApply）。

**关联：**

- [文档生成规范](../System/文档生成规范.md)（目录职责、命名、EBS 只读）
- 各功能对照正文：`document/QA/{业务域}/*-测试对照说明.md`
- 设计实现：`document/System/`；看板口径：`document/IMP/`；用户帮助：`help/pages/`（**不**替代 QA）

## 1. 定位与读者

| 文档类型 | 路径 | 读者 | 用途 |
|----------|------|------|------|
| **本总纲** | `document/QA/测试规范总纲.md` | 测试 / 开发 / AI | 通用要求、写法、必测边界 |
| **测试对照说明** | `document/QA/{域}/…-测试对照说明.md` | 测试为主 | 可执行步骤 ↔ 预期结果 |
| 设计与实现 | `document/System/…` | 开发为主 | 口径与实现索引 |
| 用户帮助 | `help/pages/` | 业务用户 | 操作说明，**禁止**堆权限码/表名/路由细节 |

测试对照说明侧重 **「按什么条件、看什么结果、和什么公式核对」**，不是复制设计全文。

## 2. 目录与命名

### 2.1 业务域子目录（与现网一致）

| 子目录 | 典型内容 |
|--------|----------|
| `财务/` | 收付款、核销桌面、发票、列表页签 |
| `数据分析/` | 销售/采购/物流/财务分析、滚存；见 [数据分析/README](./数据分析/README.md) |
| `销售/` `采购/` `物流/` `报关/` `需求/` `需求报价/` | 列表、操作面板、流程页签、打印皮肤 |
| `审批/` `报价/` `客户/` `供应商/` `系统/` | 桌面、KPI、埋点/公告等 |

新建对照说明时放入对应域目录；无合适目录时先建域文件夹，勿散落在 `QA/` 根下（**本总纲除外**）。

### 2.2 命名

```text
{功能简称}-测试对照说明.md
```

示例：`进项发票核销桌面-测试对照说明.md`、`销售订单明细列表-操作面板-测试对照说明.md`。

禁止：在 `document/EBS/` 下新建或修改测试文档（见文档生成规范）。

### 2.3 交叉引用（强制）

每份对照说明文首须能链到：

1. **设计文档**（`document/System/…` 或必要的 `IMP/`）
2. **页面路由或菜单路径**（可写在文首元信息）

设计文档文首宜反向链到对应 QA。帮助文档可链业务帮助页，但 QA **不**用帮助文代替验收口径。

## 3. 单份「测试对照说明」推荐结构

```markdown
# {功能} — 测试对照说明

> **页面 / 路由：** …
> **设计文档：** […-设计与实现](…)
> **权限 / DDL（如有）：** …

## 一、入口与权限
| 步骤 | 预期 |
|------|------|

## 二、…（按功能分节）

## …、口径 / 公式核对（金额、看板类必写）

## …、回归 / 交叉（相关列表、旧页、脱敏）

*部署含 … 的版本后验收。*
```

### 3.1 写法约定

| 约定 | 说明 |
|------|------|
| **步骤 ↔ 预期** | 优先表格；勾选清单 `- [ ]` 适用于短门控项 |
| **可观测** | 写清界面文案、字段、Network 请求名、库表公式中的一种或多种 |
| **默认与持久化** | 页签模式、面板左右/上下、排序偏好等须写「刷新后是否保持」 |
| **已知差异** | 与 EBS / 旧页不一致处单列「已知口径差异」，避免误报缺陷 |
| **范围外** | 文末可声明「本版不测 …」，避免无限扩 scope |

### 3.2 数据分析专项

看板类对照说明必须包含：

- 筛选条件与 API/视角参数一致（见 [数据分析/README](./数据分析/README.md)）
- **统计公式**（可在库或业务列表手工复算）
- 「测试注意」与「已知口径差异」
- 金额类：折算美金主口径（如订单行 `convert_price`）与回落规则写清楚

## 4. 通用验收维度（散落文档共性）

以下维度按功能适用性裁剪，**适用则必须写进该功能的对照说明**。

### 4.1 入口与权限

- 菜单 / 列表右上角入口文案与路由正确
- 无 read：不可进入；无 write：可看不可提交（或按钮禁用）
- 运维类功能：无对应权限码则无菜单

### 4.2 数据范围与脱敏

- 列表/看板结果受部门或业务数据权限约束
- 销售/采购敏感掩码下金额、客商名为 `—`，**面板仍应能加载**（操作面板类已有先例）

### 4.3 工作台 / 桌面（左栏队列 + 中区）

适用于审批桌面、报价桌面、收款/进项核销桌面等：

| 检查点 | 典型预期 |
|--------|----------|
| 左栏入列条件 | 与设计一致（如双边都有待办才入列） |
| 搜索 | 过滤左栏；顶栏全局计数是否变化写清 |
| 顶栏 N/M、上一条/下一条 | 与左栏可见列表或全局口径一致 |
| 提交成功后 | 是否留在当前桶、队列是否刷新 |
| 右扩展默认页签 | 如核销桌面默认「出库单/入库单」 |

### 4.4 列表页签模式 / 左栏检索 / 操作面板

- **页签模式**：开启后对应下拉隐藏；点页签即查；F5 持久化；亮暗主题未选中底色
- **左栏检索 preset**：与主列表筛选互斥/叠加规则写清；与操作面板交叉时注明须先满足右栏「操作」页签门控
- **操作面板门控（§2.4 类）**：收起右栏单击不请求；在「帮助」页签单击不高开帮助；切到「操作」才拉聚合

### 4.5 金额与核销 / 匹配类（强制边界）

金额提交、核销、匹配进度类功能，对照说明 **至少** 覆盖：

| 用例 | 预期 |
|------|------|
| **足额（本次金额 = 待核销/待匹配）** | **成功** |
| 略超（大于待核销一个最小货币单位或明确小数） | 拒绝，余额不变 |
| 分次核销至清零 | 状态与余额正确 |
| 前端提示与后端拒绝 | 文案可不同，但业务结果一致 |

> **教训：** 「超额拒绝」测了不等于「刚好相等成功」测了。容差比较方向写反时，**仅相等场景会失败**，界面显示却都是同一金额。

公式区建议写明（示例）：

```text
待核销 = 总额 - Σ已核销流水
提交合计 ≤ 待核销（允许最小容差内相等）
```

### 4.6 多租户皮肤 / 打印

- 在 **semicore / idesemi / ecoinf** 分别验收
- 通过标准：观感差异明显（不只换 Logo）；同租户多报表主色/页眉一致
- 打印：壳层隐藏、色块保留

### 4.7 上线前置

涉及迁移、权限脚本、埋点表等时，文首或「上线前」节写清：

1. 须执行的 SQL / 迁移  
2. 须重启的服务  
3. 须重新登录的角色  

未部署对应版本则对照说明无效（文末可注明）。

## 5. 手工对照与自动化的分工

| 层级 | 职责 | 现状约定 |
|------|------|----------|
| **QA 对照说明** | 页面流程、口径公式、权限门控、多租户观感 | 主验收依据；本目录文档 |
| **后端单测 / 集成测** | 服务边界：金额相等/超额、状态机、幂等 | 财务核销 `Apply*`、金额容差等 **应有单测**；不得仅依赖手工 |
| **前端 typecheck / CI** | 编译与类型 | **不**替代业务验收 |

新增金额校验逻辑时：开发侧补单测；QA 侧补 §4.5 边界行。二者缺一，相等类缺陷易漏到生产。

## 6. 编写与评审自检清单

新建或大改某功能对照说明时：

- [ ] 落在 `document/QA/{正确业务域}/`，命名 `*-测试对照说明.md`
- [ ] 文首有路由/菜单 + 设计文档链接
- [ ] 含入口与权限（若适用）
- [ ] 金额/核销/匹配类含 **足额成功 + 超额拒绝**
- [ ] 看板类含公式与已知差异
- [ ] 桌面/页签/操作面板类含持久化与门控交叉
- [ ] 未改动 `document/EBS/`
- [ ] 未把开发术语堆进 `help/pages/` 充当验收文档

设计变更导致验收变化时：**同步改** System 设计文档与对应 QA 对照说明。
