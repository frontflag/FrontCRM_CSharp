# 采购订单换供应商 / 刷新供应商 — 测试对照说明

> **页面 / 路由：** `/purchase-orders/:id/edit`（编辑换供应商）；详情 `/purchase-orders/:id`「刷新 ▾ → 刷新供应商」  
> **设计文档：** [采购订单换供应商-设计与实现](../../System/采购/采购订单换供应商-设计与实现.md)  
> **自动化：** `tests/CRM.Core.Tests/Services/PurchaseOrderVendorChangeServiceTests.cs`  
> **上线前：** 无迁移、无新权限码；部署含本能力的版本后验收。采购员审核前换供应商只需采购订单写权限，不必单独授权「换供应商」。

---

## 一、入口与权限

| 步骤 | 预期 |
|------|------|
| 采购员（有采购订单写权限、无换供应商特权）打开 **新建 / 待审核 / 审核失败** 单的编辑页 | 可搜索更换供应商 |
| 同上账号打开 **审核通过及之后** 的编辑页 | **不能**换供应商（只读展示） |
| 系统管理员 / 采购总监 / 持有换供应商特权的账号，审核通过后的编辑页 | 仍可换（下游完结规则见第二节） |
| 采购脱敏账号（销售方向且主部门采购数据禁止） | 编辑页无供应商搜索；改供应商接口 403 |
| 无采购订单写权限 | 不可保存；预检/刷新接口 403 |
| 待审核单上采购员换供应商后，审批桌面打开该单 | **按最新供应商**展示与调查，不是提交当时的旧供应商 |

数据范围：只能改本人数据范围内的采购订单。

---

## 二、编辑换供应商（必测）

准备两家供应商 A、B；一张有未完结下游的单、一张已入库完成且供应商仍为 A 的单。

| 步骤 | 操作 | 预期 |
|------|------|------|
| 1 | 编辑页将供应商由 A 改为 B | 页顶 tip 列出拟同步下游或阻断原因（仅提醒，尚未保存） |
| 2 | 有已完结且供应商仍为 A 的下游 → 点保存 | 弹窗「当前无法保存供应商资料」+ 阻断原因；**不保存** |
| 3 | 仅未完结下游（或无下游）→ 保存 →「刷新并保存」 | 一次保存头供应商 + 明细 + 未完结下游 |
| 4 | 保存确认点「取消」 | 留在编辑页，未落库 |
| 5 | **待审核**单由采购员完成步骤 3 | 保存成功；审批人看到 B |

---

## 三、日志（必测）

更换 **供应商 ID**（A→B）保存成功后：

| 位置 | 预期 |
|------|------|
| 采购订单详情「更改日志」 | 字段「供应商」，原值为 A（编码+名称）、新值为 B；操作人为当前用户 |
| 系统日志 → 操作日志 | `更换供应商`；描述含由 A 换到 B，以及同步的明细/下游条数 |

仅刷新名称（同一供应商 ID）：更改日志记供应商名称变化；**不**写操作日志「更换供应商」。

---

## 四、详情页「刷新 ▾ → 刷新供应商」（必测）

| 步骤 | 操作 | 预期 |
|------|------|------|
| 1 | 主数据改名后，订单头快照仍为旧名 | 明细列表可能显示旧名 |
| 2 | 详情页 `刷新 ▾` → **刷新供应商** → 确认 | 头名称与主数据一致；未完结下游名称同步 |
| 3 | 已完结下游供应商 ID 已正确 | **不阻断**头名称刷新 |
| 4 | 编辑页供应商旁 | **无**单独「刷新」链接（入口已并入详情） |
| 5 | 采购员对 **审核通过** 单点刷新供应商 | 无入口或接口 403 |

---

## 五、口径 / 公式核对

本功能不适用：金额核销 / 匹配足额与超额（无核销提交）。

核对点：头 `vendor_id` 与明细 `vendor_id` 保存后一致；未完结下游供应商 ID 与头一致。

---

## 六、回归 / 交叉

- 改动换供应商 / 刷新名称 / 审核前门控时跑本节一～四  
- 审批桌面采购订单：待审期间换商后中栏供应商与右栏调查跟新供应商  
- 采购参数「允许刷新已完成业务节点」开启时，已完结下游不再阻断（见 [采购参数-刷新供应商](./采购参数-刷新供应商-测试对照说明.md)）  
- CI：`dotnet test --filter PurchaseOrderVendorChangeServiceTests`

本功能不适用：列表页签模式 / 左栏检索 / 操作面板门控；多租户打印皮肤。
