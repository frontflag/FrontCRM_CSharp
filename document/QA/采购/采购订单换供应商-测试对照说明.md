## 一、入口与权限

权限用例已集中维护于：[权限/采购订单换供应商-权限测试对照说明.md](../权限/采购订单换供应商-权限测试对照说明.md)。

本节保留核心结论：采购员有写权限可在审核前换供应商；审核后需系统管理员/采购总监/换供应商特权；采购脱敏/无写权限/无数据范围均不可操作。

## 二、编辑换供应商（必测）

准备两家供应商 A、B；一张有未完结下游的单、一张已入库完成且供应商仍为 A 的单。

| 步骤 | 操作 | 预期 |
|------|------|------|
| 1 | 编辑页将供应商由 A 改为 B | 页顶 tip 列出拟同步下游或阻断原因（仅提醒，尚未保存） |
| 2 | 有已完结且供应商仍为 A 的下游 → 点保存（参数默认不允许） | 弹窗「当前无法保存供应商资料」+ 阻断原因；**不保存** |
| 2b | 同上，采购参数「刷新供应商」允许 | 确认「刷新并保存」（能看到已完结清单）；确定后保存成功。**不**走详情 `confirmCompleted` |
| 3 | 仅未完结下游（或无下游）→ 保存 →「刷新并保存」 | 一次保存头供应商 + 明细 + 未完结下游 |
| 4 | 保存确认点「取消」 | 留在编辑页，未落库 |
| 5 | **待审核**单由采购员完成步骤 3 | 保存成功；审批人看到 B |

---

## 三、日志（必测）

更换 **供应商 ID**（A→B）保存成功后：

| 位置 | 预期 |
|------|------|
| 采购订单详情「更改日志」 | 字段「供应商」，原值为 A（编码+名称）、新值为 B；操作人为当前用户 |
| 系统日志 → 操作日志 | `更换供应商`；描述含由 A 换到 B，以及同步的明细/下游条数 |

仅刷新名称（同一供应商 ID）：更改日志记供应商名称变化；**不**写操作日志「更换供应商」。

---

## 四、详情页「刷新 ▾ → 刷新供应商」（必测）

| 步骤 | 操作 | 预期 |
|------|------|------|
| 1 | 主数据改名后，订单头快照仍为旧名 | 明细列表可能显示旧名 |
| 2 | 详情页 `刷新 ▾` → **刷新供应商** → 确认 | 先预检；无已完结则原确认即可。头名称与主数据一致；未完结下游名称同步 |
| 2b | 参数允许且有已完结 | 警告列出单据；取消不刷新；确定后 `confirmCompleted=true` 才覆盖 |
| 3 | 已完结下游供应商 ID 已正确 | **不阻断**头名称刷新 |
| 4 | 编辑页供应商旁 | **无**单独「刷新」链接（入口已并入详情） |
| 5 | 采购员对 **审核通过** 单点刷新供应商 | 无入口或接口 403 |

---

## 五、口径 / 公式核对

本功能不适用：金额核销 / 匹配足额与超额（无核销提交）。

核对点：头 `vendor_id` 与明细 `vendor_id` 保存后一致；未完结下游供应商 ID 与头一致。

---

## 六、回归 / 交叉

- 改动换供应商 / 刷新名称 / 审核前门控时跑本节一～四  
- 审批桌面采购订单：待审期间换商后中栏供应商与右栏调查跟新供应商  
- 采购参数「分面刷新 → 刷新供应商」开启时，已完结下游不再阻断，但**详情**刷新须确认列出的单据；**编辑保存**仍走「无法保存 / 刷新并保存」，不套详情 `confirmCompleted`（见 [采购参数-分面刷新](./采购参数-刷新供应商-测试对照说明.md)、[分面刷新对照](./采购订单分面刷新-测试对照说明.md) §九）  
- CI：`dotnet test --filter PurchaseOrderVendorChangeServiceTests`

本功能不适用：列表页签模式 / 左栏检索 / 操作面板门控；多租户打印皮肤；工作台左栏队列（§4.3）。审批桌面仅作交叉：待审期间换商后中栏跟新供应商。
