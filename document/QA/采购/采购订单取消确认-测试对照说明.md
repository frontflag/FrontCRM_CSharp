## 一、入口与权限

权限用例已集中维护于：[权限/采购订单取消确认-权限测试对照说明.md](../权限/采购订单取消确认-权限测试对照说明.md)。

## 二、无下游：退回待确认（必测）

准备一张 **已确认**、无付款单、无到货通知、无已过账采购入库、无进项发票的采购订单（可仅有货代单号）。

| 步骤 | 预期 |
|------|------|
| 列表点「取消确认」 | 确认框写明将退回「待确认」，**不是**取消订单 |
| 点确认 | 主状态与明细状态均为 **待确认(20)**；成功提示「已退回待确认」 |
| 更改日志 | 字段「订单状态」，原值「已确认」，新值「待确认」 |
| 再点「供应商确认」 | 可回到已确认(30) |
| 详情顶栏对同一单再测一遍 | 与列表同一结果 |

货代单号已填：**不**阻断。

---

## 三、有下游：禁止退回（必测）

主状态保持 **已确认**，单据不变。

| 准备 | 点取消确认 | 预期 |
|------|------------|------|
| 未删除、非取消/非审核失败的付款单（含在途未付请款） | 拒绝 | 提示含「付款单」及单号；状态仍为已确认 |
| 仅已取消或已删除的付款单 | 允许 | 退回待确认 |
| 未删除的到货通知 | 拒绝 | 提示含「到货通知」 |
| 已过账采购入库（类型为采购入库） | 拒绝 | 提示含「入库单」 |
| 进项发票（未删除） | 拒绝 | 提示含「进项发票」 |
| 草稿/待入库入库单、无到货通知、无付款、无发票 | 允许 | 退回待确认（仅拦已过账采购入库） |

---

## 四、与「取消订单」交叉

| 步骤 | 预期 |
|------|------|
| 审核通过前详情点「取消订单」 | 主状态变为 **取消(-2)**，不是待确认 |
| 已确认后点「取消确认」 | 变为待确认，**不是**取消 |
| 待确认后 | 无「取消订单」按钮；不能从界面整单取消 |

---

## 五、口径 / 公式核对

本功能不适用：金额核销 / 匹配的足额成功与超额拒绝（总纲 §4.5）。本操作不提交核销金额。

状态码：已确认 `30` → 待确认 `20`。明细随主单同步。

---

## 六、回归 / 交叉

| 步骤 | 预期 |
|------|------|
| 申请付款 / 通知到货 | 退回待确认后不可再申请（门槛为已确认及之后） |
| 采购单打印 | 待确认后打印入口按「须已确认」隐藏或提示 |
| 销售订单「取消订单」 | 不受本次改动影响 |

---

## 七、本功能不适用

- **本功能不适用：工作台 / 桌面左栏队列（总纲 §4.3）。**
- **本功能不适用：金额提交 / 核销 / 匹配足额与超额（总纲 §4.5）。**
- **本功能不适用：数据分析看板公式。**
- **本功能不适用：多租户皮肤 / 打印（总纲 §4.6）。** 打印仅回归「待确认后不可出采购单报表」。
- **本功能不适用：列表页签模式 / 左栏检索 / 操作面板单击门控（总纲 §4.4）。** 本按钮在采购订单列表操作列与详情顶栏，不经过明细列表右侧操作页签。

---

## 八、上线前

1. 部署含 `PurchaseOrderRevertVendorConfirmGuard` 与 `30 → 20` 流转的 API 与前端。  
2. 重启 API。  
3. 无需新权限脚本、无需重新登录（已有采购订单写权限即可）。  
4. 历史已误写成「取消」的已确认单 **不会** 自动回到待确认，需另行改库。

*部署含本改动的版本后验收。*
