# 采购参数 · 默认分配方式 — 测试对照说明

> **页面 / 路由：** `/system/purchase-params/default-assign-method`（菜单：参数管理 → 采购参数 → 默认分配方式）  
> **设计文档：** [采购参数-默认分配方式-设计与实现](../../System/采购/采购参数-默认分配方式-设计与实现.md)、[指定采购-分配方式-设计与实现](../../System/需求/指定采购-分配方式-设计与实现.md)  
> **权限：** 查看须采购参数「默认分配方式」读权限；保存须写权限。**无新权限码、无新迁移。**  
> **总纲：** [测试规范总纲](../测试规范总纲.md)

---

## 一、入口与权限

| 步骤 | 预期 |
|------|------|
| 有默认分配方式读权限 | 采购参数左栏可见「默认分配方式」 |
| 进入页面 | 右栏有「分配方式」下拉，以及勾选 **允许指定采购**（默认未勾选） |
| 无读权限 | 左栏无该项；直接打开地址被拒 |
| 有读、无写 | 可看当前值；保存失败或不可提交（与其它采购参数页一致） |
| 分配方式下拉选项 | 仅采报优先、条目轮询、品牌轮询；**没有**指定采购 |

---

## 二、默认与持久化

| 步骤 | 预期 |
|------|------|
| 从未保存过「允许指定采购」（无参数行） | 勾选为关；分配方式为采报优先（或已保存的 2/3/5） |
| 改分配方式为条目轮询并保存，刷新 | 仍为条目轮询 |
| 勾选「允许指定采购」并保存，刷新 | 勾选仍为开 |
| 取消勾选并保存，刷新 | 勾选仍为关 |
| 保存后点「刷新」 | 与已保存值一致；未保存改动被丢弃 |

---

## 三、与新建 / 编辑需求联动

| 步骤 | 预期 |
|------|------|
| 勾选关闭，打开新建需求 | 「分配方式」**没有**指定采购 |
| 勾选开启并保存后，重新打开新建需求 | 下拉最后一项为 **指定采购** |
| 勾选关闭后打开已是指定采购的需求 | 下拉仍显示指定采购（当前值），可保存 |
| 勾选关闭后把其它方式改成指定采购（绕过前端） | 接口拒绝，文案含「未开启指定采购」 |
| 仅有需求创建、无采购参数权限 | 勾选开启后仍能看到指定采购选项 |

需求页表单、保存与编辑细则见 [需求新建指定采购-测试对照说明](../需求/需求新建指定采购-测试对照说明.md)。

## 四、回归 / 交叉

|------|------|
| 保存本页 | 报价人数、报价员池、需求保护时长、分面刷新不受影响 |

---

## 五、本功能不适用

- **本功能不适用：§4.5 核销金额足额成功 / 超额拒绝**（本页不提交核销/匹配金额）。
- **本功能不适用：工作台左右栏队列 / 列表页签模式 / 操作面板门控。**
- **本功能不适用：多租户打印皮肤。**
- **本功能不适用：销售/采购金额脱敏**（本页不展示敏感金额列）。
- **本功能不适用：看板统计公式 / 数据分析筛选。**
- **本功能不适用：部门数据范围**（系统参数全站一份，有权限即读写该参数）。

## 六、上线前置

1. 部署含本改动的 **CRM.API** 后须 **重启 API**。
2. 无新 SQL 迁移、无新权限码。可选执行 `scripts/ensure_rfq_allow_designated_purchaser_postgresql.sql`；未执行时 GET 视为关闭，首次在本页保存会自动建行。
3. 改勾选后须重新进入新建/编辑需求页，才能看到下拉变化。

*部署含「允许指定采购」门控的 API + 前端后验收。*
