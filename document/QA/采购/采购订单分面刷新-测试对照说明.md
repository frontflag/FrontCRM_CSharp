## 一、入口与权限

权限用例已集中维护于：[权限/采购订单分面刷新-权限测试对照说明.md](../权限/采购订单分面刷新-权限测试对照说明.md)。

本节保留核心结论：状态/型号/品牌/数量/单价需采购订单写权限；刷新供应商需与换供应商相同权限；无新权限码、无新迁移。

**本功能不适用：** 工作台/桌面左栏队列（§4.3）、列表页签模式 / 左栏检索 / 操作面板门控（§4.4）、多租户皮肤 / 打印（§4.6）。无需新 SQL / 迁移 / 重新登录（§4.7）。

**本版不测：** 「刷新全部」（无入口）。列表页右上角「刷新」是重查列表，不是本功能。

**本轮补加核对：** 已完结须预检列出、确认后才覆盖（§九）；刷新型号/品牌结果含「删除空汇总」（§四步骤 11，Z = 去掉几条空汇总行，不是删库存数量）；编辑换供应商不套详情 `confirmCompleted`（§九步骤 6）。供应商默认不允许已完结，见参数页对照。

## 二、刷新状态

前置：明细主状态曾被写高（如已入库），但扩展入库进度仍为待入库。

| 步骤 | 操作 | 预期 |
|------|------|------|
| 1 | 点「刷新状态」并确认 | `POST …/refresh` body `facet=status` |
| 2 | 确认文案 | 说明不改供应商、型号、品牌、数量、单价 |
| 3 | 明细状态 / 扩展进度 | 按付款、入库、出库事实对齐；可下调 |
| 4 | 到货通知 | **状态**可按质检/入库事实重算；`Pn` / `Brand` / `Cost` / `ExpectQty` **不变** |
| 5 | 入库 / 库存 / 出库 | 单价、数量、型号、品牌快照不变 |
| 6 | 操作日志 | 有「刷新状态」（若确实有字段变化） |

## 三、刷新供应商

口径与 [采购订单换供应商-测试对照说明](./采购订单换供应商-测试对照说明.md) 详情刷新相同。本页只核对：下拉「刷新供应商」仍走预检。参数关：已完结且供应商不一致 → 无法刷新。参数开：预检列出已完结单据，确认后 `refresh-vendor-name` 带 `confirmCompleted=true`；取消则不刷新。不改采购价 / 品牌 / 数量。

---

## 四、刷新物料型号 / 刷新品牌

前置：采购明细已改型号或品牌并保存；到货通知、入库明细、装箱、报关、库存明细仍是旧快照。库存中心该型号/品牌仍挂在旧堆。

**本功能不适用：足额成功 / 超额拒绝的核销或发票匹配提交。** 本分面不改采购价、入库金额、请款付款流水。

库存分堆核对（刷新后手工复算）：

```text
旧汇总行 Qty = Σ(仍挂该汇总行的库存明细 QtyInbound)；无明细且数量全 0 → 软删，库存中心不再列出
新汇总行 Qty = Σ(改挂到新汇总行的库存明细 QtyInbound)
QtyStockOut / 占用 / 预占 / 在库 / 可用 同样按明细层求和
空堆：无在库明细且数量全 0 则软删（库存中心不再列出）；库存明细编号不变
```

| 步骤 | 操作 | 预期 |
|------|------|------|
| 1 | 「刷新品牌」确认 | `facet=brand`；确认框为警告样式；文案写明会改库存分堆、可能新建汇总行、重算备货可用量 |
| 2 | 到货通知 / 质检列表 | 品牌 = 采购行当前品牌；型号列不变 |
| 3 | 入库明细 | 采购品牌更新；采购型号不变 |
| 4 | 装箱明细 | 品牌更新 |
| 5 | 报关明细 | 采购品牌更新；申报单价不变 |
| 6 | 库存明细 | 采购品牌 = 新值；采购型号仍为旧值；**库存明细编号不变** |
| 7 | 库存中心 / 库存桶 | 明细改挂到新品牌对应堆（已有则合并，没有则新建）；旧堆若已无明细则不再出现；新堆数量 = 迁入层入库累计 |
| 8 | 备货可用量 | 旧型号品牌与新型号品牌两侧可用量按库存中心口径重算（客单行备货占用不受错误分堆残留） |
| 9 | 「刷新物料型号」对称 | 只改型号类快照与分堆键中的型号，品牌不变 |
| 10 | 已入库到货；参数「刷新物料型号」允许 | 预检列出已入库等到货/库存单据；确认后仍覆盖快照并换堆 |
| 10b | 同上；参数改为不允许 | **整面拦住**，库存分堆不变 |
| 11 | 结果弹窗 | 含库存明细 / 换堆 / 新建汇总 / 删除空汇总计数。删除空汇总 = 这次去掉了几条已无明细且数量为 0 的库存汇总行，**不是**再删库存数量 |
| 12 | 仅大小写或首尾空格不同 | 仍算同一堆：不新建、不改明细挂接，只对齐汇总行展示文案；不删该堆 |
| 13 | 旧堆仍有其它在库明细 | 旧堆保留；数量 = 留下的明细合计 |

## 五、刷新数量

**本功能不适用：足额成功 / 超额拒绝的核销或发票匹配提交。** 刷新数量不发起请款、付款核销、进项匹配，也不改已有流水或入库实绩数量。

刷新后行总额仍为：

```text
行总额 = 采购行数量 × 当前单价
到货通知金额 = 通知数量 × 通知现有单价（本分面不改单价）
```

| 步骤 | 操作 | 预期 |
|------|------|------|
| 1 | 一行仅 1 条到货，预计数量 1000，采购行 800，点「刷新数量」 | 预计数量变为 800；通知单价、品牌不变；金额按 800×原单价 |
| 2 | 一行 2 条分批到货（300+200），采购行 1000 | 各批次数量**不变**（不扩成整单） |
| 3 | 入库明细数量 / 库存结存 / 出库数量 | **不变** |
| 4 | 采购数量小于已收+在途 | 失败，提示不能小于已收与在途之和 |
| 5 | 扩展待通知量、采购/入库进度 | 按新计划量与现有入库事实重算 |
| 6 | 关联：刷新数量后去进项匹配桌面 | 待匹配仍按入库金额（入库数量未改）；**足额成功**，略超**拒绝**（验收见进项发票对照） |
| 7 | 到货已入库；参数允许 | 警告列出该到货通知，确认后才可能收缩计划量 |
| 8 | 到货已入库；参数不允许 | 拦住，计划量不变 |

## 六、刷新单价

入口改为「刷新 ▾ → 刷新单价」。金额、超额警告、无状态门控、幂等见 [下游采购价刷新对照](./采购订单下游采购价刷新-测试对照说明.md) §二～§五。

额外：刷新单价后到货通知 **品牌、型号、预计数量不变**（只改单价与金额）。有已完结下游时须确认；参数关闭则拦住。

**足额 / 超额（关联回归，强制）：** 刷新不提交核销。刷新后用新待匹配 / 新待付去进项匹配或付款核销：**足额成功**；略超**拒绝**。公式见单价对照 §四。

## 七、分面互不污染

| 操作 | 不得发生 |
|------|----------|
| 刷新状态 | 到货 `Cost` / `Brand` / `Pn` / `ExpectQty` 被改写 |
| 刷新品牌 | 采购价、数量、型号被改写；库存明细编号被改写 |
| 刷新物料型号 | 品牌、采购价、数量被改写；库存明细编号被改写 |
| 刷新数量 | 入库/库存/出库实绩数量、品牌、单价被改写 |
| 刷新单价 | 品牌、型号、到货分批数量被改写 |
| 刷新供应商 | 采购价、品牌、数量被改写 |

## 九、已完结预检与确认

页面：采购订单详情；参数页见 [采购参数 · 分面刷新](./采购参数-刷新供应商-测试对照说明.md)。

**本功能不适用：足额成功 / 超额拒绝的核销提交**（本门控不改金额流水）。刷新单价之后的核销边界仍见 §六。

| 步骤 | 操作 | 预期 |
|------|------|------|
| 1 | 无已完结下游，刷新型号 | 预检 `hasCompleted=false`；确认后 `confirmCompleted` 可为 false；快照按分面覆盖 |
| 2 | 有库存明细；参数型号允许 | 警告列出「库存明细…」；取消不刷新；确定后 `confirmCompleted=true` 且覆盖 |
| 3 | 有库存明细；参数型号不允许 | 提示无法刷新已完结节点；不发 refresh（或 refresh 400）；库存不变 |
| 4 | 刷新状态，即使行已完结 | **不**走已完结门控；只重算状态 |
| 5 | 直接调 refresh 且 `confirmCompleted=false`（有已完结、参数开） | 后端拒绝「须确认后再刷新」 |
| 6 | 编辑页换供应商保存（参数开、有已完结） | 仍可保存同步（不套详情确认标志）；确认框应能看到已完结清单 |

## 十、回归 / 交叉

| 项 | 预期 |
|----|------|
| 兼容路径 `POST …/refresh-item-extends` | 仍只做刷新单价 |
| Debug「刷新采购订单状态」 | 只重算状态，不覆盖全库采购价 |
| 保存采购明细（改价/改品牌后保存，不点刷新） | 仍按 Default Recalculate 对齐到货单价与品牌（业务事件）；**库存分堆键不随保存改写**，须点「刷新物料型号 / 刷新品牌」 |
| 底部入库页签已过账采购入库 | 刷新状态后入库进度正确（见 [采购订单主状态 §4.2](../../System/采购订单主状态.md)） |
