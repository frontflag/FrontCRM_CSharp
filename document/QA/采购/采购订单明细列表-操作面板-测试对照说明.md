# 采购订单明细列表 — 右侧操作面板 — 测试对照说明

> **页面 / 路由：** 采购管理 → 采购订单明细 `/purchase-order-items`；采购订单详情 `/purchase-orders/:id`（同一操作面板）  
> **设计文档：** [采购订单明细列表-操作面板-设计与实现](../../System/采购订单明细列表-操作面板-设计与实现.md)  
> **门控规范（权威）：** [销售操作面板 §2.4](../../System/销售订单明细列表-操作面板-设计与实现.md)  
> **布局规范（权威）：** [销售操作面板 §2.5](../../System/销售订单明细列表-操作面板-设计与实现.md)；完成态生成单号见 [操作规范 §7.6](../../PRD/规范/UI规范/扩展窗口页签-操作规范.md) 与销售 §2.5.5  
> **权限 / DDL：** 无新权限码、无新迁移。申请付款按钮：`finance-payment.write` 或 `purchase-order.write`。须部署含列表字段 `orderStatus` / `financePaymentStatus` 的 API 版本。

交互门控与销售订单明细列表相同（A～F）。列表与详情共用 `PurchaseOrderItemOpsPanel`。

## 一、入口与权限

| 步骤 | 预期 |
|------|------|
| 有 `purchase-order.read` 进入明细列表 | 右栏页签 **操作 + 流程 + 帮助**；首次进入默认 **操作**（本页上次页签可记忆；收起再展开仍默认操作，见工作台规范） |
| 无采购订单读权限 | 不能进入本页 |
| 有读、无 `finance-payment.write` 且无 `purchase-order.write` | 可看操作面板；申请付款按钮**不显示**；申请付款卡片提示「当前账号没有申请付款权限。」及对应下一步 |
| 有申请付款权限 | 未完成请款时显示「申请付款」按钮（可点或灰显视本行原因） |
| 脱敏账号（采购敏感掩码） | 「操作」页签下单击仍加载面板；供应商名 / 金额为 `—` |

## 二、页签与门控（§4.4）

| 步骤 | 预期 |
|------|------|
| **A** 收起右栏后单击行 | 不展开、不请求 `detail-tab-aggregates` |
| **B** 展开 →「帮助」→ 单击行 | 高亮；不切页签；无聚合请求 |
| **D** 再点「操作」 | 加载该行操作面板（到货通知 / 申请付款等卡片） |
| **C** 已在「操作」下单击另一行 | 立即请求并刷新面板 |
| **E** 操作页签下已选行 → 收起 → 再展开 | 默认切回 **操作**；store 仍有行则沿用/加载面板 |
| **F** 查询刷新列表 | 面板清空，需重新选行 |
| 双击行 | 进入采购订单详情 |

详情页：单击明细行打开底部概况面板；**不**强制切右侧「操作」页签；加载完成后可将该行同步到同一操作面板。

左栏快捷检索与主列表筛选叠加规则仍见采购订单明细列表其它对照说明；打开操作面板须先满足本节 **C** 或 **D**。

## 三、申请付款禁用提示（本行直接原因）

有申请付款权限、卡片未进入「已完成」时：按钮灰显，摘要与「下一步」**只写当前一条原因**，**不得**出现「可能已有在途请款」或「当前不满足申请付款条件（可能…）」类兜底。原因互斥，按下表顺序只命中第一条。

| # | 准备数据 / 步骤 | 预期摘要 | 预期下一步 |
|---|----------------|----------|------------|
| 1 | 无申请付款权限的账号打开已确认、可申请仍有余额的行 | 当前账号没有申请付款权限。 | 下一步：请联系管理员开通申请付款权限。 |
| 2 | 有权限；明细或主单状态为取消 / 审核失败 | 本明细（或主单）已取消/审核失败，不能申请付款。 | 下一步：已取消或审核失败的明细不能请款。 |
| 3 | 有权限；主单与明细均未到「已确认」（如待确认） | 当前明细尚未供应商确认，暂不可申请付款。 | 下一步：等待采购主单/明细达到「已确认」及之后状态再申请付款。 |
| 4 | 有权限；行已确认；可申请金额 **> 0**；财务付款状态为 **全部付款**；聚合已返回且有**未删除**付款单 | 本明细财务付款状态已是全部付款，不能再申请。展示 **付款单号**（可点进详情）。 | 下一步：点击上方付款单号打开付款单核对。付款记录请用付款单号查询，不要把采购订单号填进付款单号。 |
| 4b | 财务状态仍为全部付款，但关联付款单已软删除（示例 `PO001ZC-1` / `PAY0022N`） | **不展示**付款单号、不标「已删除」、无「关联付款单已删除」提示；已申请/可申请与待请款一致；**申请付款按钮可点** | 付款记录填「付款单号」`PAY0022N` 应能查到，状态旁「已删除」（操作面板不展示该历史） |
| 4c | 财务状态为全部付款，聚合无任何付款单（含已删） | 不因财务状态灰按钮（可再请款）；无付款单号 | — |
| 5 | 有权限；已确认；财务未全部付款；可申请金额 = 0 且已申请 **未** 达到「已完成」展示条件时 | 本明细请款金额已满，无可申请余量。 | 下一步：请款申请已全部完成，无需再申请付款。 |
| 6 | 有权限；已确认；财务未全部付款；可申请 > 0 | 无禁用提示；按钮可点，打开请款弹窗 | — |

**已完成：** 可申请金额 ≤ 0 **且** 已申请金额 ≥ 明细总额时，卡片标题显示绿色「已完成」，**隐藏**按钮、禁用提示与进度条；指标与「付款单号」之间有浅色横线；列出未删除未取消的 **付款单号**（常规字重，可点进付款单详情）。脱敏账号只显示单号文本、不可点。

**请款口径（与概况付款列勿混）：**

```text
明细总额 = lineTotal（缺省 qty × cost）
已申请 = paymentRequestedAmount（扩展表请款累计）
可申请 = max(0, 明细总额 − 已申请)
```

概况矩阵付款列是已付 / 待付，不作为本卡片禁用原因。

**在途请款：** 未取消、未审核失败的付款单会占用已申请金额，**不是**本按钮的独立阻断条件。有在途请款且可申请仍 > 0 时，只要其它门槛满足，按钮应可点（分批请款）。

列表行 JSON 应含 `orderStatus`、`financePaymentStatus`（Network 可核对）。详情页右侧面板走 `poDetailLineToListShape`，同样应带上财务付款状态。

## 四、到货通知抽查

| 步骤 | 预期 |
|------|------|
| 未确认 | 灰按钮；「当前明细尚未供应商确认，暂不可通知到货。」及对应下一步 |
| 可通知数量 = 0 且已通知 ≥ 订单量 | 「已完成」，无按钮、无进度条；指标下「到货通知单号」列出关联通知（可点进到货通知列表）；单号不加粗 |
| 已确认且可通知 > 0，且已有到货通知 | 按钮可点；已有单号仍可展示并可跳转 |
| 已确认且可通知 > 0，尚无到货通知 | 按钮可点，打开到货通知弹窗；不出现空的「到货通知单号：」 |
| 脱敏 | 单号为纯文本，不可点 |

## 五、金额展示（只读，非核销提交）

| 步骤 | 预期 |
|------|------|
| 有金额权限 | 已申请 / 可申请两行：金额 + 币别；币别颜色与列表金额列一致 |
| 无金额权限 | 后端金额为 0；脱敏为 `—` |
| 请款已满但已付为 0 | 已申请显示请款累计，不得误显示已申请 0 却提示已满（设计 §8.1） |

## 六、回归 / 交叉

| 步骤 | 预期 |
|------|------|
| 从销售订单明细切到本页（或反向） | 对方 store 已清空，仅显示对应面板 |
| 窄右栏 | 无横向滚动 |
| 通知到货 / 申请付款弹窗提交后 | 列表刷新；打开中的操作面板同步 |
| 列表操作列「申请付款」 | 仍仅在 `canApplyPayment` 为真时显示入口；右侧面板在不可申请时用灰按钮 + 直接原因 |
| 付款记录筛「付款单号」填采购订单号（如 `PO001ZC`） | 无数据属预期；应填付款单号 |
| 付款记录筛「付款单号」填已删除单号 `PAY0022N` | 出现该行，状态旁「已删除」；不填单号的默认列表不出现该行 |

## 七、本功能不适用

- **本功能不适用：工作台 / 桌面左栏队列（总纲 §4.3）。** 非审批/报价/核销桌面。
- **本功能不适用：金额提交 / 核销 / 匹配的足额成功与超额拒绝（总纲 §4.5）。** 本面板不提交核销或匹配金额；请款弹窗内金额边界见财务请款相关对照说明。本节只验收只读金额展示与禁用提示文案。
- **本功能不适用：数据分析看板公式。** 看板口径见采购订单明细看板帮助 / IMP。
- **本功能不适用：多租户皮肤 / 打印（总纲 §4.6）。** 本面板无打印、无租户报表皮肤。
- **本功能不适用：页签模式筛选下拉隐藏的专项回归。** 主列表看板/列表切换见对应列表对照；本面板仅要求查询刷新后清空选中（第二节 F）。
