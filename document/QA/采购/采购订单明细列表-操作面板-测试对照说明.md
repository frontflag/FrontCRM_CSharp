> **页面 / 路由：** 采购管理 → 采购订单明细 `/purchase-order-items`；采购订单详情 `/purchase-orders/:id`（同一操作面板）

> **布局规范（权威）：** [销售操作面板 §2.5](../../System/销售订单明细列表-操作面板-设计与实现.md)；完成态生成单号见 [操作规范 §7.6](../../PRD/规范/UI规范/扩展窗口页签-操作规范.md) 与销售 §2.5.5

## 一、入口与权限

| 步骤 | 预期 |
|------|------|
| 有 `purchase-order.read` 进入明细列表 | 右栏页签 **操作 + 流程 + 帮助**；首次进入默认 **操作**（本页上次页签可记忆；收起再展开仍默认操作，见工作台规范） |
| 无采购订单读权限 | 不能进入本页 |
| 有读、无 `finance-payment.write` 且无 `purchase-order.write`（且非系统管理员 / 非 `SYS_ADMIN` 角色） | 可看操作面板；申请付款按钮**不显示**；申请付款卡片提示「当前账号没有申请付款权限。」及对应下一步 |
| 系统管理员（`isSysAdmin` 或角色 `SYS_ADMIN`） | 申请付款不因权限灰掉（仍受已确认 / 可申请余量等业务门槛约束） |
| 有申请付款权限 | 未完成请款时显示「申请付款」按钮（可点或灰显视本行原因） |
| 脱敏账号（采购敏感掩码） | 「操作」页签下单击仍加载面板；供应商名 / 金额为 `—` |

## 二、页签与门控（§4.4）

| 步骤 | 预期 |
|------|------|
| **A** 收起右栏后单击行 | 不展开、不请求 `detail-tab-aggregates` |
| **B** 展开 →「帮助」→ 单击行 | 高亮；不切页签；无聚合请求 |
| **D** 再点「操作」 | 加载该行操作面板；**最上方**为「采购订单」卡片，其下为订单明细 / 申请付款 / 到货通知 |
| **C** 已在「操作」下单击另一行 | 立即请求并刷新面板 |
| **E** 操作页签下已选行 → 收起 → 再展开 | 默认切回 **操作**；store 仍有行则沿用/加载面板 |
| **F** 查询刷新列表 | 面板清空，需重新选行 |
| 双击行 | 进入采购订单详情 |

详情页：单击明细行打开底部概况面板；**不**强制切右侧「操作」页签；加载完成后可将该行同步到同一操作面板。

左栏快捷检索与主列表筛选叠加规则仍见采购订单明细列表其它对照说明；打开操作面板须先满足本节 **C** 或 **D**。

## 二点一、采购订单卡片

| 步骤 | 预期 |
|------|------|
| 选中已确认行 | 操作页签**最上方**卡片标题为「采购订单」；状态只显示「已确认」，**无**「（等待供应商确认）」 |
| 选中审核通过行 | 状态为「审核通过，」后接斜体浅灰「（等待供应商确认）」；括号提示不是主单状态本身 |
| 选中待确认行 | 状态为「待确认，」后接同样斜体浅灰提示 |
| 选中进行中 / 采购完成 | 只显示主单状态文案，无括号提示 |
| 采购订单编号与状态 | **同一行**，各占行宽 **50%**；编号与订单明细里 PN 同为常规 13px，**不是**明细编号那种橙色大字；编号**无下划线**（含悬停） |
| 状态 | 采购**主单**状态（与列表采购订单状态一致），不是行上部分付款等标签。括号提示规则见上表审核通过 / 待确认 / 已确认三行 |
| 供应商 | 该卡片**最下一行**（整行）**加粗**；中英名称合并显示；英文空则只显示中文；脱敏为 `—`。**订单明细卡片不再展示供应商** |
| 点击编号 | 进入该采购订单详情（无单号或无 id 时为纯文本「—」） |

## 三、申请付款禁用提示（本行直接原因）

有申请付款权限、卡片未进入「已完成」时：按钮灰显，摘要与「下一步」**只写当前一条原因**，**不得**出现「可能已有在途请款」或「当前不满足申请付款条件（可能…）」类兜底。原因互斥，按下表顺序只命中第一条。

| # | 准备数据 / 步骤 | 预期摘要 | 预期下一步 |
|---|----------------|----------|------------|
| 1 | 无申请付款权限的账号打开已确认、可申请仍有余额的行 | 当前账号没有申请付款权限。 | 下一步：请联系管理员开通申请付款权限。 |
| 2 | 有权限；明细或主单状态为取消 / 审核失败 | 本明细（或主单）已取消/审核失败，不能申请付款。 | 下一步：已取消或审核失败的明细不能请款。 |
| 3 | 有权限；主单与明细均未到「已确认」（如待确认） | 当前明细尚未供应商确认，暂不可申请付款。 | 下一步：等待采购主单/明细达到「已确认」及之后状态再申请付款。 |
| 4 | 有权限；行已确认；可申请金额 **> 0**；已付款合计 **<** 采购总额（财务状态为 **部分付款** 或未付款）；已有未删除付款单（例如第一笔已付清） | 无禁用提示；按钮可点，打开请款弹窗 | — |
| 4b | 关联付款单已软删除并已重算（示例 `PO001ZC-1` / `PAY0022N`） | **不展示**付款单号；已申请/可申请与待请款一致；**申请付款按钮可点** | 付款记录填「付款单号」`PAY0022N` 应能查到，状态旁「已删除」（操作面板不展示该历史） |
| 4c | 聚合无任何付款单（含已删） | 不因财务状态灰按钮（可再请款）；无付款单号 | — |
| 4d | 有权限；已确认；已付款合计 **≥** 采购总额（**付款完成**）；聚合已返回且有**未删除**付款单 | 本明细货款已付清（付款完成），不能再申请。展示 **付款单号**（可点进详情）。 | 下一步：点击上方付款单号打开付款单核对。付款记录请用付款单号查询，不要把采购订单号填进付款单号。 |
| 5 | 有权限；已确认；财务未付款完成；可申请金额 = 0 且已申请 **未** 达到「已完成」展示条件时（例如全额在途请款、已付仍为 0） | 本明细请款金额已满，无可申请余量。 | 下一步：请款申请已全部完成，无需再申请付款。 |
| 6 | 有权限；已确认；财务未付款完成；可申请 > 0 | 无禁用提示；按钮可点，打开请款弹窗（与 4 同类，可用任意部分付款样例） | — |

**已完成：** 可申请金额 ≤ 0 **且** 已申请金额 ≥ 明细总额时，卡片标题显示绿色「已完成」，**隐藏**按钮、禁用提示与进度条；指标与「付款单号」之间有浅色横线；列出未删除未取消的 **付款单号**（常规字重，可点进付款单详情）。脱敏账号只显示单号文本、不可点。

**请款口径（与概况付款列勿混）：**

```text
明细总额 = lineTotal（缺省 qty × cost）
已申请 = paymentRequestedAmount（扩展表请款累计，含在途未付）
可申请 = max(0, 明细总额 − 已申请)
```

**付款状态口径（与请款口径分开）：**

```text
已付款合计 = 有效付款单已核销之和（PaymentAmountFinish / VerificationDone）
             排除取消、审核失败、已删除；不含在途未付的请款

已付款合计 == 0                         → 未付款
0 < 已付款合计 < 采购总额               → 部分付款
已付款合计 >= 采购总额                 → 付款完成

申请付款：已付款合计 < 采购总额 且 可申请 > 0（另需权限、已确认）
```

概况矩阵付款列是已付 / 待付，不作为本卡片禁用原因。

**在途请款：** 未取消、未审核失败的付款单会占用已申请金额，**不是**本按钮的独立阻断条件。有在途请款且可申请仍 > 0 时，只要其它门槛满足，按钮应可点（分批请款）。全额已申请、尚未核销时走用例 5（请款已满），状态仍可能是未付款。

**已知口径差异：** EBS 按已付 vs 请款金额标「付款完成」；FrontCRM 按已付 vs **行采购总额**。第一笔请款付清、行上仍有未请余额时，FrontCRM 为部分付款且允许再请。

列表行 JSON 应含 `orderStatus`、`financePaymentStatus`（Network 可核对）。详情页右侧面板走 `poDetailLineToListShape`，同样应带上财务付款状态。

## 四、到货通知抽查

| 步骤 | 预期 |
|------|------|
| 未确认 | 灰按钮；「当前明细尚未供应商确认，暂不可通知到货。」及对应下一步 |
| 可通知数量 = 0 且已通知 ≥ 订单量 | 「已完成」，无按钮、无进度条；指标下「到货通知单号」列出关联通知（可点进到货通知列表）；单号不加粗 |
| 已确认且可通知 > 0，且已有到货通知 | 按钮可点；已有单号仍可展示并可跳转 |
| 已确认且可通知 > 0，尚无到货通知 | 按钮可点，打开到货通知弹窗；不出现空的「到货通知单号：」 |
| 脱敏 | 单号为纯文本，不可点 |

## 五、金额展示（只读，非核销提交）

| 步骤 | 预期 |
|------|------|
| 有金额权限 | 已申请 / 可申请两行：金额 + 币别；币别颜色与列表金额列一致 |
| 无金额权限 | 后端金额为 0；脱敏为 `—` |
| 请款已满但已付为 0 | 已申请显示请款累计，不得误显示已申请 0 却提示已满（设计 §8.1） |

| 步骤 | 预期 |
|------|------|
| 从销售订单明细切到本页（或反向） | 对方 store 已清空，仅显示对应面板 |

## 七、本功能不适用

- **本功能不适用：工作台 / 桌面左栏队列（总纲 §4.3）。** 非审批/报价/核销桌面。
- **本功能不适用：金额提交 / 核销 / 匹配的足额成功与超额拒绝（总纲 §4.5）。** 本面板不提交核销或匹配金额；请款弹窗内金额边界见财务请款相关对照说明。本节只验收只读金额展示与禁用提示文案。
- **本功能不适用：数据分析看板公式。** 看板口径见采购订单明细看板帮助 / IMP。
- **本功能不适用：多租户皮肤 / 打印（总纲 §4.6）。** 本面板无打印、无租户报表皮肤。
- **本功能不适用：页签模式筛选下拉隐藏的专项回归。** 主列表看板/列表切换见对应列表对照；本面板仅要求查询刷新后清空选中（第二节 F）。

## 八、上线前

1. 部署含 `PurchaseLineFinancePaymentStatus`（已核销 vs 行总额）的 API。  
2. 重启 API。  
3. 历史采购明细的 `FinancePaymentStatus` 仍可能是旧口径（已付 vs 已请款）。对受影响订单在采购订单详情点 **刷新扩展**（或发生付款/反核销）后按新公式回写。  
4. 无需新权限脚本、无需重新登录（已有申请付款权限即可）。
