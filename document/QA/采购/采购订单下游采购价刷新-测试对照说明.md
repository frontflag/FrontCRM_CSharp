## 一、入口与权限

| 步骤 | 预期 |
|------|------|
| 1 | 打开采购订单详情 | 页头主按钮为「刷新状态」；本对照测下拉 **「刷新单价」**（「刷新供应商」是另一能力） |
| 2 | 无采购订单写权限 | 「刷新单价」不可提交（按钮禁用或 403） |
| 3 | 有写权限、无本单数据范围 | 403，下游单价不变 |
| 4 | 点「刷新单价」 | 确认框说明：按当前采购单价覆盖到货通知 / 入库 / 库存 / 出库快照（含已入库、已请款、已核销、已进项匹配）；请款与付款流水、进项发票票面不改 |
| 5 | 取消确认 | 不请求 `POST /api/v1/purchase-orders/{id}/refresh`（`facet=price`）；兼容旧路径 `refresh-item-extends` 仍等价于刷新单价 |

**本功能不适用：** 工作台/桌面左栏队列（§4.3）、列表页签模式 / 左栏检索 / 操作面板门控（§4.4）、多租户皮肤 / 打印（§4.6）。无需新 SQL / 迁移 / 重新登录（§4.7）。

## 二、黄金路径（改价后刷新）

前置：客单采购已分批到货并入库，库存层、出库明细均已按**旧采购价**落快照。编辑采购订单把该行单价改为新值并保存（折算美金随保存重算）。

| 步骤 | 操作 | 预期 |
|------|------|------|
| 1 | 详情点「刷新单价」并确认 | 先 `POST …/refresh/preview`；无已完结或确认后 `POST …/refresh` `facet=price`（或兼容 `refresh-item-extends`）成功 |
| 2 | 结果弹窗 | 列出该行旧单价 → 新单价；到货通知 / 入库明细 / 入库单头 / 库存 / 出库明细计数 ≥ 1 |
| 3 | 到货通知（含多批次） | **每一条**通知的采购单价 = 采购行当前值；预计/实收数量**不变**；金额按数量 × 新单价重算 |
| 4 | 入库明细 | 单价 / 币别 / 金额 = 入库数量 × 采购行当前单价 |
| 5 | 入库单头金额 | `Σ(该入库单各行金额)`；一单多采购行时，其它行仍用各自入库价 |
| 6 | 库存明细 | 采购价快照与入库毛利快照按新折算美金 × 入库数量重算 |
| 7 | 出库列表 / 出库明细 | 采购单价读扩展快照，为新单价（不从旧库存层抄回）；销售价与原始采购价 P0 **不变**；出库利润按（销售折算美金 − 新采购折算美金）× 本行出库数量 |
| 8 | 采购明细扩展 | 应付/待付、进项待匹配、利润等随 Recalculate 更新 |
| 9 | 操作日志 | 本单有「刷新采购价」，含操作人、行号、旧→新、条数 |

## 三、无「单据状态」门控（仍走已完结参数）

不因行已入库/已请款就拒绝本分面。采购参数「分面刷新 → 刷新单价」默认允许：关则整面拦住；开则详情须先列出已完结单据并确认（见 [分面刷新对照](./采购订单分面刷新-测试对照说明.md) §九）。

| 步骤 | 预期 |
|------|------|
| 下游已入库完成（参数允许、已确认） | **仍覆盖**采购价，不因「已入库」单独阻断 |
| 已请款 / 已付款核销 | **仍改**扩展上应付/待付；请款与付款流水金额不变 |
| 入库行已进项匹配完成 | **仍改**入库总额与待匹配；进项发票票面不变 |
| 已出库完成 | **仍改**出库扩展采购价与出库利润 |
| 报关已申报 | 申报单价**不变** |
| 销售价 / 原始采购价 P0 | **不变** |

## 四、金额与核销 / 匹配口径

**本功能不适用：足额成功 / 超额拒绝的核销或发票匹配提交。** 刷新不发起请款、不发起付款核销、不发起进项匹配，也不改已有流水。

刷新后入库进项公式（须手工核对）：

```text
Amount = 入库数量 × 采购行当前单价（四舍五入到 2 位）
InvoiceMatchDone 保持原值
InvoiceMatchToBe = Amount − InvoiceMatchDone   （可为负，不拦截）
进项匹配状态按新总额与已完成额重标
```

刷新后已付对照（不改流水）：

```text
行总额 = 采购行数量 × 当前单价
已付 = Σ 有效付款单明细 VerificationDone（排除取消 / 审核失败）
已付 > 行总额：不拒绝，结果弹窗警告
```

| 用例 | 操作 | 预期 |
|------|------|------|
| 未匹配改价 | 入库数量 2、旧单价 10→20 后刷新 | 入库金额 40，待匹配 40，状态未匹配 |
| 已进项匹配超额（降价） | 已匹配 20，新总额 16 后刷新 | **不拒绝**；总额 16，已匹配仍 20，待匹配 -4；结果弹窗警告入库编号、已匹配、新总额 |
| 已付超额（降价） | 行数量 2、已付核销 20，新单价 8 后刷新 | **不拒绝**；请款/付款流水金额不变；结果弹窗警告明细编号、已付、新行总额 16 |
| 升价后待匹配变大 | 已匹配 10，新总额 40 | 待匹配 30，状态部分匹配；**无**超额警告 |
| 取消/审核失败的付款 | 仅这些单上有超额已付 | **不**计入已付、**不**警告 |
| 刷新后足额进项匹配（关联回归） | 用新待匹配金额去进项匹配桌面提交 | 按匹配功能原规则：**足额成功**；略超新待匹配则**拒绝**（验收见进项发票对照，本页只确认余额已是新值） |
| 刷新后足额付款核销（关联回归） | 用新待付金额去付款核销提交 | 按核销功能原规则：**足额成功**；略超则**拒绝**（验收见付款核销对照） |

## 五、结果提示与幂等

| 步骤 | 预期 |
|------|------|
| 单价与下游已一致 | 「无更新数据」（扩展进度也无变更时） |
| 扩展进度无变更，但下游单价有覆盖 | **不**显示「无更新数据」，展示下游计数 |
| 连续点两次刷新 | 第二次下游计数为 0（或无单价变化行） |
| 采购金额脱敏 | 面板仍能刷新；金额列可为「—」，结果弹窗仍可出现计数/警告 |

## 六、回归 / 交叉

| 项 | 预期 |
|----|------|
| 「刷新 ▾ → 刷新供应商」 | 仍只同步供应商，不改采购价 |
| 「刷新状态」 | 不改采购价、品牌、到货计划量 |
| 多批次到货 | 刷新单价后各通知数量保持原分批；仅单价与金额变 |
| 采购明细改品牌后点「刷新单价」 | 到货通知品牌**保持原快照**（改品牌须用「刷新品牌」）；质检列表品牌以到货快照为准 |
| 采购明细改品牌后点「刷新品牌」 | 到货通知品牌 = 采购行当前品牌；质检列表只显示新品牌；库存明细品牌与分堆一并更新（见 [分面刷新对照](./采购订单分面刷新-测试对照说明.md) §四） |
| 出库列表导出采购价 | 优先扩展快照，刷新单价后导出为新单价 |
| 销售明细绩效出库利润 | 展开绩效后与出库扩展 `ProfitOutBizUsd` 合计一致 |
| 底部「入库」页签已有 **已入库** 的 **采购入库**（类型 `10`）、数量覆盖本行 | 点「刷新状态」或「刷新单价」后明细 **入库状态** 为「入库完成」（或数量不足时为「部分入库」），**不得**仍为「待入库」。关联口径见 [采购订单主状态 §4.2](../../System/采购订单主状态.md) |
| 底部「入库」页签仅有已过账 **报关入库**（类型 20），无采购入库 `10` | 点「刷新状态」后入库数量仍为 0、入库状态为 **待入库**；页签仍可看到该报关入库单 |
