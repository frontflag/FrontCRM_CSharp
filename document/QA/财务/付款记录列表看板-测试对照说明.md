## 一、入口与权限

| 步骤 | 预期 |
|------|------|
| 有付款记录列表权限 | 可进入 `/finance/payments`；搜索栏「查询」后、「设置」齿轮前有 **看板** 按钮 |
| 无对应菜单权限 | 不可进入，与现网一致 |
| 默认 | 列表；顶部四张当前页统计卡可见 |
| 点「看板」 | 按钮文案变为「列表」；顶部统计卡、表格、分页隐藏；出现看板（Tag「筛选」+ KPI + 趋势 + 饼图 + Top10） |
| 再点「列表」 | 回到表格与当前页统计卡 |
| 看板态右侧帮助 | 为付款记录看板说明（非付款记录列表帮助） |
| 列表态右侧帮助 | 恢复付款记录列表帮助 |
| 无 write | 仍可看列表与看板；付款执行等写入按钮按现网禁用 |

**本功能不适用：** 工作台左栏队列（总纲 §4.3）、多租户打印皮肤（§4.6）、看板写入/提交。

## 二、筛选联动与页签

| 步骤 | 预期 |
|------|------|
| 列表筛状态=付款完成，再切看板 | 看板只统计付款完成；Network `finance/payments/analytics/*` 带 `status=100` |
| 状态不限（全部） | 看板含新建、待审、已付、取消等当前能列出的单（**不**强制只统计已付） |
| 看板下改付款日期后点查询 | 看板自动刷新；四个 analytics 请求带同一 `startDate/endDate`（筛的是付款日期） |
| 开启页签模式（状态 / 付款方式） | 对应下拉隐藏；点页签即查；F5 后页签模式保持；看板跟当前页签 |
| 511 用户 | 供应商名与金额为「—」；看板仍能加载 |

列表与看板必须共用同一 WHERE（含数据权限）。抽 1 个筛选组合：列表总条数 = dashboard `headerCount`。

页签模式持久化与现网付款列表一致（总纲 §4.4）。

## 三、口径 / 公式核对

计数：付款**单头**数（不是明细行数）。  
金额：**明细已付货款**合计，按单头付款币别分档。  
**不要**用单头「付款金额」列（完成态可能已含费用）当看板主数字。  
**不要**把人民币与美元原币相加。

```text
某币别付款金额 = Σ 该币别付款单下各明细 PaymentAmount（已付货款，不含费用）
付款供应商数 = 头表 VendorId 非空去重
付款单数 = 筛选结果头表条数
趋势日期 = PaymentDate（空则不进趋势，仍进 KPI / 饼图 / 排名）
核销状态 = 无明细或全部 0 → 未核销；全部 2 → 核销完成；否则部分核销
采购员 = 明细所属采购订单采购员；空 → 未分配采购员；一张单可拆到多名
```

| 核对 | 预期 |
|------|------|
| **足额（筛选结果逐单加总 = 看板）** | 抽当前筛选（建议含付款完成 + 有付款日 + 至少两种币别）：列表总条数 = 筛选全量头表数；有金额权限时，各原币 KPI = 该币别**明细已付货款**之和（允许四舍五入到分的尾差）。有费用的单：看板金额 **≤** 列表「付款金额」列之和 |
| 原币分档 | 禁止把不同原币直接相加当主数字；人民币 / 美元混存时 KPI 至少两行 |
| 付款供应商数 | = 列表结果里头表有供应商 ID 的去重数 |
| 趋势（按月） | 只含有付款日的单；无付款日单进 KPI 但不进趋势桶；金额趋势每种原币一张图 |
| 核销状态饼 | 扇区为**单数** + 百分比（总要求 §3.7） |
| 采购员饼 | 按原币分面；面内为该币已付货款（或脱敏下单数）+ 百分比；一张多采购员的单金额拆开 |
| Top10 供应商 / 采购员 | 每个原币各自独立排序 |
| **超额拒绝** | **本功能不适用：** 看板只读，无核销/匹配/金额提交 |

本功能不适用折算美金主口径（总纲 §3.2 看板美金项）：产品已锁定不折美金。

## 四、数据范围与脱敏

| 步骤 | 预期 |
|------|------|
| 数据权限收窄用户 | 看板可见集合 ≤ 该用户列表可见全量，不得大于 |
| 511 采购敏感掩码 | 付款金额显示「—」；供应商名不展示；饼图/排行按单数；看板仍能加载 |
| 非 511 | 各原币金额与供应商名可见 |

## 六、回归 / 已知差异

| 项 | 说明 |
| --- | --- |
| 列表「付款金额」列 | 付款完成后单头金额可含费用；看板只用明细货款，有费用时看板更小 |
| 列表顶部四张统计卡 | 仅当前页、且「本月付款总额」可能把不同币别加在「¥」下；看板按全量筛选、分币别，不要用顶卡对数 |
| 未付款单 | 已付货款为 0，仍计入供应商数与核销饼；金额柱几乎只有付款完成才有数 |
| 采购员 | 列表列是多 PO 名称拼接；看板按明细拆到各采购员，不要用列表拼接名直接对数 |
| 财务分析 | 若日后有「已付款」透镜，口径可能只含已付并折美金；本页跟筛选、原币分开 |

**上线前：** 部署含本看板的版本后 **重启 CRM.API**；已登录用户刷新前端即可。无需新权限脚本、无 DDL。
