# 客户对账单 — 测试对照说明

> **页面 / 路由：** 收款管理 → 客户对账单 → `/finance/receivable-statements`；亦可从应收款右上角进入；详情 `/finance/receivable-statements/:customerId/:currency`  
> **设计文档：** [客户对账单-设计与实现](../../System/财务/客户对账单-设计与实现.md)  
> **总纲：** [测试规范总纲](../测试规范总纲.md)  
> **用户帮助：** [客户对账单](../../../help/pages/客户对账单_MENU_FINANCE_RECEIVABLE_STATEMENT.md)

一期只读、不落库、不编号。余额看出现金出库应收与收款核销，不对发票、未核销来款。

---

## 一、入口与权限

| 步骤 | 预期 |
|------|------|
| 无收款读权限 | 进不了应收款，也就没有对账单入口 |
| 有收款读权限，侧栏「收款管理」 | 组内最后一项为「客户对账单」 |
| 点侧栏「客户对账单」 | 进入聚合列表 `/finance/receivable-statements` |
| 有收款读权限，应收列表（列表或看板）右上角 | 有「客户对账单」，与「导出」并列 |
| 点应收列表「客户对账单」 | 进入同一聚合列表，不弹条件窗 |
| 无客户查看权仍有应收范围 | 能进列表/详情；详情上部联系人/账期/额度可为 —，名称可用应收快照 |
| 详情改期间、点「预览报表」、预览页打印/导出 PDF | 不要求写权限 |

Network：`GET /api/v1/finance/receivable-statements`；详情 `GET /api/v1/finance/receivable-statements/{customerId}/{currency}?from=&to=&aging=`。

---

## 二、数据范围与脱敏

| 步骤 | 预期 |
|------|------|
| 应收列表看不到的客户+币 | 聚合列表也不出现 |
| 猜别人的 customerId 打开详情 | 404「不存在或无权查看」 |
| 客户存在、本币从无应收、但该客户其它币有可见应收 | 200，流水仅期初行，四个数为 0 |
| 521 / 销售敏感掩码 | 列表金额为 —；页面仍能打开 |

---

## 三、聚合列表

| 步骤 | 预期 |
|------|------|
| 历史上有过应收、现已全部核销的客户+币 | 仍有一行，待核销 0 |
| 勾选「仅待核销」 | 上述行消失 |
| 同一客户 RMB 与 USD | 两行，点开各只含本币 |
| 关键词 | 匹配编号 / 中文名 / 英文名 / 业务员 |
| 单击或双击一行 | 进详情；期间默认 **上一个自然月**（如今天 9/7 → 8/1–8/31） |
| 操作列「详情」 | 与单击进详情同一页；列头 `<`/`>` 可展开/收起；默认收起为 `...` |
| 刷新列表 | 不按期间过滤（与详情期间无关） |

列：客户编号、中文名、英文名、币别、应收笔数、总额、已核销、待核销、最近出库日、业务员。待核销 = 该组 Σ 应收 `verified_to_be`，可与应收列表按客户+币合计核对。

---

## 四、详情工作页与流水

页面套用业务列表规范：页眉（返回 / 标题 / 预览报表）、客户资料面板、四个 KPI、搜索栏（期间起、至、期间止、账龄截止、查询、重置，位于 KPI 与流水表之间）、`CrmDataTable` 流水、底栏齿轮列设置与行高密度。无分页。

| 步骤 | 预期 |
|------|------|
| 客户资料面板 | 名称、联系人、业务员、电话（有客户权时）、账期 N 天、信用额度（标明来自客户档案）；无客户编号；标题栏有生成日期与币别 |
| 搜索栏改期间后点「查询」（起 ≤ 止） | 四个数与下部一起变；URL 带 `from`/`to` |
| 起 > 止 或清空后点查询 | 提示拒绝，不改数 |
| 「重置」 | 期间回到上一个自然月，账龄截止为今天，并重算 |
| 账龄截止 | 可改，点查询后只展示，不改金额 |
| 列设置 / 行高 | 齿轮在表体下方底栏左侧；设置本机记住；紧密/适中可切 |
| 下部 | 必有期初行（即使期初 0）；然后本期出库应收、本期核销；一条应收一行 |
| 单据号 | 增加=应收单号（可进应收详情）；已收=收款单号或「预收」 |
| 双击增加/已收行 | 分别进应收详情 / 收款详情；期初行不跳 |
| 未核销来款 / 预收池余额 | **不上单** |
| 销项发票 | **不上增加行** |
| 已反核销（软删）流水 | **不出现、不计入** |

## 五、口径 / 公式核对

业务日：增加 = 出库日（空则应收创建日转显示时区）；已收 = 核销创建日转显示时区。期间闭区间。

```text
期初 = Σ出库应收(日 < from) − Σ核销(日 < from)
本期增加 = Σ出库应收(from ≤ 日 ≤ to)
本期已收 = Σ核销(from ≤ 日 ≤ to)
期末 = 期初 + 本期增加 − 本期已收
```

滚余额：上一行余额 + 本行增加 − 本行已收。期初行余额 = 期初；最后一行余额 = 期末。表尾增加列合计 = 本期增加；已收列合计 = 本期已收。

**设计 §5.3 数值例（期间 8/1–8/31）：**

| 事件 | 预期 |
|------|------|
| 7/20 出库应收 100 | 进期初 |
| 8/05 出库应收 50 | 本期增加 50 |
| 8/12 核销 40 | 本期已收 40 |
| 9/03 核销 30 | 不进 8 月 |
| 结果 | 期初 100，增加 50，已收 40，期末 110 |

后端单测：`FinanceReceivableStatementCalculatorTests.DesignExample_AugustPeriod`。

| 步骤 | 预期 |
|------|------|
| 详情 `to` ≥ 今天 | 期末 = 该客户该币当前待核销合计 |
| 8/1 与 8/31 当天的出库/核销 | **计入** 8 月（闭区间） |
| 同日既有出库又有核销 | 先增加后已收 |

### 金额边界（对照总纲 §4.5）

本页 **不提交** 核销/匹配。下列用「账面恒等式」代替提交类足额/超额：

| 用例 | 预期 |
|------|------|
| **足额核对** | 手工按公式算出的四个数 = 页面 KPI = 流水合计/末行余额 |

## 八、本功能不适用

- **本功能不适用：§4.5 核销提交「超额拒绝」**（只读重算，见第五节替代核对）。
- **本功能不适用：工作台左栏队列 / 顶栏 N/M**。
- **本功能不适用：列表页签模式 / 操作面板门控**。
- **本功能不适用：流水分页**（滚余额须整表阅读；底栏仅列设置与行高）。
- **本功能不适用：开票清单、折让、退货冲应收、未核销来款上单、对账单落库/编号/邮件**。
- **本功能不适用：新权限码 / DDL**（侧栏沿用 `finance-receipt.read`）。

**上线前置：** 部署含本功能的版本后验收；**无新迁移、无新权限脚本**。建议重启 CRM.API 与刷新前端。
