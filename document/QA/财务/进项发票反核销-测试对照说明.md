# 进项发票反核销 — 测试对照说明

> **页面 / 路由：** `/finance/purchase-invoices`（侧栏付款管理 → 进项发票）；详情 `/finance/purchase-invoices/:id`  
> **设计文档：** [进项发票反核销-设计与实现](../../System/财务/进项发票反核销-设计与实现.md)  
> **正向核销：** [进项发票核销-设计与实现](../../System/财务/进项发票核销-设计与实现.md)  
> **权限：** 写 `finance-purchase-invoice.write`（财务数据只读不可写）

---

## 一、入口与权限

| 步骤 | 预期 |
|------|------|
| 有 write，发票核销状态为部分或完成（或核销金额>0），且未作废 | 列表操作列、详情页头可见「反核销」 |
| 无 write / 财务数据只读 | 不可见或点了被拒绝；列表仍能打开 |
| 无 read | 不可进入进项发票 |
| 未核销（核销金额=0） | **无**「反核销」按钮 |
| 已作废 / 已冲红 | **无**按钮；若直调接口则拒绝 |
| 进项发票核销桌面 | **无**反核销按钮（本功能不适用：入口不在桌面） |

本功能不适用：工作台左栏队列、页签模式、操作面板门控、多租户打印皮肤。

---

## 二、确认单号

| 步骤 | 预期 |
|------|------|
| 弹出提示，输入列表「发票单号」且完全一致 | 提交成功 |
| 输入该票「发票号码」（纸质号）且完全一致 | 提交成功 |
| 输入错误单号 | 前端提示不匹配，不发请求；若绕过前端，接口 400「确认单号不匹配」 |
| 取消 / 空输入 | 不提交 |

---

## 三、口径 / 公式核对（金额与核销边界）

反核销 **不提交本次核销金额**，故：

- **足额成功**：先在核销桌面把发票 **足额核销到待核销=0**，再反核销，余额应回到核销前。
- **超额拒绝：本功能不适用：反核销不提交核销金额。** 拒绝类覆盖「无需反核销 / 单号不符 / 已冲红」。

```text
反核销后：
  发票待核销 = 发票金额 - Σ剩余有效流水（本票流水已软删，通常为发票金额）
  入库明细待匹配 = 明细金额 - Σ该明细剩余有效流水（其它发票流水仍计入）
  付款待付 = max(0, 已核销 - 已付派生)
```

| 用例 | 预期 |
|------|------|
| **足额（先足额核销，再反核销）** | **成功**；发票核销状态=未核销，核销金额=0，待核销=发票金额；对应入库待匹配恢复；付款状态回到未付款（相对已核销=0） |
| 部分核销后反核销 | 成功；本票流水全部撤销，其它发票打到同一入库明细的流水保留 |
| 略超（大于待核销） | **本功能不适用：反核销不提交核销金额**（超额拒绝在核销桌面测） |
| 分次核销至清零后再反核销 | 一次整票撤销全部分次流水，余额回到未核销 |
| 未核销仍调接口 | 400「当前进项发票无需反核销」，余额不变 |
| 已冲红仍调接口 | 拒绝，流水与余额不变 |
| 入库单已删、流水仍在 | 反核销仍成功；发票余额归零 |

前端提示与后端拒绝文案可不同，业务结果须一致（不匹配不落库、无需反核销不改余额）。

## 四、回归 / 交叉

| 步骤 | 预期 |
|------|------|
| 511 采购脱敏 | 详情/列表金额与供应商名为 `—`；有 write 时反核销按钮仍可点，确认后余额按真值回滚 |
| 数据权限 | 仅能反核销权限范围内供应商的发票 |
| 反核销后刷新核销桌面 | 该票重新出现在待核销（若仍有待匹配入库） |
| 反核销后强制删除进项发票 | 无有效流水后，未认证未冲红可强删（仍须 SYS_ADMIN + 发票号码） |
| 有有效流水时强制删除进项发票 | 拒绝，提示须先反核销 |
| 有有效流水时强制删除对应入库 | 拒绝，文案含 **进项发票单号**（普通删除同样拒绝） |
| 付款单 | 反核销进项 **不**改变付款单状态 |
