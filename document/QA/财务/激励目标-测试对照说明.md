# 激励目标 — 测试对照说明

> **页面 / 路由：** `/dashboard`（控制台；欢迎区与业务总览之间的「激励目标」卡片，无独立菜单）  
> **设计文档：** [激励目标-设计与实现](../../System/财务/激励目标-设计与实现.md)  
> **实施方案：** [激励目标实施方案](../../实现方案/激励目标实施方案.md)  
> **权限 / DDL：** `incentive-target.read` / `incentive-target.write`；脚本 `scripts/ensure_incentive_target_postgresql.sql`  
> **上线前：** 执行上述 SQL（或对应迁移）后重启 API；已登录账号须重新登录才能带上新权限

---

## 一、入口与权限

| 步骤 | 预期 |
|------|------|
| 持有 `incentive-target.read` | 控制台欢迎区与业务总览之间出现「个人提成」卡片；标题含双月（如 8–9月），副文案为业务提成 / 采购提成 |
| 无 `incentive-target.read` | 卡片不出现；直打 `GET /api/v1/incentive-targets/me` 为 403 |
| 有 read、无 write | 能看实际/目标/完成度；无「设置」；`PUT` 为 403 |
| 有 write | 「设置」打开对话框，可保存本期、年度金额 |
| 冒充登录 | 能看被冒充人的进度；点保存 → 失败（403），库中目标不变 |
| 无独立菜单 | 侧栏不出现「激励目标」菜单项 |

---

## 二、金额保存边界（§4.5）

本功能是**自设定额**，不是核销/匹配进度。

**本功能不适用：核销/匹配的「足额成功 + 超额拒绝」。** 定额没有「待核销余额」；实际超过目标表示超额完成，必须成功展示，不得拒绝保存、不得改提成结果。

金额写入仍须测边界：

| 用例 | 预期 |
|------|------|
| 保存本期 `0.01`（最小正金额） | **成功**；卡片目标为 `0.01` |
| 保存年度 `8000.00` | **成功**；刷新后仍在 |
| 保存 `99,999,999.99`（上限） | **成功** |
| 保存 `100,000,000.00`（超上限） | **拒绝**（400）；原目标不变 |
| 保存负数 | **拒绝**；原目标不变 |
| 保存超过 2 位小数（如 `10.001`） | **拒绝**或按 2 位截断（以后端为准，前后须一致） |
| 清空或保存 `0` | 视为未设置；该期目标消失，完成度不显示 |
| 实际 = 目标（如目标 100、动态合计 100） | 完成度 **100.0%**（对照完成度，不是核销足额） |
| 实际 > 目标 | 完成度 **>100%**，卡片与保存都成功 |

```text
可保存 ⇔ 0 < targetUsd ≤ 99,999,999.99 且小数位 ≤ 2
清除   ⇔ targetUsd 为空或 0（软删）
完成度 ⇔ 已设目标时 Round(实际 / 目标 × 100, 1)
```

开发侧应对保存校验补单测（负数 / 上限 / 0 清除）；QA 按上表在控制台走一遍。

## 三、口径 / 公式核对

时区：`Asia/Shanghai`。本期窗 = `CommissionTerm.GetOpenWindow(今天)`，与「预计提成」默认日期窗一致。

```text
本期实际 = Σ commission_dynamic.commission_usd
           （user_id=自己 AND role_type=当前身份
             AND calc_month ∈ 开放窗两个 yyyy-MM）

年度实际 = Σ commission_locked.commission_usd（同上人/角色，calc_month 年=今年）
         + Σ commission_dynamic.commission_usd（同上人/角色，calc_month 年=今年）
```

| 步骤 | 预期 |
|------|------|
| 打开控制台，对照预计提成列表该人当期合计 | 本期「实际」与该合计一致（同一角色） |
| 库中改动态表该人该月 `commission_usd` 后刷新控制台 | 本期实际跟着变（不需重跑定额） |
| 采购主部门账号 | 实际取 `role_type=2`；业务员账号取 `role_type=1` |
| 未设目标、动态合计 > 0 | 实际有数，目标为「未设置」，无完成度条 |
| 已设目标、动态合计 = 0 | 实际 `0.00`，完成度 `0.0%` |
| 偶数月 2 日及之后（开放窗已切到下一双月） | 本期目标按**新** `period_key`；未设则「未设置」；旧期行仍在库但不出现在卡片 |
| 1 月 1 日跨年后 | 年度目标按新年；未设则「未设置」 |

## 四、数据范围与脱敏

| 步骤 | 预期 |
|------|------|
| `PUT` 体里带他人 `userId` | 仍写入**自己**；对方库中无新行 |
| 另一账号打开控制台 | 看不到别人的目标与实际 |
| 经理 / 数据范围=公司 | 仍只显示经理自己的定额，不汇总下属 |
| 销售身份且金额脱敏（511） | 实际、完成度为「—」；自己填的目标仍可见；面板能加载 |
| 采购身份且金额脱敏（521） | 同上 |
| 无 511/521 | 实际、目标、完成度均为数字 |

## 五、回归 / 交叉

| 步骤 | 预期 |
|------|------|
| 预计提成 / 正式提成列表 | 金额与行数不因设定额而改变 |
| 工作日程、待办、业务总览 | 布局仍在；本卡片在欢迎区与业务总览之间 |
| 无提成菜单权限、但有激励目标 read | 卡片仍可用（实际从库汇总，不依赖提成菜单） |
| 提成 Job 次日重算后刷新控制台 | 实际跟新的动态表，目标行不变 |

## 六、本功能不适用

- 本功能不适用：核销/匹配的「足额成功 + 超额拒绝」（见 §二）。  
- 本功能不适用：工作台左栏队列、列表页签模式、操作面板门控。  
- 本功能不适用：多租户打印皮肤。  
- 本功能不适用：经理下达、团队目标、历史窗编辑、销售额定额。  
- 看板类筛选视角不适用（无公司/部门/个人页签）。
