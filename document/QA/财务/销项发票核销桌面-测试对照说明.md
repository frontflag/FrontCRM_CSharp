## 二、左栏队列（工作台）

| 步骤 | 预期 |
|------|------|
| 打开桌面 | 仅「有待匹配发票 **且** 有待匹配应收」的客户+币别 |
| 卡片字段 | 中文名、英文名、业务员、待核销发票总额+币别（Match 合计）、条数、最早开票日期 |
| 点击卡片 | 中区加载该客户+币别候选 |
| 搜索 | 过滤左栏；顶栏 N/M **不变**（全量口径） |
| 上一客户 / 下一客户 | 按队列桶切换 |

本功能不适用：审批桌面式业务类型筛选。

---

## 三、中区匹配与金额边界

| 步骤 | 预期 |
|------|------|
| 选中一张待匹配发票 | 中右信息栏显示发票单号与待核销发票金额（MatchToBe） |
| 右栏列「待核销开票金额」 | 等于该行应收 `invoice_match_to_be`（**不是**收款 `verified_to_be`） |
| **足额**（本次金额 = 该行待核销开票金额，且合计 ≤ 发票 MatchToBe） | **提交成功**；余额与状态正确 |
| 略超（大于待匹配一个最小货币单位） | 拒绝，余额不变 |
| 分次匹配至发票 MatchToBe=0 | MatchStatus=完成；队列可能移除该客户桶 |
| 自动填写 | 按发票剩余与应收待匹配依次填满，不超额 |
| 成功后 | **留在当前客户+币别**；刷新队列与候选 |

### 公式核对

```text
发票 MatchToBe = InvoiceTotal - Σ(匹配流水 where invoice_id)
应收 InvoiceMatchToBe = Amount - Σ(匹配流水 where receivable_id)
提交合计 ≤ 发票 MatchToBe
每行 ≤ 该行 InvoiceMatchToBe
```

## 四、Receive* 派生（交叉收款核销）

| 步骤 | 预期 |
|------|------|
| 应收已收款核销、发票尚未匹配 | 发票 ReceiveDone=0、ReceiveStatus=未收款 |
| 完成匹配后 | Receive* 按 min(匹配额, 应收 VerifiedDone) 汇总回写 |
| 匹配后再做收款核销 | 相关发票 Receive* 再次刷新 |
| 收款明细 | **不得**再直接改发票 Receive* |

---

## 五、右扩展

| 步骤 | 预期 |
|------|------|
| 进入桌面 | 右侧扩展 **默认关闭** |
| 展开右侧 | 默认「出库单」页签 |
| 切换中右应收行 | 出库单内容随聚焦应收的出库变化 |
| 客户无中文名/英文名 | 对应行不显示 |

## 六、列表回归（若同期交付）

| 步骤 | 预期 |
|------|------|
| 销项发票列表收款状态筛选 | 与派生 ReceiveStatus 一致 |
| 应收列表开票状态（若已加） | 与 `invoice_match_status` 一致 |

本功能不适用：多租户打印皮肤专项（桌面非打印页）。
