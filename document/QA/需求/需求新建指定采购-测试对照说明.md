# 需求新建指定采购 — 测试对照说明

> **页面 / 路由：** `/rfqs/create`、`/rfqs/:id/edit`（菜单：需求 → 需求列表 → 新建 / 编辑）；采购参数 `/system/purchase-params/default-assign-method`  
> **设计文档：** [指定采购-分配方式-设计与实现](../../System/需求/指定采购-分配方式-设计与实现.md)、[采购参数-默认分配方式-设计与实现](../../System/采购/采购参数-默认分配方式-设计与实现.md)  
> **采购参数验收：** [采购参数-默认分配方式-测试对照说明](../采购/采购参数-默认分配方式-测试对照说明.md)  
> **权限：** 新建须需求创建权限；编辑须需求维护权限。读取报价员名单 **不** 要求采购参数权限。开关读写走既有「采购参数 → 默认分配方式」读写权限。**无新权限码。**  
> **DDL：** 无新迁移。参数行可在采购参数页首次保存时自动创建，或执行 `scripts/ensure_rfq_allow_designated_purchaser_postgresql.sql`。未配置视为关闭。

---

## 一、入口与权限

| 步骤 | 预期 |
|------|------|
| 采购参数「默认分配方式」 | 有「允许指定采购」勾选，默认未勾选；保存后刷新仍保持 |
| 未勾选「允许指定采购」，打开新建需求 | 分配方式下拉 **没有**「指定采购」 |
| 勾选并保存后，打开新建需求 | 分配方式下拉最后一项为 **指定采购** |
| 仅有需求创建、无采购参数权限的账号 | 开关开启后仍能看到指定采购；分配采购仍能列出报价员池已勾选且在职的人 |
| 无默认分配方式写权限 | 可看开关，保存按钮失败或不可提交（与其它采购参数页一致） |
| 采购参数「默认分配方式」下拉 | **没有**指定采购；默认仍是 2/3/5 |

---

## 二、创建保存

| 步骤 | 预期 |
|------|------|
| 选指定采购 | 分配方式右侧出现 **分配采购**，必填（红星 +「请选择分配采购」） |
| 选回采报优先 / 条目轮询 / 品牌轮询 | 分配采购隐藏并清空 |
| 指定采购且未选分配采购，点保存 | 前端拦截「请选择分配采购」 |
| 指定采购并选池内一人，多条明细保存 | 每条明细报价员 1 = 该人，报价员 2 为空；主单分配方式为指定采购 |
| 采购参数报价人数 = 2 | **仍只分一人**，不写第二人 |
| 分配采购选不在池内的人（绕过前端） | 接口拒绝，文案含报价员池 |
| 开关关闭时绕过前端提交 assign_method=4 | 接口拒绝，文案含「未开启指定采购」 |
| 详情展示 | 分配方式为「指定采购」 |

---

## 三、编辑

| 步骤 | 预期 |
|------|------|
| 开关开启，打开已是指定采购的需求 | 分配采购带出原人；已不在池仍显示，可保存 |
| 主单已是指定采购，只加明细不改人 | 新行报价员 = 原人；不必重选 |
| 把其它方式改成指定采购并选人，不加新行 | 主单方式变为指定采购；**已有行报价员不变** |
| 改成指定采购后加新行 | 新行 = 所选人；旧行仍不变 |
| 开关关闭后打开已是指定采购的需求 | 下拉仍显示指定采购（当前值），可保存、可加明细沿用原人 |
| 开关关闭后把其它方式改成指定采购（绕过前端） | 接口拒绝「未开启指定采购」 |
| 详情整单再分配采购员 | 方式保持指定采购（**不**受开关限制） |
| 详情只改一行采购员 | 主单方式不变 |

---

## 四、草稿 / 复制带出

| 步骤 | 预期 |
|------|------|
| 指定采购保存草稿再恢复 | 带出分配方式与分配采购 |
| 带出的人已不在报价员池 | 分配采购清空，提示重新选择 |
| 开关关闭后恢复指定采购草稿 | 当前值仍是指定采购，下拉保留该项；若改成其它方式后再改回，前端不再提供指定采购 |

---

## 五、本功能不适用

- **本功能不适用：§4.5 核销金额足额成功 / 超额拒绝**（不提交核销/匹配金额）。
- **本功能不适用：工作台左右栏队列 / 列表页签模式 / 操作面板门控。**
- **本功能不适用：多租户打印皮肤。**
- **本功能不适用：销售/采购金额脱敏**（本页不展示敏感金额列）。
- **本功能不适用：看板统计公式 / 数据分析筛选。**

---

## 六、上线前置

1. 部署含本改动的 **CRM.API** 后须 **重启 API**。
2. 无新 SQL 迁移、无新权限码。可选执行 `scripts/ensure_rfq_allow_designated_purchaser_postgresql.sql`；未执行时 GET 视为关闭，首次在采购参数页保存会自动建行。
3. 新建/编辑需求的账号重新进入页面即可（默认分配方式与池选项走登录后接口，不依赖采购参数菜单）。
4. 验收前先确认采购参数「允许指定采购」的勾选状态，避免误报「下拉没有指定采购」。

*部署含指定采购分配方式及「允许指定采购」门控的 API + 前端后验收。*
