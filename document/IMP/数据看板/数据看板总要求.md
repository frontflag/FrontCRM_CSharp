> **状态**：总要求定稿；销售/采购/物流域 IMP 已落地（销/采含 **内容 Tab**，见 §3.6）；财务域方案见 `财务统计.md`（待开发）

> **子文档**：`销售统计.md`、`采购统计.md`、`物流统计.md`、`财务统计.md`（内容 Tab 细节见销/采 §3.5+）

## 一、目标

在 CRM 内提供统一的 **数据看板（Analytics Dashboard）** 能力，对销售、采购、物流、财务四条业务线做**带权限过滤**的统计分析，支持 **公司 / 部门 / 个人** 三个层级对象，并按 **静态、趋势、分解、待办** 四类呈现方式组织指标。

**非目标（一期）**：自定义拖拽报表、定时邮件、物理数仓/BI 平台替换、训练型「数据预测」模型上线。

## 二、数据角色与权限

### 2.1 三个层级对象

同一业务看板页面通过 **Tab / 分段器** 切换统计透镜（不拆多个路由）：

| 层级 | 统计对象 | 典型用户 |
| --- | --- | --- |
| **公司** | 当前用户数据权限内的「组织整体」汇总 | 管理层、`SaleDataScope=0` |
| **部门** | 按员工**主部门**（`sys_user_department.is_primary`）分组 | 部长、总监 |
| **个人** | 按业务员 / 采购员等**归属人**分组 | 一线销售、采购 |

**原则**：

1. **数据权限是天花板**：看板数据集合 ≤ 对应业务列表在 `DataPermissionService` 下可见集合。
2. **层级是透镜**：在允许的数据内切换聚合维度；**不得**通过前端参数突破 Scope。
3. **后端强校验**：`viewLevel`、`departmentId`、`ownerUserId` 等须由服务端 `*AnalyticsScopeValidator` 校验，越权 **403**。
4. **透明提示**：响应含 `scopeContext`（可见范围文案、Scope 值、是否经权限裁剪）。

各域 Scope 与 Tab 可见性详见 `销售统计.md` §5.3、`采购统计.md` §5.3、`物流统计.md` §5.3、`财务统计.md` §5；财务域映射 `FinanceDataScope`（见 `document/System/权限/权限-部门.md`）。

### 2.2 功能权限

| 项 | 建议 |
| --- | --- |
| 权限码 | 按域拆分：`analytics-sales.read`、`analytics-purchase.read`、`analytics-logistics.read`、`analytics-finance.read` |
| 只读部门 | `*DataAccess=1` 允许看板**只读**访问 |
| 超管 | `SYS_ADMIN` 不受 Scope 限制（与各业务列表一致） |

## 三、数据统计方式（呈现模型）

所有业务域指标归入以下 **四类**；API 与前端组件按类复用。

### 3.1 静态数据（Snapshot）

| 项 | 说明 |
| --- | --- |
| **含义** | 到**当前时刻**（或筛选截止时间）的累计/存量统计 |
| **示例** | 订单条目数、销售金额、在库商品数量 |
| **呈现** | **Key : Value**（KPI 卡片、数字面板） |
| **API 形态** | `snapshot.*` 或 `kpi.*` 字段 |
| **刷新** | 用户点击查询 / 进入页面时拉取；不做 WebSocket 实时推送（一期） |

### 3.2 趋势数据（Trend）

| 项 | 说明 |
| --- | --- |
| **含义** | **同一时间段内**随时间变化的数据 |
| **示例** | 近 30 天成单金额；某月至某月应收金额走势 |
| **呈现** | **折线图** 或 **柱状图** |
| **API 形态** | `trend: [{ period, ...metrics }]` |
| **参数** | `dateFrom`、`dateTo`、`groupBy=day\|week\|month` |

### 3.3 分解数据（Breakdown）

| 项 | 说明 |
| --- | --- |
| **含义** | 某一指标的**构成比例** |
| **示例** | 人民币 vs 外币金额占比；订单在各业务环节的状态占比 |
| **呈现** | **饼图**（或环形图）；必要时附明细表 |
| **API 形态** | `breakdown: [{ dimension, value, ratio }]` |
| **约束** | 分项之和 = 100%（或标明「其他」桶） |

### 3.4 待办数据（Todo / Backlog）

| 项 | 说明 |
| --- | --- |
| **含义** | 尚需业务处理的**存量/缺口**指标（可驱动行动） |
| **示例** | 应收款余额、待出库订单条目数、待入库数量 |
| **呈现** | **Key : Value**；可带跳转链接至对应业务列表（带筛选） |
| **API 形态** | `todo.*` 或 `backlog.*` |
| **与静态区别** | 静态偏「结果总量」；待办偏「未完成/待处理」 |

### 3.5 四类与 UI 布局关系

```
┌─ 筛选：日期 / viewLevel / 部门 ─────────────────────────────┐
│ scopeContext 提示条                                          │
├─ 待办区（Todo KPI） ─────────────────────────────────────────┤
├─ 静态区（Snapshot KPI） ─────────────────────────────────────┤
├─ 趋势区（折线/柱状） │  分解区（饼图） ──────────────────────┤
└─ 排行/明细表（可选） ────────────────────────────────────────┘
```

### 3.6 内容 Tab（销售 / 采购域看板）

除 §2.1 **Scope Tab**（公司 / 部门 / 个人）外，销售与采购分析页另有 **内容 Tab**（同一路由内切换，共用上方筛选）：

| 域 | 内容 Tab | 说明 |
| --- | --- | --- |
| 销售 `/reports/sales` | 概况 · 客户 · 需求 · 订单 | 概况 = 域级 KPI/趋势/分解；后三 Tab 复用列表看板（`mode=report`）或客户维面板 |
| 采购 `/reports/purchase` | 概况 · 供应商 · 报价 · 采购订单 | 同上；供应商对齐销售「客户」；报价/订单明细双口径 `listFilter` vs `reportScope`/`reportApproved` |

- **加载**：进入子 Tab 后再请求（lazy）；概况默认加载。
- **详情与 API**：[`销售统计.md`](./销售统计.md) §3.5–3.8、[`采购统计.md`](./采购统计.md) §3.5–3.8；列表看板对照见 §九索引。

## 四、数据统计维度（指标类型）

任意业务指标标注以下**统计维度类型**之一（或多维组合），便于 API 字段命名与前端展示统一。

| 维度类型 | 说明 | 示例 |
| --- | --- | --- |
| **单据数** | 主单或明细**行数** | 需求条目数、报价条目数、销售/采购订单条目数 |
| **数量** | 物料**个数**（含库存 PCS） | 在库商品数量、已出库数量 |
| **金额数** | 货币金额（须标明币别/是否本位币） | 销售金额、采购金额、库存金额、收付款金额 |
| **日期** | 时间长度或账龄类 | 库龄、应收款天数、付款待入库天数 |
| **客户数** | 去重客户主体数 | 需求客户数、成单客户数 |
| **供应商数** | 去重供应商主体数 | 报价供应商数、成单供应商数 |
| **比率** | 两指标之比（转化、完成率） | 需求→销售订单转化率 |

**金额统一约定（建议）**：

- 看板默认展示 **本位币**（`convert_total` / 财务本位汇总字段）。
- 分解图可按 **原币** 或 **币别代码** 分桶。
- 跨域对比（销售 vs 采购）须使用同一汇率快照规则（引用财务参数，二期细化）。

### 5.1 销售

| 指标 | 维度 | 呈现 | 口径要点（实现参考） |

| 销售订单各环节执行状况 | 单据数/金额 | 分 | 主状态 + `sellorderitemextend` 进度（采购/入库/出库/收款/开票） |

#### 5.1.1 销售订单金额 — 分阶段

| 阶段 | 含义 | 数据源建议 |
| --- | --- | --- |
| **成单已审核** | 审核通过后的订单承诺额 | `sellorder.status >= Approved`，`convert_total` |
| **已出库** | 已实际出库对应金额 | `sellorderitemextend` 出库数量 × 单价，或 `stock_out` 已出库单 `total_amount` 汇总 |
| **已收款** | 已核销收款金额 | `sellorderitemextend.receipt_amount_finish` 或财务收款核销汇总 |

各阶段可单独做 `[静]` KPI、`[趋]` 走势、`[分]` 占成单金额比例。

#### 5.1.2 销售待办（示例）

| 指标 | 呈现 | 数据源 |
| --- | --- | --- |
| 应收款金额 | 待 | `receipt_amount_not` / 财务应收 |
| 待出库订单条目数 | 待 | `stock_out_progress_status` 未完成明细数 |
| 待开票金额 | 待 | `invoice_amount_not` |

### 5.3 物流

| 指标 | 维度 | 呈现 | 口径要点 |
| --- | --- | --- | --- |
| 在库商品数量 | 数量 | 静、趋 | `stock_item` 在库 `qty_repertory`；权限 `ApplyStockItemListDataScopeAsync` |
| 在库商品金额 | 金额数 | 静、趋 | Σ `qty_repertory × purchase_price_usd`（USD 成本） |
| 在库商品库龄 | 日期 | 静、分、趋 | 起算 `stock_in_date`；加权平均 + 分桶 |
| 待入库商品数量 | 数量 | 待、趋 | PO 未收 PCS |
| 统计科目数目 | 主体数 | 静 | 客户/销售员/供应商/采购员/品牌 去重数 |
| 客户×科目矩阵 | 数量/金额/库龄 | 静、分 | 客户锚点 + 单科目子表（API 分请求）；无客户行「无客户/备货」 |
| **库存类型分档** | — | 全局筛选 | **全部 / 客单（type=1）/ 采购库存（type=2 备货）** — 全指标生效 |

#### 5.3.1 物流：库存类型与统计科目

**库存类型**（`inventoryType`，与 `stock_item.stock_type` 一致）：

| 档位 | 过滤 |
| --- | --- |
| 全部库存 | 不筛 type（含样品 3） |
| 客单库存 | `stock_type = 1` |
| 采购库存 | `stock_type = 2`（备货） |

**统计科目**：客户、销售员、供应商、采购员、品牌（字段见 [`物流统计.md`](./物流统计.md) §3.3）。

**访问规则（无物流 Scope、仅有销/采 Scope）**：可进看板；仅 **个人**（归属销售员/采购员=本人）与 **部门**（本人∪下属）；**无公司 Tab**。

**落地文档**：见 [`物流统计.md`](./物流统计.md)（**已落地**）。

### 5.4 财务

| 指标 | 维度 | 呈现 | 口径要点 |
| --- | --- | --- | --- |
| 已付款金额 | 金额数 | 静、趋 | PO extend `payment_amount_finish` / 付款单；采购侧归属 |
| 应付款金额 | 金额数 | 待、趋 | PO extend `payment_amount_not` |
| 已收款金额 | 金额数 | 静、趋 | SO extend `receipt_amount_finish` / 收款单；销售侧归属 |
| 应收款金额 | 金额数 | 待、趋 | **`finance_receivable.verified_to_be`**（已出库账上应收；与销售 extend todo 不同，见 `财务统计.md` §4.4） |
| 待开进项发票金额 | 金额数 | 待、趋 | PO extend `purchase_invoice_to_be` |

| 待开销项发票金额 | 金额数 | 待、趋 | SO extend `invoice_amount_not` |
| 已开销项发票金额 | 金额数 | 静、趋 | SO extend `invoice_amount_finish` / 销项发票 |

**金额展示（产品已确认）**：上述 **每一项** 均返回 **美元折算合计**（`totalUsd`）+ **各原币别单独合计**（`byCurrency[]`）。

**访问规则（无财务 Scope、仅有销/采 Scope）**：可进看板；仅 **个人**（销售/采购归属=本人）与 **部门**（本人∪下属，销/采 Scope 2/3）；**无公司 Tab**。

## 六、技术架构（跨域统一）

### 6.1 路由

```
/reports
├── /sales       销售看板
├── /purchase    采购看板
├── /logistics   物流看板
└── /finance     财务看板
```

### 6.2 API 分层（建议）

每个业务域一组只读端点，**共享查询参数**：

| 端点 | 返回内容 | 对应 §三 |
| --- | --- | --- |
| `GET /api/v1/analytics/{domain}/dashboard` | `scopeContext` + `snapshot` + `todo` + `rankings?` | 静态 + 待办 + 排行 |
| `GET /api/v1/analytics/{domain}/trends` | `trend[]` | 趋势 |
| `GET /api/v1/analytics/{domain}/breakdowns` | `breakdown[]`（可多组） | 分解 |
| `GET /api/v1/analytics/logistics/customer-matrix` | 客户锚点 × 单科目矩阵（**仅物流域**） | 静态/分解 |

`{domain}` = `sales | purchase | logistics | finance`

**公共 Query**：

| 参数 | 说明 |
| --- | --- |
| `viewLevel` | `company \| department \| personal` |
| `departmentId` | 部门透镜（须校验） |
| `ownerUserId` | 个人透镜（须校验） |
| `dateFrom` / `dateTo` | 趋势/转化类时间窗 |
| `groupBy` | `day \| week \| month` |
| `metric` | 二期：切换金额阶段（成单/出库/收款等） |

**物流域附加 Query**（见 [`物流统计.md`](./物流统计.md) §6.1）：

| 参数 | 说明 |
| --- | --- |
| `inventoryType` | `all \| customerOrder \| purchaseStock` — 库存类型三档，**全指标生效** |
| `matrixSubject` | `customer-matrix` 必填：`salesperson \| vendor \| purchaser \| brand` |
| `warehouseId` | 仓库过滤（后端已支持，前端 UI 待做） |

**财务域附加 Query**（见 [`财务统计.md`](./财务统计.md) §6.1）：

| 参数 | 说明 |
| --- | --- |
| `metric` | 可选：趋势/分解切换单指标（二期） |

财务 dashboard 金额字段统一为 `{ totalUsd, byCurrency[] }` 结构。

