# 销售 / 采购订单列表统计看板 — 设计需求与实现方案

> **状态**：已落地（2026-07）  
> **范围**：嵌入 **销售订单列表**、**采购订单列表** 的上下文统计看板（非「报表分析」独立路由）  
> **关联总要求**：复用 [`数据看板总要求.md`](./数据看板总要求.md) §三「四类呈现」与共享前端组件；**不**使用公司/部门/个人 Tab（无 `viewLevel`）  
> **对照**：全局域看板见 [`销售统计.md`](./销售统计.md)、[`采购统计.md`](./采购统计.md)（`/reports/sales`、`/reports/purchase`）

## 一、定位与边界

### 1.1 与「报表分析」看板的区别

| 维度 | 列表统计看板（本文） | 报表分析看板（`/reports/*`） |
| --- | --- | --- |
| 入口 | 订单列表页搜索栏「看板」按钮 | 侧栏「报表分析」子菜单 |
| 统计范围 | **与当前列表筛选条件完全一致** | 独立日期 + 公司/部门/个人透镜 |
| 数据权限 | 复用列表 `Apply*OrderDataScopeAsync` | 复用域 Scope + `*AnalyticsScopeValidator` |
| API 前缀 | `/api/v1/sales-orders/analytics/*`、`/api/v1/purchase-orders/analytics/*` | `/api/v1/analytics/sales/*`、`/api/v1/analytics/purchase/*` |
| 典型用途 | 用户在筛完列表后，快速看 KPI/趋势/构成/排行 | 管理层跨周期、跨组织分析 |

### 1.2 产品原则

1. **筛选即统计范围**：看板数字必须与列表 `aggregates` / 全量筛选条数可对账（日期边界一致）。
2. **成单口径统一**：KPI、趋势、金额类分解、排行默认 **`status >= 10`（审核通过）**；状态饼图展示**筛选范围内全状态**。
3. **权限与脱敏**：金额是否展示由 `sales.amount.read` / `purchase.amount.read` 决定；无金额权限时饼图按**订单数**占比（与销售域看板一致）。
4. **组件复用**：`AnalyticsKpiGrid`、`AnalyticsTrendChart`、`AnalyticsBreakdownChart`、`AnalyticsBreakdownPieChart`。

### 2.2 看板布局（两域相同结构）

```
┌─ 工具条：口径提示 + groupBy（日/周/月）+ 刷新 ─────────────┐
├─ KPI 区（AnalyticsKpiGrid，5 项含成单金额 split 布局）─────┤
├─ 趋势区：成单数 │ 成单金额（USD）──────────────────────────┤
├─ 分解区：状态条图 + 饼图（币别、主体维度、归属人）──────────┤
└─ 排行区：Top10 表格（主体 × 金额/单数/复购复采）────────────┘
```

**成单金额 KPI**：`AnalyticsKpiGrid` `layout: 'split'` — 左侧折算 USD 大数，右侧原币分列（USD/RMB 等）；无金额权限显示 `—`。

## 四、统计口径

### 4.1 成单定义（已确认）

| 项 | 口径 |
| --- | --- |
| 成单阈值 | 主表 **`status >= 10`（审核通过）** 及以上（含待确认、已确认、进行中、完成等） |
| 成单金额 | 订单头 **`convert_total`（USD）** 合计；原币分档用头字段 **`currency` + `total`** |
| 时间字段 | **`create_time`**（订单创建时间） |
| 复购 / 复采 | **复购客户数 / 复采供应商数**：成单数 ≥ 2 的主体数；**复购/复采订单数**：Σ max(0, 该主体成单数 − 1) |

> 说明：列表看板**不**套用 `/reports` 用的 `ApplyAnalyticsStatusFilter`（排除取消/审核失败）；用户若筛选「全部状态」，取消单可进入状态饼图，但不计入成单 KPI。

### 4.2 日期边界（列表与看板对齐）

创建日期筛选统一为：

- 起始：`SalesAnalyticsDateFilter.ToUtcDateStart` / `PurchaseAnalyticsDateFilter.ToUtcDateStart`
- 截止：`ToUtcDateEndExclusive`（**含选中日全天**，上界为次日 00:00 UTC）

**实现位置**：

- 销售：`CRM.Infrastructure/SalesOrders/SalesOrderListQuery.cs` → `BuildFilteredQueryAsync`
- 采购：`CRM.Infrastructure/PurchaseOrders/PurchaseOrderListQuery.cs` → `BuildFilteredQueryAsync`（2026-07 由 `EndDate.AddDays(1)` 改为与销售一致）

### 4.3 金额脱敏

| 域 | 脱敏门闸 | 金额权限码 | 响应字段 |
| --- | --- | --- | --- |
| 销售 | `SaleSensitiveFieldMask521` | `sales.amount.read` | `context.maskAmounts`；金额为 `null`，前端显示 `—` |
| 采购 | `PurchaseSensitiveFieldMask511` | `purchase.amount.read` | 同左 |

**无金额权限时的分解规则**：

| 图表 | 计量 |
| --- | --- |
| 币别饼图 | 按**订单数** |
| 客户/供应商维度饼图 | 按**订单数**（每条成单订单计 1） |
| 业务员/采购员饼图 | 按**订单数** |
| 订单状态条图 | 按**订单数**（有金额权限时按 `convert_total`） |

## 五、指标清单

### 5.1 销售订单列表看板

#### 5.1.1 静态 KPI（Snapshot）

| 指标 | 字段 | 口径 |
| --- | --- | --- |
| 成单客户数 | `approvedCustomerCount` | 成单订单 `customer_id` 去重 |
| 复购客户数 | `repeatCustomerCount` | 成单数 ≥ 2 的客户数 |
| 成单订单数 | `approvedOrderCount` | `status >= 10` 订单数 |
| 复购订单数 | `repeatOrderCount` | Σ max(0, 客户成单数 − 1) |
| 成单金额 | `approvedAmountUsd` + `currencyLines[]` | USD 合计 + 分币别原币/USD |

#### 5.1.2 趋势（Trend）

| 序列 | 字段 | 参数 |
| --- | --- | --- |
| 成单数 | `approvedOrderCount` | `groupBy=day\|week\|month` |
| 成单金额 | `approvedAmountUsd` | 同左 |

时间桶：有筛选日期用筛选范围；否则用成单数据 min/max `create_time`。

#### 5.1.3 分解（Breakdown）

| groupKey | 标签 | 数据范围 | 展示 |
| --- | --- | --- | --- |
| `orderStatus` | 订单主状态 | **全量筛选** | 横向条图 |
| `currency` | 币别构成（成单） | 成单 | 饼图 |
| `customerType` | 客户类型（成单 USD） | 成单 + `customerinfo` | 饼图 |
| `customerLevel` | 客户等级（成单 USD） | 成单 + `customerinfo` | 饼图 |
| `customerIndustry` | 客户行业（成单 USD） | 成单 + `customerinfo` | 饼图 |
| `salesUser` | 业务员（成单 USD） | 成单 | 饼图 |

前端字典：`useCustomerDictStore` 翻译类型/等级/行业；状态用 `salesOrderList.status.*` i18n。

#### 5.1.4 排行（Rankings，Top 10）

## 六、API 设计

### 6.1 端点一览

**销售**（`SalesOrdersController`，须 `sales-order.read`）：

| 方法 | 路径 | 响应 |
| --- | --- | --- |
| GET | `/api/v1/sales-orders/analytics/dashboard` | `SalesOrderListAnalyticsDashboardDto` |
| GET | `/api/v1/sales-orders/analytics/trends` | `SalesOrderListAnalyticsTrendPointDto[]` |
| GET | `/api/v1/sales-orders/analytics/breakdowns` | `SalesAnalyticsBreakdownGroupDto[]` |
| GET | `/api/v1/sales-orders/analytics/rankings` | `SalesOrderListAnalyticsRankingsDto` |

**采购**（`PurchaseOrdersController`，须 `purchase-order.read`）：

| 方法 | 路径 | 响应 |
| --- | --- | --- |
| GET | `/api/v1/purchase-orders/analytics/dashboard` | `PurchaseOrderListAnalyticsDashboardDto` |
| GET | `/api/v1/purchase-orders/analytics/trends` | `PurchaseOrderListAnalyticsTrendPointDto[]` |
| GET | `/api/v1/purchase-orders/analytics/breakdowns` | `SalesAnalyticsBreakdownGroupDto[]` |
| GET | `/api/v1/purchase-orders/analytics/rankings` | `PurchaseOrderListAnalyticsRankingsDto` |

响应包装：`ApiResponse<T>.Ok(data)`（与报表分析 API 风格一致）。

### 6.2 公共 Query 参数

见 §三；趋势额外：`groupBy`（默认 `month`）。

### 6.3 后端分层

```
Controller.BuildListAnalyticsQueryRequestAsync（权限 + 筛选 DTO）
    → IPurchaseOrderListQuery / ISalesOrderListQuery
        → *OrderListQuery.BuildFilteredQueryAsync（数据范围 + 筛选）
        → BuildApprovedOrderQueryAsync（status >= 10）
        → 聚合方法（Dashboard / Trends / Breakdowns / Rankings）
```

**核心约束**：`BuildFilteredQueryAsync` 与列表分页、`GetAggregatesAsync` **共用同一实现**，避免看板与列表条数偏差。

## 八、验收要点

1. **筛选一致性**：同一用户、同一组筛选，列表 `aggregates.totalCount` 与看板状态饼图各分项订单数之和一致（成单 KPI 仅统计 `status >= 10` 子集）。
2. **日期含当日**：选择结束日为 D，则 D 日 23:59 创建的订单仍计入（UTC 上界 exclusive）。
3. **金额脱敏**：无 `*.amount.read` 时 API 不返回金额；饼图标题带「按订单数」后缀。
4. **采购供应商排行**：三张表均独立展示（金额 / 成单数 / 复采数）。
5. **权限过滤**：客户/业务员/供应商/采购员筛选在无权限时不传入 API（与销售/采购列表行为一致）。
