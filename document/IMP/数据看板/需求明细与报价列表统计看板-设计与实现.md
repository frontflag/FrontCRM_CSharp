### 1.1 与「报表分析」看板的区别

| 维度 | 本文两类列表看板 | 报表分析（`/reports/sales`、`/reports/purchase`） |
| --- | --- | --- |
| 入口 | 列表搜索栏「看板 / 列表」 | 侧栏「报表分析」 |
| 筛选 | 与当前列表搜索栏 **完全一致** | 独立日期 + 公司/部门/个人 Tab |
| 统计范围 | 筛选结果 **全量**（非当前页） | 域级聚合 + Scope 透镜 |
| 成单/转化 | 列表上下文、与筛选联动 | 跨周期管理分析 |

### 1.2 共性产品原则

1. **筛选即统计范围**：看板数字对应当前列表筛选下的全量结果，可与列表 `aggregates` / 总条数对账。
2. **Filter 共用**：列表分页、汇总卡片、看板聚合 **同一套** `*ListFilter` / `BuildFiltered*QueryAsync`，避免口径漂移。
3. **四端点 API**：`dashboard` / `trends` / `breakdowns` / `rankings`，与订单列表看板模式一致。
4. **四类呈现**：静态 KPI、趋势、分解（条图/饼图）、排行 Top10。
5. **交互统一**：`viewMode` = `list` \| `board`；`boardFilters` 计算属性 + 看板 `watch` 自动刷新；`btn-board-active` 青色高亮。

## 二、共性口径（两看板复用）

### 2.1 成单链路

成单 KPI、报价成单率、需求成单率 **共用**：

```
sellorderitem（status = 0）
  → quote（oi.quote_id）
  → rfqitem（q.rfq_item_id）
  → sellorder（so.status >= 10，审核通过及以上，排除取消单）
```

- **成单计数**：按 `rfqitem.id` 去重。
- **销售订单主状态**：`SellOrderMainStatus.Approved = 10` 为下限。

### 2.2 报价三档（需求明细分布 & 报价看板并联指标）

与前端 `effectiveRfqItemLineStatus`、后端 `RfqItemListAnalyticsQuery` 一致：

| 档位 | 判定 |
| --- | --- |
| **有报价** | `rfqitem.status ≠ 5` 且（`status ≥ 1` 或存在 `quote.rfq_item_id`） |
| **查无报价** | `rfqitem.status = 5` |
| **采购未处理** | `rfqitem.status = 0` 且无关联 `quote` |

### 2.3 有效需求明细（比率分母）

- **需求成单率**分母：筛选内明细，**仅排除 `status = 5`**。
- **需求报价率 / 报价成单率**分母：同上（排除查无报价）；分子侧另要求「有 quote」。

### 2.4 日期边界

- 筛选参数：`startDate` / `endDate`（日期字符串，含止日）。
- 服务端：`SalesAnalyticsDateFilter.ToUtcDateStart` / `ToUtcDateEndExclusive`。
- 趋势落桶：`groupBy` = `day` \| `week` \| `month`；时间轴均为 **`rfq.create_time`**。

### 2.5 品牌分布 TopN

- 需求明细看板：`rfqitem.brand`，**Top20 +「其他」**（`CollapseBreakdownTailToOther`）。
- 报价看板：quote 下 **首条 `quoteitem.brand`**（按 `CreateTime` 升序），**Top20 +「其他」**。

## 三、需求明细列表统计看板

### 3.1 定位

- **页面**：需求明细列表 `/rfq-items`（`RFQItemList`）。
- **场景**：筛完明细后查看客户发布/复询、需求规模、成单转化、币别品牌、采购员分配、报价三档与排行。
- **说明**：看板入口已从 `/rfqlist` 主列表迁移至明细页；`/api/v1/rfqs/analytics/*` 后端保留，前端主列表不再调用。

### 3.2 设计需求

#### UI 与交互

| 项 | 需求 |
| --- | --- |
| 入口 | 搜索栏「看板 / 列表」 |
| 日期 | 创建日期区间（`rfq.create_time`） |
| 看板模式 | 隐藏表格、分页、底部采购报价 Dock |
| 滚动 | `.rfq-item-board-scroll`（`flex:1; overflow-y:auto`） |

#### 指标清单

| 呈现 | 内容 |
| --- | --- |
| **KPI（7）** | 发布需求客户数、复询客户数、复询需求数、需求数、需求明细数、成单明细数、需求成单率 |
| **趋势（3）** | 客户数、需求数、需求明细数 |
| **分布（8）** | 主状态条图 + 7 饼图（类型/目标/行业/币别/品牌/分配采购员/报价三档） |
| **排行（6）** | 客户、业务员、MPN×2、品牌×2 Top10 |

#### 筛选（与 `GET /api/v1/rfqs/items` 一致）

| 参数 | 说明 |
| --- | --- |
| `rfqCode` | 需求编号 |
| `customerKeyword` | 客户名称模糊 |
| `materialModel` | MPN / 客户料号 |
| `brandId` | 品牌主键（搜索栏品牌选择，精确匹配 `rfqitem.brand_id`） |
| `status` | 明细状态 |
| `salesUserId` | 主表业务员 |
| `purchaserUserId` | 分配采购员 |
| `hasQuotesOnly` | 仅有报价 |
| `startDate` / `endDate` | 主单 `create_time` |

**数据权限**：`GetRfqItemLineVisibilityPredicateAsync`（与明细列表一致）。

#### 统计口径摘要

| 类别 | 要点 |
| --- | --- |
| 客户 KPI | 发布客户 = `customer_id` 去重；复询客户 = 同客户 ≥2 张主单；复询需求数 = Σ max(0, 主单数−1) |
| 需求 KPI | 需求数 = 主单去重；明细数 = 行 COUNT |
| 成单 KPI | 成单明细数见 §2.1；成单率 = 成单数 / 有效明细数 |
| 趋势 | 按 `rfq.create_time` 落桶 |
| 分布 | 主状态/类型/目标/行业按 **主单去重**；币别/品牌/采购员/报价三档按 **明细数** |
| 排行 | 空 `mpn`/`brand` →「未设置」 |

## 四、报价列表统计看板

### 4.1 定位

- **页面**：报价列表 `/quotes`（`QuoteList`）。
- **场景**：筛完报价后查看供应商覆盖、响应时效、需求报价率、成单转化、涂标/产地/包邮、采购员绩效。
- **核心差异**：采用 **方案 A**——并联需求明细集与报价主表集，**`status` 仅过滤 quote**，不裁剪并联需求（查无报价、需求报价率分母仍可见）。

### 4.2 设计需求

#### 统计范围（方案 A）

| 数据集 | 筛选约束 |
| --- | --- |
| **并联需求明细** `rfqitem` | `keyword` + 日期（`rfq.create_time`）+ 数据权限 |
| **报价主表** `quote` | 上式 **+ `status`** |
| **报价行** `quoteitem` | 隶属筛选后 quote；供应商数、首条 brand/涂标/产地等 |

#### UI 与交互

| 项 | 需求 |
| --- | --- |
| 入口 | 搜索栏「看板 / 列表」 |
| 日期 | P0：**需求创建日期**（`rfq.create_time`），列表与看板共用 |
| 看板模式 | 隐藏 4 张 stat-card、表格、分页 |
| 空筛选 | **允许**进入看板 |
| 滚动 | `.quote-board-scroll` |

#### 指标清单

| 呈现 | 内容 |
| --- | --- |
| **KPI（8）** | 供应商数、有效报价数、查无报价数、需求报价率、平均响应时间（分钟）、报价平均数、成单数、报价成单率 |
| **趋势（4）** | 报价供应商数、需求明细数、总需求数（含查无）、有效报价数 |
| **分布（9）** | 报价状态条图 + 8 饼图（报价三档/涂标/晶圆产地/封装产地/包邮/品牌/分配采购员/报价采购员） |
| **排行（7）** | 供应商、采购员×2、MPN×2、品牌×2 Top10 |

#### 筛选（与 `GET /api/v1/quotes` 一致）

| 参数 | 说明 |
| --- | --- |
| `keyword` | 报价单号、MPN、备注、需求编号、客户、业务员/采购员、明细品牌/料号（OR） |
| `status` | 报价主状态 0 新建 / 1 成单 / 2 关闭；**仅过滤 quote** |
| `startDate` / `endDate` | `rfq.create_time` |
| `rfqItemId` | 精确（API 已有） |

**数据权限**：`ApplyQuoteListDataScopeAsync`（销售 Scope ∪ 采购 Scope，与报价列表一致）。

#### 统计口径摘要

| 类别 | 要点 |
| --- | --- |
| 计数粒度 | **报价条目** = `quote` 主表条数；品牌 = 首条 `quoteitem.brand` |
| 供应商 KPI | 筛选内 `quoteitem.vendor_id` 去重 |
| 报价 KPI | 有效报价 = quote 条数；查无 = 并联需求 `status=5`；响应时间 = 首条 `quote.create_time − rfq.create_time`（分钟）；报价平均数保留 1 位小数 |
| 成单 KPI | 见 §2.1；报价成单率分母 = 有 quote 的有效明细 |
| 趋势 | 落桶键 `rfq.create_time`；有效报价数 = 桶内明细关联的筛选后 quote 条数 |
| 排行 | 供应商按去重 `rfq_item_id`；采购员报价率 = quote 数 / 分配需求明细数（双槽各计 1） |

## 五、实现模式（开发参照）

新增或维护「列表嵌入看板」时，建议按以下顺序：

### 5.1 后端

1. **抽离 Filter**：从 `*ListQuery` 抽出 `BuildFiltered*QueryAsync`，列表分页与看板共用。
2. **扩展接口**：在 `I*ListQuery` 增加四个 analytics 方法；`Query` 类改为 `partial`。
3. **Bundle 加载**：一次查询筛后行集 + 必要的 ID 集合（quoted、converted、用户/供应商名缓存）。
4. **四端点实现**：`AnalyticsQuery` partial 文件内实现 snapshot / trends / breakdowns / rankings。
5. **Controller**：四个 `GET .../analytics/*`，QueryString 与列表对齐；脱敏在 Controller 层算 `mask*` 传入 Query。

### 5.2 前端

1. **列表页**：`viewMode`、`dateRange`（若需要）、`boardFilters` computed、`toggleViewMode`。
2. **看板组件**：`watch(filters)` + `onMounted` 并行请求四接口。
3. **布局**：列表页 `display:flex; flex-direction:column; height:100%`；看板区 `overflow-y:auto`。
4. **i18n**：`*.board.kpi.*`、`*.board.breakdown.*`、`*.board.rankings.*`。

### 5.3 共享前端组件

| 组件 | 路径 |
| --- | --- |
| `AnalyticsKpiGrid` | `CRM.Web/src/components/Analytics/AnalyticsKpiGrid.vue` |
| `AnalyticsTrendChart` | `CRM.Web/src/components/Analytics/AnalyticsTrendChart.vue` |
