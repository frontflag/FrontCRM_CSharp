# 需求明细分配采购员

## 功能说明

新建需求时，每条需求明细自动分配采购员（人数由 **采购参数 → 报价人数** 决定，通常为 1 或 2 人），用于对该明细报价。分配结果写入 `rfqitem.assigned_purchaser_user_id_1` / `_2`。

## 分配方式（assign_method）

创建需求页（`/rfqs/create`）可选：

| 方式 | 编码 | 说明 |
|------|------|------|
| **采报优先**（默认） | 5 | 按 MPN 优先分配给曾采购/报价该型号的采购员；无记录时条目轮询 |
| 条目轮询 | 2 | 每条明细从报价员池连续取 N 人，全局轮询 |
| 品牌轮询 | 3 | 同品牌明细共用同一组采购员 |
| **指定采购** | 4 | 本单全部明细指定同一位报价员，不受报价人数影响；分配采购必填。须先在采购参数勾选「允许指定采购」后，创建/编辑下拉才出现 |

**默认选中项** 由 **参数管理 → 采购参数 → 默认分配方式** 配置（系统参数 `System.RFQ.DefaultAssignMethod`，默认 5）。同页 **允许指定采购**（`System.RFQ.AllowDesignatedPurchaser`，默认关闭）控制创建/编辑页是否出现指定采购。

详细规则与实现见：[采报优先-分配采购员-设计与实现](../../System/采报优先-分配采购员-设计与实现.md)、[指定采购-分配方式-设计与实现](../../System/需求/指定采购-分配方式-设计与实现.md)、[采购参数-默认分配方式-设计与实现](../../System/采购/采购参数-默认分配方式-设计与实现.md)。

历史数据：`1` 系统分配同一采购。`4` 亦可由详情「分配采购员」事后写入。指定采购细则见 [指定采购-分配方式-设计与实现](../../System/需求/指定采购-分配方式-设计与实现.md)。

## 报价员池

可参与轮询/采报兜底的采购员名单在 **采购参数 → 报价员池** 维护。池为空时新建需求可能为「待分配」。

## 显示

需求明细列表须显示两名分配采购员姓名（若仅分配 1 人则第二列为空）。

## 权限

- 普通采购员：默认仅能看到**分配给自己**的需求明细（超过 **需求保护时长** 后，可见范围按保护池规则扩大）。详见 [需求保护时长-设计与实现](../../System/需求保护时长-设计与实现.md)。
- 采购总监/经理：按数据范围看到本人及下属相关明细。
