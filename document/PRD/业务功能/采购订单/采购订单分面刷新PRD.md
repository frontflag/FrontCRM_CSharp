## 1. 背景与问题

采购员改已保存的采购明细（型号、品牌、数量、单价）或下游单据事实变化后，需要把**派生结果**对齐到本单，但不能一次把所有下游字段都改掉。

旧能力把「重算状态」和「覆盖采购价」缠在一起：详情一个「刷新」会顺带改价；保存/入库等业务事件走的 Recalculate 还会改到货品牌、计划量。Debug「刷新采购订单状态」也曾批量覆盖采购价。

**产品目标：** 详情页刷新拆成互不污染的分面。每一次操作只做声明的那一类事；准绳永远是**已经保存的采购订单头 / 明细行**，刷新**不改**这些源字段。

本需求**不是**采购订单列表右上角或搜索栏的列表重查，也不是浏览器 F5。

---

## 2. 入口与交互

| 入口 | 文案 | 确认 |
|------|------|------|
| 详情页头主按钮 | **刷新状态** | 信息框：不改供应商、型号、品牌、数量、单价 |
| 主按钮右侧 ▾ | 刷新供应商 / 物料型号 / 品牌 / 数量 / 单价 | 供应商走预检；有已完结时警告列出单据。型号、品牌、数量、单价为警告框；若预检发现已完结，须再次明确确认 |

- 取消确认不发请求。
- 成功后弹结果：计数、关键旧→新、单价分面的进项/已付超额警告。
- 无更新时提示「无更新数据」。
- 列表页、采购订单明细列表页的「刷新」不在本需求范围。

---

## 3. 总原则

1. **源字段只读：** 刷新不改本单已保存的供应商 ID、物料型号、品牌、数量、单价。要改源字段须先编辑并保存。
2. **分面隔离：** 某一分面不得改写其它分面负责的下游字段（见 §5）。
3. **保存 ≠ 刷新库存分堆：** 保存明细仍可按业务事件对齐到货单价/品牌；**库存分堆键不随保存改写**，须显式「刷新物料型号 / 刷新品牌」。
4. **数量 / 单价会顺带刷新状态；刷新状态绝不回写型号、品牌、数量、单价。**
5. **分批到货不得自动扩成整单。**
6. **无新权限码、无新迁移。**

---

## 4. 分面需求

### 4.1 刷新状态

按已经发生的到货、入库、付款、进项事实，重算本单各行状态、扩展进度、到货通知状态、销售行利润（读当前已落库采购价）、采购申请、单头主状态 / 财务状态。状态可以下调。

**不得改：** 供应商、型号、品牌、数量、单价；请款/付款流水；进项票面。

### 4.2 刷新供应商

用当前供应商档案更新本单名称，并同步下游。完结门控与采购参数「分面刷新 → 刷新供应商」相同：关则已完结且供应商不一致整面拦住；开则列出已完结单据，确认后才覆盖。审核通过后普通采购员不可用；采购脱敏不可用。

**不得改：** 采购价、品牌、数量。

编辑页把供应商 A 改成 B 再保存，走原来的换供应商保存，**不是**详情下拉「刷新供应商」。未保存时页顶只预检提醒。保存时再预检：不能换则「当前无法保存供应商资料」，整单不保存；能换则确认「刷新并保存」。参数默认关时，已完结且供应商仍为旧值则阻断。参数开时编辑确认框仍是「刷新并保存」，不套详情那套「列出已完结再点确定」。主状态不因换供应商回退。

### 4.3 刷新物料型号 / 刷新品牌

把后续环节记下的型号或品牌改成与本单当前行一致。刷新型号只改型号类字段，刷新品牌只改品牌类字段。

| 环节 | 要改 |
|------|------|
| 到货通知、入库、装箱、报关 | 对应型号或品牌快照 |
| 库存明细 | 对应型号或品牌（分堆键） |
| 库存汇总 | 按新型号+品牌重新分堆：已有则合并，没有则新建；旧堆若已无在库明细且数量为 0 则从库存中去掉（结果「删除空汇总」= 去掉几条空汇总行，不是删库存数量） |

同时重算备货可用量。已入库、已装箱仍可覆盖（采购参数默认允许）；参数关闭则整面拦住。覆盖前须确认列出的已完结单据。

**不得改：** 报关申报单价 / HS、入库出库实绩数量、采购价、另一侧身份字段（刷新型号不改品牌，反之亦然）、**库存明细编号**（拣货/装箱已引用的编号保持不变）。

仅大小写或首尾空格不同：仍算同一堆，只对齐汇总行展示文案。

### 4.4 刷新数量

按本单当前数量对齐到货**计划量**：仅当「这一行只有一批到货、且计划量大于采购数量」时收缩计划量，并按通知**现有单价**重算通知金额；然后重算总额、利润、状态。到货已入库时按采购参数：关则拦住，开则列出后确认。

**不得改：** 入库 / 库存 / 出库 / 付款 / 质检 / 报关实绩数量；品牌；单价。采购数量小于已收+在途则失败。分批到货各批次数量不变。

### 4.5 刷新单价

按本单当前采购单价覆盖到货、入库、库存、出库上的采购价快照（含已入库、已请款、已核销、已进项匹配），再重算总额、利润、状态。无「单据状态」门控；已完结节点按采购参数列出并确认（默认允许）。

**不得改：** 请款/付款流水、进项票面、报关申报单价、销售价、原始采购价、品牌、型号、到货分批数量。

降价后已付或已进项匹配大于新总额：**不拒绝**，结果里警告，由操作人核对。刷新本身不提交核销；之后用新待付 / 新待匹配去做核销或匹配时，仍须足额成功、略超拒绝。

兼容旧接口「刷新明细扩展」：行为等同本分面。

---

## 5. 分面互不污染（强制）

| 操作 | 禁止发生 |
|------|----------|
| 刷新状态 | 到货单价 / 品牌 / 型号 / 计划量被改写 |
| 刷新品牌 | 采购价、数量、型号被改写；库存明细编号被改写 |
| 刷新物料型号 | 品牌、采购价、数量被改写；库存明细编号被改写 |
| 刷新数量 | 入库/库存/出库实绩数量、品牌、单价被改写 |
| 刷新单价 | 品牌、型号、到货分批数量被改写 |
| 刷新供应商 | 采购价、品牌、数量被改写 |

---

## 6. 权限

| 分面 | 谁可以 |
|------|--------|
| 状态 / 型号 / 品牌 / 数量 / 单价 | 采购订单维护（写）+ 本单数据范围 |
| 供应商 | 与换供应商相同：审核前可维护；审核后须系统管理员 / 采购总监 / 换供应商授权；采购金额脱敏不可 |

无本单数据范围：任一操作失败，下游不变。金额脱敏仍可刷新状态/单价，金额列可为「—」，结果弹窗仍可出现计数和警告。

## 7. 本版不做 / 已做补加

**本版不做**

- 「刷新全部」（按供应商 → 型号 → 品牌 → 数量 → 单价 → 状态一次跑完）
- 列表页 / 明细列表页的列表重查按钮（与本需求无关）

**已做补加**（相对「只拆六分面」；明细见 [分期实施](../../../实现方案/采购订单分面刷新.md)）

- 采购参数「分面刷新」五个开关；已完结须预检列出、确认后才覆盖。刷新状态不走该门控。
- 供应商默认不允许覆盖已完结（沿用现网）。要允许：参数管理 → 采购参数 → 分面刷新 → 打开「刷新供应商」并保存；详情仍须确认列出的单据。
- 刷新型号 / 品牌换堆后，空旧库存汇总从库存中去掉。结果「删除空汇总」= 去掉了几条空汇总行，不是删库存数量。

## 8. 验收要点

- 详情主按钮为「刷新状态」，下拉六项（供应商按权限显示）。
- 各分面 Network：`POST /api/v1/purchase-orders/{id}/refresh`，`facet` 分别为 `status|vendor|pn|brand|qty|price`；非状态先 `POST …/refresh/preview`。有已完结时确认框列出单据，确定后 body 带 `confirmCompleted=true`。
- 采购参数「分面刷新」五个开关：供应商默认关，其余默认开。关则整面阻断；开则确认后覆盖。
- Debug「刷新采购订单状态」只重算状态，不再覆盖采购价。
- 刷新型号/品牌后库存中心分堆与备货可用量按新键对齐；旧堆无明细则去掉（结果「删除空汇总」）；库存明细编号不变。
- 编辑页换供应商保存不走详情 `confirmCompleted`；参数关时已完结仍不能保存。
- 完整步骤见测试对照；单价金额边界见 [下游采购价刷新对照](../../../QA/采购/采购订单下游采购价刷新-测试对照说明.md)。
