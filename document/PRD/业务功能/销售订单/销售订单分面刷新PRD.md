## 1. 背景与问题

业务员改已保存的销售明细（型号、品牌、数量、单价）或下游单据事实变化后，需要把**派生结果**对齐到本单，但不能一次把所有下游字段都改掉。

现网把「重算状态」和「覆盖销售价」缠在一起：详情一个「刷新」会顺带改价；保存/出库等业务事件走的 Recalculate 还会收缩超量出库通知。Debug「刷新销售订单状态」也走同一接口，会批量覆盖销售价。刷新客户已有独立下拉，完结门控只有一个布尔开关。

**产品目标：** 详情页刷新拆成互不污染的分面（镜像采购订单分面刷新）。每一次操作只做声明的那一类事；准绳永远是**已经保存的销售订单头 / 明细行**，刷新**不改**这些源字段。

本需求**不是**销售订单列表右上角或搜索栏的列表重查，也不是浏览器 F5。

---

## 2. 入口与交互

| 入口 | 文案 | 确认 |
|------|------|------|
| 详情页头主按钮 | **刷新状态** | 信息框：不改客户、型号、品牌、数量、单价 |
| 主按钮右侧 ▾ | 刷新客户 / 物料型号 / 品牌 / 数量 / 单价 | 客户走现网预检；有已完结且将覆盖时警告列出单据。型号、品牌、数量、单价为警告框；若预检发现已完结，须明确确认 |

- 取消确认不发执行请求（预检可以已发出）。
- 成功后弹结果：计数、关键旧→新、单价分面的应收超额警告。
- 无更新时提示「无更新数据」。
- 列表页、销售订单明细列表页的「刷新」不在本需求范围。

---

## 3. 总原则

1. **源字段只读：** 刷新不改本单已保存的客户 ID、物料型号、客户料号、品牌、客户品牌、数量、单价。要改源字段须先编辑并保存。
2. **分面隔离：** 某一分面不得改写其它分面负责的下游字段（见 §5）。
3. **销售身份 ≠ 库存分堆：** 库存分桶键是采购型号/品牌 + 销售明细 ID。销售刷新型号 / 品牌**不**换库存堆、不改库存明细编号、不重算备货可用量。备货分堆仍归采购订单「刷新物料型号 / 刷新品牌」。
4. **数量 / 单价会顺带刷新状态；刷新状态绝不回写型号、品牌、数量、单价。**
5. **分批出库通知不得自动扩成整单。**
6. **已出库通知的申请数量不收缩**（与采购「可收缩已入库到货计划量」不同）。
7. **无新权限码、无新迁移。** 刷新客户仍用销售订单维护（写），不新造换客户权限。

## 4. 分面需求

### 4.1 刷新状态

按已经发生的出库、收款、开票事实，重算本单各行扩展进度、利润、出库通知占用，以及单头主状态。状态可以下调。

**不得改：** 客户、型号、品牌、数量、单价；出库通知计划量；收款/核销流水；销项票面。

### 4.2 刷新客户

用当前客户档案更新本单名称，并同步下游。完结门控与销售参数「分面刷新 → 刷新客户」相同：关则已完结且客户不一致整面拦住；开则列出**将覆盖**的已完结出库通知/装箱/出库单，确认后才覆盖。已核销应收**客户主键**仍不改、不进「将覆盖」列表，名称快照可对齐；已开票销项仍不改客户字段。

**不得改：** 销售价、品牌、数量。

编辑页把客户 A 改成 B 再保存，走原来的换客户保存，**不是**详情下拉「刷新客户」。未保存时页顶只预检提醒。保存时再预检：不能换则整单不保存；能换则确认「刷新并保存」。参数默认关时，已完结且客户仍为旧值则阻断。参数开时编辑确认框仍是「刷新并保存」，不套详情那套「列出已完结再点确定」。

### 4.3 刷新物料型号 / 刷新品牌

把后续销售环节记下的型号或品牌改成与本单当前行一致。刷新型号只改型号类字段（含客户料号），刷新品牌只改品牌类字段（含客户品牌）。

| 环节 | 型号 | 品牌 |
|------|------|------|
| 出库通知 | 申请型号 ← 销售行型号 | 申请品牌 ← 销售行品牌 |
| 装箱明细 | 型号 ← 销售行型号 | 品牌 ← 销售行品牌 |
| 装箱扩展 | 客户料号 ← 销售行客户料号 | 客户品牌 ← 销售行客户品牌 |
| 应收 | 型号 ← 销售行型号 | 品牌 ← 销售行品牌 |

装箱主表型号/品牌创建时取自销售行（经出库通知快照）。采购订单分面刷新也会写同一列（按库存反查采购行）。**后执行的一方覆盖。**

**不得改：** 采购订单型号/品牌、库存采购型号/品牌、报关采购型号/品牌、报关申报单价 / HS、入库出库实绩数量、销售价、另一侧身份字段、**库存明细编号**、库存分堆。

已出库、已装箱、已核销/已开票应收的展示快照默认可覆盖（参数默认允许）；参数关闭则整面拦住。覆盖前须确认列出的已完结单据。

### 4.4 刷新数量

按本单当前数量对齐出库通知**计划量**：仅当「这一行只有一条有效出库通知、且通知数量大于销售数量、且该通知尚未出库」时收缩通知数量；然后重算总额、利润、状态。行上若存在已出库通知，按销售参数：关则拦住，开则列出后确认（确认后仍**不改**已出库通知的数量）。

**不得改：** 实出 / 库存 / 装箱 / 报关实绩数量；品牌；单价。销售数量小于已实出或小于有效通知合计则失败。分批通知各批次数量不变（不扩成整单）。

### 4.5 刷新单价

按本单当前销售单价覆盖装箱、库存、出库、应收上的销售价快照（含已出库、已核销、已开票），再重算总额、利润、状态。已完结节点按销售参数列出并确认（默认允许）。

**不得改：** 收款 / 预收核销流水金额、销项发票票面、报关申报单价、采购价 / 入库成本、品牌、型号、出库通知分批数量。

降价后已核销或已开票匹配大于新总额：**不拒绝**，结果里警告，由操作人核对。刷新本身不提交核销；之后用新待核销 / 新待匹配去做核销或匹配时，仍须足额成功、略超拒绝。

兼容旧接口「刷新明细扩展」：行为等同本分面。

---

## 5. 分面互不污染（强制）

| 操作 | 禁止发生 |
|------|----------|
| 刷新状态 | 出库通知计划量 / 型号 / 品牌、装箱型号/品牌、下游销售价被改写 |
| 刷新品牌 | 销售价、数量、型号被改写；库存明细编号被改写 |
| 刷新物料型号 | 品牌、销售价、数量被改写；库存明细编号被改写 |
| 刷新数量 | 实出/库存/装箱实绩数量、品牌、单价被改写；已出库通知数量被改写 |
| 刷新单价 | 品牌、型号、出库通知分批数量被改写 |
| 刷新客户 | 销售价、品牌、数量被改写；已核销应收客户主键 / 已开票销项的客户被改写 |

---

## 6. 权限

| 分面 | 谁可以 |
|------|--------|
| 全部六项 | 销售订单维护（写）+ 本单数据范围 |

无本单数据范围：任一操作失败，下游不变。金额脱敏仍可刷新状态/单价，金额列可为「—」，结果弹窗仍可出现计数和警告。

无新权限码。刷新客户审核后也不另要总监权限（与采购「刷新供应商」不同，沿用现网）。

---

## 7. 本版不做

- 「刷新全部」（按客户 → 型号 → 品牌 → 数量 → 单价 → 状态一次跑完）
- 列表页 / 明细列表页的列表重查按钮（与本需求无关）
- 库存换堆 / 新建汇总 / 删除空汇总（销售身份不是分桶键）
- 新权限码、新迁移
- 刷新型号/品牌回写采购订单或报关采购身份

---

## 8. 验收要点

- 详情主按钮为「刷新状态」，下拉五项（客户始终显示，权限与现网刷新客户相同）。
- 各分面 Network：`POST /api/v1/sales-orders/{id}/refresh`，`facet` 分别为 `status|customer|pn|brand|qty|price`；非状态先预检。客户可走现网 `sync-downstream-customer/preview`。有已完结且将覆盖时确认框列出单据，确定后 body 带 `confirmCompleted=true`。
- 销售参数「分面刷新」五个开关：客户默认关，其余默认开。关则整面阻断；开则确认后覆盖。刷新状态不看开关。
- Debug「刷新销售订单状态」只重算状态，不再覆盖销售价。
- 刷新型号/品牌后装箱主表与出库通知、应收展示快照对齐；库存分堆与库存明细编号不变。
- 编辑页换客户保存不走详情 `confirmCompleted`；参数关时已完结仍不能保存。
- 完整步骤见测试对照；单价金额边界见 [下游销售价刷新对照](../../../QA/销售/销售订单下游销售价刷新-测试对照说明.md)。
