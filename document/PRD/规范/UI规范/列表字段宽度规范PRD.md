# 列表字段宽度规范 PRD（初版）

## 1. 文档目的

统一系统中列表页（`el-table` / `CrmDataTable`）字段宽度设置方式，提升：

- 可读性（关键字段不被压缩）
- 一致性（不同页面视觉规则统一）
- 可维护性（新增列表有明确参照）

本规范为第一版，先落地可执行规则，后续根据业务与分辨率再优化。

---

## 2. 适用范围

- 前端所有数据列表页
- 组件：`Element Plus el-table-column` 为主
- 典型页面：审批管理、客户列表、供应商列表、订单列表、财务单据列表

---

## 3. 宽度设置规则（核心）

### 3.1 基本规则

1. **固定内容列使用 `width`**
   - 如：状态、金额、时间、操作按钮
2. **可变长度内容列使用 `min-width`**
   - 如：名称、编号、事项描述、备注
3. **超长文本列必须开启 `show-overflow-tooltip`**
4. **每张表至少 1~2 个“弹性列”**
   - 使用 `min-width` 吸收剩余空间，避免整体拥挤

### 3.2 不推荐做法

- 所有列都固定 `width`（在小屏会挤压严重）
- 关键业务列不设宽度（导致被压缩不可读）
- 长文本列不加 tooltip（信息丢失）
- **表头列标题被省略号截断**（如 `入库...`、`上期...`）——见 **§3.3**

### 3.3 列标题完整显示（强制）

**原则：** 列表**表头列标题**须在一行内**完整展示**；**禁止**以 `…` 省略表头文案作为默认实现。表体单元格可对过长内容使用省略号 + Tooltip；**表头不适用「省略号兜底」**。

**配置要求**（`CrmTableColumnDef` / `el-table-column`）：

1. 定义列时，`minWidth`（固定宽列还须 `width`）须 **≥ 该列 `label` 全文所需宽度**；以 **zh-CN 列名** 为准，双语时取较长文案估算。
2. **推荐：** `minWidth: estimateListColumnHeaderMinWidth(t('模块.columns.xxx'), { align: 'right' })`  
   工具：`CRM.Web/src/utils/listColumnHeaderWidth.ts`（《列表字段宽度规范》§3.3）。
3. 同表多列时若横向空间不足：优先保证**表头完整**；可启用横向滚动或压缩**低优先级弹性列**，**不得**仅收窄导致表头截断。
4. 调整默认列宽或 i18n 列名后，视情况递增 `column-layout-key` 版本（如 `v1` → `v2`），避免 localStorage 中旧窄宽覆盖新默认。

**推荐下限（px，12px 表头字 + th 内边距）：**

| 标题形态 | `minWidth` 建议 |
|----------|----------------|
| 4 个汉字（如「入库数量」「结余数量」） | ≥ **120** |
| 4 汉字 + `(USD)`（如「上期金额(USD)」） | ≥ **130** |
| 6～8 汉字或含英文后缀更长标题 | ≥ **150～180**，按字数递增 |
| 「操作」 | **90**（详见《列表操作列规范》） |

**自检（新建/改版列表完成前必做）：**

- [ ] 1920、1366 宽下目视检查**全部列标题**无 `…`
- [ ] zh-CN 列名变更后已复核 `minWidth` / `width`
- [ ] 默认列宽变更时已评估 `column-layout-key` 是否升版

**参考实现：** `FinanceVendorAccumulatedList.vue`、`FinanceStockAccumulatedItemList.vue`（滚存模块数量列 `minWidth: 120`）。

### 3.4 用户列宽记忆（已实现）

适用于已接入 `column-layout-key` + 声明式 `columns` 的 `CrmDataTable`。

1. **按列 `key` 记忆**，与列顺序/显隐写在同一 localStorage 键（`columnWidths`）。未拖过的列不写，继续用本节默认宽。
2. **新版本插入一列**：旧列宽度仍有效；新列用代码默认宽。不要因此升 `column-layout-key`。仅当默认宽/列名变更需要作废用户记忆时，才升版本号（§3.3 第 4 点）。
3. **不记忆**：勾选列、操作列、扩展列（扩展列走专用全局键）。
4. **恢复默认**（列设置抽屉）同时清除用户列宽。
5. 无 `column-layout-key` 的插槽表不记。

细则见 [《业务列表规范》](./业务列表规范.md) **§1.7.1**。

### 3.5 表头列界指引与热区（已实现）

与默认列宽（本章）互补：用户拖表头调宽时的**可见指引与命中区**。交互细则以 [《业务列表规范》](./业务列表规范.md) **§1.7.2** 为准。

| 项 | 值 |
|----|-----|
| 竖线颜色 | **`#CED1D1`** |
| 竖线宽度 | **2px** |
| 竖线高度 | 表头高度减去上下各 **10px**（不顶满 `th`） |
| 出现位置 | 仅表头；表体不加列间竖线 |
| 热区 | 列界左侧 **16px**（覆盖 Element Plus 默认 8px），不侵入下一列左缘控件 |
| 组件 | `CrmDataTable`（`.crm-col-resize-hit` / `.crm-col-resize-hit__line`） |

**验收：** 鼠标在表头移动时能看到最近列界；列界附近易于拖宽；拖完刷新后普通列宽度按 §3.4 保持。

## 4. 字段类型与推荐宽度

> 单位均为 px；以下为推荐区间，可按业务微调。

1. **状态/标签列**
   - `width: 160`
2. **金额列**
   - `width: 160`
3. **日期时间列**
   - `width: 160`
4. **操作列（按钮）**
   - `width: 200`
5. **单据编号列**
   - `min-width: 160`
6. **客户/供应商名称列**
   - `min-width: 200`
7. **事项描述/备注列（长文本）**
   - `min-width: 弹性剩余空间` + `show-overflow-tooltip`

---

## 5. 审批管理页（当前建议配置）

适配目标：1920 宽主流办公屏，兼容 1366。

1. 业务类型：`width: 160`
2. 单据编号：`min-width: 160`
3. 客户/供应商：`min-width: 200`
4. 事项描述：`min-width: 弹性剩余空间
5. 金额：`width: 160`
6. 提交时间：`width: 160`
7. 操作：`width: 200`

---

## 6. 实施要求

1. 新增列表页时，必须按本规范选择 `width/min-width`。
2. **表头列标题须完整显示**（**§3.3 强制**）；不得出现表头 `…` 省略。
3. 长文本列默认加 `show-overflow-tooltip`。
4. 调整已有页面时，优先保障“核心业务字段”可见性。
5. 若页面有横向滚动，优先压缩低优先级列，不压缩核心列与**表头可读性**。

---

## 7. 验收标准

1. **全部列标题**在常见分辨率（1920、1366）下完整显示，无表头 `…` 截断。
2. 关键字段在常见分辨率下不出现明显截断（或有 tooltip 兜底）。
3. 同类页面字段宽度风格一致（金额/时间/操作列一致化）。
4. 页面在不同数据长度下无明显错位、挤压、按钮换行异常。
5. 表头拖宽：列界指引符合 **§3.5**；用户拖过的普通列宽刷新后仍在（**§3.4**）。

---

## 8. 后续优化方向（下一阶段）

1. 建立“字段类型 -> 默认宽度”映射表（组件级复用）。
2. 按业务模块沉淀列模板（审批/客户/订单/财务）。
3. 增加分辨率断点策略（1366、1600、1920）。
4. 支持用户列宽记忆与个性化（**已实现**：本机、按 `column-layout-key`；见 **§3.4**）。账号级同步仍为后续可选。
