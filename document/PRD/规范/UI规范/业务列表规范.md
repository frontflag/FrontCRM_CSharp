# 业务列表规范

本规范沉淀所有「业务列表页」的通用 UI 与交互约定，作为新页面开发与代码评审的统一基线。

## 1. 列表表头（列设置：显示/隐藏/顺序/持久化）

### 1.1 目标

- **用户可自定义列顺序**（拖拽）
- **用户可自定义列显示/隐藏**（勾选）
- **用户拖表头调过的列宽需持久化**（按列 `key`；见 **§1.7.1**）
- **设置需持久化**，下次进入仍生效
- **可一键恢复默认**（含列宽）

### 1.2 入口位置（重要）

- **入口不占用列表上方额外一行**（避免浪费纵向空间）。
- 入口放在**列表底栏左侧**（与分页同一行），并与右侧分页控件**顶部对齐**。
- 入口按钮仅显示**图标**（齿轮），不显示“列设置”文字；“列设置”通过 **Tip/Tooltip** 展示。
- **详情页 / 选项卡内嵌表 / 无底部分页** 时，底栏语义仍指 **表体下方** 一行，不得挪到表头或 Tabs 行；见 **§2.6**。

> 参考实现：`CRM.Web/src/views/RFQ/RFQItemList.vue`（需求明细）

### 1.3 底栏布局规则（间隔区）

- “列设置”按钮与右侧**空白间隔区域**（Spacer）之间，**可插入「行高密度」切换**（见第 2 章）；插入时建议从左到右为：**列设置（齿轮）→ 行高密度 → Spacer → 其他按钮**。
- Spacer 右侧开始摆放其余底栏按钮（与分页同排对齐约定不变）。
- “复选篮子”入口与相关按钮按同一逻辑放置（从 Spacer 右侧开始）。

> 参考实现：`RFQItemList.vue` 的 `.pagination-wrapper` / `.list-footer-left` / `.list-footer-spacer`（与客户列表 `CustomerList.vue` 底栏类名一致）；行高密度与列设置同排见 `CustomerList.vue` 底栏。

#### 1.3.1 复选篮子旁主操作按钮（批量主动作）

适用于带 **复选篮子** 的列表页（见 **[列表复选篮子批量操作规范 PRD](./列表复选篮子批量操作规范PRD.md)**）：在 **「复选篮子」**、**「清空篮子」** 之后、**分页器左侧同一行**，放置依赖篮子数据的 **页面级批量主按钮**（如「生成销售订单」「批量申请采购」）。

| 项目 | 约定 |
|------|------|
| **DOM** | 原生 **`<button type="button">`**，与搜索区 **`btn-primary` / `btn-ghost`** 同一套视觉体系；**不用** `el-button` 承载实心主色块（避免与 Element Plus 默认主题冲突）。 |
| **类名** | **`btn-primary btn-sm basket-batch-purchase-btn`**（后一类名表示「篮子旁批量主按钮」语义，**不限于采购**，其它批量动作复用同一修饰类即可）。 |
| **尺寸** | **`btn-sm`**：较小内边距（如 **6px 12px**）、**`font-size: 12px`**，与相邻 **`basket-open-btn` / `basket-clear-btn`**（`link` 链式按钮）体量协调。 |
| **间距** | **`basket-batch-purchase-btn`** 设 **`margin-left: 10px`**，与「清空篮子」保持固定间距。 |
| **字距与悬停** | **不设** 部分列表页在通用 **`btn-primary`** 上使用的 **`letter-spacing: 0.5px`**；**悬停**不做 **上移（translateY）**、**外扩阴影**，与 **`SalesOrderItemList.vue`** 底栏批量按钮一致，避免底栏行动点过于抢眼。 |
| **图标（可选）** | 文案左侧可加 **`el-icon`**（如 **`Document`**）；异步进行中可用 **`Loading`** 旋转替代，正文可配合 **「…」** 或与 PRD 一致的加载文案。 |
| **禁用** | 依赖业务：`n === 0`、无权、前置校验中等；沿用 **`btn-primary:disabled`**（透明度、`cursor: not-allowed`）。 |

**参考实现：**

- `CRM.Web/src/views/RFQ/SalesOrderItemList.vue`（「批量申请采购」）
- `CRM.Web/src/views/RFQ/QuoteList.vue`（「生成销售订单」）

**说明：** 若批量主动作放在 **页眉右侧**（如需求明细「批量报价」），仍用 **`btn-primary`** 体系即可，**不要求** `basket-batch-purchase-btn`；页眉场景可与产品约定是否使用 **`btn-sm`**。

### 1.4 列设置交互（抽屉）

- 点击齿轮打开右侧抽屉「列显示与顺序」。
- 抽屉内：
  - 勾选控制显示/隐藏
  - 拖拽控制顺序（仅对“中间列”生效）
  - “恢复默认”一键重置为页面初始列状态（顺序、显隐、**用户拖过的列宽**）
- 文案提示需说明：设置保存在本机（localStorage），下次打开仍有效。拖表头调列宽同样记住。

### 1.5 固定列与不可配置列

- **勾选列**（`type=selection`）必须固定在最前（pinned start），且 **不可隐藏**，**不记用户列宽**。
- **操作列**（右侧固定列，通常 `fixed='right'` 且 `class-name='op-col'`）必须固定在最后（pinned end），且 **不可隐藏**、**不可拖拽排序**，**不记用户列宽**（列宽由展开/收起规范控制）。
- 固定在前/后的列不参与“中间列”的拖拽排序（避免与固定列逻辑冲突）。

### 1.5.1 与《列表操作列规范》（含「操作」列时必循）

- **业务页面**（见 **[《业务页面规范》](./业务页面规范.md)** 适用范围）中，**凡含行级「操作」列** 的列表或详情内嵌表（列头可为「操作」或仅 `<`/`>` 等该专篇允许形态；语义为末列固定操作区且通常 **`op-col`** / **`fixed='right'`**），该列的 **列头切换、列宽、展开/收起、行内按钮与 `...` 菜单等** 须完整应用 **[《列表操作列规范》](./列表操作列规范.md)**，不得仅满足本章 **§1.5** 的固定/不可隐藏要求而省略该专篇中的 **强制项**（该专篇另有 **PRD/评审豁免** 的从其规定）。
- **不含「操作」列**的列表不适用本条。

### 1.5.2 与《列表扩展列规范 PRD》（含「客户」扩展列时必循）

- 业务单据列表中启用 **「客户」扩展列** 时，须完整应用 **[《列表扩展列规范 PRD》](./列表扩展列规范PRD.md)**（**V1.1 已实现**，细则以该专篇为准）。
- **客户主档列表** `CustomerList` **不适用**扩展列。
- 扩展列在列设置抽屉中占 **一行**（一个 `key`）；子字段**不得**拆成多条可拖拽项。

### 1.6 列标题完整显示（强制）

- 凡业务列表主表（`CrmDataTable` / `el-table`），**表头列标题**须在一行内**完整展示**，**禁止**默认出现 `入库...`、`上期...` 等表头省略。
- 列宽设置、推荐下限、`estimateListColumnHeaderMinWidth` 工具与自检清单：见 **[《列表字段宽度规范 PRD》](./列表字段宽度规范PRD.md) §3.3**。
- 新建或改版列表时，完成前须做 **§3.3 自检**；调整默认 `minWidth` 后视情况递增 **`column-layout-key`** 版本，避免本机列宽记忆覆盖新默认。用户拖过的列宽记忆见 **§1.7.1** / 宽度规范 **§3.4**。

### 1.8 扩展列（Extend Column · 客户列 · 已实现）

适用于需在业务列表中查看**客户中文名 / 英文名 / 编号**、又不宜长期占三列宽度的场景。完整交互、样式、接入步骤见 **[《列表扩展列规范 PRD》](./列表扩展列规范PRD.md)**；本节为**业务列表规范内的摘要**，供评审与接入时快速对照。

#### 1.8.1 功能摘要

| 能力 | 行为 |
|------|------|
| 收起态 | 单列单行；默认显示**中文全称**；`▾` 可切换为英文名或编号 |
| 展开态 | 列头子标题与单元格均为 **中文 \| 英文 \| 编号** 三列并排 |
| 展开/收起 | 列头最左侧 **`<`（展开态，收起）** / **`>`（收起态，展开）** |
| 子列调宽 | 展开态列头子列分界处拖拽；最小宽 56px；相邻列联动 |
| 整体调宽 | `CrmDataTable` 表头列缘拖拽；展开/收起态分别记忆 |
| 持久化 | 全局键 `crm-table-extend-col:v1:global:customer`（跨列表共用） |
| 列设置 | `key: customer` 占抽屉**一行**；子字段不进抽屉 |

#### 1.8.2 组件与样式（强制复用）

不得在各列表页手写一套扩展列 UI；须使用：

| 类型 | 路径 |
|------|------|
| Composable | `CRM.Web/src/composables/useCustomerExtendColumn.ts` |
| 列头 | `CRM.Web/src/components/list/CustomerExtendColumnHeader.vue` |
| 单元格 | `CRM.Web/src/components/list/CustomerExtendCell.vue` |
| 常量 | `CRM.Web/src/constants/listCustomerExtendColumnSpec.ts` |
| 样式 | `CRM.Web/src/assets/styles/crm-unified-list.scss`（`.customer-extend-*`） |
| i18n | `common.customerExtendCol.*`（`zh-CN.ts` / `en-US.ts`） |

列定义须设 `className` / `labelClassName` 为 **`customer-extend-col`**；`prop` 建议 **`customer`**（供 `header-dragend` 识别）。

#### 1.8.3 参考接入

- **试点页面**：`CRM.Web/src/views/Inventory/StockOutList.vue`（路由 `/inventory/stock-out`）。
- 接入检查项、后端字段、脱敏约定：见扩展列 PRD **§11、§12.3**。

#### 1.8.4 与操作列的区别

| 项目 | 操作列 | 客户扩展列 |
|------|--------|------------|
| 展开态图标 | `>` | `<`（在列头**左侧**） |
| 收起态图标 | `<` | `>`（在列头**左侧**） |
| 列 class | `op-col` | `customer-extend-col` |
| 偏好存储 | 通常仅页内 state | 全局 localStorage |

### 1.6 技术约定（组件与插槽）

- 统一使用 `CrmDataTable` 承载该能力。
- 启用列设置的必要条件：
  - `column-layout-key="xxx"`：列表唯一键（建议 `模块-页面`，如 `rfq-item-list-main`）
  - `:columns="columns"`：声明式列定义
  - `:show-column-settings="false"`：关闭表格顶部入口（本规范要求入口在底栏）
- 单元格自定义渲染使用具名插槽：`#col-<key>`
- 表头自定义渲染使用具名插槽：`#col-<key>-header`
- 从外部触发打开抽屉：`dataTableRef.openColumnSettings()`

> 参考实现：
>
> - 组件：`CRM.Web/src/components/CrmDataTable.vue`
> - 持久化：`CRM.Web/src/composables/usePersistedTableColumns.ts`

### 1.7 持久化范围

- 当前实现为 **localStorage 本机持久化**：
  - 键：`crm-table-columns:v1:<columnLayoutKey>`
  - 内容：`middleOrder` + `hiddenKeys` + `columnWidths`（仅用户拖过的可记宽列）
- **换浏览器/换设备不跟随**；若需账号级同步，应另行对接后端存储（不在本规范范围内）。
- **无 `column-layout-key` 的旧插槽表**不记列顺序/显隐/列宽。

### 1.7.1 用户列宽记忆

- 在 **`CrmDataTable` 可配置模式**（有 `column-layout-key` + `columns`）下，用户拖表头调过的列按稳定 **`key`** 写入同一份存储；**不要按列序号存**。
- **只记用户拖过的列**；未拖过的列继续用代码默认 `width` / `minWidth`。
- **不记**：勾选列、操作列、扩展列（客户/供应商/报价扩展列仍走各自专用键，见 [《列表扩展列规范 PRD》](./列表扩展列规范PRD.md)）。
- **版本更新新插入一列**：旧 `key` 的宽度继续有效；新列无记录则用默认宽。改列 `key` 或升 `column-layout-key` 版本号才会让对应记忆对不上 / 整表回默认。
- 「恢复默认」同时清除 `columnWidths`。扩展列偏好**不**随本操作清除。

> 实现：`usePersistedTableColumns.ts` 的 `columnWidths`；`CrmDataTable` 统一处理 `header-dragend`，页面上为扩展列写的 `@header-dragend` 仍会转发。

### 1.7.2 表头拖宽指引与热区（已实现）

用于让用户发现「表头列缘可拖」，**不**把业务列表改回全表竖线网格。

| 项 | 约定 |
|----|------|
| 出现时机 | 鼠标在**表头**上（含固定列表头）时，高亮离指针**最近**、且允许拖宽的列界 |
| 画在哪 | **仅表头高度**；表体、单元格**不加**竖线 |
| 竖线样式 | 宽 **2px**；颜色 **`#CED1D1`**；上下各留 **10px** 空白（不顶满表头） |
| 热区 | 列界**左侧 16px**（Element Plus 默认 8px）；**不向右**侵入下一列 |
| 不可拖 | 勾选列、操作列、`resizable: false` |
| 扩展列 | 整体右缘可拖（含往左收窄）；展开态**子列**拖条优先，指针在子列手柄上时不显示本指引 |
| 下限 | 普通列跟列定义 `minWidth`；扩展列 `minWidth` 常等于当前宽（防挤窄），拖宽时**不得**把该锁当收缩下限，收起态外宽仍不低于扩展列规范（客户列 **160px**） |

实现：`CrmDataTable.vue`（`.crm-col-resize-hit`）+ `crmTableHeaderResizeGuide.ts`。拖放结束仍走 `header-dragend`（普通列写入 `columnWidths`，扩展列转发给页面 composable）。

## 2. 列表行高密度（紧密 / 适中）

用于在业务列表中切换**数据行**视觉松紧；实现以 `CrmDataTable` 为准。**表头高度不参与本功能**（表头仍走全站表格表头样式）。**未使用 `CrmDataTable` 的裸 `el-table` 不在本章约定范围内**。

### 2.1 术语与数值定义

- **行高（本规范含义）**：仅指数据格 **`td.el-table__cell` 的垂直内边距之和**，即 `padding-top` + `padding-bottom`。不改变表头 `th` 的 padding。
- **紧密（compact）**：上述垂直内边距之和为 **10px**（即上下各 **5px**，由全局变量换算）。
- **适中（medium）**：上述垂直内边距之和为 **22px**（即上下各 **11px**）。
- **水平内边距**（数据格左右 padding，与垂直独立可调）：紧密默认 **10px**（左右各 5px 量级由变量控制）、适中默认 **14px**（左右各 7px 量级由变量控制）。

全局变量与样式入口（便于统一改数）：

- `CRM.Web/src/assets/styles/variables.scss`：`$crm-list-row-density-compact-cell-padding-y-total`、`$crm-list-row-density-medium-cell-padding-y-total` 及对应 `*-padding-x`。
- `CRM.Web/src/assets/styles/crm-list-table-row-density.scss`：在 `CrmDataTable` 根节点修饰类下覆盖 **主表体与右侧固定列副本** 的 `td`，保证同列对齐。

### 2.2 默认与持久化

- **默认状态**：**紧密**（无本地记录或键无效时）。
- **持久化**：`localStorage`，键前缀 **`crm-table-row-density:v1:`**，完整键为 **`crm-table-row-density:v1:<storageKey>`**，取值 **`compact`** 或 **`medium`**。
- **storageKey 来源**：优先使用 **`column-layout-key`**（与列布局共用同一列表页唯一标识）；若无 `column-layout-key`，可显式传 **`row-density-storage-key`**。
- **按列表页独立记忆**：不同 `storageKey` 互不覆盖；用户切换后保持直至再次切换。

读写工具：`CRM.Web/src/utils/crmTableRowDensityStorage.ts`。

### 2.3 底栏入口与视觉

- **展示条件**：存在有效 `storageKey`、未将 **`show-row-density-toggle`** 设为 `false`，且页面向 **`density-toggle-anchor-el`** 传入**非空**锚点（见 2.4）时，显示两个切换入口。
- **位置**：与「列设置」**同一行、底栏左侧**；建议在列设置**右侧**紧邻排列（与 `CustomerList.vue` / `VendorList.vue` 一致）。通过 **`Teleport`** 挂到页脚占位节点（`ref` 绑定空 `span`）即可与分页、齿轮对齐。**详情页、选项卡内嵌表、无底部分页** 等场景仍须遵守同一「表下底栏左侧」语义，**禁止**把锚点放在表头上方或表格外上侧；见 **§2.6**。
- **样式**：与列设置齿轮一致——**`el-button` `link` `type="primary"`**，并加 **`list-settings-btn`** 图标按钮尺寸；两个按钮之间**无额外横向间距**（`margin`/`gap` 为 0）。
- **图标语义（当前约定）**：
  - **紧密**：**3 条横线**（表示更密）。
  - **适中**：**2 条横线**（表示相对疏）。
- **选中态**：当前模式为**主色不透明**；未选模式为**降低透明度**（muted），悬停可恢复可读。

Tooltip 文案：**「紧密」**、**「适中」**。

### 2.4 技术约定（`CrmDataTable`）

- 根节点自动增加 **`crm-items-table--density-compact`** 或 **`crm-items-table--density-medium`**，与 `crm-list-table-row-density.scss` 联动。
- 主要 props：
  - **`row-density-storage-key`**（可选）：无 `column-layout-key` 时用于持久化的独立键。
  - **`show-row-density-toggle`**：默认 `true`；设为 `false` 可隐藏底栏切换（仍按已存值渲染密度）。
  - **`density-toggle-anchor-el`**：页脚 **`HTMLElement | null`** 锚点（通常为空 `span` + `ref`）。**仅当传入非空锚点时**，底栏「紧密 / 适中」切换按钮才会通过 **Teleport** 渲染到该节点；不传或始终为 `null` 则不显示切换（行高仍按 `storageKey` 读取已保存密度应用）。
- 对外暴露（便于联调/测试）：**`rowDensity`**（ref）、**`setRowDensity('compact'|'medium')`**。

组件：`CRM.Web/src/components/CrmDataTable.vue`。

### 2.5 紧密模式下单元格内容单行化（必达）

**目标**：在 **紧密（compact）** 下，列表主表每一列的展示应尽量 **压缩为单行**——若该列在「适中」或默认结构下会把同一格内的信息拆成 **两行或多行**（例如主标题与副标题、主名称与编码上下堆叠），在紧密下 **应改为同一行内并排或连续展示**；过长内容用 **单行省略**（`text-overflow: ellipsis` + `overflow: hidden` + 父级 **`min-width: 0`**），必要时单元格或图标上提供 **`title` / Tooltip** 展示全文。

**与行高功能的关系**：`crm-list-table-row-density.scss` 只控制 **`td` 垂直/水平 padding**；**不自动**把多行 DOM 改成一行。是否单行化由 **各列表页** 在 **仅紧密态** 下通过样式或结构调整完成。

**实现约定**：

- 选择器必须挂在 **`crm-items-table--density-compact`**（由 `CrmDataTable` 根类提供）之下，使用 **`:deep(...)`** 穿透至表体单元格内层，**不得**在无前缀时全局改掉「适中」下的多行布局。
- 常用手段：容器 **`display: flex`**、`**flex-direction: row**`、`**flex-wrap: nowrap**`、子项 **`flex: 1 1 0; min-width: 0`**；副行/副文案取消 **`margin-top`** 并与主行 **`align-items: center`** 对齐；或 **`white-space: nowrap`** + **`text-overflow: ellipsis`**；多行块级文案可改为 **`display: -webkit-box; -webkit-line-clamp: 1`**（等价视觉单行）。

**例外（可不强制单行）**：

- 产品明确要求保留多行阅读的列（如备注全文、长描述预览），须在 PRD/评审中注明；若仍多行，应控制最大行数（如 `line-clamp`），避免在紧密 padding 下无限增高。
- 详情页内嵌表、弹窗/抽屉中的子表、调试页等非「标准业务列表主表」场景，按各页需求处理，**不强制**与本条完全一致。

**参考实现**（主名 + 副码/简称 两行 → 紧密下一行）：

- `CRM.Web/src/views/Customer/CustomerList.vue`：客户名称列「主名 + 状态图标」与「简称」横向并排。
- `CRM.Web/src/views/Vendor/VendorList.vue`：供应商名称列「主名 + 状态图标」与「编号」横向并排。

**新列表页自检**：接入行高密度后，在 **紧密** 下逐列检查是否存在「同一格内仍明显多行堆叠」；若有，按本条在 **`crm-items-table--density-compact`** 下补齐单行化样式或模板结构。

### 2.6 无底部分页与详情/选项卡内嵌表：底栏与「行高密度」锚点（防错位）

为避免实现时仅满足「传入非空 `HTMLElement`」而 **视觉上** 把行高密度（及列设置）放到 **表头附近、表格外上侧、Tabs 行右侧** 等与全页业务列表不一致的位置，本条对 **§1.2、§2.3、§4.2** 作补充说明。

- **语义位置（评审依据）**：凡使用 **`CrmDataTable`** 并传入 **`density-toggle-anchor-el`**（和/或需在底栏展示的 **列设置** 齿轮），**「列表底栏左侧」** 指 **该表数据区域（表体）下方** 的底栏行——与整页是否有标题区、筛选区、**Tabs** 外层无关；与 **`Teleport` 在 DOM 中的挂载深度** 无关。**自检与 Code Review 以用户看到的相对表格的位置为准**。
- **禁止**：将 **`density-toggle-anchor-el`** 绑在 **表格外侧上方**、**表头右上角**、**与 Tabs 同一行且靠内容区右缘**、**页面顶栏** 等位置。`Teleport` 只把按钮渲染进锚点节点，**不改变**「应在表下底栏左侧」的产品与规范语义。
- **无分页器时**（如 **详情页**「订单明细」、**§4.1** 豁免分页的弹窗/抽屉子表）：仍须使用与全页列表一致的 **`.pagination-wrapper` + `.list-footer-left` + `.list-footer-spacer`**（或与项目已对齐的等价类名）构成 **底栏行**；**左侧** 顺序仍为 **（可选）列设置（齿轮）→ 行高密度锚点 → Spacer**；右侧可无 **`el-pagination`**，可用 **`margin-left: auto`** 的空占位保持左侧簇贴左。
- **Vue 实现提示**：`CrmDataTable` 首次渲染时锚点 DOM 应已存在。若模板书写顺序为「表在上、底栏在下」，可将 **底栏 DOM 写在表格之前**，外层使用 **`display: flex; flex-direction: column-reverse`**，使 **锚点先挂载**、**视觉上仍为表在上、底栏在下**。（参考：`CRM.Web/src/views/RFQ/PurchaseOrderDetail.vue` 采购订单详情「订单明细」。）

## 3. 列表单元格：数量、金额与币别、日期时间（全列表对齐）

以下约定由 **报价列表**（`QuoteList.vue`）、**需求明细底部采购报价子表**（`RFQItemList.vue` 内嵌 `CrmDataTable`）先行落地，并作为 **全部业务列表**（主表及列表页内嵌子表）中同类展示的 **默认 UI 基线**。若某列表 PRD 要求例外，须在 PRD 与评审中显式注明。

### 3.1 金额与币别（同一单元格内）

- **文本结构**、**枚举 → 三位字母**、**币别字母色值**、**金额拆段（整数 / 小数点及小数）与 `formatToParts` 要求** 等，以专篇 **[金额与币别代码显示范式](./金额与币别代码显示范式.md)** 为准，本列表规范不重复定义色表与禁止项（如禁止前置 `¥`/`$`）。
- **在列表（含内嵌表）中落地时**还须满足：
  - **金额数字**：`font-weight: 700`；**币别三位字母**：`font-weight: 400`（不加粗）。
  - **数量与金额数字字色（亮色主题）**：统一为 **`#27292C`**；暗色主题下与表体可读性一致，当前全局实现为改用语义色 **`$text-primary`**（见 `crm-quote-tier-dock.scss` 中 `html[data-theme='dark']` 覆盖）。
  - **阶梯/多行单价**：金额整数段与小数段均参与上述字色与加粗；拆分实现须使用 **`Intl.NumberFormat(...).formatToParts`**，与范式文档一致。
- **全局样式入口**：`CRM.Web/src/assets/styles/crm-quote-tier-dock.scss`（由 `main.scss` 引入）。内嵌子表若因 `scoped` 无法命中 DOM，应在该文件内用 **表根类名（如 `.dock-quote-table`）下的后代选择器** 编写规则，避免在页面内复制一套色值。

### 3.2 数量（与金额同列或相邻列的阶梯行）

- **纯数量**（无「单价行」修饰类时）：**`font-weight: 700`**，字色与 **3.1** 金额数字一致（亮色 `#27292C` / 暗色按全局覆盖）。
- 与「单价（阶梯）」同表展示时，用类名区分「仅数量行」与「金额+币别行」（当前实现：数量行为 `.dock-quote-tier-line`，单价行为 `.dock-quote-tier-line.dock-tier-price-line`），避免币别字重被父级错误继承。

### 3.3 日期与时间（列表中的创建时间、报价时间等）

- **日期年分位**：业务若要求压缩年份，创建类时间列可采用 **两位年 `YY-MM-DD`**（与配置展示时区一致），工具函数见 **`CRM.Web/src/utils/displayDateTime.ts`**：带时分为 **`formatDisplayDateTime2DigitYear`** / **`formatDisplayDateTime2DigitYearParts`**；仅日期为 **`formatDisplayDate2DigitYear`**。
- **同一格内「日期 + 时间」排版**：
  - 使用 **`formatDisplayDateTime2DigitYearParts`** 得到 `{ date, time }`，模板内分为两个 **`span`**（或等价行内结构），**禁止**拼接成单一字符串导致边界数字粘连（如 `…16` 与 `09…` 连成 `…1609…`）。
  - 外层容器使用 **`display: inline-flex`**、**`align-items: baseline`**、**`gap: 6px`**（或与设计稿一致的固定间距），保证 **日期与时间之间必有可视间隔**；当前全局类名：**`.crm-quote-create-time`**、**`.crm-quote-create-time__ymd`**、**`.crm-quote-create-time__hm`**（样式定义于 **`crm-quote-tier-dock.scss`**，**`QuoteList`** 与 **需求明细采购报价 dock** 共用）。
- **字色**：**日期段** 继承或与表体主数字色一致；**时分段** 使用 **`#646776`**（类 **`.crm-quote-create-time__hm`**）。暗色主题若对比不足，可在同一 SCSS 文件中按主题增加覆盖（与产品确认后写入本文档「变更记录」）。

### 3.4 新列表页自检（数量 / 金额 / 日期列）

- 金额列是否满足范式（结构、字重、币别色、字色与拆段实现）。
- 相邻数量列字重、字色是否与金额数字一致。
- 两位年 + 分段的创建时间是否出现 **日期与时间粘连**；`gap` 是否在 **嵌入表** 中仍生效。
- **列标题**是否在 1920 / 1366 宽下**完整显示**（无表头 `…`）；见 **[《列表字段宽度规范 PRD》](./列表字段宽度规范PRD.md) §3.3** 与 **§1.6**。
- 销售/采购主单或明细列表：主单为**取消**时是否整行弱化（见 **§3.5**）；**审核失败**不得套用取消行样式。

### 3.5 主单取消行（整行弱化）

销售订单、采购订单及其明细列表：当**主单**状态为**取消**时，列表行文字弱化（浅灰），便于一眼区分已作废单据。

实现与代码索引：[业务列表取消行样式-设计与实现](../../../System/系统/业务列表取消行样式-设计与实现.md)。QA：[业务列表取消行样式-测试对照说明](../../../QA/系统/业务列表取消行样式-测试对照说明.md)。

| 项目 | 约定 |
|------|------|
| 判定 | **只看主单取消**（状态码 `-2`）。主单列表读行上的主状态；明细列表读主单状态字段 `orderStatus`（即使明细仍是已确认等）。**审核失败（`-1`）不变灰。** |
| 落地页 | 销售订单 `/sales-orders`、采购订单 `/purchase-orders`、销售订单明细 `/sales-order-items`、采购订单明细 `/purchase-order-items`。 |
| 视觉 | 共用行 class **`list-row--cancelled`**（`CRM.Web/src/utils/listCancelledRow.ts`）。样式在 **`crm-unified-list.scss`**。整行主文字、单号链接、金额与币别色改为 **`$text-muted`**。 |
| 状态标签 | **`el-tag` 保持原色**（仍能认出「取消」）。操作列按钮也不套灰字。 |
| 交互 | 单击、双击、操作列照常；**不是**禁用行。 |
| 选中优先 | 行处于 **`.crm-list-row--clicked`**、**`.current-row`**、**`.so-item-row--active`** 时恢复正常字色，选中高亮优先于灰色。悬停仍可用现有行悬停底。 |
| 范围 | **看板模式、打印页、详情内嵌表不在此条。** 入库/付款等其它列表本期不套用。 |

## 4. 列表翻页（分页器）

### 4.1 适用范围（必达）

- **凡「标准业务列表主表」**（整页以数据表格为主体、用户以浏览/检索多条业务记录为主要目的），**必须提供翻页器**，避免一次渲染过多行导致卡顿与操作困难。
- **不适用**（可不接分页或按子 PRD 处理）：详情页内嵌表、弹窗/抽屉内子表、**仅展示少量固定行**的配置表、**调试页**等；若豁免须在 PRD 或评审记录中写明。

### 4.2 位置与底栏组合（与第 1 章一致）

- 翻页器放在**列表底栏**，与 **第 1 章**「列设置入口」**同一行**；从左到右建议为：**列设置（齿轮）→（可选）行高密度 → Spacer →（可选）其他底栏按钮 → 分页器靠右**。
- 分页器容器建议使用 **`margin-left: auto`**（或与现有页一致的 **`list-main-pagination`** 类名）与左侧控件**顶部对齐**；底栏父级使用 **`display: flex`**、**`flex-wrap: wrap`**，窄屏时允许换行。

### 4.3 控件与默认值（Element Plus）

- 使用 **`el-pagination`**（或经评审同意的等价组件），建议 **`layout`**：`total, sizes, prev, pager, next, jumper`。
- **`page-sizes`**：建议 **`[10, 20, 50, 100]`**；**默认每页条数**建议 **20**（与 `QuoteList.vue`、`RFQItemList.vue` 等已有列表对齐）。
- **总条数 `total`** 须与当前筛选条件下的数据条数一致（全量或当前页接口返回的总数）。

### 4.4 数据加载方式（服务端优先）

- **优先**：列表查询接口支持 **`pageNumber` / `page` + `pageSize`**（或项目统一分页参数名），前后端一致，**只请求当前页数据**。
- **过渡方案**：若接口暂为**一次返回全量**，允许在前端对**已加载且已按筛选条件收窄后的数组**做 **`slice` 分页**；须在评审中说明**预期数据量上限**及后续改为服务端分页的计划，避免在超大集合上长期依赖前端分页。

### 4.5 页码与「刷新」交互（建议）

- **筛选条件变化**（搜索、重置、下拉筛选变更并重新拉数等）后，应将 **当前页重置为第 1 页**。
- **不改变筛选条件的刷新**（仅重新请求当前列表）：**可保留用户当前页码**；若刷新后总条数减少导致当前页超出范围，应**自动夹取到最后一页**（避免空白表）。

### 4.6 新列表页自检

- 主表是否在底栏提供 **`el-pagination`**，且与列设置/行高密度同排布局符合 **4.2**。
- `total`、当前页数据、`page-size` 是否一致；变更筛选后页码是否合理。
- 数据量或接口形态是否需在 **4.4** 中已说明或已走服务端分页。
- **详情/内嵌表**：若使用 **`density-toggle-anchor-el`** 或底栏列设置，行高密度与齿轮是否仍在 **表体下方底栏左侧**（见 **§2.6**），而非表头或 Tabs 行附近。

> **参考实现**（含底栏 + 分页）：`CRM.Web/src/views/RFQ/QuoteList.vue`、`RFQItemList.vue`；物流与库存侧已落地的标准列表示例包括：**到货通知** `Logistics/ArrivalNoticeList.vue`、**质检** `Logistics/QcList.vue`、**入库单列表** `Inventory/StockInList.vue`、**库存列表** `Inventory/InventoryList.vue`（库存中心）、**库存桶** `Inventory/InventoryBucketList.vue`、**库存明细** `Inventory/InventoryStockItemList.vue`、**出库通知** `RFQ/StockOutNotifyList.vue`、**拣货单** `Inventory/PickingSlipList.vue`、**出库单列表** `Inventory/StockOutList.vue`、**出库明细** `Inventory/StockOutItemList.vue`。
