# 列表交互规范 PRD（V1.0）

## 1. 文档目的

统一业务列表（`el-table` / `CrmDataTable` 及卡片式列表）的**行级打开主记录**交互：用**双击**进入详情、用 **Ctrl + 双击** 进入编辑，与单击选中、高亮、侧栏展开等行为区分，降低误触并缩短常用路径。

---

## 2. 适用范围

- 前端所有**主数据 / 单据列表**（表格行、或整块卡片对应一条主记录时）
- 同时具备**详情路由**与**编辑路由**的列表（如客户、供应商、询价单、销售订单等）**必须**实现本章 §3.1 与 §3.2

不包含：

- 详情页内嵌子表、弹窗内表格、仅用于行内编辑的表格
- **无**对应详情或主查看路由的列表（例如仅流程动作、无统一详情 URL——可不绑行级双击，评审时注明原因）
- 业务上**仅有编辑页、无详情页**的列表（如部分系统管理页）：**双击行**进入编辑页即可，无需实现 §3.2（与操作列「编辑」一致）

---

## 3. 行级打开主记录（强制）

### 3.1 双击 → 详情页

1. **双击数据行**（或卡片主体区域）：跳转至该行对应的**详情页**。
2. 路由与操作列「详情 / 查看」按钮一致。
3. **单击行**不因此强制跳转；仍用于当前页已有语义（`highlight-current-row`、选中、打开侧栏、勾选等）。
4. 列内「单号链接」「详情」等可保留**单击**打开；双击空白数据区进详情，行为一致即可。

### 3.2 Ctrl + 双击 → 编辑页

1. 用户**按住 Ctrl 键**（Windows / Linux；macOS 上为 **⌘ Command** 时按 `event.metaKey` 与产品约定，本规范默认与 Windows 一致使用 **`event.ctrlKey`**）的同时**双击数据行**：跳转至该行对应的**编辑页**。
2. **前提**（须同时满足）：
   - 该列表存在与操作列「编辑」一致的**独立编辑路由**；
   - 当前用户具备操作列「编辑」所需的**写权限**（如部门只读、RBAC 节点等与按钮显隐策略一致）。
3. **无写权限**或列表不提供编辑入口时：Ctrl + 双击**不**单独打开编辑；按 §3.1 进入详情（与隐藏「编辑」按钮时的预期一致）。
4. 编辑路由、参数与操作列「编辑」按钮一致。

### 3.3 操作列与冒泡

在已绑定 §3.1 / §3.2 的表格中，操作列单元格内须 **`@click.stop`**、**`@dblclick.stop`**（或等价阻止冒泡），避免在操作按钮上双击触发行级跳转。

### 3.4 实现方式

| 场景 | 约定 |
|------|------|
| `CrmDataTable` | 表组件上 **`@row-dblclick="onRowDblClick"`**（透传至内部 `el-table`） |
| 原生 `el-table` | **`@row-dblclick`** |
| 回调参数 | Element Plus 为 `(row, column, event)`；在处理器内根据 **`event?.ctrlKey`** 分支 §3.1 / §3.2 |
| 参考实现 | `CRM.Web/src/views/Customer/CustomerList.vue` — `onRowDblClick` |

示例逻辑（示意）：

```ts
function onRowDblClick(row: Row, _column: unknown, event?: MouseEvent) {
  if (event?.ctrlKey && canEdit.value) {
    goEdit(row)
    return
  }
  goDetail(row)
}
```
