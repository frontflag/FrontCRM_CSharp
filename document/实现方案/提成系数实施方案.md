## 0. 相对本稿的建议（已纳入后文）

| # | 本稿 | 建议 | 原因 |
| --- | --- | --- | --- |
| 1 | 一行 10 对「达标金额 n / 提成点数 n」 | **采用宽表**：一行 = 一个类型 + 一个等级 | 列表一行一级、弹窗改本级全部阶梯，和操作列只「编辑」对齐 |
| 2 | 10 档可不填满，须从 1 起连续、金额单调递增 | 服务端与弹窗同一套规则；空档存 **NULL**（不要用 0 表示空） | `0` 是合法首档达标金额 |
| 3 | 「单调递增」未写是否允许相等 | **严格递增** `金额 i < 金额 i+1` | 相等时取档不确定 |
| 4 | 未写金额与点数是否必须成对 | 第 n 档：**金额、点数都填或都空** | 只填一边无法取档 |
| 5 | 列表「梯度1」～「梯度10」 | 每格 `{达标金额} | {提成点数}%`，未填档 `—` | 一行最多 10 档，分列对照更直观 |
| 6 | 操作只有编辑 | **不提供新增/删除**；迁移预置每类型等级 1～20 各一行 | 否则列表没有「选定行」；删行会留下空洞等级 |
| 7 | 未写未配档怎么算 | 该级 10 档全空，或 GP 小于第 1 档金额 → **点数 0** | 建议第 1 档达标金额填 `0`，否则低 GP 拿不到点 |
| 8 | 点数单位未写 | 存 **百分比**：`5.0` = 5%，计算 `÷ 100`；范围 `0.0`～`100.0`，1 位小数 | 避免 `0.05` 与 `5` 混用 |
| 9 | 用户等级说明 | **落库** `user_level_def`，提成参数页只读展示 | 与用户等级页「等级列表」同一份 |
| 10 | 参考公司信息左栏 | **视觉**对齐公司信息；**路由**对齐财务参数（子路径） | 两套列表需要可收藏 URL |
| 11 | 菜单组最后 | 参数管理里排在 **报表参数之后** | 现网最后一项是报表参数 |
| 12 | — | 点数 **不必** 随档递增（允许高门槛低点数） | 本稿只约束金额 |

点数随档是否必须升高：本期不校验。若财务要求「档越高点越高」，再加一条即可。

## 2. 数据

**表：** `public.commission_rate_version`（头）+ `public.commission_rate`（行）+ `public.commission_calc_setting`（单行计算参数）  
**一行系数：** 一个版本 + 一个用户等级。类型只在版本头。延期天数不跟版本。

`commission_calc_setting` 固定一行（种子 `c2000000-0000-4000-8000-000000000010`）：`receipt_writeoff_delay_days integer NOT NULL DEFAULT 0`，`CHECK (0～3650)`。GET `/settings` 带回；与生效版本一起 `PUT /versions/active`。入池判断：`提成计算日期 − 收款核销日期 > 该天数`（上海日历日，严格大于）。

| 系数行列 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `uuid` PK | `gen_random_uuid()` |
| `version_id` | `varchar(36) NOT NULL` | FK → `commission_rate_version.id` |
| `user_level` | `smallint NOT NULL` | `1`～`20` |
| `threshold_1` … `threshold_10` | `numeric(18,2)` 可空 | 达标金额（USD，整数录入/展示），空=该档未启用 |
| `rate_points_1` … `rate_points_10` | `numeric(5,2)` 可空 | 提成点数（百分比，1 位小数），空=该档未启用 |
| `remark` | `varchar(200)` | 可空 |
| `created_at` / `updated_at` | `timestamptz` | 必填 |
| `created_by` / `updated_by` | `uuid` 可空 | 操作人 |

```text
UNIQUE (version_id, user_level)
CHECK (user_level BETWEEN 1 AND 20)
版本头 UNIQUE (role_type, version_no)
版本头每类型最多一行 status = 2（生效）
```

金额/点数的连续、成对、严格递增 **不写 CHECK**（跨列逻辑放服务端，避免 10 档 CHECK 难维护），保存失败返回明确中文。

**上线预置：** 各类型 V1「初始版本」为生效，并挂原 40 行。脚本幂等。禁止 SQL 出现 `{{`。

**C#**

```csharp
public enum CommissionRoleType : short { Sales = 1, Purchase = 2 }

public const int LadderCount = 10;
```

实体可用两个 `decimal?[]` 或 `Threshold1`…`Threshold10` 显式列（EF 映射宽表更直接，推荐显式 20 个属性）。

### 2.1 阶梯校验（保存时）

从档 1 到 10 扫描，得到已填前缀长度 `k`（0～10）：

1. **成对：** 第 i 档金额与点数必须同空或同有。  
2. **无空洞：** 若第 i 档有值，则 1…i 都必须有值（等价：已填必须是 `1…k`，不能 1、2、4）。  
3. **金额：** 已填档 `threshold ≥ 0`，且 `threshold_1 < threshold_2 < … < threshold_k`（**严格**递增）。  
4. **点数：** 已填档 `0.0 ≤ rate_points ≤ 100.0`，1 位小数。达标金额保存/展示为整数。  
5. **允许 `k = 0`：** 该级暂不设提成（取档得 0）。

错误文案示例：

- 「第 3 档有值时，第 1～3 档必须连续填写」  
- 「达标金额必须随阶梯严格递增」  
- 「第 2 档达标金额与提成点数需同时填写或同时留空」

### 2.2 取档

```text
在该 (指定版本, 等级) 行上，已填档中取 threshold_i ≤ 实际GP 且 i 最大的 rate_points_i；计算默认用生效版
无已填档，或 GP < threshold_1 → 0
提成 = 出库GP × (points / 100)
```

例：档 1 = (0, 5.0)，档 2 = (50000, 7.0)，档 3 = (100000, 9.0)

| 当期入池 GP | 命中 | 点数 |
| --- | --- | --- |
| 60,000 | 档 2 | 7% |
| 0 | 档 1 | 5% |
| -100 | 无（`-100 < 0`） | 0 |

规则是 `达标金额 ≤ GP`。首档建议填 0，否则 GP 小于第 1 档金额一律 0。

## 5. API

`CommissionRatesController`，`/api/v1/commission-rates`。

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/settings` | 子项 read | 两类型版本列表 + 当前生效 id |
| GET | `/versions?roleType=` | 子项 read | 某类型全部版本 |
| POST | `/versions` | 子项 write | 新建草稿（复制自指定或生效版），说明必填 |
| PUT | `/versions/active` | 子项 write | 同时指定业务、采购生效版；原生效改回草稿 |
| PUT | `/versions/{id}` | 子项 write | 改版本说明 |
| GET | `?roleType=1&versionId=` | 子项 read | 20 行（缺行则补齐）；`versionId` 空则用生效版 |
| PUT | `/{id}` | 子项 write | 改 10 档 + 备注；**不可改** 版本 / 等级 |

系数行无 POST / DELETE。版本用 POST `/versions` 新建。

PUT body：

```text
remark
ladders: [ { thresholdAmount, ratePoints } × 10 ]
```

空档传 `null`。`id` 必须属于当前 `roleType`，否则 404。校验失败 400 + 上列中文。

列表 DTO：`id, roleType, userLevel, thresholds[], ratePoints[], remark`（数组仅含已填前缀，或固定 10 位含 null，前后端约定一种；推荐 **固定 10 位**，列表自行跳过 null）。
