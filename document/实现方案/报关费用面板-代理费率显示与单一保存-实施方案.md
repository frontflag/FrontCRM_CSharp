## 0. 背景与不做

| 项 | 说明 |
|----|------|
| 现象 | `CDS00001` 已试算、已完成、费用已锁定。明细报关代理费 **351.47** 按单头 **1.025000** 算出。页头红框却显示报关公司当前费率 **1.003000**（约 0.30%）。计算公式「演示」代入页头费率，第 ⑤～⑦ 步与表格不一致 |
| 根因 | `CustomsDeclarationFeesPanel.vue` 的 `syncDraftsFromDetail` 只要 `brokerMasterAgencyRate > 0` 就用主数据，盖掉单头 `brokerAgencyRate`。费用区同时放「试算费用」和「保存」；可整单重算时两者都是「提交改动 + 试算并落库」 |
| **不做** | 改费用公式；改 `fees_locked` 的写入时机；把已锁定的费率改回未锁定；恢复代理费率「系统 / 手工」切换；让演示单独再选一套费率；改后端试算用哪一个费率 |

`broker_agency_rate` 是非空数字，生成报关单时就会写入当时的报关公司费率，不能用「列是否为 NULL」判断新建。判断用 **是否已经试算落库**（`fees_calculated_at` 有值）。

试算成功即写入单头费率、明细金额和 `fees_calculated_at`。可重算时「保存」走的就是这次试算，不存在「试算只预览、再点保存才落库」。

## 1. 目标

1. 页头「代理费率」与同一页表格金额使用同一套费率。
2. 费用区只留一个「保存」按钮。能整单重算时，保存 = 提交改动并试算；已结关锁定且当前账号不能整单重算时，保存只写杂费和商检费。
3. 「演示」继续代入页头显示的费率。显示规则改正后，已试算单据的第 ⑤～⑦ 步与表格对齐。
4. 页头「报关汇率」「代理费率」「采购系数」按本次保存会不会改数据库这一列显示锁图标。列会被改写就不加锁，即使页头数字不是最终写入的数。价税合计不加锁。不改试算写库规则。

## 3. 代理费率显示（阶段 A）

### 3.1 规则

页头只读，6 位小数，右侧仍显示「等价 n%」，再后接来源说明：读到报关公司当前费率为「(当前参数)」，读到单头已保存费率为「(历史参数)」。两个数相同仍按实际来源标注。两边都读不到合法费率、退回 1 时不显示来源说明。采购敏感字段脱敏时继续显示「—」，不套用本规则，也不显示来源说明。

| 条件 | 显示 | 来源说明 |
|------|------|----------|
| `feesCalculatedAt` 为空，且报关公司当前费率有效 | 报关公司当前费率 `brokerMasterAgencyRate`。这是下次保存（试算）会用的数。新建、尚未保存过费用时走这里 | **(当前参数)** |
| `feesCalculatedAt` 有值，且单头快照有效 | 单头 `brokerAgencyRate`。这是上次试算写入、并用来算出表格金额的数 | **(历史参数)** |
| 已试算但快照无效，退回当前费率 | 报关公司当前费率 | **(当前参数)** |
| 未试算但当前费率无效，退回单头快照 | 单头 `brokerAgencyRate` | **(历史参数)** |
| 两边都不是大于 0 的有限数字 | **1**（0% 代理费） | 不显示 |

取值都须为有限数字且 **> 0**。首选无效时：已试算则退回报关公司当前费率，未试算则退回单头快照；仍无效则显示 **1**（0% 代理费）。**1.000000 是合法费率**，不能把 1 当成「空」。

### 3.2 与试算写库的关系（不改后端）

| 时机 | 单头 `broker_agency_rate` | 页头应显示 |
|------|---------------------------|------------|
| 拣货生成报关单 | 写入当时报关公司费率；`fees_calculated_at` 仍空 | 报关公司**当前**费率，旁注 **(当前参数)**。主数据未改时与单头相同；主数据已改则显示新费率 |
| 保存 / 试算成功（未锁定、或管理员更正） | 覆盖为本次试算使用的报关公司费率，并写 `fees_calculated_at` | 刷新后显示这个快照，旁注 **(历史参数)**。此时数字可与主数据相同，说明仍是历史参数 |
| 已结关锁定或内部已完成后再试算 | 保留原快照（`preserveAgency`） | 显示原快照，旁注 **(历史参数)**，不跟后来改过的报关公司主数据 |
| 更换报关公司 | 单头改为新公司费率；汇率 > 0 时同一请求内重算 | 刷新后显示新快照，旁注 **(历史参数)** |

`CDS00001`（本地库，2026-09-28）：`broker_agency_rate = 1.025000`，`agency_rate_manual = false`，`fees_calculated_at` 有值，`fees_locked = true`，内部状态已完成，报关公司「利物通发展（香港）有限公司」当前 `agency_rate = 1.003000`。落地后页头为 **1.025000（历史参数）**。代理费 351.47 = (12441.34 + 0 + 1617.37) × (1.025 − 1)。

### 3.3 改哪些文件

| 文件 | 改法 |
|------|------|
| `CRM.Web/src/utils/customsFeeAgencyRateDisplay.ts` | `resolveDisplayedBrokerAgencyRateDetail` 返回费率与来源：`current` →「(当前参数)」，`history` →「(历史参数)」，`none` → 不显示说明。规则见 §3.1 |
| `CRM.Web/src/tests/customs-fee-agency-rate-display.test.ts` | 覆盖费率取值，并覆盖来源：未试算为 current；已试算为 history；退回时按实际读到的来源；都无效为 none |

## 4. 只留「保存」（阶段 B）

### 4.1 按钮

费用区标题右侧只保留主按钮「保存」（`customsPages.fees.btnSave`）。删除「试算费用」按钮（`btnRecalculate`）。

「采用财务汇率」仍留在报关汇率旁边，不随试算按钮一起删。

### 4.2 保存在各状态下做什么

行为与现有 `handleSave` 相同，只是不再提供另一条入口。

| 报关单状态 | 谁能看到「保存」 | 点击后 |
|------------|------------------|--------|
| 已作废 | 不显示 | — |
| 无物流写入权限 | 不显示 | — |
| 处理中，费用可维护（含缺 P0、尚未能试算） | 有写入权限 | 提交汇率、采购美金价模式、行税率、杂费、商检、手工采购美金价，再整单试算并落库。缺汇率、缺采购系数、缺 P0 且未填合法手工美金价时，按钮禁用 |
| 已结关锁定（`fees_locked`，内部状态尚未完成），且当前账号**不能**更正采购美金价 | 有写入权限 | **只**提交杂费、商检费。杂费重算该行价税总额与含税单价，并回写到货、入库、库存。商检费只记在明细，不进价税。不重算关税、增值税、代理费，不改单头代理费率。此状态下不因缺 P0 / 缺汇率而禁用 |
| 已结关锁定，且当前账号**能**更正采购美金价（系统管理员或平台管理员，且采购字段未脱敏） | 同上 | 与「处理中可维护」相同：提交改动并整单试算。已锁定时试算保留原代理费率快照 |
| 内部状态已完成，非管理员 | 不显示 | — |
| 内部状态已完成，管理员且采购字段未脱敏 | 显示 | 提交改动并整单试算，保留原代理费率快照，并级联下游 |

费用锁定的含义不变：在报关单上把海关状态设为「已结关」时 `fees_locked = true`。之后没有解锁。内部状态「已完成」是报关入库做完、待报关清单都关闭之后另写的，费用区优先按已完成处理，不走「只能改杂费和商检」那一档。

### 4.3 头区锁图标

锁只表示：**这次保存不会改数据库里的这一列**。不加锁表示这一列会被更新。页头上看到的数字可以不是最终写入的值。

例：采购系数仍显示上次保存的 1.0025，旁边写「当前参数{当前系数}，保存后覆盖历史」。这次保存会把明细采购系数改成当前生效系数，所以**不加锁**。

价税合计是试算结果，保存时会重写，**不加锁**。本方案不改后端：处理中整单重算仍用报关公司当前费率覆盖单头代理费率；已结关或已完成、且账号能整单重算、单头费率大于 0 时，仍保留原快照（`preserveAgency`）。

| 状态 | 报关汇率 | 代理费率 | 采购系数 |
|------|----------|----------|----------|
| 处理中、有写入权限、可整单重算（可编辑，或因缺 P0 暂时不能试算） | 不加锁。汇率有改动时写入页面上的数 | 不加锁。整单重算把单头费率写成报关公司当前费率 | 不加锁。整单重算把明细采购系数写成当前生效系数 |
| 已完成，且能整单重算，单头费率 > 0（如 `CDS00001`） | 加锁。汇率不变 | 加锁。保留原快照（如 1.025000） | 不加锁。写成当前生效系数 |
| 已结关锁定、内部状态未完成、不能整单重算（只保存杂费和商检费） | 加锁 | 加锁 | 加锁 |
| 已结关锁定、能整单重算、单头费率 > 0 | 加锁 | 加锁（保留原快照） | 不加锁 |
| 已作废，或无写入权限 | 加锁 | 加锁 | 加锁 |
| 已完成、不能整单重算（无保存按钮） | 加锁 | 加锁 | 加锁 |
| 已完成或已锁定、能整单重算，但单头代理费率不是大于 0 的数 | 加锁 | **不加锁**（`preserveAgency` 不成立，写入报关公司当前费率） | 不加锁 |

费率 **1.000000**（0% 代理费）大于 0，按「已有费率」加锁。悬停文案：保存不会修改报关汇率 / 代理费率 / 采购系数。

实现：`CRM.Web/src/utils/customsFeeHeaderLocks.ts` 的 `resolveFeeHeaderLocks`。面板用同一结果给三个标签加锁图标。无写入权限时三个都锁，不限于已结关、已完成、已作废。

### 4.4 实现注意

`showRecalculateActions` 今天不只控制试算按钮，还控制：保存在可重算时的禁用、采购美金价手工入口、「采用财务汇率」是否出现。去掉按钮时保留这些门控，不要把可编辑范围收窄。

可删除仅被试算按钮使用的模板分支。`handleRecalculate` 仍由 `handleSave` 在可重算时调用，不要删试算 API（`recalculateCustomsDeclarationFees`）。

成功提示维持现状：整单试算用「费用试算成功」（含下游条数时用带条数的那条）；只保存杂费/商检用「费用已保存」。

i18n：`zh-CN.ts` / `en-US.ts` 的 `customsPages.fees.btnRecalculate` 若再无引用则删除。其余费用文案里若仍写「点试算或保存」，改成只写「保存」。

## 8. 上线

无数据库脚本。先部署 Web。已打开的详情需刷新后才看到新页头费率和单个保存按钮。历史单据不必重算；已试算单据打开后即显示单头已有费率。
