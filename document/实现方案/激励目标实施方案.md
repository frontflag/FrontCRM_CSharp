员工给自己设「本期 / 年度计划提成金额」，桌面对照已有提成结果看完成度。  
**不是**任务跟进，**不是**提成引擎，**不是** OKR / 经理下达。

---

## 0. 本期锁定的口径

实现时不再分叉。

| # | 议题 | 锁定 |
| --- | --- | --- |
| 1 | 指标 | 只做 **计划提成金额**（业务 USD），不做销售额 / GP / 单量 |
| 2 | 「本期」 | 与预计提成同一 **开放双月** `CommissionTerm.GetOpenWindow(上海今天)`，不是自然月 |
| 3 | 「年度」 | 上海日历年（`yyyy`） |
| 4 | 谁设 | **只能设自己的**。经理不能下达，也不能看别人的目标 |
| 5 | 实际值 | **读现成提成结果，不重算**。本期读 `commission_dynamic`；年度 = 当年已锁 + 当年未锁动态 |
| 6 | 完成度 | `实际 ÷ 目标`；目标未设或 ≤ 0 显示「未设置」，不算完成度 |
| 7 | 销售 / 采购 | 与控制台身份一致：采购主部门（`identityType` 2/3）看采购提成；其余看业务提成。一期桌面只展示这一对定额 |
| 8 | 超额完成 | 实际 > 目标 **允许**，完成度可以超过 100%。定额不是核销余额 |
| 9 | 入口 | `/dashboard` 欢迎区与业务总览之间；仅销售部/采购部员工或 SYS_ADMIN 出卡片 |
| 10 | 任务表 | **不**扩展 `work_task` |

## 1. 范围

| 做 | 不做 |
| --- | --- |
| 表 `incentive_target`：本人本期 / 年度目标金额 | 经理下达、团队目标、OKR、评分 |
| `GET/PUT /api/v1/incentive-targets/me` | 改别人的目标；按任意历史窗写入（一期只写「当前窗 / 当前年」） |
| 桌面卡片：实际 / 目标 / 完成度 | 独立菜单页、历史趋势图 |
| 完成度用现成动态表 + 锁定表求和 | 重跑提成 Job、改提成金额 |
| 权限 `incentive-target.read` / `.write` | 把定额写进提成列表或锁定流程 |

同一人业务提成与采购提成独立。一期 UI 只维护当前桌面身份对应的那一对。

## 2. 实际值怎么取

时区与提成一致：`Asia/Shanghai`。  
`open = CommissionTerm.GetOpenWindow(上海今天)`。  
`role_type`：采购主部门 = 2，否则 = 1（与 `CommissionRoleType` 相同）。

```text
本期实际 = Σ commission_dynamic.commission_usd
  WHERE user_id = 当前用户
    AND role_type = 当前身份
    AND calc_month ∈ { FormatMonth(open.From), FormatMonth(open.To) }

年度实际 = Σ commission_locked.commission_usd
  WHERE user_id = 当前用户
    AND role_type = 当前身份
    AND left(calc_month, 4) = 当年
+ Σ commission_dynamic.commission_usd
  WHERE user_id = 当前用户
    AND role_type = 当前身份
    AND left(calc_month, 4) = 当年
```

已锁行不在动态表，两侧相加不重复。  
年度按 **`calc_month` 的自然年** 切，不按锁定 `term`（`term=yyyy01` 的窗会跨年）。

本期目标绑定 `period_key = open.Term`（例如 `202609`）。偶数月 2 日开放窗切换后，桌面看到的是**新一期**；旧 `period_key` 仍留在库里，但一期不展示、不提供改历史窗。新年 1 月 1 日同理。

## 3. 表

```sql
CREATE TABLE IF NOT EXISTS public.incentive_target (
  id                 varchar(36)    NOT NULL,
  user_id            varchar(36)    NOT NULL,
  role_type          smallint       NOT NULL,  -- 1 业务 2 采购
  period_kind        smallint       NOT NULL,  -- 1 本期(term) 2 年度
  period_key         varchar(8)     NOT NULL,  -- term=yyyyMM；年=yyyy
  target_amount_usd  numeric(18,2)  NOT NULL,
  create_time        timestamptz    NOT NULL,
  modify_time        timestamptz    NOT NULL,
  is_deleted         boolean        NOT NULL DEFAULT false,
  CONSTRAINT pk_incentive_target PRIMARY KEY (id)
);

CREATE UNIQUE INDEX IF NOT EXISTS ux_incentive_target_user_period
  ON public.incentive_target (user_id, role_type, period_kind, period_key)
  WHERE is_deleted = false;

CREATE INDEX IF NOT EXISTS ix_incentive_target_user
  ON public.incentive_target (user_id)
  WHERE is_deleted = false;
```

- **不存实际值**。展示时现算。  
- `target_amount_usd` 必须 `> 0`；清除目标 = 软删该行（或不再插入）。`0` 视为未设置，写入时按清除处理。  
- 上限 `99,999,999.99`（与提成金额同量级）。小数最多 2 位。

脚本：`scripts/ensure_incentive_target_postgresql.sql`（幂等，含权限种子）。  
迁移：`YYYYMMDDHHMMSS_IncentiveTarget`（SQL-only，与工作日程同一写法）。

权限：

| Id | Code | 名称 |
| --- | --- | --- |
| `c1000000-0000-4000-8000-000000000105` | `incentive-target.read` | 激励目标-查看 |
| `c1000000-0000-4000-8000-000000000106` | `incentive-target.write` | 激励目标-维护 |

授予：`SYS_ADMIN`、`SYS_MANAGER`、`commerce_operator`、`sale_operator`、`purchase_operator`、`purchase_buyer`（与 `work-task` 同一批业务角色）。

## 4. API

均要求登录。`user_id` **只取当前主体**，忽略请求体里的他人 Id。

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| `GET` | `/api/v1/incentive-targets/me` | `incentive-target.read` | 当前身份 + 当前开放窗 + 当年 |
| `PUT` | `/api/v1/incentive-targets/me` | `incentive-target.write` | upsert 当前窗或当年的目标 |

`GET` 返回（金额未脱敏时）：

```json
{
  "roleType": 1,
  "roleLabel": "业务提成",
  "term": {
    "periodKey": "202609",
    "from": "2026-08-01",
    "to": "2026-09-30",
    "label": "2026-09（8–9月）",
    "hasTarget": true,
    "targetUsd": 8000.00,
    "actualUsd": 3200.50,
    "completionPct": 40.0
  },
  "year": {
    "periodKey": "2026",
    "hasTarget": false,
    "targetUsd": null,
    "actualUsd": 15100.00,
    "completionPct": null
  }
}
```

`PUT` 体（一次写两行）：

```json
{ "termTargetUsd": 8000.00, "yearTargetUsd": 50000.00 }
```

- `period_key` **服务端**按今天计算，客户端不能指定历史 key。  
- 对应字段 `null` 或 `0`：清除该窗/年目标。  
- `< 0` 或 `> 99,999,999.99` 或超过 2 位小数：`400`。  
- 冒充登录：**读可以**（看被冒充人的进度），**写 403**（与工作日程写任务相同）。  
- 改 `userId` / `roleType` 无效；角色由桌面身份决定。

脱敏：销售身份且 511、采购身份且 521 时，`actualUsd` 与 `completionPct` 返回 `null`，前端显示「—」。`targetUsd` 仍返回（自己填的数）。

## 8. 验收要点（开发自测）

- 设本期 `8000.00`，动态表该人该窗合计 `3200.50` → 完成度 `40.0%`。  
- 实际超过目标 → 完成度 `>100%`，保存成功。  
- 负数 / 超上限 → 400，库中旧值不变。  
- `PUT` 带他人 `userId` → 仍写自己。  
- 偶数月 2 日后开放窗切换 → 本期目标显示未设置（新 `period_key`），旧行仍在库。  
- 采购主部门账号看到的是采购提成合计，不是业务提成。

完整步骤见 QA 对照说明。
