## 0. 本期锁定的口径

相对总设计 §8「待确认」，本期按下面写死（实现时不再分叉）：

| # | 议题 | 锁定 |
| --- | --- | --- |
| 1 | 取档用的「当期入池 GP」 | 该 **角色 + 归属人 + 当前开放双月** 内、已入池且未锁定的出库行 `profit_out_biz_usd` **合计**。再用该点数去乘 **每一行** 的出库 GP。 |
| 2 | 入池日 | **首次满足 §1.2（含延期）的提成计算日期**（上海日历日），不是核销日本身。核销日只用于延期判断与展示。 |
| 3 | 取级 | 按 **入池日** 回放 `user_level_history`；无履历用当前 `user.level`（默认 1）。 |
| 4 | 列表门控 | `SYS_ADMIN` / `SYS_MANAGER` / 业务数据旁路看全部；其余持有对应 `.read` 的人只看 **归属人 = 自己**。本期不默认给业务员/采购员授菜单。 |

## 1. 范围

| 做 | 不做 |
| --- | --- |
| 表 `commission_dynamic` + 每日 Job | 提成方案、权重、客服、RE、超期/退货/坏账 |
| 入池扫描（出库 + 收款完成 + 延期） | 手工改金额、加减项 |
| 业务预计提成 / 采购预计提成列表（占位页换成真列表） | 样品专项排除 |
| 管理员手工重算（同一套幂等） | 即时预览（可不做；若做则计算日=今天上海日） |
| 按人汇总 + 下钻出库行 | 正式锁定（下一阶段） |

同一出库行可同时有业务员一行、采购员一行，**独立核算**。已进入 `commission_locked` 的 `(role_type, stock_out_item_id)` **不再写入动态表**（该角色已正式提成过，禁止再算预计）。另一角色未锁仍可入动态。

## 2. 入池与计算

与总设计 §1、§2 一致，实现时按下列步骤。

### 2.1 候选出库行

- 来源：`stock_out_item`（未软删）+ `stock_out_item_extend`
- 须对应出库完成单（`stock_out.Status = 4`；`2` 是准备出库）。现网装箱 `packing.Status = 100` 后落库的出库行即可；不要再滤一遍拣货单
- 出库 GP = `stock_out_item_extend.profit_out_biz_usd`（业务 USD）。快照为 0 且缺少销售 USD 时，用销售明细 `convert_price` 与扩展采购 USD、出库数量按同一公式回算
- 销售明细：`stock_out_item_extend.sell_order_item_id`；采购明细：`purchase_order_item_id`（采购侧无 PO 则该侧不生成行）

### 2.2 收款核销完成

该出库行所属 **销售明细** `sellorderitemextend.receipt_progress_status = 2`。

采购员侧同样看 **销售侧应收核销**，不做进项发票/付款核销门槛。

**收款核销日期**（上海日历日）：回放该销售明细关联 `finance_receivable` 上未删的 `finance_receivable_write_off`（按核销落库时间升序），找到累计核销额 **首次 ≥ 应收额** 的那一笔。

- 有收款单：`finance_receipt.ReceiptDate` 转上海日
- 预收池（无收款单）：核销 `CreateTime` 转上海日
- 回放失败但进度已是 2：降级为这些核销的最大收款日/落库日，并打日志，不阻断整批

`sellorderitemextend` **不**加完成日列。

### 2.3 延期

```text
提成计算日期 − 收款核销日期  >  commission_calc_setting.receipt_writeoff_delay_days
```

上海日历日整数差，**严格大于**。填 `0`：核销当天不入池，次日才入。读取单行表，与系数版本无关。

**提成计算日期** = 本次动态 Job 的上海日历日（手工重算用「触发当时」的上海日）。

### 2.4 归属人

| 角色 | 优先级 |
| --- | --- |
| 业务员（`role_type=1`） | `sellorder.sales_user_id` → `packing.sales_id` / `stock_item.salesperson_id` |
| 采购员（`role_type=2`） | `purchaseorder.purchase_user_id` → `stock_item.purchaser_id` |

无归属人：该侧不生成行（另一侧仍可）。

### 2.5 入池日

该行在本角色下 **第一次** 同时满足 2.1～2.4 的计算日。

- 动态表已有该业务键：保留原 `pool_date`（反核销消失后再入池则作废旧行，新行用新的首次满足日）
- 锁定表已有该业务键：本轮跳过（正式提成已冻结）

因此：核销在锁定期内、但延期未到锁定时刻的行，首次满足日会落在锁定日之后，进入 **当前开放双月**，不补进已锁账期。

### 2.6 当前开放双月

尚未执行锁定的账期（上海日历，按 **入池日**）：

| 今天（上海） | 开放窗口 |
| --- | --- |
| 2/2 锁定之后 ～ 下一锁定前 | 2/1 ～ 3/31 |
| 4/2 锁定之后 ～ 下一锁定前 | 4/1 ～ 5/31 |
| … | … |
| 12/2 锁定之后 ～ 次年 2/2 前 | 12/1 ～ 次年 1/31 |

开放窗口算法与正式提成 Job 共用一个纯函数（见正式提成实施方案 §2）。

### 2.7 取级 / 取档 / 金额

```text
等级 = UserLevelAsOf(归属人, 入池日)
当期GP = Σ 同角色同人、入池日∈开放双月、未锁定行的出库GP
点数 = CommissionLadderRules.Pick(生效版本, 等级, 当期GP)   // 5.0 = 5%
行提成 = Round(该行出库GP × 点数 / 100, 2)
```

全空档或当期 GP &lt; 第 1 档 → 点数 0，**行仍写入**（便于列表看到「入了池但系数为 0」）。

生效版本：`commission_rate_version.status=2`，业务/采购各读各的。Job 跑的那一刻读库，不缓存跨天。

`UserLevelAsOf`：履历按 `ChangeTime` 转上海日，取 `入池日` 当天已生效的 `NewLevel`；无记录用 `user.level`。补在 `UserLevelService`，单测覆盖改级前后。

不在本表存锁定标记；是否锁定只查 `commission_locked`。

## 4. Job

对齐 `MailSyncHostedService`：`BackgroundService` + `IServiceScopeFactory`，**不用** Hangfire。时区只认 `Asia/Shanghai`（Windows 回退 `China Standard Time`）。

| 项 | 值 |
| --- | --- |
| 类 | `CommissionDynamicHostedService` |
| Cron 语义 | 每天上海 `00:00` |
| 实现 | 每分钟醒一次，判断「上海日历日是否已跑过」；用单行水位（可放 `commission_calc_setting` 加 `dynamic_job_date`，或独立 `commission_job_watermark`）防重入 |
| 偶数月 2 日 | **先**跑本 Job，**再**跑锁定 Job（锁定 Job 内若发现当日动态未跑完则先重算） |
| 手工 | `POST /api/v1/commission/estimated/recalc`，仅 `SYS_ADMIN` / `SYS_MANAGER` |

失败写日志 + `sys_error_log`，不中断进程。支持同一天手工再跑（覆盖）。

## 5. API

建议 `CommissionEstimatedController`，`/api/v1/commission/estimated`。

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `?roleType=1` | `commission-estimated-sales.read` 或 purchase 对应码 | 出库行明细，分页 |
| GET | `/summary?roleType=` | 同上 | 按人汇总 |
| GET | `/person-lines?roleType=&userId=` | 同上 | 个人未正式提成出库行 |
| POST | `/recalc` | 两管理员 | 立即按「今天」重算 |

查询参数（明细与汇总共用）：`keyword`（单号/人名）、`userId`、`poolDateFrom`、`poolDateTo`、`page`、`pageSize`。默认按 `pool_date desc, stock_out_code`。

门控：无对应 `.read` → 403；非旁路用户强制 `user_id = 当前用户`。

无 POST/PUT/DELETE 改金额。

列表 DTO 字段与表列对齐，金额两位小数。汇总 DTO：`userId, userName, userLevel, lineCount, periodGpUsd, commissionUsd`。
