## 0. 现行口径（不要用下文旧草稿）

与方案 / 总设计一致，实现不得分叉：

| # | 议题 | 锁定 |
| --- | --- | --- |
| 1 | 进预计 | 出库完成 + **该出库行对应应收核销完成** + Base/Other + 该侧未正式锁定 |
| 2 | 核销粒度 | `finance_receivable`（出库单 × 销售明细）。**不**看销售明细 `receipt_progress_status` |
| 3 | 取档 | 按 **计算月** 合计计算用 GP；须达梯度1。不是开放双月一个点数 |
| 4 | 取级 | 计算月 **1 日** 回放履历 |

| 6 | 列表门控 | 两管理员/旁路看全部；其余对应 `.read` 只看本人 |

## 1. 范围

| 做 | 不做 |
| --- | --- |
| 表 `commission_dynamic` + 每日 Job | 提成方案、权重、客服、RE、超期/退货/坏账 |
| 入池扫描（出库 + 该出库应收核销完成 + Base/Other） | 手工改金额、加减项 |
| 业务预计提成 / 采购预计提成列表（占位页换成真列表） | 样品专项排除 |
| 管理员手工重算（同一套幂等） | 即时预览（可不做；若做则计算日=今天上海日） |
| 按人汇总 + 下钻出库行 | 正式锁定（下一阶段） |

同一出库行可同时有业务员一行、采购员一行，**独立核算**。已进入 `commission_locked` 的 `(role_type, stock_out_item_id)` **不再写入动态表**（该角色已正式提成过，禁止再算预计）。另一角色未锁仍可入动态。

## 2. 入池与计算

与总设计 §1、§2 一致，实现时按下列步骤。

### 2.1 候选出库行

- 来源：`stock_out_item`（未软删）+ `stock_out_item_extend`
- 须对应出库完成单（`stock_out.Status = 4`；`2` 是准备出库）。现网装箱 `packing.Status = 100` 后落库的出库行即可；不要再滤一遍拣货单
- 出库 GP = `stock_out_item_extend.profit_out_biz_usd`（业务 USD）。快照为 0 且缺少销售 USD 时，用销售明细 `convert_price` 与扩展采购 USD、出库数量按同一公式回算
- 销售明细：`stock_out_item_extend.sell_order_item_id`；采购明细：`purchase_order_item_id`（采购侧无 PO 则该侧不生成行）

### 2.2 收款核销完成

该出库行对应 **应收** `finance_receivable.verification_status = 2`（一出库单 × 一销售明细一条应收）。**不**看销售明细 `receipt_progress_status`，不等该销售行其它出库批次收齐。

采购员侧同样看 **销售侧该出库应收核销**，不做进项发票/付款核销门槛。

**收款核销日期**（上海日历日）：回放该条应收上未删的 `finance_receivable_write_off`（按核销落库时间升序），找到累计核销额 **首次 ≥ 该应收额** 的那一笔。

- 有收款单：`finance_receipt.ReceiptDate` 转上海日
- 预收池（无收款单）：核销 `CreateTime` 转上海日
- 回放失败但状态已是核销完成：有核销流水则用最大收款日/落库日；零金额无应收则取出库日；仍没有则该行不进预计并打日志，不阻断整批

无应收且销售行金额为 0：视为核销完成，核销日 = 出库日。

### 2.3 延期

**不使用。** `commission_calc_setting.receipt_writeoff_delay_days` 不参与入期。核销完成日落入 Base/Other 窗即可进预计。

### 2.4 归属人

| 角色 | 优先级 |
| --- | --- |
| 业务员（`role_type=1`） | `sellorder.sales_user_id` → `packing.sales_id` / `stock_item.salesperson_id` |
| 采购员（`role_type=2`） | `purchaseorder.purchase_user_id` → `stock_item.purchaser_id` |

无归属人：该侧不生成行（另一侧仍可）。

### 2.5 计算月与 `pool_date`

进预计后：

- **计算月** = Base 用出库月 / Other 用核销月（上海 `yyyy-MM`）
- **`pool_date`** = Base 用出库日，否则用核销日（展示/排序冗余，**不**再当入期或取档窗口）

已锁定 `(role_type, stock_out_item_id)` 本轮跳过。

### 2.6 进本期窗口

相对 **下一锁定日** `L`（偶数月 2 日）。每天重算用 `CommissionTerm.GetNextLockDate(计算日)`。细则见方案 §4。

### 2.7 取级 / 取档 / 金额

```text
等级     = UserLevelAsOf(归属人, 计算月 1 日)
计算用GP = max(出库GP, 0)
本月GP   = Σ 同角色同人、同一计算月、未锁定行的计算用GP
本月点数 = 达标（本月GP ≥ 梯度1）后按档取点；否则 0
行提成   = Round(计算用GP × 本月点数 / 100, 2)
```

全空档或未达梯度1 → 点数 0，**行仍写入**。生效版本：`commission_rate_version.status=2`，业务/采购各读各的。

## 3. 数据

**表：** `public.commission_dynamic`  
**业务键：** `UNIQUE (role_type, stock_out_item_id)`  
脚本：`scripts/commission_dynamic_schema.sql` + 迁移（建议 `20260909120000_CommissionDynamic`）。API 启动不改库。禁止 SQL 出现 `{{`。

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `varchar(36)` PK | |
| `role_type` | `smallint` | 1 业务员 / 2 采购员 |
| `stock_out_item_id` | `varchar(36)` | 出库行 |
| `user_id` | `varchar(36)` | 归属人 |
| `user_name` | `varchar(50)` | 账号快照 |
| `user_level` | `smallint` | 计算月 1 日等级快照 |
| `version_id` | `varchar(36)` | 计算时生效版本 |
| `rate_points` | `numeric(5,2)` | 点数（百分比） |
| `gp_usd` | `numeric(18,2)` | 本行出库 GP |
| `period_gp_usd` | `numeric(18,2)` | 该计算月计算用 GP 合计 |
| `commission_usd` | `numeric(18,2)` | 本行提成 |
| `sell_order_id` / `sell_order_code` | | 可空 |
| `sell_order_item_id` / `sell_order_item_code` | | 可空 |
| `purchase_order_id` / `purchase_order_code` | | 采购侧；业务侧可空 |
| `stock_out_id` / `stock_out_code` | | |
| `stock_out_date` | `date` | 出库日（上海） |
| `receipt_date` | `date` | 收款核销日期 |
| `pool_date` | `date` | Base=出库日 / Other=核销日（冗余，不筛锁定） |
| `calc_month` / `entry_kind` | | 计算月 `yyyy-MM`；1=Base / 2=Other |
| `calc_date` | `date` | 本次计算日 |
| `calc_at` | `timestamptz` | Job 完成时刻 |
| `created_at` / `updated_at` | `timestamptz` | |

```text
CHECK (role_type IN (1, 2))
INDEX (role_type, user_id, pool_date)
INDEX (role_type, calc_date)
```

每日 Job：**按角色先删未锁定结果再插入**（或对业务键 upsert 后删掉本轮未再命中的行）。不得留下「昨天入池、今天不满足」的脏行。

不在本表存锁定标记；是否锁定只查 `commission_locked`。

## 4. Job

对齐 `MailSyncHostedService`：`BackgroundService` + `IServiceScopeFactory`，**不用** Hangfire。时区只认 `Asia/Shanghai`（Windows 回退 `China Standard Time`）。

| 项 | 值 |
| --- | --- |
| 类 | `CommissionDynamicHostedService` |
| Cron 语义 | 每天上海 `00:00` |
| 实现 | 每分钟醒一次，判断「上海日历日是否已跑过」；用单行水位（可放 `commission_calc_setting` 加 `dynamic_job_date`，或独立 `commission_job_watermark`）防重入 |
| 偶数月 2 日 | **先**跑本 Job，**再**跑锁定 Job（锁定 Job 内若发现当日动态未跑完则先重算） |
| 手工 | `POST /api/v1/commission/estimated/recalc`，仅 `SYS_ADMIN` / `SYS_MANAGER` |

失败写日志 + `sys_error_log`，不中断进程。支持同一天手工再跑（覆盖）。

## 5. API

建议 `CommissionEstimatedController`，`/api/v1/commission/estimated`。

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `?roleType=1` | `commission-estimated-sales.read` 或 purchase 对应码 | 出库行明细，分页 |
| GET | `/summary?roleType=` | 同上 | 按人汇总 |
| GET | `/person-lines?roleType=&userId=` | 同上 | 个人未正式提成出库行 |
| POST | `/recalc` | 两管理员 | 立即按「今天」重算 |

查询参数（明细与汇总共用）：`keyword`（单号/人名）、`userId`、`poolDateFrom`、`poolDateTo`、`page`、`pageSize`。默认按 `pool_date desc, stock_out_code`。

门控：无对应 `.read` → 403；非旁路用户强制 `user_id = 当前用户`。

无 POST/PUT/DELETE 改金额。

列表 DTO 字段与表列对齐，金额两位小数。汇总 DTO：`userId, userName, userLevel, lineCount, periodGpUsd, commissionUsd`。

替换 [`CommissionPlaceholderPage.vue`](../../CRM.Web/src/views/Commission/CommissionPlaceholderPage.vue)。

| 路由 | 名称 | 权限 |
| --- | --- | --- |
| `/commission/estimated/sales` | `CommissionEstimatedSales` | `commission-estimated-sales.read` |

### 6.1 默认：按人汇总

| 列 | 说明 |
| --- | --- |
| 业务员 / 采购员 | `user_name`。在职全员都列出（提成可为 0）；离职仅提成 > 0 时列出 |
| 用户等级 | 快照（同一人多行等级应相同；若历史脏数据不一致取最新计算行） |
| 出库行数 | |
| 本月 GP | 该计算月 `period_gp_usd` |
| 预计提成 | `commission_usd` 合计 |

双击人员行进入个人提成详情（`/commission/estimated/sales/:userId` 或采购对应路由）。

### 6.2 个人提成详情

列出该人该计算月 **已写入动态表** 的出库行（未进预计的不在第 3 层；核对未核销请看提成池）。

| 列 | 说明 |
| --- | --- |
| 用户账号 / 用户等级 | 当前账号与 `user.level` |
| 出库日期 / 出库明细单号 | 优先 `{出库单号}-{行序}`；无明细号回退出库单号。可链到出库详情（无库存权限则纯文本） |
| 销售明细单号 / 采购明细单号 | 优先明细号，无则回退单据号。可链到销售/采购订单详情 |
| 是否收款核销 | 该出库对应应收核销完成 则为「是」 |
| 收款核销 | 待核销 / 部分核销 / 核销完成 |
| 收款核销日期 | 该条应收回放核销日；未完成则为空 |
| 收款核销日期距今天数 | 上海今天 − 核销日；无日期为 — |
| 是否参与提成 | 该出库应收核销完成且落入当期 Base/Other |
| GP | 出库行 `profit_out_biz_usd` |
| 提成点数 / 提成金额 | 来自动态表；未入预计为 0 |

检索：出库/销售/采购明细单号（单据号子串仍命中）。API：`GET /api/v1/commission/estimated/person-lines`。

帮助：改写现有占位帮助为业务语言（怎么看汇总、为何次日才出现、改档次日变），**不要**写表名/权限码。

## 9. 与总设计 / EBS

- 公式只保留 **计算用 GP × 本月点数 / 100**，不平移 EBS 预计→转正、扣补、方案版本。  
- 页面名「预计提成」对应动态表，不是 EBS Anticipatory 全套。  
- 正式提成只 **复制本表快照**，不再用新系数重算。  
- 口径冲突时以 [业务员与采购员提成方案](./业务员与采购员提成方案.md) 为准。
