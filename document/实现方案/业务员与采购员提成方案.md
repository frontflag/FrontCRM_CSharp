# 业务员与采购员提成方案

> **状态：** 已确认（按本文落地：Base/Other、按月达标、三层列表、GP≤0 当 0、无延期天数）  
> **对照（只读）：** [MogulCRM 个人提成](../MogulCRM/提成/个人提成.md)  
> **现网已落地：** [业务员与采购员提成-设计与实现](../System/财务/业务员与采购员提成-设计与实现.md)、[预计提成实施方案](./预计提成实施方案.md)、[正式提成实施方案](./正式提成实施方案.md)、[提成系数实施方案](./提成系数实施方案.md)  
> **EBS 只读（不验收、不平移）：** [提成逻辑.md](../EBS/提成/提成逻辑.md)、[提成系数梯度.md](../EBS/提成/提成系数梯度.md)  
> **前置：** [用户等级](../System/系统/用户等级-设计与实现.md)、[收款核销](../System/财务/收款核销-设计与实现.md)

对照 Mogul 个人提成后：**无扣点、不按销售额、无异常扣减**；去掉核销延期天数，改为 **Base / Other**；计算用 GP = max(出库GP, 0)；**按自然月取档、按月达标发钱**；预计 / 正式为 **人 → 月 → 池行** 三层。

## 0. 已拍板

| # | 议题 | 结论 |
| --- | --- | --- |
| 1 | 回款 / 库龄 / 毛利率扣点 | **不做** |
| 2 | 高级别按销售额 × 点数 | **不做** |
| 3 | 异常扣减 / 入库超期按成本扣 | **不做** |
| 4 | GP ≤ 0 | **当做 0**（§6.2） |
| 5 | 收款核销延期提成天数 | **去掉**，改 Base / Other（§4） |
| 6 | 取档粒度 | **按自然月**；该月达标才发该月的钱（§6.1） |
| 6b | 月达标金额 | 该人该月等级在业务/采购系数表上的 **梯度1 达标金额（USD）** |
| 7 | 预计 / 正式列表 | **三层**：全员汇总 → 该人各月 → 该月池行（§8） |

## 1. 原则

| 原则 | 说明 |
| --- | --- |
| 用本系统单据 | 一行事实 = 一条已完成出库行（提成数据池），不回到 Close PO |
| 进本期看 Base / Other | 出库日窗 + 核销日窗；不按「核销 + 延期」当入池日 |
| 发钱看自然月 | 同人同月先加计算用 GP，套档得到 **本月点数**；只乘本月行。月与月不共用一个点数 |
| 公式 | `行提成 = 计算用GP × 本月点数 / 100`；无扣点 |
| 业务 / 采购独立 | 同一池行两侧分开算、分开锁 |
| 预计可变、正式冻结 | 每天重算未锁定；偶数月 2 日锁定本期扫中的行 |
| 负 GP | 计算用 GP = max(出库GP, 0)，不拉低月档、不出现负提成 |

## 2. 数据分层（不必为三层再建结果表）

| 表 | 粒度 | 职责 |
| --- | --- | --- |
| 提成数据池（新建） | 一出库明细一行 | 出库事实、核销投影、业务/采购「是否已正式」标记 |
| `commission_dynamic` | 一角色 × 一出库行 | 预计金额；带 **计算月** |
| `commission_locked` | 同上 + `term` | 正式快照；已提成权威登记 |

第 1、2 层 API **按人 / 按人+计算月 GROUP BY** 即可，**不强制**建月汇总表。若正式锁定后要留「当时月达标」快照，可后加人×月表，不是上线前提。

已提成听锁定表；池上 `sales_commission_status` / `purchase_commission_status` 只作扫描剔除，与锁定 **同事务** 回写。

## 3. 范围

### 3.1 做

| 项 | 说明 |
| --- | --- |
| 池表 | 出库完成插入；按销售明细回写核销（待/部分/完成 + 完成日） |
| 进本期 | Base / Other（§4），不再用延期天数 |
| 点数 | 该人 **该计算月** 的计算用 GP 合计套等级档 |
| 行金额 | 计算用 GP × **该月点数** / 100 |
| 页面 | 业务/采购 × 预计/正式，均为三层 |
| 人员 | 在职全列（提成可为 0）；离职仅提成 > 0 |

### 3.2 不做

- 扣点、按销售额、奖金、EBS GP、异常 Debit、手工补加  
- 核销延期天数、客户多业务员拆成  
- Mogul 按建单日换 Grade、CreateDate/OutTime 双规则（本系统归月只用出库日或核销日，见 §6.3）

## 4. 期数：Base / Other（偶数月 2 日）

锁定日 `L` = 2/4/6/8/10/12 月 **2 日 0:00 Asia/Shanghai**。例：`L = 2026-04-02`，`term = 202603`。

| | 窗口 | 尚未正式提成的池行 |
| --- | --- | --- |
| **Base** | 出库日 ∈ 上一完整双月 `[2/1, 3/31]` | 核销 **完成**，且核销日 **&lt; L** |
| **Other** | 出库日 **&lt; 2/1** | 核销完成，且核销日 ∈ **`[2/2, 4/2)`** |

6 月 2 日：Base = 4/1–5/31，Other 核销窗 = `[4/2, 6/2)`。  
该侧池状态已是「已提成」或锁定表已有键 → 跳过（Other 不会把已锁 Base 再发一次）。

去掉 `commission_calc_setting.receipt_writeoff_delay_days`。池行 **不在出库插入时写期数**。

## 5. 池行与入池事实

出库完成（`stock_out.Status = 4`）→ 幂等插入一池行（唯一键出库明细 ID）。核销 / 反核销按 **销售订单明细 ID** 更新所有相关池行（进度 0/1/2，完成日）。无采购员 / 无 PO：采购提成状态 = **不适用**。

归属：业务员 `sellorder.sales_user_id`（否则装箱/库存）；采购员 `purchaseorder.purchase_user_id`（否则库存）。无归属则该侧不算。

历史已完成出库一次性补灌。另做对账：有出库完成无池行则补；核销进度与销售明细不一致则修。

## 6. 按自然月达标发钱

### 6.1 取档（相对现网：双月一条当期 GP → 每月一条）

现网：开放双月所有未锁行加总，**一个点数**乘每一行。  

本方案按自然月。 **本月达标金额** = 该角色生效版本里、该人该月等级那一行的 **梯度1 达标金额（折算 USD）**（`threshold_1`）。

- 业务员读业务提成系数；采购员读采购提成系数。  
- 不是全员同一个数，是 **该人该月等级** 的梯度1。  
- 不另建「月任务」字段。

```text
计算月 M     = 该行归属的自然月（§6.3），上海日历 YYYY-MM
等级         = UserLevelAsOf(归属人, M 的 1 日)
本月GP       = Σ 同角色同人、计算月=M、本锁定期内未锁定行的计算用GP
达标金额     = 该 (生效版本, 等级) 的梯度1 达标金额
本月达标     = 梯度1 已填 且 本月GP ≥ 达标金额
本月点数     = 达标时：在已填档中取 threshold ≤ 本月GP 且档号最大的点数（可到梯度2～10）
               未达标或梯度1 未填：点数 = 0，本月所有行提成 = 0
行提成       = Round(计算用GP × 本月点数 / 100, 2)
```

梯度1 达标金额填 **0**：本月 GP ≥ 0 即达标（计算用 GP 已是 max(出库,0)，通常即有参与行就达标）。  
第 2 层「是否达标」只用梯度1，与上面同一口径。

### 6.2 计算用 GP

```text
出库GP     = 池行/快照 profit_out_biz_usd（可负）
计算用GP   = max(出库GP, 0)
```

列表「GP」显示原值；`gp_usd` 存原值；月合计与行提成只用计算用 GP。

### 6.3 行归哪一个自然月（避免 Other 翻开已锁月）

| 行类型 | 计算月 | 原因 |
| --- | --- | --- |
| **Base** | **出库日** 的年月 | 正常批次跟货走的月 |
| **Other** | **核销完成日** 的年月 | 补漏算在「钱收齐」的月；不把已锁的出库月重开 |

同一锁定期内，2 月、3 月各算各的档。例如 2 月 GP 够、3 月不够：2 月行按 2 月点数发，3 月行金额 **0**。

Other 行若核销在 3 月，只进入 **3 月** 的本月 GP，与 3 月 Base 行加在一起取档。

### 6.4 算例

业务员，4 月 2 日将锁的本期。等级档：0→3.0%，1000→5.0%。

| 行 | 类型 | 出库日 | 核销日 | 出库GP | 计算月 | 计算用GP |
| --- | --- | --- | --- | --- | --- | --- |
| A | Base | 2/10 | 2/20 | 800 | 2026-02 | 800 |
| B | Base | 3/05 | 3/10 | 400 | 2026-03 | 400 |
| C | Other | 1/15 | 3/18 | 300 | 2026-03（核销月） | 300 |
| D | Base | 3/20 | 3/22 | −100 | 2026-03 | **0** |

- 2 月 GP = 800 → 3.0% → 达标。A 提成 = 24.00  
- 3 月 GP = 400+300+0 = 700 → 3.0% → 达标。B = 12.00，C = 9.00，D = 0  
- 第 2 层两行：2 月达标 24.00；3 月达标 21.00  
- 第 1 层该人预计合计 45.00  

若 3 月只有 D（计算用 0）且无其它行：3 月 GP = 0，点数 0（第 1 档若为 0 则仍 3.0% 但金额 0）。第 1 档门槛若是 300，则 3 月 700 达标、若只有 200 则整月 0。

### 6.5 结果列

动态 / 锁定行增加（或明确语义）：

| 列 | 说明 |
| --- | --- |
| `calc_month` | `yyyy-MM`，§6.3 |
| `period_gp_usd` | **该计算月** 的计算用 GP 合计（不再是双月合计） |
| `rate_points` | **该月** 点数 |
| `commission_usd` | 该行提成 ≥ 0 |

锁定仍按 §4 整期一次切，**不是**按自然月 2 日锁。正式行带 `term` + `calc_month`。

## 7. 预计扫描

每日 / 手工重算，对下一锁定日 `L`：

```text
池行核销完成
且 该侧未正式提成
且 (Base 或 Other，§4)
→ 写入/覆盖 dynamic（按角色拆行）
```

未核销、核销未完成、本期末核销的行 **不进动态**，仍留在池里供第 3 层「未参与」若产品要看；第 3 层默认只列 **本月参与计算** 的池行（已写入 dynamic 或满足 Base/Other 且计算月=该月）。

## 8. 三层页面

业务预计、采购预计、业务正式、采购正式 **同一套三层**（正式第 2 层多账期/term 筛选，默认最近已锁期）。

| 层 | 路由（业务预计示例） | 一行 | 主要列 |
| --- | --- | --- | --- |
| 1 | `/commission/estimated/sales` | 一个业务员 | 等级、参与月数、各月 GP 合计、预计提成合计 |
| 2 | `/commission/estimated/sales/:userId` | 一个自然月 | 计算月、是否达标、本月 GP、本月点数、本月提成、出库行数 |
| 3 | `.../:userId/months/:yyyyMM` | 一条池行 | 出库日、单号、核销、GP、计算月、点数、提成、Base/Other |

双击进入下一层；第 3 层双击做出库详情（有库存权限）。列表壳继续业务列表规范。采购、正式对称改路由。

第 1 层「提成合计」= 各月提成之和（未达标月贡献 0）。

---

## 9. 参数、Job、门控

参数只留系数版本 + 等级档。删除延期天数字段与维护项。

Job：每天重算动态；偶数月 2 日先动态后锁定本期 Base/Other 行；锁定时回写池两侧状态。  
门控不变：两管理员/旁路看全部；其余 `.read` 只看本人。

## 10. 相对现网表：改什么

| 是否改表 | 项 |
| --- | --- |
| **新建** | 提成数据池（事实 + 核销 + 两侧正式标记） |
| **改语义 / 加列** | `dynamic` / `locked` 增加 `calc_month`；`period_gp_usd` 改为月合计 |
| **不建** | 月汇总表（第 2 层 GROUP BY 即可） |
| **删除配置** | `receipt_writeoff_delay_days` |
| **不改** | 锁定仍按双月 `term` 切，不是按自然月切 |

三层导航 **单独不要求** 新结果表；按月达标是 **计算规则** 变了，所以行上必须能落到 `calc_month`。
