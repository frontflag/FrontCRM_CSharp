## 1. 目标与非目标

**目标**

1. `stock_out_item` 具备业务单号 `{出库单号}-{行序号}`。
2. 装箱三处「流程」出库站按装箱行对齐真实出库明细，展示出库单号、出库明细单号、本行数量。

**非目标（本方案不排期）**

- 装箱批量出库幂等拦截
- 销售行 / 出库通知 / 拣货站数量改为装箱行数量
- 出库明细独立详情页

---

## 2. DDL 与回填

### 2.1 列

表 `stock_out_item`（实体 `StockOutItem`，主键列 `ItemId`）：

| 列 | 类型 | 说明 |
|----|------|------|
| `stock_out_item_code` | `varchar(64)` | 出库明细单号；新单必填；回填前可空 |

实体属性：`StockOutItem.StockOutItemCode`，`[Column("stock_out_item_code")]`，`[StringLength(64)]`。

### 2.2 回填

按出库单分组，组内 `CreateTime` 升序、`ItemId` 升序：

```text
stock_out_item_code = {stock_out.StockOutCode}-{行序号}
行序号从 1 起，含软删行
跳过 StockOutCode 为空的头（不应出现；若有则记日志不赋号）
```

### 2.3 索引

回填完成后：

```text
UNIQUE INDEX UX_stock_out_item_code
  ON stock_out_item (stock_out_item_code)
  WHERE stock_out_item_code IS NOT NULL AND btrim(stock_out_item_code) <> ''
```

（PostgreSQL 部分唯一；若项目惯用全表唯一且回填保证无空，可用普通 UNIQUE。）

### 2.4 迁移

- EF：`CRM.Infrastructure/Migrations/{时间戳}_StockOutItemCode.cs`
- 步骤：加可空列 → 回填 SQL → 唯一索引
- 新写入在应用层保证非空；**不**在首版对列加 `NOT NULL`（避免未覆盖的写入路径发布瞬间失败）。第二迭代若写入点已收口，再收紧非空。

## 3. 应用层

### 3.1 编号

```text
OrderLineItemCodes.StockOut(stockOutCode, seq)
  → seq>0 且单号非空则 "{code}-{seq}"，否则 ""
```

单测：与 `Sell` / `StockIn` 同文件风格。

### 3.2 写入

| 路径 | 赋号时机 |
|------|----------|
| `ExecuteStockOutAsync` 拣货行循环 | 第 i 条（从 1） |
| 同方法 FIFO 兜底（若仍可达） | 接续序号 |
| `InternalTransferPostingKernel` 虚拟出库 | 固定 `-1`（单行） |

禁止只 `new StockOutItem` 不赋号。

### 3.3 列表 / API

- `StockOutItemListRowDto.StockOutItemCode`
- `StockOutItemListQuery` 增加可选 `StockOutItemCode` 子串（或并入现有出库单号框，实施时二选一，默认**独立筛选**以免和单头号混淆）
- `StockOutItemEfListQuery` 同步
- 出库明细列表列、出库单详情行表、明细导出 CSV

### 3.4 流程出库站

1. 新增查询：按 `packingItemId` → 拣货行 Id 集合 → `stock_out_item.picking_task_item_id` IN … → JOIN `stock_out`（排除已删、建议排除调拨类型 `StockOutType=3`）。
2. Store 绑定装箱行后写入 extras（如 `stockOutLines`）。
3. `buildPackingItemFlowStations` 出库站**只**用 extras；禁止再按 `packingCodes` 回退销售行全量单头。
4. 卡片：出库单号、出库明细单号、本行数量。
5. 装箱明细列表 / 装箱单列表 / 装箱详情共用，一处改三处对。

## 5. 上线顺序

1. 部署 API（含迁移）→ **必须先于**只发前端的 P3。  
2. P1+P2 可同一发布；P3 可紧随或下一版。  
3. 迁移窗口：回填为单次 SQL，行数与出库明细存量同级，一般可在发布时同步执行。  
4. 无需新权限码、无需强制全员重新登录。  
5. 发布后抽查：一笔历史多行出库单编号连续；一笔新装箱出库立即有 `-1`。

---

## 6. 风险

| 风险 | 处理 |
|------|------|
| 漏写路径产生空号 | P1 后搜 `new StockOutItem`；空号不进唯一冲突（部分索引），但流程显示「—」 |
| 回填与在途出库并发 | 发布时短暂停写或接受极少数空号后手工补 |
| 流程改完仍见多张卡 | 数据上确有重复出库，属如实展示，不是回归失败 |
| 无拣货历史行 | 出库站空，符合口径 |
