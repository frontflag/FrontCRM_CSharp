## 0. 背景与产品定稿

| 项 | 说明 |
|----|------|
| 现象 | 如 `CDS00002`：已完成 + 已结关。单头快照 `broker_agency_rate = 1.025000`（历史参数），报关公司主数据已改为 `1.003000`。页头正确显示历史参数；费用面板「保存」因 `preserveAgency` **不会**把主数据费率写入本单 |
| 根因 | 锁定/已完成下管理员试算故意保留代理费率快照，避免改采购美金价/补杂费时误改账单费率 |
| **要做** | 正式功能：管理员可主动「从报关公司刷新代理费率」→ 写单头 → 全单重算 → **必须**回写到货/入库/库存成本（与采购美金价更正相同级联） |
| **不做** | 恢复页头代理费率「系统/手工」自由编辑；非管理员刷新；作废单可改；自动冲财务应付/发票；批量刷全部历史单（本期仅单张详情入口；批量可另开需求） |

**定稿答复（2026-09-30）：**

1. 已完成/已结关管理员可刷新代理费率并重算 → **要做**  
2. 刷新后必须回写到货/入库/库存成本 → **必须**  
3. 正式功能（非一次性运维脚本）→ **要做**

## 1. 目标

1. 在费用已锁定（已结关）或内部状态已完成时，**SYS_ADMIN / SYS_MANAGER** 可将本单代理费率刷新为**当前绑定报关公司**主数据 `agency_rate`，并重算费用链。  
2. 重算成功后走与采购美金价更正同一套 `CascadeDeclarationItemAsync`，回写到货通知成本、报关入库明细、在库 `stock_item` 采购价（P1）。  
3. 写入变更日志：**必记动作「刷新代理费率自报关公司」及刷新前后费率数值**（即使数值未变也留痕迹）；若清除手工标记另记 `agencyRateManual`。  
4. 未锁定且可正常维护费用的单据：现有「保存」已会按主数据覆盖费率，**不必**依赖本按钮；按钮可隐藏或禁用并提示「请直接保存」。  
5. 页头显示规则不变：刷新并保存成功后，快照等于主数据，仍旁注「(历史参数)」（表示已落库快照，不是「未试算的当前参数预览」）。

## 3. 业务规则

| 项 | 约定 |
|----|------|
| 可见/可点 | 费用面板处于 **结关锁定** 或 **已完成**，且当前用户 `canCorrectLockedCostUsd`（SYS_ADMIN / SYS_MANAGER），且物流可写、未作废、未脱敏屏蔽费用 |
| 费率来源 | 本单 `customs_broker_id` 对应 `customs_broker.agency_rate`（须 > 0）；无效则拒绝并提示「报关公司代理费率无效」 |
| 写入 | `broker_agency_rate = 主数据费率`；`agency_rate_manual = false`（若原先为 true 一并清掉并记日志） |
| 重算 | 全单费用链与常规试算相同（含手工采购美金价行仍走手工公式）；**本路径不** `preserveAgency` |
| 下游 | `cascadeInbound: true`（固定；前端不可关掉本操作的回写） |
| 与现有保存关系 | 管理员在锁定/已完成下改采购美金价或杂费再「保存」→ **仍** `preserveAgency`（行为不变）。仅点本功能按钮才刷新费率 |
| 费率已相同 | 仍允许执行：重算 + 级联（可提示「费率已与报关公司一致，将按当前费率重算并回写下游」）；避免「主数据未变但明细曾被旁路改坏」无法修复 |
| 作废 | 拒绝 |
| 未试算（`fees_calculated_at` 空）且未锁定 | 不展示本按钮；用普通保存即可 |

## 4. 后端（阶段 A / B）

### 4.1 `RecalculateDeclarationFeesAsync`

文件：`CRM.Core/Services/CustomsV2FlowService.cs`、`ICustomsV2FlowService.cs`

新增参数（建议命名）：

```csharp
bool refreshAgencyRateFromBroker = false
```

逻辑调整（在现有 `preserveAgency` 判定处）：

```text
preserveAgency =
  canCorrectLockedCostUsd
  && dec.BrokerAgencyRate > 0
  && (FeesLocked || Completed)
  && !refreshAgencyRateFromBroker;   // 新增：显式刷新时关闭保留
```

当 `refreshAgencyRateFromBroker == true`：

1. 门控：须 `canCorrectLockedCostUsd == true`，且（`FeesLocked` 或 `InternalStatus == Completed`）；否则抛明确错误（如「仅已结关或已完成报关单可由管理员刷新代理费率。」 / 「无权刷新代理费率。」）。  
2. 读取报关公司；`agency_rate` 无效则拒绝。  
3. **变更日志（强制，见 §4.3）**：点击并确认刷新后，无论费率是否与主数据相同，均须落库记录**动作 + 数值**（操作人、时间、原费率、新费率）。  
4. 赋值后走现有试算循环；成功后 **必须** `cascadeInbound: true` 路径调用 `CascadeDeclarationItemAsync`（与采购美金价更正相同）。  
5. 返回 DTO 仍含下游回写计数（arrival / stockIn / stockItem），供前端提示。

未传刷新标志时，行为与现网完全一致。

### 4.2 API

`POST /api/v1/customs-declarations/{id}/recalculate-fees`

`RecalculateFeesRequest` 增字段：

| 字段 | 类型 | 默认 | 说明 |
|------|------|------|------|
| `refreshAgencyRateFromBroker` | bool | false | true = 从报关公司刷新费率后再试算 |
| `cascadeInbound` | bool | true | **本功能前端固定传 true**；若 refresh=true 且 cascade=false，服务端应拒绝或强制 true（推荐 **强制 true**，避免误关回写） |

权限：沿用现接口（模块访问 + 物流可写 + `CanCorrectAsync` → `canCorrect`）。`refreshAgencyRateFromBroker=true` 且 `canCorrect=false` → 业务异常/403。

可选（更清晰）：单独 `POST …/refresh-agency-rate` 内部调同一服务方法。**推荐扩展现有 recalculate**，少一个入口，与「保存=试算」心智一致。

### 4.3 变更日志（动作 + 数值，强制）

用户点击并确认「刷新自报关公司」后，**必须**写入 `log_change_fldval`（详情页「变更日志」可见），记登录操作人与时间。对象码 = 报关单号。

| fieldName | 标签（中文） | 旧值 / 新值 | 何时写 |
|-----------|--------------|-------------|--------|
| `refreshAgencyRateFromBroker` | 刷新代理费率自报关公司 | 旧：刷新前单头 `broker_agency_rate`（6 位）；新：报关公司当前 `agency_rate`（6 位）。两端格式与页头一致，如 `1.025000` → `1.003000` | **每次确认刷新成功均写一条**（即使旧值=新值，也要留下「执行过该动作」的痕迹） |
| `brokerAgencyRate` | 代理费率 | 同上旧/新 | 费率实际发生变化时另写（或与上条合并为一条——**推荐只写上表动作字段一条**，避免重复；若合并，标签用「刷新代理费率自报关公司」，数值仍为旧→新费率） |
| `agencyRateManual` | 代理费率手工 | `是`→`否`（或 true/false 与现网头字段日志一致） | 仅当刷新前为手工且被清为 false |

**推荐落地口径（避免双条重复）：**

1. **必写 1 条动作日志**：`fieldName = refreshAgencyRateFromBroker`，标签「刷新代理费率自报关公司」，`oldValue`/`newValue` = 刷新前后代理费率数值。  
2. 若同时清除手工标记：再写 1 条 `agencyRateManual`。  
3. **不要**再重复写一条仅标签为「代理费率」的同类数值日志（除非与现网其它改费率入口必须统一，则动作条可省略、改为强制 `Append` 而非 `AppendIfChanged`——二选一，实现时取「动作条必写」即可）。

详情页现有 `GET …/change-logs` 聚合即可展示，无需新 API。QA 验收须核对：确认刷新后日志出现动作 + 旧/新费率。

### 4.4 单测（建议）

| 用例 | 预期 |
|------|------|
| 已完成 + 管理员 + refresh=true，主数据 1.003、快照 1.025 | 单头→1.003；代理费按 (货款+关税+增值税)×0.003；级联被调用 |
| 同上 + 非管理员 | 拒绝 |
| 已完成 + 管理员 + refresh=false（改价保存路径） | 仍保留 1.025 |
| 已作废 + refresh=true | 拒绝 |
| refresh=true 且主数据费率无效 | 拒绝 |
| 处理中未锁定 + refresh=true | 拒绝或 no-op 策略按 §3（建议拒绝「仅锁定/已完成可用」） |

## 5. 前端（阶段 C）

文件：`CustomsDeclarationFeesPanel.vue`、`api/customs.ts`、i18n

### 5.1 入口

代理费率只读值右侧（锁图标旁）：

- 按钮文案建议：**刷新自报关公司**（i18n：`customsPages.fees.btnRefreshAgencyRate`）  
- 仅 `canCorrectLocked && (isLockedPartial \|\| isCompletedReadonly)` 显示  
- 可选副文案：展示主数据费率 `brokerMasterAgencyRate`（若与历史不同，用次要色提示「公司当前 1.003000」）

### 5.2 交互

1. 点击 → `ElMessageBox.confirm`：说明将把本单代理费率从 **当前快照** 改为 **报关公司当前费率**，并重算费用、**回写到货/入库/库存**。  
2. 确认 → 调用 `recalculateCustomsDeclarationFees(id, { refreshAgencyRateFromBroker: true, cascadeInbound: true })`（可先 PATCH 其它脏字段策略：**本按钮只做刷新费率重算**，不自动提交未保存的杂费/手工价草稿；若有未保存草稿，先警告「请先保存或放弃其它修改」——推荐，避免一次动作语义不清）。  
3. 成功 → `emit('refresh')`；提示含下游条数（复用采购美金价成功文案结构）。  
4. 锁图标：执行本操作时代理费率**会被改写**，故在「仅展示本按钮的模式」下，代理费率锁可保持（表示普通保存不改）；或点击刷新成功后仍显示历史参数旁注。

### 5.3 与「保存」分工

| 动作 | 代理费率 | 下游 |
|------|----------|------|
| 普通保存（锁定/已完成管理员） | 保留快照 | 改价/改杂费时回写 |
| **刷新自报关公司** | 主数据覆盖快照 | **必须**回写 |

## 7. 验收用例（开发自测）

以 `CDS00002` / 利物通（主数据 `1.003000`）为例：

| # | 步骤 | 期望 |
|---|------|------|
| 1 | SYS_ADMIN 打开已完成单，见「刷新自报关公司」 | 普通物流账号不可见 |
| 2 | 确认刷新 | 页头代理费率 → 1.003000（历史参数）；代理费、价税、P1 变化；成功提示含下游回写；**变更日志**有「刷新代理费率自报关公司」且旧/新值为 1.025000 / 1.003000 |
| 3 | 再改杂费点保存 | 代理费率仍为 1.003（不被主数据二次意外覆盖以外的逻辑破坏；仍 preserve） |
| 4 | 公式演示⑤ | 与表格代理费一致；与公司 0.3% 综合费率对照行不再因 2.5% 历史费率长期红字（若综合费率写死 0.3% 且主数据亦 0.3%） |
| 5 | 非管理员调 API refresh=true | 拒绝 |
| 6 | 费率已与主数据相同再点刷新 | 仍写一条动作日志（旧值=新值）；可重算并回写 |

## 8. 风险与说明

| 风险 | 处理 |
|------|------|
| 刷新后 P1 下降/上升影响已入账成本 | 确认框明示；不自动冲应付；与采购美金价更正同一业务责任边界 |
| 主数据再次改费率 | 本单不会自动跟；需再次点刷新 |
| 与「报关公司公式 0.3%」演示 | 刷新后系统⑤应接近公司公式；演示红字仅在两套费率仍不一致时出现 |
| `agency_rate_manual` 历史 true | 刷新强制 false，并记日志 |
