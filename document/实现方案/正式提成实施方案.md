正式提成 = **锁定表** `commission_locked`。偶数月 2 日 0:00（`Asia/Shanghai`）把动态表中入池日属于上一完整双月的行 **复制冻结**。锁定后不回滚、不随改档/反核销变化。

---

## 0. 本期锁定的口径

| # | 议题 | 锁定 |
| --- | --- | --- |
| 1 | 锁定窗口 | 总设计 §3.2：按 **入池日** 切上一完整双月。不是「锁上一自然月」，也不是「锁当前动态全部」。 |
| 2 | 账期标签 `term` | 窗口 **结束月** 的 `yyyyMM`（如 2025-12-01～2026-01-31 → `202601`）。 |
| 3 | 金额 | **原样复制** 动态行的 GP / 点数 / 提成 / 等级 / `version_id`，锁定 Job **不再取档**。 |
| 4 | 不重复正式提成 | **已正式提成过的出库行，该角色不允许再入预计、再锁一次。** 销售正式与采购正式 **分开**：同一 `stock_out_item_id` 可以各有一行；一侧锁了不影响另一侧。判定只看 `commission_locked` 是否已有 `(role_type, stock_out_item_id)`，不在出库单上打标。 |
| 5 | 门控 | 与预计提成相同：两管理员/旁路看全部；其余 `.read` 只看本人。 |

入池日、延期、取档定义以预计提成实施方案为准。本阶段不重算钱。

## 1. 范围

| 做 | 不做 |
| --- | --- |
| 表 `commission_locked` | 反核销回滚已锁行 |
| 偶数月 2 日锁定 Job | 改系数后重算已锁行 |
| 业务正式 / 采购正式列表 | 财务手工加减、补发 |
| 管理员补跑指定账期（幂等） | EBS Formal 全套调整单 |

未到锁定日的行一直留在动态表（含很久才收款、或收款后延期未满的行）。

## 2. 双月窗口（纯函数）

偶数月：2 / 4 / 6 / 8 / 10 / 12。  
**锁定时刻：** 该月 2 日 0:00 上海。

| 锁定触发日 | 入池日落入（闭区间，上海） | `term` |
| --- | --- | --- |
| 2月2日 | 上年 12/1 ～ 本年 1/31 | 本年 `01` |
| 4月2日 | 2/1 ～ 3/31 | 本年 `03` |
| 6月2日 | 4/1 ～ 5/31 | 本年 `05` |
| 8月2日 | 6/1 ～ 7/31 | 本年 `07` |
| 10月2日 | 8/1 ～ 9/30 | 本年 `09` |
| 12月2日 | 10/1 ～ 11/30 | 本年 `11` |

2 日 **当天及之后** 才首次入池的行（`pool_date >= 锁定日`）进入 **下一个** 开放双月，不补进本次 `term`。

例（总设计验收 #9）：3 月出库、4 月 10 日才收款完成且延期已满足 → `pool_date` 约 4 月 11 日（delay=0 则为 4 月 11 日）→ 入 4–5 月开放窗，**6 月 2 日**锁定，不进 4 月 2 日那批。

与预计提成共用 `CommissionTerm` 纯函数：`GetWindow(lockDate)`、`GetOpenWindow(today)`、`FormatTerm`。单测覆盖闰年 2 月末、12→1 跨年。

## 3. 锁定步骤

偶数月 2 日（或手工指定 `lockDate`）：

1. **先跑动态重算**（计算日 = 锁定日上海日历）。保证前一日刚满足延期的行已在动态表。  
2. 算窗口 `[from, to]` 与 `term`。  
3. 从 `commission_dynamic` 选出 `pool_date ∈ [from, to]`。  
4. 对每一行：若 `commission_locked` 已有 `(role_type, stock_out_item_id)` → 跳过；否则 INSERT 快照 + `term` + `locked_at`。  
5. 从动态表 **删除** 本批成功锁定的业务键。  
6. 写水位，防止同日重复切（手工补跑只补「窗口内尚未锁定」的键）。

事务：按角色分批提交亦可，但同一业务键必须「插入锁定 + 删除动态」同事务。

不满足窗口的动态行原样保留。

### 3.1 不可变

已锁行禁止：反核销删除、改 GP、改点数、改归属、改 `term`。反核销只影响次日动态。改档、切生效版本不影响已锁行。

## 4. 数据

**表：** `public.commission_locked`  
**业务键：** `UNIQUE (role_type, stock_out_item_id)` —— 这就是「哪些出库行已正式提成」的唯一登记。  
另：`INDEX (role_type, term, user_id)`  
脚本：`scripts/commission_locked_schema.sql` + 迁移（建议 `20260909130000_CommissionLocked`）。禁止 SQL `{{`。

不在 `stock_out_item` / `stock_out_item_extend` 增加「已提成」标记。查询是否已正式提成：

```text
销售已正式提成 ⇔ EXISTS commission_locked WHERE role_type = 1 AND stock_out_item_id = ?
采购已正式提成 ⇔ EXISTS commission_locked WHERE role_type = 2 AND stock_out_item_id = ?
```

列 = 动态表全部业务列（金额、单号、日期、等级、版本、点数）+：

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `term` | `char(6)` | `yyyyMM`，窗口结束月 |
| `locked_at` | `timestamptz` | 锁定时刻 |
| `lock_date` | `date` | 锁定日（上海） |

`version_id` / `rate_points` / `commission_usd` 是快照，**不** FK 强制版本仍存在（版本以后停用也要能读历史）。

## 5. Job

| 项 | 值 |
| --- | --- |
| 类 | `CommissionLockHostedService` |
| Cron 语义 | 上海 `0 0 2 2,4,6,8,10,12 *` |
| 实现 | 每分钟醒一次；仅当上海日为偶数月 2 日且该 `term` 尚未切完时执行 |
| 顺序 | 内部先调动态 Calculator，再切锁定 |
| 手工 | `POST /api/v1/commission/official/lock`，body 可带 `lockDate`（默认今天）；仅两管理员 |

水位建议与动态 Job 共用 `commission_job_watermark`（`dynamic_job_date`、`lock_term`），避免两 Job 抢跑。

不用 Hangfire。时区同预计提成。

## 6. API

建议 `CommissionOfficialController`，`/api/v1/commission/official`。

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `?roleType=1&term=` | `commission-official-sales.read` / purchase | 明细分页 |
| GET | `/summary?roleType=&term=` | 同上 | 按人汇总 |

无改金额接口。

## 9. 实现顺序

1. `CommissionTerm` 单测（表中 6 个触发日 + 跨年）  
2. `commission_locked` 脚本/迁移  
3. `CommissionLockService`（依赖动态表已有数据）  
4. Lock Job（先动态后锁定）+ 手工 lock  
5. GET terms / summary / list  
6. 两页列表  
7. 帮助、i18n  
8. 浏览器：2 日窗口内行动到正式、动态消失；窗口外仍在预计；再跑 lock 行数不变；改档后正式金额不变；反核销后正式仍在  

QA：`document/QA/财务/正式提成-测试对照说明.md`（先读总纲）。金额：窗口内足额入池行锁定成功；未入池/窗口外拒绝进入该 `term`。无超额核销拆锁定。

## 10. 与预计提成 / EBS

```text
出库+核销+延期 → 动态表（每天覆盖） → 偶数月2日按入池日切上一双月 → 锁定表
```

- 正式不是「再算一遍」，是 **快照搬家**。  
- 不平移 EBS Formal 的扣补、转正审批、方案版本。  
- 导出、按日取级 API 若列表已够用可留 M4。
