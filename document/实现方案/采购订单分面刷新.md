## 本轮补加（相对「只拆六分面」）

| 补加 | 用户能感知到什么 | 口径要点 |
|------|------------------|----------|
| **已完结按分面控制** | 采购参数左栏「分面刷新」五个开关；详情刷新前若有已完结单据会列出，确定才改 | 关 → 整面拦住。开 → 必须确认。刷新状态不看开关。供应商默认**关**（沿用现网：改已完结单据上的供应商风险高）；型号/品牌/数量/单价默认**开**（上线前本来就会覆盖，避免一上线全拦住） |
| **详情须确认才覆盖已完结** | 警告框列出到货已入库、入库已过账等；取消不刷新 | `POST …/refresh/preview` 后，确定才带 `confirmCompleted=true` |
| **编辑换供应商 ≠ 详情刷新供应商** | 编辑保存仍是「无法保存 / 刷新并保存」 | 编辑走原换供应商 `ApplyAsync`，**不**套详情的 `confirmCompleted`。参数关时已完结且供应商不一致仍不能保存 |
| **空旧堆清理** | 刷新型号/品牌结果里多「删除空汇总 N」 | N = 去掉了几条**已经没有库存明细、数量也是 0** 的库存汇总行。不是删库存数量。旧堆上还有别的明细则保留 |
| **刷新全部** | 无入口 | 本版不做 |

## 第一期：分面入口 + 展示层身份

### 1.1 做了什么

- 详情主按钮改为「刷新状态」；下拉：供应商、物料型号、品牌、数量、单价。
- `POST /api/v1/purchase-orders/{id}/refresh`，`facet=status|vendor|pn|brand|qty|price`。
- 旧 `refresh-item-extends` **兼容，等价 price**。
- `PurchaseOrderItemRecalculateOptions`：`Default` / `StatusOnly` / `QtyPlanOnly`。详情刷新状态 / 单价之后走 `StatusOnly`，不再偷偷改到货品牌/价/量。
- 刷新数量：只收缩超量**单批次**到货计划量，再 `StatusOnly`。
- 刷新单价：现网下游采购价覆盖 + `StatusOnly`，**不再**顺带写品牌。
- 刷新型号 / 品牌：覆盖到货 `Pn`/`Brand`、入库 `PurchasePn`/`PurchaseBrand`、装箱 `Pn`/`Brand`、报关 `purchase_pn`/`purchase_brand`。
- Debug「刷新采购订单状态」改为 `facet=status`。

### 1.2 第一期明确不做

库存 `stockitem.purchase_pn` / `purchase_brand` 分桶键（改键要换 `StockAggregateId`、重算桶数量与备货可用量）→ 第二期。

## 第二期：库存分桶

### 2.1 做了什么

- `PurchaseOrderIdentityDownstreamSyncService` 写库存明细 PN/品牌后调用 `StockItemPurchaseIdentityRebucketService`。
- 同桶：只对齐汇总行文案。跨键：并入已有桶或新建 `stock`（`ModuleCodes.Stock`，先 `SaveChanges`），改 `StockAggregateId`，**不改** `StockItemCode`。
- 重算旧/新桶数量；对涉及的 (PN, Brand) 重算备货可用量。
- 本期末删空桶（第四期软删）。结果增加 `stockItemsMoved` / `stockAggregatesCreated`。
- 前端确认改为警告；结果摘要含换堆 / 新建汇总。帮助与 QA 同步为「会改分堆」。

### 2.2 关键文件

| 层 | 路径 |
|----|------|
| Facade | `CRM.Core/Services/PurchaseOrderService.cs` → `RefreshDownstreamAsync` |
| Recalculate | `PurchaseOrderItemExtendSyncService` |
| 身份 | `PurchaseOrderIdentityDownstreamSyncService` |
| 换桶 | `StockItemPurchaseIdentityRebucketService` |
| 单价 | `PurchaseOrderPurchasePriceDownstreamSyncService` |
| 供应商 | `PurchaseOrderVendorChangeService` |

## 第三期：按分面控制已完结节点

### 3.1 做了什么

- 采购参数页（原「刷新供应商」路由/权限）改为五个开关：供应商默认关；型号/品牌/数量/单价默认开。
- 详情非状态分面先预检。参数关且有已完结 → 整面阻断。参数开且有已完结 → 警告列出单据，用户确定后 `confirmCompleted=true` 才执行。
- 刷新状态不走此门控。编辑换供应商保存不套详情确认标志。
- 旧布尔参数与 JSON 分面参数同步（供应商）。

### 3.2 关键接口

- `GET/PUT /api/v1/purchase-params/refresh-completed-facets`
- `POST /api/v1/purchase-orders/{id}/refresh/preview`
- `POST …/refresh`、`POST …/refresh-vendor-name` body `confirmCompleted`

---

## 第四期：空汇总行清理

换堆并重算后：旧库存汇总已无未删除在库明细、且数量字段全 0 → 软删汇总行（库存中心不再列出）。目标堆仍有明细则保留。结果增加「删除空汇总」计数（`stockAggregatesRemoved`）。

仍挂有明细的旧堆（哪怕数量为 0）**不删**。库存明细编号不变。
