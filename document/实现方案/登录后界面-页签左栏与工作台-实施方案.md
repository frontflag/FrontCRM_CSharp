# 登录后界面本次改动 — 实施方案

**状态：** 已实施（2026-10-03）  
**范围：** 顶栏页签跟当前页、无内容左栏不占宽、工作台金额不叠字  
**代码：** `CRM.Web/src/layouts/AppLayout.vue`、`CRM.Web/src/components/Dashboard/DashboardOverviewPanel.vue`  
**不做：** 英文菜单 `Buz`、筛选去重、供应商数据质量条、报价分页、客户详情页签降层、待审批改卡片、帮助栏默认关闭、取消多页签

无新表、无 DDL、无新权限。只改前端，刷新即可。

---

## 0. 结论

| 项 | 做法 |
|----|------|
| 顶栏页签 | 仍保留已打开的页。地址变了，高亮必须是当前页；当前页必须出现在这一排，放不下的更早页签进「...」 |
| 左栏 | 有检索/漏斗的页保持现在的开关。没有模块内容的页不占宽，也不去改全局的「左栏已打开」 |
| 工作台金额 | 五格仍在一行。格子里的数字换行，禁止画到旁边一格上 |

## 1. 顶栏页签

位置：`AppLayout.vue` 的用户 id 恢复、`recalcTabOverflow`、`visibleTabs`。

### 1.1 高亮跟地址

用户 id 从空变为有效时，现在会读回上次高亮。只要那条还在页签列表里，就不会改成当前地址。主区已经是库存，蓝条仍在 RFQ List。

改这一处：恢复完列表后，**一律** `activeTab = route.path`。当前地址不在列表里时仍追加一条，再高亮它。不要再用「存储里的高亮还在列表中就保留」。

路由 `watch` 里已有「进入新地址就高亮」的逻辑，保持不动。账号切换时只留当前页，也保持不动。

### 1.2 当前页留在这一排

`visibleTabs` 现在是 `tabs.slice(0, n)`，新页签在末尾，宽不够就进「...」。眼睛仍看见 My Desktop、Customers、RFQ List。

显示窗口改成包含当前页，**不改** `tabs` 的存储顺序：

1. 按现有宽度估出能放下的个数 `n`。
2. 当前页下标 `< n`：仍显示前 `n` 个。
3. 当前页下标 `≥ n`：显示以当前页结尾的 `n` 个，例如下标 `n-1 … active`。
4. 「...」里是没进窗口的页，顺序与 `tabs` 相同。点「...」里的一项仍走现有 `activateTab`。

拖拽排序、关闭、右键关闭的对象仍是完整 `tabs`，不要改成只对可见窗口操作。

## 2. 左栏

`leftPanelVisible` 存在 `frontcrm_workspace_layout_v1`，**全站一份**。进入仪表盘时若写成 `false`，再到客户列表，检索栏也会被关掉。所以空页不写这个值。

### 2.1 去掉开发文案

`AppLayout.vue` 左栏 `v-else` 里的这句删掉：

`子页面可 inject(WorkspaceLayoutKey)；或 window 派发 workspace:toggle-left / workspace:toggle-right`

换成 i18n：`此页没有快捷筛选` / `No shortcuts on this page`。无内容时整栏不显示，这句只在用户主动打开该页左栏时出现。

### 2.2 有内容 / 无内容

沿用现有 `show*SearchPanel`、`show*FavoritePanel` 等条件，收成一个计算属性 `leftPanelHasModule`。为 true 的路由至少包括：客户、供应商、需求、报价、销售订单、采购订单，以及已经挂了左栏队列的审批桌面、核销桌面、邮件。

为 false 的路由（本次必须收起占位）：仪表盘、库存列表、待审批列表、个人设置、应收列表。其它尚未挂左栏模块的页同样视为无内容。

### 2.3 占宽规则

实际是否渲染左栏：

- 有模块：仍看 `leftPanelVisible`（用户原来的开关和记忆）。
- 无模块：默认不渲染、宽度为 0。顶栏左按钮仍可打开；打开后只显示 2.1 的空态，并只记在**当前路由**上。离开该路由不改全局 `leftPanelVisible`。

记忆键与 `frontcrm_aux_tabs_by_route_v1` 分开，例如 `frontcrm_left_panel_forced_by_route_v1`：只记录用户在无模块页上主动打开过的路由名。未记录的无模块页一律不占宽。

## 3. 工作台金额

位置：`DashboardOverviewPanel.vue` 的 `.overview__kpis`、`.kpi`、`.kpi__value`。

现状：一行五格，`minmax(0, 1fr)`，数字 `overflow` 可见。左右栏都打开时主区变窄，On hand 与 Receivable 叠在一起。折行断点写的是视口 900px，主区比视口窄，断点不起作用。

改动：

- `.kpi` 设 `overflow: hidden`。
- `.kpi__value` 允许换行（`overflow-wrap: anywhere`），不要单行溢出。
- 五格改用容器查询：网格容器窄于约 720px 时改为两列。不要改成上下两套卡片，也不要改金额口径。

## 4. 验收

| # | 步骤 | 通过 |
|---|------|------|
| 1 | 先打开桌面、客户、需求，再从菜单进库存或待审批 | 蓝条在当前页签上；当前页签在这一排里，不在「...」里 |
| 2 | 刷新停在库存的页 | 高亮仍是库存，不是上次的 RFQ |
| 3 | 页签多于一排能放下的个数时点「...」里的旧页 | 打开该页，且该页签进入这一排 |
| 4 | 拖拽页签、关闭其它页 | 顺序和关闭结果与改前一致 |
| 5 | 客户列表、销售订单、采购订单 | 左栏检索/漏斗仍按用户原来的开关显示 |
| 6 | 仪表盘、库存列表、待审批、个人设置、应收 | 左栏默认不占宽；按钮打开后只有「此页没有快捷筛选」，没有 inject 字样 |
| 7 | 从第 6 步的页再进客户列表 | 客户左栏仍是第 5 步的状态，不被第 6 步关掉 |
| 8 | 1440 宽、左右栏都打开时看工作台概况 | On hand 与 Receivable 数字各自在格子内，不重叠 |
