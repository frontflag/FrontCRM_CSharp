## 与采购的差异（实施时不得照搬）

| 项 | 采购 | 销售 |
|----|------|------|
| 客商分面 | 刷新供应商（审核后要总监 / 换供应商权限） | 刷新客户（始终 `sales-order.write`） |
| 型号/品牌 | 写采购身份 + **库存换堆** | 只写销售身份快照，**不换堆** |
| 装箱主表型号/品牌 | 采购分面会写 | 销售分面也写（创建口径是销售）；后执行者生效 |
| 数量 | 可收缩已入库到货计划量 | **不收缩**已出库通知数量 |
| 单价完结 | 已完结列出再确认（默认允许） | 同样：已核销/已开票列出再确认（默认允许） |
| 已核销应收 | 刷新供应商不改其供应商 | 刷新客户不改已核销应收**客户主键**；主键已一致时名称快照可对齐。刷新型号/品牌/单价确认后可改展示快照或金额 |

## 第一期：分面入口 + 展示层身份

### 1.1 做什么

- 详情主按钮改为「刷新状态」；下拉：客户、物料型号、品牌、数量、单价。
- `POST /api/v1/sales-orders/{id}/refresh`，`facet=status|customer|pn|brand|qty|price`。
- 旧 `refresh-item-extends` **兼容，等价 price**（对 price 传 `confirmCompleted: true`）。
- `SellOrderItemRecalculateOptions`：`Default` / `StatusOnly` / `QtyPlanOnly`。详情刷新状态 / 单价之后走 `StatusOnly`，不再偷偷收缩出库通知。
- 刷新数量：只收缩超量**单条且未出库**的出库通知，再 `StatusOnly`。
- 刷新单价：现网下游销售价覆盖 + `StatusOnly`。
- 刷新型号 / 品牌：覆盖出库通知 `MaterialCode`/`MaterialName`、装箱 `Pn`/`Brand`、装箱扩展 `customer_pn`/`customer_brand`、应收 `PN`/`Brand`。不跑 Recalculate，不换库存堆。
- `facet=customer` 转到现网客户同步结果映射。
- Debug「刷新销售订单状态」改为 `facet=status`。
- 现网 `RefreshItemExtendsAsync` 按销售行 PN+品牌重算备货可用量：**拿掉**（备货可用量归采购分面）。

### 1.2 第一期明确不做

已完结按分面预检确认 → 第二期（第一期单价仍可先保持「点了就改」仅当两期拆 PR；**同一 PR 落地时与第二期一起上**）。

## 第二期：按分面控制已完结节点

### 2.1 做什么

- 销售参数页（原「刷新客户」路由/权限）改为五个开关：客户默认关；型号/品牌/数量/单价默认开。
- 详情非状态分面先预检。参数关且有已完结 → 整面阻断。参数开且有已完结 → 警告列出单据，用户确定后 `confirmCompleted=true` 才执行。
- 刷新状态不走此门控。编辑换客户保存不套详情确认标志。
- 旧布尔参数与 JSON 分面参数同步（客户）。
- 刷新客户：将覆盖的已完结出库链列入确认；已核销应收 / 已开票销项不进覆盖列表、仍不改客户字段。

### 2.2 关键接口

- `GET/PUT /api/v1/sales-params/refresh-completed-facets`
- `POST /api/v1/sales-orders/{id}/refresh/preview`（客户分面可转现网预检）
- `POST …/refresh`、`POST …/sync-downstream-customer` body `confirmCompleted`
